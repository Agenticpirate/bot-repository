name: ache-life-to-comic-skill description: 把用户持续发送的日常、照片、知识笔记、会议纪要、读书心得和完整长文，整理为可长期续更、按月成册的漫画手帐连载。用于用户提到漫画人生、续更、连载、收进我的书、把今天或照片记下来、制作月册/季度部/年度合辑，或要求沿用既有画风与持续角色时；不用于没有长期保存意图的一次性主题漫画。

Ache life-to-comic skill

把每次输入变成一本长期漫画人生中的新章节。第一次完成创刊选择，之后默认低打扰续更；让内容决定页数，让记录价值高于强剧情和固定主角。

核心边界

  • 始终采用“手帐逻辑 + 漫画效果”的产品底盘，不把它们作为创刊问题。
  • 不要求主角。没有角色时，用物件、空间、天气、动作、手、背影和视觉隐喻叙事。
  • 每个新章节有独立封面；补充、纠错、排版修改和明确续接上一条时不新开章节。
  • 一本长期连载按自然月形成独立月册；每月有独立月封，同月章节持续追加到一个月册入口，不生成每章一个用户文件。
  • 每三个月形成一部，年末形成合辑；只增加索引、封面与装订页码，不复制月册正文。
  • 默认主版本始终是可继续编辑的 HTML + assets；便携单文件是完成节点按需生成的分享副本，不能替代或反写主版本。
  • Skill 不绑定具体图片厂商或模型。探测当前平台能力，使用平台原生图片能力；未暴露的信息写 not_exposed。
  • 准确中文、日期、页码、来源和结构化字段始终由确定性排版生成，不交给图片模型。
  • 不把技术 PASS 当成人工视觉通过。

开始前读取

按任务读取，不要一次加载全部 references：

  • 每次视觉规划：先读取 references/design-system.md；这是白底、字体、留白、模板和材料的唯一基础口径。
  • 用户可见回复：遵守 references/interaction-voice.md，不主动展示内部路由、校准和调用过程。
  • 新建书：读取 references/first-run.md、references/style-system.md、references/publication-targets.md 和 references/presentation-runtime.md。
  • 每次输入路由：读取 references/input-routing.md。
  • S/P/K/M/L 页面：读取 references/page-grammar.md；封面同时读取 references/cover-director.md。
  • 有固定或穿插角色：读取 references/character-system.md。
  • 生成图片或缺少生图能力：读取 references/runtime-capabilities.md。
  • 续更、召回与上下文：读取 references/memory-context.md。
  • 月册、季度部、年度合辑：读取 references/serialization.md。
  • 搜索、隐私或外部发布：读取 references/privacy-sources.md。
  • 提交作品前：读取 references/validation-gates.md。

第一次创刊

只在不存在 publication-profile.json 时执行。

逐题确认，每次只出现一个问题，回答后再进入下一题：

  1. 画风：先通过真实展示能力呈现 assets/presets/style-selector.png 并取得 displayed: true 回执，再选择上传 1–5 张参考图、02 雪色粉蜡或 01/03/04/05 候选。
  2. 持续角色：暂时没有；让自己的 IP 进入漫画；66 大王仅作为内置角色示例。
  3. 主载体：本地 HTML 月册；飞书月册；GitHub 连载站；先本地后同步。
  4. 书：默认《我的漫画人生》；命名新书；续更已有书。

使用 scripts/onboarding.mjs 保存未完成状态。前一题未答时不得同时抛出后续问题；只有四题完成后才创建书级配置。

默认：

  • 画风为 02 雪色粉蜡，状态 validated_preset。
  • 角色为无。
  • 主载体为本地 HTML 月册。
  • 标准图片预算。
  • 弱连续。

将选择写入书级 publication-profile.json。后续不重复询问，除非用户主动修改设置。

01 云层水粉、03 白纸彩铅、04 双色线记、05 细墨轻彩的状态是 optional_candidate。首次启用先生成“封面 + 标准页”轻校准；用户确认后只为当前书激活，不能改写为全局已验证。

每次续更

  1. 建立提交 UUID、幂等键和临时目录。
  2. 归一化文字、图片、链接、会议字段、原文和输出意图。
  3. 判断复合输入关系：相关内容合成一集；独立内容拆成多集；每页只保留一个主要路由。
  4. 使用 context-pack.mjs 加载有上限的书级设定、最近摘要、钉住内容和直接相关旧记录。
  5. 选择 S/P/K/M/L 路由和角色介入级别；按 cover-director.md 保存核心物件、情绪动词、微小反差和封面语法四项导演卡。
  6. 生成必须先完成 compositionPlan：锁定内容职责、语义单元、页数区间、页面配方、图片预算、目标占页率和禁止项；再用 layout-plan.mjs 固定模板、字体角色、白底和留白规则。未通过预排不得生图。 同时锁定本章主题色板与每张生成图的目标像素尺寸。白底保持不变，标题线、边注、纸托和小装饰可根据画风、参考图、照片取色或本章情绪变化；不得让所有书和章节机械沿用 02 的冰蓝色。
  7. 探测图片与发布能力，生成平台无关 visual-job。
  8. 生成无字画面或执行已保存的无生图方案；所有资产先经 asset-contract.mjs 记录角色、实际宽高、比例与来源。
  9. 使用 page-renderer.mjs 完成确定性排版，再按 measured-layout.mjs 的分级纠偏完成四视图 QA；平台不得自行重写月册 HTML。
  10. 只有技术、语义完整性、有效占页率和人工视觉均通过，才在书级锁内原子提交。
  11. 更新当月唯一月册、系列书架和精简记忆。
  12. 章节完成后调用 portable-export.mjs 取得便携分享选择；同一来源版本只问一次，不擅自替用户选择。

用户正常只需要发送内容并接收结果。

排版器必须先测量再分页：标题、正文、图片与页脚使用正常网格流，元素矩形不得相交。生成图按 layout-plan.mjs 给出的实际放置区尺寸生成；图片内容框与图片宽高比误差不得超过 2.5%，外框留边不得超过短边 7%，避免固定框里硬塞不同尺寸的图。图片默认完整显示，只有显式 allowCrop: true 且声明安全主体区的非证据资产才可使用不规则窗口；原照片不裁切，只允许在其外侧制作手撕纸边。连续场景禁止比例切片，宫格只允许带安全间隔的独立单元。内容放不下时按“轻移位、局部压缩、节奏调整、换配方或分页”修正，不能先缩小正文到手机 12px 以下或隐藏溢出。已排好的 3:4 成品页直接整页展示，禁止再次套框。

知识、会议和长文的页边解释图属于独立组件：必须单独生成透明 PNG/WebP 或 SVG，并像贴纸、线稿或物件一样直接落在白纸上；禁止带白色长方形底、默认相框或假透明底。不得从共享大图、素材表或连续场景中裁出局部。只有 S 多格主体允许使用声明了安全间隔与精确边界的 isolated-cells 素材表。

平台不得手写替代版 HTML。能运行 Node 时必须调用本 Skill 的 monthly-serial.mjs 与 page-renderer.mjs；不能运行时只能交付完整 3:4 成品页或标记 render-blocked，不能自行发明博客、固定相框或 overflow:hidden 截字版。输出缺少 ache-design-system/1.10.0、ache-monthly-renderer/2.8.0、主题契约或框图匹配标记时，视为非正式产物。跨平台交付后可运行 node scripts/cli.mjs validate-html --input <index.html>；不是 PASS 就不得作为正式月册。

完成后的便携分享

单章正式提交、月册结束、季度部完成或年度书完成时，主版本仍保存为 HTML + assets，随后询问一次：

  1. 轻量分享版：内嵌图片与版式，使用接收设备中文字体；
  2. 完整保真版：图片、版式与字体全部内嵌，文件更大；
  3. 暂不导出：保留主版本，以后可主动补导。

使用 share-prompt 生成带估算大小的选择，用户回答后才调用 share-choice。不设置默认选项，不把“暂不导出”当永久放弃；相同层级、键与来源摘要已决定时不重复打扰。四级完成定义、命名和路径遵守 references/serialization.md。

无生图能力

第一次检测到缺失时只问一次：

  1. 启用当前平台图片能力；
  2. 使用原图、CSS/SVG、线条、色块和纸张材料继续；
  3. 先完成可读连载并进入 visual-pending 待补图队列。

把选择保存在书级设定中，不在每章重复。

  • P/K/M/L 可在轻插画档形成正式页。
  • S 若依赖原创漫画镜头，默认形成完整待补图草稿；只有用户接受轻插画版后才标记正式。
  • 待补图不能阻塞后续章节。以后只补资产，不重写原文、事实、章节 UUID 和时间。

路由硬规则

  • S 日常：先提取最多 8 个真实节拍，再使用 plan-entry.mjs 的 panelPlan 固定逐页格数、节拍顺序与上→下布局；一页 1–3 格，使用独立资产或带安全间隔的独立单元，禁止从连续大场景切出分镜。
  • P 照片：原图只读、完整保留、不重绘；异形窗口只作用于外层纸托；另做基于内容语义的独立章节封面，禁止把原图滤镜化、转绘或沿原机位重画后当封面。
  • K 知识：正文先自洽，少量解释图；区分事实句、编辑标题、视觉旁注。方法型内容必须先组成“背景→完整步骤→用户反应”，禁止按分号把因果或步骤机械拆成散句。
  • M 会议：默认文字优先、轻配图；保留发言人、决定、风险、未决、负责人、期限和状态。会前预排必须先形成“背景/议题→讨论→决议/风险→行动”的页面职责，普通会议不允许裸段落、UI 卡片或因字段数而变多图。
  • M 漫画会议：只有用户明确要求“会议漫画化”或“万物变漫画”时才进入完整漫画纪要。
  • L 长文：默认逐字逐段同序保留；先实排一页再决定是否分页。先均衡自然语义单元，目标为每页 62%–88% 有效占页，禁止制造只有顶部几段或一两段的孤立尾页。

不要因为用户建立角色库就在每页加载角色。不要把参考图中的人物自动当作用户主角。

连载载体

内部数据始终使用同一书库契约，外部载体只负责呈现和同步：

  • 本地：一个系列书架 index.html，每个有内容月份一个月册 index.html。
  • 飞书：一个系列目录文档，每月一个持续追加文档。
  • GitHub：一个仓库/站点，首页为系列书架，每月一个连续阅读路由。
  • 先本地后同步：本地为主版本，远端只同步用户批准的镜像。

飞书月册默认使用连续画册模式：只保留月册标题与一句导语，随后按页码连续放置已经通过四视图验收的 1080×1440 成品页。不要把同一内容再次拆成飞书原生正文，避免两套排版互相干扰；用户需要检索或无障碍文字时，另附原文入口或独立文字附录，不插进画册阅读流。

执行飞书操作时，只允许用户已经核验的个人账号。调用前回读连接身份；无法确认账号归属时返回 identity_confirmation_required，不得写入。

任何外部写入、公开发布、权限改变或上传都需要用户明确授权。GitHub 公开站只使用脱敏副本。

确定性脚本

使用当前环境的 Node 运行以下脚本；若 node 不在 PATH，先定位平台自带运行时，不全局安装。

  • scripts/runtime-capabilities.mjs：标准化图片与运行能力。
  • scripts/presentation.mjs：为必要视觉选择真实展示表面并生成展示回执。
  • scripts/publication-target.mjs：解析本地、飞书、GitHub与同步模式。
  • scripts/feishu-image-edition.mjs：验证飞书连续画册的页数、页序、尺寸、清晰度凭据和上传 token，并生成确定性 XML。
  • scripts/plan-entry.mjs：生成路线、页数、封面和预算计划。
  • scripts/layout-plan.mjs：从已验收设计基线生成白底、字体、模板和视觉门禁。
  • scripts/theme-system.mjs：把书级画风与本章主题翻译为可变化的克制色板，始终锁定纯白纸底。
  • scripts/asset-contract.mjs：记录并校验封面、原照片、独立分镜、解释插图和月封的尺寸与来源。
  • scripts/measured-layout.mjs：根据真实溢出量和页面密度选择纠偏级别，不允许先缩正文。
  • scripts/context-pack.mjs：生成有字符与记录数上限的年度上下文包。
  • scripts/onboarding.mjs：逐题创刊并在完成后生成书级配置。
  • scripts/validate-entry.mjs：先验证五路由共同的四字段封面导演卡，再验证 P 照片哈希、K 事实账本、M 结构字段和 L 原文。
  • scripts/monthly-serial.mjs：书级锁、幂等提交、月册与系列索引。
  • scripts/page-renderer.mjs：执行固定 3:4 页面、字体、留白、异形窗口和响应式规则。
  • scripts/portable-export.mjs：生成单章、单册、单部和单本的离线便携分享副本。
  • scripts/cli.mjs：初始化书、规划、追加、分享选择和检查。

先写临时文件，校验后原子替换。失败草稿不占正式章节序号。重复幂等键返回已有结果。

上下文

默认只加载：

  • publication-profile.json；
  • 画风和角色决策；
  • 用户钉住内容；
  • 最近五页形式摘要；
  • 当前输入直接相关的旧记录。

不要默认加载全部历史正文、旧图、角色历史或完整对话。相关性不确定时选择弱连续。 即使连载一年或更久，也保持最多最近 5 条形式摘要、3 条直接相关旧记录、10 条待办与 12,000 字符上下文预算；历史规模不能直接增加单次响应负担。

提交门禁

每个正式章节至少检查：

  • 1080×1440 原尺寸；
  • 135×180 缩略图；
  • 桌面 HTML；
  • 390px 手机 HTML；
  • 文字溢出、缺图、遮挡、安全区、横向滚动和控制台错误；
  • 标题/正文/图片/页脚局部碰撞、页面隐藏溢出、图片裁切比例和手机最小字号；
  • 与已验收 good case 做逐类型审美回归；布局可以变化，但不能丢失白底、编辑层次、手帐关系与单页视觉趣味点；
  • P 原图比例与哈希；
  • K 事实与来源；
  • M 结构化字段；
  • L 原文哈希与真实版面占用；
  • 页面是否过空、过挤或阅读顺序不清；长文是否存在被强制拉开的巨大内部空洞；
  • 生成前 compositionPlan 是否锁定；各语义单元是否完整，页面有效占页率是否处于 62%–88%，底部无功能空带是否不超过 25%；
  • 生成图目标尺寸是否与实际放置区一致；图片与内容框比例误差是否不超过 2.5%，外框是否没有明显硬贴、过宽留边或多层套框；
  • 解释小插画是否为透明底位图或 SVG；不规则窗口是否声明了安全主体区，且没有裁掉人物、物件、文字或关键环境；
  • 本章色板是否来自当前画风与主题，而不是无条件复用默认冰蓝；页面大背景仍必须为 #FFFFFF；
  • 长文正文是否保持自然段落流，相邻段落最大连续空白是否不超过内容区 12%，且未使用 space-between 伪造触底；
  • 封面是否根据本次内容生成，而非复用固定物件与构图。
  • 月册是否有独立月封；章节封面与月封是否都是 3:4 独立资产。
  • 多格主体是否完整；任何 sheet crop 是否来自声明了安全间隔和精确边界的独立单元。

便携分享版还必须复制到一个没有 assets 的空目录中，断网打开并通过桌面与 390px 手机检查；不得含未内嵌资源、远程依赖或本机绝对路径。

任一技术错误、内容失真、隐私问题或人工视觉失败都阻止正式提交。保留可恢复草稿和定向修复信息。

Ache life-to-comic skill

一句话、一张照片、一段会议，或者一篇不想改的长文。第一次创刊后，接下来只管发来。每次记录会拥有自己的封面和页法，再续进当月的漫画手帐。

不是把所有内容塞进同一张模板，也不要求你天天都有故事。有时是三格漫画，有时是一页照片手帐，有时只需要文字和一幅很小的图。

它会怎么陪你记录

第一次只做四个选择，而且一题一题来：

  1. 先看五款画风的同屏样张，也可以上传 1–5 张参考图。
  2. 决定要不要让一个熟悉的 IP 偶尔路过。
  3. 选择本地 HTML、飞书、GitHub，或先本地再同步。
  4. 给这本书起名字。

之后就不再反复填表。你发内容，它负责把这一章续进去。

你发来的内容 它会怎么处理
日常、心情、朋友圈感受 提取真实节拍，做成一至三格漫画或写意页面
一至多张照片 保留完整原图，用异形纸托、手帐边注和漫画节奏重新组织
知识、读书笔记、心得 正文先讲清楚，只在关系、过程或尺度需要时穿插少量解释图
会议纪要 保留决定、风险、待办、负责人和期限，默认轻配图
已经写好的长文 不强行改写，按原顺序排进可读页面，再补少量插画元素
几种内容一起发 判断它们是在说同一件事还是应该拆成不同章节

每次正式输入都有自己的章节封面。一个月的内容持续进入同一本月册，每三个月形成一部，年末再生成合辑索引。不是每章散落一个 HTML 文件，也不会因为连载一年就把全部历史塞进上下文。

想把 HTML 单独发给别人时

平时连载保留的是可继续修改的 HTML + assets，像书稿和插图放在同一个书盒里。单独只发其中的 index.html，图片当然不会跟着走。

所以，每次单章、单册、单部或单本完成后，它会问你一次：

  • 轻量分享版：图片与版式已经装进一个 HTML，适合聊天和邮件发送；
  • 完整保真版：连字体也一起装进去，更接近原书，但文件更大；
  • 暂不导出：继续保留可编辑主版本，以后想发时再补导。

选择前会先告诉你预计大小，不会悄悄生成一个几十 MB 的文件。导出的成品放进 share-exports/，可以离开原来的 assets/，断网单独打开。

让自己的 IP 进入漫画

持续角色不是硬性主角。它可以是一只宠物、一个人物、品牌角色、一件总会出现的物品，甚至只是一种背影。

你可以让它：

  • 偶尔在页边观察；
  • 在某些章节进入场景；
  • 只保留固定动作或标志物；
  • 完全不出现，让天气、空间和物件来叙事。

示例中的 66 大王只用于展示角色系统。安装到你的书里时，优先问的是“要不要带上你的 IP”，不会把 66 大王自动塞进所有人的故事。

五款画风

  • 02 雪色粉蜡：默认。白底、冰蓝、炭灰，安静但不冷淡。
  • 01 云层水粉：更松、更有空气感。
  • 03 白纸彩铅：线条清楚，像认真画过的纸上记录。
  • 04 双色线记：颜色克制，适合轻快日常与物件叙事。
  • 05 细墨轻彩：线稿更稳，适合阅读、知识与长文。

预设只是起点。大多数时候，更推荐上传自己的参考图。Skill 会拆出媒介、配色、人物画法、构图、手帐材料和漫画镜头，不会把参考图里的具体人物或 Logo 顺手抄进来。

为什么换个平台，排版不会重新变一遍

比例、字体、白底、分页、照片适配和手帐材料，不再只写成提示词。它们已经落进确定性渲染器：

  • scripts/page-renderer.mjs 负责 3:4 页面和月册装订；
  • assets/templates/page-system.css 负责字体、留白、异形窗口与响应式；
  • assets/layout-system/design-baseline.json 是唯一设计基线；
  • scripts/theme-system.mjs 让白纸保持不变，但章节点睛色随画风、参考图与情绪变化；
  • scripts/validate-rendered-html.mjs 拦截通栏博客、图框比例失配、白底假透明、文字截断和工具 JSON 泄漏。

不同平台只负责提供文字、原图和无字画面，不能各自重新发明 HTML。图片生成与图片展示也分开探测：如果当前环境没有生图能力，会引导启用原生能力、使用轻插画方案，或先进入待补图队列；不会直接拒绝，也不会假装图片已经出现。

已经写死的质量底线

  • 页面默认纯白，不用米黄或牛皮纸铺满背景；
  • 中文标题主动平衡换行，不留单字孤行；
  • 照片完整保留，外框可以变化，照片本身不被重绘；
  • 生成图按实际版位尺寸出图，图与框比例误差不得超过 2.5%；
  • 不规则窗口必须预留主体安全区，页边小插画使用透明底位图或 SVG；
  • 已经排好的成品页原样装订，不再缩进另一个页面；
  • 知识、会议和长文以文字为主，图片少而有用；
  • 每章封面跟随这次内容，不复用一个固定构图；
  • 桌面、手机、原尺寸和缩略图都要检查；
  • 并发追加使用 UUID、书级锁、幂等键和原子写入，避免页码重复或文件损坏。
