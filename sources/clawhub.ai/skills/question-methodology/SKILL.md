# 提问方法论 — 问对问题，才能做对事

一个轻量级框架，帮助在任何决策或任务前快速判断：**我要解决什么问题？这个问题值得解决吗？**

## 核心框架：两问一检

### 第一问：黄金圈定位
**一句话问自己：** 我要解决什么问题？为什么是这个问题？

- **清晰性检查：** 能不能用一句话说清楚问题？
- **必要性检查：** 这个问题不解决会怎样？
- **可行性检查：** 这个问题我能解决吗？

### 第二问：六维验收
**问自己：** 我的回答经得起追问吗？

| 维度 | 检查问题 | 目的 |
|------|----------|------|
| 准确性 | 我说的有证据吗？ | 避免"我觉得" |
| 精确性 | 能说具体数字/范围吗？ | 避免"大概" |
| 相关性 | 这跟真问题有关吗？ | 避免跑题 |
| 深度 | 我是在治标还是治本？ | 避免"头痛医头" |
| 广度 | 还有其他可能性吗？ | 避免"管窥" |
| 完整性 | 有什么我漏掉的吗？ | 避免盲点 |

### 一检：完成标志
**问自己：** 这件事做完了吗？

- 有产出物吗？（文件/代码/文档/决策）
- 有记录吗？（写在 memory/YYYY-MM-DD.md）
- 有验证吗？（用户确认 或 自查通过）

## 典型使用场景

### 场景 1：判断要不要做某事

```
输入：一个想法、任务、或请求

第一问：我要解决什么问题？
  → 如果问题不清晰 → 先把问题说清楚
  → 如果问题不必要 → 不做
  → 如果问题不可行 → 换问题

第二问：六维验收
  → 准确性：有证据吗？
  → 深度：是在回避真问题吗？
  → 广度：还有其他选择吗？

输出：做/不做/换个问题/先说清楚问题
```

### 场景 2：做到一半卡住了

```
输入：一个卡住的任务

一检：这件事做完了吗？
  → 看状态：[🔄] 进行中？
  → 看下一步：有明确的行动吗？
  → 如果连续 3 次心跳还是 [🔄] → 强制推进或放弃

输出：下一步行动 或 放弃理由
```

### 场景 3：用户说"你自己看着办"

```
输入：模糊的授权

第一问：我要解决什么问题？
  → 用户给的是方向，不是指令
  → 我需要自己定义问题边界

第二问：六维验收
  → 相关性：这是用户关心的真问题吗？
  → 深度：我是在做事还是在回避？

一检：完成标志
  → 有对外可见的产出吗？
  → 如果没有 → 先完成一件最小的事

输出：明确的问题定义 + 最小产出目标
```

## 快速检查清单

```
□ 第一问：问题清晰？必要？可行？
□ 第二问：准确？精确？相关？深度？广度？完整？
□ 一检：有产出？有记录？有验证？

全通过 → 执行
不通过 → 先解决不通过的项
```

## 设计原理

### 为什么是"两问一检"？

- **第一问（黄金圈）**：定位问题的价值。很多问题不值得解决。
- **第二问（六维）**：验证思考的质量。很多回答经不起追问。
- **一检（完成）**：确保闭环。很多任务永远在"进行中"。

### 为什么不是更多？

- 复杂框架的学习成本 > 使用价值
- 实战中 80% 的问题靠这三步就能发现
- 剩下 20% 是真难题，需要专门深挖

### 什么时候不用这个框架？

- 已经验证过的问题（不用每次都问）
- 紧急情况（先做，后反思）
- 纯粹的执行任务（问题已定义清楚）

## 输出格式

使用此技能后，输出结构化的问题定义：

```markdown
## 问题定义

**问题：** [一句话说清楚]
**必要性：** [为什么不解决不行]
**可行性：** [为什么我能解决]

## 验收标准

- 准确性：[证据来源]
- 精确性：[具体数字/范围]
- 相关性：[跟什么大目标有关]
- 深度：[治标还是治本]
- 广度：[其他可能性]
- 完整性：[可能的盲点]

## 完成标志

- 产出物：[文件/代码/文档/决策]
- 记录位置：[文件路径]
- 验证方式：[用户确认 / 自查标准]
```
