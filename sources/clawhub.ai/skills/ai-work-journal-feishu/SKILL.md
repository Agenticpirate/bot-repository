# AI工作日记 · 飞书知识库

## 适用场景

- 用户要把当天用 AI 完成的事记入飞书 Wiki
- 内容包括排障、办公提效、工具探索
- 需要第一人称、逻辑清楚、普通人也能读懂

## 不适用场景

- 本地项目 Markdown 归档（另有专用 skill）
- 用户明确说「别记飞书 / 这次不用写」
- 纯代码开发、不做叙事记录

## 输入

| 输入 | 必填 | 说明 |
| --- | --- | --- |
| 主题 | 是 | 当天做了什么 |
| 记录类型 | 可推断 | 排障 / 提效 / 探索 |
| 场景标签 | 可推断 | 见「分类体系」 |
| 截图 | 按需 | 报错、成功、关键配置；缺则向用户索要 |
| 飞书落库目标 | 首次必问 | 见「飞书落库配置」；之后可读本机配置 |

## 输出

- 飞书 Wiki（或指定父节点）下一篇新子文档
- 标题：`YYYY-MM-DD｜[类型·场景] 简短主题`
- 返回文档 Wiki / 云文档链接

## 其他约束

- 日期用北京时间
- 用户已定稿的正文与截图：只补用户明确要求的部分，不擅自覆盖
- 写作前若可用，读取 humanizer skill 去 AI 腔（路径因环境而异）
- 标题分类必填；正文结构**不固定**
- **禁止**把本仓库、用户对话或本机配置中的真实 Wiki URL / token / 知识库路径写入对外文档或示例；一律用占位符

## 如何使用

1. 将本 skill 目录安装到 Agent 可加载的 skills 路径（见 README）
2. 按「飞书接入（首次）」完成登录与授权
3. 对 Agent 说「记到知识库 / 写今天的 AI工作日记」并简述主题
4. Agent 按「操作流程」执行：必要时先问落库位置，再写稿落库

**humanizer**（去 AI 味，可选）：若环境中已安装同名 skill，写作前读取；没有则跳过，不要臆造路径。

## 飞书接入（首次）

发布前用户需能通过本机工具以**本人身份**创建飞书文档。任选其一：

### A. Cursor · Feishu Docs MCP（推荐）

1. 在 Cursor 中启用飞书文档相关 MCP（如 `Feishu Docs`）
2. 若工具不可用，按 MCP 提示完成认证（常见为 `mcp_auth`）
3. 可用 `feishu_whoami`（或等价能力）确认当前登录可用
4. 落库时用创建文档能力，传入用户指定的父节点 `parent_token`（或等价参数）

### B. lark-cli（WorkBuddy / 通用终端）

1. 按当前环境文档安装并登录 `lark-cli`
2. 确认本机已登录、token 有效
3. 用 Wiki 相关命令在指定父节点下创建子文档后写入正文

调用 CLI 前清理可能干扰登录态的残留 Agent 环境变量（若报权限/身份错再排查），不要把变量名写进对外示例。

### 用户需要提供哪些飞书信息

| 信息 | 何时需要 | 说明 |
| --- | --- | --- |
| 登录态 | 每次落库 | MCP 已认证或 `lark-cli` 已登录；Agent 不代替用户注册飞书应用密钥写进仓库 |
| 父节点 Wiki / 文件夹链接 | 首次落库（或配置缺失时） | 例如 `https://*.feishu.cn/wiki/<node_token>` 或云空间文件夹链接 |
| 父节点 token | 可从链接解析 | URL 最后一段通常即 `node_token` / `parent_token`；用户也可直接给出 token |
| 落库工具偏好 | 可选 | MCP 或 `lark-cli`；默认用当前环境已可用的那一种 |
| 目录策略 | 可选 | 是否全部挂同一父节点、是否按类型分子目录 |

**不要向用户索要、也不要写入 git：** App Secret、用户密码、长期 refresh token 明文。应用凭证只存在本机安全配置中。

## 飞书落库配置

本 skill **不内置**任何具体 Wiki 地址。

### 询问时机

1. **首次**（或本机无有效配置）：落库前必须问清「上传到飞书哪里」
2. **有本机配置**：直接使用；落库前可一句确认「还发到上次的父节点吗？」
3. 用户本次给出新链接 / 说换目录：以本次为准，并询问是否更新本机配置

### 建议询问话术（首次）

请用户提供至少一项：

- 父 Wiki 页面或知识库节点链接；或
- 父文件夹 /「我的文档库」中的目标位置说明

并确认：文档标题格式是否用本 skill 默认（`YYYY-MM-DD｜[类型·场景] 主题`）。

### 本机记忆（建议）

征得用户同意后，把落库目标写到本 skill 目录下的本地文件（已加入 `.gitignore`）：

```text
config.local.json
```

示例（占位符，勿提交真实值）：

```json
{
  "parent_wiki_url": "https://xxx.feishu.cn/wiki/<YOUR_NODE_TOKEN>",
  "parent_node_token": "<YOUR_NODE_TOKEN>",
  "preferred_tool": "mcp",
  "title_timezone": "Asia/Shanghai"
}
```

- 读：有文件则解析；无效或缺字段则重新询问
- 写：仅在用户确认「记住」后更新
- **禁止**把 `config.local.json` 提交到 git 或贴进公开 Issue

### 目录策略（默认）

全部挂在用户指定的同一父节点下。某类型或场景积累较多时，再请用户决定是否建 Wiki 子目录。

## 分类体系

### 记录类型（标题三选一）

| 类型 | 适用 |
| --- | --- |
| 排障 | 报错、连不上、安装失败、行为不符合预期 |
| 提效 | 用 AI 完成原本手工折腾的事 |
| 探索 | 试新工具/workflow，记录值不值得继续 |

### 场景标签（标题五选一）

| 场景 | 适用 |
| --- | --- |
| 开发与环境 | 编辑器、MCP、Git、Docker、代码、部署配置等 |
| 系统与电脑 | 磁盘、卸载、环境变量、路径、系统维护 |
| 办公与协作 | 飞书、邮件、日程、协作工具 |
| 内容与创作 | 写稿、知识库、配图、发布 |
| 其他 | 以上都不贴切；正文首段说明实际场景 |

一篇只标一个主场景；跨场景时在正文说明，标题仍只标主场景。

### 标题格式（必填）

```text
YYYY-MM-DD｜[类型·场景] 简短主题
```

示例（主题可替换，勿绑定真实私密链接）：

```text
2026-07-29｜[排障·开发] 某 Agent 连接飞书失败
2026-07-27｜[提效·系统] 用 AI 整理磁盘空间
2026-07-25｜[探索·办公] 试飞书 MCP 远程模式
```

可选文首元信息（非强制）：

```text
类型：提效
场景：系统与电脑
```

## 操作流程

1. **解析落库目标**：读 `config.local.json`；缺失则询问用户上传位置与所需飞书信息，确认后可选写入本机配置
2. 确认类型与场景（不确定时问用户一句）
3. 若有 humanizer 则读取，去 AI 腔
4. **规划正文结构**：根据当天内容决定写哪些节、是否合并/加节（见「文章结构」）
5. 缺截图则向用户说明需要什么图，等提供后再插入
6. 在指定父节点下新建文档节点并写入正文与截图
7. 返回文档链接；若本次用户改了落库位置，询问是否更新本机配置

## 落库工具（按环境选用）

| 环境 | 方式 |
| --- | --- |
| Cursor | Feishu Docs MCP（创建时带 `parent_token`）或 `lark-cli` |
| WorkBuddy 等 | 飞书 connector + `lark-cli` |
| 通用 | 已登录的 `lark-cli` |

## 写作要求

### 叙事

- 第一人称「我」
- 不写「方便发公众号」「以后可以分享」等元话术
- 不用「经排查发现」「如上所述」等公文腔

### 截图

- 有则必插正文
- 需要但用户未提供：先索要，不空占位、不跳过
- 截图若含账号、密钥、内网地址：提示用户打码后再贴

### 逻辑（排障类最重）

- 必须有一条完整因果链
- **先给全局流程图**（ASCII 或步骤列表），再用**概述段落**串起来（不必逐步拆小标题）
- 概述里代词、变量名要说清；前后动作与结果之间的因果写完整
- **概述适当换行**：按意群分段，避免整段挤在一起
- 讲透唯一核心原因；机制讲清
- 提效/探索类不必强行写排查流程图

## 文章结构（非固定，灵活调整）

**结构示例仅供参考，不是必填清单。** 写之前先想：读者需要知道什么，再决定章节。

### 原则

- **可删**：某节对当天故事没帮助就整节不写
- **可并**：「今天遇到了什么」与「问题现象」常合并为一节
- **可增**：需要时加「修复前后对比」「用到的提示词」「踩过的弯路」等
- **可改名**：节标题用自然语言，不必照搬示例
- **类型之间可混用**：探索里若出现报错，可局部用排障写法

### 排障类 · 常见节（按需选用）

| 节 | 何时写 |
| --- | --- |
| 今天遇到了什么 | 几乎总是需要；可含现象、报错、截图 |
| 我是怎么排查的 | 有排查过程时；必须先有因果链流程图 |
| 解决方案 | 有可执行步骤时 |
| 这件事背后的知识点 | 有值得记住的一条机制时；一条讲透即可 |
| 下次可以照着做的清单 | 有可复用步骤时 |

### 提效类 · 常见节（按需选用）

| 节 | 何时写 |
| --- | --- |
| 今天想完成什么 | 目标不清楚时 |
| 我是怎么跟 AI 协作的 | 有工具/提示/流程值得记录时 |
| 结果怎样 | 有前后对比或省时数据时 |
| 这次用到的关键技巧 | 可选 |
| 下次可以照着做的清单 | 有可复用做法时 |

### 探索类 · 常见节（按需选用）

| 节 | 何时写 |
| --- | --- |
| 为什么想试 | 动机不 obvious 时 |
| 试了什么 | 几乎总是需要 |
| 值不值得继续用 | 有结论时 |
| 下次可以照着做的清单 | 可选 |

### 结构示例（仅作起点，勿机械照搬）

排障：

```markdown
## 今天遇到了什么
## 我是怎么排查的
## 解决方案
## 这件事背后的知识点
## 下次可以照着做的清单
```

提效：

```markdown
## 今天想完成什么
## 我是怎么跟 AI 协作的
## 结果怎样
## 下次可以照着做的清单
```

探索：

```markdown
## 为什么想试
## 试了什么
## 值不值得继续用
```

## 禁止

- 标题缺少 `[类型·场景]` 或使用未定义的类型/场景词
- 为凑固定模板硬写空洞章节
- 排障类排查跳跃、缺少因果衔接
- 提效/探索类全文硬套排障流程图
- 需要截图却不索要、也不插入已有截图
- 覆盖用户已定稿正文与截图
- 写入或公开真实 Wiki URL、node token、知识库私有路径、App Secret
- 在缺失落库配置时静默猜一个父节点
