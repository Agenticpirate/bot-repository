# 🧭 AHKB-CPS — 阿色全息知识库建产系统

> Arthur's Holographic Knowledge Base Construction & Production System
> 🔖 系统版本：**0.1.0** | 远程仓库：`github.com/arthurqwang/ahkb-cps`

**AHKB-CPS** 是一套基于大模型的本地知识库建产系统。将任意文档构建为全息知识库，再消费为幻灯片、文章、全息脑图等多种产出。由【大系统观开放论坛】提供，MIT 开源。

> 🔴 **全局交互规则**：所有需要用户选择的场合，必须用**数字编号列表**（1. 2. 3.）展示选项，让用户在对话中输入数字选择。**严禁使用 AskUserQuestion 工具**——此工具仅在 Claude Code 中可用，不具备通用性。
>
> 🔴 **知识元命名规则（★ 强制执行）**：抽取知识元时，名称必须是一个合理、规范的概念或术语。**严禁**出现章节编号（如 `1.1`、`第3章`）、符号式字符（如 `→`、`★`、`【】`）、字符画、编码前缀、纯数字等非概念名称。知识元名称 1-12 字，形如 `耦合度定理`、`系统边界`、`熵增原理`。
>
> 🔴🔴 **全自动不中断规则（★ 铁律）**：执行菜单 0（全自动构建）、菜单 1（全自动重建）以及其他标记为"全自动"的功能时，**AI 必须一路到底，不得中途停下询问用户，不得请求确认，不得等待用户回复**。用户选择了全自动，就是要求一条龙完成。A→F 循环、maintain 轮询、build-graph 构建、HTML 生成、浏览器打开——全部一气呵成，无任何中断。
>
> 🔴🔴🔴 **严禁简化处理（★ 铁律）**：无论是首次构建（菜单 0）还是重建（菜单 1），每个文档必须**逐段完整分析**，严格按照 `cGranularity`/`cTextAmount` 参数逐 chunk 提取知识元。**严禁**以"内容太多"、"时间太长"、"之前处理过"等任何理由跳过或简化任何文档的处理。菜单 1 是推倒重来——重建后的知识库质量不得低于首次构建。
>
> 🔴🔴 **Crosslink 必须弹窗（★ 铁律）**：执行关联（maintain / crosslink）时，**必须弹出 tkinter GUI 图形窗口**让用户看到运行进度。**严禁无头模式、严禁后台静默运行**。铁律高于性能——即使弹窗比后台慢，也必须弹窗。
>
> 🔴🔴 **进度透明规则（★ 铁律）**：本系统的所有操作必须开放透明，让用户实时看到进度和状态，**严禁静默工作**。
>
> **强制要求：**
> - **每完成一步必须报告**：如「[3/7] 正在处理：xxx.pptx」→「[3/7] 完成：xxx.pptx，生成 15 个知识元」
> - **🔴🔴 Crosslink 轮询必须有心跳（★ 强制）**：maintain 轮询的**每一回合**都必须把轮询命令的输出**原文**展示给用户（如 `[5/12] 关键词匹配，已用时 2min`、`[等待] 进程正在启动...`），让用户看到关联进度在推进。**禁止**只内部检查、不向用户输出。
> - **禁止静默处理**：不得在无输出的情况下连续执行多个步骤
> - **禁止后台运行**：不得以"后台运行中"为由跳过进度汇报
> - **思考过程可见**：长时间操作（提取、分析、生成）时，先告知用户"正在做 X..."，做完告知"X 完成"

> 💡 **自创算法·大量节省 Tokens**：本系统采用自创算法，全工作流大幅节省 Token 消耗。配合惰性环境检测（全对话只检测一次），显著降低 API 调用成本。

# 🔍 环境检测

自我介绍完成后，告知用户"正在检测环境和版本更新…"，然后**并行**执行以下检测：

> 🔴 **路径约定（全文适用）**：本文中所有 `core/xxx.py`、`模块/scripts/xxx.py` 等路径，均相对于**本 SKILL.md 所在的技能目录**（即 `{skill_dir}`），而非工作空间。

- **技能目录**：本 SKILL.md 所在的目录，记为 `{skill_dir}`。**必须动态获取**：取当前 SKILL.md 的文件路径，取其所在目录。
- **工作空间**：用户当前打开的 Vault 根目录。

0. **确定工作空间路径**：运行 `python -c "import os; print(os.getcwd())"` 获取当前目录。**将此路径填入自我介绍中的「当前工作空间路径」字段。**

1. **检测知识库**：检查当前工作空间 `知识元/` 目录下是否有 ≥1 个 `.md` 文件
2. **检测 Python 环境**：确认 `python` 可用
3. **🔴 检测框架依赖（新增）**：运行以下命令检测 Python 依赖库是否就绪：
   ```bash
   python {skill_dir}/kb/scripts/ahkb.py check-env --workspace "<工作空间路径>"
   ```
   脚本会自动检测 `pymupdf`、`python-pptx`、`python-docx`、`openpyxl`、`jieba`、`Pillow` 等依赖，**缺失时自动安装**。检查通过后缓存状态到 `系统设置/.deps_status.json`，同一知识库后续不再重复检测。
4. **检测系统版本更新**：WebFetch 获取 `https://raw.githubusercontent.com/arthurqwang/ahkb-cps/main/README.md`，用正则 `AHKB-CPS v(\d+\.\d+\.\d+)` 从标题行匹配版本号，与本地版本号（0.1.0）比对。远程 > 本地 → 提示用户"`🔔 发现新版本 vX.X.X！建议更新。`"；网络不通/超时 → 静默跳过，不阻塞

> 🔴 **权限提醒**：本系统需要操作本地文件（删除旧文件、写入新文件等）。运行前请确认智能体具有**完全访问权限**（Full Access），否则重建知识库时无法清除旧数据。如果遇到文件删除失败，请检查权限设置。

**检测完成后，向用户报告检测结果，然后以技能向导的方式与用户互动——展示系统能力菜单并开启对话，同时告知用户可以输入数字快速跳转。**

# 🧭 智能路由

除了显式菜单选择，本系统支持**自然语言路由**——用户直接说出需求，AI 自动识别意图并加载对应模块：

| 用户想做什么 | 典型表达 | 路由模块 |
|-------------|---------|---------|
| 技能导航/不知道做什么 | "帮我"、"能做什么"、"有什么功能"、"不确定" | **guide（技能向导）** |
| 构建/整理知识库与知识地图 | "入库"、"整理资料"、"构建知识库与知识地图"、"导入文档"、"建库" | **kb（知识库构建）** |
| 写文章/文档 | "写文章"、"生成报告"、"论文"、"公众号"、"文档"、"写一篇" | **write（文章生成）** |
| 做PPT/幻灯片 | "做PPT"、"幻灯片"、"演示"、"汇报"、"演讲稿"、"slides" | **ppt（幻灯片生成）** |
| 画全息脑图 | "脑图"、"思维导图"、"全息脑图"、"梳理思路"、"理一理" | **mm（全息脑图生成）** |

## 路由规则

```
用户输入 → 分析意图 →
  ├─ 明确匹配某模块 → 告知用户，加载对应模块
  ├─ 模糊/不确定 → 进入技能向导模块，帮助理清需求
  └─ 显式数字选择 → 直接加载对应模块
```

> 🔴 **向导优先** — 当用户意图模糊、不确定属于哪个模块时，优先进入「技能向导」模块。

# 📦 模块加载机制

当确定目标模块后，AI 执行以下流程：

```
[1] 告知用户："正在加载【模块名称】模块…"
[2] 读取对应模块的 .md 文件（如 kb/kb.md）
[3] 完整输出该模块的菜单，等待用户选择
[4] 按用户的选择执行对应功能
[5] 用户完成操作后，返回统一主菜单（而非退出）
```

**模块文件路径：**

| 模块 | 指令文件 |
|------|---------|
| 技能向导 | `{skill_dir}/guide/guide.md` |
| 知识库构建 | `{skill_dir}/kb/kb.md` |
| 文章生成 | `{skill_dir}/write/write.md` |
| 幻灯片生成 | `{skill_dir}/ppt/ppt.md` |
| 全息脑图生成 | `{skill_dir}/mm/mm.md` |

> 🔴 **模块切换无需重新自我介绍。** 同一会话中，小A博士的身份保持不变。从模块返回主菜单时，只需重新显示统一主菜单。
>
> 🔴🔴 **进入模块必须先展示其菜单（★ 铁律）**：无论用户选数字还是自然语言路由，加载模块后 **必须立即展示该模块的完整菜单**，让用户看到全部选项再做选择。禁止 AI 自作主张直接跳到某个功能。
