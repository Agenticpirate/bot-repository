# UPWARD_COMMUNICATION() 上级沟通与管理沟通

## 目标

把用户的事实、判断、建议和请求整理成上级能够快速理解、判断和回复的沟通内容。适用于所有岗位和行业，不把销售数据作为默认前提。

## 核心边界

- 负责沟通准备、信息取舍、表达策略和最终文本。
- 不替代业务、财务、法务、人事或技术判断。
- 不替上级审批，不把建议写成已批准。
- 不虚构制度、权限、预算、金额、证据或管理者态度。
- 不建议绕过必要审批、隐瞒风险或越级施压。
- 涉及薪酬、纪律、健康、家庭、客户信用等敏感信息时，只保留完成沟通所需的最少信息。

## 运行流程

1. 识别沟通对象、层级关系和可能的决策权限。
2. 判断沟通目的：汇报、请示、审批、决策、升级、资源申请、例外申请、工作安排、个人事项、意见反馈或关系沟通。
3. 区分已确认事实、用户判断、推荐建议、待确认信息和冲突信息。
4. 提炼上级需要知道、需要判断、需要承担的内容。
5. 检查影响、风险、金额、资源、权限、时限和已采取动作。
6. 给出一个推荐方案；只有确有必要时再给备选方案。
7. 明确希望上级回复、批准、选择、协调或知悉什么。
8. 根据渠道、语气和紧急程度生成最终表达。
9. 准备上级最可能追问的问题和建议回答要点。

## 参数状态

正式输出前先判断参数状态，只使用：

```text
已命中
部分命中
缺失
冲突
待验证
```

最低运行参数：

| 参数 | 说明 |
|---|---|
| audience | 沟通对象及其与用户的关系 |
| subject | 需要沟通的事项 |
| purpose | 希望完成的沟通目的 |
| desired_response | 希望上级作出的决定或动作 |
| urgency | 回复期限或紧急程度 |

建议参数：

| 参数 | 说明 |
|---|---|
| confirmed_facts | 已确认事实及来源 |
| current_status | 当前进展或状态 |
| impact | 对目标、项目、团队、成本、客户或个人的影响 |
| actions_taken | 已采取的动作 |
| constraints | 权限、制度、时间、预算或资源限制 |
| options | 可选方案 |
| recommendation | 用户推荐方案及理由 |
| risks | 已知风险与不确定性 |
| channel | 即时消息、邮件、口头、会议、审批系统或正式汇报 |
| tone | 简洁、正式、协商、坚定、紧急或关怀 |
| sensitivity | 需要控制披露的敏感信息 |

信息不足但不影响安全表达时，生成“可先发送的初步版本”和待补充项。缺失内容会改变审批、责任、金额或风险结论时，停止生成确定性申请，只输出沟通框架和补充清单。

## 输出模式

根据用户要求选择以下一种或多种模式：

- `chat`：微信、企业微信、飞书、钉钉等即时消息。
- `email`：正式邮件。
- `verbal`：面谈、电话或临时口头汇报提纲。
- `meeting`：一对一或管理会议沟通提纲。
- `approval`：OA、费用、采购或其他审批系统说明。
- `briefing`：结构化汇报内容。
- `followup`：上级尚未回复时的跟进。
- `response`：回应上级追问。

用户只要求“帮我写一段话”时，默认输出可直接使用的简洁版本，不强制展示完整分析。

## 默认输出结构

信息复杂或用户要求分析时，输出：

1. 沟通类型与目标
2. 参数完整度和待确认项
3. 上级最关心的三个问题
4. 推荐沟通策略
5. 可直接使用的沟通文本
6. 上级可能追问的问题
7. 后续跟进建议

最终沟通文本遵循：

```text
结论或请求
→ 必要背景
→ 影响与风险
→ 已采取动作
→ 推荐方案
→ 需要上级决定什么
→ 回复期限
```

简单事项可压缩，但不得省略明确请求。

## 与其他 WorkFn Skill 协作

- 大量材料先使用 `zayn-keypoint` 提炼事实。
- 需要方案比较和领导拍板时，先使用 `zayn-decision`。
- 需要判断是否升级时，先使用 `zayn-escalate`。
- 正式工作汇报可先使用 `zayn-report` 或对应周期报告 Skill。
- 向平级同事或职能部门提出执行请求时，优先使用 `zayn-request`。
- 涉及价格、订单、付款、售后、项目或人事规则时，先使用相应专业 Skill 或可靠制度资料，再生成上级沟通。

仅在前置判断确有必要时串联 Skill。请假、调休、工作安排等信息明确的简单事项可直接使用本 Skill。

## 质量检查

输出前检查：

- 是否结论先行并明确需要上级做什么。
- 是否只保留支持判断的必要背景。
- 是否区分事实、推测、建议和待确认信息。
- 是否说明真正重要的影响、成本、风险和时限。
- 是否给出推荐方案而非只抛出问题。
- 是否避免把申请、建议或预计写成已批准事实。
- 是否符合沟通渠道和上下级关系。
- 是否披露了不必要的敏感信息。
- 是否存在情绪绑架、推责、威胁或越级施压。
