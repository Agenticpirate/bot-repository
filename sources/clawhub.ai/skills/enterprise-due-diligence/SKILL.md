# 企业尽调 (Enterprise Due Diligence)

## Overview

本技能对目标企业进行全面尽职调查，覆盖法律、财务、业务三大维度。自动通过企查查公开接口获取企业工商信息，结合用户提供的财报/合同等文档，AI完成三维度分析推理，最终生成结构化Word报告和检查清单。

**触发词**: 企业尽调、公司背景调查、投资尽调、DD、due diligence、corporate background check、帮我尽调、查一下这家公司

**输出**:
1. **尽调报告** (Word docx) — 结构化的完整报告，含封面+7章正文+附录
2. **尽调检查清单** (Word docx) — 30项检查表，四色状态标记

## 核心工作流（7步）

### Step 1: 信息采集

**目标**: 获取被调企业基本信息 + 用户提供的文档

1. 向用户确认被调企业**完整名称**（含全称和简称）
2. 询问用户是否有已有文档提供（财务报表、合同文本、工商资料、尽调问卷等）
3. 收集用户提供的文档路径，识别文件类型（Excel/PDF/Word/图片）
4. 调用 `fetch_company_data.py` 尝试从企查查获取公开工商信息
5. 若企查查数据不可得，标记"待核实"并继续

**调用方式**:
```bash
python scripts/fetch_company_data.py "企业名称"
```

**输出**: 企业基本信息 dict (JSON格式打印到stdout)，包含：
- basic_info: 名称/信用代码/法人/注册资本/成立日期/注册地址/经营范围
- equity: 股东列表、持股比例
- lawsuits: 诉讼记录、被执行信息
- ip: 商标/专利/软著信息
- management: 高管信息
- financing: 融资历史

### 无 API 数据校验策略（数据质量五规则）

用户无企查查/爱企查等开放平台 API（未配置 QICHACHA_TOKEN、连接器未连接）时，按以下五规则保证数据准确性（完整版见 `references/data_quality.md`）：

1. **多源轮询**：关键字段至少 2 个网页源交叉（企查查/爱企查/天眼查/启信宝/水滴/爱诺特）；某平台不显示的字段（如实缴资本）换平台获取或请用户截「工商注册详情页」。
2. **权威裁决**：冲突时按信任级裁决——上市公司公告 / NMPA 注册证 / 国家企业信用信息公示系统 > 启信宝/爱企查/天眼查 > 行业媒体 > 用户口述。
3. **时间戳优先**：取最新变更记录并注明时点；历史口径并存标注，不静默覆盖（如不同平台实缴资本显示值不一致时，以最新变更记录为准并标注历史值）。
4. **用户截图兜底**：关键字段缺失/冲突时，主动生成优先级「请截图清单」（历史信息 → 工商详情 → 股东 → 知产 → 主要人员 → 司法 → 企业图谱）；截图按「用户提供 > 公开数据」采纳，标蓝 + 来源「用户提供XX截图+时间」。
5. **必核字段红标**：实缴/法人/参保/注册资本/历史名称/股东出资明细/司法/处罚等必核字段无 2 源 → 标红「待核实」，不臆断。

### Step 2: 法律尽调

**目标**: 评估企业的法律合规风险

基于 Step 1 获取的数据和用户提供的文档，从以下维度进行分析：

#### 2.1 公司基本信息核实
- 注册资本是否与经营范围匹配
- 注册地址与实际经营地址是否一致（如可得）
- 成立年限与行业平均对比

#### 2.2 股权架构分析
- 股权结构是否清晰（是否存在代持、质押、多层嵌套）
- 实际控制人是否明确
- 股东之间是否存在关联关系
- 特殊架构说明（如双实体、VIE等）

#### 2.3 司法诉讼风险
- 在审案件类型和金额
- 被执行信息
- 失信限高记录
- 劳动争议情况

#### 2.4 知识产权分析
- 专利数量/类型/状态（发明、实用新型、外观设计）
- 商标注册类别和状态
- 软著数量
- 知识产权风险（是否涉及侵权、FTO问题）
- 发明人/设计人的在职状态

#### 2.5 合规性检查
- 行政许可和资质证书
- 行政处罚记录
- 行业特殊监管要求

**分析判断标准**:
- 股权结构有争议或瑕疵 → 高风险 (P0)
- 存在重大未决诉讼（金额>注册资本20%）→ 高风险 (P0)
- 存在被执行/失信记录 → 高风险 (P0)
- 核心专利即将到期或失效 → 需关注 (P1)
- 行政处罚金额不大且已整改 → 需关注 (P1)
- 无上述问题 → 正常

---

### Step 3: 财务尽调

**目标**: 评估企业的财务健康状况

> 注意：财务数据通常来自用户提供的文档（企查查等公开源一般不提供详细财务数据）

#### 3.1 财务报表分析（数据可得时）
- 资产负债表分析：资产负债率、资产结构、负债结构
- 利润表分析：收入增长率、毛利率、净利率
- 现金流量表分析：经营性现金流是否健康

#### 3.2 关键财务比率
- 偿债能力：流动比率、速动比率、利息保障倍数
- 营运能力：应收账款周转率、存货周转率
- 盈利能力：ROE、ROA、净利率
- 增长能力：收入复合增长率

#### 3.3 税务合规
- 是否正常纳税
- 是否存在重大欠税
- 是否享受税收优惠
- 税务处罚记录

#### 3.4 关联交易分析（数据可得时）
- 是否存在重大关联交易
- 关联交易是否公允
- 是否存在利润转移嫌疑

#### 3.5 其他财务风险
- 应收账款账龄和回收风险
- 存货跌价风险
- 表外负债（对外担保等）

**分析判断标准**:
- 财务数据疑似造假 → 高风险 (P0)
- 资产负债率 > 70% → 需关注 (P1)
- 经营性现金流持续为负 → 需关注 (P1)
- 重大欠税 → 高风险 (P0)
- 财务数据不可得 → 标记待核实，不妄下结论

---

### Step 4: 业务尽调

**目标**: 评估企业的商业价值和可持续性

#### 4.1 核心业务分析
- 产品/服务是什么（清晰描述）
- 商业模式（B2B/B2C/混合？盈利模式？）
- 收入来源结构

#### 4.2 市场地位与竞争格局
- 目标市场规模和增长率
- 市场占有率（如有公开数据）
- 主要竞争对手分析
- 差异化优势

#### 4.3 核心团队分析
- 创始人和核心高管背景（教育、工作经验、行业声誉）
- 团队完整度（研发/市场/管理/财务各职能是否齐备）
- 核心技术人员稳定性和激励机制

#### 4.4 客户与供应商分析
- 客户集中度（前5大客户占比）
- 供应商集中度
- 是否存在单一依赖风险
- 客户复购率和留存情况

#### 4.5 核心产品分析
- 产品/服务的完整名称和品牌
- 产品类别与形态（硬件/软件/平台/服务等）
- 核心功能与定位
- 产品技术路线与成熟度
- 服务对象（B端/C端/医疗机构/个人消费者等）
- 使用场景（具体在什么环境下使用、解决什么问题）

#### 4.6 行业环境分析
- 行业所处周期（初创/成长/成熟/衰退）
- 政策环境（监管趋严还是利好）
- 技术壁垒和替代风险

**分析判断标准**:
- 核心团队流失 → 高风险 (P0)
- 单一客户/供应商占比 > 50% → 需关注 (P1)
- 行业政策趋严 → 需关注 (P1)
- 商业模式不可持续 → 高风险 (P0)

---

### Step 5: 风险评估

**目标**: 综合三维度发现，按统一风险框架评级

#### 风险等级体系（P0/P1/P2 三级，参考内部模板 B 设计）

| 级别 | 含义 | 决策影响 |
|------|------|----------|
| **P0 - Deal Breaker** | 致命风险，可能推翻交易 | 建议暂缓或终止交易，需深入调查 |
| **P1 - Material** | 重大事项，需要关注 | 建议在交易结构中加入保护条款 |
| **P2 - Informational** | 参考信息，无需立即行动 | 了解即可，持续跟踪 |

#### 综合评级规则
- 任一维度有 ≥1 项 P0 → 综合评级 **P0（高风险）**
- 任一维度有 ≥2 项 P1 且无 P0 → 综合评级 **P1（需关注）**
- 所有维度均正常 → 综合评级 **正常**
- ≥30% 检查项为"待核实" → 标注**数据不完整，需补充**

#### 风险矩阵输出格式
```
【风险矩阵摘要】
P0 - Deal Breaker（X项）: [列表]
P1 - Material（X项）: [列表]
P2 - Informational（X项）: [列表]
综合评级: [P0/P1/正常/数据不完整]
```

### Step 6: 生成报告和检查清单

**目标**: 将分析结果输出为格式化的 Word 文档

#### 6.1 生成尽调报告

调用 `generate_dd_report.py`，传入分析数据：

```bash
python scripts/generate_dd_report.py \
  --data dd_data.json \
  --company "企业名称" \
  --output "输出路径.docx" \
  --template lite    # 可选：lite（默认，轻量版）| standard（基础版）
```

**数据格式** (JSON):
```json
{
  "basic_info": { "name": "...", "credit_code": "...", ... },
  "equity": [ { "shareholder": "...", "ratio": 60, "type": "自然人" } ],
  "lawsuits": [ { "case_type": "...", "status": "审理中", "amount": 1000000 } ],
  "ip": { "patents": [...], "trademarks": [...], "copyrights": [...] },
  "management": [ { "name": "...", "position": "CEO", "background": "..." } ],
  "financing": [ { "round": "A轮", "amount": 50000000, "investors": "..." } ],
  "products": [ { "name": "...", "description": "...", "category": "B端" } ],
  "legal_analysis": { "risk_level": "正常", "findings": [...], "notes": "..." },
  "financial_analysis": { "risk_level": "待核实", "findings": [...], "notes": "数据不可得" },
  "business_analysis": { "risk_level": "正常", "findings": [...], "notes": "..." },
  "risk_matrix": { "p0": [...], "p1": [...], "p2": [...] },

```

#### 6.2 生成检查清单

```bash
python scripts/generate_dd_checklist.py \
  --data checklist_data.json \

  --output "输出路径.docx"
```

> **数据优先级**: 用户提供的文档信息 > 企查查公开数据。当两者冲突时，以用户提供为准，但需标注差异。

### Step 7: 交付

1. 将生成的报告和检查清单交付给用户
2. 向用户口头/文字说明风险高亮项（哪些是P0/P1）
3. 提醒用户哪些字段因数据不可用标注为"待核实"
4. 建议用户补充哪些材料以完善尽调

**交付示例**:
```
【企业尽调完成】— XX科技有限公司

📄 尽调报告: XX科技_尽调报告_2026-07-28.docx

⚠️ 综合风险评级: P1-需关注
- P0 (Deal Breaker): 无
- P1 (Material): 2项 — 核心专利FTO未完成、注册时间表不确定
- P2 (Informational): 3项 — 详见检查清单

❓ 待核实项: 5项（财务数据未提供）
建议补充: 近两年审计报告、核心团队劳动合同
```

## 模板版本选择（standard 基础版 / lite 轻量版）

生成报告前，先确认用户想要的模板版本（两版均通过 `generate_dd_report.py --template` 参数输出）：

| 版本 | 结构 | 定位 | 数据要求 | 触发词 |
|---|---|---|---|---|
| **lite**（默认） | 轻量版 5 章 + 附录（基本信息/团队/知产/融资/产品 + 红色风险标注内嵌） | 轻量版，公开信息初筛 / 快速背景调查 | 纯公开渠道即可成稿 | 默认；「轻量版」「轻量」「快速初筛」「lite」 |
| **standard** | 7 章 + 附录（法律/财务/业务三维度 + P0/P1/P2 风险矩阵） | 基础版，投资/并购级完整尽调 | 需用户提供财报等一手材料（不可得时标「待核实」） | 「基础版」 |

- 用户未明确要求时，默认 **lite（轻量版）**；明确说「基础版」时才使用 7 章版本。
- lite 版样式：封面 42pt #1A1A2E；章/节标题 14/13pt #1A1A2E；表头 #0F3460 白字；融资要点 14pt #0072C6；风险/待验证标注 10.5pt 加粗 #EE0000；正文说明 10.5pt #444444；产品方向标题 13pt #0F3460；附录来源 9pt #4F81BD；免责 9pt #888888；A4 页面。
- 两版标题均使用内置 Heading 样式（导航窗格可用）；lite 版数据结构与样式细节见 `references/report_template.md` 的 Lite 章节。
- **lite 板块分页**：六个板块（一、二、三、四、五、附录）各自从新页开始——章节标题使用「段前分页」（pageBreakBefore，见脚本 `_add_lite_chapter`），不依赖显式分页符，内容增删后分页不漂移。

- 核心高管背景表

- 商标注册情况
- 核心技术评估

### 第四章：财务分析与税务情况
- 财务报表摘要（数据可得时）
- 关键财务比率
- 税务合规情况
- 关联交易分析
- 数据不可得时标注"【待核实】"

### 第五章：业务与市场分析
- 核心产品/服务分析
- 商业模式分析
- 市场与竞争分析
- 客户与供应商分析

### 第六章：融资历史与估值
- 融资轮次列表
- 估值变化

### 第七章：风险评估与结论
- 综合风险矩阵
- 各维度风险评级
- 尽调结论
- 下一步建议

### 附录
- 数据来源清单
- 免责声明

## 检查清单结构

Word文档，表格形式，覆盖30项检查点：

**法律维度（12项）**
| 序号 | 检查项 | 来源 | 状态 | 备注 |
|------|--------|------|------|------|
| 1.1-1.12 | 注册信息/股权/诉讼/IP/资质等 | 公开/文档 | ⬜ | |

**财务维度（10项）**
| 序号 | 检查项 | 来源 | 状态 | 备注 |
|------|--------|------|------|------|
| 2.1-2.10 | 报表/比率/税务/关联交易等 | 用户提供 | ⬜ | |

**业务维度（8项）**

## 风险管理说明

### P0 - Deal Breaker 类风险
```
条件：
1. 重大在审诉讼/被执行/失信
2. 知识产权侵权或核心IP失效
3. 财务数据造假/重大异常
4. 核心团队全部流失
5. 重大违法违规处罚
6. 股权结构有致命缺陷

处理：标记为P0，在交付时重点提醒用户
```

### P1 - Material 类风险
```
条件：
1. 单一客户/供应商占比>50%
2. 资产负债率>70%
3. 持续经营性现金流出
4. 短期偿债压力大
5. 关联交易不公允
6. 行业政策明显趋严
7. 股权结构较复杂

处理：标记为P1，在报告中详细说明
```

### P2 - Informational 类风险
```
条件：
1. 产品注册时间表不确定
2. 团队尚不完整
3. 行业竞争加剧
4. 需补充验证的数据

处理：标记为P2，在检查清单中记录
```

## 实战经验补充（2026-08 实战验证）

### 无 QICHACHA_TOKEN / 无企查查连接器时的公开渠道采集
fetch_company_data.py 依赖 QICHACHA_TOKEN，未配置时直接走 WebSearch/WebFetch 公开渠道，可覆盖 90% 工商数据：

| 数据维度 | 推荐渠道 |
|---|---|
| 工商信息/股东/主要人员/变更记录/行政许可 | 企查查企业页（qcc.com/firm/…）、水滴信用（shuidi.cn）、启信宝（qixin007.com）、爱诺特（innotop.com.cn，含疑似最终受益人/知识产权总量） |
| 融资历史 | 36氪 PitchHub（pitchhub.36kr.com）、动脉橙 vbdata（vbdata.cn）——两平台均无记录则写「未公开披露」 |
| 专利明细 | 企查查企业动态时间线 + 国家知识产权局公布文本（可经 max.book118 专利公报核实 CN 号） |
| 团队/产品/行业 | 行业媒体深度报道（动脉网、智慧医械、南方+等）、传感器行业站（sensorexpert.com.cn）、公司官网 |
| 荣誉/政策 | 地方政府人才政策新闻、行业榜单等 |

注意：各平台实缴资本、员工人数、行业分类口径可能不一致（如实缴资本多平台金额不一致时），报告中应取最新变更记录并注明口径差异。

### 模板变体：轻量版（5 章，已正式化为 Lite 模板）
> 本变体已于 2026-08 正式化为 `--template lite`（轻量版），结构与样式见上方「模板版本选择」及 `references/report_template.md` 的 Lite 章节；本节保留历史说明。

用户要求「轻量版」时，用 5 章框架替代本技能默认 7 章（基础版）：
封面 + 目录 + 一、公司基本信息与股权架构（1.1基础信息两列表/1.2经营范围/1.3股权结构/1.4主要人员）+ 二、核心团队画像（维度-信息表）+ 三、知识产权与专利 + 四、融资历史与资本结构（含红色融资要点）+ 五、核心产品（分方向多表+核心技术+行业市场）+ 附录来源清单 + 免责声明。
样式参数：正文微软雅黑 11pt；章/节标题 14/13pt 加粗 #1A1A2E；表头白字 #0F3460 底纹；融资要点标题 14pt #0072C6；风险/待验证标注 10.5pt 加粗 #EE0000；正文说明 10.5pt #444444；产品方向标题 13pt 加粗 #0F3460；附录来源 9pt #4F81BD；免责 9pt #888888；A4 页面、边距 2.5cm。生成脚本基于 python-docx 1.2.0（需本地虚拟环境安装依赖），实现见 `scripts/generate_dd_report.py`。
