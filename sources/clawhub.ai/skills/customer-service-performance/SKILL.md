# 客服坐席绩效核算

读取坐席工作量数据与绩效规则 → 逐人按规则核算 → 输出透明的绩效明细、团队分布与待人工复核清单。

## 核心原则

1. **复核优先**：核算结果是给管理者复核用的参考，不是最终考核裁决。绩效关联薪酬与考核，用于任何管理决策前必须人工复核确认。输出中强制标注"供复核参考，以人工确认为准"。
2. **计算全透明**：每个坐席的每个维度，必须列出原始值、命中的规则档位、该维度得分、权重与加权结果，逐项可核。绝不只给一个总分而不给推导过程——算错时要能一眼定位到哪一步。
3. **不排名、不点名**：可按总分排序展示、可给团队分布对比，但不输出"末位 N 名""Bottom 名单""S/A/B 强制梯队"这类人事评判结论——那是管理者的职责，不是核算工具的输出。团队汇总必须标注样本量。
4. **缺失值待复核，不按 0**：某坐席某项数据缺失时，该维度标记为"待人工复核"并计入待复核清单，**绝不静默按 0 计分**（按 0 会直接错误拉低该人得分）。
5. **本地处理**：数据含员工信息，全程本地处理不外传。输出中对可识别到个人的敏感字段（工号之外的手机号、身份证等，如有）做掩码。

## 工作流

### 第 1 步：读取数据与规则

用户会提供两份文件（Excel 或 CSV）：
- **工作量数据表**：一行一个坐席，含坐席标识与各项考核指标（如在线时长、接待量、好评数、差评数、解决率、响应时长等）。
- **绩效规则表**：定义各维度的权重、阶梯计分标准（如"在线占比 ≥90% 得 30 分，80%-90% 得 20 分…"）。

直接读取用户提供的文件（Excel/CSV 由运行环境解析，无需用户预处理）。查看两份表的表头，把数据表的指标列与规则表的维度按语义对应。列名不确定、或规则表某维度在数据表中找不到对应指标时，向用户确认一次，不猜测。

若用户只提供了数据表没有规则表，加载 `references/rules-default.md` 的通用规则；若用户提供了自己的规则表，以用户规则为准。

### 第 2 步：介绍本次规则

读取规则后，用 3-5 行简述本次采用的维度、权重与阶梯档位（以规则表实际内容为准），给用户一次调整机会，但不等待，说明后直接继续。

### 第 3 步：逐人核算

按坐席逐行处理，每个坐席：
1. 对每个维度：取原始值 → 匹配阶梯档位 → 得该维度分 → 乘权重。**记录这一串中间值供输出。**
2. 加权求和得总分。计算除法类指标（好评率、解决率）时注意分母为零的情况（如差评数为 0），按规则处理并在备注说明。
3. **缺失值检查**：任一维度所需数据缺失 → 该维度不计分、标记"待复核"，该坐席进入待复核清单，其总分标注"含待复核项，不完整"。

### 第 4 步：生成结果

输出一个 Excel（环境不支持则 Markdown 表格），含：

**Sheet1 绩效明细**：坐席 | 各维度[原始值/档位/得分/加权] | 总分 | 状态（正常/含待复核项）。逐项透明，一眼可复核。
**Sheet2 团队分布**：总分区间分布、各维度平均分、最高/最低分区间（**只给分布，不点名到人**）；标注参与核算人数。
**Sheet3 待人工复核**：坐席 | 待复核维度 | 原因（数据缺失/规则未覆盖/除零等）| 建议。

报告开头附摘要（≤150 字）：核算人数、平均分、得分最集中区间、待复核人数。**结尾强制标注**："本结果由规则自动核算，供人工复核参考，用于薪酬/考核决策前请独立验证。"

### 第 4.5 步：交付前自检（必做）

1. **总分账**：每人总分 = 各维度加权得分之和，逐行验算。
2. **一致性账**：明细中每个维度的"得分×权重"与加权列一致；待复核维度未被计入总分。
3. **人数账**：明细行数 + 未处理/待复核独立人数口径清晰，核算人数 = 输入坐席数 - 完全无法核算的人数。
任一账不平，先修正再交付。

### 第 5 步：收尾

提醒用户：结果供复核参考，重点看 Sheet3 待复核项；如规则与本次不符，可上传自有规则表重新核算。

## 错误处理

- 数据表或规则表无法识别表头：展示前几行请用户确认列含义，不猜测。
- 单个坐席数据整行异常（乱码/关键字段全缺）：列入待复核清单说明原因，不中断整体，不按 0 硬算。
- 规则表阶梯定义有歧义（如档位区间重叠或有缺口）：按最接近的档位计算并在备注标注歧义点，提示用户核对规则。
