# 专家团即时拉起

## 定位

本技能是「专家团即时拉起」领域的领域负载物：收到任务后即时判定是否需要专家团、动态设计最小团队、**直接临时拉起运行**至任务交付——角色提示词即席生成、内联注入调度调用，不落盘为系列提示词交付物。

依赖声明：本技能仅依赖自身 references/ 下的三层结构文件、templates/ 模板、scripts/ 设计校验脚本与通用任务执行能力（三轴正交框架），不依赖任何其他领域技能。

**固化边界**：本技能交付任务结果与执行摘要，临时团队随交付释放；若某次团队设计具有复用价值，仅输出固化建议（设计要点、复用场景、建议形态），固化与资产化的具体实现不在本技能范围内，由用户另行决定。

## 核心能力

1. **判定与路由**：任务接收、专家团必要性判定（判定依据须向用户展示）、运行方案规划（团队形态 + 拉起机制三态）
2. **动态设计**：编排者 + 成员角色设计（职责互斥）、SOP 阶段编排（3~5 阶段）、角色提示词即席生成
3. **拉起运行**：团队实例化、成员调度执行（并行/串行按 SOP）、消息中转与进度通报
4. **守护校准**：阶段门禁校验、缺口修正循环、七项质量验证
5. **整合交付**：产出汇编、交付与团队释放、执行复盘（可复用团队建议固化为正式资产）

## 领域特有维度

| 维度 | 说明 | 影响 |
|------|------|------|
| 临时性 | 团队随任务创建、随交付释放，不遗留常驻资源 | 产出物是任务结果而非团队文档；交付后强制释放 |
| 直接运行性 | 提示词即席生成并内联注入调度调用，不交付系列提示词文件 | 提示词质量在运行中经门禁校准，而非交付前人工审阅 |
| 形态适配性 | 拉起机制三态（团队工具/子代理/单会话分段） | 规划阶段必须先判定机制，实例化按机制执行 |

## 使用规则

### 执行流程
1. **首次加载**：读取 `references/on-demand-expert-team-catalog.md`，获取域分类、依赖拓扑与元操作映射提示
2. **按需深入**：进入某域执行前，读取 `references/on-demand-expert-team-requirements.md` 对应域的任务要求；需要模仿产出时按 `references/on-demand-expert-team-exemplars.md` 索引读取对应范本
3. **生成执行**：按 catalog 依赖拓扑编排管线逐任务执行；结构类组件（团队设计文档、角色提示词）优先从 templates/ 模板填充；角色提示词即席生成后内联注入调度调用，不落盘为交付物
4. **门禁校验**：团队设计定稿前运行 `python scripts/validate_team_design.py <设计文档路径>` 预检；每个 SOP 阶段结束执行阶段门禁；FAIL 项修正后复检，全部通过再进入下一阶段

### 内容权限
5. **修改权限**：本技能 references/ 内容按领域负载物规范维护；运行机制或约束变更时，先更新 requirements 对应任务要求，再同步范本与脚本，保持三者一致
6. **用户补充**：用户可提供满意的临时团队案例（脱敏后按范本标准格式放入 references/ 并在索引登记），作为后续样本法参考

### 降级模式

| 模式 | 权限 |
|------|------|
| 标准模式 | 读写目标目录、执行 scripts/、拉起子代理/团队、生成全部产出 |
| 只读模式 | 仅读取与判定（OD0、OD1 设计稿以对话呈现），不拉起任何代理、不写任何文件 |
| 禁写模式 | 无法落盘时，任务结果以对话形式直接交付；团队设计文档以代码块输出由用户自行保存 |

### 提示词导出
7. 可将本技能合并为单一提示词文件用于不支持 skill 目录格式的工具。合并顺序：SKILL.md → on-demand-expert-team-catalog.md → on-demand-expert-team-requirements.md → on-demand-expert-team-exemplars.md → references/ 下各范本文件（按 OD0→OD4）。命令示例：`cat SKILL.md references/on-demand-expert-team-catalog.md references/on-demand-expert-team-requirements.md references/on-demand-expert-team-exemplars.md references/OD*.md > on-demand-expert-team-prompt.md`

## 与执行框架的接口

本技能通过以下五步接入通用任务执行框架（三轴正交），任何拉起请求都从 Step 0 进入：

- **Step 0 三轴判定**：复杂度（满足组建判断标准任一=中等；多领域多阶段并行=复杂；均不满足=简单，单专家直办）、内容类型（任务结果为主，附团队设计记录）、创新需求（默认无需创新；角色与 SOP 设计属受约束创造）
- **Step 1 领域校准**：按本领域 R1-R5 参数校准执行（见下）
- **Step 2 三轴分解**：执行轴按 catalog 依赖拓扑分解为 OD0→OD1→OD2→OD3↻→OD4 管线；内容轴对设计类组件启用清单法；创新轴默认关闭
- **Step 3 管线编排与执行**：并行阶段成员调度扇出（⇉）、串行阶段等待前序产出；每阶段结束做基元内分步校准（阶段门禁）
- **Step 4 整合交付**：编排者汇编成员产出 → 交付任务结果与执行摘要 → 团队释放 → 复盘记录

**Step 1 领域校准的领域特定推导**：

| 参数 | 本领域取值 | 执行影响 |
|------|-----------|---------|
| R1 信息密度 | 中（设计稿与阶段产出密集，无字段级规范表） | S/C 权重中：设计前必须核对组建判断标准与门禁清单，禁止凭感觉组团 |
| R2 创造性 | 中高（角色设计、SOP 编排、提示词即席生成可创造） | A 权重高：提示词按 templates/ 模板+清单法生成；团队构成受最小团队原则约束 |
| R3 交互性 | 中（入口确认目标与关键约束；过程中按阶段通报） | I 权重中：OD0-01/OD0-02 需用户输入或确认；运行中非必要不打断 |
| R4 规范性 | 中高（编排者铁律、职责互斥、基元≤5 为硬约束） | G 权重高：阶段门禁为强制环节；缺口修正循环 ≤3 次 |
| R5 迭代性 | 高（阶段门禁→缺口补拉→复检循环贯穿运行期） | 循环多：S→C→A 链短而频，每阶段一轮 |

**拉起机制三态**（OD0-03 判定、OD2-01 执行）：

| 态 | 触发条件 | 实例化方式 |
|----|---------|-----------|
| 态1 团队工具态 | 当前环境可用 TeamCreate/SendMessage 等团队工具 | 建团并拉入成员，编排者按编排者铁律调度 |
| 态2 子代理态 | 可用 Agent/子代理工具 | 每成员以子代理拉起（调度时 name 参数传成员角色名中文），本会话承担编排者职责 |
| 态3 单会话态 | 无多代理工具 | 以"角色分段+基元内分步校准"按 SOP 顺序在单会话内等效运行，各段产出标注执行角色 |

**自治度**：判定与设计⬛全自动（判定依据须向用户展示）、拉起运行⬛全自动、缺口修正🟨半自动（循环超限须用户决策）、最终交付⬛全自动（交付后接受反馈迭代）。

## 通用任务执行能力

**三轴正交**：执行轴（How，必选）+ 内容轴（What，按需）+ 创新轴（Why Different，按需）。

**执行轴**：6 大元操作 S 感知（接收任务、读取上下文与附件）/ C 认知（必要性判定、角色设计、SOP 编排）/ A 行动（提示词生成、拉起实例化、调度执行）/ O 组织（成员登记、产出归集）/ I 交互（目标确认、进度通报）/ G 守护（阶段门禁、缺口修正、质量验证）；6 种编排模式：顺序→、并行‖、条件?、循环↻、扇出⇉、扇入⇇；7 种通用管线模式 P1~P7。本领域默认管线：入口前接 P4 条件分支（组团或直办），主体为 P5 交互驱动（阶段通报）嵌套 P2 迭代精炼（门禁循环）。

**内容轴**：清单法（团队设计文档 = 字段清单逐项填充）+ 样本法（模仿 references/ 下 OD0~OD4 范本的结构与风格，不复制内容）。

**创新轴**：默认关闭；仅在用户对团队构成、SOP 提出差异化要求时启用，创新后仍须通过门禁校验。

**三轴协同**：顺序协同（判定→设计→拉起→守护→交付）为默认；并行阶段启用并行协同；门禁 FAIL 时启用迭代协同（G 发现问题 → 回到对应 A/C 任务修正）；单会话态下启用递归协同（角色分段内部可再套基元链）。

**核心公式**：产出 = 元操作（S/C/A/O/I/G 管线）× 本负载物（references/ 任务要求 + templates/ 模板 + OD 系列范本）。

## 域概览

按运行流程组织，共 5 域 15 种任务：

| 域 | 任务数 | 典型任务 |
|----|--------|---------|
| OD0 判定路由域 | 3 | 任务接收与需求感知、专家团必要性判定、运行方案规划 |
| OD1 动态设计域 | 3 | 团队角色设计、SOP 阶段编排、角色提示词即席生成 |
| OD2 拉起运行域 | 3 | 团队实例化、成员调度执行、消息中转与进度通报 |
| OD3 守护校准域 | 3 | 阶段门禁校验、缺口修正循环、质量验证 |
| OD4 整合交付域 | 3 | 产出整合汇编、交付与团队释放、执行复盘 |

**域间逻辑流**：OD0 → OD1 → OD2 → OD3（↻ 缺口修正）→ OD4；OD0-02 判定"无需专家团"时条件退出、单专家直办后交付。

完整任务清单与依赖拓扑见 `references/on-demand-expert-team-catalog.md`；任务要求见 `references/on-demand-expert-team-requirements.md`；范本索引见 `references/on-demand-expert-team-exemplars.md`。

## 事实纪律

1. 仅使用本技能 references/ 中确知的机制与约束，不得编造平台工具名或能力边界；环境能力不确定时按拉起机制三态降级处理
2. 组团判定必须向用户展示依据，不得跳过判定直接拉起
3. 每个成员必须有明确职责边界与输出物，职责重叠的成员应合并
4. 编排者不代写成员专业产出；跨成员信息流必须经编排者中转
5. 质量门禁必须逐项核对，不可凭感觉通过；缺口修正循环 ≤3 次，超限须用户决策
6. 任务结果中引用的事实与数据必须确知真实存在，不确定的标注"待验证"
7. 样本法模仿范本时仅借鉴结构与风格，不复制范本的业务内容
