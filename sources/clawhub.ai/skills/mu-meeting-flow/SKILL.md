**IRON LAW：①日程创建前必须查忙闲确认无冲突，禁止盲建日程导致撞车；②会后纪要/TODO 必须基于实际转写或录音内容，禁止编造未发生的讨论；③适配器未配置时必须走降级路径（手动模式），禁止跳过该步骤直接报错中断。无例外。**

# mu-meeting-flow — 会议全流程编排 Skill

## 适配器架构

本 Skill 通过**能力描述 + 接口约定 + 推荐工具 + 降级方案**对接外部服务，不写死任何特定工具。用户在 `config/adapters.json` 中声明自己的工具，Agent 按配置调用；未配置的模块自动降级为手动模式（Skill 给出操作指导，用户自行完成，流程不中断）。

六个核心适配器：

| 能力 | 用途 | 推荐工具 | 未配置时降级 |
|------|------|---------|-------------|
| 日历 | 查忙闲/建日程/改期/取消 | Google Calendar / Cal.com / ICS | 跳过忙闲校验，输出日程信息让用户手动创建 |
| 转写 | 会议录音→结构化文本 | Whisper.cpp / faster-whisper / 平台字幕 | 提示用户手动记录或上传笔记 |
| 文档 | 读写会议文档/纪要 | Notion / Obsidian / 本地 Markdown | 直接在对话中输出内容 |
| 通知 | 推送消息给参会人 | Slack / Email / Webhook | 输出消息文本让用户自行发送 |
| 会议室 | 预订/查询/借用会议室 | Google Workspace / Office365 | 跳过，标注"需用户自行安排场地" |
| 会议平台 | 查询会议记录/获取录制 | Zoom / Google Meet / Teams | 提示用户手动提供笔记或转写文本 |

> 适配器接口契约与降级规则详见 [references/integration-rules.md](references/integration-rules.md)

## 自动触发规则

当用户消息涉及以下场景时，自动调用本 Skill 全流程：

| 触发信号 | 动作 |
|----------|------|
| 帮我开个会 / 约XX聊 / 预约会议 | 一条龙全流程 |
| 帮我订会议室 / 订个会议室 | 不只订室 → 走全流程（订室+建日程+材料） |
| 查忙闲 / 改期 / 取消会议 | 日程管理流程 |
| 会议总结 / 纪要 / TODO / 会后 | 会后自动化流程 |
| 准备会议 / 会前材料 | 会前准备流程 |
| 借会议室 / 会议室全满 | 借会议室流程 |
| 修改适配器配置 / 重新配置适配器 | 重新触发首次使用引导 |

**核心原则**：用户说的是一个点（比如"订会议室"），但要做的是一条线（从排期到纪要的完整闭环）。永远不让用户逐步指挥，主动推进到下一步。

## 首次使用引导

**触发条件**：检查 `config/adapters.json` 是否存在。不存在 → 进入首次引导；存在 → 跳过，直接走流程。

**引导流程**（一次性，完成后不再打扰）：

1. 简要说明：「本 Skill 通过适配器对接你的日历、转写、文档等工具。你可以现在配置，也可以跳过——未配置的能力会降级为手动模式，流程不中断，但自动化程度会降低。」
2. 逐个询问六个适配器，每个只问一句，用户可跳过：

| 适配器 | 问法 | 用户回答后 |
|--------|------|-----------|
| 日历 | 「你用 Google Calendar 还是其他日历？跳过的话查忙闲和创建日程需要你手动操作。」 | 写入 `calendar.provider` |
| 转写 | 「会议转写用 Whisper 还是会议平台自带字幕？跳过的话会后纪要需要你手动提供笔记。」 | 写入 `transcription.provider` |
| 文档 | 「会议文档放 Notion、Obsidian 还是本地文件夹？跳过的话纪要直接在对话里输出。」 | 写入 `knowledge.provider` |
| 通知 | 「会后通知发 Slack、邮件还是不用？跳过的话通知文本输出给你自己发。」 | 写入 `messaging.provider` |
| 会议室 | 「需要自动订会议室吗？用 Google Workspace 还是 Office365？跳过的话需要你自己安排场地。」 | 写入 `room.provider` |
| 会议平台 | 「会议平台用 Zoom、Meet 还是 Teams？跳过的话查会议记录需要你手动提供。」 | 写入 `meeting.provider` |

3. 生成 `config/adapters.json`（用户回答的写入对应 provider，跳过的写 `"none"`）
4. 确认完成：「✅ 配置已保存。后续可以随时说"修改适配器配置"重新设置。现在继续帮你处理会议。」

**规则**：
- 引导只执行一次。已存在 `config/adapters.json` 时跳过。
- 用户可随时说"修改适配器配置"重新触发引导。
- 引导过程中用户不耐烦（如"先跳过""以后再说"）→ 全部写 `"none"`，立即继续主流程。
- 不阻塞主流程：引导完成后立即接续用户原始请求，不让用户说第二遍。

## 先做后报模式

用户给出会议需求后，Agent 一口气执行全部步骤，只在必须人工决策时才暂停。正常场景：一句话进，一句话出。

| 原则 | 说明 |
|------|------|
| 默认自动 | 查忙闲→选时段→订室→建日程→出材料，串行完成，中间不问 |
| 偏好驱动 | 按用户已知偏好自动选择，不重复确认 |
| 模板自动匹配 | 识别会议类型后直接套模板 |
| 冲突才暂停 | 只有命中暂停条件表时才询问用户 |
| 结果一次性报 | 全部完成后一次性汇报 |

### 暂停条件

| 暂停条件 | 处理方式 |
|----------|---------|
| 参会人全忙 | 列冲突详情 + 推荐替代时段，问"选哪个" |
| 会议室全满 | 触发借会议室流程，展示候选+话术 |
| 参会人标识不确定 | 列出候选，问"是哪位" |
| 跨天/超长会议 | 时长 >4 小时或跨天 → 确认是否需要培训室 |

### 自动决策规则

**时段评分函数**：14:00-16:00 权重5 > 10:00-12:00 权重4 > 16:00-17:30 权重3 > 09:00-10:00 权重2。午休(12:00-13:00)和下班后(17:30后)硬排除。同等评分时整点 > 半点；接近用户期望时间 +2 权重。

**人数→房型映射**：1-2人→小型(4人) | 3-5人→中型(6-8人) | 6-10人→大型(10-14人) | 11-20人→超大(20人) | >20人→暂停确认

**时长默认表**：1on1=30min | 周会=45min | 立项/评审=60min | BR/复盘=90min | 培训/分享=60min | 默认=60min。优先级：用户明确指定 > 关键词匹配 > 默认 60min

## 一条龙全流程

```
用户说"帮我开个会" / "约XX聊" / "订会议室"
  ↓
【会前】 提取信息 → 查忙闲+选时段 → 订会议室 → 创建日程 → 生成会前材料 → 一次性汇报
  ↓
【会中】 开录制+转写 → 默读 → 核心讨论 → 决策确认
  ↓
【会后】 查会议记录 → 读纪要+转写 → AI提取结论/TODO → 写文档 → 推送通知
```

### 阶段1：会前自动化

Step 1-7 连续执行，中间不暂停。只有命中暂停条件表时才中断。

**Step 1：提取信息** — 从用户消息提取：会议主题、参会者、时间偏好、时长（默认60min）、地点偏好。参会者标识无法推断时才暂停。

**Step 2：查忙闲** — 调用日历适配器，输入(参会人列表, 时间范围)→输出(每人忙闲时段)。多人时执行，单人/1on1跳过。未配置日历适配器 → 跳过，标注"未校验冲突"。

**Step 3：选时段** — 将期望时段与忙碌区间做交集，按评分函数选最优空闲窗口。全忙 → 暂停，列冲突 + 推荐替代。

**Step 4：订会议室** — 调用会议室适配器，输入(人数, 时段)→输出(房间信息)。全满 → 触发借会议室流程（展示候选 + 话术模板，等用户确认）。未配置 → 跳过，标注"需自行安排"。

**Step 5：创建日程** — 调用日历适配器，输入(标题, 参会人, 起止时间, 地点, 备注)→输出(日程ID)。未配置 → 输出日程信息文本让用户手动创建。⚠️ 日程创建成功后才继续；失败则停止并提示用户。

**Step 6：准备会前材料** — 调用文档适配器，按会议类型套模板（详见方法论）。文档链接更新到日程备注。未配置 → 直接在对话中输出材料。

**Step 7：一次性汇报**
```
✅ 已约好[日期] [时段]，[会议室名称]（[容量]人）
📋 参会人：[列表] 已收到日程邀请
📝 会前材料：[文档链接]
```

### 阶段2：会中提示

提示用户：① 开启会议平台录制 ② 开启转写适配器 ③ 进入主持流程（详见方法论）

> 会后流程依赖转写数据。若用户未开启转写，提示「会后流程将降级为手动输入或跳过AI提取TODO」。

### 阶段3：会后自动化

**Step 1：查会议记录** — 通过会议平台适配器查询近期会议（输入时间范围→输出会议列表）。未配置 → 提示用户手动提供会议笔记或转写文本。

**Step 2：读取纪要/转写** — 调用转写适配器获取结构化文本；调用文档适配器读取已有纪要。

**Step 3：AI提取结论/TODO** — 从转写内容提取：关键决策、待办事项（主R+截止日期）、风险项。转写为空 → 提示用户补充笔记。

**Step 4：写文档** — 调用文档适配器创建会议纪要文档。

**Step 5：推送通知** — 调用通知适配器，发送纪要链接 + TODO摘要给参会人。未配置 → 输出消息文本让用户自行发送。

**降级链**：转写有→AI提取；转写空但用户有笔记→基于笔记提取；都没有→提示用户手动补充。

## 周期性会议自动带入

创建周会/双周会/月会日程时，自动附带"上期遗留TODO"区块：搜索上次同类会议纪要 → 提取未完成TODO → 写入本次材料。找不到上次会议记录则跳过（不报错）。适用于所有周期性会议，不适用于一次性会议和1on1（除非用户要求）。

## 已知局限

1. [P] 转写质量取决于适配器实现（Whisper模型大小/平台字幕质量）→ 会议录音不清晰时 → AI摘要标注低置信度，提示用户校对
2. [D] 会议室预订仅支持配置了会议室适配器的环境 → 未配置时 → 跳过该步骤，标注"需自行安排场地"
3. [E] 跨时区会议需用户明确指定时区 → Agent 未自动推断时区时 → 按用户本地时区处理并标注
