# PRIORITY() 今日客户优先级

## 1. 基本信息

```text
Skill ID: zayn-priority
Display Name: PRIORITY()
Chinese Name: 今日客户优先级
Project: WorkFn
Author Prefix: zayn
Category: Customer Management
Version: 0.1.0
Status: Draft for testing
```

## 2. 解决的问题

根据成交证据、紧迫度、项目价值、卡点和投入判断今天先推进哪些客户。

## 3. 适用场景

适用于需要执行上述职责，且能够提供核心对象、目标和至少一项可靠证据的场景。

## 4. 不适用场景

不适用于超出本 Skill 职责边界的其他任务，应调用对应 WorkFn Skill。

## 5. 输入参数

输入分为必填参数和建议参数，必须先解析并形成参数状态表。

## 6. 必填参数

1. 候选客户清单
2. 每个客户当前状态
3. 今日可用时间
4. 本次排序目标

## 7. 可选参数

1. 项目金额
2. 成交信号
3. 时间节点
4. 回复窗口
5. 所需投入
6. 风险
7. 下一步动作

## 8. 证据优先级

待补充完整证据优先级。当前至少提供一项可靠证据，不得让官网、平台行为或 AI 推测覆盖真实业务记录和人工确认。

## 9. 判断规则

1. 真实证据优先
2. 近期可推进优先
3. 高投入低证据降级
4. 明确今日动作
5. 限制作战池数量

## 10. 风险检查

1. 不得把所有客户都列为重点
2. 不得仅按金额排序
3. 不得因焦虑扩大作战池
4. 不得强行判断无证据客户

## 11. 输出结构

1. 参数完整度结论
2. 参数状态表
3. 今日优先清单
4. 排序依据
5. 今日动作
6. 暂缓客户
7. 风险提醒

## 12. 禁止事项

1. 不得把所有客户都列为重点
2. 不得仅按金额排序
3. 不得因焦虑扩大作战池
4. 不得强行判断无证据客户

## 13. 信息不足时的处理

关键参数缺失时先要求用户补充，不得强行输出正式结论。

## 14. 人工判断边界

人工确认事实和现有人工分类、责任人或决策优先，不得自动覆盖或修改原始数据。

## 15. 验收标准

1. 参数状态清晰
2. 达到最低运行条件后才正式分析
3. 核心判断和输出符合提示词
4. 不把推测写成事实
5. 不越过本 Skill 职责边界

## 参数解析流程

本 Skill 必须先解析用户输入并映射到参数表。

## 参数状态表

正式分析前必须输出参数状态表，状态只能使用：已命中、部分命中、缺失、冲突、待验证。

## 最低运行条件

1. 已提供本 Skill 的核心对象
2. 已明确本次分析目标
3. 已提供至少一项可靠证据
4. 关键参数缺失时先要求用户补充

## 缺失参数处理

不得自动补全缺失参数，必须明确提示补充并说明影响。

## 冲突参数处理

不得自行解决冲突，必须保留来源并提示验证。

## 待验证参数处理

待验证信息不得写成确定事实。

## 正式分析触发条件

只有达到最低运行条件且关键缺失、冲突、证据、目标和风险边界已处理后，才进入正式分析。

## 初步分析模式

参数不完整时只能提供明确标注的初步分析。

## 正式分析模式

参数完整并满足触发条件时才可输出正式分析。
