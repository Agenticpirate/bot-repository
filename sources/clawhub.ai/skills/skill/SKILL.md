# Skill 发布文案优化

专门用于优化 Skill 在各发布渠道的**元数据文案**，提升搜索可见性和点击转化率。

**核心问题**：Skill 写好了，但名称、description、triggers 写得不好，导致其他 Agent 和用户搜不到、看不懂、不想装。

---

## 功能概述

覆盖 Skill 发布所需的全部文案要素，按平台规范逐一优化：

| 优化对象 | 作用 | 影响平台 |
|---------|------|---------|
| **技能名称** | Agent 搜索第一匹配字段，用户一眼看懂 | 全部平台 |
| **description** | 搜索结果摘要，决定用户是否点进详情 | ClawHub / 虾评 / SkillHub |
| **triggers** | Agent 自动触发词，决定 Agent 会不会调用这个 Skill | Agent 生态 |
| **发布介绍文案** | 各平台详情页/发布帖的正文 | 小红书 RED Skill / 知识星球 / 虾评 |
| **slug / displayName** | URL 和展示名，影响搜索和品牌 | ClawHub / GitHub |

---

## 触发方式

**直接触发**：
- 「优化skill发布文案」「优化技能描述」「skill名称怎么起」
- 「让别人更容易搜到我的skill」「写skill发布介绍」
- 「优化skill的description」「优化skill的triggers」

**场景触发**：
- 准备发布一个 Skill，但不知道怎么写介绍文案
- 已发布的 Skill 下载量/安装量低，想优化文案提升发现率
- 多个 Skill 功能类似，想通过文案差异化定位

## 核心流程

### 第一步：收集 Skill 信息

需要了解以下信息（未提供则询问）：

1. **Skill 的核心功能**：这个 Skill 做什么？解决什么问题？
2. **目标用户**：是给普通用户用，还是给 Agent 调用？
3. **已有文案**：现有的名称/description/triggers 是什么？（如有）
4. **发布平台**：要发布到哪些平台？（虾评/ClawHub/GitHub/小红书 RED Skill/知识星球）

### 第二步：按平台执行优化

#### 优化A：技能名称

**命名原则**（按优先级）：

1. **场景限定词 + 功能词**：让用户/ Agent 一眼知道用在什么场景
   - ✅ 好例子：`自媒体文案润色`（场景=自媒体，功能=润色）
   - ❌ 坏例子：`文案优化器`（场景不明，太多东西都叫文案）

2. **10字以内**：超过会被截断或影响搜索权重

3. **名称即搜索词**：用户会搜什么词，名称里就包含什么词
   - 用户会搜「去AI味」→ 名称里要有「去AI味」
   - 用户会搜「扣子编程」→ 名称里要有「扣子编程」

4. **不用版本号作名称**：`v2.0」「加强版」放版本号里，不放在技能名称里

**输出格式**：
```
📛 技能名称优化建议

当前名称：「[现有名称]」
问题：[一句话说明为什么不好搜/不好懂]

推荐名称（按优先级）：
1. 「[推荐名称A]」— [理由]
2. 「[推荐名称B]」— [理由]

关键词覆盖检查：
  ✅/❌ 用户搜「[关键词]」能命中？
```

---

#### 优化B：description 字段

**description 的作用**：在 ClawHub/虾评/SkillHub 的搜索结果中，这是直接展示的摘要，决定用户会不会点进去。

**好 description 的标准**：
- **50字以内**（各平台均有截断）
- **第一句说清楚**：谁用？在什么场景下？解决什么问题？
- **覆盖核心搜索关键词**（至少3个）
- **不用「这个技能可以…」这种废话开头**

**各平台 description 最佳实践**：

| 平台 | 最大长度 | 注意事项 |
|------|---------|---------|
| ClawHub | 120字符 | 搜索结果直接展示，前60字符权重最高 |
| 虾评 | 200字符 | 支持 xiaping_description 字段单独设置 |
| SkillHub | 150字符 | 分类浏览时直接展示 |
| GitHub | 无限制（README第一行） | 写一句人话，别写「A skill for...」 |

**输出格式**：
```
📝 description 优化建议

当前 description：「[现有内容]」
问题：[字数/关键词/清晰度问题]

推荐 description（按平台）：
  ClawHub（≤120字符）：「[优化后]」
  虾评（≤200字符）：「[优化后]」
  SkillHub（≤150字符）：「[优化后]」

关键词覆盖：[列出覆盖的核心词]
```

---

#### 优化C：triggers 字段

**triggers 的作用**：Agent 根据用户说的话匹配 Skill，triggers 覆盖的用户表达越多，Agent 越容易正确触发。

**好 triggers 的标准**：
1. **覆盖用户自然表达**：用户会怎么说，triggers 里就有什么
2. **至少5个，多多益善**：覆盖同义表达（「优化文案」/「润色一下」/「帮我改改」）
3. **包含长短两种触发词**：既有「去AI味」短词，也有「帮我优化一下这段文案」长句
4. **动词开头优先**：「优化文案」比「文案优化」更容易被 Agent 匹配

**triggers 生成方法**：
1. 列出用户遇到这个问题时会说的**所有表达方式**（至少8个）
2. 按「直接触发词」和「场景触发词」分类
3. 去重，保留最自然的表达

**输出格式**：
```
🎯 triggers 优化建议

当前 triggers：[列出已有]
缺失的触发词：[列出用户可能会说但没覆盖的表达]

推荐 triggers（[N]个）：
- [触发词1]
- [触发词2]
...

分类说明：
  直接触发：[哪些]
  场景触发：[哪些]
```

---

#### 优化D：发布介绍文案（各平台）

不同平台需要不同格式的发布介绍文案：

**① 虾评发布文案**

虾评的 Skill 详情页需要一段介绍文案，格式如下：
```
🔧 [技能名称]

[一句话说清楚这个Skill做什么]

## 适合谁用？
- [用户类型1]
- [用户类型2]

## 怎么用？
[最简单的使用场景描述]

## 为什么装？
[1-2个核心价值点]

📦 安装口令：[安装命令或链接]
```

**② ClawHub 发布文案**

ClawHub 需要：
- `displayName`：展示名称（可以比技能名称更详细）
- `summary`：一句话摘要（显示在搜索结果）
- `description`：详情页长描述（支持 Markdown）
- `slug`：URL 标识（用英文，语义化，如 `copy-optimizer`）

**③ 小红书 RED Skill 发布文案**

小红书笔记格式：
```
标题：[吸引眼球的标题，含关键词]

正文：
[痛点引入——你现在是不是也有这个问题？]
[这个Skill怎么解决的]
[我用它做了什么，效果如何]
[安装方式：口令/链接]

配图建议：[封面图应该是什么内容]
话题：#[话题1] #[话题2] #[话题3]
```

**④ 知识星球发布文案**

知识星球帖子格式（付费用户，偏干货）：
```
【Skill 分享第X期】[技能名称]

今天分享一个我自己在用的 Skill：[名称]

[它解决什么问题？]
[怎么用？举一个具体例子]
[我为什么推荐装？]

安装方式：[口令或链接]
```

---

#### 优化E：slug / displayName（ClawHub 专属）

| 字段 | 作用 | 命名建议 |
|------|------|---------|
| `slug` | ClawHub URL 标识，如 `clawhub.com/skills/[slug]` | 用英文，语义化，短横杠分隔，如 `copy-optimizer` `ai-image-gen` |
| `displayName` | ClawHub 展示名称，可以比技能名称更详细 | 可以加 emoji 和场景说明，如 `文案优化器 🔧 去AI味/平台适配` |

## 🔌 技能体系结合分析：Skill发布文案优化

### 🔗 协作链路

```
上游：技能创建器（创建Skill时）
   ↓
Skill发布文案优化 ← ← ← ← ← ← ← ← ← ← ← ←
   ↓（输出优化后的名称/description/triggers/发布文案）
下游：技能发布（执行多渠道发布）
```

**详细协作**：
- `技能创建器` 创建完 SKILL.md → 调用 `Skill发布文案优化` 生成各平台发布文案 → 交给 `技能发布` 执行发布
- 已发布的 Skill 下载量低 → 手动调用 `Skill发布文案优化` 重新优化 → 更新各平台元数据

---

### ♻️ 重叠/替代关系

**与现有技能无功能重叠**。

| 看似相关但实际不同的技能 | 差异 |
|---------|------|
| `文案优化器` | 优化的是「自媒体内容文案」；本技能优化的是「Skill的发布元数据文案」——完全不同的优化对象 |
| `标题创建` | 创建内容标题；本技能创建的是 Skill 的名称和 description |
| `技能发布` | 执行发布操作；本技能提供发布所需的文案内容，是上游关系 |

- □ 建议：在 `技能发布` 的「准备」阶段，先检查是否已有优化后的发布文案，没有则提醒用户调用本技能
