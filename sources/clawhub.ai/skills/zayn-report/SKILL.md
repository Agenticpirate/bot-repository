# REPORT() 通用汇报识别与路由

## 职责

识别汇报需求并路由；仅在没有专门子 Skill 时整理单个项目等通用汇报。不得重复执行子 Skill 已负责的内容。

## 统一运行流程

按“输入解析 → 参数映射 → 参数状态表 → 最低运行条件检查 → 缺失或冲突处理 → 正式分析 → 结构化输出”运行。参数状态只使用：`已命中`、`部分命中`、`缺失`、`冲突`、`待验证`。

## 必需参数

1. 汇报类型
2. 汇报对象
3. 汇报目的
4. 时间范围
5. 原始事实
6. 期望输出形式

## 最低运行条件

必须能判断汇报对象、目的，具有可核实的原始事实，并能判断汇报类型或明确需要补问。未满足时进入初步分析模式，不生成完整汇报。

## 路由规则

| 用户需求 | 处理方式 |
|---|---|
| 当天总结、日报、下班汇报 | 路由到 `zayn-daily-report` |
| 本周总结、周会汇报、忙但没结果分析 | 路由到 `zayn-weekly-report` |
| 本月总结、月报、月度复盘、月会汇报 | 路由到 `zayn-monthly-report` |
| 上半年总结、年中复盘、下半年计划 | 路由到 `zayn-midyear-report` |
| 年度总结、年度述职、全年复盘、下一年度计划 | 路由到 `zayn-annual-report` |
| 单个项目进展 | 执行有限的通用项目汇报整理 |
| 判断是否找领导协调 | 推荐 `zayn-escalate` |
| 需要领导选择 | 推荐 `zayn-decision` |
| 会议总结 | 推荐 `zayn-minutes` |
| 复杂多 Skill 问题 | 交给 `zayn-route` |
| 无法分类 | 补问类型、对象、目的和周期 |

路由后停止，不继续生成子 Skill 的最终文本。

## 通用项目汇报兜底

仅在需求明确为单个项目汇报时输出：参数状态表、核心结论、目标、已确认进展及证据、风险、下一步、责任人、截止时间、所需支持。区分动作与结果，不得补造事实。

## 模板兼容

接受现有模板、零散记录或“只检查不重写”的请求。模板负责稳定记录事实，Skill 负责检查、追问、分析和纠偏。

## 禁止事项

1. 不把所有汇报写成日报或周报。
2. 不在事实不足时生成完整汇报。
3. 不把动作自动写成结果。
4. 不编造数据、反馈或结论。
5. 不覆盖子 Skill 职责。
6. 应路由时不继续自行处理。

## 输出

1. 参数完整度结论
2. 参数状态表
3. 识别出的汇报类型与依据
4. 路由结果或需要补充的信息
5. 仅在通用兜底条件满足时输出项目汇报
