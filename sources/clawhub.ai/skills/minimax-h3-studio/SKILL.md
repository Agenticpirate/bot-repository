# MiniMax H3 Studio

统一管理官方 9 个 Skill。先判断用户需要提示词、制作方案、素材还是完整成片，只读取相关模块；不要把轻量请求扩大为全流程。所有输出提示词、结构标题、角色设定、镜头描述和交互均使用中文。用户锁定的原文、专名和明确要求的外语对白或画面文字保留原样；不要自动把整份提示词转为英文。

## 中文提示词与独立角色设定

这是所有九个模块共同遵循的输出约定，优先于参考资料中要求英文正文、英文字段、英文广告文案或固定英语开头的默认规则。用户明确指定的文案语言和原文不改动。

- 输出前读取 [中文输出规范与模板](references/中文输出规范.md)。基础结构统一为「综合多模态描述」「整体声景」「画外配乐」；全能参考结构使用该文档中的六段中文标题。镜头使用「【镜头一】」「在第4秒，镜头切换至……」等中文表达。
- 涉及人物、动物或拟人角色时，先逐个给出独立、可修改的角色设定，再给视频提示词。角色设定与镜头正文不混写，每个角色用稳定名称或中文编号。角色块和视频块构成一份完整提交文本，提示用户一起复制；不得仅给依赖缺失角色设定的视频片段。
- 角色设定集中写身份、体型、脸部、发型或毛发、服装、配色、识别特征，必要时加性格、动作习惯和声音。剧情动作写入镜头，不塞进固定设定。已有设定不反复重写；用户修改某角色后同步更新受影响镜头和声音，不改其他角色。
- 没有参考素材时使用文生视频结构。单独写角色不等于全能参考模式，不虚构参考图片、视频、音频或服务端编号。
- 中文标题是本 Skill 的本地译名，不称为官方中文协议，也不保证与英文结构生成效果相同。用户可读提示词保持中文；若实际接口强制使用英文键、标签或对齐句式，在提交适配层按当前接口要求映射，保留中文正文及独立角色设定，不把中文标题当作 API 字段发送。若接口要求进一步翻译正文，说明需求后按用户选择执行。

## 跨平台执行规则

以下是可移植的本地整合规则；与上游运行环境假设冲突时按此执行，不将其表述成官方原文。

- 默认视频模型是 MiniMax-H3。只有用户明确选择另一模型后，核对该模型当前输入类型、时长、画幅、音频和服务参数，再切换。失败、缺少接口或某镜头较难，都不能自动切换模型。上游关于性能、价格、分辨率和时长的说明是版本快照，实际调用前以当前官方文档和已连接服务为准。
- 原版 Hub 画布映射为项目目录里的中文 Markdown 文档与真实媒体文件。按制作顺序命名并提供文件链接；修改已确认角色卡、场景卡或镜头后，同步修订下游引用。没有画布工具时不能声称已创建画布节点。
- 原版选择卡用于收集真正缺失的创意决策；继承用户已给的参数和授权，不重复询问。用户要求直接做时，在范围内采用合理默认并注明。确需选择且工具支持时使用问题工具，否则简短询问；不要依赖并不存在的 Hub 卡片接口。
- `hub_generate_image`、`hub_generate_video`、音乐模型、语音和合成工具只表示原版能力需求。实际使用前检查当前可调用工具或用户配置的服务，不虚构工具、API、资产 ID 和任务结果。图片按当前环境的图像工具规则执行；本地素材不是服务端资产 ID。
- 缺少视频或音频服务时，继续完成已授权且不依赖服务的故事、角色、分镜、提示词与素材清单，明确说明尚未生成；需要实际出片时指出缺少的具体连接。安装 Skill 本身不会安装模型或开通 API。
- 用户明确锁定的原文逐字保存，改编稿单独标明。精确品牌文字、歌词和 UI 文案必须检查实际画面；提示词正确不代表成片文字准确。是否后期叠字遵循用户需求和选定流程，不静默改换方案。
- 需要从音视频转字幕时优先使用 DashScope Paraformer；先检查目标环境是否具备相应工作流或接口，不假设已安装；已有字幕直接用于封装或烧录。不能自行改用 Whisper。纸拼贴模块默认保留触感音效，不主动加入音乐、旁白或字幕；不要把该默认值套到其他风格。
- 失败先诊断原因，修正提示词或输入；同一镜头连续三次失败后停止自动重试，说明可选修正。保留已成功产物，不因重试静默更换模型或丢弃用户要求。

## 交付与检查

对提示词检查模式、字段、标签、对白和时间覆盖。对多镜头方案检查角色身份、空间锚点、动作衔接、道具状态、画幅、时长和主音轨一致性。对真实成片检查镜头顺序、黑帧、音画同步、文字、声音与分镜标记残留；最终修改后针对最终文件复查。

最终反馈区分「提示词完成」「素材已生成」「已合成」「已验收」，提供实际文件路径；未执行的步骤直接说明。

来源与逐文件校验值见 [来源与版本](references/来源与版本.json)。保留官方英文语法资料和中英文原文以便追溯；中文入口及 Codex 环境映射是本地整合内容。
