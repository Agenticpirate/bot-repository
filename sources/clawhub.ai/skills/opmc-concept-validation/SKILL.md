# 概念验证中心 · 创意方案验证引擎

> 核心理念：技术交易的本质是信任传递，不是信息搬运。概念验证中心负责验证概念成立——验证技术能跑通、市场能接受、资源能匹配。

## 技能定位

| 属性 | 说明 |
|------|------|
| 核心使命 | 对创意方案进行系统化验证，判断是否值得进入下一阶段 |
| TRL覆盖 | 1-4（概念→原理验证） |
| 验证周期 | 3-6个月 |
| 失败容忍 | 30-50%正常 |
| 资产属性 | 轻资产，百万级起步 |

## 六维验证框架

### 维度1：技术可行性验证（TRL 1-4）

| TRL等级 | 定义 | 验证标准 |
|:-------:|------|---------|
| TRL 1 | 观察到基本原理 | 有科学原理支撑，非空想 |
| TRL 2 | 形成技术概念 | 技术路线清晰，有初步方案 |
| TRL 3 | 关键功能验证 | 核心功能在实验室环境验证通过 |
| TRL 4 | 实验室环境验证 | 完整功能在模拟环境验证通过 |

**验证要点**：
- 技术路线是否可行？有无替代方案？
- 核心瓶颈在哪里？是否需要突破性技术？
- 开发周期和资源需求是否合理？
- 知识产权风险：有无专利壁垒？能否绕过？

### 维度2：商业可行性验证

**验证要点**：
- 目标市场是否真实存在？市场规模多大？
- 商业模式是否成立？收入来源是否清晰？
- 获客成本 vs 用户生命周期价值是否合理？
- 竞争格局如何？差异化优势是否可持续？
- 盈亏平衡点在哪？需要多少用户/订单？

### 维度3：资源匹配评估

**验证要点**：
- 所需核心能力是否具备？
- 所需资金规模及来源？
- 关键合作伙伴是否可获取？
- 时间窗口是否合适？

### 维度4：团队能力评估

**验证要点**：
- 核心团队是否具备必要技能？
- 是否存在关键人才缺口？
- 团队执行力评估
- 激励机制是否合理？

### 维度5：风险画像

**风险类型** | **评估要点** | **应对策略**
-----------|-------------|------------
技术风险 | 技术复杂度、成熟度、替代方案 | 分阶段验证、技术储备
市场风险 | 市场接受度、竞争反应、政策变化 | 最小可行市场测试
团队风险 | 能力缺口、关键人员流失 | 人才储备、知识沉淀
资金风险 | 资金链断裂、后续融资困难 | 分阶段融资、成本控制

### 维度6：验证结论与建议

| 结论 | 含义 | 建议动作 |
|:---:|------|---------|
| ✅ **通过** | 概念可行，建议进入中试阶段 | 准备中试入驻材料 |
| ⚠️ **有条件通过** | 概念基本可行，但有明确风险需解决 | 列出风险项及解决时间表 |
| ❌ **不通过** | 概念不成立或时机不成熟 | 给出具体原因和改进建议 |

## 三阶段交付流程

### 阶段1：接收与评估
- 接收创意造物局输出的方案
- 明确验证范围和目标
- 识别关键验证点

### 阶段2：验证执行
- 六维验证框架逐项评估
- 技术验证：技术路线、TRL评估、IP风险
- 商业验证：市场、模式、财务
- 资源与团队评估
- 风险画像

### 阶段3：验证结论
- 输出验证结论（通过/有条件/不通过）
- 填写验证报告
- 提出下一阶段建议
- 若通过，准备中试基地入驻材料

## 输入/输出规范

**输入**：创意方案（来自创意造物局或其他来源）
- 项目概述
- 技术方案
- 商业模式
- 团队信息
- 资源需求

**输出**：完整验证报告
- 六维验证评分
- 结论与建议
- 风险清单
- 中试建议（如通过）

## 衔接接口

### 上游：创意造物局
- 接收：创意方案+商业模式分析报告
- 反馈：验证结论+改进建议

### 下游：中试基地
- 输出：验证通过的项目交付包
- 内容：验证报告+技术方案+商业计划书

## 适用场景

| 场景 | 说明 |
|------|------|
| 技术方案验证 | 判断技术路线是否可行 |
| 创业项目评估 | 从技术+商业双维度判断项目可行性 |
| 投资前尽调 | 快速评估技术项目的成熟度和风险 |
| 成果转化评估 | 判断科研成果是否具备转化价值 |
| 内部立项评审 | 企业新技术/新业务的立项前验证 |
