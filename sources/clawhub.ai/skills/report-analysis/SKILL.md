# 渠道评优激励通报 · 数据欠缺分析与整改清单生成器

## 用途

把一份「合作伙伴评优激励通报」Excel（典型为运营商渠道评优激励核算表），转化为三类可交付的分析成果：

1. **数据欠缺分析报告**（Word）：总体评价 + 主要欠缺问题清单（按重要性排序）+ 改进建议，语言简洁通俗、避免术语。
2. **重点网格整改清单**：挑出问题最突出的少数网格，每个网格按「问题—整改」两行说明。
3. **网格汇总表**：全部网格一张表，用颜色标出短板，一眼看出问题。

## 使用前提（分享/下载后必读）

1. **数据文件**：需要用户自己的一份《合作伙伴评优激励通报》Excel（含「渠道完成情况通报」「县（市）汇总」「否决项门槛值」等工作表）。本技能不内置示例数据。
2. **政策文档（可选）**：模式⑥⑦需要三份政策 Word（管理办法、日常运营执行要求、分级施策指导意见）。可通过 `YJ_DOC_DIR` 指定所在文件夹后运行 `doc_index.py` 建索引；不提供则⑥⑦不可用，其余功能不受影响。
3. **运行环境**：Python 3.10+，依赖 openpyxl、python-docx、matplotlib（仅图表模式需要），脚本目录已附 `requirements.txt`。缺库时一条命令装齐：`pip install -r requirements.txt`。
4. **本技能不含任何本机路径**：所有文件路径均通过环境变量（`YJ_SRC`/`YJ_DOC_DIR` 等）或对话中用户提供的路径传入。

## 触发条件

满足以下任一即启用本技能：

- 用户引用/上传 `.xlsx` 文件，文件名或内容含「评优」「激励」「通报」「渠道」等字样，并要求「分析欠缺 / 找短板 / 需要改进的地方 / 生成报告」。
- 用户要求对渠道/合作伙伴激励数据做「欠缺分析、诊断、复盘、整改清单、汇总表」。
- 用户提到「否决门槛、终端合约、APP融合率、重点业务、弱势网格」等评优核算指标。

## 损失计算逻辑

激励金额经过六道核算逐级递减：

```
原始兑换金额
  → 否决门槛（AI五件套/金虎/权益升档/88会员年包，未达档即归零或降档）
  → 终端合约搭载（合约率不足扣减）
  → 重点业务牵引系数（0.81/0.9/1 乘系数）
  → 有责投诉考核
  → 弱势网格扣罚（签约未完成扣罚）
  → APP 融合率（系数 0.8/1.1）
  = 最终可发金额
```

- **总损失 = 原始兑换金额 − 最终金额**（列8 − 列14）
- **损失率 = 总损失 ÷ 原始金额**
- 各项「损收」可逐级用相邻两列相减得到，用于定位最大出血点。

## 标准分析结论框架（9 类常见欠缺，按重要性）

统计后按此框架组织问题清单，并按数据实际情况排序：

1. **AI 五件套完成率为零**（通常是最大短板，全渠道为 0）
2. **否决门槛大面积未达档**（统计「门槛未完成」渠道占比）
3. **关键会员/套餐业务乏力**（88会员/99会员年包、金虎为 0 的渠道占比）
4. **终端合约搭载不足**（终端合约率均值、为 0 的渠道数）
5. **APP 融合率偏低**（新入网/终端/宽带三类融合率均值）
6. **重点业务发展不均衡**（牵引系数为 0.81 最低档的占比）
7. **弱势网格攻坚参与度低**（签约率、签约后 4 项业务为 0 的数量）
8. **激励极度集中**（拿到 0 元的渠道占比、头部金额）
9. **数据质量隐患**（有责投诉未出数、拍照值与原始金豆口径不一致）

每项欠缺的写法：**问题表现（带数字）→ 可能原因 → 改进建议**，避免术语。

## 输出规范

### 交付物 1：数据欠缺分析报告（Word）
结构：标题 + 数据来源说明 → 一、总体评价（含县市损失一览表）→ 二、主要欠缺问题（按重要性排序，逐条）→ 三、改进建议（分「业务短板」与「参与/管理」两组）。

### 交付物 2：重点网格整改清单
- 按县分组、县内按损失降序，挑损失最大的 8 个左右网格（约占全州损失六成）。
- 每个网格：标题 + 「问题：…」+「整改：…」两行。
- 问题用红字、整改用绿字，末尾加一条共性提醒。

### 交付物 3：网格汇总表
- 11 列：网格 | 县 | 渠道数 | 原始(万) | 损失(万) | 达档 | 金虎 | 88会员 | 合约率 | APP融合(新/终/宽) | 主要短板。
- 按县分组行、县内按损失降序，末尾全州合计行。
- 「主要短板」列自动归纳：零达档 / 金虎空白 / 会员空白 / 合约低 / APP融合低 / 无业务量 / 相对均衡。

### 交付物 4：渠道预警分级名单（Excel）
- Sheet1 全渠道分级：县/网格/编码/名称/预警等级/分级说明/原始/最终/损收/损收率/门槛/金虎/AI5/权益/88会员/合约率/APP系数，按「红→黄→绿」再按损收降序。
- Sheet2「红牌-重点整改」：门槛未完成且四项全为 0 或最终金额为负的渠道，按损失降序。
- Sheet3「黄牌-关注帮扶」：门槛未完成但有业务量的渠道。
- Sheet4「县市分级汇总」：各县红/黄/绿计数与红牌占比。
- 预警列自动填色（红 #FFC7CE / 黄 #FFEB9C / 绿 #C6EFCE）。

### 交付物 5：可视化看板（自包含 HTML）
- 顶部 8 张数据指标卡：渠道总数、原始/最终金额、损收合计及损收率、门槛未完成、红/黄/绿牌数量。
- 6 张图：各县激励金额对比、门槛完成情况饼图、预警分级堆叠柱状图、损收 TOP10 渠道、渠道损收率分布直方图、逐道核算损收构成横向条形图。
- 内联 base64 图片，无需联网即可打开，可打印。

### 交付物 6：政策速查手册（Word）
- 一、政策文件概览表（文档/版本/层级/内容定位/篇幅）；二、核心政策规则速查：按文档分章，每条规则带章节出处，附章节结构树；附录A 业务术语对照表（Excel 核算术语 ↔ 政策文档表述）；附录B 政策⇄数据联动速查（当前季度实测关键数字）。
- 三份政策文档定位（默认目录 `YJ_DOC_DIR`）：
  | 文档 | 版本 | 层级 | 内容 |
  |---|---|---|---|
  | 日常运营执行要求 | 2024 | 操作层 | 合作引入流程、资质要求、运营规范、违规处罚 |
  | 西双版纳分级施策指导意见 V4.0 | 2023 | 激励层 | 月度激励公式、季度星级激励、否决与扣罚项 |
  | 云南公司销售合作伙伴管理办法 | 2023 | 制度层 | 分类布局、准入退出、费用管理、星级评定、运营管理 |
- 注意版本：分级施策/管理办法为 2023 版、运营执行为 2024 版，新旧规则以最新发文为准。

## 八种交互模式（功能增强 v5，2026-08-20）

用户问题先判断模式：**模式0 先给菜单等选择；模式A/B 直接回复数据结论（带数字），模式C/D/E 生成文件，模式F/G 基于政策文档分析/检索**。

### 模式0：功能引导（说"帮我分析"等模糊指令时）

触发：用户说「帮我分析 / 分析一下 / 开始 / 有什么功能 / 能做什么 / 帮我看看 / 分析分析」等，且没有明确指向某个具体模式时。

流程：
1. **列出功能菜单**（每项注明输出物，用户能预知会拿到什么）：
   - ① 具体指标查询 —— 输出：该指标的完整问答（全州数据 + 分县数值 + 结论 + 改进建议）。例：问「门槛」→ 369家未达档（92.9%）、单道损收60.00万、景洪46.70/勐腊13.00/勐海0.30万
   - ② 网格/渠道查询 —— 输出：该网格或渠道的情况卡片（总览 + 损失构成 + TOP5渠道 + 逐条改进建议）。例：问「曼弄枫」→ 15家|原始22.20万→最终6.92万|损失15.28万|门槛未完成12家|0元10家
   - ③ 总结分析报告 —— 输出：Word 文档《数据欠缺分析报告》，含一、总体评价+县市损失一览表；二、主要欠缺问题（问题表现/原因/改进）；三、改进建议；附1 重点网格整改清单（红字问题/绿字整改）；附2 网格汇总表（横向页+颜色标注）
   - ④ 预警分级名单 —— 输出：Excel 文件（4个工作表）：全渠道分级（含预警等级列，红黄绿底色）、红牌-重点整改名单、黄牌-关注帮扶名单、县市分级汇总（各县红/黄/绿数量+红牌占比）。例：397家 → 红牌241/黄牌128/绿牌28
   - ⑤ 图表可视化 —— 输出：HTML 看板（可离线打开），含8张指标卡 + 6张图：①各县激励金额对比（原始/最终/损收）②门槛完成情况饼图 ③预警分级按县堆叠柱状图 ④损收TOP10渠道条形图 ⑤渠道损收率分布直方图 ⑥逐道核算损收构成横向条形图
   - ⑥ 政策文档分析 —— 输出：所选政策文档的总结（定位 + 章节结构 + 核心政策规则逐条带原文出处 + 与 Excel 的关联点）。可用文档：《日常运营执行要求2024》《分级施策指导意见2023》《管理办法2023》
   - ⑦ 政策文档检索问答 —— 输出：问题对应的政策条款（跨文档检索，标注文档+版本+章节），涉及 Excel 指标时自动附实测数据联动
2. **请用户选择**：回复数字（如 1）或功能名即可开始；若未提供数据文件，询问或采用默认最近批次（`YJ_SRC` 环境变量，未设置则提示用户提供路径）。
3. 用户选择后，**进入对应模式执行**：①→模式A、②→模式B、③→模式C、④→模式D、⑤→模式E、⑥→模式F、⑦→模式G。
4. 执行完按该模式规范交付；用户说「再来一个」时回到菜单，可连续切换模式。

> 判断优先级：若指令已明确指向某模式（如「查景洪市」→B、「出报告」→C），直接执行，不要用模式0绕一圈。

### 模式A：具体内容查询（"XX情况怎么样 / 查一下XX"）
触发词：门槛/否决、金虎、AI五件套、会员、终端合约、牵引系数、投诉、弱势网格、APP融合、0元渠道、激励集中。
回答模板（每步必须带具体数字）：
1. **数据**：全州完成量 / 为0家数及占比 / 单道损收（**单道损收以「县（市）汇总」表为准**，不要用主表相邻列相减）
2. **分县**：景洪、勐海、勐腊各自的数值（金额类指标）
3. **结论**：一句话判断主次与根因
4. **改进**：1~2 条可执行建议

### 模式B：具体网格/渠道查询（"XX网格怎么样 / 查XX渠道"）
触发：用户输入网格名、渠道名或渠道编码（支持模糊匹配）。
网格回答模板：
1. 总览行：渠道数 | 原始 | 最终 | 损失(率) | 门槛未完成 | 0元
2. 损失构成：逐道核算累计扣减（门槛→终端→重点→弱势→APP），指出最大出血点
3. 网格内损失 TOP5 渠道：名称、原始→最终、门槛档、金虎/AI5/88会员、合约率
4. 改进建议（规则化）：门槛未完成占比≥80%→先补四项门槛；0元占比≥70%→逐户归类（业务缺口帮扶/门槛缺口宣贯）；合约率0→主推合约机；融合<15%→默认开APP
渠道回答模板：
1. 指标卡：县/网格/编码/星级、原始→最终+损失率、门槛四件套、终端办理/合约率、牵引系数、弱势网格签约+4项完成量、三类APP融合率+系数
2. 逐条改进：门槛未完成→指出具体缺哪几项（按完成量为0的项点名）；合约率0→补合约；新终端/宽带融合<15%→默认开APP；牵引系数<1→补运营积分；签约但4项0→协议扣罚风险；最终0但有原始→优先补门槛

### 模式C：总结分析 → 输出 Word
按原方法生成 Word（交付物1+2+3 合一）：
标题+数据来源 → 一、总体评价（县市损失一览表，含六道损收）→ 二、主要欠缺问题（按重要性逐条：问题表现/可能原因/改进建议）→ 三、改进建议（业务短板/参与管理两组）→ 附1 重点网格整改清单（横向页，红字问题/绿字整改）→ 附2 网格汇总表（横向页+颜色标注）。

### 模式D：预警分级 + 名单导出
触发：用户说「预警分级」「红黄牌」「重点整改名单」「导出名单」「Excel 名单」等。
自动按规则分级并导出 Excel（交付物4）：
- **红牌（重点整改）**：门槛未完成且四项门槛业务全为 0（完全无业务）；或最终金额为负（扣罚超可发额）。
- **黄牌（关注帮扶）**：门槛未完成但有业务量（有量未达档）。
- **绿牌（达标稳定）**：门槛达档。
同时汇报全州与各县红/黄/绿数量及红牌 TOP5。

### 模式E：图表可视化 / HTML 看板
触发：用户说「图表」「可视化」「看板」「趋势图」「排名图」等。
生成自包含 HTML 看板（交付物5），并简要说明关键洞察：
1. 各县激励金额对比：哪里原始高、最终低、出血最大。
2. 门槛完成情况：达档/有量未达档/完全无业务占比。
3. 预警分级分布：各县红/黄/绿堆叠对比。
4. 损收 TOP10：哪些渠道损失最大。
5. 损收率分布：多数渠道损失集中在哪个区间。
6. 逐道损收构成：哪一道核算扣罚最多。

### 模式F：政策文档分析（"总结XX政策 / 这份文档讲了什么"）
触发：用户引用/提到政策类 Word 文档（管理办法、运营执行要求、分级施策指导意见等），要求总结内容、说明政策规则。
流程：
1. 定位文档（按用户点名或文件名关键词匹配），先建索引（`doc_index.py`，已建可直接复用 policy_docs.json）。
2. 输出模板：
   - **文档定位**：层级（制度层/激励层/操作层）+ 版本年份 + 一句话内容定位
   - **章节结构**：顶层章节树
   - **核心政策规则逐条**：每条带原文出处（章节路径），如「月度激励=月度贡献奖励上限×月度贡献完成率×省级协同系数」
   - **与 Excel 的关联点**：该文档规则对应的评优核算项（如否决项→门槛核算、星级协同考核系数→牵引系数）
3. 语言通俗，规则原文保留关键数字（金额、比例、系数）。

### 模式G：政策文档检索问答（"政策里XX怎么规定的 / 查XX条款"）
触发：用户就政策内容提问（跨三份文档检索），如「月度激励怎么算」「星级评定标准」「资质要求是什么」「违规怎么处罚」。
流程：
1. 关键词提取：去停用词 + 术语映射扩展（Excel 术语→文档表述，如 门槛→否决、牵引系数→协同系数）。
2. 全文检索打分（整词命中优先；不足 3 条时用问题 2~4 字 n-gram 兜底）。
3. 输出模板：
   - **检索结果**：按相关度排序，每条标注 [文档·版本·层级] + 章节路径 + 原文片段
   - **政策⇄数据联动**：问题命中 Excel 指标（门槛/激励/星级/APP融合/合约/弱势网格/投诉/牵引）时，自动附 2026年3季度实测数据，用政策解释数据、用数据佐证政策
   - **综合回答**：归纳条款来源，标注版本年份，提示以最新发文为准
4. 规则：**必须引用原文出处，不凭空编造条款**；文档无相关条款时如实说明（如三份文档均无「终端合约率」条款，属 Excel 核算项而非政策条款）。

## 数据口径（2026年3季度实测校正，务必遵守）

- **逐道损收以「县（市）汇总」表为准**（门槛/终端/重点业务/弱势网格/APP 五道各列），主表相邻列相减得到的是累计口径，不要混用。示例：全州门槛损收 60.00万、终端 2.50万、重点 10.80万、弱势 9.40万、APP 7.78万。
- **门槛未完成归因**：拆成「四项门槛业务全为 0（完全无业务）」与「有量但未达档位线」两类分别统计，不要武断归因于某一单品（示例：369 家中 215 家全 0、154 家有量未达档）。
- **预警分级口径（模式D）**：
  - 红牌（重点整改）：门槛未完成 且 四项门槛业务全为 0（完全无业务）；或最终金额为负（扣罚超可发额）。
  - 黄牌（关注帮扶）：门槛未完成 但有业务量（有量未达档）。
  - 绿牌（达标稳定）：门槛达档。
  - 示例：397 家渠道中 红牌 241 / 黄牌 128 / 绿牌 28。
- **负值渠道**：最终金额为负（扣罚超可发额）按 0 计，报告中注明数量（示例 31 家）。
- **有责投诉未出数**：主表按「先按不扣罚计」，报告标注存在追溯扣罚风险。
- **主表数据从第 3 行开始**（行1分组标题、行2列名）；2026年3季度实测 397 家渠道、90 列。
- 档位门槛值以「否决项门槛值」工作表为准（1档：AI五件套≥20/金虎≥100/权益升档≥1000/88会员≥500，金额区间可反查）。

## 技术实现要点

- **读表**：`openpyxl.load_workbook(path, data_only=True)` 读公式计算后的值；`iter_rows(min_row=3, values_only=True)` 跳过表头。
- **统计**：用 `collections.defaultdict`/`Counter` 按网格、按县聚合；金额单位注意万元换算（原始表通常为「元」）。
- **生成 Word**：`python-docx`，默认字体微软雅黑；标题深蓝 `1F3B73`；表格用 `Table Grid` 样式 + 单元格 `w:shd` 填底色；表格列宽用 `cell.width` 逐行设置。
- **宽表横向页**：11 列表在竖版放不下，用 `doc.add_section(WD_SECTION.NEW_PAGE)` + `WD_ORIENT.LANDSCAPE` + 交换 page_width/page_height 建横向节。
- **Excel 预警名单**：用 `openpyxl`；预警等级列按红/黄/绿填充底色；按等级+损失排序；多工作表（全渠道、红牌、黄牌、县市汇总）。
- **图表/看板**：用 `matplotlib`+`Agg` 后端；中文字体跨平台动态探测（微软雅黑/黑体/苹方/Noto/文泉驿等候选名，找不到自动扫系统字体文件注册兜底，仍失败会打印明确警告），杜绝其他机器中文变方框；输出 PNG 后用 base64 内联到自包含 HTML，无需外部 CDN 或联网即可打开。
- **文档索引**：`python-docx` 提取段落+表格；章节用正则（第X章/一、/（一）/1、）识别并维护章节栈，条款带出处路径；输出 JSON（policy_docs.json）+ 术语映射（term_map.json）。
- **文档检索**：停用词清洗（只用多字停用词，单字会拆坏双字词）+ 疑问尾字清洗 + 术语映射扩展；整词命中打分按词长加权，命中不足 3 条时用问题 2~4 字 n-gram 兜底（权重打折）。
- **政策⇄数据联动**：检索命中指标词（门槛/激励/星级/APP/合约/弱势/投诉/牵引）时，从 analyzer 取实测数据附在回答中；三份政策文档均无「终端合约率」条款，属 Excel 核算项，检索不到要如实说明。
- **HTML 汇总表**：若用户要可打印/可视化版本，可另出 HTML，用内联样式标色。

## 注意事项

- 涉及本地 Office 文件时，若环境有腾讯文档编辑链路（tencent-docs-routing / sheetagent / tencent-docx 等），先走其路由；无则用 openpyxl/python-docx 直接处理，并告知用户。
- 修改用户桌面等个人目录文件前，先 `shutil.copy` 备份。
- 语言简洁通俗、文字密度控制在 60% 以下，不做术语堆砌。
