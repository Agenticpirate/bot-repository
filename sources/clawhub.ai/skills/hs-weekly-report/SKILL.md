# Weekly Report（领导视角周报）

## Overview

把用户"这周做了 A、做了 B"的流水账，升级成"领导 30 秒读懂全局"的项目仪表盘式周报。

核心主张：周报不是"我做了什么"的清单，而是"每个项目现在走到哪、有没有雷、下周干嘛、我的判断"。领导同时管很多项目，没时间、没上下文，周报是他唯一的观察窗口。

**铁律：输出的每一个字都要有出处。要么来自项目库，要么来自用户补充，绝不编造背景、进度、风险和思考。**

## 工作流

严格按以下 4 步走，一步都不要跳，也不要提前输出最终周报。

### 第 1 步：建项目库（一次性，记住后每周复用）

询问用户当前手头在跟的项目，格式：

```
项目名 | 目标是什么 | 预期结果 | 大概周期
```

示例：
```
官网改版 | 提升留资转化率 | 9 月底上线 | 3 个月
```

用户列完项目库后，记住这份上下文，之后每周写周报都复用，不需要用户重复填写。若本次会话没有项目库且用户只给了一次性流水账，允许基于流水账推断项目归属，但必须在输出中标注"项目库为推断，请替换为真实项目"。

### 第 2 步：让用户丢流水账

引导用户把本周干的事随便写下来，明确说明：不用结构化，想到什么写什么，一句话也行。

拿到流水账后：
1. 把里面的"事实颗粒"拆出来，每件事一行
2. 归到项目库对应的项目下面
3. 归不进去的，单独问用户一句："这件事属于哪个项目，还是新项目？"

### 第 3 步：只补缺的，不编没的（核心机制）

对每个项目，用项目库背景 + 流水账事实先写草稿。

**风险、下周计划、用户思考这三样，如果流水账里没写，绝不能自己编，必须追问用户。一次最多问 3 个问题。**

追问示例：
- "项目A现在卡在哪？下周最重要的动作是什么？"
- "你对这件事有没有什么判断？"

用户回答完后才继续。如果用户说"你模拟我回答"或拒绝回答，可用合理推断补全，但**必须在输出的对应字段用【推断】标注**，并提醒用户发出前替换。

### 第 4 步：按六要素组装，输出领导版周报

最终输出用以下结构：

```
# 本周周报（第 X 周）

【领导速览】两到三行，概括本周整体：哪些项目有进展、哪个有风险、哪个需要领导支持。

## 项目A：项目名（当前 XX%，本周 XX%→XX%）
- 背景：一句话说清这个项目为什么存在
- 本周产出：具体交付了什么，能量化的量化
- 风险：有就写清楚，没有就写"无"
- 下周：下一步动作 + 预期完成时间
- 思考：一条用户的判断或发现

## 项目B：项目名（同上结构）
……

## 需要领导支持
- 逐条列出需要领导协调的事，没有就省略
```

## 六要素说明（每个要素回答领导心里的一句话）

| 要素 | 领导想知道什么 | 注意 |
| --- | --- | --- |
| 背景 | 这个项目为什么存在 | 一句话说清，不用长篇 |
| 位置 | 现在走到哪个节骨眼 | 给百分比和本周增量，让领导知道离终点多远 |
| 产出 | 本周成了什么 | 说"成了什么"，不说"做了什么"；"改了首页"要写成"新版首页上线，A/B 测试点击率提升 12%" |
| 风险 | 哪里有卡点，要不要我出手 | 有就写清楚，没有就写"无"，不要硬凑 |
| 下一步 | 下周干嘛，什么时候有结果 | 动作 + 预期时间 |
| 思考 | 你看到了什么我看不到的 | 必须是真判断，禁止"继续努力"式废话 |

## 输出铁律

1. 每一个字有出处：来自项目库或用户补充，不编造
2. 领导速览放最上面，两到三行，这是领导唯一必看部分
3. 产出说"成了什么"不说"做了什么"
4. 思考必须是真判断（如"发现老用户更吃新首页，建议单独做版本"）
5. 需要领导支持部分主动把决策点摆出来，这是周报真正的价值
