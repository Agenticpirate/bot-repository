# 离职交接单生成

目标：把离职员工的任务台账、聊天记录、本地资料整理成一份可直接签字的交接表（Excel），并配套附页明细。

> 本 Skill 由 小朱AI养成（527856337@qq.com）编写，欢迎反馈改进。

## 适用性与降级原则

- **平台无关**：数据可能来自钉钉、飞书、企业微信、微信、Teams、Slack、QQ 或任意自研系统。先确认用户实际使用的平台，再选采集路径。
- **采集双轨制**：优先走自动连接（API/CLI/MCP）；连不上或无授权时，立即切换到**手动提供路径**，引导用户导出或粘贴数据，不要卡死。
- **AI 无关**：本流程只依赖通用能力（读文件、跑脚本、写表格）。执行它的 AI 助手缺少某项能力时（如不能执行脚本），按"降级方案"执行：产出 Markdown/CSV 中间稿，把组装步骤交给用户。
- **授权与最小化**：只处理用户有权提供、且完成本次交接所必需的数据。自动采集前确认数据范围、时间范围、参与人范围和输出接收人；不得绕过登录、权限、审计、导出限制或组织政策。
- **默认不留存**：中间文件放在用户指定的受控目录；交付后说明中间文件位置，由用户决定保留或删除。不得把真实聊天、员工资料或组织内部信息上传到未获批准的第三方服务。

## 前置输入（向用户确认）

1. 交接人姓名、部门、岗位
2. 工作文件夹根路径（本地资料总库）
3. 使用的沟通/任务平台清单（钉钉？飞书？企微？微信？）
4. 记录获取方式：能否用 API/CLI 自动拉取，还是用户手动提供
5. 格式参照件（交接单模板，如有；无则用本文"三段式格式"默认结构）
6. 数据底稿（如已有聊天归类汇总文档则直接使用）

## 步骤

### 1. 数据采集 —— A 轨：自动连接（有 API/CLI/MCP 时）

- **钉钉**：用 `dws` 命令族——`dws aitable` 读任务多维表（按部门筛选、翻页至 hasMore=false）；`dws chat` 拉离职人区间消息（本人发言 + @我，高价值会话双向完整读取）；`dws contact` 核对接人岗位。命令一律加 `--format json`，细节以 `dws <cmd> --help` 为准，不要猜参数。
- **飞书**：优先飞书开放平台多维表格/消息 API 或已安装的飞书 MCP；导出为 xlsx/json 后进入统一处理。
- **Teams/Slack**：管理员导出（Compliance export / workspace export）或已装 MCP，得到后按文本处理。
- 统一输出中间表：任务表（任务名/状态/责任人/计划起止/所属项目）、消息表（时间/会话/发送人/正文）、通讯录表（姓名/岗位/部门）。

### 2. 数据采集 —— B 轨：用户手动提供（无连接手段时的主路径）

按可获得性依次引导用户：

1. **官方导出文件**：企微/飞书/钉钉都支持聊天或数据导出（txt/csv/html/json）；直接解析。
2. **微信类无官方导出的平台**：请用户用"合并转发"把关键会话转成一个文件，或按会话滚动截图、或复制粘贴关键对话文本。
3. **截图**：用视觉/OCR 逐屏读取（标注"截图识别，可能存在误差"），注意按会话与时间排序去重。
4. **口述/粘贴**：用户直接粘贴关键记录文本，逐条录入。
5. **任务台账替代**：无在线任务表时，请用户提供 Excel 任务清单、项目计划表，或按"已完成/进行中/未开始"口述列出。

手动数据的质量控制：记录来源口径（谁提供、什么时间、哪个会话），无法核实的部分标注"用户口述，未核实"。

### 3. 本地资料扫描

- 列出工作文件夹根目录与二级目录树，统计各目录文件数。
- 建立任务 ↔ 资料目录的匹配关系：按任务关键词（项目名/型号/事项类）对应目录；共享盘、PDM/PLM、团队网盘、IM 平台云文件作为公共位置单列。
- 明确口径：正式受控版以公司受控系统（PDM/文档平台）为准，本地为工作过程档案。

### 4. 归类逻辑（数据源无关）

- 以任务名中的**低重复印记**（型号/编码/【】标签/专有词）把消息归入任务；命中为高置信，未命中不等于没聊过。
- 区分：已完成（按项目分组摘要）/ 进行中+未开始+暂停（逐条展开：现状、待办、建议接手人、风险）。
- 提炼接手人第一周优先级（审批权限转移、对外承诺的开放项、未验证的工艺/方案、他人名下遗留事项）。

### 5. 三段式交接表格式（默认结构）

主表同一个 Sheet 内堆叠三张子表，每张有独立表头行，类别列跨行合并：

1. **业务来源**：列=类别·序号·项目明细·任务来源·业务工具·交付标准·备注。每行一个业务模块，交付标准用 1.2.3. 分点写处理路径与交付对象，备注放判断口径。
2. **资料储存**：列=类别·序号·资料明细·路径位置·备注。路径写确切位置（本地路径/网络共享/受控系统/IM 平台云文件+权限人）。
3. **年度项目/临时事项**：列=类别·序号·项目明细·任务进程/交付标准·负责人·优先级。任务进程=当前进度+方案+时间节点，负责人明确到人，优先级 1/2/3。
4. 结尾签署行：交接人：______ 接收人：______

**附页**（内容多时拆分）：
- 附页1 未完成任务明细：序号·状态·所属项目·任务·责任人·计划起止·现状/待办要点·建议接手人·优先级。有聊天证据的写现状/待办/风险；无痕迹的标注"需当面向责任人确认"。
- 附页2 任务↔资料位置匹配：序号·任务/事项·关联资料·存放位置·说明。
- 附页3 关键对接人名册：对接人·岗位/部门·交接注意点。
- 附页4 交接检查表（可签字项）+ 数据来源与覆盖缺口披露（诚实标注哪些数据未覆盖）。

### 6. 生成 Excel（按运行环境选路径）

优先级从高到低：

1. **有 Python**：openpyxl（合并单元格先赋值再 merge；写完后用 LibreOffice/Excel 重算或重开验证）。
2. **Windows + WPS/Excel**：COM 自动化（PowerShell `KET.Application` 或 `Excel.Application`）。脚本保存为 UTF-8 with BOM；行高按内容估算（中文按 2.1 倍字宽折算行数 × 13.5 磅）；`SaveAs(path, 51)` 存 xlsx。使用 PowerShell 7 时可用 `Set-Content -Encoding utf8BOM`，不要混用 Bash 的 `printf/cat` 命令。
3. **macOS**：osascript 驱动 Numbers/Excel，或 Python。
4. **什么都不能跑（降级）**：输出 Markdown 表格 + CSV 文件，附一页"如何粘贴进 Excel"的操作说明，交给用户手工组装。

### 7. 验证（必做）

- 重新打开生成的文件，逐页核对：页签数、各页数据行数与预期一致、表头正确、合并单元格生效、签署行存在。
- 抽查 2~3 个关键单元格内容与源数据一致。
- 数字核对：任务总数 = 已完成 + 未完成；未完成明细行数与总览数字一致。
- 覆盖缺口已披露（未读会话、未 OCR 图片、截图识别误差、用户口述项）。

## 坑位（Pitfalls）

- **微信类无官方导出**：只能合并转发/截图/粘贴，务必记录来源口径与时间范围。
- **截图识别误差**：OCR/视觉读聊天记录会有错漏，关键数字（日期、金额、编码）要让用户复核。
- **隐私与脱敏**：聊天记录含敏感信息，交接文档默认仅交接收人与交接人，分发前确认是否需脱敏。
- **PowerShell 输出是 GBK**：重定向到文件后需 `iconv -f GBK -t UTF-8`；powershell.exe 偶发 "Permission denied" 是安全驱动抖动，隔几秒重试。
- **聊天归类是高置信低召回**：未命中不等于没聊过；无痕迹任务必须标注需口头确认，不得当作无进展。
- **跨 AI 执行差异**：不同 AI 助手的文件读写/脚本能力不同，开工前先探测环境（有没有 python、Office、压缩工具），按第 6 步选路径，不要假设能力存在。

- [ ] 数据来源口径与覆盖缺口已披露
