# 工作邮件起草

根据用户意图起草邮件正文（也可用于企微/飞书长消息）。默认中文。只写用户授权范围内的承诺和信息。

## 什么时候用

- 「帮我回这封邮件」
- 「给客户写一封说明延期的」
- 「催一下对方提供资料，语气客气一点」
- 「把这段话改得正式/简短/好说话一点」

## 先确认（缺了再问）

1. 收件对象：上级 / 同事 / 客户 / 供应商 / 群通知
2. 目的：请示、同步、催办、答复、道歉、邀约、拒绝
3. 必须写进正文的事实（时间、数字、附件名、链接）
4. 语气：正式、平实、强硬、柔和
5. 是否需要英文版或中英双语

## 结构

大多数工作邮件用这个骨架，按场景裁剪：

1. 称呼（不知道名字就写「您好」或对方组名）
2. 一句话说明来意
3. 事实与要点（短段落或条目）
4. 明确请求或下一步（谁、在什么时间前做什么）
5. 结束语 + 署名（用户没给署名就留占位）

## 场景要点

### 催办
- 先提上次约定或已发材料，再写还缺什么、为什么急、期望回复时间。
- 第一次催：客气；再次催：仍克制，但把截止写死。

### 请示上级
- 背景两到三句够了。
- 给出建议方案，别只扔问题。
- 写清需要对方拍板的具体选项。

### 对外答复 / 道歉
- 先回核心问题，再解释原因。
- 道歉具体，不甩锅。
- 补偿或补救方案只写用户明确同意的。

### 进度同步
- 按「已完成 / 进行中 / 风险」写。
- 日期和责任人写清楚。

## 输出

默认一次给两版：

1. **可直接发送版**（完整邮件）
2. **更短版**（适合聊天工具）

主题行单独给出一行。用户只要正文就不要硬塞主题。

## 文风

- 像同事写的，不像稿件。
- 少形容词，少排比。
- 不用「希望一切顺利」「非常感谢您的贵公司」这类空套话堆砌。
- 不承诺用户没说过的交付时间、折扣、责任归属。
- 敏感内容（薪资、处罚、法律结论）草稿里标「请人工确认后再发」。
