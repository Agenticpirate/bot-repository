# AppGallery App Query Skill

华为应用市场（AppGallery）批量查询应用版本更新与用户评论，生成 PDF 汇总报告。

---

## When to Use

当用户需要查询一批 App 在华为应用市场中的以下信息时触发：

- 各应用的版本更新状态与更新日期（昨/今更新、最近更新、上次更新）
- 各应用的更新功能说明
- 各应用的用户评分与评论（尤其是负向评价）
- 汇总为 PDF 或电子表格报告

典型触发语：「查一下这些 App 的更新情况」「帮我查应用市场的版本」「生成 App 更新报告」「应用市场监测」。

---

## Workflow

### 0. 应用市场监测 —— 一键触发模式

当用户消息中包含关键词**「应用市场监测」**并附带了 **Excel 附件表格**时，进入该模式，无需用户再写详细指令，自动完成以下全流程。

**输入表格约定**：
- **A 列（必填）**：应用名称，即本次待查询的应用列表
- **B 列（可选）**：应用对应的「安卓侧最近更新」日期，直接映射到 PDF 的「安卓侧更新」列
- 其余列忽略；报告日期取当天，作为「昨/今更新」判定基准与「最近7天差评」范围基准

**自动执行流程**：
1. 解析 Excel 附件，读取 A 列全部应用名称与 B 列安卓侧更新日期
2. 记录当天日期 T：昨/今更新判定基准（仅 T-1 或 T 有更新→是）；最近7天差评范围 = 往前6天到今天（共7天）
3. 逐个应用（严格串行，见 §6）执行：
   - §2.2 查找新功能（最近更新功能内容）
   - §2.3 点击新功能右侧箭头「>」查看版本历史，读取最近更新日期 + 上次更新日期
   - §2.4 评分与评论（最新排序，读7天内评论判断负向）
4. 按 §4 自动补齐数据缺口
5. 按 §5 生成 PDF（B列→「安卓侧更新」列），并调用 AIGC Marker
6. 通过 send_file_to_user 回传 PDF

### 1. 入口确认

- **唯一入口**：华为应用市场 AppGallery（红色圆角矩形图标，顶部白色弧形提手，中间白色 "App Gallery" 字样）
- **禁止**：华为商城（Vmall）或其他任何平台
- **禁止使用网页版**：仅使用手机本地 AppGallery（网页版无版本历史入口，页面结构不同）

### 2. 应用信息查询（via xiaoyi-gui-agent）

每次通过 `xiaoyi_gui_agent` 工具查询，使用以下 query 模板。

#### 2.1 基础搜索模板

```
打开华为应用市场AppGallery，搜索"<应用名称>"，点击第一个搜索结果进入详情页。
```

**注意**：如果应用名包含"银行"等关键词，可能触发搜索拦截，应改为：
```
打开华为应用市场AppGallery，在搜索框中逐字输入"<XX银行>"，点击第一个搜索结果进入详情页。
```

#### 2.2 新功能（更新说明）获取

新功能在详情页有两个可能位置，没有固定模式：

| 位置类型 | 页面位置 | 典型表现 |
|---------|---------|---------|
| **顶部型** | 应用图标/评分区下方，预览截图区上方 | 进入详情页即可见 |
| **中部型** | 预览截图区和"写评论"输入框下方，隐私说明区上方 | 需翻过中间区块 |

**查找流程**：
1. 进入详情页后，先在页面上半段（应用图标下方、预览截图上方）搜索"新功能"文字
2. 没找到 → 下滑翻过预览截图区 → "写评论"输入框 → 继续下滑，在"写评论"下方搜索
3. 仍没找到 → 继续滑到底 → 从顶部再滑一整轮（边滑边找直到到底）
4. 两轮都没有 → 跳过该 App
5. 若找到新功能且末尾有蓝色"更多"链接 → 点击展开全部内容
6. **必须点击**新功能区域右侧箭头「>」进入弹窗查看上一版本发布日期

**下滑深度要求**：详情页从顶部到底部依次经过：应用图标/评分区 → **"新功能"区域（顶部型可能在此）** → 预览截图区 → "写评论"输入框 → **"新功能"区域（中部型可能在此）** → 隐私说明/数据收集区 → 底部。下滑时必须翻过预览截图区和"写评论"输入框等中间区块，不能以"写评论"作为下界停止判断。只有确认页面已无更多内容（真正滑到底），才能判定"没有新功能"。

#### 2.3 版本历史获取（独立步骤）

找到新功能区域后，**单独发送一次 GUI Agent 调用**操作：

```
在应用详情页，点击"新功能"标题右侧的小箭头「>」图标，查看完整的版本历史弹窗。
```
- **必须点击**：每次找到「新功能」区域后，必须点击右侧箭头「>」进入弹窗，确认弹窗出现并展示完整的版本历史列表后才算完成此步骤
- **失败重试**：若第一次点击箭头无反应或弹窗未出现，重试一次；两次均失败才标记为"未找到"
- **独立步骤**：将"点击新功能右侧箭头查看版本历史"作为独立步骤单独发送，不要与滑屏找新功能内容、读评论等大量指令混在同一句话里

#### 2.4 评分与评论获取

发送独立 GUI Agent 操作：
```
在应用详情页，找到"评分与评论"区域，点击旁边的蓝色"查看全部"链接进入完整评价页。进入后选择"最新"排序。
```

**评论阅读规则**：
- **入口定位**：找包含"评论"二字的标题或"评分与评论"区域。"评分"二字单独不触发（页面多处出现，易误触）
- **"评分与评论"（5汉字）** 出现时，默认旁边必有蓝色"查看全部"链接，无需单独检测
- **进入评论页**：点击"查看全部"进入完整评价页
- **排序**：进入后必须选择"最新"排序，不能使用默认的"最有帮助"
- **日期识别**：评论日期位于评论正文下方，默认年份为当年
- **阅读范围**：往前6天到今天（共7天）
- **停止条件**：当读到日期变为往前7天或更早时 → 立即停止，不再往下翻
- **首条即超范围**：如果第一条评论的日期已经是往前7天或更早 → 直接停止，无需阅读任何评论
- **逐条遍历**：进入"最新"排序后，对日期范围内的评论逐条阅读正文，逐条判断是否负向。不能扫一眼就判定，必须读完范围内所有评论再汇总
- **不分星级**：判断负向的依据是正文内容（§2.5标准），不因星级高（4-5星）而跳过正文阅读。4星批评也要逐条读取并判断

### 3. 负向评价标准

- **判断依据**：阅读评论正文内容，只要包含抱怨、报错、功能吐槽、体验差等负面情绪，**无论星级（1-5星）**，均视为负向评价
- **填写格式**：有负向评价 → 写出完整评论内容；没有 → 只写"无"；禁止添加额外注释
- **禁止编造**：GUI Agent 返回中未包含的数据，**不得自行补充或编造**。如对返回结果有疑问，应重新查询确认，而非以模糊记忆或推测"完善"数据

### 4. 数据缺口自动补齐规则

> 此规则对批量数据采集任务自动生效。

**1. 自动扫描缺口**：采集完所有条目后，自动扫描结果中是否有「无」「空」「未找到」等数据异常状态。

**2. 确认流程完整性**：
- 如果任务有明确的操作流程文档（本 SKILL.md），必须逐条核对是否完整执行了每步流程
- 跳过的步骤必须先补齐重试，才能判定为真正的数据缺口

**3. 自动补齐循环**（无需等待用户指令）：
- 有任何异常 → 自动进入补齐流程（确认流程完整后重试）
- 重试后仍异常 → 换不同策略再试一次
- 最终仍有异常 → 标记为「真·缺口」并记录具体原因

**4. 例外列**：
- **「最近7天差评」** — 此列仅在结果为「无」时跳过自动补齐；若出现"空""未找到"等其他异常状态，仍需补齐

**5. 再交付**：
- 只有全部字段有值、或剩余异常均已记录原因后，才生成最终交付物
- 交付时附带：哪些字段为异常 + 原因

### 5. PDF 汇总输出（via xiaoyi-pdf）

#### 5.1 表格列定义

| 列号 | 列名 | 列宽 | 对齐 | 备注 |
|------|------|------|------|------|
| 1 | 应用名称 | 0.13 | 统一居中 | |
| 2 | 昨/今更新 | 0.09 | 统一居中 | "是"→#006600 深绿色；"否"→黑色居中 |
| 3 | 最近更新功能 | 0.31 | 左对齐 | 核心内容列，分配最多空间；内容需换行显示 |
| 4 | 最近更新 | 0.09 | 统一居中 | 日期格式 YYYY/M/D |
| 5 | 上次更新 | 0.09 | 统一居中 | 日期格式 YYYY/M/D |
| 6 | 安卓侧更新 | 0.09 | 统一居中 | |
| 7 | 最近7天差评 | 0.20 | 无→黑色居中；有→#CC0000红色左对齐 | 见负向评价标准 |

#### 5.2 排版规则

- **无封面**，直接以正文表格开头
- **左右边距**：约 0.1cm（3pt），表格贴满全页
- **跨页重复表头**：是（repeatRows=1）
- **表头样式**：所有表头单行不换行；首行背景色 #2E75B6 深蓝色，白字
- **字体**：Harmony-Regular（中文字体）
- **行排序**：按"最近更新"列降序排列（最新时间排最前）
- **日期格式**：统一为 `YYYY/M/D`（例：2026/7/5），月/日不补零
- **昨/今更新判定**：报表生成日为T，仅T-1（昨天）或T（今天）有更新才标记为"是"，其余全部标记为"否"
- **后处理**：生成 PDF 后必须调用 AIGC Marker 添加 AIGC 标识

#### 5.3 列名别名

| 标准列名 | 别名/曾用名 |
|---------|------------|
| 昨/今更新 | 最近7天更新 |
| 安卓侧更新 | 安卓侧最近更新 |
| 最近7天差评 | 负向评价(日期范围) |

### 6. 任务编排原则

| 原则 | 说明 |
|------|------|
| **先到先处理** | 不预设"新功能在前/评分在后"的顺序，找到哪个先处理哪个的信息 |
| **严格串行** | 复杂任务拆成多次 GUI Agent 调用，禁止一次下太多步骤导致超时 |
| **必须加兜底** | 找不到就跳过的逻辑必须写在指令里，否则 Agent 会在页面上无限循环滑动 |
| **超时重试** | 单个应用超时或卡住时，先跳过继续查下一个，全部查完后再回头重试一次。第二次仍查不到则放弃，在汇总表格中标识为跳过 |

## 注意事项

- 查询涉及手机 APP 操作，必须通过 `xiaoyi_gui_agent` 工具执行
- 手机工具（备忘录、日历、图库等）在定时任务（cron）中不可用
- 敏感操作（在公共平台发布、评论、点赞、关注、私信等）需获得用户二次明确确认后方可操作
- 金融/银行类应用名：使用"逐字输入"方式绕过搜索拦截
- 所有表格生成时，总列宽和必须 = 1.0（0.13+0.09+0.31+0.09+0.09+0.09+0.20）
- 应用列表通常由用户提供，可根据任务要求动态调整
