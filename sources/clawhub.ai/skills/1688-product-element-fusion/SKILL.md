# 元素融合创款

从视觉灵感中提取创意元素，在1688找到同元素真实商品，调研其材料/款式/成本后融合生成概念图。核心价值不在"生图"，在**元素拆解 + 落地调研 + 嫁接逻辑**。

**完整链路**：灵感图 → 提取元素 → 元素转关键词 → 关键词搜目标品类 → 调研 → 创款

## 输入收集

启动时向用户收集两项输入：

1. **灵感素材** — 图片路径（本地文件或用户粘贴的图片）。视频请用户截取关键帧
2. **目标品类**（必问）— 用户想把元素用到的商品品类（如"陶瓷杯"、"连衣裙"），或1688商品链接/ID

**关键原则**：目标品类是用户**想做的商品品类**，不是灵感图中出现的物品品类。灵感图里的物品（如街拍人物穿的裙子）只是元素的载体，不代表目标品类。

如果用户只给了图片没说目标品类，必须主动询问："你想把这些元素用到什么商品上？（如：陶瓷杯、手机壳、帆布包）"，得到明确回答后才能进入 Stage 2。

**版权提示**：收集灵感素材时，提示用户「请确保您提供的灵感图片拥有合法使用权」。

## Pipeline（五步）

```
[Stage 1] 视觉解析 + 元素提取 → 结构化元素卡片
    ↓
[Stage 2] 元素搜品：1688 商品匹配 → 候选商品列表
    ↓
[Stage 3] 商品调研 + 融合方案 ← 人工审核点 ①
    ↓
[Stage 4] 概念图融合生成 → 2-3 张变体
    ↓
[Stage 5] 用户审核/微调 ← 人工审核点 ② → 最终输出
```

每一步的详细指令见下方。元素模型和提取指引见 [references/element-model.md](references/element-model.md)，融合 prompt 模板见 [references/fusion-prompt.md](references/fusion-prompt.md)，完整案例见 [references/examples.md](references/examples.md)。

## 全局约束

以下约束对所有 Stage 生效，优先级高于各 Stage 局部指令：

| 约束 | 规则 |
|------|------|
| 成本脱敏 | 禁止输出具体价格数字或价格区间，成本相关描述一律使用定性档位（如"亲民档"、"中高档"、"成本基本不变"、"成本上升"） |
| 法务合规 | Stage 1 须输出版权提示；Stage 4/5 须输出法务声明 |

### Stage 1：视觉解析 + 元素提取

**工具**：Read（读取图片，多模态分析）

1. 用 Read 工具读取用户提供的图片
2. 对图片进行整体视觉感知，按六维度逐一提取创意元素
3. 每个维度输出 2-3 个具体描述项，并评估提取置信度（0-1）

**六维度**：色彩 / 材质质感 / 风格标签 / 场景氛围 / 装饰图案 / 构图手法

详细提取指引和 prompt 见 [references/element-model.md](references/element-model.md)。

**输出元素卡片**（展示给用户参考，无需确认）：

📋 元素卡片

━━━━━━━━━━━━━━━━━━━━━

来源：{图片简要描述}


🎨 色彩：{主色}、{辅色}、{点缀色} — {色彩关系}

🧱 材质：{材质1}、{材质2}、{材质3}

🏷 风格：{风格标签1}、{风格标签2}

🌅 氛围：{氛围描述1}、{氛围描述2}

✨ 图案：{图案1}、{图案2}

📐 构图：{构图手法1}、{构图手法2}

置信度：色彩 {X} / 材质 {X} / 风格 {X} / 氛围 {X} / 图案 {X} / 构图 {X}

━━━━━━━━━━━━━━━━━━━━━

同时保存结构化 JSON 供后续阶段使用（JSON Schema 见 element-model.md）。

**输出格式**：元素卡片严格按上述模板输出，六维度 + 置信度不可省略。

**版权提示**：收集灵感素材时，提示用户「请确保您提供的灵感图片拥有合法使用权」。

**元素偏好确认**：展示元素卡片后，询问用户："你最想把哪些元素用到产品上？"用户可以：

- **选元素** — 从元素卡片中选出最想要的 1-3 个维度（如"色彩和材质最重要"、"风格是核心，其他无所谓"）
- **补充元素** — 说出自己想加的元素，即使灵感图里没有（如"再加点金属质感"）
- **说"自动"** — 按提取置信度最高的元素继续，不追问

这些偏好将在 Stage 2 搜品时优先作为修饰词、Stage 3 融合方案中标记为核心维度。

**视频处理**：如果用户输入视频，提示"请截取 2-3 个最能代表你想要风格的关键帧图片，我来逐一分析"。

### Stage 2：元素搜品（1688 商品匹配）

**输入**：Stage 1 提取的元素 + 用户指定的目标品类/关键词

**搜索方式：只允许关键词搜品，禁止以图搜品。** 灵感图只用于 Stage 1 提取元素，不参与任何图片搜索。

**查询策略**：用元素关键词在1688搜索**目标品类**的商品。构建搜索 query 的规则：

1. **品类锚定**：目标品类**只来自用户输入**（品类名称/关键词/1688链接），严禁从灵感图元素推断品类。灵感图中出现的物品品类（如街拍中的连衣裙）≠ 目标品类
2. **核心属性叠加**：从六维度中选 2-3 个最有区分度的词作为修饰（通常：材质 + 风格 + 图案）
3. **query 示例**：元素"日式侘寂 + 水洗棉麻 + 雾霾蓝 + 扎染纹"，目标品类"陶瓷杯" → query "日式 侘寂 陶瓷杯"
4. 如果结果少，放宽条件（去掉风格或图案修饰）

**执行方式**：通过 Skill 工具调用 `1688-supplychain-procurement` 采购技能进行关键词找品：

```
Skill(
  skill: "1688-supplychain-procurement",
  args: "帮我找 日式 侘寂 陶瓷杯"
)
```

**防图搜红线**：

- 传入技能的只能是纯关键词文本，**严禁**附带灵感图、图片 URL、`<attached_file>` 附件标记或本地路径——任何图片信息都会触发该技能的以图搜品
- 找品关键词从 Stage 1 元素转化而来，灵感图本身不进入找品环节
- 该技能可能发起需求澄清（show_interaction），按其内部流程配合即可，找品结果以其返回的候选商品列表为准

**结果**：获取候选列表（5-10 个），每个包含：商品图片、标题、价格、链接。

**兜底**：如果搜索结果不理想，引导用户直接提供1688商品链接或ID。

### Stage 3：商品调研 + 融合方案（人工审核点 ①）

**目标**：不能凭空融合。先调研匹配到的真实商品，让融合方案贴合实际、可落地。

**执行步骤**：

1. **商品调研** — 对候选商品逐一分析，提取四个维度：
   - **材料**：材质构成（从标题、属性、详情中提取，如"PU皮"、"陶瓷釉面"、"水洗棉"）
   - **款式**：主流版型、结构、部件（如头枕的绑带式/卡扣式、杯子的直筒/锥形）
   - **装饰复杂度**：花纹、结构部件的实现难度（简单/中等/复杂），不直接输出工艺类型（印花、刺绣、开模、开版等）
   - **成本敏感点**：定性描述价格档位（如"亲民档"、"中高档"）+ 影响成本的因素（花纹复杂度、异形结构、特殊质感），不输出具体价格区间
2. **提炼"可落地性"发现** — 把调研结论转化为融合约束，示例：
   - 匹配结果发现"汽车头枕花纹过于复杂 → 装饰复杂度高，成本上升" → 方案改用简洁几何图案或局部点缀
   - "陶瓷杯异形把手 → 结构复杂度高，成本上升" → 保留标准把手，改釉色/图案
   - "连衣裙大面积装饰纹样 → 装饰复杂度高，成本上升" → 装饰收敛为领口小面积点缀
3. **输出融合方案**（严格按以下格式输出）：

| 输出项 | 内容 | 约束 |
|--------|------|------|
| 基底商品 | 商品标题 + 1688 链接 + 选择理由 | 从候选列表中选**最适合结合元素的一个**（依据：款式、表面、结构上最能承载创意元素的），用户可换，或在左侧面板勾选 |
| 元素裁剪 | 分三类：应用 / 弱化 / 放弃，每项附调研依据 | 每类至少 1 项，决策须引用调研发现 |
| 成本提示 | 定性描述融合后成本变化方向 | 禁止输出具体价格数字或区间，仅用"成本基本不变/小幅上升/大幅上升"等定性描述 |
4. 将融合方案展示给用户确认：

> 请确认这个融合方案是否可以？如果没问题我直接进入概念图生成。你也可以：
>
> - **换一个基底商品** — 左侧AI找货源面板勾选后回车告诉我，或者直接提供商品图
> - **调整某个元素的应用方式** — 比如"色彩再淡一点"、"材质换成哑光"
> - 说"**自动**"直接生成

用户说"没问题"/"自动"则直接进入 Stage 4。

**快捷通道**：用户已在 Stage 1 提供具体商品链接/ID，只调研该商品后输出方案。

### Stage 4：概念图融合生成

**工具**：ImageGen（图生图模式）

这是最核心的环节。**必须使用图生图模式**——将融合方案的基底商品主图 + 灵感图作为参考图传入 ImageGen 的 `image` 参数，确保生成结果贴合真实商品形态。

**执行步骤**：

1. 读取 [references/fusion-prompt.md](references/fusion-prompt.md) 获取 prompt 模板
2. 获取基底商品的主图 URL（从搜索结果的 enriched_file 中提取 imageUrl 字段）
3. 用融合方案中的元素裁剪结果 + 基底商品信息填充 prompt 模板
4. 调用 ImageGen 时 **必须传入 `image` 参数**，包含：
   - 商品主图 URL（保留产品真实形态）
   - 灵感素材图 URL（传递视觉风格）
5. 按变体策略生成 2-3 张概念图：
   - **变体 A（忠实融合）**：所有元素均匀应用
   - **变体 B（元素强化）**：融合方案中确定的核心维度放大，其他弱化
   - **变体 C（克制融合）**：只应用最核心的 1 个维度，保留更多原始产品特征
6. 每张图 size 根据品类选择：
   - 服装/家居/大件：`1024x1536`（竖版产品图）
   - 小商品/配饰/杯具：`1024x1024`（方形）
   - 场景氛围为主：`1792x1024`（横版场景图）

**输出格式**：每个变体生成后紧跟 1-2 句文字说明，描述融合特点。禁止使用 `present_files` 等工具重复展示图片（图片由平台立即展示）。

**法务声明**：生成概念图仅供参考，不构成商业决策建议，版权归属遵循平台用户协议。

**图生图调用示例**：
```
ImageGen(
  prompt: "融合 prompt 文本...",
  image: ["商品主图URL", "灵感素材图URL"],
  size: "1024x1024"
)
```

**融合 prompt 核心结构**：

```
产品摄影风格概念图。

[产品] {商品标题}，{品类}。核心特征：{从商品图推断的视觉特征}。

[融合指令] 在保留产品基本形态和功能可识别性的前提下，将以下创意元素融入：
- 色彩：调整为{色彩描述}
- 材质：表面处理为{材质描述}
- 风格：整体视觉对齐{风格标签}美学
- 场景：置于{场景氛围}中
- 图案：表面融入{装饰图案}
- 构图：{构图手法}

[品质约束] 产品摄影级别，真实感，自然光影，不是插画或抽象画。
```

详细模板和变体策略见 [references/fusion-prompt.md](references/fusion-prompt.md)。

### Stage 5：审核与微调（人工审核点 ②）

展示生成的概念图后，用户可以：

- **选一张满意的** → 保存为最终输出
- **微调** → "颜色再深一点"、"材质感再强一些" → 调整 prompt 后重新生成
- **全部不满意** → 回到 Stage 3 调整融合方案
- **保存为模板** → 将元素卡片保存为 JSON，下次直接复用

**最终输出格式**（严格按以下结构输出，保存到 outputs 目录）：

| 序号 | 输出项 | 约束 |
|------|--------|------|
| 1 | 概念图（PNG） | 平台已展示，无需额外动作 |
| 2 | 元素卡片摘要 | 文本形式，方便复制分享 |
| 3 | 商品原始链接 | 1688 商品链接 |
| 4 | 使用的融合 prompt | 方便后续微调 |
| 5 | 法务声明 | 必须包含："生成概念图仅供参考，不构成商业决策建议，版权归属遵循平台用户协议" |

**法务声明**：生成概念图仅供参考，不构成商业决策建议，版权归属遵循平台用户协议。

## 快捷模式

用户说"快速模式"或"全自动"时，压缩审核点：

- Stage 3 融合方案自动确认（默认基底商品 + 默认元素裁剪）
- Stage 4 只生成变体 A（忠实融合）
- Stage 5 直接输出，不做微调引导

## 元素模板复用

如果用户之前保存过元素卡片 JSON，可以直接加载使用，跳过 Stage 1：

```
用户："用上次保存的元素卡片，帮我融合到这个陶瓷杯上"
→ 加载 JSON → 直接进入 Stage 2（元素搜品）或 Stage 4（直接融合）
```
