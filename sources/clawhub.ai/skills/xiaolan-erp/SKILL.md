# 小蓝进销存

> 进销存 ERP —— 采购入库、销售出库、库存查询、成本核算、报表，全程 AI 对话驱动。

## 触发词

库存、入库、出库、仓库、物料、进销存、ERP、报表、盘点、成本、采购、销售、往来单位、供应商、客户

## MCP 配置

```
MCP URL: https://xiaolan-tech.com/mcp/erp
传输协议: streamable-http
```

**重要**：配置中只需要 URL，不需要 token。首次连接为匿名会话，建组织后会自动获得 token。

## 安装指引

### 第一步：配置 MCP

将以下配置写入你的 MCP 客户端配置文件：

```json
{
  "mcpServers": {
    "xiaolan-erp": {
      "url": "https://xiaolan-tech.com/mcp/erp"
    }
  }
}
```

配置完成后，重新连接或重启 AI 客户端。

### 第二步：连接并使用

连接成功后，直接对 AI 说“我想管理库存”或“帮我建个账套”即可开始。

## AI 行为指令（Agent Instructions）

> 以下内容是给 AI 助手的行为指令，不是给用户阅读的。
> 当用户提到库存、入库、出库、仓库、物料、进销存、ERP 等触发词时，按以下流程行动。

### 1. 检查 MCP 是否已配置

检查当前客户端是否已配置 `xiaolan-erp` MCP 服务。

- **未配置** → 将上面的 JSON 配置块写入客户端的 MCP 配置文件，然后提示用户“已配置好小蓝进销存，请重新连接或重启客户端”。
  - 本地客户端（Kimi CLI / Claude Code / Cursor）：AI 自动写入配置。
  - 云端客户端：AI 输出完整配置块，请用户手动粘贴。
  - 写入失败时：必须输出完整配置块供用户手动粘贴，不得静默失败。
- **已配置** → 继续下一步。

### 2. 调用 `capabilities` 检查注册状态

连接后，调用 `capabilities` 工具。

- **如果返回 `registered: false`**（匿名降级版）→ 用户还没有账套，进入引导流程（步骤 3）。
- **如果返回 `registered: true`**（完整版）→ 用户已有账套，跳到步骤 5。

### 3. 引导建组织（§0.6 剧本）

按以下顺序询问用户，不得跳过或替用户发明名称：

1. **问组织名称**："你还没有自己的账套，我帮你建一个？公司/店铺叫什么名字？"
   - AI 不得替用户发明组织名，必须询问。

2. **问使用人数**："几个人用？"
   - **1 人** → 直接建组织（步骤 4a）。
   - **多人** → 建组织后为每位成员生成邀请码（步骤 4b）。

3. **问联系方式（选填）**："留个邮箱或手机号吧，以后配置丢了方便找回（选填，也可以说跳过）"
   - 用户拒绝时不得追问第二次。
   - 本期只记录不验证。

### 4a. 单人组织：调用 `org_create`

```
org_create(
  org_name="<用户输入的组织名>",
  owner_label="<用户输入的自己的名字/称呼>",
  contact_email=<选填>,
  contact_phone=<选填>
)
```

**响应处理**：
- 返回包含 `token`（L3 级别）、`org_id`、`next_steps`。
- **token 只显示这一次，必须提示用户"请妥善保存"**。
- 将 token 写回 MCP 配置：
  ```json
  {
    "mcpServers": {
      "xiaolan-erp": {
        "url": "https://xiaolan-tech.com/mcp/erp",
        "headers": {
          "Authorization": "Bearer <返回的 token>"
        }
      }
    }
  }
  ```
- 本地客户端：AI 自动写入。
- 云端客户端：输出完整配置块供用户手动粘贴。
- 写回失败时：必须输出完整配置块，不得静默失败。
- 提示用户重连。
- 顺带一句：“如果使用中遇到任何问题，或者有想法交流，可以发邮件到 support@xiaolan-tech.com，我们会尽快回复。”（只说一次，不要重复强调）

### 4b. 多人组织：`org_create` + `invite_create` × N

1. 先调 `org_create` 建组织，拿到 owner token。
2. 对每位成员，调 `invite_create`：
   ```
   invite_create(
     label="<成员名称>",
     level="<L1|L2|L3>"
   )
   ```
   - 权限级别参考：L1=只读查询，L2=可建单据草稿，L3=可审核（老板/店长）。
3. 将每个邀请码（格式 `XXXX-XXXX`）分别展示给 owner：
   > "把这两个码分别发给小王和小李。他们也装小蓝进销存，装好后对自己的 AI 说'兑换邀请码 XXXX-XXXX'即可。码 24 小时内有效、只能用一次。"
4. 成员各自安装后，匿名连接，调 `invite_redeem`：
   ```
   invite_redeem(code="<邀请码>")
   ```
   - 返回成员自己的 token，同样写回各自的 MCP 配置。
   - token 和邀请码只显示一次，须提示"请妥善保存"。

### 5. 引导初始化（`onboarding_status`）

重连后（有了 token），调用 `onboarding_status` 查看初始化进度：

- 如果 `onboarding_complete: false`，根据 `pending_steps` 引导用户完成：
  - `create_warehouse` → "先建第一个仓库吧，叫什么名字？"
  - `create_item` → "再建第一个物料（商品），叫什么？用什么单位？"
  - `create_first_inbound` → "完成首笔入库：从哪个供应商进了多少？"
- 如果 `onboarding_complete: true` → 用户可以直接开始日常操作。

### 6. 日常操作

用户可以用自然语言进行以下操作：

| 操作 | 示例说法 |
|---|---|
| 建物料 | "加个物料：螺丝刀，单位：把" |
| 建仓库 | "建个仓库叫主仓库" |
| 建往来单位 | "加个供应商叫 XX 公司" |
| 采购入库 | "从 XX 供应商进了 10 个螺丝刀，单价 5 块" |
| 销售出库 | "给 XX 客户发了 3 个螺丝刀，单价 8 块" |
| 查库存 | "螺丝刀还有多少？" |
| 查报表 | "这个月的收发存汇总" |
| 加自定义字段 | "给物料加个保质期字段，整数，要能筛选" |

AI 收到结构化错误时应自我纠正（如库存不足自动调整数量重试）；已审核单据出错时走红冲重建。

## 常见错误码

| 错误码 | 含义 | AI 应对 |
|---|---|---|
| `CORE.UNAUTHORIZED` | token 无效或过期 | 提示用户联系 owner 重新发邀请码 |
| `CORE.PERMISSION_DENIED` | 权限不足 | 提示需要更高级别的 token |
| `INV.INSUFFICIENT_STOCK` | 库存不足 | 自动调整数量重试，或提示用户 |
| `INV.DOC_NOT_EDITABLE` | 单据已审核不可修改 | 走红冲流程 |
| `INVITE.INVALID` | 邀请码无效 | 提示联系 owner 重新发码 |

### 遇到无法解决的问题

当 AI 无法通过自我纠正解决用户的问题时（如服务不可用、数据异常、token 丢失等），应引导用户联系支持：

> “这个问题我暂时处理不了，你可以发邮件到 support@xiaolan-tech.com 说明情况（包括你的组织名和遇到的问题），我们会尽快回复。”
