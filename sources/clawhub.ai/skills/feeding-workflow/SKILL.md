# 喂料专家 · 五步投喂工作流

> 把散料变成真料：收料核实、原创化入库、喂料包装配，让知识库与 AI 团队有真料可依，杜绝编造。

## 这是什么

喂料专家（Feed Master）是一套「知识投喂」工作流：把用户扔过来的散料（文件 / 网址 / 贴文 / 会议记录 / 截图）加工成"已核实、可入库、可被 AI 直接使用"的知识资产，服务于知识库运营、RAG 补料和多智能体团队喂料。

核心信条：**喂料质量 = 下游 AI 产出质量**。AI 不会自动核实自己编造的数字，凡喂料包没有的它就会自行填补——本工作流用「三要素纪律 + 源头较真核实」从源头堵住编造。

## 核心能力

1. **五步喂料流程**：收料登记 → 溯源核实 → 提炼原创化 → 分区入库 → 回执，全程留痕可追溯。
2. **喂料包三要素纪律**：凡带数值/限值/条款的料，必须三要素齐全——`出处`（官方来源+日期）+ `适用条件`（什么产品/什么市场/什么阶段）+ `归口标准`（哪个法规/标准体系管）。
3. **源头较真核实**：官方源优先（gov.cn / nmpa.gov.cn / ecfr.gov / eur-lex / iso.org / openFDA 等一手源），逐条核数值、条款、编号；查不到就标"待核实"，绝不推断填充。
4. **原创化与去敏**：第三方内容不镜像原文，改写重组只留公开客观事实；入库/发布前做敏感扫描（真名/邮箱/手机号/本地路径/密钥），0 命中才放行。

## 工作流程（五步，固定顺序）

1. **收料登记**：登记料源、格式、数量，建/更新喂料台账（对象 × 缺料 × 优先级 × 状态）。
2. **溯源核实**：逐条查官方源核实数值/条款/证号；每一条结论标注出处与核实日期。
3. **提炼原创化**：第三方内容改写为自有逻辑重组，只保留可公开的客观事实；区分公开区（可入知识库）与私密区（只留本地）。
4. **分区入库**：按目标落地——知识库 references / RAG 补料区 / 喂料包容器，回写索引。
5. **回执**：台账记一行（喂了什么、核实到什么程度）+ 知会用户。

## 输出规范

- 每条带数值/限值/条款的料，必须附三要素：出处 + 适用条件 + 归口标准
- 查不到官方源的，标"待核实"，禁止自行"补全"
- 第三方内容不镜像原文、不标注第三方出处，原创化重组
- 喂料包命名：`喂料包_主题_YYYYMMDD_vN.md`
- 每次喂料：台账记一行 + 向用户回执

## 快速开始

试试这样问：

- 「这批素材帮我按五步流程处理入库（登记→核实→原创化→入库→回执）」
- 「给多智能体团队准备一份喂料包，数值带出处/适用条件/归口标准」
- 「盘点现有知识库缺口，出一份喂料清单」

## 能力边界

- 本工作流负责"把料加工好"，不替代下游 AI 的产出；凡喂料包没有的内容，要求下游一律标"待核实"。
- 入库云端知识库、发布、外发属外部动作，执行前必须征得用户授权。
- 官方源查不到的，只能标"待核实"——宁缺毋编。
