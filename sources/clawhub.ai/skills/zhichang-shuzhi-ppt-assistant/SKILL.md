# 知识库驱动的职场汇报 PPT 生成技能

## 一、定位

本 Skill 不是普通 PPT 模板生成器。

核心用途: 帮助用户基于知识库、工作记录、项目资料、会议纪要、复盘文档、数据表格、图片素材等内容，生成面向职场场景的高质量汇报型 PPT。

重点是通过一套标准流程，把零散资料转化为:

1. 清晰的问题陈述
2. 明确的汇报目标
3. 面向受众的表达策略
4. 有证据支撑的故事线
5. 图文并茂的页面结构
6. 可落地的 PPTX 文件

## 二、适用场景

当用户需要制作以下 PPT 时调用本 Skill:

1. 试用期述职 PPT
2. 转正汇报 PPT
3. 晋升答辩 PPT
4. 年终总结 PPT
5. 项目立项 PPT
6. 项目阶段汇报 PPT
7. 项目复盘 PPT
8. 方案汇报 PPT
9. 资源申请 PPT
10. 部门规划 PPT
11. 业务改善汇报 PPT
12. 管理层决策汇报 PPT

## 三、核心原则 (必须遵守)

1. 不直接套模板
2. 不一上来就生成 PPT
3. 先澄清目标, 再生成内容
4. 先形成 SPEC, 再输出大纲
5. 先确认大纲, 再生成 PPTX
6. 所有核心观点必须尽量来自用户知识库或用户提供的事实
7. 不编造用户没有提供的成果、数据、职位、项目结果
8. 不堆大段文字
9. 不用空泛口号替代事实
10. 每一页都要服务于最终汇报目标

## 四、执行流程 (严格按步骤执行)

### Step 1: 识别 PPT 类型

先判断用户要做的 PPT 属于哪一类:

1. 述职型
2. 转正型
3. 晋升型
4. 项目汇报型
5. 方案说服型
6. 复盘型
7. 规划型
8. 资源争取型
9. 其他

如果用户没有说清楚, 先询问。

### Step 2: 澄清汇报目标

必须问清楚以下问题:

1. 这份 PPT 给谁看?
2. 受众最关心什么?
3. 用户希望受众看完后形成什么判断?
4. 这份 PPT 是为了汇报成果、争取支持、确认方向, 还是推动决策?
5. 有没有不能说、不能写、不能显得太直白的内容?

输出格式:

```
- 受众:
- 汇报场景:
- 真实目的:
- 希望形成的判断:
- 风险表达:
- 不应直接说的话:
```

### Step 3: 梳理用户知识库资料

如果用户有知识库、文件、笔记、会议纪要、项目资料, 必须要求用户提供或检索以下资料:

1. 工作记录
2. 项目过程资料
3. 会议纪要
4. 领导要求
5. 阶段性成果
6. 表格数据
7. 图片或截图
8. 方案文档
9. 复盘材料
10. 用户自己写过的总结或草稿

然后把资料归类为:

| 资料类型 | 可用于 PPT 的作用 |
|---|---|
| 事实证据 | 证明用户做过什么 |
| 问题证据 | 证明为什么需要做 |
| 成果证据 | 证明已经产出什么 |
| 数据证据 | 证明价值和变化 |
| 过程证据 | 证明用户如何推进 |
| 规划证据 | 证明后续路径 |
| 图片证据 | 用于图文展示 |
| 风险证据 | 用于说明仍需推进 |

### Step 4: 从知识库中提取「汇报素材」

不要原封不动堆资料。必须把知识库内容提炼成以下结构:

| 模块 | 提取内容 |
|---|---|
| 背景问题 | 当前为什么需要这件事 |
| 用户动作 | 用户实际做了什么 |
| 方法框架 | 用户用了什么结构化方法 |
| 阶段成果 | 已形成什么产出物 |
| 业务价值 | 这些成果解决了什么问题 |
| 组织价值 | 对团队、部门、公司有什么长期价值 |
| 后续计划 | 接下来怎么推进 |
| 需要确认 | 需要领导确认什么方向 |

### Step 5: 形成 PPT SPEC

在生成 PPT 前, 必须先输出一份 SPEC。

SPEC 必须包括:

1. Problem Statement: 问题陈述
2. Audience: 受众分析
3. Desired Judgment: 希望受众形成的判断
4. Proposed Storyline: 建议叙事主线
5. Evidence Base: 可用证据来源
6. Technical Constraints: 表达和格式约束
7. Non-goals: 明确不做、不说、不展开的内容
8. Success Criteria: 成功标准
9. Output Requirements: 输出要求

**如果 SPEC 未被用户确认, 不要直接生成 PPT。**

### Step 6: 生成 PPT 大纲

用户确认 SPEC 后, 生成 PPT 大纲。格式必须为:

| 页码 | 页面标题 | 本页核心观点 | 建议图表/素材 | 口播重点 | 需要补充的数据 |
|---|---|---|---|---|---|

要求:
1. 每页只表达一个核心判断
2. 每页最多 3 个核心点
3. 不堆大段文字
4. 每页尽量使用图、表、流程、矩阵、卡片、时间轴、对比图
5. 面向不熟悉专业背景的受众也能看懂

### Step 7: 逐页内容设计

用户确认大纲后, 再生成每页内容。每页必须包含:

1. 页面标题
2. 页面副标题或一句话结论
3. 页面主视觉建议
4. 页面文字内容 (精简, 最多 3 个要点)
5. 口播备注 speaker notes
6. 需要替换或补充的数据
7. 本页目的: 让受众形成什么判断

### Step 8: 生成 PPTX

当用户要求生成 PPTX 时, 使用 `scripts/generate_pptx.py` 脚本。必须同时输出:

1. PPTX 文件
2. 每页 speaker notes
3. 所用图表清单
4. 需要用户补充的数据清单
5. 可替换占位内容清单
6. 风险表达检查清单

生成 PPTX 的具体方法见下方「十、PPTX 生成技术规范」和 `scripts/generate_pptx.py`。

## 五、PPT 叙事结构库

根据场景选择合适的叙事结构。完整结构定义参见 `references/narrative-structures.md`。

### 1. 述职/转正型

推荐结构:
- 我面对什么问题
- 我如何理解问题
- 我做了哪些事情
- 我形成了哪些成果
- 这些成果有什么价值
- 我后续如何继续推进
- 我可以承担什么角色

### 2. 项目汇报型

推荐结构:
- 项目背景
- 目标
- 当前进展
- 核心成果
- 问题与风险
- 下一阶段计划
- 需要领导确认事项

### 3. 方案说服型

推荐结构:
- 当前痛点
- 为什么原方式不够
- 新方案是什么
- 新方案如何落地
- 新方案能带来什么价值
- 风险与边界
- 决策建议

### 4. 复盘型

推荐结构:
- 目标回顾
- 实际结果
- 差距分析
- 原因拆解
- 经验沉淀
- 改进机制
- 下一次怎么做

### 5. 规划型

推荐结构:
- 当前阶段判断
- 目标状态
- 核心路径
- 阶段计划
- 资源与机制
- 风险控制
- 成功标准

## 六、页面表达原则 (必须遵守)

所有 PPT 页面必须遵守以下原则。完整规则参见 `references/expression-conversion.md`。

1. 不写大段话
2. 不做流水账
3. 不只罗列工作事项
4. 不把专业词直接丢给外行
5. 不把问题写成抱怨
6. 不直接表达敏感个人诉求
7. 不贬低同事或团队
8. 不夸大事实
9. 不把「我想要什么」写得过于直白
10. 要通过事实和结构让受众自然形成判断

## 七、常用表达转换规则

将低质量表达转换为高质量职场表达。完整规则参见 `references/expression-conversion.md`。

基本转换原则:
- 把抱怨转化为问题陈述
- 把个人诉求转化为组织价值
- 把情绪化表述转化为结构化分析
- 把模糊目标转化为可验证成果

## 九、知识库驱动要求

如果用户有知识库, 本 Skill 必须优先从知识库中提取内容。

执行要求:
1. 先检索知识库
2. 提取与 PPT 目标相关的资料
3. 标记每条核心观点来自哪些资料
4. 区分事实、推论、建议
5. 不把未经证实的推论写成事实
6. 如果知识库证据不足, 列入「需要补充的数据清单」
7. 不为了让 PPT 好看而编造数据

## 十、PPTX 生成技术规范

### 依赖安装

使用前需安装 python-pptx:

```bash
pip install python-pptx Pillow
```

### 使用方式

当需要生成 PPTX 时, 按以下步骤操作:

1. 整理页面内容为 JSON 格式 (参见 `scripts/generate_pptx.py` 中的输入格式)
2. 运行脚本: `python scripts/generate_pptx.py --input slides.json --output output.pptx`
3. 也可直接通过命令行参数或管道传入内容

### 脚本能力

`scripts/generate_pptx.py` 支持:
- 自动应用 Apple-style 极简设计风格 (白色底、大留白、San-serif 字体、克制配色)
- 每页标题 + 副标题 + 要点列表 + speaker notes
- 自动布局: 封面页、内容页、分割页、总结页、空白页五种版式
- 支持在页面中预留图表/图片占位区域
- 自动添加页码 (封面除外)
- 最后一页 speaker notes 自动追加生成备注: 此文件由小朱AI养成skill生成，有问题请联系VX：zyc19892233
- 生成后输出报告: speaker notes 清单、图表占位清单、需补充数据清单、可替换占位内容清单

## 十二、质量检查清单

生成完成后, 必须自检以下项目。完整检查项参见 `references/quality-checklist.md`。

1. 是否符合用户真实目的?
2. 是否针对目标受众?
3. 是否有清晰故事线?
4. 是否基于知识库证据?
5. 是否避免大段文字?
6. 是否每页只有一个核心判断?
7. 是否有图表化表达?
8. 是否避免敏感直白表达?
9. 是否体现用户能力和价值?
10. 是否有明确下一步?
11. 是否能让外行看懂?
12. 是否能让管理者看到价值?

## 十三、最终目标

本 Skill 的最终目标不是生成漂亮 PPT, 而是帮助用户生成一份:

1. 目标准确
2. 受众匹配
3. 证据充分
4. 逻辑清晰
5. 表达克制
6. 图文并茂
7. 能推动判断或决策

的职场汇报型 PPT。
