# 类案检索报告生成 Skill

## 一、功能定位

基于待决案件信息，通过 deli-cli 获取类案候选，完成案件拆解、检索执行、类案筛选、比对分析与规则提炼，最终输出一份可直接向法院提交或供内部策略研判使用的标准化《类案检索报告》。

所有中间环节作为后台处理流程，不单独生成过程性文件；唯一输出物为《类案检索报告》。

法律依据：《最高人民法院关于统一法律适用加强类案检索的指导意见（试行）》（2020年7月27日）。

## 二、前置工作

命中本 skill 后，凡需要执行类案检索、相似案例匹配、报告候选案例获取、分页查看更多结果或调用后端能力，必须先执行 [deli-cli 通用前置](./references/cli-common.md)。

完成 CLI 前置检查后，通过当前 skill scope 发现命令，并以当次返回的 `RUN id`、命令名和参数形态执行；不得假设固定命令或固定参数存在。

如果 CLI 未配置、不可用或未返回覆盖当前任务的命令，应先说明“检索受限”或“命令不可用”，并给出建议检索式或需要用户补充的事实，不得编造案例信息。

## 三、触发条件

### 3.1 主动触发

| 触发类型 | 典型表达 |
|---------|---------|
| 类案检索 | “帮我检索类似案例”“查一下这个案由的类案”“做类案检索报告” |
| 裁判观点查询 | “法院对这类问题怎么判的”“有没有支持我方观点的判决” |
| 裁判倾向预判 | “这类案件一般判赢还是判输”“类似案件的胜诉率如何” |
| 案例参考 | “找几个和本案类似的生效判决”“有没有最高院的类似案例” |
| 提交法院准备 | “我要向法院提交类案检索报告”“检索支持我方主张的典型案例” |

### 3.2 被动触发

在对话上下文中，用户已提供待决案件的基本事实、争议焦点或案由信息，且后续提问涉及“法院怎么判”“类似案例”“裁判观点”“案例支持”等需求时，自动激活。

### 3.3 不触发场景

- 纯理论法学问题。
- 法律意见书、合同审查、尽职调查等深度分析任务；类案检索可作为子步骤，但不单独替代主任务。
- 寒暄或无关内容。

## 四、信息收集

触发本 skill 后，若用户未提供以下信息，须逐一确认：

| 信息项 | 重要性 | 说明 |
|-------|-------|------|
| 待决案件基本事实 | 必需 | 主体关系、交易结构、核心行为、纠纷经过 |
| 核心争议焦点 | 必需 | 如合同效力、责任承担、损失计算标准 |
| 案由 | 必需 | 如营业信托纠纷、合同纠纷 |
| 所涉法条 | 推荐 | 用于法条关联和裁判规则定位 |
| 待决案件所在省份/法院 | 推荐 | 用于地域性类案优先筛选 |
| 检索目的 | 推荐 | 向法院提交或内部策略研判 |
| 委托方立场 | 推荐 | 原告、被告、申请人等，用于报告分析视角 |

必需信息缺失时须追问；推荐信息缺失时可基于已有信息进行有限假设，但须在报告中注明。

## 五、执行流程

### Step 1：待决案件拆解与检索标准确立

1. 事实拆解：提取时间线、主体关系、交易结构、核心行为及结果。
2. 争议焦点提炼：归纳 1-3 个核心争议焦点。
3. 法律关系定位：明确案由、所涉法条及法律规则。
4. 相似性标准：以基本事实、争议焦点、法律适用问题三要素判断类案相似性。

### Step 2：CLI 检索策略制定

先执行 [deli-cli 通用前置](./references/cli-common.md)，再阅读 [类案检索 CLI 策略指南](./references/api-guide.md)，按当前 `cmds` 返回的命令和参数制定检索方案。

检索层级优先级：

| 优先级 | 检索目标 | 说明 |
|:------:|---------|------|
| 1 | 最高人民法院指导性案例 | 须参照适用 |
| 2 | 最高人民法院典型案例及裁判生效案件 | 典型案例及生效裁判 |
| 3 | 本省高级人民法院参考性案例及裁判生效案件 | 体现地域裁判口径 |
| 4 | 上一级法院及本院裁判生效案件 | 作为本案裁判参考 |

### Step 3：CLI 检索执行与数据获取

根据检索目的分别形成关键词主题或长文本事实摘要。每次调用都记录检索目的、检索主题、法院层级、时间范围、CLI 返回数量和初筛结果。

如用户提供案件材料文件，先提取案件事实摘要，再按 `cmds` 返回的长文本、相似案例或材料摘要参数形态调用。

首次检索无结果或结果不足时，不自动连续扩词重试；先说明不足，并给出一个建议改写检索式或需要补充的事实。

### Step 4：类案筛选与精细化识别

1. 深度审读：调取 CLI 返回的内容摘要、法院观点或裁判要旨。
2. 相似性比对：评估基本事实、争议焦点、法律适用三要素匹配度。
3. 分类标注：按裁判结果分类，例如支持、驳回、认定有效、认定无效、未明确表态。
4. 去重合并：系列案件在除当事人外基本相同时合并统计，并在报告中说明合并理由。

字段缺失时不得补写；可在工作底稿中标注“CLI 未返回”。

### Step 5：类案比对与裁判观点分析

1. 裁判观点摘要：摘录或概括与争议焦点相关的核心论述。
2. 规则提炼：归纳支持不同裁判结果的法律逻辑。
3. 异同分析：对比类案与待决案件在事实细节、法律适用、裁判结果上的异同。
4. 倾向性判断：统计各级法院裁判观点分布，提示地域分歧和时间演变。

报告须同时呈现有利与不利案例；对不利类案主动分析其与待决案件的差异性，不得选择性回避。

### Step 6：类案检索报告生成

输出完整报告，格式见 [标准报告模板](./references/report-template.md)。

## 六、报告格式规范

报告标题：`【{待决案件名称/案号}】类案检索报告`

报告头部信息：

- 检索日期：{YYYY年MM月DD日}
- 生成主体：得理案例数据库 AI 检索系统
- 主数据源：deli-cli 返回的得理案例数据库结果
- 提交说明：{供向法院提交 / 供内部策略研判使用}

### 第一部分：检索情况概述

1. 检索目的：明确为解决待决案件哪项争议焦点而检索。
2. 检索平台：列明 deli-cli 返回结果及必要的补充核验来源。
3. 检索条件：列明检索主题、事实摘要、法院层级、时间范围和筛选条件。
4. 检索结果及结论：呈现整体倾向、各级法院观点分布和不确定性。

### 第二部分：类案信息总表

| 序号 | 审理法院 | 案件名称 | 案号 | 裁判时间 | 案涉标的 | 争议焦点 | 法院观点 | 裁判结果 | 数据来源 |
|:---:|---------|---------|------|---------|---------|---------|---------|:-------:|---------|
| 1 | {法院名称} | {名称} | {案号} | {年份} | {标的} | {焦点} | {摘要} | {结果} | deli-cli 返回结果 |

如类案为指导性案例，在案件名称栏特别标注“【指导性案例】”；系列合并案件在脚注中说明合并理由。

### 第三部分：类案裁判观点摘要

按裁判结果分类逐案摘录，至少包含案号、审理法院、裁判时间、数据来源、核心裁判观点和裁判结果。

### 第四部分：分析说明

1. 类案与本案异同比较。
2. 裁判倾向性判断。
3. 参照或参考意见：建议参照、建议参考或建议不予参照，并说明理由。

## 七、质量控制要点

| 控制项 | 规范要求 |
|-------|---------|
| 指导性案例标注 | 检索到指导性案例须明确标注，分析说明中论证参照理由 |
| 时效性控制 | 优先使用近三年案例；援引早期案例须说明裁判规则持续有效性 |
| 地域性考量 | 注意不同地区裁判分歧，在报告中特别提示并分析原因 |
| 客观性保证 | 同时呈现有利与不利类案，不得选择性呈现 |
| 原文忠实性 | 法院观点须来自 CLI 返回内容、裁判要旨或经核验的官方文本，不得曲解 |
| 数据透明性 | 每个类案须标注数据来源 |
| 补充验证 | 对拟作为主要参照的关键类案，通过官方渠道核验案号、法院、裁判日期 |
