## 数据处理前置声明 / Data Handling Notice（先读本节）

金融客服场景涉及账户、身份与交易信息，处理前必须遵守：

| 原则 | 具体要求 |
|---|---|
| 最小必要 | 只索取办理该项业务必需的字段，不主动收集与业务无关信息 |
| 脱敏展示 | 卡号、证件号、手机号默认只显示后四位；不在对话中复述完整号码 |
| 目的限定 | 告知客户信息用途，不用于业务目的之外 |
| 授权核验 | 查询他人账户须有合法授权，亲属关系不构成授权 |
| 保存留痕 | 对话与工单按本机构档案与合规要求留存，超出期限清理 |
| 预览确认 | 生成的话术、工单、外发内容须先向使用者展示，经明确确认后再落库或外发 |

**绝不出现的四类内容**
1. 完整卡号、证件号、密码、验证码、短信码
2. 收益承诺、保本承诺、风险淡化表述
3. 代客操作（代客转账、代客签约、代客解约）
4. 对同业或具体个人的评价与贬损

> 本节为通用合规提示，具体执行口径以本机构制度与监管最新规定为准。

```python
| 注销账户 | 条件、前置清理项、办理渠道 | 网点办理 | 是 | 一律转人工或网点 |

**FAQ 回答三段式**
1. 直接给路径（客户要的是"怎么操作"，不是"为什么"）
2. 给一个时限或一个数字（模糊答复会引发二次来电）
3. 给出失败时的下一步（转人工条件前置说明）

**避免的三类答复**
- "请您稍后再试" —— 没有时限，等于没说
- "系统显示正常" —— 与客户感受冲突，易激化
- "这个不归我们管" —— 应给出明确归属与联系方式
```

```python
### 2b. 投诉分级与时效 / Escalation & SLA

> 各级别时限为示例口径，须以本机构制度与监管要求为准。

**禁止话术 / Never Say**

| 禁止表述 | 为什么 | 替代说法 |
|---|---|---|
| "这不是我们的责任" | 激化矛盾、无助于解决 | "我先帮您核实具体情况，会给您明确答复" |
| "系统就是这样" | 推诿 | "我记录您的情况，反馈给相关部门优化" |
| "您自己去网点问吧" | 推诿且无路径 | "这个需要网点办理，我帮您查询最近的网点并说明携带材料" |
| "肯定/保证能解决" | 过度承诺 | "我会在 X 个工作日给您明确结论" |
| "稍后再试" | 无限时 | "请您在 X 时间后再查看，如仍未恢复我这边为您登记跟进" |
| "别人都没这个问题" | 否定客户感受 | "我理解给您带来不便，我们先看具体原因" |
```

### 3. Intent Classification / 意图分类

```python
class IntentClassifier:
    """客户意图分类"""
    
    INTENT_PATTERNS = {
        "查询类": {
            "keywords": ["查询", "看看", "多少", "有没有", "怎么"],
            "entities": ["余额", "账单", "记录", "流水", "积分"]
        },
        "办理类": {
            "keywords": ["办理", "开通", "申请", "设置", "修改"],
            "entities": ["转账", "分期", "还款", "挂失", "密码"]
        },
        "投诉类": {
            "keywords": ["投诉", "不满", "问题", "没用", "太差"],
            "entities": ["服务", "处理", "速度", "态度"]
        },
        "咨询类": {
            "keywords": ["问问", "了解一下", "怎么用", "是什么"],
            "entities": ["产品", "功能", "规则", "费用"]
        }
    }
    
    def classify(self, query: str) -> dict:
        """意图分类"""
        for intent, patterns in self.INTENT_PATTERNS.items():
            score = 0
            for kw in patterns["keywords"]:
                if kw in query:
                    score += 1
            for entity in patterns["entities"]:
                if entity in query:
                    score += 2
            
            if score >= 2:
                return {
                    "intent": intent,
                    "confidence": min(score / 5, 1.0),
                    "suggested_response_type": self._get_response_type(intent)
                }
        
        return {"intent": "unknown", "confidence": 0}

| 查询类 | "余额多少" "账单在哪看" | FAQ/自助 | 身份核验 | 未核验不得展示账户信息 |
| 办理类 | "我要挂失" "开通短信" | 自助或人工 | 身份核验 + 意愿确认 | 不得代客操作 |
| 投诉类 | "我要投诉" "太差了" | 投诉SOP → 人工 | 工单要素 | 不与争辩，先安抚登记 |
| 咨询类 | "怎么收费" "有什么区别" | FAQ | 无需核验 | 不得作收益承诺 |
| 紧急类 | "卡被盗刷" "钱没了" | 立即转风控 | 卡号后四位 | 先止损，再解释 |
| 未知 | 无法归类 | 澄清一次 → 转人工 | — | 连续 2 轮未识别即转人工 |

**unknown 处理策略（三选一，不要循环追问）**
1. 给出最相近的 2 个候选：'您是想查询账单，还是想了解费用？'
2. 仍无法确认 → 直接转人工，并告知客户正在转接
3. 记录该语料进入未识别清单，每周复盘补充知识库
```

### 4. 合规红线 / Compliance Red Lines

| 红线 | 说明 | 风险 |
|---|---|---|
| 不作收益或保本承诺 | 涉及理财、基金、保险代销 | 合规与消保风险 |
| 不代客操作 | 不代客转账、签约、解约、改密 | 效力争议与资金风险 |
| 不索取验证码/密码 | 任何情况下都不得索取 | 诈骗与信息安全风险 |
| 不泄露完整账户信息 | 卡号证件号仅显示后四位 | 信息泄露 |
| 不隐瞒智能客服身份 | 客户询问时如实告知 | 信任与合规风险 |
| 不推诿无归属 | 无明确归属时须给出路径 | 投诉升级 |
| 不淡化风险 | 产品咨询须提示风险等级 | 适当性与消保风险 |
| 不评价同业与个人 | 只陈述本机构规则 | 合规与声誉风险 |
| 结论性表述须可追溯 | 引用规则名称与依据 | 无法回溯 |
| 外发与落库须先确认 | 话术、工单、邮件先预览 | 误发与合规风险 |
