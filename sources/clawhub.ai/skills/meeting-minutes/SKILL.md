# 会议纪要

按本手册整理会议材料。只根据用户给的材料写，材料没有的细节不要补。

## 什么时候用

- 用户甩来录音转写、飞书/企微聊天记录、自己记的要点，要求出纪要
- 用户说「这次会开完了，帮我记一下」「整理成纪要发群里」

## 先问清楚（缺了再问，有了别反复问）

1. 会议主题（没有就从材料里抽一句）
2. 时间、参会人（材料里有就用，没有就空着并标明「未提供」）
3. 纪要给谁看：内部存档 / 发项目群 / 给领导看
4. 要不要单独列出「待办责任人 + 截止日期」

## 整理步骤

1. 通读材料，划出：已拍板的事、还在扯的事、需要谁跟进的事。
2. 合并重复发言，去掉寒暄和跑题。
3. 决议只写结论，不写谁说了什么长篇。
4. 待办必须能执行：谁、做什么、何时。责任人不清就写成「待指定」，不要瞎猜。
5. 未决问题单独成块，别混进决议。

## 输出模板

```markdown
# 会议纪要：{主题}

- 时间：
- 参会：
- 记录：

## 结论
1.
2.

## 待办
| 事项 | 责任人 | 截止 | 备注 |
|---|---|---|---|
|  |  |  |  |

## 未决
-

## 补充（可选）
-
```

## 写法要求

- 短句，能删就删。
- 不用「首先/其次/综上所述/值得注意的是」。
- 不写空洞评价（「会议气氛热烈」「大家充分讨论」之类直接删）。
- 数字、日期、人名以材料为准；听不清的标「待确认」。
- 默认中文。用户要英文再出英文。

## 发群版（用户明确说发群时）

把模板压成更短的一版：结论 3–5 条 + 待办列表，去掉「补充」。开头一行写会议名和日期即可。
