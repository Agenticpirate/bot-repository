# 教学案例写作（Business Case Writing）：从灵感到成稿

**核心承诺**：主人给一个灵感（一句话想法、一个公司、一条新闻、一个决策困境、一个理论概念），即可交付一份逻辑清晰、结构严谨、符合学术规范的商学院教学案例（Business Case），支持中文、英文或中英双语版本。

本技能是妙笔先生案例写作的**总纲**，组织为：方法论源流 → 五段流水线 → 结构模板 → 写作铁律 → 双语规范 → 去 AI 味 → 质量检查 → 配套资源。
配套技能（可在 ClawHub 检索或按需自建）：teaching-note（教学笔记）、case-method-facilitation（案例教学法）、case-publishing（投稿发表）、case-analysis-writing（学生案例分析作业）、knowledge-base（知识库检索）、humanizer（去 AI 味）。

## 一、方法论源流：向顶尖商学院学什么

### 1. 哈佛商学院（HBS）——「决策者故事」

- 案例是 10-20 页文档，**以真实组织中的真实主角（protagonist）视角**撰写，以必须做出的关键决策收尾（decision point）
- **信息不完整是刻意设计**（incomplete by design）：学生在信息缺口下做决策
- 案例教学四步：独立研读分析 → 小组讨论 → 课堂辩论 → 反思
- 写作十步（Lundberg Case Consortium）：定焦点 → 构框架 → 背景研究 → 一手调研 → 访谈（反复追问「然后呢？And then what happened?」建立时间线）→ 搭结构 → 叙事技巧 → 待在故事之内（只写当时已知信息）→ 作者隐身（学生看不出作者倾向，课堂才有辩论）→ 清样（clearance）
- **组合建议**：金融投资方向的案例，取 HBS 的「决策者故事 + 决策点」骨架，配 Wharton 的「数据分析密度」，是最佳组合

### 2. 沃顿商学院（Wharton）——「数据与分析驱动的决策」

- 案例数据密集、分析工具导向；决策必须能通过财务、统计、博弈论等分析框架检验
- 分析严谨性先于戏剧性：结论有数据支撑，决策可建模验证
- 对金融投资类案例尤其适用：财务模型、估值、情景分析是案例的核心血肉

### 3. 国际共识（Ivey / RSM / CAIS / Emerald）

- 教学案例 = 组织真实管理情境的「打包快照」：呈现问题/挑战/机遇，风格生动可信，迫使学生代入决策者
- 教学案例 ≠ 研究案例：只讲故事不下判断；可对信息选择、简化、强调（以最大化教学价值），但事实须真实
- 必须有 **hook（钩子）**：统领全局、需要紧急处理的决策问题；不能一眼看穿，要学生拼凑线索发现；必须与某个概念/理论/方法论挂钩（Farhoomand, CAIS）
- 好案例「易读而难解」：线索都在文本里但隐藏起来，多层结构越挖越有
- 篇幅：本科 5-8 页、MBA/高管 8-15 页正文（不含附录）；8-10 页的案例卖得最好；迷你案例 2-5 页

## 二、五段流水线：灵感 → 成稿

### 阶段 1：灵感捕捉与选题验证（Inspiration Intake）

输入可以是任何形式的灵感。立即做三件事：

1. **转成决策焦点测试句**：「**X（公司/主角）在 Y 情境下，面对 Z 约束，是否应该做 W？**」
2. **验证三性**：紧迫性（有 deadline 吗？）、戏剧性（有冲突、两难、利益分歧吗？）、教学性（挂靠什么理论/概念？）
3. **查重**：在 thecasecentre.org 及案例库检索，避免与已有案例重复

输出：**选题验证卡**——焦点句 + 教学价值 + 素材来源（公开资料/访谈） + 案例类型（field case 实地调研首选 / library case 公开资料 / armchair case 虚构泛化慎用）+ 篇幅定位。

### 阶段 2：案例简报（Case Brief）——动笔前必须答 10 问

1. 教学目标：教什么理论/概念/方法论？用于哪门课？
2. 受众与难度：本科生/MBA/高管？难度三级——L1 给方案让学生评判；L2 给问题让学生出方案；L3 只给情境让学生先找问题再出方案
3. 焦点：具体可执行？足够一般化（能导出普适教训）？紧迫（有 deadline）？只有一个？
4. 新鲜度：独特吗？查重过了吗？
5. 类型：field / library / armchair；full-length / mini / series / multimedia
6. 戏剧元素：争议、对比、冲突、两难在哪里？
7. 主角：谁来决策？为什么是他/她？他的视角能让学生代入吗？
8. hook 与线索：学生需要拼凑哪些线索才能发现真问题？
9. 信息量：给足可拆解分析的信息，但不给诊断与答案
10. 教学法：课堂讨论、角色扮演还是模拟？

输出：一页 **Case Brief** + **教学笔记草案**（教学目标、讨论问题、理论框架）。铁律：**教学笔记先行**——动笔前先列目标，教学笔记与案例并行起草、相互校验。

### 阶段 3：骨架搭建（Outline）

- 按标准结构列大纲：Title → Opening → Background → Development → Decision Point → Exhibits
- 每个章节标注：信息来源、关键数据点、需要核实/交叉验证的数字
- 金融案例：确定 Exhibit 清单（财务报表、估值表、市场数据、时间线），正文中编号引用
- 输出：带 Exhibit 编号的章节大纲（可套用 templates/case-outline.md）

### 阶段 4：正文起草（Draft）

- 按 HBS 结构写正文；第三人称、过去时；数据融入叙事（「收入三年翻倍，但利润率下滑到 8%」而非「业绩表现优秀」）
- 只讲故事、不做分析；作者隐身；信息不完整是设计
- 引语不超过 3 句；引语重在意准而非逐字
- 金融案例：确保有可计算、可建模的数据，附录支持正文
- 输出：初稿（含 Exhibits）

### 阶段 5：去 AI 味与交付（Humanize & Deliver）——**必经步骤，不可跳过**

1. 用 humanizer 技能逐段清理初稿（调用方式见第六节）
2. 对照第七节质量清单自检
3. 按目标语言交付：中文版 / 英文版 / 双语版（见第五节）
4. 交付物：案例正文 + Exhibits + 配套 Teaching Note

## 三、HBS 标准结构模板

```
标题（Title）：公司 + 决策困境，有吸引力（可加副标题「IPO 还是并购？」）
引言（Opening，1-3 段）：
 - 场景与基调（会议室、电话、屏幕上的数字）
 - 主角（姓名、职位）
 - 时间（具体日期）、地点（组织）
 - 事件脉络（为什么、怎么样）
 - 以 1-2 个主角面临的关键问题收束（hook）
背景（Background）：
 - 行业背景（漏斗结构：先一般后具体）
 - 公司背景（只放与决策相关的信息，拒绝公司全史）
 - 宏观/市场（融资环境、周期位置）
发展（Development / Case Story）：
 - 按时间线推进事件，逐步揭示矛盾与压力
 - 呈现多方视角、竞争性替代方案
 - 用引语增强戏剧性与真实性（≤3 句）
决策点（Decision Point）：
 - 回到主角视角，信息收窄、压力最大
 - 明确选项与约束，不做解答
附录（Exhibits）：
 - 财务数据、图表、时间线；编号并在正文引用（Exhibit 1: ...）
可选：尾声（Epilogue）——已发生的结果，用于课后讨论（常放教学笔记）
```

- Closing 与 Opening 呼应：开头的问题具体紧迫，结尾的问题更深更一般化，仍回到主角视角
- 小标题简短描述性（如「The Chemicals Industry」），最多一层，避免结构碎片化

## 四、写作铁律（十条）

1. **一个案例，一个决策焦点**——不要试图解决多个问题
2. **教学笔记先行**——先列教学目标、讨论问题、理论框架
3. **只讲故事，不做分析**——分析、诊断、经验教训全部留给教学笔记
4. **作者隐身**——客观中立，不评判；必须表达判断时借人物之口说出
5. **主角视角**——真实可代入的决策者（高管/经理/创业者），不用外部顾问当主角
6. **信息不完整是设计，不是缺陷**——给足可拆解的信息，不给答案
7. **紧迫感**——决策必须有 deadline（「面对政府补贴削减 50%，如何调整资金策略」优于「资金策略怎么定」）
8. **戏剧张力**——争议、冲突、两难是灵魂；好案例有「Wow!」感
9. **数据是血肉**——财务数据、图表、Exhibits 嵌入叙事；金融案例尤其要有可计算、可建模的数据
10. **真实可溯源**——公开事实标注来源；敏感信息脱敏或获授权（release）

## 五、双语写作规范（中 / 英）

### 版本关系

- **双语案例 = 同一事实内核，两套语言表达；不是机械翻译**——按各自语言习惯重写
- 推荐顺序：先写母语版（定事实、逻辑、数据），再写第二语言版；两版事实与数字必须一致

### 中文版规范

- 商业/学术术语保留英文原文：CAPM、Teaching Note、decision point、hook、Exhibit、LBO
- 数字用中文习惯：万、亿；日期用「2024 年 3 月」；货币注明币种（人民币 ¥、美元 US$、港元 HK$）
- 引语可意译但须准确；人名保留原文或首次出现时中英对照
- 行文：简洁、直接、报纸语言；避免翻译腔与公文腔

### 英文版规范（HBS 出版风格）

- 美式拼写（organize 非 organise）；数字用 million/billion；货币用 $、HK$；日期 Month DD, YYYY
- 标题用 sentence case（句首字母大写）；引语用直引号 " "
- 人物首次出现全名 + 职位（如 Jane Smith, chief financial officer），此后只用姓氏；职位不大写
- 一律过去时，用具体时间锚点（「In May 2024, ...」）而非「currently」

### 双语对照表（写作时随身携带）

| 中文 | English |
|------|---------|
| 决策点 | decision point |
| 主角 | protagonist |
| 教学笔记 | Teaching Note |
| 附录 | Exhibits |
| 案例简报 | case brief |
| 信息不完整是刻意设计 | incomplete by design |
| 戏剧张力 / 钩子 | dramatic tension / hook |
| 实地调研案例 / 公开资料案例 | field case / library case |
| 清样（授权审阅） | clearance |

## 六、去 AI 味：humanizer 集成（写作环节必调）

### 调用时机

- 阶段 4 初稿完成后、阶段 5 交付前，对正文（含中文版和英文版）逐段执行
- 若要求快速交付，至少保证 Opening、决策点段落和全部引语过一遍

### 调用方式

- 读取 humanizer 技能（ClawHub 社区有 humanizer 类技能可安装，或参考 Wikipedia「Signs of AI writing」指南自建）：按其 24 类模式清单（内容、语言语法、风格、沟通、填充词五大类）逐项扫描与改写
- 输出格式：改写后文本 + 变更摘要（可选）

### 案例写作特有的 AI 味重灾区（在 humanizer 清单之外额外注意）

- 陈词滥调式开头（「Mr. Y leaned back in his chair pondering the challenges...」——HBS 明令禁止）
- 排比三连、negative parallelism（「Not only... but also...」「这不仅关乎...更关乎...」）
- 空洞评价与升华（「体现了公司对创新的坚定承诺」「marking a pivotal moment」）
- 分析性语言混入叙事（案例只讲故事，分析留给教学笔记）
- AI 高频词：landscape、pivotal、underscore、testament、leverage、robust、seamless、vibrant、showcase、delve、foster
- em dash（——/—）滥用；加粗滥用；-ing 悬挂结构（ensuring.../reflecting...）
- 模板化结尾（「The future looks bright...」「展望未来，前景广阔」）
- 中文套话：「值得注意的是」「不难发现」「综上所述」「赋能」「抓手」「生态」

### 平衡提醒

- humanizer 建议「加入个性」，但案例作者必须隐身——「个性」体现为**叙事的具体细节、节奏变化、真实引语**，绝不是作者观点或价值判断
- 客观中立的案例 + 具体生动的细节 = 有灵魂且合规；切勿为了「有个性」破坏作者隐身铁律

## 七、质量检查清单

结构完整性：
- [ ] 有清晰的唯一决策焦点？
- [ ] Opening 含 6W（何时/何地/何人/何事/为何/如何）并以关键问题收束？
- [ ] 背景只含与决策相关的信息？
- [ ] 故事有多方视角与戏剧张力？
- [ ] 结尾回到主角视角、呼应开头？
- [ ] 附录编号完整、正文有引用？

文体合规：
- [ ] 第三人称、过去时（中文版相应时态处理）？
- [ ] 无分析、无诊断、无「经验教训」？
- [ ] 作者立场不可辨（学生看不出作者倾向）？
- [ ] 语言简洁、无行话、朗读测试通过？
- [ ] humanizer 已执行，无 AI 味残留？

内容质量：
- [ ] 数据真实可溯源、交叉验证过？
- [ ] 信息量恰到好处——足够分析，不淹没重点？
- [ ] 有紧迫感和 deadline？
- [ ] 引语生动且经授权？
- [ ] 与教学笔记互相支撑？

双语合规（如交付双语版）：
- [ ] 两版事实与数字完全一致？
- [ ] 各自符合语言习惯（非翻译腔）？
- [ ] 中英术语对照正确？

合规：
- [ ] 组织/被引用者授权（release）到位？
- [ ] 版权材料获准使用？
- [ ] 敏感信息已脱敏或说明？
