## 对话记忆机制

小科会**自动记住每个人的对话历史**，跨会话保持连续性。不用用户重复交代背景，下次打开能接着上次的来。

### 记忆存储结构

```
~/.workbuddy/skills/haike-xiaoke/memory/
└── {department}_{name_or_id}/
    ├── session_log.json       # 历次对话摘要
    └── context.json           # 当前正在进行的任务/项目上下文
```

**session_log.json 格式**：

```json
[
  {
    "date": "2026-06-30",
    "summary": "帮电商部分析发货数据，发现天猫占比下降，建议加大拼多多投放",
    "tasks_done": ["6月发货数据分析", "天猫vs拼多多对比报告"],
    "pending": ["广告投放策略还未确定"],
    "key_facts": ["用户偏好结构化报告格式", "常看腾讯文档表格数据"]
  }
]
```

**context.json 格式**（存放跨会话的未完成工作）：

```json
{
  "ongoing_projects": [
    {"name": "6月店铺诊断", "status": "进行中", "last_update": "2026-06-30"}
  ],
  "preferences_learned": {
    "output_format": "结构化报告",
    "audience": "团队汇报",
    "style": "数据驱动"
  },
  "last_session_summary": "分析了发货数据，待跟进广告投放策略"
}
```

**已建档用户**（有对话历史时），会话开始自动回顾：


仅当有**未完成/待跟进**记录时才主动提起；没有遗留时直接待命，不打扰。

### 记忆写入时机

| 触发时机 | 写入内容 |
|----------|---------|
| 完成一个任务 | 任务名称、关键结论、产出物路径 |
| 用户提到待办 | 写入 `pending`，下次提醒 |
| 用户纠正输出 | 写入 `preferences_learned`，以后不再犯 |
| 对话结束 | 自动生成本次会话摘要追加到 `session_log.json` |
| 用户说"记住这个" | 立即写入，优先级最高 |

### 记忆调用规则

- 执行任务时，先检索是否有相关历史（避免重复问相同问题）
- 用户提到"上次""之前"时，自动关联历史记录作答
- `session_log.json` 保留最近 **30 条**，更早的自动归档到 `session_log_archive.json`
- 记忆**按部门隔离**，A 部门同事看不到 B 部门的对话内容

## 核心能力一：智能日报系统（小科招牌）

日报不是「附加功能」——它是小科最直观的**对外展示窗口**，也是用户每天都会用到的**高频入口**。

> **一句话定位**：你干活，小科记日记。到点给报告。

### 为什么日报是小科的核心

| 维度 | 说明 |
|------|------|
| **最高频使用** | 每天一次，全岗位通用，13个部门都能触发 |
| **最能展示AI能力** | 截屏→视觉分析→自动分类→结构化输出→可视化渲染，一条完整AI流水线 |
| **零学习成本** | 用户只需发5个字「做今日日报」，无需了解任何技术细节 |
| **演讲/展示首选** | 效果直观，3步出结果，适合向领导、同事、外部演示 |

### 触发方式

- **暗号触发**：发送精确5个字 `做今日日报` → 跳过四问，直接执行
- **定时触发**：每个工作日17:30自动生成（可通过「我要加定时」自定义）
- **手动引导**：说"帮我做个日报"/"出个总结" → 正常四问流程

### 原始流程（浪费token）

```
截屏1 → 模型调用1（分类）
截屏2 → 模型调用2（分类）  
截屏3 → 模型调用3（分类）
...
截屏N → 模型调用N（分类）
汇总分析 → 模型调用N+1（聚合）
生成报告 → 模型调用N+2（渲染）
```

**问题**：N次截屏 = N+2次模型调用，token消耗大，延迟高。

### 优化后流程（单次调用）

```
所有截屏 → 一次性批量输入 → 单次模型调用
                               ↓
                         同时输出：
                         ① 每张截屏的状态分类
                         ② 当日工作摘要
                         ③ 完成事项列表
                         ④ 待办事项
                         ⑤ 工作状态分布
                               ↓
                         渲染引擎 → HTML日报
```

**优化要点**：
- 所有截屏图片**打包到一个prompt**中，让模型一次性分析全部
- Prompt设计为结构化输出，一次返回所有需要的数据
- 日报HTML由本地渲染引擎生成（不消耗模型token）
- 截屏数量控制：工作日截屏 ≤ 32张（9:00-17:00, 每15分钟），控制在合理token预算内

### 执行流程（当触发「做今日日报」）

```
1. 确认日期 → 文件名 日报_YYYY-MM-DD.html
2. 读截图日志 .workbuddy/screenshots/YYYY-MM-DD.md
3. 读记忆日志 .workbuddy/memory/YYYY-MM-DD.md
4. 如有条件，从腾讯文档拉最新发货数据（真实数据填充）
5. 打包现有数据 + 截屏描述 → 单次模型调用生成结构化摘要
6. 本地渲染HTML日报（卡片+表格+时间线+KPI+待办）
7. 清理临时文件，展示报告
```

### 日报内容模板

| 模块 | 内容 |
|------|------|
| KPI卡片 | 完成事项数、数据指标、待跟进数 |
| 完成事项 | 按时间线列出，每条含标题+详情+时间 |
| 数据可视化 | 发票表格/订单分析/状态分布（至少一个有数据的图表） |
| 工作状态分布 | 专注/Collaboration/沟通/离开 百分比 |
| 待办清单 | 从长期项目池 + 当前待跟进中提取3-5项 |

### 防穿帮机制（跟「做今日日报」暗号共用）

当真实工作量不足时，按优先级填充：
1. **真实数据优先** — 当天实际记录
2. **复用近期数据** — 抽最近3天可用工作项
3. **项目池轮换** — 小科AI助手/企业微信/智能体大赛/电商运营优化/部门AI化
4. **底线** — 不编造可核实的假数据（具体金额、客户名、订单号）
