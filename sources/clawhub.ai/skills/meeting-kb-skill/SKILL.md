# 跨会议知识库（meeting-kb-skill）

> 基于官方「腾讯会议 Skill（tmeet）」二创 · 赛事主题「让开会更简单」

单场会议的价值有限，**跨会议的知识沉淀**才是组织资产。本 Skill 把多场会议的决策/结论/行动项/风险聚合为一个**可检索知识库**，让"上次会怎么定的""支付相关决策有哪些"一查即得，打通周报、复盘、面试、培训的场景边界。

## 一、能力边界

- 单向依赖 **腾讯会议 Skill（tmeet）**：多场会议的智能纪要/转写拉取。
- 本地模式：`kb_build.py` 直接读本地纪要素材目录，零依赖。
- 增强能力（v3）：章节优先归类、一行只归一类、自动去重、**行动项结构化（负责人/截止日）**、统计概览、增强检索、**文件校验与诊断输出**。

## 二、标准工作流

1. 通过 tmeet 拉取多场会议的智能纪要 / 转写。
2. **归类抽取**：按类型沉淀 **决策 / 结论 / 行动项 / 风险**。
   - 优先依据素材中的 `## 决策`、`## 行动项` 等章节标题归类（最准）；
   - 无章节的自由文本，按关键词特异性优先级（决策 > 行动项 > 风险 > 结论）归类，**一行只归一个类别**，避免重复。
   - 自动去重：归一化（全/半角、标点、大小写）后相同条目只保留一次。
3. **行动项结构化**：从行动项文本中抽取 `负责人` 与 `截止日(DDL)`，便于追踪与跟进。
4. 构建可检索知识库（索引 Markdown，或本地向量检索）。
5. 支持关键词查询，返回跨会议的相关条目、出处、章节，并提示是否涉及多会议冲突。

## 三、与 tmeet 的对接指令（给 Agent）

- 批量拉取：`tmeet 录制管理 列表` → 逐场 `智能纪要 <会议ID>`
- 历史会议：`tmeet 会议管理 查询`（按时间/主题筛选）

> 若环境未安装 tmeet，直接读取用户提供的纪要素材目录，走本地模式。

## 四、本地脚本 `kb_build.py` 使用说明

```bash
# 构建知识库（产物：知识库.md）
python scripts/kb_build.py --input-dir <素材目录>
# 多关键词 OR（命中任一即可），按命中数排序
python scripts/kb_build.py --input-dir <素材目录> --query "支付 张伟"
# 多关键词 AND（须全部命中）
python scripts/kb_build.py --input-dir <素材目录> --query "支付 微信" --all
# 限定类别（决策/行动项/风险/结论）
python scripts/kb_build.py --input-dir <素材目录> --query 跟进 --cat 行动项
# 结构化 JSON 输出（便于程序化消费，含 owner/deadline）
python scripts/kb_build.py --input-dir <素材目录> --query 张伟 --json
# 仅看统计：每类数量 + 各会议贡献度
python scripts/kb_build.py --input-dir <素材目录> --stats
# 详细诊断（逐文件扫描结果，排查问题时使用）
python scripts/kb_build.py --input-dir <素材目录> --verbose
```

- 检索对全/半角、大小写、常见标点**容错**；命中词以 `*高亮*` 展示。
- 若命中条目来自 **2 个及以上不同会议**，自动提示「结论可能存在差异，请人工核对」——实现 SKILL.md 承诺的冲突并列展示。
- v3 新增：**输入校验**——二进制文件检测、空文件告警、编码异常自动兼容(GBK)、构建结束时输出扫描摘要，不再静默跳过任何问题文件。

## 五、示例

> 用户：之前关于支付方案，会议是怎么定的？
>
> 助手：检索知识库「决策/结论」类 → 跨 2 个会议命中 → 返回：
> - 【项目启动会】支付采用分阶段接入，先接微信/支付宝
> - 【周同步会】支付联调延后，待决是否砍范围
> - ⚠️ 涉及 2 个会议，结论存在差异，请人工核对

> 用户：这周哪些行动项要跟进？
>
> 助手：检索「行动项」类，返回带负责人与截止日：
> - 张伟跟进支付文档（负责人 张伟 · DDL 周三）
> - 李娜补充自动化用例（DDL 下周一）

## 六、注意事项与局限

- 知识库为**事实索引**，来源可追溯（每条注明会议与章节）；结论冲突时并列展示，由人判断。
- 本地模式用关键词检索，未做语义向量；如需语义检索可接嵌入模型（超出本 Skill 范围）。
- 涉及内部决策须遵守权限与合规要求。
