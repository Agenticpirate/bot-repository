# Market Research Protocol (桌面级行业调研协议)

> 本 Skill 将《桌面级行业调研 SOP v3.0》固化为可执行流程。执行前请先阅读配套文档 `SOP.md`（位于本 skill 目录）获取完整细节与表格。

## 何时使用

- 用户要求调研某市场 / 行业 / 竞品格局
- 用户要求分析某类产品的竞争态势、市场特点、未来趋势
- 需要产出"带可信度评分的分级结论报告"，而非随便搜几条就回答

## 核心流程（5阶段）

```
阶段0 问题定义 → 阶段1 来源分层采集 → 阶段2 交叉验证 → 阶段3 结论分级输出 → 阶段4 复盘迭代
```

### 阶段0：问题定义（调研目标书）

动手前先明确并告知用户：
- 调研目标（≤3个主问题）
- 主线对象（深度调研）与备选对象（浅调研/横向参照）
- 输出形态、调研预算（搜索轮次上限）
- **边界动态开放**：调研中发现更值得对比的产品，主动建议纳入，不固守初始名单

### 阶段1：来源分层采集

按 CR 系数给来源分级（完整表见 SOP.md 2.1）：

| 级别 | 类型 | CR |
|------|------|-----|
| S1 | 官方一手（官网/文档/定价/发布会） | 0.90 |
| S2 | 第三方研究（易观/IDC/艾瑞/Gartner） | 0.85 |
| S3 | 主流媒体（新浪/36氪/钛媒体/晚点） | 0.70 |
| S4 | 用户社区（知乎/B站/小红书/应用商店） | 0.50 |
| S5 | 自媒体/未验证渠道 | 0.30 |

- 按"对象 × 维度"关键词矩阵采集，每条证据记录：事实陈述 + URL + 来源级别 + CR + 时点
- S4 用户反馈按六维加权（恶意吐槽0.05 / 灌水0.05 / 主观0.40 / 客观体验0.60 / 实际问题0.85 / 改进建议0.95）

### 阶段2：交叉验证（三件套，缺一不可）

1. **支持性验证**：关键结论 ≥2 个独立来源
2. **反驳性验证**：必须搜反向关键词尝试推翻结论（"X翻车/X争议/X数据质疑"）
3. **独立性检查**：两个来源须无共同利益关联（不能都是厂商系媒体）

冲突处理与时效衰减规则见 SOP.md 3.2 / 3.3。

### 阶段3：结论分级输出

每条结论按格式输出：

```
【结论】〈一句话〉
【等级】✅事实 / 🔶推断 / ❓未知
【证据链】〈来源级别 + URL + 时点〉
【建议】〈行动建议〉
```

- 报告末尾输出**整体可信度评分**：
  `[ Σ(结论权重×CR) / Σ(权重) ] × 校准系数`（校准系数=抽查结论独立可验证率）
- 每条结论必须附行动建议（增加对比项 / 增加框架 / 减少维度 / 细化搜索 / 人工补充 / 人工分析）

### 阶段4：复盘迭代

- 输出缺口清单（无答案的问题、单源数据、付费墙、未解决反证）
- 判断是否第二轮调研或转人工

## 硬性纪律（违反即视为调研无效）

1. 禁止用 S4 层验证结论（只能发现假设）
2. 禁止将单源信息表述为事实
3. 必须标注每条数据时点
4. 必须执行反驳搜索（即使结论"显然正确"）
5. 必须公开评分方法与局限
6. 必须为每条结论附行动建议
7. 禁止固守初始边界，发现更佳对比项必须主动建议

## 输出约定

- 调研报告（Markdown）：结论分级标签 ✅ / 🔶 / ❓ 贯穿全文
- 结尾附：整体可信度评分 + 评分方法说明 + 缺口清单
- 可作为 `市场洞察内容生产`（链路B）或 `产品GTM内容生产`（链路A）的输入
- 报告正文中主动给出"建议增加对比项 / 更佳选择"提示，不限于初始对象

## 已知局限

付费报告墙、无一手实测、公开信息天花板（留存率/DAU/内部战略不可得）等，详见 SOP.md 第7节。遇到即标注 ❓未知，不硬编。
