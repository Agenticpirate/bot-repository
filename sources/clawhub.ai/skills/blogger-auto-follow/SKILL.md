# 博主批量关注

将用户提供的名单转成单个平台、固定范围的批次；先展示完整预览，再由用户
按每批最多 30 人在前台浏览器中连续执行；每一批均需单独确认。

## 何时可以执行

只有同时具备下列信息时，才能开始浏览器操作：

1. 唯一目标平台；
2. 固定候选名单；
3. 明确的最大关注数量；
4. 用户已经审阅名单，并确认执行本批次。

若用户只给出模糊需求（如“多关注一些同类博主”），只提取或生成候选清单，
不要进入浏览器执行阶段。

## 工作流

1. 从图片或文本提取候选，并去重、移除空名称。
2. 生成 JSON 名单并展示平台、数量、名称、分类和筛选依据。
3. 按每批最多 30 人自动拆分较长名单，并展示所有批次的完整预览。
4. 首次使用某平台时，让用户在该平台的专用可见浏览器资料目录中自行登录并确认账号正确；后续批次复用该专用资料目录。
5. 用户输入本批次的确认口令后，运行执行器。
6. 对名单中的每个账号记录成功、已关注、未找到或失败结果；只将成功或已关注
   的最小必要资料写入本地资产库。

使用示例：

```bash
python3 scripts/blogger_auto_follow.py \
  --platform bilibili \
  --file examples/bilibili_10_bloggers.json \
  --max-follows 30
```

先只预览和校验名单：

```bash
python3 scripts/blogger_auto_follow.py \
  --platform bilibili \
  --file examples/bilibili_10_bloggers.json \
  --dry-run
```

## 执行边界

- 每个平台仅使用前台的专用浏览器资料目录，供用户复用自己的登录状态；不连接、
  接管或读取日常浏览器会话，也不导出 Cookie、密码或浏览记录。
- 一次执行只针对已预览、已确认的单个平台固定名单；不自动追加候选、跨平台或
  扩大数量。
- 不使用后台运行、规避服务控制或处理额外验证的行为。
- 检测到登录问题、验证码、风险提示、限流或未知页面状态时，立即停止整批任务，
  输出已处理结果，不自动重试或继续。
- 仅点击与当前名单匹配的“关注/订阅”控件；不发送私信、评论、点赞、转发或处理
  其他外部操作。

## 数据与审计

执行结果写入 `data/batch_results/`，包含目标、平台、结果、原因和时间。候选名单
及结果只用于当前任务与用户明确要求的本地资产库管理；如不需要保留，可删除对应
结果文件和资产记录。平台专用浏览器资料目录位于 `data/browser_profiles/<platform>/`；
如需移除登录状态，可关闭浏览器后删除对应目录。

平台适配与选择器的维护说明见 [supported_platforms.md](references/supported_platforms.md)。
