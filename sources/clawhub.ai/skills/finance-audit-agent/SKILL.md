```
│  ─────────                       ────────────                   │
│  ? 核对条款一致性                ? 边界情况决策                  │
│  ? 校验病例完整性                ? 复杂案件定性                  │
│  ? 判断资料齐全性                ? 欺诈案件调查                  │

│                                                                 │
├─────────────────────────────────────────────────────────────────┤
│  ROI叙事：讲"释放产能"而非"节省人头"                            │

└─────────────────────────────────────────────────────────────────┘
```

**五步落地法（参考中国太保）：**
1. **选对场景**：从"规则明确的文档处理"开始（核赔核对、条款校验、资料完整性判断）
2. **人机分工**：AI做执行，人做判断，审计员从重复劳动中解放
3. **领域知识工程**：建立金融专业规则库（保险条款/监管法规/行业惯例）
4. **ROI叙事**：量化"释放产能"而非"节省人头"，统计AI处理量/人效提升/准确率
5. **分步推进**：先单点验证（某险种/某地区），验证ROI后扩展至全量

**人机协作分工的落地举例：**
- 举例1（核赔核对）：AI逐单比对诊断编码与条款疾病定义，输出"一致/存疑/不一致"三分类；人工只处理"存疑"档（通常占15%-20%），把核对工时从人均4小时/天压到0.8小时/天。
- 举例2（理赔时效）：AI按R006自动抓取受理时点与结案时点计算时效达标率；人工负责认定"复杂案件"起算日争议，避免机器把客户补充材料的等待期误算为机构延误。
- 举例3（边界定性）：AI给出"疑似重复理赔"信号后，人工结合伤情部位、就诊科室、票据号段判断是重复索赔还是拆分报销——这类定性不得由AI直接出结论。

### 1. 审计规则引擎（59条规则）

#### 1.1 保险行业审计规则（20个）

**承保业务审计**
- R001：投保人身份真实性核验 - 身份证OCR识别+人脸比对+公安库交叉验证
- R002：受益人关系合法性 - 受益人与被保险人关系符合保险法规定，18岁以下需指定监护人
- R003：健康告知完整性 - 既往病史/家族史/生活习惯告知完整性校验，漏告知触发人工复核
- R004：财务状况真实性 - 年收入与保费比例不超过合理范围（年收入×20%≥年缴保费）
- R005：职业风险等级匹配 - 被保险人职业类别与投保险种风险等级匹配，高风险职业需加费或拒保

**理赔业务审计**
- R006：理赔时效合规性 - 普通案件15个工作日内完成，复杂案件60个工作日内完成
- R007：理赔材料完整性 - 发票/病历/事故证明/身份证明四要素齐全性校验
- R008：理赔金额准确性 - 赔付金额=保额×赔付比例-免赔额-已赔付金额，与条款计算一致
- R009：重复理赔检测 - 同一事故/同一医院/同一时间段内是否存在多次理赔记录
- R010：既往病史关联分析 - 理赔疾病与健康告知历史是否存在关联，关联时需启动既往症调查

**核保风控审计**
- R011：超额保险检测 - 累计保额超过风险保额限制（未成年人身故险≤20万，航空险≤500万）
- R012：逆选择风险评估 - 短期内集中投保/观察期刚过即申请理赔等逆向选择信号检测
- R013：带病投保识别 - 体检异常/门诊记录与投保时间序列分析，检测带病投保行为

**销售合规审计**
- R014：销售误导检测 - 宣传材料与条款一致性，夸大收益/隐瞒免责条款检测
- R015：双录合规性 - 1年期以上寿险/重疾险双录（录音录像）完整性检查，回溯可追溯
- R016：代理人资质验证 - 销售人员持有有效执业证书，无违规从业记录
- R017：代签名检测 - 投保单/变更申请书签名笔迹与历史样本差异检测

**资金合规审计**
- R018：保费资金来源合规 - 大额保费（≥20万）资金来源证明，防范洗钱风险
- R019：理赔资金去向追踪 - 理赔款打款账户与投保人/受益人账户一致性验证
- R020：退保资金合规性 - 犹豫期退保全额退款，超过犹豫期按现金价值计算，退保资金退回原账户

**保险规则应用举例：**
- 举例1（R006+R007组合）：某医疗险案件受理日为3月1日，客户3月20日补充病理报告，机构4月10日结案。AI按"补充材料等待期可扣除"口径计算实际处理时长12个工作日（达标），但需人工确认补充材料通知是否在3月20日当日发出——若通知晚于3月20日，则时效重新起算可能超15个工作日。
- 举例2（R009）：客户1月5日因"腰椎间盘突出"在A医院就诊理赔8000元，1月12日在B医院以"腰椎间盘疾患"再次申请理赔6500元，两次票据号段连续且诊断编码同属M51类。AI标记高风险后，人工调阅完整病历判断是否为同一次事故拆分索赔。
- 举例3（R011+R004组合）：投保人为其8岁子女在3家机构累计投保身故险保额合计45万元，超出未成年人身故险限额；同时其申报年收入12万元、年缴保费6万元，保费收入比50%远超20%参考线——两条规则叠加，AI直接出具"建议拒保+上报可疑"的高风险结论。

#### 1.2 证券行业审计规则（18个）

**经纪业务审计**
- R021：客户适当性管理 - 投资者风险等级与产品风险等级匹配，C1-C3客户不得购买R5产品
- R022：开户资料完整性 - 身份证/银行卡/风险测评/投资者确认书齐全性校验
- R023：客户身份持续核验 - 大额转账（≥50万）/异常交易时二次身份验证
- R024：僵尸账户激活合规 - 长期不动户（1年以上）激活时重新完成适当性管理和风险揭示

**交易合规审计**
- R025：异常交易监测 - 集合竞价阶段虚假申报/对倒交易/涨停板虚假申报检测
- R026：老鼠仓检测 - 资管产品建仓前关联账户先于资管账户交易同只股票
- R027：限售股减持合规 - 高管/5%以上股东减持提前披露，窗口期禁止交易
- R028：内幕交易防控 - 信息披露前敏感期内关联账户交易行为监测

**投行业务审计**
- R029：IPO项目尽职调查完整性 - 财务真实性/法律合规性/业务完整性核查清单校验
- R030：承销定价合理性 - 发行价与询价结果偏离度超±30%需专项说明
- R031：持续督导合规 - 上市公司年报/季报/重大事项披露及时性跟踪

**资产管理业务审计**
- R032：产品净值核算准确性 - 单位净值计算=（资产总值-负债）/份额，与托管人核对
- R033：利益输送检测 - 产品间对倒/产品与股东账户间利益输送信号检测
- R034：信息披露合规 - 产品净值/季报/年报披露时间符合合同约定和监管要求

**融资融券业务审计**
- R035：融资融券准入合规 - 客户证券资产≥50万且开户满6个月资质验证
- R036：担保品折算率合规 - 担保证券折算率符合交易所规定，单只股票集中度≤30%
- R037：强制平仓合规性 - 维持担保比例低于130%时通知客户，低于110%时强制平仓

**反洗钱审计**
- R038：可疑交易识别 - 分散转入集中转出/短期大额资金进出/频繁小额试探交易检测
- R039：制裁名单筛查 - 交易对手/受益人/实际控制人实时对接OFAC/UN/中国制裁名单

**证券规则应用举例：**
- 举例1（R021）：风险测评结果为C2（稳健型）的客户通过线上渠道申购R4混合型基金，系统留存的"不适当销售确认书"为客户自行勾选。AI核对发现确认书未留存双录且无营业部盖章，判定适当性管理程序不完整，需补充投资者教育记录并回溯销售环节。
- 举例2（R036+R037组合）：客户担保证券中单只创业板股票占比38%，超过30%集中度上限；T日维持担保比例降至128%，机构T+1日才发出追加通知。AI同时标记集中度超限与通知时点滞后两项问题，人工据此认定平仓程序存在瑕疵。
- 举例3（R025）：某账户连续5个交易日在9:15-9:20集合竞价阶段申报买入后立即撤单，撤单率92%，且申报量占同期市场申报量15%以上。AI判定存在虚假申报嫌疑并生成异常交易线索，移交合规部门人工研判是否上报。

#### 1.3 银行行业审计规则（21个）

**信贷业务审计**
- R040：贷款准入合规性 - 借款人资质/担保物评估/授信额度测算符合信贷政策
- R041：贷前调查完整性 - 财务报告/经营场所/行业分析/还款来源调查四维度完整
- R042：贷款用途真实性 - 受托支付凭证与合同约定用途一致性，跟踪资金流向
- R043：贷后管理合规 - 季度现场检查/年度重评/风险分类调整及时性监测
- R044：五级分类准确性 - 正常/关注/次级/可疑/损失分类与贷款实际风险匹配

**存款业务审计**
- R045：存款利率合规 - 存款利率不超过自律机制约定上限
- R046：存款保险标识合规 - 营业场所显著位置展示存款保险标识
- R047：大额交易报告合规 - 单笔/累计日交易≥50万报告反洗钱系统

**结算业务审计**
- R048：银行间往来合规 - 同业存放/同业拆借利率符合Shibor±一定范围
- R049：票据业务真实性 - 票据真实性（电票验真/纸票查复线）+贸易背景真实性
- R050：贸易背景真实性 - 进出口单据/发票/物流单据与结算业务匹配性

**合规内控审计**
- R051：授权审批合规 - 重大业务（≥500万）双人复核，分级授权体系执行
- R052：岗位分离合规 - 账务处理/复核/授权三分离，不相容岗位分离
- R053：印章管理合规 - 印鉴卡保管/使用登记/定期盘点完整性

**反洗钱/制裁合规**
- R054：客户尽调（KYC）完整性 - 法人客户受益人识别，自然人客户职业/地址/资金来源登记
- R055：制裁名单实时筛查 - 新建客户/交易对手/受益人开户时实时对接制裁名单库
- R056：恐怖融资检测 - 可疑特征交易（宗教场所收捐款/小额多笔规律性转账）识别
- R057：跨境汇款合规 - 汇款人/收款人身份信息完整，国际收支申报及时准确

**数据安全合规**
- R058：个人信息保护合规 - 个人信息收集授权/存储加密/跨境传输审批完整性
- R059：数据分级分类 - 客户数据按敏感程度分级，访问权限与数据级别匹配

**监管数据治理与以数治审（2026新增）**
- R059A：报送口径一致性 - EAST/监管标准化报送数据口径与业务系统源数据一致，字段映射有据可查
- R059B：报送时效性 - 监管报送数据按规定的频度与时限提交，延迟报送需留痕说明原因
- R059C：数据质量闭环 - 监管反馈的差错数据须在规定时限内完成整改并回检，形成"发现—整改—核验"闭环

**银行规则应用举例：**
- 举例1（R042+R050组合）：企业以采购原材料名义申请流动资金贷款3000万元，受托支付至供应商账户后，资金在2日内分5笔转入某房地产关联方账户。AI追踪资金链路判定"贷款用途与约定不符"，人工据此提前收贷并下调风险分类。
- 举例2（R044）：某制造业客户连续3个月欠息、主要账户被冻结，但贷款仍分类为"关注"。AI比对逾期天数、欠息期数与担保物变现能力，建议下调至"次级"；人工复核担保物评估报告后确认调整。
- 举例3（R059A）：监管标准化报送中"贷款投向行业"字段取自信贷系统行业代码，而源系统近半年有1200笔贷款未维护行业代码，报送时以默认值填充。AI比对源系统与报送表后标记口径失真，需补录后再报。

### 2. 影像件智能解析能力

#### 2.1 支持的影像件类型

| 影像类型 | 行业 | 解析字段 | 典型解析难点 | 降级/兜底策略 |
|---------|------|---------|-------------|--------------|
| 身份证 | 全行业 | 姓名/身份证号/性别/民族/出生日期/住址/有效期 | 反光、复印偏色、边角遮挡导致有效期漏识 | 置信度<90%转人工复核，禁止自动通过 |
| 营业执照 | 银行/证券 | 统一社会信用代码/法定代表人/注册资本/成立日期/经营范围 | 三证合一后版式多样，经营范围换行多 | 关键字段二次校验，经营范围仅作参考 |
| 银行卡 | 全行业 | 卡号/银行名称/卡类型/开户行 | 卡号压印凹凸导致字符断裂 | 卡号Luhn校验，不通过转人工 |
| 发票 | 保险/证券 | 发票代码/发票号码/开票日期/购买方/销售方/金额/税号 | 热敏纸褪色、折痕压字 | 金额大小写交叉校验，必要时查验平台核验 |
| 病历资料 | 保险 | 医院名称/科室/诊断/入院日期/出院日期/费用明细 | 手写体诊断、医生签名潦草、表格跨页 | 手写段单独走高识别模型，结论标"需人工确认" |
| 财务报表 | 银行/证券 | 资产/负债/所有者权益/营业收入/净利润（表格结构化提取） | 合并报表与母公司报表混淆、单位（元/万元）不明 | 抽取后强制核对单位与勾稽关系 |
| 合同文本 | 全行业 | 合同编号/当事人/标的/期限/金额（条款关键字段提取） | 补充协议、手写修改条款 | 主协议与补充协议冲突时标红提示 |
| 不动产证 | 银行 | 证号/权利人/坐落/面积/权利性质 | 附记页抵押信息易漏扫 | 提示补扫附记页 |
| 行驶证/驾驶证 | 保险 | 车牌/车架号/品牌型号/注册日期/发证日期 | 副页检验记录遮挡主信息 | 主副页分别识别后合并 |

```
影像上传 → 图像预处理（去噪/倾斜校正/增强） → 版面分析 → 文字识别（OCR） → 字段抽取 → 结构化输出 → 质量校验 → 低置信度转人工
```
