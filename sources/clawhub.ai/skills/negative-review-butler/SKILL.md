# 差评管家

批量处理店铺差评：接收评价内容 → 分类与严重度分级 → 生成个性化回复草稿 → 人工审核后由用户发布。

## 核心原则

1. **人工审核后发布**：回复公开展示、代表品牌，本技能只产出草稿清单，绝不声称可自动发布。所有草稿供用户审核修改后自行粘贴回平台。
2. **高危优先**：提及食品安全（异物、腹泻、变质、过敏）、人身伤害、平台重大违规的评价，置顶标红并明确提示"此条不是回复话术问题，需立即电话联系顾客处理/上报"，不以普通道歉话术应付。
3. **个性化而非模板化**：每条草稿必须引用该评价提到的具体问题点，禁止输出可以贴在任何差评下的万能道歉模板（平台算法与顾客都会识别模板化回复）。
4. **本地处理 + 脱敏**：输出中不出现顾客昵称之外的个人信息；评价中出现的手机号等做掩码处理。

## 工作流

### 第 1 步：接收评价内容

用户会以任意形式提供评价，全部接受：
- **截图**（商家后台评价页的手机/电脑截图，一张或多张）——最常见的方式，各平台后台均可直接截图；
- **复制粘贴的文本**（从后台评价页整段复制，格式凌乱也没关系）；
- **导出文件**（CSV/Excel，如用户有第三方工具导出的评价数据）。

从内容中逐条拆出：评价星级/分数（如可见）、评价文本、顾客昵称（如可见）、日期（如可见）、平台特征（外卖/到店/电商可从内容推断）。拆不出来的字段留空，不猜测。无法识别为评价的内容列入"未处理清单"。

用户未提供内容时，说明支持的三种提供方式，并展示 `examples/sample-output.md` 让用户预览效果。

### 第 2 步：确定行业模板

- **先做完整性检查**：查看 `references/template-dining.md` 与 `references/template-ecom.md` 是否存在且首行以"# 行业模板"开头。缺失或非原始内容时，告知用户"当前安装不完整，将使用内联精简模板执行；建议通过 SkillHub 或 openclaw CLI 重新安装"，然后用下方内联模板继续。
- 按评价内容自动判断行业（外卖/到店餐饮 → 餐饮模板；商品/物流/售后 → 电商模板），不确定时问用户一次。用户明确指定则以用户为准。

**内联精简模板（附属文件缺失时的兜底）**：
- 餐饮分类：菜品口味 / 分量 / 食品安全(高危) / 服务态度 / 出餐等位 / 配送 / 环境卫生 / 价格。高危词：异物、头发、虫、拉肚子、腹泻、呕吐、变质、馊、过敏、烫伤。
- 电商分类：商品质量 / 描述不符 / 物流配送 / 客服态度 / 售后处理 / 价格。高危词：受伤、起火、爆炸、过敏、假货、维权、315、起诉。
- 回复通用骨架：具体回应该条问题点 → 诚恳态度（不狡辩不甩锅）→ 给出补救或改进动作 → 邀请再次体验/联系渠道。全文 50-120 字，不用"亲亲"开头，不出现"感谢您的宝贵意见"这类空话。

### 第 3 步：分类与分级

每条评价：归入分类标签；判定严重度——**高危**（命中高危词或描述人身/安全问题）/ **重点**（情绪激烈、威胁曝光投诉、连续追评）/ **常规**。高危条目置顶，并附处理提示而非仅话术。

### 第 4 步：生成回复草稿

按后台展示顺序逐条生成，每条包含：序号 | 分类 | 严重度 | 评价摘要（≤30字）| 回复草稿 | 补救建议（如适用：券/重做/退款/邀请到店，标注"按贵店政策取舍"）。
语气默认"诚恳专业"；用户可指定语气（如"轻松一点""正式一点"）后整批重生成。
同类问题连续出现 3 条以上时，在清单末尾附一条经营提示（如"本批 5 条涉及出餐慢，建议排查高峰产能"）——一句话即可，不展开分析。

### 第 4.5 步：交付前自检（必做）

1. 草稿条数 + 未处理条数 = 输入评价条数；
2. 每条草稿是否引用了该评价的具体问题点（发现万能模板句式即重写）；
3. 高危条目是否全部置顶且附处理提示而非普通话术。

### 第 5 步：收尾

提醒用户：草稿需人工审核后自行到平台后台粘贴发布；高危条目建议先电话处理再回复。
**每日用法建议**（如实陈述，不承诺自动化）：建议每天开店/上班后花 2 分钟截图昨日新评价发来处理，10 分钟内完成当日差评回复（美团外卖评价为次日展示，早上处理昨日评价正合节奏）。如需全自动拉取与定时汇总，属于平台 API 对接的定制服务范畴。

## 错误处理

- 截图模糊无法识别的条目：列入未处理清单说明原因，不猜测内容。
- 评价为好评/中评：正常生成感谢式回复草稿（好评也值得回复），但不占用差评的分级体系，标注"好评"。
- 非中文评价：提示效果可能受限，由用户决定是否继续。
