# 会议周报 / 复盘自动生成器

把散落在多场会议里的智能纪要、转写稿，自动聚合成一份**可直接发出的周报**或**可供团队对齐的复盘报告**。让「会后 30 分钟的手工整理」变成「一句话触发、分钟级产出」。

本 Skill 是官方「腾讯会议 Skill（tmeet）」的二次创作：它不重复造会议能力，而是站在 tmeet 的纪要与转写之上，解决「会议纪要有了，但没人看、没人汇总」的最后一公里问题。

## 何时使用

- 用户需要把**一周/一个 sprint**内的多场会议汇总成周报
- 用户需要对某项目做**阶段性复盘**（进展 / 风险 / 待决 / 下一步）
- 用户需要从多场会议里**抽取跨会议行动项**并去重归并
- 用户拿到 tmeet 导出的纪要/转写文本，想**重排成正式文档**

## 能力边界（依赖）

- 本 Skill 依赖 **腾讯会议 Skill（tmeet）** 提供的会议查询、智能纪要、转写、会议报告能力。
- 若环境未接入 tmeet（未授权 / 无 CLI），Skill 仍可处理**用户本地已有的纪要素材**（.md/.txt），此时走「本地素材模式」。
- 不替代人工判断：生成物标注「待确认」项，绝不编造数据来源。

## 标准工作流

1. **收集原料**
   - 优先：调用 tmeet 查询目标时间窗内的会议列表，逐场拉取「智能纪要」与「转写」文本。
   - 兜底：读取用户提供的本地纪要素材目录（`scripts/meeting_digest.py --input-dir <dir>`）。
2. **逐场提炼**：对每场会议抽取——主题、关键结论、决策、行动项（负责人/截止/DDL）、开放问题、风险。
3. **跨会议聚合**：合并同名行动项、识别重复议题、标注跨会议依赖与冲突。
4. **套用模板**：按用户选择的形态（周报 / 复盘 / 行动项清单）渲染。
5. **产出与回写**：输出 Markdown；若用户授权，可调用 tmeet 能力把报告回填到会议备注或推送给参会人。

## 与 tmeet 的对接方式（二创点）

- 会议清单 / 纪要 / 转写：由 tmeet 的会议管理、录制管理、会议报告能力提供。
- 参会人画像（可选）：结合 tmeet 通讯录搜索，在周报里标注各行动项的责任人所属团队。
- 本 Skill 只做「聚合 + 结构化 + 成文」，保持对 tmeet 的单向依赖，便于评审识别二创关系，也降低维护成本。

## 输出模板（周报）

```markdown
# 周报 · {起止日期}

## 一、本周概览
- 共召开会议 {N} 场，覆盖主题：{…}
- 关键进展：{3 条}

## 二、各会议要点
### {会议1 主题}（{日期}）
- 结论：…
- 决策：…
- 行动项：{负责人 | DDL | 验收}

## 三、跨会议行动项（去重后 {M} 条）
| 行动项 | 负责人 | DDL | 来源会议 |
|--------|--------|-----|----------|

## 四、风险与待决
- {风险 / 阻塞 / 需升级事项}（标注：待确认 / 待 {某人} 拍板）

## 五、下周重点
- {从行动项与开放问题中推导}
```

复盘报告与行动项清单模板见 `references/` 目录。

## 示例

> 用户：把本周的三场项目会汇总成周报，重点看行动项和风险。
>
> 助手：（调用 tmeet 拉取 3 场会议纪要）→ 提炼 → 聚合 → 输出上述周报，行动项表按负责人分组，风险项标红「待确认」。

> 用户：我本地有 5 个纪要 txt，帮我做复盘。
>
> 助手：`python scripts/meeting_digest.py --input-dir ./notes --mode retrospective --output 复盘.md` → 产出复盘报告。

## 注意事项

- 来源缺失的结论一律标「证据不足」，不臆造。
- 涉及人名/结论前先与用户确认，避免误发。
- 时间窗默认「本周一—本周日」，可用自然语言覆盖（如「上月最后两周」）。
