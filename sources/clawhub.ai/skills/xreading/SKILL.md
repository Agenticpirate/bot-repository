# XReading /book

把一本书加工成用户以后认得出、用得上的知识。目标不是写书评，也不是展示审计过程。

## 开始前

1. 从 `$ARGUMENTS` 取得书名或文件路径；若参数为空且上下文也没有书，才询问用户。
2. 阅读本文件后，按需读取：
   - 写卡片前：`references/card-template.md`
   - 选择用户场景、去重或涉及投资时：`references/project-context.md`
   - 判断可信度、配比和反模式时：`references/quality-rules.md`
   - 工作区还没有书单或使用日志时：`references/workspace-files.md`
3. 所有正式产出使用中文。

## 不可破坏的原则

- **先讲清内容，再谈质疑。** 目标配比约为内容 60%、用法 30%、红旗 10%。
- **论证链不可省。** 掌握一本书，意味着能复述它如何从前提走到结论。
- **规则必须有入口和出口。** 每条规则写清：什么时候用、做什么、什么情况不适用或算用错。
- **不把读书变成催执行。** 可选验证不设期限；规则暂时没用上通常只是情境尚未出现。
- **不强行量化定性框架。** 一个自造代理失败，不能自动推翻原框架。
- **阅读验证与真实投资分离。** 单条读书观点不能独立触发开仓、平仓或调仓。
- **判断过程可以重，卡片表达必须轻。** 统计术语、长篇举证和研究细节放进查证文件，不挤占卡片。

## 执行流程

### 1. 确认内容来源

| 输入 | 处理 |
|---|---|
| 本地 PDF/EPUB/文本路径 | 直接读文件，以原文为主 |
| 只有书名 | 先核对作者、版本、目录或可靠简介，再建立内容框架；不要只凭模糊记忆 |
| 用户说有文件但没给路径 | 先在当前目录、`~/Downloads`、`~/Books` 查找，找不到再问 |

只有书名时，在卡片标注：

```text
内容来源: 模型已有知识 + 联网核对
```

并在末尾简短列出可能遗漏或记错之处。

### 2. 先做 Gate 0，不要先展开研究

用目录、序言、后记、章节首尾或可靠简介回答三行：

1. 这本书在回答什么问题？
2. 作者的核心主张是什么？
3. 最意外、最不服或最可能带来增量的一点是什么？

随后自动选择：

| 出口 | 判据 | 产出 |
|---|---|---|
| **快读** | 内容单薄、与已读高度重复、核心论据明显低质 | 不建书籍目录；在 `书单.md` 留一行，并向用户给出一页内速览 |
| **挂起** | 可能有价值，但缺少前置知识或可靠内容来源 | 不建书籍目录；在 `书单.md` 记录所缺前置条件 |
| **提炼** | 有明确增量价值 | 继续以下流程并写完整卡片 |

用户明确要求完整处理时，可以覆盖自动降档；但仍要说明原本建议的档位。

### 3. 提取内容与论证链

只精读反直觉点所在章节：

1. 快速浏览全书结构；
2. 标出反直觉、可能改变判断或让人不服的点，不设下限、上限 12 个；
3. 精读这些点所在章节；
4. 将内容分成：
   - 可检验观点；
   - 可操作规则；
   - 心法。

对核心主张写出 3–6 步论证链，并明确：

- 哪一步一旦失败，整条链就塌；
- 为什么它最脆弱；
- 现实中可以观察什么来检验它。

### 4. 做快速体检

只核查核心观点是否被公开质疑、推翻、撤回、更正，或被作者本人否认。通常搜索 2–4 轮即可。

| 发现 | 处理 |
|---|---|
| 未发现核心观点被推翻 | 一句话结束，不硬找问题 |
| 有争议但仍在讨论 | 可信度降到 ★★★，一句话说明分歧 |
| 大规模复制失败、原始研究算错、作者承认错误 | 降到 ★，进入“别用这些”，给出替代做法 |

只有出现“影响真实资源配置 + 证据弱”时才**建议深研**。用户明确要求深研视为已同意；否则先交付提炼档，再询问是否追加原始研究、反例和边界条件核查。

### 5. 写完整卡片

读取 `references/card-template.md`，写入：

```text
{书名}/卡片.md
```

要求：

- 核心观点 3–7 条；
- 可操作规则 3–6 条；
- 每条规则包含可识别的触发信号、1–3 步动作和退出条件；
- “别用这些”只列已被推翻或方向相反的观点；
- 若没有红旗，只写“未发现核心观点被推翻”；
- “我不同意”和“作者盲区”不硬凑；
- 卡片以 2–4 屏为目标；偏长时先删举证和重复解释，不删论证链。

若需要保存详细证据，另写：

```text
{书名}/查证-{主题}.md
```

### 6. 设计一个可选入口

只有存在能在两小时内、用现成材料完成的小验证时才写。它必须：

- 绑定这本书最独特的规律；
- 绑定用户真实关心的对象；
- 有明确产出；
- 标注“可选”；
- 不设置执行期限。

先检查 `使用日志.md` 和已有实验，避免把同一个动作伪装成多本书的新成果。确实应该复用时，明确写“复用哪一本书的哪条规则”。

### 7. 运行质量检查

卡片完整写完后，定位本 Skill 目录并运行随附脚本：

```bash
python3 <Skill目录>/scripts/check_ratio.py "{书名}/卡片.md"
```

若失败：

- 内容不足：补论证链，不盲目增加观点；
- 用法不足：补具体触发条件、动作或退出判据；
- 质疑超标：把举证过程移到查证文件；
- “其他”比例异常：检查标题是否与模板一致。

同时人工确认脚本报告的总字数与文件实际规模大致一致，避免静默解析错误。

### 8. 回写项目索引

1. 如果工作区尚无 `书单.md` 或 `使用日志.md`，按 `references/workspace-files.md` 初始化最小版本。
2. 更新 `书单.md`：书名、日期、档位和一句话结论。
3. 对提炼档产生的新规则：
   - 先去重；
   - 只追加到 `使用日志.md` 的候选/待用区域；
   - 不经用户筛选，不得自动提升为“在用规则”。
4. 若卡片包含真实持仓或其他敏感信息，在推送前明确提醒用户。

### 9. 向用户交付

简洁报告：

- 选择了哪个档位，为什么；
- 创建或更新了哪些文件；
- 最值得记住的一句话；
- 是否发现重大红旗；
- 若建议深研，说明追加研究的具体范围。

不要把内部搜索过程、统计细节或长篇自检日志复制到聊天里。
