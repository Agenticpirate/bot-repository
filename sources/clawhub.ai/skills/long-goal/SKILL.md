# 长期目标管理

让 `goal.md` 成为长期目标的唯一持久状态，避免依赖聊天记忆、上下文摘要或其他阶段性材料。

## 建立唯一事实源

1. 读取全部适用的 `AGENTS.md` 和用户约束。
2. 按以下顺序确定唯一权威目标文件：用户明确指定的 `goal.md`；当前对话 Goal 文本中显式登记的路径；用户所给交接材料明确指出的 `goal.md`；工作区内与该目标唯一匹配的现有 `goal.md`。
3. 发现多份可能的权威目标时，先根据交接、当前任务标识和最新内容判断；仍无法唯一确定时停止状态写入并请用户选定。不得并行维护多份目标。
4. 没有目标文件时，遵循当前工作区的产物目录规范，从 `assets/goal-template.md` 创建；落点会改变项目结构或无法安全判断时先询问。
5. 将 Goal mode 视为当前会话的执行目标，将 `goal.md` 视为跨会话、跨工具的持久事实。只有用户显式要求创建或启动 Goal 时才调用产品 Goal 能力；创建时在目标文本中登记权威 `goal.md` 路径。

## 每轮先恢复

1. 在任何实际任务动作前完整读取权威 `goal.md`，以其中的总目标、当前检查点和未闭环项恢复，不以聊天摘要代替。
2. 若用户从交接材料开始，先读取交接材料和 `goal.md`，把交接材料仅视为一次性输入；结合当前可读事实校准后，立即把有效变化写入 `goal.md`。不要在两份文档间建立路径、版本或状态绑定。
3. 对易变化的信息做必要的只读回查，例如文件、分支、服务、外部记录、数据或负责人状态；先把校准结果和新的当前检查点写回 `goal.md`，再继续执行。
4. 上下文被压缩、任务被恢复或执行人发生变化时，重复本节，不从记忆猜测停止位置。

## 处理每轮迭代

1. 收到用户新增要求后，先将它归入已有子目标，或新增一个具有独立完成判据的子目标；同步当前检查点，再做可能消耗较多上下文的工作。
2. 用户改变范围、行为或优先级时，先更新子目标及完成判据；形成稳定取舍后同步“重大决策”。不要因为本轮改动小而把它从长期目标拆出。
3. 执行实际工作，并按领域选择真实证据：
   - 软件与数据：测试、构建、接口、页面、数据库或部署读回。
   - 研究与分析：来源、反证、数据集、推导边界和未收敛项。
   - 文档与设计：内容审阅、渲染结果、格式检查和用户确认。
   - 运营与协作：外部状态、发送/提交回读、负责人和时间边界。
4. 详细证据放入工作区既有的验收、记录或附件产物；`goal.md` 只保留结论、证据索引和剩余差距。
5. 只有可观察证据满足完成判据时才把子目标标记为完成。单轮结束、提交成功或工具成功回执都不等于长期目标完成。
6. 每完成一个可验证里程碑，立即更新对应子目标、证据索引和当前检查点；不要等到长上下文结束才集中补写。
7. 每轮结束前再次更新 `goal.md` 的进展、决策、重要信息、下一步和未闭环项，并运行 `scripts/validate_long_goal.py --goal <goal.md 路径>`。

## 维护时机

以下时机都必须维护同一份 `goal.md`：

1. 新长期目标建立时：写清总目标、完成条件、约束和首个当前检查点。
2. 新要求进入时：先更新子目标和当前检查点，再执行。
3. 重大决策形成时：当场记录取舍、原因和影响。
4. 可验证里程碑完成时：当场记录状态和证据。
5. 即将切换任务、会话、执行人或暂停时：写清唯一下一步与未闭环项。
6. 每轮向用户交付前：校验并只读回查 `goal.md` 已真实落盘。

## 结束长期目标

区分“本轮完成”“子目标完成”和“长期目标完成”。仅当完成条件全部有证据满足，并且用户要求的显式结束条件已经成立时，才结束长期目标。否则保留为活动、等待验证、等待输入或暂停状态。

最终回报至少包含：权威 `goal.md` 路径、当前子目标、状态、关键证据和剩余边界。不得以生成了交接文档、完成了一轮工作或工具返回成功替代长期目标完成。
