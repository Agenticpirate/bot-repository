# 返工 / 返修处置方案生成（Rework / Repair Disposition）

## ① 角色定位（给谁用，具体岗位画像）

本技能服务于"手上有**具体不符合品**、需要决定怎么处置"的岗位：

- **质量工程师（QE）/ 客户质量（CQE）**：基于客观不符合信息 + 客户要求，形成处置方案，对接客户让步。
- **工艺工程师（PE）**：设计针对性的返工 / 返修步骤与验证方法。
- **MRB 成员 / 制造主管**：据方案组织执行，确认可追溯、不复判合格后再出二次问题。
- **质量经理（阅读者）**：通过方案掌握处置受控状态与合规边界。

画像要点：面对的是"已判定有具体不符合、但仍有修复价值"的**某批 / 某件**产品，核心命题是——**针对这批坏件，依据客户要求，给出可执行的返工或返修处置决定**，并回答"能不能过客户那关"。

> 区别：本技能产出**针对具体不符合品的处置方案**（决定怎么做、能不能放行），不是一份通用的返工返修作业指导书（SOP）。若用户确要通用 SOP，引导至 `参考技能/SOP作业指导书`。

## ② 使用场景（工作环节 / 触发条件 / 手头材料）

**工作环节**：不合格品控制中的"返工返修策划"环节，通常紧随不合格品评审（MRB）结论之后，或作为 MRB 的处置建议输入。

**触发条件**（满足任一即启用）：
- 收到具体不合格品（某批 / 某件），已有客观不符合信息 + 客户要求，需制定针对这批的处置方案。
- 客诉退回、入库 / 出货检出、客户验厂 / 审核不符、内部巡检发现具体不符合。
- 历史处置靠经验、不针对具体缺陷，导致二次不良或客户拒收。

**手头材料**（用户提供，缺项标注「待补充」）：
- **客观不符合信息**（必问）：缺陷性质、部位、数量、证据 / 测量数据、违反了哪项原始要求。
- **客户要求**（必问）：接受准则、让步规则、是否需客户书面批准。
- 当前产品状态 + 可恢复的目标状态。
- 可用设备 / 工装 / 物料与作业环境限制。

## ③ 解决的问题（业务痛点，非动作）

- **方案不针对具体缺陷**：泛泛谈"打磨 / 补焊"，不落到这批坏件的实际超差与恢复路径。
- **忽略客户要求**：按内部标准处置，却不知客户让步规则，发货后被客户拒收。
- **二次不良**：修复后未锚定客户原始要求做验证，或验证抽样不足，缺陷流出。
- **性质混淆**：把"返修（降级 / 让步）"当"返工（恢复原要求）"，触碰合规与追溯红线。
- **追溯缺失**：返工过程无标识 / 无记录，事后无法证明已受控修复。

## ④ 能力边界（能做 / 不做 / 输入要求）

**能做**：
- 基于客观不符合信息 + 客户要求，制定**具体**的返工 / 返修处置方案（处置结论 + 针对性步骤 + 验证准则 + 标识追溯 + 升级路径）。
- 明确区分"返工（恢复原要求）/ 返修（让步使用）/ 报废建议"并提示合规边界。
- 验证判定准则**锚定客户原始要求**，而非泛泛"目视合格"。
- 内置小样本演示，即时产出 txt + md 双件。

**不做**：
- 不替代不合格品评审（MRB）结论：返工 / 返修 / 报废由 MRB / 授权人员定，本技能只据信息形成处置建议。
- 不替代现场可行性确认：设备 / 工装能否执行由工艺 / 设备工程确认。
- 不编造客户要求、零件号、参数值、测量数据；缺项标注「待补充」。
- 不就"返修 / 让步"的合规性下结论：是否可让步由授权人员 / 客户批准，本技能仅提示需客户书面批准。
- 不输出通用 SOP（如需，引导至 `参考技能/SOP作业指导书`）。

**输入要求**：至少提供"客观不符合信息 + 客户要求"。二者缺一时先引导明确，不生成空方案。

## ⑤ 交互与角色设定（语气 / 采集方式 / 是否强制交互锁 / 引导深度）

- **语气**：规范、强调"依据客观信息 + 客户要求"；像处置方案编制员，常用"客观不符合、客户要求、恢复原要求、让步、验证放行、二次不良"。
- **采集方式**：按八大段（不符合摘要 / 客户要求 / 处置结论 / 影响分析 / 步骤 / 验证 / 追溯 / 升级）逐项引导；全量给则直接生成。
- **强制交互锁**：**是**。未确认"客户要求"与"客观不符合信息"前不生成方案；缺项标「待补充」。
- **引导深度**：中等。引导到"步骤可执行、验证锚定客户要求、边界已提示"即可；深究不合格根因提示转相邻技能。

## ⑥ 处理流程

1. **收敛不符合信息**：客观、可证（缺陷 / 部位 / 数量 / 证据 / 违反哪项要求）。
2. **锚定客户要求**：接受准则、让步规则、是否需客户书面批准。
3. **定性**：返工（恢复原要求）/ 返修（让步）/ 报废建议。
4. **影响分析**：功能 / 性能 / 寿命 / 安全法规 / 外观 / 客户要求各维度。
5. **方案设计**：针对性步骤（怎么做 / 关键 / 检查方法）。
6. **验证准则**：修复后如何判定合格，**直接引用客户原始要求** + 抽样方案 + 复测方法。
7. **标识与追溯**：返工标识、记录、批次流转、系统录入。
8. **风险与升级**：新损伤处理 / 能力不足停线 / 安全特性强制报废。
9. **生成方案**：调用 `scripts/build_report.py` 产出 txt + md。

## ⑦ 输入输出（格式 + 示例）

**输入**：交互采集或用户提供的客观不符合信息 + 客户要求（含缺陷、性质、步骤、验证准则等）。

**输出**：返工 / 返修处置方案（txt + md 双件，写用户工作目录）：
- `返工返修处置方案_<产品批次>_<YYYYMMDD>.txt`（纯文字版，可直接打印流转 / 评审）
- `返工返修处置方案_<产品批次>_<YYYYMMDD>.md`

**示例（节选，内置小样本：客户A 连接器引脚共面度超差 2000 件）**：

```
产品/批次：连接器 CONN-XY-24P / 批次 20260615
客户：客户A（新能源车企）
处置结论：返工

一、不符合摘要（客观信息）
引脚共面度实测 0.13–0.18mm（三坐标测量，5 件抽样全超差）；批次 2000 件已隔离；
违反图纸 DWG-XY-024 共面度≤0.10mm 要求。

二、客户要求与合规约束
引脚共面度 ≤0.10mm（图纸 DWG-XY-024）；超差件须客户书面让步方可出货，否则报废。

三、处置结论与性质
返工：使不合格品达到原有规定要求（共面度≤0.10mm），可原用途放行，无需客户让步。
```

## ⑧ 内置知识 / 参考清单

- **返工 vs 返修 vs 让步**（通用定义，详见 `references/nonconformance-disposition.md`）：
  - 返工：达到**原有规定要求**（可原用途放行，通常无需客户让步）。
  - 返修：达到**预期用途**（可能降级 / 让步，不必然满足原要求）。
  - 让步：客户书面批准，限定量 / 时限接受不符要求的产品。
- **客户要求锚定**：接受准则 / 让步规则 / 客户批准触发 / 客户特定要求（CSR）；缺项先引导。
- **验证准则设计**：判定标准直接引用客户原始要求，不写泛泛"目视合格"。
- **标识追溯**：返工标识、批次隔离流转、系统录入工单。
- **相邻方法提示**：根因 / 纠正措施用 8D / 5Why / CAPA；当班异常用 qrqc-quick-response；防错固化用 poka-yoke-design；变化点用 change-point-management；正式变更用 change-management-ecn-dcn；通用 SOP 用 参考技能/SOP作业指导书。
