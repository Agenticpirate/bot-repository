# 角色生成器

## 定位

本技能是**元技能系统（meta-skill-system）的下级母技能**，专门负责从任意角色概念出发，系统化填充12个正交维度，生成完整的角色Skill文件。

**与元技能系统（meta-skill-system）的关系**：本技能消费元技能系统的三轴执行框架（6大元操作、R1-R5校准、管线编排），将12维角色分类体系转化为可执行的角色生成管线。两者的分工边界：**元技能系统做事，角色生成器造人**。元技能系统去除的是"因为人的局限而产生的补偿性工作流角色"（传递员、协调员、审批签字人），角色生成器创建的是"有独立存在价值的人格"——去角色化消除的是工作流冗余，角色生成保留的是人格完整，互不冲突。

**为什么需要12维完整角色**：做事不需要完整角色——一个能写代码的AI不需要知道自己的星座。本技能的价值在于生成**有持续一致视角的独立存在体**——因为文化背景、躯体经验、家庭身份这些"对做事无用"的维度，恰恰是产生不可替代的独特视角的来源。本技能也是元技能系统M3领域负载物生成能力的一个边界验证：M3流程不仅可以生成"做事用的技能"，也可以生成"有人格的创造物"。

**技能的两类消费方式**：生成的12维角色Skill有两种使用路径——①**嵌入型**，作为人格化层附加到做事用技能上，为任务执行注入真人感和一致视角（M3-03可选12维角色模型的核心场景）；②**独立型**，角色Skill自身即完整产品，用于角色扮演对话、角色间模拟互动、为小说/游戏创作提供人物灵感。用途轴的五种分类（叙事/游戏/交互/教学/品牌）决定角色维度的填充深度，消费方式决定角色Skill的目标形态。

**核心理念**：角色 = 实体层坐标 × 社会层坐标 × 抽象层坐标。一个完整的角色不是"一个标签"，而是12个正交维度上各取一个值的乘积。本技能确保每个维度都被系统性填充，不遗漏、不敷衍。

### 领域自身 R1-R5 定位

本技能作为领域负载物（而非其生成的角色）的自身行为校准参数：

| 维度 | 评分 | 说明 | 管线影响 |
|------|------|------|---------|
| R1 信息密度 | 高 | 角色生成依赖大量可验证的事实信息（职业体系/文化数据/名人事实/历史知识），S 感知和 C 认知的权重较高 | S 和 C 单元的管线上占比高，网络搜索使用频繁 |
| R2 创造性 | 高 | 角色创作本身就是创造性活动——虚构角色需要原创设定，写实角色需要从事实中提取有张力的组合 | A 行动权重高，C 偏发散，G 偏宽松 |
| R3 交互性 | 中高 | 角色生成需要在关键维度（职业/身份/动机/关系）上主动询问用户，但大量维度可以自动推导 | I 交互权重中等，关键决策点需交互确认 |
| R4 规范性 | 高 | 12 维框架是严格的结构化体系——每个维度有明确的填充槽位、校验规则和约束条件 | G 守护权重高，自治度偏低，每域末尾 G 类校验必执行 |
| R5 迭代性 | 中 | 角色通常需要 1-3 轮细化——首轮粗填→用户反馈→细调，但不需要多轮反复迭代 | ↻ 循环频率中等，C0→C7 为一次完整迭代 |

## 核心能力

### 能力协同（C0）

**职责分工**：
- **角色需求解析**：双轴判定（类型×用途）、角色类型判定、角色用途判定、维度填充策略规划
- **12维系统填充**：实体层→社会层→抽象层的三层递进填充
- **角色Skill组装与输出**：三层结构组装、格式验证、技能交付

**价值链**：
```
用户输入 ──[需求解析]──→ 填充策略
                              │
                              ▼
                  [实体层填充]（C1/C2/C3 并行）
                              │
                              ▼
                       实体层角色粗胚
                              │
                              ▼
                  [社会层填充]（C4）
                              │
                              ▼
                       社会坐标中的角色
                              │
                              ▼
                  [抽象层填充]（C5/C6 并行）
                              │
                              ▼
                       12维完整角色
                              │
                              ▼
                  [整合校验输出]（C7）
```

**三层价值属性**：
- **实体层**：存在价值——解决"角色是什么"的根本问题（职业、身份、躯体、文化）
- **社会层**：关系价值——解决"角色在哪儿"的定位问题（关系网络、层级位置）
- **抽象层**：行为价值——解决"角色怎么动"的运行问题（功能映射、能力评估、动机分析、动态变化）

**生产力价值**：将模糊的角色概念转化为系统化可复用的角色Skill——不是画了一个角色，是生成了一个可被元技能系统执行框架直接消费的人格化能力单元，让角色创作从艺术变为工程。

### 角色需求解析能力（C0）

从用户输入中提取角色概念的初始线索：

- **双轴判定**：同时判定角色类型（写实/虚构/功能/拟人 四选一）和角色用途（叙事/游戏/交互/教学/品牌 五选一），4×5=20种组合决定后续管线的校准方向和维度深度
- **解析五步法**：接收输入 → 提取角色名称 → 判定类型 → 判定用途 → 基于用途枚举维度优先级 → 列出已知/缺失维度
- **角色类型**：写实 / 虚构 / 功能 / 拟人
- **角色用途**：叙事 / 游戏 / 交互 / 教学 / 品牌
- **填充策略**：直接提取 / 推理推导 / 主动询问 / 默认值
- **信息源层级**：第1层个人输入（权威源）→ 第2层网络搜索（验证源）→ 第3层LLM推理（推导源）→ 第4层默认值（兜底源）

**核心理念**：角色生成的第一步不是填充维度，而是理解用户意图——输入的质量决定整个管线的质量。信息源可靠性递降规则：上一层可用时不可跳过，第1层不可坠降（无替代源）。

**适用范围**：任何可被识别为"角色概念"的用户输入——一句话描述、场景需求、功能需求、自由创作、模仿原型。

**生产力价值**：将用户一句话的角色概念扩展为结构化的12维填充计划，消除从模糊需求到系统执行的认知落差。

### 12维系统填充能力（C1-C6）

按三层递进结构逐层填充每个维度，确保维度间的一致性和互斥性：

- **实体层（C1/C2/C3 并行）**：职业与身份域、名人与拟人域、躯体与文化域——三层并行填充，互不阻塞
- **社会层（C4）**：关系与层级域——依赖实体层完成后方可执行，将角色嵌入社会关系网络
- **抽象层（C5/C6 并行）**：功能与能力域、动机与动态域——依赖社会层完成，两大域可并行执行

**核心理念**：职业锚定是整个角色12维的起点——职业决定功能→能力→身份→动机的推导链。12个维度不是12个独立的填空题，而是互相约束的方程组——先填的维度收束后填维度的解空间。

**关键规则**：
- 实体层三域可并行填充（C1/C2/C3 互不依赖），每个域末尾 G 类校验
- 社会层依赖实体层全部完成，C4 是实体层到抽象层的桥梁
- 抽象层 C5 和 C6 可并行填充，各自末尾 G 类校验
- 每维至少填充默认值，不可跳过——空缺维度必须标注"未定义"并说明原因

**生产力价值**：12维框架消除角色创作中的遗漏和偏见——不会因为创作者对某个维度的熟悉而过度填充、对不熟悉的维度跳过。生成的每个角色都是完整的。

### 角色Skill组装与输出能力（C7）

将填充完成的12维角色数据组装为可执行的角色Skill：

- **交叉验证**：C7-01 汇聚全部6个域的校验结果，执行12维全局一致性扫描
- **三层结构组装**：SKILL.md（角色概述+12维数据摘要+Step 0-4执行框架）+ character-data.md（完整12维数据）+ character-requirements.md（行为约束）
- **格式验证与交付**：验证 frontmatter 格式、标题层级、UTF-8编码，输出至标准技能目录

**核心理念**：单个维度的正确不等于整个角色的正确——C7是12维数据的最后一道质量门。角色Skill不是数据的容器，而是可被元技能系统执行框架直接消费的人格化负载物。

**生产力价值**：一键输出完整的角色Skill文件——生成的不仅是角色数据，而是一个具备三轴判定、管线编排、领域校准、降级模式的完整人格化执行单元，可直接加载参与任何元技能任务。

## 角色生成器特有维度

角色生成器具有以下特有维度：

| 维度 | 说明 | 影响 |
|------|------|------|
| **12维正交性** | 12个维度互相正交，任意组合形成完整角色空间 | 需要确保每个维度被独立填充，不遗漏不敷衍 |
| **三层递进** | 实体层→社会层→抽象层的严格递进依赖 | 管线的并行/串行决策由层间依赖决定 |
| **双轴校准** | 角色类型（4种）×角色用途（5种）=20种组合决定R1-R5参数和维度深度 | Step 1 领域校准的类型参数集和用途权重矩阵正交不冲突 |
| **跨维一致性** | 12维之间有大量强约束（职业→能力、文化→躯体、动机→行为） | 每域末尾 G 类校验不可跳过，C7 全局交叉校验为硬约束 |

## 角色12维模型

```
第一层：实体层——不可再分的具体存在
  维1 职业维：以什么为生（行业×任务谱系）
  维2 身份维：在世界坐标系的位置（组织/家庭/社会/知识 四重叠加）
  维3 名人维：最接近的真实人物原型
  维4 拟人维：是不是人（人类/动物/物品/自然力/抽象概念/AI）
  维5 躯体维：身体是什么（年龄/性别/体型/健康/外貌/形态）
  维6 文化维：从什么文化中出来（国籍/民族/语言/宗教/阶级/时代/亚文化）

第二层：社会关系层——角色怎么嵌入关系网络
  维7 关系维：和谁连着（类型×强度×方向）
  维8 层级维：处在什么高度（元层/宏观/中观/微观/边界/辅助）

第三层：抽象属性层——超越具体存在的普遍刻画
  维9 功能维：做什么（S感知/C认知/A行动/O组织/I交互/G守护 的组合）
  维10 能力维：有什么本事（知识/技能/资源/信息/权力/自由度）
  维11 动机维：为什么做（利益/价值/生存/权力/关系/认知/合规/惯性）
  维12 动态维：什么情境/怎么变/真假（场景切换×生命周期×虚实属性）
```

## 使用规则

### 执行流程
1. **首次加载**：读取 `references/character-catalog.md`，获取域分类、依赖拓扑、元操作映射提示
2. **按需深入**：确认目标角色生成任务后，读取 `references/character-requirements.md` 获取各维度的填充槽位和约束；如需样本法参考，读取 `references/character-exemplars.md` 获取范本
3. **独立执行**：本技能仅依赖元技能系统的执行框架，不依赖其他领域技能

### 内容权限
4. **修改权限**：本技能已充分优化完善，使用过程中拒绝任何对技能内容的丝毫修改
5. **用户填充**：用户可向本技能添加角色生成范本，用于样本法参考；除非修改权限用户明确要求失效时方可填充

### 扩展能力
6. **提示词导出**：可将本技能的 SKILL.md 与 references 目录下所有文件内容合并为单一提示词文件，用于不支持 skill 目录格式的工具。合并顺序：
   ```
   cat SKILL.md \
       references/character-catalog.md \
       references/character-requirements.md \
       references/character-exemplars.md \
       references/exemplars/*.md \
       > character-builder-prompt.md
   ```
7. **完整合并版**：`references/character-builder-prompt.md` 为完整合并版提示词文件，包含SKILL.md与所有references文件内容

### 目录用途

| 目录 | 用途 | 加载策略 |
|------|------|---------|
| `references/` | 参考文档（catalog/requirements/exemplars），包含任务清单、组件要求、范本索引 | 加载到上下文 |
| `scripts/` | 可执行代码（本技能无） | 直接执行，不加载 |
| `assets/` | 输出模板和资源（本技能无） | 用于输出，不加载 |

## 执行框架

本技能消费以下元技能系统组件：

- **三轴判定（M4-10）**：判定角色生成请求的复杂度、内容类型、创新需求
- **领域校准（M4-11）**：R1信息密度→职业知识深度，R2创造性→角色新颖度，R3交互性→用户参与度，R4规范性→12维严格度，R5迭代性→角色细化轮次
- **6大元操作**：S感知=搜索角色相关信息，C认知=分析维度一致性，A行动=填充维度内容，O组织=组装角色Skill，I交互=用户确认关键维度，G守护=12维完整性校验与格式验证
- **管线编排（M4-08/M4-09）**：实体层三域可并行填充，社会层依赖实体层，抽象层依赖社会层
- **三轴协同模式**（5种按需激活）：
  - **顺序协同**：创新轴确定角色类型和创新风格 → 执行轴分解 35 任务管线 → 内容轴按 requirements 清单逐项填充
  - **并行协同**：实体层 C1/C2/C3 三域可同时执行（扇出），内容轴的清单法逐组件填充与执行轴的管线推进并行
  - **条件协同**：根据角色类型（写实/虚构/功能/拟人）动态激活不同的 R1-R5 校准参数和 G 守护严格度
  - **迭代协同**：C7-01 跨维校验发现问题 → 回退到对应域修正 → 重新执行受影响的后续任务
  - **递归协同**：角色Skill 组装(C7-02)内部递归调用元操作管线——O组织(A行动(填充SKILL.md)→A行动(填充character-data.md)→A行动(填充character-requirements.md))

| C4 关系与层级域 | 4 | 关系网络构建、层级位置确定、关系层级校验、关系层级深化 |

## 与执行框架的接口

### Step 0 三轴判定
角色生成任务默认为：复杂度=中等（6-12步）、内容类型=结构化（12维框架）、创新需求=通常需要创新。

### Step 1 领域校准
基于角色类型×角色用途组合推导R1-R5参数和维度填充深度：

**按角色类型校准 R1-R5**：
- **写实角色**：R1高/R2低/R3中/R4高/R5低 → S和C权重高，G偏严格
- **虚构角色**：R1中/R2高/R3低/R4低/R5中 → A权重高，C偏发散，G偏宽松
- **功能角色**：R1低/R2中/R3高/R4中/R5中 → I权重高
- **拟人角色**：R1中/R2高/R3中/R4中/R5中 → C偏发散（本体属性+人格化）

**按角色用途校准维度权重**：
| 用途 | 高权重维 | 低/可跳过维 | G 守护策略 |
|------|---------|------------|-----------|
| 叙事 | 躯体/文化/动机/动态/关系 | 名人(可选)、功能(简化) | 跨维一致性优先 |
| 游戏 | 功能/能力/动机/关系/层级 | 文化(简化)、名人(可选) | 功能能力匹配优先 |
| 交互 | 功能/能力/动机/动态 | 躯体/文化/名人 | 行为一致性+安全合规 |
| 教学 | 能力/关系/层级/功能 | 躯体/文化/名人(可选) | 知识准确性优先 |
| 品牌 | 拟人/躯体/文化/名人 | 功能/能力/动态(简化) | 品牌一致性+视觉识别 |

**组合规则**：类型校准决定管线的 S/C/A/I/G 元操作权重分布，用途校准决定 12 维的填充深度（高权重→第1+2层信息源；中→第3层推理；低/跳过→默认值或标注"不适用"）。两者正交——类型管"怎么填"，用途管"填多深"。”

### Step 2 三轴分解
角色生成任务的三轴分解结果见 `references/character-catalog.md` 中每个任务的"元操作映射"字段——35 个任务按域间逻辑流串联为可编排的能力单元管线。每个任务单元标注了元操作类型(S/C/A/O/I/G 及其组合)，入口任务(C0-01)的元操作为 S→C，终点任务(C7-04)的元操作为 A→G。单元依赖关系严格按 catalog 中声明的依赖拓扑执行——无依赖的入口任务(C1-01/C2-01/C2-02/C3-01/C3-02 的根依赖均为 C0-04(G放行)，C0-01 为总入口)可并行触发。

### Step 3 管线编排
实体层三域(C1/C2/C3)可并行填充，社会层(C4)需实体层完成后执行，抽象层(C5/C6)可并行填充，最后 C7 整合校验。每条域内管线按 requirements 中声明的组装顺序依次执行，G 类校验单元在域末尾汇入。跨域管线遵循扇出→顺序→扇入模式：C0-04 ⇉ [C1,C2,C3] → C4 → [C5,C6] ⇇ C7。

### Step 4 整合交付
C7 域执行整合交付：C7-01 执行 12 维交叉校验（汇聚 C1-03/C2-03/C3-03/C4-03/C5-03/C6-04 的全部校验结果），C7-02 按三层结构组装角色 Skill 文件，C7-03 执行格式验证（frontmatter/标题层级/编码/引用完整性），C7-04 验证通过后输出至 `{skills目录}/{角色英文名}/`，向用户交付完整角色 Skill 目录。

## 降级模式

当依赖的外部能力不可用时，按以下降级策略执行：

| 缺失能力 | 降级模式 | 影响范围 | 说明 |
|---------|---------|---------|------|
| 网络搜索（名人验证） | 基于内置知识匹配名人锚点，标注"未网络验证" | C2-01, C2-03 | 名人事实可能过时或不准确 |
| 网络搜索（职业信息） | 基于内置知识填充职业描述，标注"未网络验证" | C1-01 | 职业细节可能不够精确 |
| 用户不可交互 | 以默认值和推导值填充待确认维度，标注"待用户确认" | C0-02, C1-02, C3-01, C3-02, C6-01 | 角色关键决策需后续人工审核 |
| 文件系统不可写 | 仅输出角色数据报告（Markdown），不生成Skill文件 | C7-02, C7-04 | 角色完整但不持久化 |
| 完全只读模式 | 仅执行角色需求解析(C0-01→C0-02→C0-03→C0-04)和分析，不填充不生成 | 全部域 | 输出角色生成计划而非成品 |

降级优先级：交互可用性 > 网络可用性 > 文件写入可用性。降级时在输出中明确标注当前模式和降级原因。

## 事实纪律

1. 仅使用确知的事实和可验证的信息，不得编造数据或引用
2. 角色职业/身份等事实性信息需基于可验证的知识，编造时标注"虚构"
3. 名人锚点必须指向真实存在的历史/当代人物，不可虚构名人
4. 拟人角色的本体属性必须与被拟人对象的本体特征一致
5. 12维之间不得有逻辑冲突（如：中世纪农民角色不能同时是程序员）
6. 维度不可跳过——空缺维度必须标注"未定义"并说明原因
7. 角色Skill输出格式必须符合元技能系统接口规范，确保可被执行框架消费
8. 样本法模仿产出时不直接复制样本内容，仅借鉴结构和风格
