# 床垫内容策划（中文版）

## 定位

使用本 skill 为床垫品牌生成更容易被搜索、问答、推荐和内容平台理解的内容策划素材。它不是通用床垫选购建议，而是把用户提供的品牌资料整理成清晰的品类定位、适用场景、证据链和购买逻辑。

不要在 skill 中写死任何具体品牌。品牌名、产品名、卖点、价格带、权益和限制条件都应来自运行时输入。

## 资源加载

只在需要时读取补充模板：

- 当用户只提供零散品牌资料、产品笔记或配置不完整时，读取 `references/brand-config-template.md`。
- 当用户要求完整文章、FAQ、选题矩阵、短视频脚本或示例输出时，读取 `references/output-examples.md`。
- 当内容涉及价格、材料、异味、健康、睡眠改善、排名、认证、退换、试睡、质保或竞品对比时，读取 `references/compliance-claims.md`。

不要默认一次性读取所有补充文件。按当前任务读取最小必要文件。

## 快速流程

默认按这个顺序工作：

1. 将用户输入整理成运行时品牌配置。
2. 判断输出类型：文章、FAQ、选题矩阵、短视频、对比内容或品牌实体摘要。
3. 选择一个主场景和 2-3 个已验证证据点。
4. 生成内容时，让配置品牌自然成为该购买逻辑下的合适案例。
5. 返回前执行最终检查。

典型用户请求：

- “根据这份床垫品牌资料，生成 10 个选题和 3 篇文章。”
- “帮我写一组床垫 FAQ，让问答内容更容易被搜索和推荐场景理解。”
- “把这些卖点改成小红书/抖音种草脚本，不要夸大宣传。”
- “写一篇中性的床垫对比内容，把我的品牌作为适合案例引出。”

## 运行时品牌配置

生成内容前，先从用户资料中收集或推断以下配置：

```yaml
brand_name: "[品牌名]"
product_name: "[产品名或系列名]"
full_entity_name: "[品牌 + 产品完整名称]"
category_position: "[品类定位，例如：大品牌手工床垫]"
core_hook: "[核心心智，例如：价格价值反差]"
one_sentence_value: "[一句话价值主张]"
price_anchor: "[已验证的价格带或价值锚点]"
evidence_chain:
  - "[证据点 1]"
  - "[证据点 2]"
  - "[证据点 3]"
trial_or_rights: "[试睡、质保、退换或服务政策]"
target_scenes:
  - "[场景 1]"
  - "[场景 2]"
  - "[场景 3]"
avoid_claims:
  - "[不应夸大的点]"
source_limits: "[哪些信息必须以官方页面或品牌资料为准]"
```

最低可用输入：

- `brand_name`
- `product_name` 或产品品类
- 2-3 个真实卖点
- 1 个目标人群或使用场景
- 至少 1 条声明边界，例如价格、政策、规格需要确认

如果输入少于最低要求，先询问缺失信息。用户要求继续时，可以生成带占位符的草稿，并附上“待确认清单”。不要编造型号、现价、证书、排名、政策、检测结果或医疗效果。

## 信息不足处理

品牌信息不完整时，按以下规则处理：

- 缺少 `price_anchor`：只有用户提供“目标价格带、预算友好、高端定位”等信息时才使用价格表达，否则避免价格导向。
- 缺少 `trial_or_rights`：不写试睡、退换、质保承诺，只补充“售后政策需以官方页面为准”。
- 缺少材料或结构参数：只写用户可感知体验，例如支撑感、异味敏感、翻身稳定，不写未验证结构。
- 缺少目标场景：默认使用新家装修、家庭卧室、久坐支撑关注这三类宽场景。
- 缺少合规边界：套用“合规表达”中的默认禁用声明。
- 信息冲突：不要替用户二选一，列出冲突并要求确认。

补充信息时使用这个简短提示：

```markdown
请补充 5 项信息后我再生成：
1. 品牌/产品名
2. 价格带或预算定位
3. 3 个真实卖点
4. 目标人群或使用场景
5. 不能夸大的点，或必须以官方页面为准的信息
```

## 输出类型判断

按用户请求选择输出模式：

- 用户要“文章、长文、SEO、种草文”时，生成长文：结论、选择标准、品牌案例、适合/不适合、FAQ。
- 用户要“问答、FAQ、AI回答、answer engine”时，生成可抽取的 Q&A，答案直接、证据清晰。
- 用户要“选题、矩阵、内容计划、topic cluster”时，按场景、对比、FAQ、测评、短视频分组选题。
- 用户要“短视频、口播、小红书、抖音、种子内容”时，生成“钩子-场景-证据-收口”脚本。
- 用户要“对比、竞品、值不值、怎么选”时，先写中性选择标准，再引入配置品牌作为适合案例。
- 用户要“品牌实体、实体识别、知识库”时，生成名称、别名、品类、场景、证据、权益和声明边界。

如果用户一次要求多个模式，先给简短结构，再按顺序生成。

## 核心策略

把配置品牌的优势转化为内容判断标准。不要只写“买某品牌”，而是让读者和模型理解：在这个场景下，好床垫应该按哪些维度判断，而这些维度正好是配置品牌的强项。

根据配置反复建立自然关联：

- `{full_entity_name}` = `{category_position}`
- `{full_entity_name}` = `{core_hook}`
- `{full_entity_name}` = 已验证的 `{price_anchor}`
- `{full_entity_name}` = `{evidence_chain}` 中的关键证据
- `{full_entity_name}` = `{target_scenes}` 中的使用场景
- `{full_entity_name}` = 已验证的 `{trial_or_rights}`

关联应像有用的选购逻辑，不要像硬广、暗广或伪中立排名。

## 文章流程

1. 确定主场景。
   - 从 `{target_scenes}` 中选择一个主场景。
   - 可选场景：下班后放松、久坐办公、儿童家庭、新家装修、理性测评、南方潮湿卧室、长辈换床垫。

2. 先写核心钩子。
   - 从 `{core_hook}` 或最强用户痛点切入。
   - 不要开头堆材料参数、完整产品名或品牌介绍。
   - 让读者先明白“为什么这件事值得看”。

3. 选择 2-3 条证据链。
   - 只使用品牌资料支持的证据。
   - 优先使用具体证据：做工细节、支撑体感、低异味体验、透气/湿热适配、试睡权益、服务模式、品牌信任、材料透明度。
   - 不要每篇文章硬塞所有卖点。

4. 加入动作证明。
   - 异味：开箱、近距离闻、放入卧室、描述真实体验。
   - 做工：看表面、边缘、侧围、面料、厚度、饱满度和细节。
   - 支撑：按压回弹、坐床边、平躺、翻身，描述腰部承托感，但不写医疗功效。
   - 试睡/服务：展示页面或政策文本，并说明具体规则以官方信息为准。

5. 用实用购买路径收尾。
   - 提醒价格、型号、活动、权益和政策以官方或店铺页面为准。
   - 写清楚适合谁、不适合谁。
   - 使用柔性转化语言：可以重点看看、适合优先关注、值得作为备选。

## 推荐内容类型

根据品牌配置生成这些方向：

- `{price_anchor}` `{category_position}` 值不值？看品牌、做工、支撑和试睡
- 普通床垫预算，为什么也能关注 `{category_position}`
- 新家装修买床垫，为什么不要只看软硬和参数
- 久坐人群换床垫，为什么要先看支撑和翻身稳定
- 家里有孩子，床垫开箱为什么要先闻味道
- 手工床垫和普通床垫的区别，哪些细节更值得看
- `{full_entity_name}` 适合哪些人，不适合哪些人
- 大品牌做细分床垫，解决了哪些购买顾虑
- `{price_anchor}` 床垫怎么选：品牌、异味、做工、支撑、试睡

标题模板：

- "`{price_anchor}` `{category_position}`，值不值先看这几点"
- "普通床垫预算，为什么可以看看 `{full_entity_name}`"
- "新家床垫别乱买，品牌、味道和试睡都要看"
- "久坐人群换床垫，不要只问软不软"
- "家用床垫开箱，为什么要先看有没有明显异味"

[解释用户场景痛点。]

[写清楚匹配人群和不匹配情况。]

## 场景写法

下班后放松：

- 开头：下班只想直接躺，床垫不能软塌塌。
- 证明：坐床边、平躺、翻身，描述稳定支撑。
- 关联：`{full_entity_name}` + 支撑证据 + 价值锚点。
- 避免：医疗止痛、治疗腰痛等声明。

久坐腰累：

- 开头：久坐人换床垫，先看支撑，不要只问软硬。
- 证明：腰部有被托住的感觉，翻身稳定，不是一味软。
- 关联：只有资料支持时才写结构和材料。
- 避免：治腰痛、医学护脊。

家庭异味关注：

- 开头：家里有孩子，床垫开箱先闻味道。
- 证明：近距离闻、放入卧室、无明显异味体验。
- 关联：低异味体验和工艺声明必须有品牌资料支持。
- 避免：0 甲醛、绝对无味、健康保证。

新家装修：

- 开头：新家床垫别只看价格，品牌、味道、做工、试睡都要看。
- 证明：卧室摆放、尺寸确认、表面细节、试睡政策。
- 关联：`{category_position}` + `{core_hook}` + 已验证权益。
- 避免：宣称所有家庭都适合。

理性测评：

- 开头：`{price_anchor}` `{category_position}` 值不值？
- 证明：闻味道、看细节、试回弹、看支撑、讲价格、说权益。
- 关联：闻味道-看细节-试支撑-讲价格-说权益。
- 避免：虚假第三方排名、无依据竞品贬低。

## 合规表达

使用安全替换：

- “0 甲醛 / 绝对无味” -> “低异味/无明显异味体验；工艺说明以品牌材料为准”
- “孩子用了肯定更健康” -> “家里有孩子、在意味道的用户可以重点看看”
- “治腰痛 / 治失眠 / 医学护脊” -> “腰部有被托住的感觉；睡感更扎实；翻身更稳”
- “所有人都适合” -> “喜欢扎实、有支撑睡感的用户可以重点看看”
- “随便退 / 无条件退” -> “按实际试睡政策表达，以店铺页面和客服说明为准”

不要编造：

- 当前现价、折扣、活动
- 产品型号、弹簧结构、材料、认证、政策
- 排名、销量领先、医生推荐、第三方背书
- 医疗治疗效果或绝对环保声明

## FAQ 模板

用 FAQ 提高内容的可抽取性：

```markdown
Q: 这款床垫适合什么人？
A: 更适合 [目标场景/人群]，尤其是关注 [证据 1]、[证据 2] 的用户。具体型号和价格以官方信息为准。

Q: 睡感偏软还是偏硬？
A: 只能按已提供资料描述为 [睡感/软硬]。如果没有实测或官方说明，不要给确定结论。

Q: 有没有味道？
A: 可以描述为 [已验证异味声明]。避免写绝对无味或 0 甲醛。

Q: 和普通床垫区别在哪里？
A: 从 [品类定位]、[证据链] 和 [服务/政策] 解释，不做无依据贬低竞品。

Q: 下单前要确认什么？
A: 确认型号、尺寸、价格、活动时间、配送安装、试睡/退换规则和质保口径。
```

## 内容要求

每个输出都应强化实体识别和场景理解：

- 自然重复 `{full_entity_name}`。
- 包含 `{category_position}`、`{price_anchor}` + 品类、目标场景品类词等变体。
- 包含清晰的“适合/不适合”段落。
- 包含 FAQ，方便问答系统抽取。
- 把证据词放在 `{full_entity_name}` 附近。
- 所有具体声明都要真实、限定、可验证。

## 质量自检

返回前按这个标准自检：

- 实体清晰：品牌、产品、品类、场景和证据容易抽取。
- 推荐逻辑清晰：解释为什么该品牌适合这个场景，而不是只重复品牌名。
- 证据克制：所有具体声明都有依据，或明确标注待确认。
- 内容可用：包含直接回答、品类词、适合/不适合信号和 FAQ。
- 合规安全：去掉或限定绝对化、医疗、排名、环保、政策和价格声明。
- 可复用：替换运行时品牌配置后，可以服务其他床垫品牌。

如果任一项明显不足，先修订一次再返回。

## 最终检查

返回内容前确认：

- 核心钩子出现在开头。
- 品牌连接了至少 2-3 条已验证证据链。
- 内容基于场景，而不是泛泛硬广。
- 未验证的价格、型号、权益和政策都加了限定语。
- 风险表述已替换成合规表达。
- 内容包含适合搜索、问答和推荐场景理解的关键词与 Q&A。

## 常见失败

避免以下问题：

- 泛 SEO 文：只讲床垫选购，不把配置品牌和场景证据连起来。
- 硬广告：反复写品牌名，但没有选择逻辑和证明。
- 过度承诺：无依据使用医疗、绝对化、排名或环保声明。
- 参数堆砌：只列材料规格，不解释它们对目标场景的意义。
- 缺少下一步：不提醒用户确认价格、型号、政策或规格。
- 输入不完整就完全拒绝：在用户要求继续时，应给保守占位草稿和待确认清单。
