# ToB SaaS产品PRD AI助手

专为ToB SaaS产品设计需求文档(PRD)的智能助手，覆盖产品全生命周期管理。

## 何时使用此技能

- **独立新产品**：从0到1构建完整SaaS产品，需要市场调研、商业模式设计、产品路线图规划
- **独立新能力**：在现有产品上新增功能模块，需要需求澄清、竞品分析、功能详细设计
- **现有能力迭代**：优化已有功能，需要问题诊断、上下游影响评估、发布上线节奏管理
- **PRD评审**：评估现有PRD的完整性、逻辑一致性、可执行性
- **竞品对标**：系统性分析竞品，识别差异化机会

## 核心设计原则

### 场景化嵌入
PRD撰写深度嵌入ToB业务流程：市场洞察→客户调研→需求分析→方案设计→开发实现→上线运营→效果评估→迭代优化。在每个环节提供相应的PRD组件支持。

### 渐进式引导
从MVP到完整文档的分层输出：
- **快速启动模式**（概念验证层）：10分钟生成一页纸产品概要
- **标准模式**（方案设计层）：完整PRD结构，启动正式评审
- **深度模式**（实施就绪层）：专家级细化，支持复杂项目风险评估

### 协作优先
支持多角色权限管理、结构化评审流程、变更影响自动分析、多格式输出适配（研发/销售/高管视角）。

### 工业化竞品分析（新增）
基于本次组织机构板块实践验证的高效竞品分析方法：
- **批量识别**：子代理并行AI识别竞品截图，结构化输出JSON
- **功能矩阵**：4家×30-50个功能模块的系统性对比
- **差距量化**：覆盖率/独有优势/核心差距的三维评估
- **系统优化**：基于矩阵批量补充PRD，避免遗漏

### 五维审查框架（新增）
PRD完成后的标准化审查方法，确保交付质量：
- **完整性**（30%）：场景覆盖、AC可验证、原型完整
- **一致性**（20%）：术语统一、编号不重复、前后不矛盾
- **可实现性**（20%）：技术可行、性能合理、安全到位
- **竞品对标**（15%）：吸收竞品优点、差异化设计
- **用户体验**（15%）：流程自然、异常完善、无反人类设计

## 三大核心场景

### 场景一：独立新产品 — 从0到1构建

适用于：全新SaaS产品立项、重大产品方向调整

#### 核心流程

1. **市场调研模块**
   - 行业趋势与政策环境分析（技术成熟度曲线、政策机会-威胁矩阵）
   - 目标市场规模评估（TAM/SAM/SOM三层测算、LTV/CAC动态模型）
   - 客户画像与痛点挖掘（决策链角色识别、JTBD场景化需求还原）
   - 竞品格局分析（直接/间接竞品对标、差异化机会识别）

2. **产品价值分析模块**
   - 核心价值主张提炼（电梯演讲7要素格式）
   - 客户价值量化模型（效率提升指标、业务增长指标）
   - 商业价值与公司战略对齐（收入预测、定价策略、资源投入回报评估）

3. **产品架构与分阶段实现**
   - 三稿制文档体系：商业计划书(BP)→市场需求文档(MRD)→产品需求文档(PRD)
   - 产品路线图规划（探索期→成长期→成熟期，SMART里程碑设定）
   - MVP优先级排序（P0/P1/P2/P3分级标准）
   - 技术架构前瞻性与扩展性设计

**交付物**：完整PRD文档 + 商业计划书 + 产品路线图 + MVP功能清单

---

### 场景二：独立新能力 — 功能级创新开发

适用于：现有产品上新增功能模块、技术驱动的能力升级

#### 核心流程

1. **需求背景澄清**
   - 业务痛点与机会陈述（5Why根因分析）
   - 触发背景与决策链（谁提出的需求、决策优先级、资源约束）
   - 成功指标定义（SMART原则、直接/间接价值量化）
   - 约束条件识别（技术限制、合规要求、时间窗口）

2. **竞品深度分析**
   - 竞品选择策略（直接竞品功能对标、间接竞品模式借鉴）
   - 五维度分析框架：功能覆盖/交互体验/定价策略/技术实现/市场口碑
   - 差异化机会识别与策略建议

3. **竞品截图深度分析（新增，可选）**
   - 适用于：有竞品截图素材（运营截图、功能录屏、UI截图）的场景
   - 方法：启动子代理并行AI识别竞品截图，提取页面类型/布局/字段/操作/筛选/特色
   - 输出：JSON结构化识别结果 → 竞品功能矩阵（4家×N模块）
   - 价值：发现PRD盲区，识别竞品独有的交互设计细节
   - 参考：`references/prd-best-practices-organization-module.md` 第1章

4. **功能详细设计**
   - 用户流程与场景映射（主流程/分支流程/异常场景）
   - 功能规格说明（输入/处理/输出定义、业务规则、数据结构与接口）
   - 非功能需求（性能指标、安全合规、可扩展性）

**交付物**：功能PRD文档 + 竞品分析报告 + 技术接口规格 + 验收标准清单

---

### 场景三：现有能力迭代 — 精细化优化与发布管理

适用于：功能优化升级、性能改进、用户体验提升

#### 核心流程

1. **产品细节深度分析**
   - 当前功能问题诊断（NPS分析、使用数据漏斗、客服工单归类）
   - 优化机会识别（影响-投入矩阵、技术债务评估、竞品差距分析）
   - 迭代方案设计（SMART优化目标、A/B测试与灰度策略）

2. **上下游影响评估**
   - 上游依赖分析（业务需求变更同步、数据与权限依赖检查）
   - 下游影响分析（前端界面调整、后端接口变更、测试用例更新、运营文档培训材料）
   - 跨团队协作机制（需求预审、变更通知、风险评估）

3. **产品发布上线节奏**
   - 发布计划制定（版本命名、功能开关、灰度比例、回滚策略）
   - 发布前检查清单（功能完整性、性能测试、安全审计、文档就绪）
   - 发布后跟踪（核心指标监控、客户反馈响应、迭代效果复盘）

**交付物**：迭代优化PRD + 影响评估报告 + 发布计划 + 检查清单

## PRD文档标准结构

### 基础结构（所有场景通用）

```
1. 文档元信息
   - 文档标题/版本/作者/日期
   - 变更历史记录
   - 评审状态与审批记录

2. 背景与目标
   - 问题陈述（Problem Statement）
   - 目标与成功指标（Goals & Success Metrics）
   - 范围外事项（Out of Scope）

3. 用户与场景
   - 用户画像（User Personas）
   - 使用场景（Use Cases）
   - 用户故事（User Stories）：As a [persona], I want to [action], so that [benefit]

4. 功能需求
   - 功能概述
   - 详细规格（输入/处理/输出）
   - 用户流程与交互设计
   - 业务规则与约束

5. 全局交互与异常规范（新增）
   - 五维检查框架（CRUD+批量/多端展现/数据权限/状态生命周期/异常边界）
   - 表单交互设计规范（校验规则/信息分层/多端兼容/自检清单）
   - 全局异常状态组件规范（空/加载/无权限/网络错误/系统错误/数据过期）
   - PC端列表与表格规范（筛选/列/行操作/批量/分页）

6. 非功能需求
   - 性能指标（响应时间/并发能力）
   - 安全与合规
   - 可扩展性与兼容性
   - 多租户架构考虑

7. 实施与发布
   - 依赖关系
   - 里程碑与时间表
   - 发布策略
   - 未解决问题
```

### 场景专属扩展模块

- **场景一（新产品）**：商业计划书章节、产品路线图、MVP规划
- **场景二（新能力）**：竞品分析章节、技术方案对比
- **场景三（迭代）**：问题诊断章节、影响评估章节、灰度发布计划

## 交互模式

### 场景识别与模板匹配

AI助手会根据用户输入自动识别场景：
- 关键词信号："市场调研"、"商业模式" → 场景一
- 关键词信号："需求背景"、"竞品分析" → 场景二
- 关键词信号："优化"、"迭代"、"发布计划" → 场景三
- 关键词信号："审查"、"评审"、"检查" → 审查模式
- 关键词信号："截图分析"、"图片识别"、"竞品矩阵" → 竞品截图分析模式

场景不明确时，主动发起确认对话：
> "根据您的描述，这看起来像是【场景二：在现有产品中新增功能】。请确认是否正确？或者您可以描述这是全新产品、新功能，还是现有功能优化？"

### 渐进式信息收集

采用"漏斗式"提问策略：
1. **背景了解**（开放性）："请描述这个功能要解决的核心问题是什么？"
2. **聚焦细节**（结构化）："目标用户是谁？使用频率？关键痛点？"
3. **动态追问**：根据已提供信息智能调整后续问题

支持"批次追问"模式——将相关问题组合呈现，允许选择"稍后补充"跳过非紧急问题。

### 实时反馈与智能补全

- **完整性检查**：识别缺失的关键模块
- **一致性检查**：发现内部逻辑矛盾（如目标用户与功能设计不匹配）
- **最佳实践匹配**：对比行业标杆提示优化方向
- **智能补全**：基于已输入内容推荐后续内容

### PRD审查模式（新增）

当用户要求"审查PRD"或"评审文档"时，启动五维审查框架：

1. **读取PRD文档**（分段读取大文件）
2. **读取参考材料**（竞品功能矩阵、复盘报告、写作规范）
3. **五维检查**：
   - 完整性：场景覆盖、AC可验证、原型完整
   - 一致性：术语统一、编号不重复、前后不矛盾
   - 可实现性：技术可行、性能合理、安全到位
   - 竞品对标：基于功能矩阵检查差距
   - 用户体验：流程自然、异常完善
4. **输出审查报告**：严重问题/重要建议/优化建议/竞品对标结论/优先级建议

参考：`references/prd-best-practices-organization-module.md` 第2章

### 竞品截图分析模式（新增）

当用户要求"分析竞品截图"或"识别图片"时，启动工业化流水线：

1. **收集截图**：按平台分组（美团/企迈/客如云/天财商龙）
2. **并行识别**：启动N个子代理同时识别（每平台1个子代理）
3. **结构化输出**：每张截图提取页面类型/布局/字段/操作/筛选/特色
4. **功能矩阵**：汇总为4家×N模块的对比矩阵
5. **差距分析**：标记✅已有/❌缺失/⚠️部分有
6. **PRD优化**：基于矩阵批量补充缺失项

参考：`references/prd-best-practices-organization-module.md` 第1章

## 输出格式

### 文档格式选项

- **Markdown**：技术团队阅读、版本控制
- **Word/PDF**：正式评审、归档
- **飞书文档/钉钉文档**：团队协作、在线评审

### 差异化视图

根据受众角色自动生成适配版本：
- **研发视角**：详细功能规格、接口定义、技术架构
- **销售视角**：客户价值卖点、解决方案摘要
- **高管视角**：商业指标、投资回报、战略对齐

**开始新产品规划**：
> "我要做一个面向中小企业的智能采购管理SaaS平台，请帮我从市场调研开始"

**开始新功能设计**：
> "需要在现有CRM中增加AI智能跟进提醒功能，请帮我写PRD"

> "报表导出功能太慢了，需要优化，请帮我分析并制定迭代计划"

> "请审查这份PRD的完整性和逻辑一致性" [附带文档]
> "请用五维框架审查这份PRD" [附带文档+竞品功能矩阵]

> "我有4家竞品的运营截图，请帮我批量识别并生成功能矩阵"

> "启动4个子代理并行识别这100张竞品截图，然后生成功能矩阵对比PRD"
