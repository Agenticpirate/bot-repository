# LINE 貼圖生成大師

將貼圖製作拆成「需求定義 → 套組腳本 → 4x3 網格圖生成 → 切圖去背 → 品質檢查 → 匯出」六個階段。不要直接產生零散貼圖；先建立固定的角色 bible、畫風規格與 12 格腳本，確保整套貼圖一致。

## 執行流程

### 1. 定義套組規格

先確認或合理詢問下列欄位：角色主體、角色名稱、年齡感或物種、固定外觀特徵、服裝與配色、畫風、使用情境、文字語言、語氣、背景/去背方式，以及套組數量。若使用者沒有指定，預設為 **12 張、4 欄 × 3 列、台灣繁體中文、透明背景、正方形單張輸出**。

建立一份簡短的角色 bible，至少包含固定臉型、髮型/毛色、服裝、配件、主色與禁止變更項目。每一格都重複引用同一份 bible，不要讓模型自行改造角色。

### 2. 編寫 12 格腳本

為每格產生以下欄位：編號、貼圖文字、情緒、動作、視線/姿勢、特效、構圖留白。文字要短、口語化、適合聊天，避免將重要文字放在臉部或手勢上。優先覆蓋問候、確認、感謝、道歉、拒絕、鼓勵、驚訝、忙碌、晚安等高頻情境；若是特定主題，保留至少數格作為萬用回應。

對台灣繁體中文進行人工語意檢查：使用自然的台灣用字，修正簡繁混用、直譯、標點錯誤與不適合聊天的長句。製作日常或職場主題時，讀取 `references/zh-tw-copy-check.md`，依其中的情境、語氣、台灣慣用詞、職場風險與逐格審核規則檢查。除非使用者指定，不要把 emoji 放進生成圖片文字；若需要符號，改用可控的圖形特效描述。

### 3. 產生 4x3 網格圖提示詞

需要輸出可直接複製到圖像生成模型的完整 Markdown Prompt 時，讀取 `templates/line-sticker-prompt-template.md`。將模板中的 `[方括號]` 欄位替換成角色、主題、12 格文案、動作、情緒、視角與特效；保留角色參考圖、二頭身比例、1480×960 px、純綠色 `#00FF00`、粗白外框、台灣繁體中文與負面提示詞等固定規格。輸出給使用者時，將完整 Prompt 放在單一 Markdown fenced code block 中，方便一鍵複製，不要把說明文字混入 Prompt。

若使用者提供角色圖片，將圖片作為角色參考輸入，不要只用文字描述取代參考圖。若使用者未提供圖片，先保留模板中的角色參考欄位，並提醒需要上傳圖片後再生成。

提示詞必須明確要求：單一 4x3 網格畫布、12 個互不重疊的獨立格子、閱讀順序由左至右再由上至下、每格保留安全邊界、角色全身或半身完整可見、背景使用指定純色且不與角色/文字主色混淆、不要額外標題或編號、不要把多格合併成一張場景。

對含文字的圖像，要求模型逐格放入指定文字，但把生成結果視為草稿：文字模型常會產生錯字，因此生成後必須逐格檢查；若文字不可靠，改採透明留白版本，後續以可控方式排版文字。

採用下列提示詞結構：

```text
Create one LINE sticker sheet as a single 4-column by 3-row grid, exactly 12 separate panels.
Character bible: [固定角色外觀與禁止變更項目]
Visual style: [畫風、線條、光影、色彩]
Canvas: [尺寸] px, equal cells, generous safe margins, no overlap between cells.
Background: solid [色彩] for easy background removal; do not use this color on the character or lettering.
Reading order: row 1 panels 1-4, row 2 panels 5-8, row 3 panels 9-12.
Panel script:
1. Text: "[文字]"; emotion: [情緒]; action: [動作]; effect: [特效].
...
12. Text: "[文字]"; emotion: [情緒]; action: [動作]; effect: [特效].
Do not add panel numbers, captions, logos, watermarks, borders, extra characters, or merged scenes.
```

若套用 `line-sticker-factory` 的色鍵去背，預設綠幕時避免角色與文字使用綠色；若使用黑幕或白幕，也要避免大面積同色元素。對寫實人物、毛髮或半透明物件，優先建議 AI 去背或 Python `rembg` 後端，而不是只依賴色鍵。

### 4. 搭配 line-sticker-factory 處理

此 GitHub 專案是前端處理器，不應假設它本身提供圖像生成 API。取得 4x3 網格圖後，使用專案進行：上傳、選擇目標背景色、切成 12 張、去背、調整縮放/邊緣柔化、預覽，再 ZIP 匯出。專案支援瀏覽器端 Web Worker 色鍵去背，也提供可選的 Python `rembg` 去背後端。

若需要在本機啟動參考實作：

```bash
cd /home/ubuntu/line-sticker-factory
npm install
npm run dev
```

若要建立更自動化的產品流程，將此 Skill 放在生成器前端或代理層，讓它輸出結構化的 12 格腳本與單一網格圖；不要把生成邏輯硬編進 `GridSlicer`。切圖器應維持單一職責：處理畫布、去背、預覽及壓縮下載。

### 5. 小沙彌向善用語網站整合

若使用者要製作小沙彌、向善或日常溫柔語氣的貼圖，可讀取 `references/little-monk-kind-words-site.md`，使用公開的 [小沙彌向善用語專區](https://qpooqp777.github.io/little-monk-kind-words-site/) 作為語料選擇層。網站目前整理 12 類、144 筆內容，每筆包含貼圖文字、適合情境、小沙彌動作、表情、視角與手繪特效。

單句製作時，使用網站的「收下這句」取得完整單格 Prompt；完整套組製作時，先選擇單一類別，再使用「收下該類 12 格」取得以換行分隔的 12 筆內容。將這 12 筆內容放入本 Skill 的 4×3 網格模板，並補上同一份角色 bible、尺寸、背景、粗白外框、繁體中文檢查與負面提示詞。不要把網站語料當成已完成的圖片，也不要跳過生成後的逐格文字與去背檢查。

網站採 GitHub Pages 公開部署，參考儲存庫為 [qpooqp777/little-monk-kind-words-site](https://github.com/qpooqp777/little-monk-kind-words-site)。網站的分類、搜尋、今日一句與複製互動只協助挑選內容，不會取代本 Skill 的角色一致性與品質檢查流程。若網站內容更新，優先以網站與 `references/little-monk-kind-words-site.md` 的最新欄位為準。

### 6. 品質檢查

在交付前逐格檢查數量與順序、角色外觀一致性、動作是否符合文字、文字是否正確可讀、文字是否被裁切、角色是否超出安全邊界、去背是否殘留色邊、是否誤刪角色細節，以及每張圖片是否有透明背景。日常與職場文字另須檢查台灣繁體用字、語氣詞、情境對象、英文縮寫、梗的可理解性、粗口/歧視/霸凌風險、是否誤指涉真人或公司內幕，以及是否提供中性替代句。任何一格失敗都要標記原因並重新生成或重新排版，不要用整套重新生成掩蓋單格問題。

使用下表記錄結果：

| 編號 | 文字正確 | 角色一致 | 去背乾淨 | 安全邊界 | 修正事項 |
| --- | --- | --- | --- | --- | --- |
| 1–12 | 是/否 | 是/否 | 是/否 | 是/否 | 具體說明 |

最後確認輸出檔案命名穩定且排序正確，例如 `01.png` 至 `12.png`；同時保留原始 4x3 網格圖、透明 PNG 個別檔與 ZIP。若使用者要送審 LINE Creators Market，另行查閱當時官方提交規範，不要把專案的切圖尺寸當成所有市場規範的保證。

## 互動原則

當使用者只說「做一套貼圖」時，先提供一份可修改的套組提案與 12 格腳本，再進入生成。當使用者已提供角色圖或網格圖時，保留其角色特徵，優先進行切圖/去背與品質檢查。當使用者要求修改單格時，只重做該格並維持角色 bible、畫風、背景色與排版規則不變。

涉及真人、品牌、動漫角色或第三方素材時，提醒使用者確認肖像、商標與著作權授權；不要主動仿製在世藝術家的獨特風格。對暴力、仇恨、性內容或其他高風險題材，先調整成適合公開貼圖的安全版本。

## 專案整合細節

需要了解 `line-sticker-factory` 的元件、去背參數與改造方向時，讀取 `references/line-sticker-factory.md`；需要檢查台灣繁體中文、日常用語或職場梗時，讀取 `references/zh-tw-copy-check.md`；需要輸出可一鍵複製的完整圖像生成 Prompt 時，讀取 `templates/line-sticker-prompt-template.md`；需要製作小沙彌向善用語或從網站挑選 12 格內容時，讀取 `references/little-monk-kind-words-site.md`。需要變更專案原始碼時，先保留現有切圖與下載流程，新增獨立的「腳本/提示詞匯入」模組，並以既有 `PromptGenerator` 的資料結構作為相容參考。
