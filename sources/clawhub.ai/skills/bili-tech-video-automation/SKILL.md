# 多平台视频内容自动化产品 · 六阶段全流程工作流

面向视频内容分发/翻译/字幕合成类 SaaS 产品的完整产品生命周期工作流。核心交付物为「需求池 → PRD → 评审结论 → 研发任务 → 测试报告 → 复盘报告」六件套。全程遵循 EARS（Easy Approach to Requirements Syntax）需求描述原则。

## ⚠️ Safety & Compliance Warning（使用前必读）

**本 skill 是产品管理与需求文档撰写的工作流模板，不包含任何可执行的爬虫、抓取或自动发布代码。**

使用本 skill 规划涉及第三方平台（如视频网站、社交平台）的内容处理产品时，你必须：

- **遵守目标平台的 Terms of Service（服务条款）**：多数平台明确禁止未经授权的批量抓取、自动上传或 API 滥用。违反可能导致账号永久封禁及法律风险。
- **尊重版权（Copyright）**：跨平台搬运他人创作内容前，必须确认拥有合法授权或该内容属于允许再分发的许可范围（如 CC 协议）。自动化搬运未授权受版权保护的内容属于侵权行为。
- **将合规作为硬性安全约束**：本工作流中的「合规校验」「违规拦截」等环节是产品设计的强制性安全要求，不是可选功能。在 PRD 中应将其定义为 P0 级别的阻断条件。
- **自行承担法律责任**：本 skill 仅提供产品管理方法论框架，不对使用者基于此框架构建的任何实际系统之合规性或合法性承担责任。

> 如果你计划构建的实际系统涉及从第三方平台自动获取并重新发布内容，请先咨询法律专业人士，确认不违反相关平台条款及当地法律法规。

## When to Use

- 为**视频翻译 / 字幕合成 / 多平台内容分发**类 SaaS 产品撰写结构化 PRD
- 按 EARS 原则规范产品功能描述，需要 Ubiquitous / Event-driven / Unwanted / State-driven / Optional 五类句式模板
- 组织视频类产品的技术评审会议，需要标准化的评审议题清单与风险评估框架
- 拆解后端（视频转码/任务调度）、算法（ASR/翻译模型）、前端（后台管理）的研发任务并绑定负责人
- 设计视频处理系统的测试用例（正常流程 + 边界异常 + 并发稳定性）与上线验收清单
- 上线后做数据复盘（产出效率/成功率/流量表现）并输出迭代需求规划

## Prerequisites（启动前确认）

在正式进入阶段一前，先确认以下阻塞项，缺一项就先标注为「待确认」并升级给对应负责人：

- **目标平台接口权限**：是否支持通过官方 API 进行视频上传、元数据填写、定时发布等操作（需申请对应权限）。
- **源数据获取方式**：优先使用目标平台提供的官方 API 或授权数据接口；若需自行采集，须确认符合平台 ToS 及当地法律法规。
- **翻译与语音识别精度**：口语化 vs 专业术语精度要求、字幕排版规范（字号/位置/双语 or 单语）。
- **合规边界**：版权授权验证、敏感内容拦截标准、平台规则合规检查点，默认拦截策略。
- **算力资源**：视频转码、ASR、翻译的服务器算力预估（长视频易堆积阻塞）。

## 全流程总览（Pipeline Overview）

```
阶段一 需求规划 ──▶ 阶段二 PRD撰写 ──▶ 阶段三 设计&研发评审 ──▶ 阶段四 研发跟进 ──▶ 阶段五 测试验收 ──▶ 阶段六 上线复盘
   (需求池)         (EARS PRD)        (评审结论+风险)        (任务拆解表)      (测试/验收报告)    (复盘报告)
```

自动化核心链路（贯穿各阶段的技术目标）：

```
定时触发数据采集 → 筛选合规内容 → 下载解析 → ASR语音识别 → AI翻译
→ 字幕嵌入合成 → 格式适配目标平台 → 合规校验 → 智能文案生成 → 自动发布 → 结果回显+日志 → 异常告警
```

## Step-by-Step（按阶段执行）

### 阶段一：需求规划（输出：需求池）

1. **核心信息梳理**：明确目标用户（内容运营团队、翻译工具使用者、多平台分发从业者）、用户痛点（人工成本高/时效性差/流程繁琐/筛选无标准）、核心场景（日常自动化运营、热点紧急抓取、批量内容沉淀）、业务目标（全链路无人值守、单条分钟级、日均产出目标、发布延迟要求）。
2. **行业与竞品分析**：对比「纯人工处理 / 单一翻译工具 / 通用采集工具」，评估用户价值、业务价值、行业价值，界定影响范围与实现复杂度（中高）。
3. **需求优先级分级**：

```markdown
## 需求优先级（P0 最高）
- P0：热门内容精准采集、AI翻译、基础格式适配、目标平台自动发布核心链路
- P1：热度筛选规则自定义、字幕样式自定义、发布定时设置、基础发布数据回显
- P2：内容合规AI审核、违规拦截、批量任务管理、发布失败重试、日志统计分析
- P3：多账号管理、视频二次剪辑（裁剪/去水印）、智能标题封面生成、流量优化适配
```

4. **待确认问题清单**：目标平台接口权限、热度筛选维度（播放/点赞/评论/涨幅）与阈值、翻译精度与字幕规范、合规边界。
5. **阶段收尾**：将 P0-P3 整理为正式需求池，创建项目事项，分配后端/算法/测试/运维负责人，同步运营角色。

```markdown
## 需求池模板
| 需求ID | 名称 | 优先级 | 描述 | 负责人 | 关注人 | 关联文档 | 状态 |
|--------|------|--------|------|--------|--------|----------|------|
| R-001  | 双平台热度采集 | P0 | 定时采集热门科技视频 | 后端 | 运营 | PRD | 待评审 |
```

### 阶段二：PRD撰写（EARS 原则，输出：PRD）

遵循 EARS（Easy Approach to Requirements Syntax）五类句式规范撰写：

```markdown
## 2.4 核心功能清单（EARS）
### 基础约束 Ubiquitous
- The system shall 仅采集公开可访问且允许再分发的内容，禁止采集私密/付费/受限内容
- The system shall 优先保障专业术语准确性，口语内容适配目标平台用户阅读习惯
- The system shall 默认拦截不符合目标平台社区规范及法律法规的内容
- The system shall 完整记录每条任务的采集/翻译/发布/异常日志，可追溯审计

### 事件触发 Event-driven
- When 到达预设定时任务时间，the system shall 自动触发热度采集任务
- When 采集完成且格式合规，the system shall 自动触发ASR+翻译+字幕合成流程
- When 翻译完成且合规校验通过，the system shall 自动触发目标平台上传发布流程
- When 手动触发单次任务，the system shall 优先执行手动任务，插队完成流程

### 异常处理 Unwanted
- If 目标数据源失效/链接过期/权限受限，then 终止当前任务，记录异常日志并推送失败提醒
- If 解析失败/音轨异常/文件损坏，then 跳过当前条目，自动采集下一条补充任务
- If 翻译接口超时/翻译内容为空，then 重试3次，重试失败后标记任务异常并告警
- If 目标平台接口请求失败/权限不足/内容被拦截，then 停止发布，留存处理后素材并推送异常通知
- If 网络波动/服务器资源不足，then 暂停批量任务，恢复资源后自动续跑未完成任务

### 状态驱动 State-driven
- While 系统处于正常运行状态，the system shall 实时监测数据源热度，定时更新热门内容池
- While 任务处于处理中状态，the system shall 锁定当前任务资源，避免重复执行/重复发布
- While 系统处于维护更新状态，the system shall 暂停所有自动化任务，维护完成后自动恢复

### 可选拓展 Optional
- Where 开启自定义热度筛选功能，the system shall 支持用户自定义播放量/点赞涨幅/时间等筛选阈值
- Where 开启定时发布功能，the system shall 支持用户设置精准发布时间段与间隔频率
- Where 开启AI封面标题生成功能，the system shall 基于内容自动生成适配目标平台的标题/封面/话题标签
```

PRD 必含章节：需求背景、核心目标、用户故事、核心功能清单（上）、核心流程说明、交互与权限（管理员/普通运营）、数据指标与埋点、验收标准（见下）、阶段收尾（上传资料库 + 建评审事项 + 分配负责人）。

```markdown
## 2.8 验收标准（checklist 式）
- [ ] 可定时/手动采集24h内热门内容，筛选规则生效，无无关内容
- [ ] ASR+翻译正常，术语准确，字幕清晰嵌入，无乱码错位
- [ ] 视频自动适配目标平台分辨率/格式/码率，无需人工二次处理
- [ ] 合规内容自动上传、填标题简介、完成发布，状态可回显
- [ ] 各类异常场景可正常拦截/重试/告警，日志完整可追溯
- [ ] 全流程自动化运行，无人工干预可稳定产出内容
```

### 阶段三：设计与研发评审（输出：评审结论 + 风险清单）

- **评审核心议题**：多平台数据获取技术方案可行性与合规风险评估、ASR/翻译技术方案精度与效率、目标平台对接方案与限流适配、异常重试机制与合规风控逻辑合理性、后台管理页面设计与交互合理性。
- **关键依赖**：数据源获取能力（官方API优先）、高精度 ASR/翻译模型、目标平台接口权限、服务器算力资源。
- **核心风险**：平台策略变更导致数据获取失效、目标平台限流导致发布失败、长视频转码/翻译耗时过长导致任务堆积、版权合规风险导致账号违规。

```markdown
## 评审输出要求
### 设计侧
- 后台管理全页面设计稿、任务状态视觉规范、弹窗提示样式、数据看板设计
### 研发侧
- 技术架构图、接口清单、数据库设计、任务调度方案、风险规避方案、排期计划
```

**阶段收尾**：整理评审结论、问题整改清单、技术风险应对方案，沉淀至项目资料库；将待优化、待落地的技术问题、设计问题拆分为独立事项，分配对应负责人跟进闭环。

### 阶段四：研发跟进（输出：任务拆解表）

#### 需求任务拆解

**后端任务**
- 多平台数据热度采集模块开发、筛选规则配置功能开发
- 视频下载、解析、转码、格式适配模块开发
- 目标平台开放平台对接、视频上传、发布、状态同步模块开发
- 定时任务调度、异常重试、日志记录、告警功能开发
- 后台权限管理、任务数据看板、手动操作功能开发

**算法任务**
- 视频语音识别(ASR)模型调用与适配
- 领域专属AI翻译模型优化、术语库适配
- 字幕自动合成、排版适配功能开发
- 基础内容合规AI校验模型适配

**前端任务**
- 后台管理页面开发、任务状态展示、参数配置页面开发
- 数据统计看板、异常日志查询页面开发

#### 进度跟进与风险管控

- 每日同步各模块开发进度，梳理已完成、进行中、阻塞任务
- 重点监控数据获取稳定性、接口对接、算力适配等高风险模块进度
- 及时识别需求范围变更、技术实现卡点、延期风险，同步团队调整方案
- 每日输出研发进度摘要、风险清单，同步项目全员

**阶段收尾**：将所有研发子任务录入项目事项，绑定对应负责人、PRD文档、设计稿；阻塞问题及时升级处理，确保研发按期完成。

### 阶段五：测试验收（输出：测试报告 + 上线风险评估）

#### 核心测试用例覆盖

**正常场景测试**
- 定时任务自动触发，正常采集热门内容
- 视频完整下载、解析、转码，格式适配目标平台要求
- 语音识别、翻译、字幕合成正常，内容准确
- 合规内容自动上传、编辑文案、成功发布至目标平台，状态同步正常

**边界&异常场景测试**
- 测试视频时长边界：短视频、长视频的处理稳定性
- 测试网络波动、接口超时场景的重试机制
- 测试违规内容、无语音视频、损坏视频的拦截逻辑
- 测试目标平台接口限流、权限失效的异常告警逻辑
- 测试批量任务并发场景的系统稳定性

#### Bug管理规范

所有测试问题统一规范记录：包含复现环境、复现步骤、实际结果、期望结果、影响范围、严重等级；阻断核心流程、影响上线的P0 Bug优先修复，验证通过后方可进入上线阶段。

#### 上线验收清单

```markdown
- [ ] 功能全覆盖验收  [ ] 异常场景验收  [ ] 性能稳定性验收
- [ ] 数据准确性验收  [ ] 日志完整性验收  [ ] 告警功能验收
```

**阶段收尾**：所有测试Bug创建为项目事项，关联原需求PRD，分配开发修复并闭环；输出版本测试报告、上线风险评估报告，确认无误后推进上线。

### 阶段六：上线复盘（输出：复盘报告 + 迭代需求）

#### 核心复盘维度

- **目标达成情况**：自动化产出效率、采集/翻译/发布成功率是否达标
- **上线效果**：内容时效性、内容质量、目标平台账号流量数据表现
- **问题复盘**：上线后出现的异常问题、技术卡点、流程漏洞
- **角色反馈**：研发、测试、设计、运营使用体验与优化建议

#### 遗留问题与优化方向

- **短期优化**：修复上线后 minor Bug、优化翻译精度、优化异常重试逻辑
- **中期优化**：新增自定义筛选规则、封面标题AI优化、多账号管理功能
- **长期优化**：完善合规风控体系、提升批量任务并发能力、拓展更多内容源

#### 复盘输出物

输出项目上线复盘报告、核心数据观测清单、版本问题总结、下一版本迭代需求清单。

**阶段收尾**：将复盘报告上传项目资料库，把所有优化迭代需求创建为新的需求事项，规划下一版本排期，完成项目全流程闭环。

## 通用全流程提醒（全程生效）

- 各阶段交付物（需求池、PRD、评审结论、测试报告、复盘报告）全部归档项目资料库，统一项目上下文
- 所有事项均绑定对应交付文档、负责人、关注人，确保信息同步到位
- 涉及排期、资源调配、上线范围、权限变更等决策，务必同步对应负责人确认后执行
- 各阶段完成后，主动流转至下一环节角色，保障项目高效推进

## Troubleshooting

- **PRD 功能描述混乱**：严格用 EARS 五类句式（Ubiquitous/Event/Unwanted/State/Optional），不要混用，避免「系统应该支持…」式模糊陈述
- **需求池与 PRD 脱节**：PRD 中每条功能必须能回溯到需求池需求ID，评审前做双向追溯检查
- **数据获取在评审后失效**：阶段三必须产出合规风险规避方案（官方API优先/IP池/限频/降级策略），不要等到研发后期才补
- **长视频堆积阻塞**：阶段四排期时单独评估转码/翻译算力，设置任务队列上限与并发控制
- **目标平台发布失败无感知**：异常分支（If 接口失败）必须接告警通道，且留存处理后素材便于人工补发
- **合规漏拦导致账号违规**：默认拦截策略 + P2 的 AI 合规审核需在发布前卡点，不能后置于发布后

## Tips

- EARS 的 `The system shall`（基础约束）最适合写「永远成立」的合规/日志类规则，把它们从事件流里抽出来单独成节，PRD 可读性最高
- 需求优先级 P0-P3 不是越大越后做，而是上线必须有 P0，P1 决定首发体验，P2/P3 作为迭代 backlog
- 验收标准写成 checkbox 清单，能直接复用作阶段五的测试用例入口，减少重复沟通
- 把「自动化核心链路」画成一张贯穿六阶段的图，每次阶段收尾都对照它确认「这一环今天做到哪了」
- 所有「待确认问题」必须带负责人和截止时间，否则会在评审时被打回，拖慢整体排期
- 阶段间流转用「交付物 + 事项绑定负责人」做抓手，比口头同步可靠得多
- 合规与版权是该系统的生死线，宁可首发少做几个 P1，也要把 P0 的拦截与日志做扎实
