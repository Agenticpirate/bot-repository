# 党政机关公文格式标准排版（GB/T 9704-2012）

一个技能覆盖公文成文的三个环节：**先净化文风 → 再国标排版 → 后合规质检**。

## 〇、交互铁律（最先读，违反即失败）

用户是公务员、文员，坐在**对话框**前，不是终端前。本文档里的所有命令行是**给你执行的，不是给用户看的**。

1. **你自己跑脚本，不要把命令贴给用户。** 用可用的代码执行能力（终端/Bash）调用 `scripts/` 下的脚本。除非用户明确说"给我命令我自己跑"，否则回复里不出现 `python scripts/...` 这类代码块。
2. **没有代码执行能力时**，如实说明并给出两条路：①请用户在本地按你提供的命令执行；②由你按国标规则**直接输出结构化预览**（见第九节），至少让用户看到层级与要素是否正确。不要假装文件已生成。
3. **不报告中间过程的技术细节。** 用户要的是"文件好了没、合不合规"，不是 stdout。按第八节的模板汇报。
4. **产出文件后必须让用户能拿到。** 用文件呈现能力把 `.docx` 与报告交付给用户。
5. **缺要素先问，别瞎编。** 发文机关、发文字号、成文日期这类要素编错了比空着更糟。按第七节的清单追问。

## 一、先做意图路由

拿到用户请求后，先判断落在哪一档，再决定调用哪个脚本。三个模式可单独用，也可串联。

| 用户意图信号 | 模式 | 脚本 |
|---|---|---|
| 公文排版、红头文件、按国标排公文、不规范 Word/TXT 重排为公文 | **A. 排版** | `scripts/gongwen_format.py` |
| 检查格式、这份公文合规吗、质检、找问题、校对格式、格式审核 | **B. 质检** | `scripts/gongwen_check.py` |
| 统一文风、去口语、去网络用语、去 AI 味、改成公务书面语、润色成公文语言、纠错别字 | **C. 文风净化** | `scripts/style_clean.py` |
| 「把这篇草稿弄成正式文件」这类笼统请求 | **C → A → B 串联** | 三个都跑 |

### 模糊输入的兜底

关键词匹配会失灵，下面几种情况按此处理，**不要反问一堆问题把用户挡在门外**：

| 情况 | 处理 |
|---|---|
| 用户只丢来一段文字，什么都没说 | 默认跑 **模式 C**（净化风险最低、不需要任何额外要素），然后问一句：「已按公务书面语初步净化。需要我排成正式公文吗？如果要红头，请告诉我发文机关和发文字号。」 |
| 用户丢来一个 `.docx`，只说「看看」 | 默认跑 **模式 B** 质检，报结论，再问是否需要按国标重排 |
| 说了「排版」但没给标题 | 从正文首行猜标题，**猜完必须复述确认**：「我按《××》作为公文标题，对吗？」 |
| 说了「红头文件」但没给机关名 | 先按无红头版式生成，交付时说明：「未提供发文机关名称，暂未加红头。告诉我机关全称和发文字号即可补上。」不要用「××市人民政府」这类占位符冒充真实机关 |
| 判不准是哪种 | **先问用户确认意图**（给出「只净化 / 只质检 / 净化+排版+质检」等选项），不自行跑全链路；用户确认后再执行 |

### 必须拒绝的请求

用户常会顺口说「帮我写个关于××的通知」。**本技能不代拟公文内容**，遇到时这样答：

> 我可以负责格式和文风，但公文内容涉及具体政策、数据和责任分工，需要由您来定。
> 您把要点写下来（哪怕是几句大白话），我来做三件事：润色成公务用语 → 按国标排版 → 出质检报告。

不要一边说"不代拟"一边生成一篇编造的通知——格式再标准，内容是假的就是废纸。

## 二、运行环境

脚本只依赖 `python-docx`。首次使用先确认：

```bash
python -c "import docx" || pip install python-docx
```

PDF 导出不在本技能范围内：排版产物为标准 `.docx`，可用 Word/WPS「另存为 PDF」获得 PDF 版。

字体处理：脚本内置**字体回退链**，仅以只读方式查询本机已安装字体列表用于回退映射（不读取其他环境信息）。国标要求的「方正小标宋简体」在多数 Windows/macOS 上并未预装，此时自动回退到宋体/华文中宋并在运行日志中打印实际映射。若必须严格写入国标字体名（送印刷厂、对方机器有字体），加 `--strict-font`。

## 三、模式 A：国标排版

### A1. 准备正文

正文来源支持三种：`--input draft.md` / `draft.txt` / `draft.docx`，或写进 JSON 配置的 `body_text` 字段。

正文里的层级用下面任一种写法，脚本都能识别并套用正确字体：

```
一、提高思想认识          →  黑体 3号，顶格空两字
（一）压实属地责任        →  楷体 3号
1. 建立台账               →  仿宋 3号
（1）逐点登记             →  仿宋 3号
```

Markdown 的 `#/##/###/####` 会被映射到上面四级；`**加粗**`、`- 列表` 等标记会被清理，不会漏进正文。

### A2. 最小可用命令

```bash
python scripts/gongwen_format.py \
  --title "××市人民政府关于进一步加强城市排水防涝工作的通知" \
  --input draft.md \
  --output 通知.docx
```

### A3. 完整红头文件

```bash
python scripts/gongwen_format.py \
  --redhead "××市人民政府" \
  --doc-number "×政发〔2026〕12号" \
  --title "××市人民政府关于进一步加强城市排水防涝工作的通知" \
  --recipient "各区县人民政府，市政府各部门、各直属机构" \
  --input draft.md \
  --attachment "1. 城市易涝点位整治清单" \
  --attachment "2. 排水防涝责任分工表" \
  --author "××市人民政府" \
  --date 2026-08-06 --seal \
  --notes "此件公开发布" \
  --cc "市委办公室，市人大常委会办公室" \
  --print-author "××市人民政府办公室" --print-date 2026-08-07 \
  --output 通知.docx
```

要素多时改用配置文件更清爽（模板见 `gongwen_config.demo.json`）：

```bash
python scripts/gongwen_format.py --config my.json --output 通知.docx
```

命令行参数优先级高于配置文件，可以混用。

### A4. 常见变体

- **上报的公文**：加 `--signer "张××"`。签发人与发文字号同一行，发文字号左空一字、签发人右空一字；发文机关标志上边缘改为距版心上边缘 80mm。
- **联合行文**：`--redhead "××市发展改革委;××市财政局"`，`--author` 同理用 `;` 分隔。
- **会议纪要**：`--minutes`，自动取消版记与印章版式。
- **涉密/紧急**：`--copies 000001 --secret-level "机密★20年" --urgency 特急`，三要素按国标编排在首页版心上方左右两侧。
- **附件正文另面编排**：`--attachment-doc "附件1.md::城市易涝点位整治清单"`。
- **不编页码**：`--no-page-num`。国标要求全篇编码，`--no-first-page-num` 仅为迁就个别单位惯例，默认不要用。

### A5. 排完必须自检

排版脚本结束后**紧接着跑一次质检**，把报告结论同步给用户：

```bash
python scripts/gongwen_check.py --input 通知.docx --report 质检报告.md
```

## 四、模式 B：格式质检

对任何 `.docx`（不限于本技能生成的）做逐项扫描：

```bash
python scripts/gongwen_check.py --input 待检公文.docx --report 质检报告.md
```

检查覆盖 6 组共 30+ 项：页面设置、标题、正文与层级字体、版头要素、署名日期与版记、结构完整性。详细项目见 `references/qc-checklist.md`。

输出分三级，向用户汇报时按级别归并说明：

| 级别 | 含义 | 处理建议 |
|---|---|---|
| **高** | 明确违反国标强制条款，如页边距错、正文非3号仿宋、纸张非A4 | 必须改 |
| **中** | 不符合通行规范或国标推荐做法，如版记字号、页码位置、成文日期用汉字 | 建议改 |
| **低** | 提示性问题，如缺少可选要素、行距略有偏差 | 酌情 |

结论只有两种：**合规**（无高级别问题）/ **不通过**（存在高级别问题）。不要自行放宽。

加 `--json` 可拿到结构化结果，便于程序化处理。

## 五、模式 C：文风净化与校对

```bash
python scripts/style_clean.py --input draft.md --output draft_clean.md --report 文风报告.md
```

处理逻辑分两档，这是本模式的核心设计：

- **REPLACE（直接替换）**：高置信度、语义不会走样的问题。网络用语（给力→有力、点赞→肯定、吐槽→反映）、口语（咱们→我们、搞好→做好）、AI 腔（「在当今社会」「值得注意的是」「让我们」「总的来说」等直接删除或降格）、常见错别字（其它→其他、截止→截至、法人代表→法定代表人、帐目→账目、按步就班→按部就班、再接再励→再接再厉）、公文体例（成文日期虚位 `2026年08月06日`→`2026年8月6日`、发文字号 `[2026]12号`→`〔2026〕12号`、附件说明去尾标点）、半角标点转全角、emoji 清除。
- **FLAG（仅标记不改）**：改了可能失真的地方。滥用的抽象词（赋能、闭环、抓手）、主观表述（我觉得、我认为）、模糊表述（尽快、大概、有关部门）。这些**只写进报告，原文不动**，由人决定。

向用户交付时，务必把 FLAG 清单单独列出来请其确认，不要替用户拍板。

### FLAG 批量确认话术

当净化报告出现 FLAG 项（如"赋能、闭环、抓手、我觉得"），不要悄悄改掉，也不要只丢一份报告了事——把决定权交回用户：

> 文风净化发现 N 处建议人工确认的用法（**不改变原文**，仅供您定夺）：
> 1. "赋能基层治理" → 建议改为"提升基层治理效能"（[替换] / [保留]）
> 2. "形成闭环" → 建议改为"健全工作闭环机制"（[替换] / [保留]）
> 3. "我觉得应按…" → 建议改为"经研究，拟按…"（[替换] / [保留]）
> …
> 回复"全替换"我立即批量改写；回复"保留 X、Y"则原样保留，其余替换。

其它参数：`--dry-run` 只出报告不改文件；`--keep-markdown` 保留 `#` 等标记以便后续交排版脚本识别层级（**串联使用时建议加上**）；`--no-punct` 跳过标点规范化。

## 六、串联工作流（推荐）

用户丢来一篇脏草稿要「正式文件」时：

```bash
# 1. 净化文风，保留 Markdown 层级标记
python scripts/style_clean.py --input draft.md --output clean.md --report 文风报告.md --keep-markdown

# 2. 国标排版
python scripts/gongwen_format.py --config my.json --input clean.md --output 正式文件.docx

# 3. 合规质检
python scripts/gongwen_check.py --input 正式文件.docx --report 质检报告.md
```

三份产物一起交付：`正式文件.docx` + `文风报告.md` + `质检报告.md`。

## 七、交付时说什么

给用户的回复里要包含：

1. 产出文件路径。
2. 质检结论（合规 / 不通过 + 高中低各几项）。
3. **字体实际映射**——如果本机缺方正小标宋等国标字体发生了回退，必须明说，并提示在装有对应字体的机器上重新生成或加 `--strict-font`。
4. 文风净化的 FLAG 待确认项。
5. 需要人工补的要素（如份号、密级、印章图片）。

### 模拟执行反馈模板

用户看不到命令行黑盒，但要知道"在跑什么、跑完了没"。处理过程中给一句短反馈，处理完给一句结论，中间不刷进度、不贴命令：

- **串联开始**：「正在为您进行【文风净化 → 国标排版 → 合规质检】串联处理…」
- **完成**：「🟢 已完成。产出：①`正式文件.docx`（GB/T 9704-2012 合规）；②`文风报告.md`；③`质检报告.md`。质检结论：合规（高 0 / 中 1 / 低 2）。」

若本机缺字体发生回退，把字体实际映射合并进这句结论（见第 3 条要求）。若有 FLAG 待确认项，附一句：「另发现 N 处文风建议确认项，见文风报告，回复'全替换'即可批量处理。」

## 八、边界

- 只管**格式与文风**，不代拟公文内容、不判断行文关系是否恰当、不核实事实与数据。
- 印章默认只留位置，不合成电子印章图像；`--seal-image` 仅做图片嵌入。
- 国标条款以正式发布文本为准，本技能参数表见 `references/gb9704-2012.md`。遇到与本单位现行发文格式规定冲突的，以用户单位规定为准并提示差异。
- **本地处理声明**：本技能为纯本地运行，不发起任何联网请求、不调用外部 API、不上传文件。所有排版、质检、净化均在用户本机完成，仅处理用户主动提供的文件，不读取其他目录。可离线使用。
- 常见问题见 `references/faq.md`。

## 九、结构化预览（无执行能力时的兜底）

当运行环境无法生成 `.docx`（无 python-docx、无代码执行权限），按"交互铁律"第 2 条，用 Markdown 渲染一份**红头预览**，让用户肉眼核对层级、要素、字体映射是否合理。这**不是成品**，是给用户的"校对稿"——必须明确告诉用户："以上是预览稿，不是 Word 成品，正式版请按模式 A 用脚本导出。"

预览写法对照：

| 公文要素 | Markdown 写法 | 模拟字体 |
|---|---|---|
| 发文机关标志（红头） | `>` 引用块 + **加粗**，支持红色时标红 | 方正小标宋/宋体，红色 |
| 发文字号 | 居中一行，引用块内 | 仿宋，红色 |
| 公文标题 | `### **标题**` | 2号小标宋 |
| 一级标题 `一、` | `### **一、xxx**` | 黑体 |
| 二级标题 `（一）` | `**（一）xxx**` | 楷体 |
| 三级标题 `1.` | `1. xxx` | 仿宋 |
| 正文 | 普通段落 | 仿宋 3号 |
| 版记 | `>` 引用块模拟 | 4号宋体 |

红头预览示例：

```
> ### **××市人民政府文件**
> ×政发〔2026〕12号

### **××市人民政府关于进一步加强城市排水防涝工作的通知**

各区县人民政府，市政府各部门、各直属机构：

一、提高思想认识
（一）压实属地责任
1. 建立易涝点位台账
……

（此件公开发布）
> 抄送：市委办公室，市人大常委会办公室
```

预览仅用于要素与层级核对，正式版务必按第七、八节用脚本导出为标准 Word。
