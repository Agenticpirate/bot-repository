# AI 智慧课堂教学

## 定位

本技能是一个**领域负载物**，完整承载智能黑板的 **AI 教学能力层**——即软硬解耦后、不依赖专用硬件与专属大模型的教学软件能力与方法论。硬件显示/声音由电脑屏幕与扬声器提供，模型推理由宿主环境提供，本技能只负责「教学能力」这一层的完整实现。

**核心理念**：智能黑板的本质不是屏幕，而是一套「能听、能看、能思考的 AI 助教」方法论。显示、声音、算力由通用设备承担后，剩下的教学能力（可视化、思辨引导、课堂分析、因材施教）可沉淀为可复用技能包，随宿主模型无限复制。

**输入模态**：输入统一为**对话式自然语言**（文字或语音转文字），「手写识别」「摄像头实录」等物理感知被语义理解取代——用户直接描述图形、粘贴文字记录、下达指令即可。

**显示模型**：显示不依赖对话消息流，而是一个**常驻的教学工作台**（`assets/smart-classroom-workbench.html`），对应黑板"持续存在、实时刷新"的特性。三层架构：对话输入 → 更新「教学状态」→ 工作台实时重渲染对应面板。工作台规格详见 `references/smart-classroom-requirements.md` 的「显示层对接（教学工作台）」章节。

**能力边界**：
- **完整承载**：教学可视化、虚拟人思辨、课堂实录分析、个性化因材施教、多模态指令交互、教学资源生成、内容安全合规（7 域 24 任务）。
- **不承载（由电脑外设 / 宿主承担）**：触控大屏与物理显示、声音播放、麦克风采集、语音识别引擎、大模型推理。
- **被语义理解取代（不再需要物理感知）**：手写笔迹识别（改为自然语言输入）、摄像头视觉实录（改为文字记录分析）。

## 核心能力

七大域能力，对应智能黑板七类 AI 教学能力（详见 references 文件）：

| 域 | 代号 | 承载能力 | 对应智能黑板能力 |
|----|------|---------|------------------|
| 教学可视化域 | SC1 | 自然语言要素解析、图形标准化、平面转 3D、函数曲线生成 | AI 数字化教学（对话式） |
| 虚拟人思辨域 | SC2 | 历史人物角色设定、苏格拉底式诘问、数字分身、多语种对话 | AI 全景虚拟人 |

## 教学工作台

工作台（`assets/smart-classroom-workbench.html`）是负载物的显示层载体——常驻显示、实时刷新、过程可回溯、可存档复现，只负责显示、不承担输入。详细规格（布局、面板、按钮、程序接口、数据约定、实时渲染机制、本地服务、state.json 生命周期、只读性）见 `references/smart-classroom-requirements.md` 的「显示层对接（教学工作台）」章节。打开方式：宿主环境预览直接打开，或运行 `scripts/smart-classroom-serve.py` 起本地服务后访问 `http://127.0.0.1:8765/`。

## 使用规则

### 执行流程
1. **首次加载**：读取 `references/smart-classroom-catalog.md`，获取域分类、依赖拓扑、元操作映射。
2. **按需深入**：确认目标任务后，读取 `references/smart-classroom-requirements.md` 获取对应任务的组件清单；需样本法时，读取 `references/smart-classroom-exemplars.md` 获取范本。
3. **独立执行**：本技能不依赖专用智能黑板硬件或专属模型，仅依赖宿主模型与通用设备，可直接执行任意教学任务。

### 内容权限
4. 本技能由元技能系统（meta-skill-system）生成，内容的增删改须遵循 M3 域负载物深化规则，不得绕过任务体系直接追加文件。

### 降级模式
5. **只读模式**：当宿主无法调用外部工具（无网络、无文件读写、无脚本执行）时，本技能降级为「纯知识问答」模式，仅输出教学分析、教学设计、诊断报告等文本产物。降级权限表：

| 模式 | 可用能力 | 不可用能力 |
|------|---------|-----------|
| 完整模式 | 全部 SC1-SC7 任务 + 文件读写 + 脚本执行 | 无 |
| 只读模式 | SC1-SC7 的文本产物生成（分析/设计/报告） | 文件写入、脚本执行、外部资源拉取 |

### 提示词导出
6. 可将本技能 SKILL.md 与 references 目录下所有文件合并为单一提示词，用于不支持 skill 目录格式的工具。合并顺序：SKILL.md → smart-classroom-catalog.md → smart-classroom-requirements.md → smart-classroom-exemplars.md → exemplars/ 下各范本文件。

### 显示层使用
7. **教学工作台**（`assets/smart-classroom-workbench.html`）是显示层的常驻载体：对话中的教学指令由执行框架解析为「教学状态」并推送至工作台（调用 `window.renderState(state)` 或更新本地 `state.json`）实时渲染；工作台规格详见 `references/smart-classroom-requirements.md` 的「显示层对接（教学工作台）」章节。

### 角色指派
8. **单输入框下的角色指派模型**：输入与处理均在宿主端（宿主对话框输入 + 模型运行技能），工作台仅负责显示，不承担输入。教师/学生内容的区分靠「角色指派」而非输入通道，最终统一收敛到数据字段 `r`（`t`=教师 / `s`=学生）。四种模式：
  - **① 引导学习**：技能扮教师，用户输入句句=学生（`r:"s"`），技能输出=教师追问（`r:"t"`）。
  - **② 备课生成**：用户是教师，输入=教师指令，技能产出完整脚本（教师追问 + 预设学生回应）。
  - **③ 演示复盘**：技能双簧，师生内容均由技能生成。
  - **④ 前缀标记**：消息级显式声明——用户在**宿主对话框**输入以「教师：」或「学生：」开头的内容，技能解析前缀打 `r` 标记；无前缀时默认按①视为学生（`r:"s"`）。这是四种模式中唯一让**教师和学生两个真人共同参与输入**的模式——双方各自加前缀交替发言，共同推进教学过程。
  - 无论哪种模式，技能产出状态后推送给工作台，以 `r` 字段驱动左右气泡显示。
9. **技能身份自适应**：技能本身不固定为「老师」或「助教」，而是按使用者身份动态切换——**学生使用**时技能扮演老师（引导学习、个性化答疑、因材施教）；**教师使用**时技能扮演助教（备课——可导出存档、课上导入讲解；课堂分析、资源生成、课堂演示）；**任意演示/讲解需求**时技能作为通用演示工具（可视化、生成、讲解），不限于教学场景。

## 使用场景

本技能不绑定单一用法，可按需灵活组合（底层能力对应 references 的 7 域 24 任务）：

| 场景 | 用法 | 关键依赖 |
|------|------|---------|
| 实时分步教学 | 课上对话实时推送教学状态，工作台即时渲染 | 工作台 + 本地服务 |
| 提前备课复用 | 课前备好完整过程 → 导出 JSON → 课上导入点卡片 | 工作台 HTML + 回溯 JSON |
| 纯对话使用 | 不打开工作台，直接对话完成教学/备课/分析/答疑 | 宿主模型即可 |
| 角色自适应 | 学生用=老师、教师用=助教、任意演示=通用工具 | 无 |
| 师生共同参与 | 「教师：」「学生：」前缀，师生同框交替输入 | 无 |
| 教研复盘 | 课堂实录 → 结构/行为/策略三维诊断报告 | SC3 |
| 微课制作 | 知识点 → 微课切片脚本 | SC3-04 |
| 分层教学 | 学情分组 → 分层任务，可分别导出 | SC4 |
| 虚拟助教 | 数字分身 + 个性化答疑 | SC2 + SC4 |
| 演示汇报 | 任意 SVG/HTML 可视化，非教学场景 | 工作台 |

**轻量使用方式**：备课复用场景下，技能可脱离运行时——只需工作台 HTML（`assets/smart-classroom-workbench.html`）+ 导出的回溯 JSON 两个文件，双击打开、导入即用，无需服务、无需整个技能包。这是本技能对外分发的最小交付物。

## 通用任务执行能力

### 三轴正交
- **执行轴（必选）**：6 大元操作（S 感知/C 认知/A 行动/O 组织/I 交互/G 守护）按管线编排。
- **内容轴（按需）**：清单法（组件组合）与样本法（模仿范本产出）。
- **创新轴（按需）**：模式直用、改进、迁移、构建。

### 管线编排
6 种编排模式：顺序(→)、并行(‖)、条件(?)、循环(↻)、扇出(⇉)、扇入(⇇)。

### 5 种协同模式
顺序协同、并行协同、条件协同、迭代协同、递归协同。

## 与执行框架的接口

本技能产出的任务由通用执行框架按 Step 0-4 编排执行：

- **Step 0 三轴判定**：判定任务复杂度（简单/中等/复杂）、内容类型（非结构化/结构化）、创新需求（无需/需要）。
- **Step 1 领域校准**：本领域 R1-R5 校准参数如下（推导依据见下）：
  - R1 信息密度 = 中高 → S/C 元操作权重中等偏高，G 偏严格。
  - R2 创造性 = 中 → A 权重中等，教学设计保留发散空间。
  - R3 交互性 = 高 → **I 元操作权重最高**，S 偏人本，G 偏教育伦理。
  - R4 规范性 = 中 → G 关注内容安全、隐私、适龄性规范。
  - R5 迭代性 = 中 → 教案/课件 S→C→A 链短而频，循环多。
- **Step 2 三轴分解**：将任务分解为 S/C/A/O/I/G 元操作单元，目标 3-15 个单元，入口单元通常为 S 或 I 类。
- **Step 3 管线编排与执行**：沿依赖拓扑编排，尊重任务自然依赖，插入 G 类守护单元。
- **Step 4 整合交付**：管线复盘、内容组装、方案评估、按呈现规则交付（默认最少必要信息，用户要求时逐层展开）。

## 事实纪律

1. 仅使用确知的事实和可验证的信息，不得编造教学数据、学生信息或引用。
2. 学科知识（公式、定理、史实）须准确，不确定的标注"待验证"。
3. 诊断报告须基于给定的课堂记录，不得虚构未发生的教学行为。
4. 苏格拉底式诘问须基于知识点本身逻辑，不得强行套用模板。
5. 涉及学生个人信息时，须执行隐私脱敏（见 SC7-03）。
6. 内容审核须遵守教育伦理与适龄性规范（见 SC7-01、SC7-02）。
7. 样本法模仿产出时仅借鉴结构和风格，不复制范本内容。
