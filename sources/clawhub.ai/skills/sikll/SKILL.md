# 佛学讲评助手 v2.26.0（通用版 · 跨平台固化）

> 配套引擎：`佛学讲评/build_v2.20.py`（主引擎，读取 `analysis/*.packet.json` 与 `scores/*.json`，输出 `reports_v2.20/` 下 HTML 报告 + `_汇总.html`）。当前技能规范版本 v2.25.0。
> 本文件是 **自包含技能说明**，可直接作为技能描述投到 IMA 或其他大模型平台使用。

---

## 0. 定位与通用性声明

- 本 skill 是**通用佛学讲说质量评测工具**，不绑定任何个人或机构；一切"指定/个性化"类表述均已清除，仅保留客观判定规则。
- 评估架构为**双轨**：讲说风格轴 + 内容分类轴；不设级别判定、不分九宫格、不输出 Markdown。
- 输出为**内联 CSS 的单文件 HTML**，配色与版式已锁定（见 §9），在 WorkBuddy / IMA / 其他大模型平台渲染效果一致，不随平台或所换大模型而漂移。
- 繁体内容统一经 `OpenCC('t2s')` 转简体后再进入全部计算与比对。

---

## 1. 触发与输入

- **触发**：用户上传佛教相关讲说/复讲/授课/演讲/讲座录音或视频，要求评测、评分、分析、评价、打分。
- **不触发**：非佛教内容的一般演讲评测；纯文本校对；音视频转写（仅中间步骤）。
- **唯一合法输入**：音频（mp3/wav/m4a/aac…）或视频（mp4/mov/avi…）。
- **不接受**：纯文字稿、第三方预转写文档、PPT、讲义——即使一并提供也忽略，自行从音频转写（预转写稿会清洗掉停顿/重复/填充词/语速等关键特征，导致评分失真）。可注明"已收到参考文字稿，但本评测以自转写结果为准"。

### 1.1 转写（必须带时间戳）

所有转写引擎**必须输出带时间戳的文本**（词级或句级），否则依赖时序的特征（F2/F4/F5 等）无法计算，此时中止音频维度分析，不得在无时间戳情况下评分。

| 运行平台 | 推荐引擎 | 费用 | 时间戳 | 中文能力 |
|---------|---------|------|--------|---------|
| **WorkBuddy / 本地（主路径）** | faster-whisper | 免费（MIT） | ✅ 词级 | ✅ 多语言，CPU 可跑（int8） |
| **IMA 平台（备选）** | IMA 内置「录音纪要 / 转录」或沙箱 faster-whisper | 免费 | ✅ 句/词级 | ✅ 腾讯云 ASR |

本机一键跑通（已实测）：
```bash
pip install -i https://pypi.tuna.tsinghua.edu.cn/simple faster-whisper soundfile
export HF_ENDPOINT=https://hf-mirror.com        # CN 环境模型走镜像
python transcribe.py <音频文件> small <输出.json>  # small≈460MB，首次自动下载，之后缓存
```
- 无 GPU 也可用（`compute_type="int8"`）；中文用 `small` 起，术语密集可换 `medium`。
- 完全离线/免网络部署：把 faster-whisper 依赖装进本 Skill 的 `.deps` 随 Skill 分发。

### 1.2 大文件 / 非常规格式预处理（ffmpeg）

| 场景 | 处理 | 命令要点 |
|------|------|---------|
| 文件过大（IMA 上传上限约 200MB） | 压成 16kHz 单声道 64kbps MP3 | `ffmpeg -i in.wav -ar 16000 -ac 1 -b:a 64k out.mp3` |
| 视频文件（mp4/mov/avi） | 抽取音频再压 | `ffmpeg -i in.mp4 -ar 16000 -ac 1 -b:a 64k out.mp3` |
| 高码率 WAV（48k 立体声 24bit） | 同上压缩 | 50min 原 ~830MB → 压后 ~23–33MB |

- 体积参考：16kHz 单声道 64kbps 下，50 分钟 ≈ 23–33MB、110 分钟 ≈ 50MB，语音识别清晰度足够。
- WorkBuddy 本地无上传限制；IMA 端若文件 >200MB 必须先压成 MP3 再上传。

## 2. 工程链路概览

```
音频/视频
  → 转写（带时间戳，繁体经 OpenCC t2s 转简体）
  → 特征包 build_packets（F1–F7 + 名相密度 + 叙事/实践信号 + 问答 + 术语/祖师/经论…）
  → 六维打分 gen_scores（D1–D6 + 附加，保留人工修正接口；含来源核验、结构大纲、状态观察、亮点/待改进/建议）
  → build_v2.20.py（双轨评估 + 综合评定 + 总分 + 自动标题 + 渲染 HTML）
  → reports_v2.20/*.html + _汇总.html
```

`build_v2.20.py` 只做**判定与渲染**：读取 `analysis/*.packet.json` 与 `scores/*.json`（按文件名对齐），输出单文件 HTML。上游转写/特征提取/六维打分沿用既定流程。

## 3. 双轨评估架构

### 3.1 讲说风格轴（单一轴，暖红 ⇄ 冷蓝）

合并原「讲说风格」与「讲述方式」规则，落为单一连续轴：

- 左端 `pos=0` = **通俗开示型**（暖色/红）
- 中段 `pos=5` = **平衡型**（中间橙黄）
- 右端 `pos=10` = **学院专业型**（冷色/蓝）

**档位标签（定名，不再沿用"偏学院""偏通俗"旧称）：**

```
pos ≥ 7.0     学院专业型
pos ≥ 5.5     专业兼通俗型
pos ≥ 4.0     平衡型
pos ≥ 2.5     通俗兼专业型
else          通俗开示型
```

**判定核心：以"是否依着原文/课本讲说"为主。**

- **学院信号**（`academy_raw`，权重 35/25/20/10/10）：
  - 段落级"类原文"检测 `verbatim_score`（长连贯句占比最高权）——**最核心判据**；
  - 学院化结构信号密度 `acad_per_k`（科判/注疏/论师/宗派名相）；
  - 经论顺序性 `seq_score`（主经锚定/引用跨度/主导率/章节递进）；
  - 课堂仪式 `ritual_score`（开经偈/回向/翻到/PPT/下课/打铃/敲钟/问答）；
  - 名相密度辅助 `term_density`。
- **通俗信号**（`casual_raw`，权重 30/30/20/20）：
  - 大众化通达信号 `pop_per_k`（公案/故事/家常）；
  - 灵活性 `flexibility`（互动密度 + 叙事/实践信号 + F7 口语化）；
  - 严格口语填充词 `filler_per_k`（排除"然后/就是/这个"等正式讲经也用的连接词）；
  - 短时长因子（<50 分钟偏向通俗）。
- 计算：`net = academy_raw − casual_raw`；`pos = clip(5.0 + tanh(net·1.5)·1.15·5.0, 0.3, 9.7)`。
- 要素 1（经论原文大段依止 + 消文解义 + 宗派名相）+ 要素 2（>40min 课堂式连续讲说）叠加 ⇒ 高概率判学院专业型。
- 平衡型加分：互动/口语/比喻/体悟/多媒体等**多维度同时显著**才明显拉向中间；单一灵活因素**不应**把类型拉向平衡区。

### 3.2 内容分类轴（教义 / 叙事 / 实践 三维）

- 三维得分：教义教理 `a`、叙事陈述 `b`、实践修证 `c`（均由名相密度、叙事信号、实践信号归一化到 0–10）。
- 主类判定：最高维 ≥ 3.0 且第二维 < 主类 × 0.5 → 单类；第二维 ≥ 主类 × 0.5 → 混合类（"主类/次类"）。
- **类型标签（统一称"实践"，不再使用"实证/实证行修"等旧名）：**

  | 标签 | 含义 |
  |------|------|
  | 教义教理类 | 以经论原文、名相、教理辨析为主 |
  | 叙事陈述类 | 以公案、故事、人物、事件叙述为主 |
  | 实践修证类 | 以止观、禅修、实修操作、心性体认为主 |
  | 教义/叙事类、教义/实践类、叙事/教义类、叙事/实践类、实践/教义类、实践/叙事类 | 混合类型（按主导维度组合命名） |

## 4. 综合评定（多段落口语化综合判断）

由 `style_rationale_v20(mode_str, details, pkt, sc, auto_title)` 生成，是报告「二、双轨评估」下的核心文字段落。原则：

- **主题判定优先 `auto_title`**（自动标题基于开场信号 + 全文分析生成），`seq_info.dominant`（经论词频最高者）仅作交叉验证——两者不一致时分别表述（主题 + "内容中称引较多的经论包括《X》"），避免"心经高频引用"覆盖正文主经《增一阿含》这类错判。
- 覆盖**五个维度**，分 2–3 个自然段（每段内用句号/逗号完整标点）：
  1. 主题 + 场合：时长定位（长时段系统讲授/完整一节课/专题开示或节选/限时发言）+ 开场信号（课程回顾/比赛演讲/学术研讨）+ 课堂仪式痕迹；
  2. 风格 + 内容：讲说风格档位依据（学院/专业兼通俗/平衡/通俗兼专业/通俗）+ 原文依止度 + 内容类型依据（名相密度/叙事比例/实践成分）；
  3. 质量观察：语速（快/适中/偏慢）+ 节奏均匀度 + 问答互动标记。
- **隐藏具体数字与频率**：不列出"每千字 X 处""称引 N 次"等量化数据；时长以"约 N 分钟"通俗带过。
- **禁止定式句**：不得套用"未见系统的学院讲授框架"等固定表述——每句按实际数据动态生成。
- **去除尾注**：不再附"注：讲说风格仅描述讲述路数，不等于评分高低……"这类说明。
- 来源依止判定已并入本段（见 §5），不单独成模块，避免与双轨判定重复。

## 5. 来源比对（独立板块「六、」+ 综合评定互补）

报告「六、来源比对」独立展示 L0 大藏经核验 + L1 天台藏核验 + 关键断言核验列表；不重复渲染"综合来源判定"白框（其结论语已并入「综合评定」一段，避免双重呈现）。

- 报告"六、来源比对"内容（按序）：
- **L0 大藏经核验**：经论文本引用是否与 CBETA2026 简体版一致；命中 CBETA 出处者附**路径式行级深链** `https://cbetaonline.dila.edu.tw/zh/{linehead}`（例 `https://cbetaonline.dila.edu.tw/zh/T46n1939_p0938c04`），仅卷/页级者用卷级备用链 `https://cbetaonline.dila.edu.tw/zh/{work_id}_{juan}`。
- **L1 天台藏核验**：天台宗祖典（智者大师/蕅益等）原文对应；天台藏文献底本与 CBETA 2026.R1 同源，凡能对应 CBETA 经号/页栏行者同样附行级深链。
- **关键断言核验**：依经论原文 / 祖师原话 / 名相定义逐条列出的引用条目，可定位者附行级深链。
- 综合评定只接收"依何经论 / 是否课堂 / 是否比赛 / 是否自编辑"的结论语（多段落口语化），与"六、来源比对"形成"详细核验列表 + 概括判定"互补结构。
- 上游知识库底座（六维打分阶段使用）：L0 大藏经CBETA2026简体版、L1 天台藏全集2026（均为 IMA 平台公共订阅知识库），核验结论写入 scores 的 `source` 字段。

**抽样灵活化 `sample_paragraphs()`：**

- 样本量按时长动态调节：≤20min→8 段、≤60min→12、≤120min→18、>120min→24；长录音抽得更多、更细。
- 开头约 15% 区域**过采样**，结尾约 5% **必取**；优先抽取"自我介绍 / 课程衔接 / 上节课回顾 / 为何讲此题"等开场段落——这些信息最能定位音频的性质、来源、场合与主讲人。
- 多主讲人场景（比赛/研讨）：先定位**主讲人**并优先抽取其开场，以提升自动标题精度。
- 课堂仪式检测 `detect_classroom_rituals()`：课前（开经偈/三皈依）、课中（翻到/PPT/课本）、课后（回向/下课/打铃/敲钟）、问答（老师好/讲师好）。

## 6. 六维评分与评分档

- **六维**：D1 教义准确度 / D2 结构与逻辑 / D3 语言表达 / D4 契机与应变 / D5 感悟与感染力 / D6 自主发挥度（另有「附加」项）。
- **权重**：按内容类型选择权重表（A/B/C 型对应不同 D 维侧重），再乘讲说风格加权 `style_adj(pos)`（学院/平衡/通俗三档，对 D4/D5/D6 适当调整）。
- **总分**：`norm_total = Σ(各维得分 × 风格加权) / Σ(卡权重 × 风格加权) × 10`。
- **评分档（必须严格沿用）：**

  | 总分 | 等级 |
  |------|------|
  | ≥ 8.0 | 优秀 |
  | 6.0 – 8.0 | 良好 |
  | 5.0 – 6.0 | 及格 |
  | < 5.0 | 待及格 |

- 六维评语基于各维 `d_scores` 自动补全薄弱项，去重并各上限 5 条；不与「综合评定 / 亮点待改进」重复。
- **读稿/念稿压分**：大段连续书面长句 + 零自问零比喻零互动 + 语速极均匀 + 填充词极少 → D4/D5/D6 重扣；生疏/紧张（高填充词 + 高重复 + 停顿多 + 语速不稳）→ 下调。
- **讲述性质识别（内容特征驱动，告别"回向即共修"误判）**：评分前**必读 `analysis/名称.packet.json` 的 `nature` / `recitation_signature` / `nature_show_badge` 字段**（由 `build_packets.py` 自动判定，无需自行重扫）。
  - **是否启用复讲量表只看内容特征 `recitation_signature`（0–1）**：`≥0.6` 即判定为"依文念诵＋白话释义"的复述还原型 → 启用 **复讲/副讲独立量表**（`score_recite_native()`），**不再与有经验讲者的原创讲授同尺合并**（否则所有复讲皆不及格，不合理）。该判定**不依赖任何标签、不依赖结尾回向/合掌/南无**（公开讲法常态，绝不能当信号）。
  - **复讲/副讲独立量表**：复讲评估的"成就" = 忠实还原度 + 科判完整度 + 释义清晰度 + 表达沉稳度 + 准备完整度，而非原创义理发挥 / 证悟感染。六维在两套标尺下含义不同：
    - **D6 重定义为「会通/小结能力」**（复讲内部的【加分轴】）：纯依文串讲、无自设小结/对照/举例 → 复读基线（低分）；在念原话后加一处设问、对照表或生活化举例 → 显著加分。这是**复讲之间评分高低的关键分化点**。
    - **D5 重定义为「表达沉稳度」**（复讲内部的表达质感）：不再是"由证悟而发的感染"，故不因"非证悟感染"扣分。
    - **D1/D2/D3/附加** 在两类标尺下含义一致（忠实度 / 结构 / 清晰 / 完整），复讲者忠实还原原典即拿高分。
  - **复讲内部高低分化细节**。在原有加分/减分项基础上，**把「卡顿频率、前后句重复密度、语言组织与复述流畅度」作为独立观察维度**：
    - 卡顿/填充词频率高、前后句重复密度大、长停顿多 → 判定为"对文本尚不熟/思维转表达迟疑"，在 D3（释义清晰度）、D5（表达沉稳度）中明确扣分，并用"语言组织与复述流畅度不足"等人话表述。
    - 语速沉稳、无明显卡壳、重复率低 → 复讲表达质感加分。
  - **复讲独立标尺档位**：复讲·优秀(7–8) / 复讲·良好(6–7) / 复讲·及格(5–6) / 复讲·待提升(<5)。**复讲在独立标尺上可达"复讲·优秀"**（流畅＋忠实＋清晰＋科判完整＋节奏稳＋至少一处会通），不再强制降档。
  - **加分项 / 减分项（复讲内部差异来源）**：
    - 加分：准确实引经论、白话释义通俗、科判完整、系统串讲完整、一处小结/对照/设问呼应（会通）、语速沉稳节奏稳。
    - 减分：**卡顿/前后句重复密度大、语言组织不流畅**；零互动单向；对文不熟迟疑；缺会通小结（纯复读）；结构跳跃。
  - **"讲述性质判定"模块仅在有实锤字面时显示**（`nature_show_badge=True`）：①自陈复讲/复述（"我这次复讲""复讲完毕""我今天的复述就到这里"等；v2.25 增加模糊匹配，兼容 ASR 同音错字如"部署"/"富庶"）；②第三者总结＋回向/共修（如同辈说"师兄辛苦"＋"咱们就回向"）。前台只展示四项：**判定依据、加分项、减分项、本评分反映说明**；不展示"独立量表标尺"和"原创讲授口径参比"（二者为后台隐藏规则）。无实锤字面则不显示该模块，但后台仍按特征改用复讲量表（避免误判正常讲法，也避免漏判只录中段的复讲）。
  - **后台增强**：`build_packets.py` 额外提取开场/结尾文本与仪式信号（`opening_text` / `closing_text` / `ritual_signals`），细粒度检测无书名号的经论引用（`quoted_sutras_detail`），并计算卡顿/填充词复合指标（`hesitation_score`），帮助更准确地判定场景、所依原典与复讲者语言熟练度。
  - 关键分辨：**"用自己的话复述原典"≠"自主发挥"**。D6 衡量义理原创度，不是语言重组度——依文串讲、念原话＋白话释义、第三者总结收尾、回向文、共修场景，均指向副讲复讲，在复讲标尺下 D6 表现为"会通能力"而非"原创度"。
  - 正常公开讲法（仅末尾回向/南无/合掌，无第三者收尾、无自述复讲、特征不显著）→ `nature=原创讲授`，不受影响，分数不降。
- **ASR 错字不入分**：名相识别错误结合上下文还原，绝不扣分。

## 10. 质量护栏（跨平台必须一致，不得漂移）

1. **时间戳铁律**：转写必须带时间戳；无时间戳时中止音频维度分析（F2/F4/F5），不得评分。
2. **中文字符计**：语速/字数按中文字符计，绝不按英文空格分词；填充词匹配中文填充词表；停顿按相邻句/词时间戳间隔 >1.5s 计数。
3. **全简体**：所有文本读取即经 `OpenCC('t2s')` 转简体，杜绝繁体残留。
4. **ASR 术语还原**：套用「佛教术语还原对照表」校正专有名词错字（如"开示悟入佛之知见"误为"开师误入佛之之简"），还原后再进入计算；ASR 错字绝不入分。
5. **读稿检测**：低填充词 + 极均匀 + 高书面语 + 低重复 → 读稿/念稿（D6 重扣）；须结合 F6 区分"读稿"与"熟背复述"（后者属正面）。
6. **工具克制**：音频维度核心已由"faster-whisper 时间戳 + 自写中文 F1–F7"覆盖；增强工具（opensmile 等）一律可选，不装不影响评分。
7. **客观公平**：不以讲者身份（学员/授课者/出家众/在家众/年龄/资历）为标准；同一套规则、同一把尺子。
8. **自检**：报告输出前逐项确认——仅用自转写、双轨判定有据、断言经 L0/L1 核验、建议具体可操作、无技术标签/术语。

## 11. 使用方式

- **本机（WorkBuddy / 本地）**：准备 `analysis/*.packet.json` 与 `scores/*.json` 后运行
  ```bash
  python build_v2.20.py
  ```
  输出至 `reports_v2.20/`（单场 HTML + `_汇总.html`）。
- **IMA / 其他大模型平台**：按本文件 §3–§9 规则，由平台 LLM 直接生成符合「配色与格式固化规范」的单文件 HTML 报告；繁体内容统一转简体后再比对经论。

### 11.1 闭环执行（WorkBuddy 本地 · 自动弹出报告）

长音频转写耗时与音频时长成正比，必须以**后台任务**方式启动，避免阻塞对话；完成后由平台自动回呼，agent 接力渲染，全程无需用户追问。

1. 转写必须用后台任务（`run_in_background`）启动：`python transcribe.py <音频> small <transcripts/名称.json>`；模型权重走 HF 缓存，首次下载后零网络等待。
2. 转写完成的 `<task-notification>` 会重新进入 agent 循环——**收到通知即自动接力**，依次执行：
   `build_packets.py`（生成 `analysis/*.packet.json` + `.txt`）→ 读取全文与 packet 做六维评分与 L0/L1 核验（写出 `scores/名称.json`）→ `build_v2.20.py`（渲染 `reports_v2.20/名称.html`）→ `present_files` 弹出报告。
3. 用户**无需任何追问或二次触发**；若会话在转写完成前被关闭，则回呼不会触发，需重新发起（属运行时限制，非技能缺陷）。
4. 进度可通过 `TaskOutput(block=false)` 查看，但**不要轮询空等**——依赖后台回呼即可。
