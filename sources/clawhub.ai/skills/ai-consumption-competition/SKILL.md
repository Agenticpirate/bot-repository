# AI+消费创新大赛报名助手

## 触发条件

**调用本 Skill 当且仅当**以下任一条件为真：
- 用户明确提及"AI+消费创新大赛"、"人工智能+消费大赛"、"上海AI消费大赛"等赛事名称
- 用户表示要参加/报名上述大赛，需要选择赛道
- 用户请求帮助填写大赛报名表
- 用户提供项目信息，请求评估适合的参赛赛道

**不调用本 Skill 当：**
- 用户询问的是其他AI大赛（如WAIC路演、GOAI大赛等非本赛事）
- 用户只是泛泛讨论AI+消费话题，无参赛意图
- 用户请求生成商业计划书或PPT（即使用户同时提及大赛）

首届上海"人工智能＋消费"创新大赛（2026），落实国家"人工智能+"行动部署和商务部等八部门《关于加快"人工智能+消费"发展的实施意见》，聚焦AI与消费深度融合。作为西岸国际科技消费嘉年华（WTCC）核心专题活动，赛事主题为"AI赋能美好数智消费"。

## 核心工作流程（6步）

### Step 1：信息收集

向用户收集项目核心信息。**必收集8项 + 选收集6项**：

**必收集：**
1. 项目名称（或暂定名）
2. 项目一句话描述（做什么、给谁用）
3. 核心AI技术（大模型/CV/NLP/推荐算法/机器人控制/其他）
4. 目标用户群体
5. 当前阶段（创意/原型/试商用/规模化商用）
6. 是否已有商业化数据（用户数/营收/客户数）
7. 团队构成（企业/高校/创业团队/个人，人数，核心能力）
8. 是否面向6-18岁青少年

**选收集（用于深度分析）：**
9. 竞品或类似产品
10. 核心差异化优势
11. 目标市场规模估计
12. 已有知识产权（专利/软著/商标）
13. 数据合规情况
14. 是否涉及联合申报

可使用结构化提问或对话方式收集，不要求一次性全部获得。

### Step 2：第一性原理分析

从4个维度对用户项目进行解构：

**2.1 需求本质** — 解决的根本问题是什么？需求是否真实？AI的不可替代性在哪？
**2.2 技术本质** — AI技术栈构成（感知→认知→决策→执行），核心壁垒在哪层？技术成熟度？
**2.3 价值链定位** — 在消费价值链中的位置（生产→流通→营销→体验→服务→反馈），价值创造点？
**2.4 趋势对齐** — 是否符合国家"AI+消费"政策？是否符合上海产业布局？可复制性？

### Step 3：赛道匹配

> 📌 加载 `references/tracks-detail.md` 获取完整赛道明细

**3.1 一级赛道决策**（核心交付物判断）：
- 实体产品/硬件 → 赛道1：AI消费·新产品
- 服务/应用/解决方案 → 赛道2：AI消费·新场景
- 平台/模式/商业工具 → 赛道3：AI消费·新模式
- 青少年(6-18岁)创意作品 → 赛道4：AI新力量·青少年创客

**3.2 细分赛道评分**：对候选2-3个细分赛道按5维度评分（匹配度30% + 创新性20% + 竞争优势20% + 商业潜力15% + 政策契合15%）

**3.3 输出**：首选赛道 + 备选赛道 + 选择理由 + 风险提示

### Step 4：对抗式审查

> 📌 加载 `references/adversarial-review.md` 获取完整审查清单

模拟5种评审视角交叉质疑：
1. **技术专家** — 质疑技术壁垒和护城河
2. **商业评委** — 质疑商业可行性和付费意愿
3. **消费者** — 质疑用户体验和采用门槛
4. **合规审查** — 质疑数据安全和伦理风险
5. **产业专家** — 质疑行业理解和竞争窗口

**输出**：每个视角的关键质疑 + 风险等级 + 改进建议，汇总为致命/重要/一般三级风险表。

### Step 5：报名表填写指导

> 📌 加载 `references/form-guide.md` 获取逐字段填写指南

基于前4步分析，为用户提供逐字段填写建议，重点指导：
- 项目名称命名公式与示例
- 项目简介300字结构模板
- 技术创新点200字结构模板
- 商业化数据填写格式
- 数据合规说明要点
- 团队信息配置建议

### Step 6：最终检查

提交前逐项检查（12项 checklist）：
- [ ] 项目名称简洁且体现AI+消费特征
- [ ] 申报组别与项目阶段匹配
- [ ] 所属重点方向与推荐赛道一致
- [ ] 项目简介≤300字且逻辑完整
- [ ] 技术创新点≤200字且有量化指标
- [ ] 商业化数据已填（应用组）或标注选填（创客组）
- [ ] 数据合规说明已填（算法项目）
- [ ] 团队信息完整（负责人+≥2核心成员）
- [ ] 四项法律声明均勾选同意
- [ ] 附件材料已准备（至少商业计划书+演示材料）
- [ ] 文件命名为"组别＋项目名称"
- [ ] 对抗式审查致命风险已在材料中回应

## 特殊场景处理

| 场景 | 处理方式 |
|------|---------|
| 项目跨赛道 | 优先选核心交付物对应赛道，简介中提及跨赛道属性，主申报只选一个 |
| 青少年创客 | 切换赛道4评估框架，评审重点转向创意完整性和实践价值，对抗审查以鼓励性建议为主；提示赛道4独立报名、官方另行发布 |
| 联合申报 | 团队信息明确各方分工，知识产权声明说明联合开发权属，建议附联合申报协议 |
| 外资/海外团队 | 评估中国市场适配性，简介说明本土化策略，考虑"AI+消费企业全球化"赛道 |

## 反模式（Anti-Patterns）

以下行为会降低建议质量，执行时需避免：

| 反模式 | 说明 | 正确做法 |
|--------|------|---------|
| **跳过第一性原理直接选赛道** | 不分析需求本质就推荐赛道，导致匹配肤浅 | 必须完成Step 2分析后再进入Step 3 |
| **对抗式审查走过场** | 只提表面问题，不触及致命风险 | 每个视角至少提出1条"最尖锐"的质疑 |
| **填表建议过于笼统** | 只给模板不给具体内容 | 基于用户项目信息给出可直接使用的建议文本 |
| **忽视伦理风险** | 对情感陪伴/教育类项目不审查伦理问题 | 赛道1陪伴机器人、赛道2教育产品必须重点审查伦理 |
| **虚报商业化数据** | 建议用户夸大数据以提升竞争力 | 据实填写，数据不足时用替代指标（试点案例、满意度等） |
| **忽略组别匹配** | 原型阶段项目建议报应用组 | 严格匹配：已商用→应用组，原型→创客组 |
| **预读全部参考文件** | 一次性加载所有references文件 | 按Step进度按需加载对应文件 |
