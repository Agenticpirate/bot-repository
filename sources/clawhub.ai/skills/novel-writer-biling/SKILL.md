# Novel Writer Biling — 七阶段AI小说创作流水线

基于笔灵AI小说创作方法论，提供从灵感到定稿的完整长篇小说创作工作流。
纯prompt驱动，不依赖外部API，用当前模型的能力执行全部创作阶段。

## 核心理念

> 把创意变成长篇小说。将实现工作委派给AI，从配置、架构、蓝图到写稿与审稿，专注于更高层次的创作方向。

## 何时使用

- 用户要创作小说（长篇/短篇/连载）
- 用户需要搭建故事大纲或世界观
- 用户需要生成角色设定
- 用户卡文需要续写/扩写
- 用户需要对已有稿件进行审稿/润色
- 用户提到"写小说""网文创作""小说大纲"等关键词

## 七阶段创作流水线

严格按顺序执行。每个阶段产出物是下一阶段的输入。未完成前一阶段时不得跳到后一阶段（除非用户明确要求跳过或已有现成材料）。

---

### 阶段1：小说配置

**目标**：确定小说的核心元数据和基础定位。

**输入**：用户提供的基本创意或关键词。

**产出**：一份完整的小说配置文档，包含以下字段：

```yaml
小说配置:
  书名: （如有暂定名，否则标记"待定"）
  类型: （从下方类型库选择1-2个主类型）
  频道: 男频 / 女频 / 通用
  受众: 少年读者 / 青年读者 / 成年读者 / 全年龄
  叙事视角: 第一人称 / 第三人称有限 / 第三人称全知 / 多视角交替
  核心冲突: （一句话概括故事最根本的矛盾）
  核心卖点: （读者为什么要看这本书？1-3个卖点）
  目标字数: （短篇5万以下 / 中篇5-20万 / 长篇20万以上 / 超长篇百万字级）
  参考风格: （可选：列出2-3部风格相近的已有作品）
  平台定位: （起点 / 番茄 / 知乎盐选 / 晋江 / 通用）
```

**类型库**：

| 男频常用 | 女频常用 | 跨频通用 |
|---------|---------|---------|
| 玄幻·东方修仙 | 古言·宫斗宅斗 | 科幻·太空歌剧 |
| 奇幻·异世界 | 现言·都市甜宠 | 悬疑·推理探案 |
| 都市·异能觉醒 | 仙侠·师徒虐恋 | 历史·架空权谋 |
| 科幻·末世生存 | 幻想·穿书重生 | 恐怖·灵异惊悚 |
| 军事·战争 | 校园·青春成长 | 武侠·江湖侠义 |
| 游戏·无限流 | 悬疑·心理惊悚 | 现实·都市职场 |
| 系统·金手指 | 短剧·爽感反转 | 奇幻·西幻魔法 |

**执行规则**：
- 如果用户只给了模糊创意，主动提问补齐必要字段（类型、核心冲突、受众至少必须有）
- 不需要一次性填完所有字段，缺少的标记"待定"即可，后续阶段可补充
- 参考笔灵的"AI一键填充"思路：根据已有信息推断缺失字段

---

### 阶段2：故事架构

**目标**：构建完整的故事骨架——角色、世界观、主线剧情框架。

**输入**：阶段1的配置文档。

**产出**：

#### 2a. 世界观设定

```yaml
世界观:
  时代背景: （故事发生的时间与空间）
  核心规则: （这个世界最关键的1-3条运行法则）
  力量体系: （如有，描述等级/层级/代价/限制）
  社会结构: （主要势力/组织/阶级划分）
  关键地点: （故事主要发生的3-5个场景）
  禁忌与红线: （这个世界绝对不能做的事）
```

#### 2b. 角色档案

为每个核心角色建立档案卡片：

```yaml
角色: [角色名]
  身份: （表面身份 / 隐藏身份）
  外貌特征: （2-3个最具辨识度的特征，不写"很帅很美"）
  性格标签: （3-5个核心性格词）
  核心动机: （TA最想要什么？为什么？）
  致命弱点: （性格或能力上的致命缺陷）
  说话口癖: （TA特有的表达方式或口头禅）
  人际关系: （与其他核心角色的关系链）
  成长弧线: （起始状态 → 转变契机 → 最终状态）
```

**角色分类**：
- **主角**：1-2人，必须有完整的成长弧线
- **核心配角**：2-4人，与主角有深度互动
- **反派/对手**：1-2人，动机必须合理（不能为反而反）
- **功能角色**：可简略，1-2句话描述即可

#### 2c. 主线剧情框架

```yaml
主线剧情:
  起始事件: （打破日常的那个瞬间）
  第一转折: （25%处，主角被迫踏上旅程）
  中点翻转: （50%处，真相揭露或局势逆转）
  第二转折: （75%处，跌入谷底或失去一切）
  高潮决战: （90%处，最终对决）
  结局: （收束所有线索）
  
伏笔清单:
  - 伏笔1: [埋设章节] → [揭开章节] | 内容: ...
  - 伏笔2: ...

主题内核: （这个故事真正在说什么？一句话）
```

**执行规则**：
- 世界观和角色必须互相支撑——世界观决定角色的可能性，角色动机驱动世界观的展开
- 每个角色的动机必须与核心冲突有关联
- 伏笔至少规划3条，标注埋设和揭开的预估位置
- 如果是长篇（20万字+），主线按卷/部拆分，每卷有独立的起承转合

---

### 阶段3：章节蓝图

**目标**：逐章规划定位、冲突与悬念钩子，形成可执行的写作路线图。

**输入**：阶段2的故事架构。

**产出**：章节蓝图列表，每章包含：

```yaml
第X章: [章节标题]
  定位: （铺垫 / 推进 / 转折 / 高潮 / 过渡 / 收束）
  主视角: （以谁的视角展开）
  场景: （主要发生的地点）
  核心事件: （这章发生了什么？1-2句话）
  人物互动: （哪些角色登场/碰撞）
  情绪曲线: （开头情绪 → 结尾情绪，如：紧张→释然）
  悬念钩子: （章末留给读者的悬念或转折）
  字数预估: （2000-5000字/章，根据定位调整）
  伏笔操作: （埋设/推进/揭开 哪条伏笔）
```

**批量生成规则**：
- 一次可规划5-10章的蓝图
- 蓝图不是死的——写稿过程中允许微调，但核心事件和悬念钩子不能随意删除
- 每章必须有悬念钩子（网文"黄金法则"：章末必须让读者想翻下一章）
- 过渡章不超过总章数的20%，避免节奏拖沓
- 前3章（黄金三章）必须包含：1）吸引人的开篇冲突 2）主角核心设定展示 3）第一个悬念反转

**节奏模板参考**：

| 章节位置 | 功能 | 情绪强度 |
|---------|------|---------|
| 1-3章 | 黄金开头，建立世界观+冲突 | ★★★★ |
| 4-6章 | 展开设定，引入核心角色 | ★★★ |
| 7-9章 | 第一个小高潮/转折 | ★★★★ |
| 10-12章 | 短暂回落，为下一个高潮蓄力 | ★★ |
| 13-15章 | 第二个高潮，更深的危机 | ★★★★★ |

（以上为15章节奏范例，长篇按此模式循环，每个"弧"5-8章）

### 阶段4：AI写稿

**目标**：根据章节蓝图生成完整的章节正文。

**输入**：章节蓝图 + 前文内容 + 知识库中的相关设定。

**产出**：完整的章节正文（含对话、描写、心理活动）。

**写稿规则**：

1. **开场**：每章前50字内必须有一个"钩子"——动作、对话、悬念或感官刺激，不要用环境描写开头
2. **展示而非讲述**：用动作和对话表现性格，而不是直接写"他很愤怒"
3. **对话规则**：
   - 每个角色的说话方式必须符合其性格和口癖
   - 对话占比建议30%-50%，避免大段独白
   - 对话中穿插动作描写和心理活动
4. **描写规则**：
   - 环境描写服务于情绪和剧情，不超过每章10%
   - 善用五感（视觉、听觉、触觉、嗅觉、味觉）
   - 避免形容词堆砌，用具体细节代替抽象描述
5. **节奏控制**：
   - 短句制造紧张感，长句放缓节奏
   - 段落控制在3-5行，避免"文字墙"
   - 关键转折前留白（单句成段）
6. **结尾**：每章最后一段必须是悬念或情绪钩子，让读者"必须翻下一章"
7. **连贯性**：严格检查前文的时间线、角色状态、已埋伏笔，绝不前后矛盾

**字数与质量平衡**：
- 单章2000-4000字为佳
- 宁可3000字高质量，不要5000字注水
- 如果蓝图内容不够支撑预期字数，主动补充细节而非重复叙述

**网文特有技巧**：
- 爽点密度：每1500-2000字至少一个小爽点（实力展示、打脸、反转、获得）
- 情绪标签：写作时可标注段落情绪（如【紧张】【燃】【虐】），但不写入最终文本
- "装逼打脸"公式：低估→展示→震惊→跪服（按需使用，不是每章都要）
- "卡文急救"：当不知道写什么时，让意外发生——有人闯入、信息揭露、环境突变

### 阶段5：自动审稿

**目标**：对生成的章节进行质量审查，产出审稿报告和修改建议。

**输入**：章节正文 + 角色档案 + 世界观设定。

**产出**：审稿报告。

```yaml
审稿报告:
  章节: 第X章
  总评: （A/B/C/D，A级可直接发布，D级需重写）
  
  维度评分:
    剧情推进: （1-5分）| 评语: ...
    角色一致性: （1-5分）| 评语: ...
    对话自然度: （1-5分）| 评语: ...
    节奏感: （1-5分）| 评语: ...
    悬念钩子: （1-5分）| 评语: ...
    文笔质量: （1-5分）| 评语: ...
    
  关键问题:
    - [严重] 问题描述 → 修改建议
    - [中等] 问题描述 → 修改建议
    - [轻微] 问题描述 → 修改建议
    
  连续性检查:
    人设崩坏: （有无角色行为与设定矛盾）
    时间线: （有无时间逻辑错误）
    伏笔追踪: （本章应操作的伏笔是否已处理）
    
  爽点/亮点:
    - 本章做得好的地方
    
  修改优先级:
    1. 必须修改: ...
    2. 建议修改: ...
    3. 锦上添花: ...
```

**审稿标准**：

| 评级 | 标准 | 处理方式 |
|-----|------|---------|
| A | 剧情推进有力，角色一致，对话自然，钩子有效 | 可直接使用 |
| B | 整体流畅，有1-2处可优化 | 小幅修改后使用 |
| C | 存在明显问题（人设偏差、节奏拖沓） | 需要局部重写 |
| D | 核心逻辑错误或严重人设崩坏 | 需要整章重写 |

**特别检查项**：
- **AI味检测**：是否有过分工整的排比、空洞的形容词堆砌、不自然的总结性句子？如有，标记需改写
- **OOC检测**：角色的言行是否符合其档案中的性格和口癖？
- **信息重复**：同一信息是否在不同段落重复叙述？
- **视角混乱**：是否在受限视角中出现了角色不可能知道的信息？

### 阶段6：知识库

**目标**：维护创作过程中的设定一致性，防止长篇跑偏。

**这不是一个"执行阶段"，而是贯穿创作全程的持续维护动作。**

**知识库结构**：

```
小说项目/
├── 配置.yaml          （阶段1产出）
├── 世界观.yaml        （阶段2产出）
├── 角色/
│   ├── [角色A].yaml
│   ├── [角色B].yaml
│   └── ...
├── 章节/
│   ├── 第01章.md
│   ├── 第02章.md
│   └── ...
├── 蓝图/
│   └── 章节蓝图.yaml
├── 伏笔追踪.yaml      （所有伏笔的状态追踪）
└── 时间线.yaml        （故事内时间线记录）
```

**知识库维护规则**：
- 每次写新章节前，先检索知识库中相关的角色设定和世界观规则
- 每次审稿后，更新伏笔追踪表和时间线
- 角色状态变化时（如受伤、获得新能力、关系变化），更新角色档案
- 发现前后矛盾时，以先发布的章节为准，后续章节对齐

**伏笔追踪模板**：

```yaml
伏笔追踪:
  - ID: F001
    内容: [伏笔描述]
    埋设: 第X章
    计划揭开: 第Y章
    当前状态: 待揭开 / 已揭开 / 已废弃
    关联角色: [角色名]
```

**时间线模板**：

```yaml
时间线:
  - 章节: 第X章
    故事内时间: [具体日期/时段]
    关键事件: [1-2句话]
    角色状态: [谁在哪里，什么状态]
```

### 阶段7：扩展能力

**目标**：提供创作过程中的辅助功能，提升效率和质量。

#### 7a. 拆书分析

当用户想学习某部作品的写作技巧时使用。

```yaml
拆书报告:
  作品名: [书名]
  类型: [类型]
  开篇公式: （前3章的结构和节奏分析）
  角色关系图谱: （主要角色及其关系链）
  爽点分布: （标注每个爽点的位置和类型）
  节奏曲线: （情绪起伏的章节分布）
  可借鉴技法: （3-5条具体可学的写法）
  避坑提醒: （该作品的不足之处）
```

#### 7b. 命名生成

为角色、地点、组织、功法/技能等生成名字。

规则：
- 名字必须符合世界观风格（古风世界观不出现现代名）
- 提供5个候选名并附含义解释
- 避免生僻字和谐音问题

#### 7c. 场景扩写

将简短的情节描述扩展为完整的场景。

输入："两人在酒馆相遇，发生争执"
产出：完整的场景描写（500-1500字），包含环境、对话、动作、心理

#### 7d. 润色改写

对已有文本进行风格调整：

| 模式 | 说明 |
|------|------|
| 去AI味 | 消除工整排比、空洞描写，增加口语化和具体细节 |
| 提升文采 | 在不改变内容的前提下优化文笔 |
| 压缩精简 | 删除冗余，保留核心信息 |
| 风格仿写 | 仿照指定作者/作品的文风改写 |
| 情绪强化 | 放大指定情绪（燃/虐/甜/紧张）的表达力度 |

#### 7e. 连续性检查

对指定章节范围做全局一致性扫描：

- 人设一致性：角色行为是否符合档案
- 时间线连续性：时间逻辑是否有矛盾
- 世界观合规性：是否违反已设定的世界规则
- 伏笔完整性：计划中的伏笔是否都有交代

## 使用流程

### 全流程模式（推荐新手）

用户说"我要写一部小说" → 按1→2→3→4→5→6顺序逐步推进

### 单阶段模式

用户已有部分材料，直接进入指定阶段：
- "帮我生成角色设定" → 阶段2b
- "写第5章" → 阶段3+4
- "审一下这章" → 阶段5
- "续写下一章" → 阶段4

### 快速模式

用户只想快速出稿：
- "给我写个短篇" → 简化阶段1-2，快速进入3-4
- "一键全篇" → 输入创意后，快速生成3-5章完整短篇

## 文件管理建议

建议在用户工作区创建以下目录结构保存小说项目：

```
[用户指定路径]/
└── [小说名]/
    ├── 配置.yaml
    ├── 世界观.yaml
    ├── 角色/
    ├── 章节/
    ├── 蓝图/
    ├── 审稿/
    └── 知识库/
        ├── 伏笔追踪.yaml
        └── 时间线.yaml
```

每个阶段的产出物保存为对应文件，方便后续引用和版本管理。

## 注意事项

1. **长篇记忆管理**：写第N章时，务必回顾前N-1章的关键信息，可通过读取知识库文件实现
2. **角色口吻一致性**：在写对话前，先读取该角色的档案，特别是"说话口癖"字段
3. **伏笔不忘**：每章写稿前检查伏笔追踪表，确认本章应操作的伏笔
4. **不替用户做决定**：关键剧情走向、角色命运等重大决策应征求用户意见
5. **保持创作主动权**：AI是助手不是替代——提供选项让用户选择，而非直接拍板
6. **避免AI味**：审稿时重点检查和消除以下AI特征：
   - 过度使用"不禁""竟然""居然"
   - 大段心理独白解释角色动机
   - 过于工整的排比和对仗
   - 结尾强行升华或总结
   - 所有角色说话风格雷同

## 质量底线

无论哪个阶段，产出物必须满足：

- **无硬伤**：逻辑自洽、无前后矛盾
- **有个性**：不是"万能模板"，要有针对当前故事的独特设计
- **可执行**：蓝图能直接指导写稿，审稿意见能直接指导修改
- **有钩子**：每个章节都有让读者继续读下去的理由
