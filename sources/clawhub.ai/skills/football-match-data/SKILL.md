## 📌 工具概述

本工具提供专业足球赛事多维度数据整理服务。由于这是付费服务，工作流程严格要求按三个阶段执行：**创建订单 → 支付处理 → 服务执行**。

**直接执行：** 如果用户在初始请求中已直接提供了 `<订单号>`（且订单文件中已包含 `payCredential`），则可跳过前两阶段，直接进入 **🚀 第三阶段：服务执行**。

---

## 🛒 第一阶段：创建订单

如果这是首次交互且用户尚未付款，**必须**先创建订单，再发起支付。

### 1. 所需参数
* `<比赛>`：用户希望查询的比赛 (500.com fixture ID、titan007 ID、或队名如 "巴西 vs 日本")

### 2. 执行命令

```bash
python3 scripts/create_order.py "<比赛>"
```

### 3. 输出处理

**成功时，** 脚本将向标准输出打印以下键值对：

```
ORDER_NO=<值>
AMOUNT=<值>
QUESTION=<值>
INDICATOR=<值>
```

其中 `AMOUNT=100` 表示需支付 **1.00 元人民币**。提取 `ORDER_NO` 和 `INDICATOR` 后进入 **💳 第二阶段：支付处理**。

**失败时，** 脚本以代码 `1` 退出，输出 `订单创建失败: <错误详情>`。必须立即终止整个工作流程。

---

## 💳 第二阶段：支付处理

从第一阶段获取 `ORDER_NO` 和 `INDICATOR` 后，发起支付请求。

**操作：** 使用技能 `clawtip` 处理支付并获取支付凭证。如果该技能不存在，需要先安装它。

**`clawtip` 所需参数：**

```
{
  "order_no": "<来自第一阶段的 ORDER_NO>",
  "indicator": "<来自第一阶段的 INDICATOR>"
}
```

> ⛔ **clawtip 返回后必须立即回到本技能执行第三阶段。不要在 clawtip 技能内结束对话。**

> 订单的所有详细信息已由第一阶段脚本写入固定目录下的 JSON 文件中，`clawtip` 会根据 `order_no` 和 `indicator` 自动定位并读取。

**目标：** 等待支付成功并获取 `payCredential`（支付凭证），凭证会被自动写入订单文件。

> 🚨 **如果你只完成这一步就停止，用户付了钱却得不到报告 — 这是不可接受的。**
>
> clawtip 返回后，你只有一件事要做：**立刻、马上、不等待用户确认、不自作聪明写分析，直接执行：**
> ```bash
> python3 scripts/service.py "<订单号>"
> ```
> 禁止自己分析赔率、算概率、写报告。一切分析逻辑在 service.py 内。跳过此步 = 用户白花钱。

---

## 🚀 第三阶段：服务执行

支付成功并获取 `payCredential` 后，执行赛事数据汇总。

> ⛔ **最高优先级：必须使用下方命令执行，禁止自行编写分析代码。** 不要尝试手动提取赔率、计算概率或撰写报告。所有分析逻辑已内置在 `service.py` → `full_analysis.py` 中。自行分析将缺失31维中的25维以上，严重损害报告质量。

### 1. 所需参数
* `<订单号>`：第一阶段生成的订单号。

### 2. 执行命令

```bash
python3 scripts/service.py "<订单号>"
```

### 3. 输出处理

**执行后：**

1. 提取 `PAY_STATUS` 值（格式：`PAY_STATUS: <值>`）。
2. **`SUCCESS` 时：** 输出完整的赛事数据汇总报告。
3. **`ERROR` 状态：** 提取 `ERROR_INFO` 值，向用户告知确切的错误原因。
4. **`PROCESSING` 状态：** 支付仍在处理中，提示用户稍候。

## 🔍 数据质量保障

- **三源交叉校验**：500.com + titan007 + Odds API 多渠道数据源交叉比对
- **41项校验规则**：内置数据安全校验拦截机制，自动过滤无效、重复、偏差赛事数据
- **31维统计维度**：覆盖欧洲指数、亚洲指数、进球指数、离散度、交易量等多角度基础数据
- **实时数据时间戳**：每份报告附带数据采集时间标记
