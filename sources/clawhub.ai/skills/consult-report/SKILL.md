# 咨询报告工作流

解决咨询报告两个最常见的失败模式:
- **自洽的谬误**——框架跑一圈,方向错了 → 靠"假说先行 + 锋利性约束"
- **无根的断言**——判断犀利但没证据 → 靠"数据纪律 + 证据标注"

## 双轨架构

- **判断轨**:出框架、出假说、出判断。先想清楚"问题是什么、核心矛盾是什么",再动手写。
- **数据轨**:有数据文件 → 用 Python 实际算,绝不编数字;无数据文件 → WebSearch/公开信息,标注来源。

两轨在关键判断处必须对得上。数据不支持判断 → 判断让位于数据,并在报告中标注矛盾。

## 流程(标准版)

### Step 0 澄清需求(必做,跳过视为无效)
确认四件事,用户没说就问:
- **问题**:要回答什么决策问题
- **受众**:谁看这份报告,决定深度
- **数据**:有没有数据文件?路径是什么
- **时间窗**:判断的时效范围

用户只给一句话 → 基于公开信息推断,标注"未经确认"。

### Step 1 框架选择
按问题类型选,不贪多:
| 问题类型 | 主框架 |
|---|---|
| 市场进入/规模 | TAM-SAM-SOM + 五看三定(市场端) |
| 竞争分析 | 五力 + 战略群组 + 价值链 |
| 战略转型 | BLM + VRIO + 组织诊断 |
| 商业模式 | 商业模式画布 + 盈利结构拆解 |

选 1 个主框架,最多 1 个辅助框架,禁止框架堆砌。

### Step 2 假说先行
生成 2-3 个**互斥**假说(需求端/竞争端/组织端),每个假说必须能写出:
- **排他性**:它的含义是"因此我们不做什么"
- **可证伪性**:什么证据能推翻它
- **杠杆差异**:如果它为真,行动和别的假说真不一样

三条硬标准任一不满足 → 打回重来。

### Step 3 数据验证
按假说**定向**拉数据,不全面铺开。
- 有数据文件 → 按 `references/data-analysis.md` 用 Python 实际算。
- 无数据文件 → WebSearch/公开信息(财报、招股书、行业报告),逐条标注来源。
- 每个关键数据点标注:**来源 / 方法 / 时效 / 置信度**。
- 数据缺失 → 逻辑推演 + 类比估算,标注"估算值,置信度低";用户内部数据缺失 = 高风险,必须显式标注"关键假设未验证"。

### Step 4 诊断 + 指导方针
诊断 = 重新框定问题(不是复述),找出**单一核心矛盾**。
指导方针三要素缺一不可:
1. 应对思路(有排他性)
2. "因此不做[X]"(至少一条)
3. 近期目标(6-18 个月可验证,给具体数字)

### Step 5 输出
按 `references/output-spec.md` 的结构写 Markdown 报告。

### Step 6 自检(交付前必做)
- **反方攻击**:对每个核心结论尝试推翻,推不动的才保留
- **数据核对**:报告里每个数字回数据源复核一遍(算错/抄错/编造),并逐条确认归属「计算值/引用值/估算值/不可得」四类之一
- **硬门控**:追不到任何来源的数字 → 删除或写「数据不可得」,禁止用估算顶替;核心结论的唯一支撑不可得 → 该结论降级为「未验证」
- **引用核对**:引用不可验证 → 删除;若它是核心判断的唯一支撑 → 该判断置信度降级为「未验证」
- **锋利性检查**:逐条过下面的约束,违反即重写

## 复杂度路由

| 等级 | 触发 | 路径 |
|---|---|---|
| 快速 | 单维度小问题 | Step 0 + 1 假说 + 定向数据 + 一页结论 |
| 标准 | 明确但多维度 | 全流程 |
| S级 | 高度不确定/生死决策 | 3 假说各派子代理并行验证 + 对抗辩论 + 情景规划 + 双倍自检 |

## S 级并行执行(用子代理)

S 级路径用 Agent 工具**并行派子代理**,避免单线程逐个跑:
- **每个假说一个子代理**,定向验证:拉数据(数据文件或 WebSearch)、算数、给结论和置信度
- 主流程收集全部结果后做**对抗辩论**:结论冲突的假说当面对质
- **红队自检派一个独立子代理**做反方攻击,避免"自己审自己"的批判力打折
- 子代理无法并行时(环境限制)→ 降级回单线程,并在报告中标注「未经独立验证」

## 锋利性约束(违反即重写)

- 报告第一句话必须是判断,禁止"这是一个复杂的问题"等废话
- 只留单一核心矛盾;去掉它问题依然存在 → 还没找到真问题
- 强制取舍:做什么、不做什么、做了反而有害的
- 指导方针必须含"不做[X]"
- 目标锚定 6-18 个月可验证
- 数字优先:能用数字的不用形容词;敢于可证伪的单点判断,不用"高中低"
- P0 建议最多 2 个,P1 最多 3 个,每个必须写代价

## 例外处理

- **两轨矛盾** → 不强行统一,标注矛盾留两个视角;数据明确反例时判断必须让位
- **用户只说一句** → 降级为快速路径,报告开头注明"基于有限信息,建议补充确认"
- **假说连续打回 3 次** → 问题本身太模糊,回到 Step 0 重新澄清;不降标准
