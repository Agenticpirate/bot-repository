# 产品检验规程生成

## 任务目标

- 本 Skill 用于: 根据用户提供的产品相关资料，自动生成符合规范的产品检验规程 Word 文档
- 能力包含: 从控制计划/测试报告/图纸中提取检验信息、数据校验与缺失项处理、按模板格式生成 .docx 文档
- 触发条件: 用户要求生成检验规程、编制入厂检验规范、制作 IQC 检验文件

## 前置准备

- 依赖说明: 脚本需要 `python-docx` 库（见 dependency 声明）
- 数据结构规范: 见 [references/data-schema.md](references/data-schema.md)，定义了 JSON 数据的完整字段、格式和校验规则

## 操作步骤

### 步骤 1: 信息收集与提取

从用户提供的资料中提取检验规程所需信息。资料来源可能是:

- **控制计划**: 提取检验项目、检验方法、抽样方案、公差要求
- **测试报告**: 提取已有测试项、测试结果、判定标准
- **产品图纸**: 提取产品名称/型号/规格、尺寸公差、材质要求、关键尺寸
- **文字描述**: 用户直接口述的产品信息和检验要求

提取时重点关注以下信息:

| 类别 | 关键字段 |
|------|----------|
| 产品信息 | 产品名称、型号、规格、材质、图纸编号 |
| 文件信息 | 公司名称、文件编号、版本号 |
| 检验项目 | 项目名称、缺陷等级(CRI/MAJ/MIN)、检验方法/工具、合格标准 |
| 抽样方案 | 抽样标准、检验水平、AQL值、抽样计划表 |
| 检验环境 | 温湿度要求、所需设备 |

### 步骤 2: 数据校验与缺失处理

对照 [references/data-schema.md](references/data-schema.md) 中的校验规则，逐项检查提取的数据:

1. **必填字段检查**: `product_info.product_name` 和 `inspection_items` 不能为空
2. **缺陷等级校验**: 每个检验项目的 `defect_level` 必须为 CRI/MAJ/MIN 或其组合
3. **序号层级校验**: `seq` 应保持逻辑层级关系（如 1, 2, 2.1, 2.2, 3）

**缺失数据处理原则**:

- 缺少非关键信息: 使用合理默认值或省略
- 缺少关键信息: **主动向用户索要**，一次性列出所有缺失项
- 用户拒绝提供或无法提供: 对应字段标注 **"待确认"**，绝不自行编造技术参数
- 在文档末尾汇总所有"待确认"项，方便用户后续补充

### 步骤 3: 组织 JSON 数据

将提取和校验后的信息按 [references/data-schema.md](references/data-schema.md) 中定义的格式组织为 JSON 文件，保存到工作目录。

调用示例:
```bash
python scripts/generate_doc.py --data ./inspection_data.json --output ./产品检验规程_产品名称.docx
```

### 步骤 4: 生成文档并预览

1. 调用脚本生成 Word 文档
2. 向用户展示关键内容摘要（检验项目清单、关键参数、待确认项列表）
3. 用户确认无误后，交付最终文档

### 步骤 5: 迭代修改（可选）

用户反馈修改意见后:
1. 更新 JSON 数据中对应字段
2. 重新调用脚本生成文档
3. 再次展示摘要供确认

## 使用示例

### 示例 1: 从控制计划生成检验规程

- 场景/输入: 用户提供一份电机槽绝缘的控制计划文件，包含检验项目、公差要求、抽样方案
- 预期产出: 生成完整的《槽绝缘入厂检验规程》Word 文档，包含所有检验项目、抽样表、合格标准
- 关键要点: 从控制计划中准确提取每个检验项目的缺陷等级和合格标准；公差值必须与图纸一致，无法确认时标注"待确认"

### 示例 2: 从产品图纸和口头描述生成

- 场景/输入: 用户提供产品图纸（图片）并口述"这是一个NMN复合纸，厚度0.25mm，用于电机相间绝缘"
- 预期产出: 生成《相间绝缘入厂检验规程》，图纸中的尺寸信息自动填入，口述信息作为补充
- 关键要点: 图纸中的尺寸公差需精确提取；用户未提及的检验项目（如电气性能）需主动询问是否需要包含

### 示例 3: 信息不完整时的处理

- 场景/输入: 用户仅提供产品名称"青壳纸"和简单描述，缺少详细规格和检验标准
- 预期产出: 先生成框架文档，缺失字段标注"待确认"，同时向用户列出需要补充的信息清单
- 关键要点: 不编造任何技术参数；明确告知用户哪些信息缺失、为什么需要这些信息

- 资产: 见 [assets/template.docx](assets/template.docx)（原始模板参考，脚本不直接依赖此文件，而是按模板格式从头构建文档）

## 注意事项

- 仅在需要确认数据结构时读取 references/data-schema.md，保持上下文简洁
- 缺失数据时优先向用户索要，标注"待确认"是最后手段，绝不自行编造
- 充分利用智能体能力分析用户提供的各类资料（文件、图片、文字），提取结构化信息
- 每个产品单独生成一份检验规程，不支持多产品合并
- 生成的文档遵循 GB/T 2828.1 抽样标准框架，具体参数根据产品特性调整
