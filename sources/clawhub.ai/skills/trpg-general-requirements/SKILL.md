你是這個任務的 AI。這份是伴隨 TRPG 需求規格書一起發給你的通用需求。請在撰寫規則的同時，一併產出以下所有交付物。

🌐 如有需要，使用 WebSearch 上網查找參考作品的原始設定（世界觀細節、角色能力、劇情結構等）。不要僅憑訓練記憶填寫——以網上最新、最準確的資訊為準。特別是在處理已有原作的改編規則時，主動查證原作設定。如需爬取結構化網頁資料（如 Wiki 條目、數據表、怪物圖鑑頁面等），可使用 Agent Browser 無頭瀏覽器（`agent-browser navigate <URL>` + `agent-browser snapshot` 取得頁面內容）。

🚨 所有中文必須使用繁體中文（正體中文）。禁止使用簡體中文。

🚨 所有遊戲術語——包括玩家規則書、GM 規則書、角色卡、劇本、圖鑑等全部文件——一律採用「中文全稱（縮寫）」的統一格式。不得出現只有英文縮寫而沒有中文全稱的情況。GM 規則書也不例外。

🚨 純技術性 Key（如 YAML 鍵名、Excel 公式中的變數名等只在內部流通的標識）可以保留英文。

🚨 關於英文縮寫的檢查標準（內置規則，無需參照外部文件）：

核心原則：真人玩家是人，真人 GM 也是人。無論是玩家規則書還是 GM 規則書、空白角色卡還是 NPC 數據表，看到「STR」「DEX」「HP」這些英文縮寫時都可能一頭霧水。這不是寫給程式看的技術文檔，是給人看的遊戲文件。

需要改的英文縮寫：遊戲術語——屬性名、技能名、狀態名、裝備名、怪物名——任何出現在遊戲文件中的詞。GM 規則書雖然是給 GM 看的，但 GM 也是真人，看不懂英文縮寫的機率跟玩家一樣高。不論是玩家規則書還是 GM 規則書，遊戲術語一律使用「中文全稱（縮寫）」格式。不只標題和定義要改，正文中每次出現也要用全稱。

可以保留的英文：YAML 的鍵名、Excel 公式中的變數名、純數值、公式、程式碼片段。簡單判斷：「這個詞會出現在任何真人會閱讀的遊戲文字中嗎？」會 → 必須補中文全稱；不會 → 可以保留英文。

常見需要檢查的類別（玩家規則書和 GM 規則書都要檢查）：屬性（STR、DEX、CON…）、衍生值（HP、MP、SP…）、狀態效果（Stun、Poison、Burn…）、裝備稀有度（Common、Rare…）、傷害類型（Physical、Magic、Fire…）、技能類型（Active、Passive…）、檢定類型（Skill Check、Saving Throw…）、貨幣/資源（Gold、EXP…）。

🚨 屬性對照表縮寫例外：在表格中，如果同一列的前一格已經是該屬性的中文全稱，則縮寫格用純縮寫（如 GUG），不重複寫「根骨（GUG）」。此例外適用於所有規則自定的屬性縮寫（如 GUG、WUX、SHS、STR、DEX 等），但不適用於 HP、DC、CR、AC、AOE 等非屬性縮寫——這些仍照主規則包裝。判斷方式：當前格是「中文全稱（縮寫）」、且前一格去粗體後等於該全稱 → 還原為純縮寫。
🚨 遊玩人數必須預設相容單人模式（1 位玩家 + 1 位 GM），同時可選支援多人（多位玩家 + 1 位 GM）。所有機制設計時必須確保 1 位玩家 + 1 位 GM 的配置即可完整運行。這裡的「單人」指的是 1 個玩家角色，不是只有一個人自己玩。


你需要產出的交付物：

一、主規則文件（分為玩家用和 GM 用兩份獨立檔案）

撰寫兩份獨立的 TRPG 規則書（.md 格式），一份給玩家、一份給 GM：

玩家規則書（[規則名稱]_玩家規則書.md）：
  玩家創建角色和參與遊戲所需的所有內容。包含：屬性系統說明、種族/職業選項、技能與能力列表、裝備與道具列表、角色創建步驟、升級與成長規則、戰鬥基礎規則（玩家視角）。不需要包含 GM 才知道的幕後機制（隱藏 DC、怪物數據、劇情秘密等）。

GM 規則書（[規則名稱]_GM規則書.md）：
  主持遊戲所需的所有內容。包含：完整的檢定機制與 DC 設定指南、戰鬥完整規則（含怪物行為、AI 邏輯）、所有特殊系統的完整運作規則、遭遇設計與難度平衡指南、世界觀與設定細節、劇本運行指引、可選規則與變體。GM 規則書同時包含玩家規則書的所有內容，因此 GM 只需閱讀一份即可。

所有規則說明必須清楚完整，讓真人玩家/GM 可以閱讀後直接開始遊戲。

二、劇本（每個劇本需同時產出兩種格式）

每個劇本需產出兩個同名檔案，存放在 scenarios/ 目錄中：

2-1. .md 格式（供真人 GM 和玩家閱讀使用）
  └ 自然段落敘述。包含開場描述、場景流程、NPC 對話、遭遇資訊、關卡設計、獎勵等。排版清晰，可直接列印或在平板上閱讀。劇本整體長度必須相容規則的等級下限和上限——例如類似 D&D 5E 從等級 1 到等級 20 的一連串劇本，覆蓋從新手到封頂的完整成長曲線。每個劇本應標註建議等級範圍和難度。

2-2. .yaml 格式（供 briefing_package / AI GM 使用）
  └ 從同一份劇本內容提取結構化資料。包含 name、description、difficulty、level_range、map_ref（如有）、initial_map（如有）等欄位。用於 AI GM 載入和地圖面板渲染。

兩種格式使用相同檔名、不同副檔名（例如 S1_墓地探險.md + S1_墓地探險.yaml），一起存放在 scenarios/ 目錄中。

三、角色卡（全部使用 Excel .xlsx 格式）

以下 Excel 檔案全部獨立存放，每個檔案內含公式自動計算：

3-1. 空白玩家角色卡（1 個獨立檔案）
   └ 一張空白的玩家用 Excel 角色卡。包含所有屬性欄位、技能欄位、裝備欄位等。所有需要計算的欄位（如屬性加值、衍生數值、技能總值等）必須預先輸入 Excel 公式，讓玩家填入基礎數值後自動計算結果。

3-2. 空白 NPC 角色卡（1 個獨立檔案）
   └ 一張空白的 NPC 用 Excel 角色卡。結構比玩家卡精簡，但同樣包含所有需要自動計算的公式。

3-3. 空白敵人角色卡（1 個獨立檔案）
   └ 一張空白的敵人/怪物用 Excel 角色卡。包含怪物所需的特殊欄位（如挑戰等級、特殊能力等），所有公式預先輸入自動計算。

3-4. 範例玩家初建角色卡（單一多頁 Excel 檔案）
   └ 一個 Excel 檔案，內含多個分頁（Sheet），每一頁是一張示範用的已填寫玩家角色卡。供玩家參考如何填寫角色。建議至少 3-5 張不同職業/風格的範例角色。所有公式保持自動計算以展示正確結果。

3-5. NPC 角色卡合集（單一多頁 Excel 檔案）
   └ 一個 Excel 檔案，內含多個分頁。將劇本和世界觀中會出現的所有 NPC 角色卡統一收錄在此檔案中，每個 NPC 一個分頁。

3-6. 敵人角色卡合集（單一多頁 Excel 檔案）
   └ 一個 Excel 檔案，內含多個分頁。將所有劇本中用到的敵人和怪物角色卡統一收錄在此檔案中，每個敵人一個分頁。

⚠️ Excel 角色卡統一規範：
- 同一類型（敵人/NPC/範例玩家）合併為一個多頁 Excel 檔案，不要拆成多個檔案
- 所有需要計算的欄位都使用 Excel 公式自動計算（如屬性加值 = FLOOR((屬性值-10)/2)、生命值 = 基礎HP + 體質加值 x 等級 等），確保玩家只需要輸入基礎數值
- 公式中使用繁體中文欄位標題作為參考時，請確保 Excel 能正確識別
- 每一張角色卡（玩家、NPC、敵人均適用）預留一個用來放置角色圖的空白區域（合併儲存格，標註「角色圖」）。位置統一放在角色卡左上角，大小約 3×4 個儲存格

四、劇本地圖（如有需要）

如果劇本涉及具體空間結構（地下城、建築平面、世界地圖等），每張地圖需要同時產出兩種格式：

4-1. YAML 結構化資料（供 briefing_package / AI GM 使用）
  └ 格式：nodes（節點 id + label + 座標 + type + explored）/ edges（from + to + type）/ regions（name + color + nodes）。用於程式讀取和地圖面板渲染。

4-2. SVG 視覺化地圖（供真人 GM 和玩家閱讀使用）
  └ 從同一份地圖資料生成。節點→圓角矩形標註名稱、區域→淺色半透明底色區分、連線→箭頭線條可標註通道名稱。可直接用瀏覽器打開、列印、或插入規則書中。

兩種格式使用相同檔名、不同副檔名（例如 墓地.yaml + 墓地.svg），一起存放在 maps/ 目錄中。每張地圖必須清楚標註對應哪一個劇本的哪一段劇情使用。

五、圖鑑（如有需要）
物品圖鑑、怪物圖鑑、魔法圖鑑等參考資料，均為獨立檔案存放。格式可使用 .md 或 .yaml。每個圖鑑項目應包含完整的中文名稱、描述、數值、效果等資訊。
