# ACCOUNT_WATCH() 客户动态跟踪与商机信号分析

Display Name：`ACCOUNT_WATCH()`  
Chinese Name：客户动态跟踪与商机信号分析  
Project：WorkFn  
Version：v1.0.0

## 职责边界

持续发现某一已确认企业自上次检查以来的公开变化，并判断其行动价值。不要替代：

- `zayn-company-research`：企业基础公开信息调查。
- `zayn-social-listening`：给定时间段的社媒与舆情分析。
- `zayn-opportunity`：具体商机成立与否的判断。
- `zayn-followup`：跟进节奏和动作编排。
- `zayn-reply`：最终对外表达。

推荐传递链：`ACCOUNT_WATCH()` → `OPPORTUNITY()` → `FOLLOWUP()` → `REPLY()`。只在后续 Skill 满足最低运行条件时传递。

开始分析前读取并遵守：

## 参数解析协议

按以下顺序运行：用户输入 → 输入解析 → 参数映射 → 参数状态表 → 最低运行条件检查 → 缺失或冲突处理 → 用户补充 → 重新检查 → 正式分析 → 结构化输出。

参数状态只能使用：`已命中`、`部分命中`、`缺失`、`冲突`、`待验证`。

### 核心参数

1. 客户主体：正式名称、常用名、国家/地区、官网、域名、LinkedIn、官方社媒、关联品牌和母子公司。
2. 我方背景：产品/服务、历史关系、询价订单、最近沟通、希望推动的业务、价值和当前供应能力。
3. 跟踪边界：官网、LinkedIn、活动官网；可补充新闻、招聘、产品、合作伙伴、管理层和监管风险。
4. 时间：检查周期、上次与本次检查时间、关注窗口、发布日期和首次发现时间。
5. 目标：寻找机会或联系理由、识别战略/采购变化、跟踪项目、寻找见面窗口、识别风险。

## 最低运行条件

正式增量分析必须同时满足：主体可确认；至少一个可靠官方来源可检查或用户提供可验证材料；我方产品或服务明确；跟踪目标明确；上次检查时间或可比较历史状态明确；本次内容可与历史区分；官方、第三方和个人账号可区分。

缺少上次检查时间时，只执行“近期动态/基线扫描”，不得声称内容是“新增”或“最新”。缺少我方业务背景时，可整理动态但不得给出强联系建议。主体不明或关键来源无法核验时停止正式分析。

## 工作流

1. 确认主体、官方账号、来源范围、时间边界和跟踪目标。
2. 决定扫描模式：首次基线、近期扫描或增量扫描。
3. 收集范围内的公开动态；记录来源、发布日期和首次发现时间。
4. 按去重规则合并转载、重复发布和同一事件的更新版本。
5. 将事件分为采购与需求、联系机会、战略变化、风险或弱信号。
6. 评估相关性、新鲜度、明确度、可行动性、关系基础、证据强度、风险和商业价值。
7. 将事件归入强业务信号、可跟进信号、观察信号、风险信号、无行动价值或信息不足。
8. 从动作规则中选择一个动作，并补齐目标、时机、角度、准备、风险和停止条件。
9. 保存事件状态和动作结果，设置下次检查时间；无新信号时只输出一句简短结论。

## 输出结构

1. 参数完整度结论与参数状态表。
2. 本次监测摘要：模式、来源、时间范围、发现数、有行动价值数。
3. 新增或近期动态清单：时间、来源、动态、类型、证据状态。
4. 信号分析：与我方关联、信号状态、依据、风险。
5. 建议动作：优先级、动作、目标、推荐时间、建议角度、准备、风险、停止条件。
6. 可用与禁用联系角度、待观察事项。
7. 状态更新：`signal_id`、`company_id`、来源、发布时间、标题、摘要、类型、状态、首次/最后发现时间、动作、动作状态和结果。
8. 来源清单：名称、链接或位置、发布日期、检查时间、来源类型、可信度、是否官方。

## 动作和传递规则

最终动作只能选择：立即联系、在活动前联系、活动后联系、轻互动、转交其他同事、补充调查、持续观察、暂不行动、风险升级。

- 形成明确项目、需求、预算、时间或采购角色线索时，将已确认字段传给 `zayn-opportunity`。
- 仅在“是否/何时跟进”仍需判断时，将信号、窗口、关系基础和风险传给 `zayn-followup`。
- 只有动作已经确定且用户要求最终文案时，将已确认事实、角度、禁区和时间窗口传给 `zayn-reply`。
- 不把整份监测报告原样传递，不把推断升级为事实。

## 状态、隐私与自动化

动态状态只能使用：新发现、已分析、待行动、已行动、持续观察、已忽略、已失效。已处理事件不重复提醒，除非发生实质变化。

只使用合法、公开、获授权的数据；不绕过登录、权限或付费限制；不收集非公开或敏感个人信息；不监控员工私人账号；不把个人观点当企业立场；不利用负面事件做冒犯式营销；不编造日期、展位、身份、需求、来源或结论。

本 Skill 负责“查什么、如何判断、如何分类、如何建议”；调度器负责“何时检查、多久检查、何时通知”。不要自行创建定时任务、持续后台监控或通知机制，除非用户另外明确要求并授权。
