# 产品需求文档生成器

> 产品开发全链路 Skill #4 · 从 Idea 到可执行文档

## 功能

基于产品 Idea 和调研数据，生成结构化 PRD，涵盖产品概述、用户画像、功能需求、技术架构、商业化策略、路线图。

## 核心工作流

### Step 1：需求澄清

确认以下信息：
- 产品一句话定位是什么？
- 目标用户是谁？规模多大？
- 核心解决什么问题？
- 当前有没有替代方案？
- 预期的变现方式？
- 技术资源情况？

### Step 2：市场与用户调研

基于定位执行调研：
- 竞品扫描（3-5个）
- 用户核心痛点
- 市场规模估算
- 行业趋势

### Step 3：PRD 结构生成

#### 一、产品概述
| 字段 | 内容 |
|------|------|
| 产品名称 | 中文名 + 英文名 |
| 一句话定位 | 谁 + 解决什么问题 + 怎么解决 |
| 核心价值 | 用户为什么选你 |
| 产品形态 | Web / App / 小程序 / AI Agent |

#### 二、用户画像与场景
至少 2-3 个典型画像，按优先级排列核心场景。

#### 三、功能需求
按 P0/P1/P2 分级，P0 不超过 5 个。

#### 四、技术架构（简要）
前端 → API → 后端 → 数据库 → AI/LLM

#### 五、数据策略
核心数据资产、来源、采集方式、数据飞轮逻辑。

#### 六、商业化方案
分层定价模型 + 变现路径。

#### 七、路线图
验证期 → 增长期 → 变现期 → 扩张期

#### 八、Non-goals
明确不做的事。

#### 九、风险与应对

## 输出格式

- 最终交付物：Markdown 或 HTML 格式的 PRD 文档
- 命名规范：`{产品名}-PRD.md`

## 硬约束

1. P0 功能不超过 5 个
2. 必须有 Non-goals 章节
3. 必须有数据策略章节
4. 所有数据来源必须标注
