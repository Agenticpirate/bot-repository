# 微信文件助手

这个技能用于解决“微信文件在哪里，以及找到后还要做什么”的实际问题。它可以扫描新版和旧版微信文件目录，通过文件名或文件内容定位文件，建立本地增量索引，识别完全重复的文件，并在找到文件后继续完成总结、提取、比较或整理等任务。所有搜索与索引均在本地进行，不会修改微信原始文件。

根据用户真正想完成的事情选择流程：

- 精确或模糊文件名查询：使用快速 PowerShell 搜索，不需要索引。
- 内容搜索、自然语言筛选、重复或版本检查、反复快速查询：使用 SQLite 索引流程。
- 找到文件后：继续完成用户明确要求的打开、总结、提取、比较或复制任务。复制、移动、上传、转发和删除属于独立操作，不能从“查找”请求中自动推断。

## 快速文件名查找

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "<skill-dir>\scripts\find_wechat_file.ps1" -Query "文件名或关键词" -OpenInExplorer
```

根据请求添加 `-Exact`、`-Since`、`-Before`、`-Root` 或 `-MaxResults`。用户直接查找单个文件时使用 `-OpenInExplorer`；存在多个候选项需要选择时不要自动打开。结果中始终显示完整绝对路径。

## 索引与内容搜索

建立、更新或搜索索引，以及导入元数据或检查重复文件前，先阅读 [references/index-workflow.md](references/index-workflow.md)。索引存放在微信目录之外，不会修改源文件。

当用户记得文件内容但忘记文件名，或提出类型、日期、大小条件，需要重复快速查询或检测重复文件时，使用索引搜索。调用脚本前，把“上周”等相对日期转换为明确的本地日期。结果可能带有本地内容片段，但不能把内容片段当作发送人信息。

## 找到后继续处理

如果用户同时提出后续目标，不要只返回路径：

- “总结、提取、阅读”：使用适合该文件格式的本地能力检查选定文件。
- “比较版本”：先确认候选文件，再比较内容及相关文件元数据。
- “打开位置”：在资源管理器中选中文件；只有用户明确要求时才打开文件本身。
- “复制、整理、发送、删除”：执行前确认准确目标、目的地或接收人。

存在多个合理候选项时，依次优先排列完整文件名匹配、内容匹配和较新的文件，让用户选择，不能随意打开其中一个。

## 证据规则

- 只有 `metadata_source` 指向明确的可信元数据索引时，才能把 `sent_at`、`sender` 和 `chat` 标记为已验证。
- 不能把 `last_write_time` 或年月目录称为微信发送时间，只能称为“文件修改时间”。
- 不能根据账号目录、哈希、`wxid`、文件名或父目录推断发送人。
- 无法获取发送人或时间时，应明确说明并继续返回匹配文件。不得尝试解密、修补、复制或修改微信数据库。
- 只搜索脚本发现的本地路径或用户明确提供的路径。直接查找请求可以在资源管理器中选中文件；打开文件本身、复制、上传或转发仍需要用户明确要求。
- 内容提取是本地尽力而为的过程。必须显示 `no_text_or_scanned_pdf`、`unsupported_type` 等状态或提取失败；未成功提取内容时，不能声称文件不包含某个词语。

## 可选的可信元数据

如果用户提供可信的 CSV、JSON 或 JSONL 导出文件，通过 `-MetadataIndex` 传入。建立或调整元数据索引前，阅读 [references/metadata-index.md](references/metadata-index.md)。脚本通过规范化后的绝对路径关联元数据。

如果没有发现微信文件根目录，显示 JSON 中已经尝试的路径，并请用户提供微信或 Weixin“设置 → 文件管理”中显示的存储位置。不能直接声称电脑没有安装微信。

## 使用示例

- “帮我找微信文件 `report.txt`，并打开它所在的位置。”
- “找一下内容里提到‘退款条款’的微信 Word 文件。”
- “查找今年收到的所有 PDF，按文件修改时间倒序排列。”
- “查找重复的微信文件，但先不要删除。”
- “找到减脂计划，提取每天的训练安排并整理成表格。”
