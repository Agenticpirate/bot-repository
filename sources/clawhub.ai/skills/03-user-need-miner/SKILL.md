# 用户需求挖掘器

> 产品开发全链路 Skill #3 · 从用户嘴里挖出真实需求

## 功能

从用户访谈记录、社交媒体讨论、产品评论、论坛帖子中提取真实需求，生成结构化用户画像和需求清单。

## 核心工作流

### Step 1：数据采集

根据用户提供的信息来源，采集原始数据：

**信息来源（按优先级）**：
1. 用户访谈记录（最高价值）
2. 社交媒体讨论（小红书/知乎/微博）
3. 竞品用户评论（App Store/应用商店）
4. 论坛帖子（豆瓣/贴吧/知乎问答）
5. 客服记录/用户反馈

### Step 2：需求提取

从原始数据中提取以下信息：

**显性需求**（用户直接说出来的）：
- "我想要XX功能"
- "XX产品不好用"
- "如果能有XX就好了"

**隐性需求**（用户没说但行为暗示的）：
- 反复出现的操作场景
- 绕过限制的"黑科技"行为
- 高频搜索的关键词

**情绪信号**（用户情绪强度）：
- 强烈不满（愤怒/失望）
- 一般不满（吐槽/抱怨）
- 渴望（期待/羡慕）

### Step 3：用户画像生成

```
画像名称：XXX
身份标签：博士三年级 / 准备求职
核心场景：睡前刷手机查学校
核心痛点：信息不透明，不知道真实待遇
当前方案：一个一个学校官网查，累
理想方案：输入条件，一键对比
付费意愿：低（¥0-50）
```

### Step 4：需求优先级排序

| 需求 | 用户提及频次 | 痛点强度 | 付费意愿 | 实现难度 | 优先级 |
|------|-------------|----------|----------|----------|--------|
| XX功能 | 高频 | 强 | 高 | 低 | P0 |
| YY功能 | 中频 | 中 | 中 | 中 | P1 |

## 输出格式

- 最终交付物：Markdown 用户需求分析报告
- 命名规范：`{产品名}-用户需求分析.md`

## 硬约束

1. 需求必须来自真实用户数据，不能编造
2. 用户画像至少 2 个，不能只有一个
3. 必须区分显性需求和隐性需求
4. 需求优先级必须结合频次和强度两个维度
5. 如果用户没有提供原始数据，先用 WebSearch 收集公开信息
