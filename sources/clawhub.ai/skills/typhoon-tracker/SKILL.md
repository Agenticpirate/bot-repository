# 台风追踪与研判（Typhoon Tracker）

## 用途

系统性追踪和评估逼近华东的台风。提供可复用的数据采集、预报解读、影响建模、
报告生成和决策支持框架。适用于西北太平洋台风逼近中国沿海的全周期追踪。

## 触发条件

- 用户询问某个台风的路径、登陆预测或强度变化
- 用户需要评估台风期间某活动/出行是否可行
- 用户位于杭州/上海/宁波/合肥等城市，询问台风影响
- 用户有出行计划（高铁/航班）需评估取消或延误风险
- 用户需要结构化的台风应急准备方案
- **用户询问航班/高铁/交通出行或行程规划（必触发）**：即使未明确提及台风，也必须排查台风及残余环流、冷空气等系统性天气背景——**禁止仅凭当日天气预报回答交通问题**。航班延误/取消的根源常是台风残涡"回马枪"、残余环流+冷空气联合降雨等宏观系统，当日预报只显示"阵雨/雷雨"表象，漏查台风背景会严重误判。处理流程：①查是否有活跃台风/残余环流影响目标区域 ②查其停编/残涡状态与移动趋势 ③再叠加当日天气预报和机场/铁路公告判断
- **用户询问停编台风的残涡去向/残余影响/降雨成因（必触发）**：即使主台风已停止编号，只要用户询问"残涡去哪了""为什么还在下雨""残余环流影响"等，必须按"残涡追踪协议"完整追踪残涡中心位置、移向、重组信号与影响，**禁止用"已停编/无编号"简单了事**——残涡可在停编后重组二次增强（白海豚8/14-15太湖重建低压实证）。处理流程：①定位残涡中心 ②判断移向（含回折转向）③监测重组信号 ④评估影响 ⑤出境时用韩国/日本气象厅交叉验证
- **近海热带系统高优先级（必触发，无论是否编号）**：**凡距重点城市 <500km 的海上系统（未编号扰动/热带低压/近海弱台风/残涡），其关注优先级 ≥ 远洋强台风**（教训㉓：简拉维仅8级却触发山洪海浪预警+铁路停运，优先级高于16级强台风沙德尔）。拿到台风/天气数据后，**先列出所有影响重点城市的系统并按"距重点城市距离"排序，近海弱系统优先**；对距重点城市<500km的近海扰动/低压（无论编号与否）→ **加载 `references/nearsea_system_protocol.md`** 执行连续谱跟踪（未编号扰动→热带低压→台风→残涡，同实体沿链快速变化须全程跟踪）。**禁止因"未编号/弱编号"降级呈现权重**（8/22 晨报漏报东海低压20260022→数小时后升级为20号简拉维并实登陆福建）。

## 区域优先级框架

本 skill 以华东地区为核心评估区域（**江浙沪闽**），适用于西北太平洋台风逼近中国沿海的全周期追踪。区域优先级用于内部评估权重分配，不作为默认输出顺序。

### 一级优先（核心评估区域）

**江浙沪核心城市**，内置详细评估参照：

- 杭州市（含西湖区、滨江区、拱墅区等区域）—— 内置参照示例
- 上海市（含嘉定区南翔等近郊区域）—— 内置参照示例

> 该列内置完整评估维度，是 skill 的"饱和覆盖"区。实际评估不受此表限制——**江浙沪闽任意城市及全国其他城市**均可通过下方"城市快速评估框架"获得系统评估。

评估维度：风力衰减修正、地形降雨差异（山区vs城区）、地铁/高铁停运、活动可行性

### 二级优先（扩展评估区域）

**台风登陆点邻近 + 远内陆关键城市；含福建沿海片区（可试用评估区域）**：

- 温州/宁波等台风登陆点邻近城市（沿海直接冲击评估）
- 安徽省淮南/淮北（远内陆残余降雨+地质灾害评估）
- **福建沿海城市（福州/泉州/厦门等）—— 台风登陆潜在风险地区，支持评估**：走"城市快速评估框架"（当前未内置细分参照表；福建相关风雨/路径经验由近海系统协议与案例支撑，如简拉维2620 外围环流致福建持续风雨记录）

评估维度：沿海风力/港口影响 / 远内陆残余降雨+地质灾害 / 福建沿海台风登陆风险

### 三级（其他任意城市）

使用"城市快速评估框架"进行评估（见下方详细流程）。该方法论基于风圈半径与距离的关系模型、内陆衰减系数和省级气象预报数据，为任意城市提供系统性的影响评估。

### 输出原则

- 输出用户明确指定的城市，不默认只输出特定城市
- 若用户未指定城市，默认评估一级优先区域，同时提示可评估其他城市
- 多城市对比时按用户列出的顺序输出
- 一级/二级/三级差异体现在评估深度和案例参照丰富度，不影响输出格式

## 网络可达性与容错协议

部署环境分类、信息源可达性分级、容错策略和环境判断规则，详见 `references/deployment_guide.md`。

简要：国内源始终可用；JMA通常可达；JTWC大概率受限。国际源超时10s跳过，全部不可用时置信度上限降为"中"。替代方案：搜索国内媒体引用。

## 信息源冲突解决协议

22个数据源不等于每次都查22个。核心原则：**分层查询、交叉验证、CMA为锚、一次搜索覆盖多源**。

### 用户提供信息验证协议（取代"先询问来源"流程）

**目的**：用户发来截图/消息是"信息输入"，目标是收集信息给用户反馈。**禁止要求用户先说明截图来源**（用户体验差、自动化场景不可行、且可能用户自己也不清楚）。正确流程：

1. **用户信息进来 → 先用内置 P0/P1/P2 信源交叉验证**（WebSearch 覆盖官方源/权威媒体/实时数据）
2. **验证一致 → 采信**，报告中标注"用户提供信息，经内置信源验证一致"
3. **验证冲突 → 以内置信源搜索到的消息为准**，并在报告中如实说明差异（"用户提供的X与官方预报Y不一致，以官方为准"）
4. **内置信源覆盖不到 → 标记"待验证新信源信息"**，采信但降低置信度，提示用户；同时**评估是否将该信源纳入信源池**（skill 迭代机制：新信源经1-2次验证可靠后升格为内置信源）
5. **例外**：仅当用户信息与内置信源冲突且影响重大决策（如航班取消）时，可向用户确认信息出处以便回溯

> 案例：用户经航旅纵横APP提供机场天气警报（雷暴解除+区域预警）——经中央气象台/省气象台交叉验证方向一致后采信，随后将航旅纵横APP升格为内置P1信源。信源标引必须按信源链分级（P0一手/ P1二级/ P2三级），不得凭内容反推层级。

### 搜索效率与信息源覆盖的平衡

关键认知：**一次 WebSearch 可以覆盖多个信息源**。搜索"白海豚 最新路径 JMA ECMWF"一次可以同时获取CMA公报、JMA预报、ECMWF模型结果。因此"5-6次搜索"可以覆盖12-20个信息源。

### 冲突解决规则

当不同来源预报出现分歧时，按以下规则取舍：

#### 路径分歧（登陆地点）

| 场景                     | 仲裁规则                                             | 理由                           |
| ------------------------ | ---------------------------------------------------- | ------------------------------ |
| CMA vs JMA 分歧<100km    | **以CMA为准**                                  | CMA对中国近海数据更优          |
| CMA vs JMA 分歧100-300km | **CMA为主、JMA为辅，标注区间**                 | 两者都有道理，给区间更诚实     |
| CMA vs JMA 分歧>300km    | **列出两种路径，标注概率，追加第三层模型对比** | 真实不确定性，用多模型辅助判断 |
| GFS/ECMWF vs CMA分歧     | **远洋时偏ECMWF，近海时偏CMA**                 | ECMWF全球最优，CMA近海最优     |

#### 强度分歧

| 场景                    | 仲裁规则                     |
| ----------------------- | ---------------------------- |
| CMA vs JTWC 强度差≤1级 | 以CMA为准                    |
| CMA vs JTWC 强度差>1级  | 取较低值，但标注JTWC较高估计 |
| 模型预报强度 vs 官方    | 以官方为准，模型仅参考趋势   |

#### 时间分歧（登陆时间）

| 场景              | 仲裁规则             |
| ----------------- | -------------------- |
| CMA vs JMA 差≤6h | 取CMA                |
| CMA vs JMA 差>6h  | 给区间，标注"±Xh"   |
| 多模型集合        | 取中位数，标注离散度 |

### 判断置信度标注规则

每个结论必须标注置信度：

| 置信度         | 条件                                         | 标注方式                                             |
| -------------- | -------------------------------------------- | ---------------------------------------------------- |
| **高**   | CMA+JMA一致 或 距登陆<24h                    | 不标注（默认高）                                     |
| **中**   | CMA+JMA分歧100-300km 或 距登陆24-72h         | 标注"（置信度：中）"                                 |
| **低**   | 多模型分歧>300km 或 距登陆>72h               | 标注"（置信度：低，路径仍有较大不确定性）"           |
| **降级** | **国际源全部不可用（国内服务器部署）** | 标注"（置信度：中，国际源未获取，交叉验证覆盖降低）" |

### 搜索结果新鲜度检查

- WebSearch 结果中 **排除超过24小时的旧预报**（台风预报变化快，旧预报无参考价值）
- 优先选择搜索结果中标注"X小时前""今日"的结果
- 如果搜索结果全部超过24小时，在报告中标注"（近期预报数据获取受限）"

### 何时停止搜索、开始判断

**核心原则：不要为了追求100%确定而无限搜索。台风预报本身就是概率性的。**

满足以下任一条件即可停止搜索、输出判断：

1. ✅ 已完成第一层（3次搜索）且CMA与JMA共识明确
2. ✅ 已完成第一+二层（5次搜索）且无重大分歧
3. ✅ 已完成全部三层（7次搜索）——搜索上限
4. ✅ 台风距登陆<24h（短临预报可信度高）

**输出判断时的诚实原则：**

- 有把握的结论直接说
- 不确定的明确标注"不确定"和可能的区间
- 绝不用确定性语气描述不确定的事情
- 宁可说"两种可能，概率各半"，不要装作只有一种可能
- 分歧本身就是有效信息——告知用户"权威机构之间存在分歧"比假装统一更有价值

### ⚡ 新台风假消息鉴别协议（内容农场"新台风来袭"类文章激增时必查）

**背景**：台风停编+新台风展望密集期，内容农场AI生成"新台风已登陆/今夜登陆/官方发预警"类假消息，并联动编造"铁路停运/机场取消"细节。**必须用三重否决核验，全部通过才可采信：**

1. **编号核验**：查CMA台风网台风列表（WebFetch typhoon.nmc.cn）——假消息常编错编号（如"第11号杨柳"，实际2611为海神），与已知编号体系（案例数据中连续编号）矛盾即否决
2. **官方预警核验**：查中央气象台当日预警全文（中国天气网 news.weather.com.cn）——若官方暴雨/台风预警未提及该"新台风"，即否决
3. **实况交叉核验**：查受影响地区官方天气预报（如"14级台风已登陆台东"则台湾城市预报不应是"多云"）——实况矛盾即否决

**判断规则**：三项中任一项矛盾→判定假消息，报告中设"不实信息核验"小节说明核验路径（HOW），不采信（置信度：高）。来源域名可疑（内容农场聚合站，如 gzylhyzx.com 类）+发布时间逻辑矛盾（发稿时间早于引用的预警时间）是强信号。

## 预测变化规律

### 登陆时间收敛（实测量化）

| 提前量  | 时间误差 | 地点误差 | 强度误差 |
| ------- | -------- | -------- | -------- |
| T+4天   | ±12小时 | ±300km  | ±3级    |
| T+2天   | ±6小时  | ±150km  | ±2级    |
| T+1天   | ±3小时  | ±50km   | ±1级    |
| T+1小时 | 分钟级   | 乡镇级   | ±0.5级  |

关键规律：登陆时间预报在"下午→夜间→凌晨→半夜"之间反复横跳，这不是预报失误，
而是副热带高压东西摆动导致的真实不确定性。仅在登陆前48小时内区间才稳定在"夜间/半夜"。

### 风圈半径急剧缩小（关键发现）

七级风圈可在登陆前24小时内从480km缩至150km——缩小70%。这是内陆城市预报与实际
偏差最大的来源，无法提前24小时以上预测。

"闭眼"期（台风眼被云层填满）是能量向外扩散的信号，风圈会扩大——不代表威胁减弱。

### 近海强度衰减

四件套：长途奔袭+近海海温低+干冷空气入侵+台湾地形摩擦。登陆强度通常比巅峰
低2-3级，最后24小时衰减最剧烈。

### 远距离水汽副作用（浪卡 2617 案例）

"对我国无影响"≠"完全无害"——远洋东北行/东行的无影响型台风，其水汽输送带可
在距中心 1500km+ 外制造极端降雨（浪卡 2617 案例：8/14 日本关东千叶县 1h 115mm、
12h 341.5mm、山区最大 519mm，破当地 8 月整月雨量纪录，为浪卡远距离送水所致）。
追踪无影响型台风时，需记录其与高纬度系统的水汽互动，不可一句"无影响"带过。

### 路径北漂

北向分量每天约增加一个方向级：西→西北西→北西→北北西。出现"北北西"时
北上趋势确立，登陆点将北调。

### 预报偏差模式

- 沿海城市：预报基本准确（±0-1级）
- 内陆城市：预报系统性偏保守（预报比实际强1-3级），风圈缩小后尤为突出

## 影响评估公式

### 风圈与距离关系模型

```
if 距离 < 十二级风圈_min:    核心破坏区，风力12级+
elif 距离 < 十级风圈_max:    严重，风力10-11级
elif 距离 < 七级风圈_max:     显著，风力7-9级
elif 距离 < 七级风圈_max×1.3: 外围影响，风力5-7级
else:                         基本无影响

内陆衰减修正：以上风力 × 0.6-0.7（距海岸>150km的城市）
```

### 建筑高度修正

```
F_高楼 = F_地面 × (1 + 0.008 × H)
```

H为高度（米）。6楼（约18m）：×1.12。100m+：×1.25-1.40。
依据：《建筑结构荷载规范》GB 50009。

### 内陆风力衰减

| 距海岸距离 | 衰减率 |
| ---------- | ------ |
| 0-50km     | 10-20% |
| 50-150km   | 20-30% |
| 150-300km  | 30-40% |
| >300km     | 40-50% |

台风近海正在减弱时，额外加10-15%衰减。

### ⚠️ 交通停运信息验证协议（防止预测误报为事实）

**交通停运信息是用户最依赖的关键决策信息，容不得模糊。核心原则：已发布 vs 预测必须严格区分，禁止把预测写成事实语气。**

#### 信息状态三级分类（每条交通信息必须归类）

| 状态                | 定义                                                          | 标注             | 举例                                                                    |
| ------------------- | ------------------------------------------------------------- | ---------------- | ----------------------------------------------------------------------- |
| **已发布**    | 官方机构（12306/上海铁路局/航空公司/机场/地铁公司）已正式公告 | `[官方已发布]` | "上海铁路局8月8日10时公告：8月9日杭深线停运"                            |
| **预警/提示** | 官方发布的影响预警或出行提示，但**未宣布停运**          | `[官方预警]`   | "深航出行提示：7日午后华东机场阵风13-18m/s，提醒旅客关注动态"（≠取消） |
| **预测/推断** | 基于气象预报、历史规律、触发条件的推算，**非官方公告**  | `[预测]`       | "按巴威规律，预计8日晚-9日早发布航班停运公告"                           |

#### 输出铁律

1. **只查官方渠道确认停运状态**：12306（列车）、航空公司官网/短信（航班）、机场官方（机场）、上海局集团公众号（铁路）。**禁止**仅凭媒体标题或历史规律断定"已停运"
2. **"预计/可能/大概率"必须显式写出**：预测时用 `预计X时发布`、`可能停运`、`大概率取消`，**绝不使用** `已停运`、`已取消`、`将全天停运` 等确定语气描述预测内容
3. **先报状态，再报预测**：输出顺序 = ①当前已发布状态（如"暂无停运公告"）→ ②官方预警/提示 → ③预测时间窗（标注[预测]）
4. **搜索时同时查"停运公告"和"出行提示"**：两者不可混淆——"出行提示"只是预警，不是停运事实
5. **时间敏感性**：预测的时间窗要标注"预计"和依据（如"按巴威案例T-27h规律"），并说明复查时间点

#### 报告模板中的标准写法（交通部分）

```
**交通状态**：
- [官方已发布] 高铁：上海铁路局8月X日X时公告，X月X日X线停运（如已发布）
- [官方已发布] 航班：萧山机场X月X日取消X班（如已发布）
- [官方预警] 深航出行提示：X日午后华东机场阵风X级（≠取消）
- [预测] 按历史规律预计X日X时前后发布停运公告（基于巴威T-27h案例，置信度：中）
- 当前状态核实时间：X月X日X时（重要！标注核查时刻）
```

#### 误报案例复盘

- **案例（白海豚，2026年8月）**：曾将预测写成"萧山机场8/9大量取消"——核查发现萧山机场无任何取消公告，仅航司发布"出行提示"（预警≠取消）；上海铁路局亦未发布停运公告。**教训：预测必须标注[预测]，禁止写成已发生事实。**

## 降雨评估框架

风圈半径可以估算风力影响范围，但降雨不行——降雨取决于地形、水汽输送和台风结构不对称性。

### 降雨预测因子

| 因子     | 影响                           | 多台风实测（示例：巴威(2609)等） |
| -------- | ------------------------------ | -------------------------------- |
| 地形抬升 | 迎风坡增雨2-3倍                | 淳安山区292mm vs 杭州市区23mm    |
| 台风象限 | 东北象限（危险半圆）雨最强     | 确认城市在台风哪一侧             |
| 外围雨带 | 远离中心也能触发强降雨         | 永嘉外雨带251mm                  |
| 水汽输送 | 西南季风可在台风过后维持暴雨   | 风力结束后降雨可延12-24h         |
| 地形阻挡 | 山脉可阻滞雨带导致局地极端降雨 | 临安81mm（距登陆点350km）        |

### 降雨估算方法

```
步骤1：获取省级气象台官方预报（P1来源）
步骤2：如城市在山区，预报降雨量×1.5-2.5
步骤3：检查地形朝向——迎风坡降雨更多
步骤4：估算小时雨强：台风雨通常20-50mm/h，地形增雨可达80mm/h
步骤5：与历史相似路径台风降雨数据对比
```

### 降雨风险阈值

| 24h降雨量 | 风险等级  | 影响                                   |
| --------- | --------- | -------------------------------------- |
| <25mm     | 🟢 低    | 可忽略                                 |
| 25-50mm   | 🟡 中     | 路面积水、能见度下降                   |
| 50-100mm  | 🟠 高     | 低洼区域积水、排水超载                 |
| 100-250mm | 🔴 严重   | 城市大面积积水、河道水位上涨、滑坡风险 |
| >250mm    | 🔴🔴 极端 | 重大洪涝、强制撤离、基础设施损坏       |

## 风暴潮评估

风暴潮是海水位异常升高，与降雨独立。

关键参数：

- 中心气压越低→增水越高（经验：气压每降1hPa≈水位升1cm）
- 风向朝岸→增水在海岸堆积
- 潮汐时机：高潮时登陆=最坏情况

| 增水高度  | 风险                 |
| --------- | -------------------- |
| <50cm     | 低                   |
| 50-100cm  | 中——沿海积水开始   |
| 100-200cm | 高——沿海广泛淹没   |
| >200cm    | 极端——严重沿海破坏 |

查询：国家海洋预报台获取官方风暴潮预报。

| 风险因子          | 评估                         |
| ----------------- | ---------------------------- |
| 低洼道路/下穿通道 | 查询该城市已知易积水点       |
| 排水能力          | 老城区低于现代标准           |

## 双台风效应（藤原效应）

两个台风相距约1500km以内时：

| 间距        | 影响                       |
| ----------- | -------------------------- |
| >1500km     | 基本无交互                 |
| 1000-1500km | 弱影响，可能改变移速       |
| 500-1000km  | 中等：绕中点旋转，路径偏转 |
| <500km      | 强：合并或路径显著改变     |

关键：较小/较弱的台风受影响更大。较大的一方可能减速或停滞。
追踪主台风时务必检查是否存在第二个热带系统。

搜索："[台风A] [台风B] 双台风 藤原效应"

## 城市快速评估框架

对于案例数据中没有内置参照的城市，使用以下系统性评估方法。每一步都有明确的输入、操作和输出。

### 步骤1：获取城市坐标与地理特征

- 搜索或检索该城市的经纬度
- 确认城市类型：沿海（距海岸<50km）/ 近海（50-150km）/ 内陆（>150km）
- 确认地形特征：平原 / 丘陵 / 山区 / 沿江河谷
- 确认城市规模：超大城市（热岛效应显著）/ 中型城市 / 小城市

### 步骤2：计算与台风中心距离

- 用城市经纬度和台风中心经纬度计算直线距离（近似公式：1°纬度≈111km，1°经度≈111km×cos(纬度)）
- 标注城市在台风中心的方位（如"位于台风中心北偏西约350km"）

### 步骤3：确定影响区域

- 将距离与当前风圈半径对比，使用风圈与距离关系模型判定影响等级（核心破坏区/严重/显著/外围/基本无影响）
- 确认城市处于台风的哪个象限（NE象限=危险半圆，SW象限=相对安全）

### 步骤4：估算风力

- 基准风力 = 当前台风中心附近最大风力 × 风圈距离衰减系数
- 内陆修正 = 基准风力 × (1 - 内陆衰减率)（使用内陆风力衰减表）
- 建筑高度修正 = 内陆修正 × (1 + 0.008 × H)（如用户指定楼层）
- 输出：预测阵风等级和对应的陆地影响（如"8级=可折断树枝，9级=可掀翻临时搭建物"）

### 步骤5：估算降雨

- 搜索该城市的省级气象台官方预报
- 如城市在山区且位于迎风面：预报值 × 1.5-2.5
- 如城市在台风NE象限：降雨偏强
- 输出：预测24h降雨量和对应的风险等级（低/中/高/严重/极端）

### 步骤6：评估次生灾害

- 如降雨>100mm且城市有山区：山洪/地质灾害风险
- 如降雨>50mm且城市排水系统老旧：城市内涝风险
- 如城市沿海且增水>100cm：风暴潮风险
- 输出：标注是否需要关注的次生灾害类型

### 步骤7：评估交通影响

- 距台风中心<300km：查该城市所在铁路局公告
- 距台风中心<200km：查该城市地铁运营公告
- 距台风中心<300km：查该城市最近机场航班状态
- 输出：高铁/地铁/航班/高速的预计影响

### 步骤8：检索本地应急响应

- 搜索"[城市名] 防台风应急响应 [日期]"获取本地响应等级
- 搜索"[城市名] 台风黄色预警/橙色预警/红色预警"获取预警状态
- 输出：当前应急响应等级和已公布的本地措施

### 步骤9：综合风险评级

对以下维度分别评分：

- 风力风险：🔴/🟠/🟡/🔵
- 降雨风险：🔴/🟠/🟡/🔵
- 洪涝风险：🔴/🟠/🟡/🔵
- 交通中断风险：🔴/🟠/🟡/🔵
- 综合风险：取各维度最高值

### 步骤10：生成城市评估输出

为每个评估城市输出结构化的影响摘要：

- 城市名称 + 城市类型 + 距台风中心距离
- 预计风力 + 预计降雨 + 风险等级
- 交通影响 + 需要关注的次生风险
- 1-2句行动建议

### 城市评估效率原则

- 一级优先城市：全流程1-10步执行
- 二级优先城市：执行1、3、4、5、7、9步
- 三级城市：执行1、3、4、9步（快速评估）
- 单次追踪周期中最多评估5个城市，超过则优先评估前5个

## 停编与收官处理协议（台风生命周期终点）

当主追踪台风停止编号（中央气象台发布"停止编号"公告）时，按以下流程处理：

**三种收官场景：**

| 场景                                 | 处理                                                                                                                                          |
| ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------- |
| 主台风停编，但仍有其他台风编号在追踪 | 生成**收官报告**：①停编公告+生命周期复盘 ②全周期实测数据（官方评估报告补录）③残涡/残余影响预报 ④其他活跃台风状态 ⑤预测vs实际复盘表 |
| 主台风停编，无任何其他编号           | 简要说明"当前无活跃台风追踪中"，无需生成报告                                                                                                  |
| 主台风停编，但残涡仍影响重点城市     | 报告重心转向**残涡+冷空气联合降雨**（落区随残涡摆动，逐日滚动修正），而非台风本体                                                       |

> **场景判定优先级**：定时任务指令若写"如无活跃台风（无编号在追踪中）则简要说明即可"，**当主台风停编但残涡/残余降雨仍实质影响重点城市（官方山洪/地灾/暴雨预警仍在生效）时，应执行场景三生成收官报告，而非仅简要说明**——"无活跃台风编号"≠"影响结束"，用户依赖报告做出行/安全决策。判断依据：以**降雨/山洪/地灾类预警是否在生效**为准，不是台风编号有无。

**关键准则：**

- **停编≠影响结束**：判断"台风影响结束"以降雨/强对流/山洪/地质灾害类预警解除为准，不是台风停编公告本身
- **残涡回旋滞留模式**：残涡在陆上省际交界区滞留+冷空气结合会开启第二轮强降雨（如鄂豫皖交界案例），落区不确定性大，需12小时级滚动修正
- **双台风水汽接力**：相邻台风即使不登陆我国，其东侧水汽输送带也可能维持残涡造雨能力——评估残涡影响时必须检查相邻台风水汽通道是否仍在工作
- **收官必做**：补录官方评估报告数据（面雨量、单站极值、阵风纪录）作为预测vs实际对比基准；补全预测演变表"实际"列；总结本轮独特性和新教训

## 空窗期强对流触发判定（条件触发，详细协议见 references）

无活跃台风且无残涡影响时，若省/市气象台趋势预报含"阵雨或雷雨/局地短时暴雨"类表述，或用户询问日常强对流/下雨问题——**加载 `references/empty_window_convection_protocol.md`** 执行三要素简评（能量/水汽/抬升），输出"强对流潜势**五档等级🟢🔵🟡🟠🔴**（🟢=无风险正常，🔵🟡🟠🔴对应官方蓝/黄/橙/红预警级）+时段窗口+精确落区以官方短临预警为准"；铁律：**常规天气预报渠道（官方App/网页）显示的"无雨"不代表安全**——午后对流局部突发，官方预警发出到降雨可能仅剩 20min~2h。**空窗期强对流属季风槽/热对流机制，非台风系统，评估须与台风框架分开。** 定时任务（气象研判双模式）在空窗期自动执行该文件"定时任务执行规范"节（模式三：空窗期天气研判，聚焦杭州西湖区）。

## 残涡追踪协议

> **背景**：白海豚（2613）停编后，残涡仍制造了连续 4 天强降雨（河南溃口、太湖流域性大洪水、苏南/浙北第二波极端暴雨），"无编号=影响结束"的直觉判断会漏掉最危险的后半程。本协议将"追踪残涡影响"升级为"追踪残涡本身"。

**核心认知（三条铁律）：**

1. **停编后残涡可"重组"并二次增强**：已停编的残涡在有利条件下（充足水汽+冷空气交汇+湖面/海面增湿）可在陆地边缘重新组织低层低压中心，制造不低于台风本体的强降雨（白海豚案例：8/15 晚太湖附近重建松散低压中心 → 苏南/浙北第二波暴雨，无锡宜兴 279mm、太湖流域性大洪水）
2. **"无编号"≠"无影响"**：残涡影响期恰好处在台风编号清零状态，定时任务若以"有无编号"为开关会漏报（白海豚 8/13-8/16 期间无活跃编号，但河南/浙江/苏南持续强降雨+洪水）
3. **残涡路径不是"单向消散"**：残涡可滞留、回旋、**回折转向**（白海豚：西北行→鄂豫皖滞留→折向东移苏南/太湖→自上海入海）——需像追踪台风本体一样追踪残涡中心位置与移向

**追踪触发条件（替代"无编号即停"）：**

| 条件                                                             | 动作                               |
| ---------------------------------------------------------------- | ---------------------------------- |
| 有活跃编号台风                                                   | 正常追踪（台风本体）               |
| 无编号，但残涡中心仍在我国境内或邻近海域                         | **启动残涡追踪**（每12小时） |
| 无编号，但残涡仍实质影响重点城市（官方暴雨/山洪/地灾预警在生效） | **启动残涡追踪**（每12小时） |
| 无编号、无残涡、无生效预警                                       | 简要说明"当前无活跃台风追踪中"     |

**追踪内容（每12小时）：**

1. **残涡定位**：查 CMA 天气图/省市气象台公报中"残余低压/残余环流"位置描述；无直接定位时用降雨落区反推（强降雨中心即残涡水汽辐合区）
2. **移向判断**：连续两次定位对比得出移向（重点识别"回折转向"——与先前方向相反即警报升级）；对照高空槽位置判断引导气流
3. **重组信号监测**（出现任一即升级关注，标注"残涡可能二次增强"）：
   - 卫星云图上对流云团在残涡中心附近重新组织（zoom.earth 红外/可见光）
   - 低层低压环流再现（雷达拼图可辨识气旋性环流）
   - 暖湿输送带（西南季风/东南季风）重新接通
   - 冷空气与残涡暖湿气流交汇带重新建立（降雨落区出现东西向对峙带）
4. **影响评估**：按"残涡+冷空气联合降雨"框架逐日滚动修正落区；叠加流域洪水滞后效应（太湖/杭嘉湖高水位回落需1-3天甚至1-2周，退水期堤防风险）
5. **出境验证**：残涡预报出境时，用**相邻国家气象机构交叉验证**（韩国气象厅 KMA / 日本气象厅 JMA——会跟踪残涡低压穿越本国路径，是"残涡是否真出境"的独立验证源；白海豚案例：KMA 确认"上海附近低压穿过黄海影响韩国"）

**收官判定（替代"停编即收官"）：**

- 残涡完全消散（无低压环流）且影响区域无生效预警，或残涡中心已移至我国影响范围外且不再回折 → 正式收官
- 收官报告必须补录：残涡全路径（含转向点）、重组事件记录、第二波暴雨实测、预测vs实际复盘

**与近海系统协议联动**：残涡也属"无/弱编号但可能实质影响"对象，与近海未编号扰动同构。跟踪残涡时的"多源反推法"（定位→移向→重组→影响）见 `references/nearsea_system_protocol.md` 的"通用多源反推跟踪法"节；两个协议共享该方法论，不重复建设。二者区别：本协议聚焦"停编后"阶段，近海系统协议聚焦"未成名"的生成/近海阶段。

**自动化任务执行要求（更新版，与上述触发条件一致）：**

```

   按"残涡追踪协议"生成收官期研判报告（场景三），而非仅简要说明
```

## 追踪周期

每个追踪周期（台风距登陆48h内时通常每4-6小时一次）：

### 第一层：基础搜索（3次，覆盖~8源）

1. WebFetch CMA台风网 → 实时位置/强度/风圈
2. WebSearch "[台风名] [日期] 最新路径 登陆" → CMA公报+省市气象+权威媒体
3. WebSearch "[台风名] 信欣 路径 解读" → 分析师解读

**→ 此时即可做基础判断。如距登陆>72h或CMA路径稳定，可跳到判断阶段。**

### 第二层：交叉验证（距登陆<72h追加，2次，覆盖~6源）

4. WebSearch "[台风名] JMA JTWC 路径 分歧" → 独立验证
5. WebSearch "[用户问的城市] [日期] 台风 风力 降雨 地铁 高铁 停运" → 城市影响

### 第三层：深度分析（条件触发，1-2次，覆盖3-5源）

6. 【条件】CMA与JMA分歧>300km：WebSearch "[台风名] tropicaltidbits ECMWF GFS"
7. 【条件】双台风/沿海活动/航班/结构判断：按需搜索

### 判断阶段

8. 按冲突解决协议取舍，确定各维度结论
9. 标注置信度（高/中/低）
10. **交通停运信息执行验证协议**（见"交通停运信息验证协议"）：区分[官方已发布]/[官方预警]/[预测]三级，预测必须用"预计/可能"语气，标注核实时间
11. 按输出模式回复：默认模式=直接文本回复；文件模式=生成 .md 报告
12. 追加到workspace每日日志

- 第一层3次搜索 = 充分条件，足以输出基础判断
- 第二层追加后覆盖14个源，足以输出详细研判
- 第三层追加后覆盖17-19个源，用于高不确定性场景
- **总计5-7次搜索，覆盖17-19个信息源**——不是5-7个源
- 超过7次搜索 = 效率问题，应停止并输出已有判断

### 输出格式硬性规范（所有输出必须遵守，不依赖读取 references）

以下规范适用于**所有输出**（PC端和移动端一致），是移动端可读性的关键：

**1. 表情符号白名单（仅允许这些）**

- `✅` / `❌` / `⚠️` — 状态判断
- `🔴 🟠 🟡 🔵` — 风险等级（放在文本后，如 `杭州：9日大到暴雨（🟠）`）
- `**加粗**` — 关键数字、结论强调

**1b. ⚠️ 预警等级颜色映射（必须与官方预警级别严格对应，禁止混淆）**

**中国气象预警四色等级（蓝/黄/橙/红）→ 表情颜色：**

| 官方预警级别               | 表情   | 含义           |
| -------------------------- | ------ | -------------- |
| **蓝色预警**（最低） | `🔵` | 注意，一般影响 |
| **黄色预警**（中级） | `🟡` | 注意，较大影响 |
| **橙色预警**（次高） | `🟠` | 防御，严重影响 |
| **红色预警**（最高） | `🔴` | 紧急，极端影响 |

**对应关系速记**：蓝色🔵 → 黄色🟡 → 橙色🟠 → 红色🔴（颜色由浅到深，与官方预警色环一致）

**铁律：**

- 标注官方预警级别时，**必须**用上面的映射——`台风黄色预警（🟡）`、`暴雨橙色预警（🟠）`、`山洪红色预警（🔴）`、`台风蓝色预警（🔵）`
- **禁止**把黄色预警写成🟠、橙色预警写成🔴（历史上多次混淆）
- 风险等级（评估结论）与预警级别（官方发布）是两套标注：风险等级用🔵🟡🟠🔴表示"低/中/高/严重"，预警级别同样用🔵🟡🟠🔴表示"蓝/黄/橙/红"——两者颜色一致、含义不同，文字必须写清是"预警"还是"风险"
- 报告表格中"级别"列直接写 `🔴 红色`、`🟠 橙色`、`🟡 黄色`、`🔵 蓝色`，统一格式

**2. 表情符号黑名单（禁止使用）**

- 装饰性气象 emoji：`🌪️ 🌧️ ⛈️ 💨 🌀`
- 图标类 emoji：`📍 🧭 🎯 🌆 🚦 🔁 ⏰ 🗓️`
- 其他装饰：`✨ 🎉 👍 👌`

**3. 排版规则**

- **标题不用 emoji 前缀**：直接写 `台风晚报·白海豚（2613）— 8月6日20时`
- **段落小标题必须加粗**：字段名用 `**加粗**` 与内容区分，格式 `**位置**：26.6°N...`。固定字段：`**位置**`、`**强度**`、`**移动**`、`**登陆预测**`、`**预警**`、`**城市影响**`、`**交通状态**`、`**行动建议**`、`**下次复查**`
- **列表同层级统一**：城市影响/行动建议等有顺序的用 `1. 2. 3.` 有序；预警/交通状态等并列短项用 `-` 无序；同一段落内只用一种标记，禁止混用；字段名本身不作为列表项
- **换行用真实换行**（段落间空行），**禁止输出字面 `\n` 字符串**（飞书会显示为乱码）
- **度符号统一用 `°`**，如 `26.7°N`；风速 `42m/s`

### 适配原则

1. **结论先行**：前1-3行必须是关键发现，让用户在消息预览就能看到
2. **表格→文字列表**：表格在消息通道中渲染差。将表格改为`[字段]: [值]`格式的键值对列表
3. **单条消息≤500字**：超出则拆分为多条。每条消息自包含（假定用户可能不按顺序阅读）
4. **不引用文件路径**：移动端无法打开文件。需要完整报告时，将核心内容直接嵌入消息
5. **行动导向**：以明确的行动建议结尾（而非"详见报告"）
6. **紧急标记**：如风力或将登陆时间在12h内，消息开头加 `⚠️` 标记

**速报模板**：台风名/位置/强度/登陆预测/城市影响/风险等级/行动建议（完整模板见 `references/mobile_channel_guide.md`）
**上下文恢复**：WorkBuddy→workspace memory；OpenClaw→case_data文件；Other→搜索重建（详见 references）
