# 专业命名技能

按场景生成候选名称，但不要把启发式判断说成已完成的权威核查。

## 工作原则

- 先识别场景：中文个人名 / 英文个人名 / 公司品牌名。
- 先补齐必要输入；缺关键条件时，一次最多提 3 个最关键问题。
- 只读取当前场景需要的 reference，不加载无关资料。
- 输出至少 5 个候选名，并给出简短释义、适配理由、风险提示、推荐等级。
- 把用户最新约束视为当前唯一有效约束，重新生成完整名单，不复用旧名字。
- 默认优先规避高重名、高爆款模板和仅换一字/一词根的套路候选。
- 同一轮候选中，至少覆盖 3 种不同结构或构词路径；除非用户明确要求，否则不要让大多数候选共享同一核心字或同一英文词根。

## 不要过度承诺

- 不要声称已完成正式商标检索、法律检索、姓名学认证或全球俚语穷尽核查。
- 把商标、侵权、俚语、方言、文化歧义相关判断表述为“风险提示”或“启发式规避”。
- 当信息不足以支撑严谨判断时，明确说“不确定”并提示缺什么信息。

## 场景路由

### 中文个人取名

先读取 `references/chinese-naming-rules.md`。

优先补齐以下信息：

- 必需：姓氏、性别、期望寓意
- 推荐：单双名偏好、五行喜用、音韵偏好
- 可选：辈分字、指定包含字、指定规避字、出生信息（仅当用户主动要求按出生信息辅助判断）

若缺少姓氏，不要声称已核查全名谐音或完整音律效果。

### 英文个人取名

先读取 `references/english-naming-rules.md`。

优先补齐以下信息：

- 必需：性别偏好、期望内涵
- 推荐：姓氏或常用中文姓氏拼音、使用地区/语境、文化来源偏好
- 可选：音节长度、首字母、规避字母组合、是否接受中性名

若缺少姓氏，不要声称已核查与姓氏连读的流畅度。

### 公司 / 品牌命名

先读取 `references/company-naming-rules.md`。

优先补齐以下信息：

- 必需：细分行业、品牌风格、目标市场/注册地区
- 推荐：商标类别或主要业务范围、目标客群、是否需要中英文双名
- 可选：命名形式偏好、指定关键词、域名偏好、禁用词

若缺少目标市场/注册地区，默认先补问；只有当用户明确要求“先给灵感”“先出草案”“先随便看看方向”时，才允许输出草案。

若缺少注册地区或类别，不要声称商标风险低，只能给出初步规避建议。

## 约束优先级

按以下顺序决策：

1. 硬性禁用约束
2. 最新用户明确约束
3. 场景 reference 中的自检规则
4. 风格与传播性优化
5. 多样性与候选数量
6. 低重名与区分度优化

若约束彼此冲突，先指出冲突，再请求用户放宽；不要强行拼凑不合格名字。

典型冲突包括：

- 指定包含字与指定规避字冲突
- 既要求首字母固定，又要求规避该字母组合
- 既要求极短，又要求包含多个固定元素
- 公司名既要求描述性极强，又要求高商标显著性

## 生成流程

### 1. 收集信息

- 仅提问当前最缺、最影响结果的 1-3 个问题。
- 若用户明确说“先给我灵感”，可在标注“草案”后给出初步候选，但仍要指出缺失信息带来的限制。
- 公司 / 品牌命名场景中，若缺少目标市场/注册地区，优先把它作为补问项；除非用户明确要“草案”，否则不要直接进入正式命名输出。

### 2. 读取规则

- 中文个人名：读取中文 reference 的五行、音韵、避讳、自检清单
- 英文个人名：读取英文 reference 的词源、性别、发音、自检清单
- 公司品牌名：读取公司 reference 的行业调性、风格、商标规避、自检清单

### 3. 生成候选

- 默认输出 5-8 个候选名。
- 保持候选之间有差异，不要只换一个字或一个词根。
- 优先给出可传播、可解释、可继续迭代的名字。
- 若输出独创英文名、英文缩写名或拼音变体名，必须能说明构词依据；不能只给无解释的字母组合。
- 若 reference 标注某些字、词根、模板为高重名风险，默认降权；只有用户明确偏好“主流、热门、经典爆款”时才允许提升优先级。
- 中文名优先混合不同语义轴（如品德 + 自然、光明 + 志向、古典 + 灵动），不要批量生成“梓/轩/涵/熙”式同质化组合。
- 英文名优先混合不同来源、音节长度和气质层次，不要整组都落在同一热门榜单风格。
- 公司 / 品牌名至少混合 3 类命名路径（描述型 / 意象型 / 独创型 / 中西融合型 / 缩写型中的任意 3 类），避免候选全是同一种行业通用词拼接。

### 4. 自检筛选

每个候选都至少做以下检查：

- 是否满足用户显式约束
- 是否满足场景自检清单
- 是否存在明显负面含义、拗口发音、过强品牌近似或低级谐音风险
- 是否仍有无法确认的风险点
- 是否与同轮其他候选过于相似（只换一字 / 一音节 / 一词根的应淘汰）
- 是否落入 reference 标注的高重名、高泛化、高行业套话风险

### 5. 输出结果

先给出推荐结论，再给完整候选名单。

## 输出格式

根据场景使用对应标题；每个候选都包含：

- 名称
- 20 字以内简释
- 适配理由
- 风险提示
- 推荐等级（高 / 中 / 低）

优先采用以下模板。

### 中文个人名

```markdown
## 中文个人名

**优先推荐：**
- **姓名** — 一句话概括最强理由

1. **【姓名】**
   - 释义：20字以内
   - 适配：寓意 / 音律 / 五行 / 辈分等
   - 风险：如“未提供姓氏，未核查完整谐音”
   - 推荐：高
```

### English Personal Names

```markdown
## English Personal Names

**Top Pick:**
- **Name** — strongest reason in one sentence

1. **【Name】**
   - Meaning: within 20 Chinese characters or short English phrase
   - Fit: origin / tone / ease of use / style
   - Risk: e.g. "surname missing, full-name flow not checked"
   - Recommendation: High
```

### 公司品牌名

```markdown
## 公司品牌名

**优先推荐：**
- **中文名 / English Name** — 一句话概括最强理由

1. **【中文名 / English Name】**
   - 释义：20字以内
   - 适配：行业 / 风格 / 客群 / 传播性
   - 构词：若英文名非通用词，说明词根 / 拼音 / 含义映射 / 发音设计
   - 风险：如“未做正式商标检索，仅为启发式规避”
   - 推荐：高
```

## 风险提示写法

优先使用以下表述：

- “未提供姓氏，无法完整核查全名连读效果”
- “未提供注册地区 / 类别，商标风险仅做初步规避”
- “未提供注册地区，以下仅为灵感草案，不作为正式命名建议”
- “该名字词源积极，但不同地区使用热度可能不同”
- “当前判断基于常见语义与命名经验，不替代正式法律检索”

不要使用以下表述：

- “已确保不侵权”
- “已确认可注册”
- “已完成全球俚语排查”
- “绝对适合”

## 失败分支

出现以下情况时，不要硬凑答案：

- 条件冲突导致可行名字不足
- 用户要求违反硬性禁用规则
- 公司命名要求“低风险注册”但不给地区和类别

此时执行：

1. 明确说明为什么当前条件不足或冲突
2. 给出最小放宽建议
3. 若用户接受，再重新生成完整名单

## 迭代规则

- 用户新增任何约束后，废弃旧名单，重新生成完整名单。
- 若用户要求“保留某两个候选继续优化”，只把它们作为灵感来源，不直接复用不合新约束的旧结果。
- 若用户只要“更偏稳重 / 更国际化 / 更有书卷气”这类风格微调，保持场景与硬约束不变，整体重生候选。
