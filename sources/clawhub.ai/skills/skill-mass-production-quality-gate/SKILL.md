# 量产质量门与遏制升级技能

## 一、角色定位（给谁用）

本技能服务于**量产阶段**的质量拦截与异常遏制，目标用户为：

- **质量经理 / 质量主管**：负责量产现场日常质量拦截标准、升级决策与资源调度。
- **SQE（供应商质量工程师）**：负责来料/供应商端异常在客户端或供应商端的遏制与升级。
- **制程质量工程师（PQE）/ 线体质量负责人**：负责产线异常围堵、隔离与批次管控。

**岗位画像（典型）**：用户正站在量产现场或客服质量接口，手里有一批异常数据、一个不合格批次、或一条客户投诉，需要快速判断"该不该升级、升到哪一级、先围堵什么"。用户要的是**可执行的标准动作和一张能跟踪的看板**，而不是空泛的管理原则。

> 重要区分：本技能只管**量产阶段**的质量拦截与遏制升级，**不替代 NPI 新品质量门（npi-quality-gate）**，也**不替代 Safe Launch 安全投产**（新品爬坡期的强化监控）。三者阶段不同、触发不同，切勿混用。

## 二、使用场景（工作环节 / 触发条件 / 手头材料）

| 场景 | 触发条件 | 用户手头通常有的材料 |
|------|----------|----------------------|
| 产线异常拦截 | 工序检出批量不良 / 连续超差 / 防错触发 | 不良现象、不良率、批次号、控制计划编号 |
| 客户端投诉遏制 | 客户端反馈批量异常 / 退货 / 停线 | 客诉描述、缺陷照片、涉及批次、发货范围 |
| 供应商来料异常 | IQC 检出批量不合格 / 在线暴露来料缺陷 | 检验报告、供应商批次、缺陷数据 |
| 批次隔离与围堵 | 已识别风险批次，需要界定影响范围 | 批次追溯链、库存数量、在途/在制数量 |
| 升级决策 | 异常超出本岗处置权限或范围 | 当前处置进展、已围堵范围、损失初估 |

**激活触发词**：量产质量门、质量拦截、遏制、围堵、异常升级、批次隔离、停线、客户投诉遏制、供应商遏制、质量升级、风险升级、质量看板。

## 三、解决的问题（业务痛点，非动作）

1. **升级无标准**：同一类异常，A 线升级、B 线不升，凭经验拍脑袋，管理层无法横向对比。
2. **遏制不闭环**：围堵动作做了，但"影响范围算清了吗、库存清点了吗、客户处排查了吗"常漏项，事后翻车。
3. **围堵动作零散**：谁隔离、隔离到哪、标识怎么贴、追溯链怎么拉，没有统一清单，容易漏批次。
4. **看板缺位**：异常升上去后缺乏一张可跟踪的看板（级别/责任人/截止/状态），闭环靠口头催。
5. **与 NPI / Safe Launch 混淆**：把量产异常当成新品门禁去套，或把爬坡期 Safe Launch 的新品问题误判为量产问题，处置路径错位。

## 四、能力边界（能做 / 不做 / 输入要求）

**能做**：
- 依据异常分级与升级阈值，给出**该升级到哪一级**的建议与理由。
- 生成标准化的**围堵/升级流程卡**（动作清单 + 责任 + 时限）。
- 生成一张可跟踪的**质量遏制升级看板**（纯文字版 .txt + Markdown .md）。
- 提示常见的围堵漏项（库存、在制、在途、客户端、在修品）。

**不做**：
- 不替代 **NPI 新品质量门**做新品阶段放行评审。
- 不替代 **Safe Launch 安全投产**做爬坡期强化监控策划。
- 不替代正式 **8D / CAPA** 闭环系统（本技能只做"拦截+升级+围堵"这一段；根因与永久对策交由 8D 技能承接）。
- 不代签放行/升级批准（决策与签字由责任人线下完成）。
- 不对异常做根因分析（那是 5why / 8D 的活）。

**输入要求**：
- 至少提供：异常对象（产品/零件/工序）、异常现象简述、涉及批次或范围、初步数据（不良率/缺陷数/损失量）。
- 缺失关键项时，明确标注「待企业补充/待你确认」并针对性追问，不臆造严重度或损失数字。

## 五、交互与角色设定（语气 / 采集方式 / 是否强制交互锁 / 引导深度）

- **语气**：专业、务实、直给。像一名有现场经验的质量经理在带新人，少讲大道理，多给可执行动作。
- **采集方式**：先确认"异常是什么 + 涉及范围 + 现有数据"，再给升级与围堵建议；关键参数缺失时只问最影响判定的 1–2 点（如"这批次在客户端还有多少库存未用"），不发长篇问卷。
- **强制交互锁**：默认**不强锁**。若用户提供信息足够，直接给出建议流程卡与看板；若关键维度（严重度/范围/损失）缺失，则在看板中将该行标「待补充」并提示，不阻断其他部分产出。
- **引导深度**：中等。给出标准动作与升级路径，但不展开根因分析；如用户需要闭环，提示转 8D 技能。

## 六、处理流程

```
步骤1 异常登记
  └─ 记录对象/现象/批次/初步数据（缺项标「待补充」）

步骤2 严重度初步判定
  └─ 按安全/法规/功能/外观/批量 维度定性（仅定性，不替用户决策）

步骤3 影响范围界定（围堵四问）
  ├─ 库存（含待检/合格/隔离）
  ├─ 在制 / 在途
  ├─ 客户端 / 在修 / 已装机
  └─ 追溯链是否完整

步骤4 升级判定
  └─ 对照"升级矩阵"判定升级级别（L1~L4）与触发理由

步骤5 生成围堵/升级流程卡
  └─ 每项动作：做什么 + 谁 + 何时 + 证据

步骤6 生成看板
  └─ 调用 scripts/build_report.py 渲染纯文字版 .txt + Markdown .md 双件

步骤7 闭环跟踪提示
  └─ 提示转入 8D/CAPA 做根因与永久对策；看板状态持续更新
```

## 七、输入输出（格式 + 示例）

**输入（结构化，可由对话抽取）**：

```json
{
  "product": "转向节总成 XZ-203",
  "date": "2026-07-13",
  "abnormal": "螺纹孔位置度超差，装配干涉",
  "batch": "Lot-20260710-A / 共 1200 件",
  "data": "在线检出 35 件不良 / 抽检 200 不良率 17.5%",
  "scope_note": "在制 600、库存 300、客户端已发 200（待补充在客户处用量）",
  "severity_hint": "功能类"
}
```

**输出**：围堵/升级流程卡 + 质量遏制升级看板（纯文字版 .txt + Markdown .md）。看板字段含：异常编号、对象、级别、围堵四问状态、责任人、计划完成、当前状态、升级理由。

> 报告由 `scripts/build_report.py` 渲染；脚本输入为 JSON，内置小样本可直接 `python build_report.py` 跑通产出示例（txt + md 双件，写入当前工作目录，可用 `--out-dir` 指定）。

## 八、内置知识 / 参考清单

**1. 异常分级（定性锚点）**
- 安全/法规类：涉及人身、法规符合性 → 最高优先级，一票升级。
- 功能类：影响核心功能/装配 → 高优先。
- 外观/次要类：仅影响外观或客户体验 → 常规。

**2. 升级矩阵（默认建议阈值，企业可自定义覆盖）**

| 级别 | 触发条件（示例） | 升级对象 | 响应时限（建议） |
|------|------------------|----------|------------------|
| L1 | 单工序可控、无外流 | 线体质量负责人 | 当班内 |
| L2 | 跨工序 / 批量不良 / 在制风险 | 质量经理 | 4 小时内 |
| L3 | 客户端影响 / 停线风险 / 法规 | 质量总监 + SQE | 2 小时内 |
| L4 | 安全/法规/批量召回风险 | 质量总监 + 高管 | 立即（1 小时内） |

**3. 围堵四问（必查清单）**：库存、在制/在途、客户端/在修、追溯链。

**4. 看板状态机**：开放 → 围堵中 → 已升级 → 已遏制 → 转 8D → 关闭。

**参考（区分）**：
- `npi-quality-gate`（NPI 新品质量门）：新品阶段门禁，非量产拦截。
- `Safe Launch 安全投产`（参考技能）：新品爬坡期强化监控，非量产稳态拦截。
- 升级阈值与时限为**通用建议模板**，企业实际阈值见《异常管理程序》「待企业补充」具体数值。

## 九、联动声明（相邻技能，纯提示）

- **npi-quality-gate**：新品阶段门禁评审；本技能是量产阶段拦截，阶段不同，**不回写、不混用**。
- **8d-report-assistant / 8d-report-analyzer**：围堵升级完成后，根因与永久对策移交 8D 闭环。
- **supplier-iqc-analysis**：若异常源自来料，先用其做供应商来料分析，本技能承接客户端/现场遏制。
- **special-characteristic-manager**：若异常涉及关键/重要特性（CC/SC），优先参照其控制级别定升级紧迫度。
- 本技能产物为"建议稿 + 看板"，最终升级批准与签字由企业责任人线下完成。
