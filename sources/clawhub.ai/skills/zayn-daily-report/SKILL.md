# DAILY_REPORT() 日报推进与结果检查

## 职责

只处理单日工作。将事实记录整理为动作、结果、状态、下一步、责任人和期限，减少流水账。读取共享规则：`../shared/reporting/` 下的状态、结果、等待、关闭、优先级和指标定义。

## 运行协议

先解析输入并输出参数状态表；状态只使用：`已命中`、`部分命中`、`缺失`、`冲突`、`待验证`。未达到最低运行条件时只补问或给出明确标注的初步分析。

## 必需参数

汇报日期、岗位或职责、当日工作事项、每项目标、实际结果、当前状态、未完成事项下一步、负责人、截止时间、需要支持。

推荐补充：客户或项目、价值、优先级、内外部反馈、风险、等待天数、重复跟进和继续投入判断。

## 最低运行条件

1. 有明确的当日工作事项。
2. 每个重点事项至少有结果或当前状态。
3. 未完成事项有下一步动作。
4. 等待事项至少明确等待对象。
5. 重点事项不能只有动作描述。

缺少结果或期限时不得猜测，标记缺失并追问。

## 判断规则

1. 将发消息、联系、询问、更新、整理、发送、提醒判为动作，除非有独立结果证据。
2. 将明确回复、范围/预算/交期/付款确认、进入谈判或执行、问题关闭、暂停或退出判为结果。
3. 状态只使用：已完成、有效推进、等待外部、内部阻塞、暂停、退出。
4. 等待事项必须包含对象、原因、开始时间、最晚确认时间、下一次动作和超时处理。
5. 明日目标必须描述要获得的可验证结果，默认不超过 3 个。
6. 兼容销售和非销售岗位；根据岗位替换业务语境。

## 输出结构

1. 参数完整度结论与参数状态表
2. 今日核心结论（不超过 3 句）
3. 今日有效结果：项目、目标、实际结果、状态、业务意义
4. 仍在推进：项目、卡点、下一步、负责人、截止时间
5. 等待与阻塞：项目、等待对象、已等待时间、最晚确认时间、超时动作
6. 今日未形成结果的动作
7. 明日最多 3 个结果型目标
8. 需要管理者支持

## 禁止事项

不得美化流水账；不得把联系、询问、发送或报价数量自动视为成果；不得编造反馈、数据、金额、态度或进展；不得混淆外部等待与内部阻塞；不得保留无截止时间的等待事项；不得隐藏问题；不得把所有未完成事项写成“明天继续”。

## 模板兼容

接受现有日报模板、零散记录或“只检查不重写”。模板负责记录事实，Skill 负责检查、追问、分析和纠偏。
