# 极义GEO

使用官方 `@g1geo/cli` 作为极义GEO 内容处理、品牌可见度检测、分析和自动化任务的统一执行入口。当前可用命令、身份验证流程、输出约定和工作流程均以已安装的 CLI 版本为准。

## 核心能力

- 品牌可见度与 GEO 检测——发起一次结合企业知识的网页端或应用端检测，在限定范围内轮询各问题与平台的进度，获取最终结论，重试失败的检测单元，并分享或导出报告。
- 企业知识与素材——管理产品、企业信息、参考文档、图片素材、图文素材、写作要求和写作配置。
- 问题与文章生产——生成和管理问题集，查看趋势和近期 GEO 检测摘要，基于主题、问题集或文章组直接生成文章，管理手动文章组和恢复任务，以及创建、读取或更新文章。
- 文章检查与改写——检测或修复 AI 痕迹，并预览或应用自然表达改写。
- 文章裂变——基于一篇现有文章、公开网址或本地 Markdown 文件，生成最多十篇纯文本变体，并可按需引用产品的参考文档。
- 分析与监控——生成企业品牌报告，查看整体 GEO 分析，并跟踪可见度趋势。
- 桌面端发布——查看已授权团队、在线桌面设备和发布账号的登录状态；提交文章或图文发布任务；在不接触平台登录凭据的情况下查看、取消、重试或审计任务。
- GEO 媒体发布——分页查看启用中的 3 类 GEO 媒体，可按需仅查看当前高收录媒体；根据精简的选择说明及积分、人民币价格进行选择；提交经用户确认的文章或图文媒体发布任务，同时不暴露上游标识和成本。
- 智能体与持续集成自动化——安全完成身份验证，明确传递产品和发布上下文，发现当前可用能力，监控或取消异步任务，并使用稳定的机器可读结果。

以上能力用于帮助智能体选择正确的极义GEO 业务流程。业务路径选择、安全默认值和结果处理方式以已安装 CLI 提供的指南为准；选定工作流程后，通过已安装 CLI 的帮助信息确认准确语法，并通过身份验证后的服务端能力信息确认功能当前是否可用。

## 开始使用

如果 `g1geo` 不可用，或者已安装版本不支持 `g1geo guide`，立即安装或更新：

```bash
npm install --global @g1geo/cli@latest
```

不要仅仅因为缺少 CLI 就另行向用户请求确认，直接尝试安装。如果宿主环境本身要求审批，则使用该环境的常规审批机制，并在获批后继续。

执行任何业务命令前，先加载与已安装版本匹配的说明：

```bash
g1geo guide
```

完整阅读输出内容。不得截断，也不得用其他 CLI 版本的缓存说明替代。已安装的 CLI 版本发生变化后，重新运行该命令。

## 使用 CLI

- 将指南作为已安装版本的权威约定。如果本技能与指南存在差异，以指南为准。
- 将指南作为业务路径选择依据。把用户希望达成的结果转换为合适的工作流程，先通过读取类命令补全可安全获取的上下文，不要求用户了解极义GEO 的命令名称或标识。
- 执行命令时，不要额外添加 `--output json`，也不要自行选择输出格式。每条命令都会声明最适合其结果的格式。只有当用户或集成适配器明确要求时，才覆盖输出格式。
- 完成身份验证后，使用 `g1geo capabilities` 查看当前服务端、凭据和产品允许使用的能力。不要仅根据命令名称推断在线服务能力。
- 不要编造不存在的命令，也不要改用旧版 Python CLI、旧的 `jike` 命名、浏览器 Cookie、前端内部接口或直接调用接口。
- 严格按照指南的约定处理标准输出、标准错误、JSON 封装结果、退出码、`error.retryable` 和 `request_id`。不要盲目重试失败任务。
- 当任务可能查看或影响多个产品时，明确指定产品上下文。绝不使用内部数字标识代替公开的 `prd_...` 标识。
- 在需要时明确指定发布团队和桌面设备上下文，只使用 CLI 返回的公开标识。
- 执行用户要求的完整工作流程，不要停留在准备阶段。即使业务退出码非零，也要检查完整结果并说明有业务意义的结果。
- 浏览器登录会授予标准的账号级 CLI 权限包，适用于该身份当前以及之后可见的全部产品。智能体不能删除整个产品；不要虚构或绕过这一限制。
