# ALI_RFQ_SCAN() 阿里 RFQ 市场筛选


`ALI_RFQ_SCAN()` 用于筛选 Alibaba.com 采购直达市场中的 RFQ 机会，解决哪些 RFQ 值得点开、值得报价和值得投入时间的问题。它不负责填写最终报价表，也不替代通用 `RFQ()`。

## 2. 解决的问题

1. 判断哪些 RFQ 与公司能力匹配
2. 判断哪些 RFQ 值得消耗报价权益
3. 识别低质量、模糊或高风险需求
4. 识别可以快速报价的机会
5. 明确哪些 RFQ 应该跳过

`RFQ()` 用于分析一条已经进入手中的询价，判断需求完整度、成交信号、信息缺口、响应方式和报价边界。`ALI_RFQ_SCAN()` 用于 Alibaba RFQ 市场中的批量机会筛选。

## 与相邻 Skill 的区别

1. `ALI_RFQ_SCAN()` 只负责 Alibaba RFQ 市场筛选，不生成正式报价字段。
2. 平台外或已经进入手中的一般询价价值判断由 `RFQ()` 完成。
3. 决定参与后，平台报价字段生成转入 `ALI_RFQ_BID()`。
4. 产品身份不清时，可先转入 `PRODUCT_BRIEF()`。

## 3. 适用场景

1. 浏览 Alibaba 采购直达 RFQ 列表
2. 每天筛选可报价 RFQ
3. 报价权益有限，需要控制投入
4. 从大量 RFQ 中找出高匹配机会
5. 判断是否值得点开详情
6. 建立每日 RFQ 作战清单

## 4. 不适用场景

1. 已经拿到客户完整询价，需要做业务判断
2. 已经决定报价，只需要填写报价表
3. 需要生成客户沟通话术
4. 需要核算最终销售价格
5. 需要判断客诉或售后问题

## 5. 输入参数

输入分为必填参数和建议参数。平台行为和买家认证仅作为辅助信息，不能替代真实需求证据。

## 6. 必填参数

| 参数 | 说明 |
|---|---|
| `rfq_title` | RFQ 标题 |
| `rfq_description` | RFQ 描述 |
| `quantity` | 数量 |
| `buyer_country` | 买家国家 |
| `publish_time` | 发布时间 |
| `remaining_quote_slots` | 剩余报价席位 |
| `company_capabilities` | 公司当前能力 |

## 7. 可选参数

| 参数 | 说明 |
|---|---|
| `buyer_profile` | 买家资料 |
| `target_market` | 目标市场 |
| `available_quote_quota` | 剩余报价权益 |
| `known_supply` | 当前供应 |
| `margin_expectation` | 利润要求 |
| `compliance_risk` | 合规风险 |
| `historical_success` | 历史成功记录 |
| `product_match` | 产品匹配程度 |

## 8. 证据优先级

判断时优先使用：

1. 公司明确的供应能力和真实供应经验
2. RFQ 标题、描述、数量和技术参数
3. 已确认库存或稳定供应
4. 类似 RFQ 的历史成交和回复记录
5. 公司当前服务范围、最低利润和合规边界
6. 买家明确资料和 RFQ 发布时间
7. 平台报价席位、认证和行为信号
8. AI 推测

不得因为平台推荐、买家认证、剩余席位少或标题匹配，就判定 RFQ 高质量或有真实成交意向。

## 9. 判断规则

### A. 产品匹配度

检查是否属于公司主营产品、是否有真实供应经验、能否确认品牌型号规格、是否要求超出能力的定制，以及是否偏离现有供应链。

### B. 需求清晰度

检查型号、数量、成色、交期、目的地、贸易条款和技术参数是否明确。

### C. 商业价值

检查数量是否合理、项目金额潜力、复购可能性、重点市场匹配和是否值得消耗报价权益。

### D. 竞争程度

检查剩余报价席位、发布时间、进入是否过晚、是否为热门价格战品类和低价竞争风险。

### E. 可执行性

检查现货或稳定货源、交期、运输方式、保修、清关或 DDP 能力，以及是否有足够信息生成有效报价。

### F. 风险

检查信息极少、标题描述不一致、数量异常、高风险国家或地区、品牌授权要求、高额售后承诺、产品能力不匹配和疑似价格收集。

### 辅助评分

可按 100 分辅助判断：

| 维度 | 权重 |
|---|---:|
| 产品匹配度 | 25 |
| 需求清晰度 | 20 |
| 商业价值 | 20 |
| 可执行性 | 20 |
| 竞争机会 | 10 |
| 风险控制 | 5 |

评分仅作辅助，不得代替人工判断。证据不足时允许不评分。

## 10. 风险检查

1. 是否仅因标题匹配就判定高质量
2. 是否把买家认证等同于真实成交意向
3. 是否把剩余席位少当作必须抢报
4. 是否为消耗报价权益而强行报价
5. 是否把未知规格补成确定规格
6. 是否大规模分析无关 RFQ
7. 是否为分类完整而强行评分
8. 是否把平台推荐当成真实需求证据
9. 是否忽略国家、品牌、清关或合规风险
10. 是否超出公司真实供应和服务能力

## 11. 输出结构

正式输出依次包含：

1. 参数完整度结论
2. 参数状态表
3. 筛选结论
4. 已有正向信号
5. 关键缺失信息
6. 竞争与执行风险
7. 是否值得消耗报价权益
8. 推荐下一步

推荐下一步只能选择一个主要动作：快速响应、继续核实或跳过。

## 12. 禁止事项

1. 不因为标题匹配就判定高质量
2. 不把买家认证等同于真实成交意向
3. 不把剩余席位少当作必须抢报
4. 不为消耗报价权益而强行报价
5. 不把未知规格补成确定规格
6. 不大规模分析无关 RFQ
7. 不为了分类完整而强行评分
8. 不把平台推荐当成真实需求证据
9. 不生成最终报价
10. 不替代通用 `RFQ()`

## 13. 信息不足时的处理

缺少标题、描述、数量、买家国家、发布时间、剩余报价席位或公司供应能力时，应列出缺失项并选择“先点开详情确认”或“暂不报价”，不得强行评分或建议消耗报价权益。

## 14. 人工判断边界

1. 评分只辅助人工筛选
2. 公司供应能力、利润底线、服务范围和合规边界以人工确认为准
3. AI 不得把平台行为信号升级为成交证据
4. AI 不得自动消耗报价权益或提交报价
5. 人工可以基于最新库存、市场和资源情况覆盖筛选建议

## 15. 验收标准

1. 能明显区分高价值和低价值 RFQ
2. 能控制报价权益消耗
3. 不把平台行为信号当成交信号
4. 能指出信息缺口
5. 能给出明确下一步
6. 不越权生成最终报价
7. 与通用 `RFQ()` 职责不重叠

## 参数解析流程

本 Skill 必须先解析用户输入并映射到参数表。

## 参数状态表

正式分析前，必须输出参数状态表。

参数状态只能使用：

```text
已命中
部分命中
缺失
冲突
待验证
```

统一格式：

| 参数 | 必需程度 | 当前状态 | 已获取内容 | 缺失或冲突影响 |
|---|---|---|---|---|
| 待按本 Skill 参数填写 | 待确认 | 缺失 | 无 | 待判断 |

参数状态表必须基于用户输入，不得凭空补充。

## 最低运行条件

1. RFQ 基本信息完整
2. 产品或需求可识别
3. 公司能力可判断
4. 能识别至少一个商业价值或风险信号

未达到以上条件时，先输出参数状态表，说明缺失或冲突内容、重要性、影响和可直接补充的字段，然后停止正式分析。

## 缺失参数处理

不得自动补全缺失参数，必须明确提示用户补充，并说明缺失参数、重要性、影响、补充方式及当前是否可以先做初步分析。

## 冲突参数处理

不得自行解决冲突，必须保留不同来源、标记冲突、说明影响并提示验证。在冲突解决前降低分析置信度。

## 待验证参数处理

待验证信息不得写成确定事实。供应商口头反馈、市场信息、预计库存、预计交期、公开资料、客户可能意图和 AI 推测等必须明确标记。

## 停止条件

出现以下任一情况时停止正式分析：

1. RFQ 标题、描述或数量不足以识别需求
2. 公司当前能力无法判断
3. 关键平台信息存在冲突
4. 无法识别任何商业价值或风险信号
5. 产品身份需要先确认

停止时必须说明原因、缺失字段、补充方式，以及补充后从 `ALI_RFQ_SCAN()` 继续还是转入 `PRODUCT_BRIEF()`。

## 正式分析触发条件

只有达到最低运行条件，且关键缺失、冲突、证据来源、分析目标和风险边界已得到处理后，才进入正式分析。

## 初步分析模式

参数不完整时，只能提供明确标注的初步分析：

```text
以下为初步分析，仍需补充关键参数。
```

不得把初步分析包装成确定结论。

## 正式分析模式

参数完整并满足触发条件时，才可输出正式分析。正式输出前必须再次检查参数缺失、冲突、待验证信息、推测、人工判断、职责边界和用户真实目标。
