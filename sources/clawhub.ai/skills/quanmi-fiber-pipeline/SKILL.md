# 全米膳食纤维糖尿病管理管线系统

## 定位

**一句话**：加载即执行的糖尿病管理端到端管线——AI 从知识感知到销售激活一气贯通，一人+AI 替代传统 5-7 人团队。

**一段话**：以「饮食结构变化→肠道菌群失衡→肠漏→LPS入血→慢性炎症→胰岛素抵抗→β细胞衰竭→临床糖尿病」为底层病因链，以「修复肠道微生态，而非补菌或杀菌」为核心产品主张，以「病因→病机→病理→病症」四级嵌套因果模型为分析框架，基于 M2 工作流重构将传统人工流程重组为 5 基元 IPO 管线——知识引擎(P1)→产品引擎(P2)→内容引擎(P3)→验证引擎(P4)→销售激活(P5)，仅保留 3 处人工校准点，实现一人+AI 端到端闭环。

## 技能形态（通用 ↔ 专用）

本技能正文已脱敏，默认为**行业通用**形态（企业、创始人、某医药流通企业、功能糖冲调产品等泛称），任何膳食纤维控糖食品企业均可直接套用。

**专用化 = 改对照表即可，无需改正文**（运行时实时替换机制）：

1. 打开 `references/脱敏前后对照表.md`，将左列「原文示例」替换为本企业的真实专名（公司名/人名/机构名/品牌名/产品名/价格等），右列「泛称」保持不变。
2. 加载与执行时，AI 先读取对照表：若左列已被替换为真实专名，则在**输出内容**时实时将正文/范本中的「泛称」替换为对应的真实专名，并将价格占位 `XXX` 按对照表第六节实时替换为真实价格。
3. 若对照表保持默认（虚构谐音示例名），则按行业通用形态输出——保留泛称、价格保留 `XXX` 占位。

## 使用规则

### 执行规则

1. **管线优先于路由**：收到任务按 P1→P2→P3→P4/P5 基元链线性传导，不需要手动判断"执行哪个域"
2. **知识先于行动**：P2/P3/P4/P5 的所有输出，必须基于 P1 产出的最新知识库
3. **校准点必须触发**：P2 产出草案后暂停等待人工审核定价设计；P4 严重异常告警后暂停等待人工判定；P5 关键合作决策前暂停等待人工确认
4. **合规不可跳过**：P3-03 合规守护是硬约束，所有对外内容必须通过校验
5. **证据等级标注**：所有医学声明标注证据等级（A荟萃/B RCT/C观察/D专家/待验证）
6. **类比不歪曲事实**：每个类比必须保留"机制对照"字段，确保通俗表述不歪曲医学事实
7. **患者材料严守边界**：标注"本品为食品，不可替代药物""请遵医嘱"，不暗示停药
8. **加载元技能系统**：执行本管线任务时，应同时加载「Meta Skill System」技能——本技能的元操作映射（S/C/A/O/I/G）、三轴执行框架（Step 0-4）、管线编排模式均基于 Meta Skill System 定义，未加载则无法正确理解任务清单中的元操作符号及其编排语义
9. **专用化实时替换**：加载本技能时先读取 `references/脱敏前后对照表.md`；若左列「原文示例」已被替换为企业真实专名，则在所有对外输出中实时将正文/范本中的「泛称」替换为对应真实专名、将价格占位 `XXX` 替换为对照表第六节的真实价格；若左列保持默认虚构示例名，则保留泛称与 `XXX` 占位

## 执行框架

### Step 0 — 三轴判定

收到任务后沿三个维度判定：
- **复杂度**：简单（查/更新一个知识点）→ P1 单基元直达；中等（生成一类输出）→ P1→P3 或 P1→P4 部分链路；复杂（完整方案）→ P1→P2→P3→P4→P5 全管线
- **内容类型**：知识输出 → P1；方案设计 → P1→P2；内容生成 → P1→P3；验证 → P1→P4；销售 → P1→P2→P5
- **创新需求**：常规执行 → 按既定管线；需要突破 → 激活创新轴（M7-01第一性原理/M7-02逆向思维/M7-09故事叙述）

### Step 1 — 领域校准

| 参数 | 评分 | 调参 |
|------|------|------|
| R1 信息密度 | 8 | P1 的 S+C 权重 60%，每项产出标注证据等级 |
| R2 创造性 | 7 | P3 的 A 偏发散（内容层允许创新），P1 的 C 偏收敛 |
| R3 交互性 | 3 | I 权重仅 10%——仅 3 处校准点需要人工交互 |
| R4 规范性 | 8 | G 严格——P3 输出全量合规校验，P4 异常强制人工审核 |
| R5 迭代性 | 5 | 循环中频——P1 每季度系统刷新，P2-P5 每月增量更新 |
| 自治度 | ⬛75% 🟨20% ⬜5% | P1/P3 全自动，P2/P4 半自动（校准点），P5 辅助（决策点） |

### Step 2 — 三轴分解

- **执行轴**：S(P1感知)→C(P1认知+P2认知)→A(P2行动+P3行动+P4行动+P5行动)→G(P3合规+P4异常)→I(P2校准+P4校准+P5校准)
- **内容轴**：清单法为主（按基元取对应任务模板），样本法为辅（exemplars 范本参考）
- **创新轴**：需突破时激活 M7-01 第一性原理/M7-02 逆向思维/M7-09 故事叙述

### Step 3 — 管线编排与执行

| 场景 | 管线 | 执行流程 |
|------|------|---------|
| 完整方案生成 | P5 全管线 | P1 → P2(校准) → P3 ‖ [P4, P5(校准)] |
| 知识更新 | P1 单基元 | P1-01 → P1-02 → P1-03 |
| 内容产出 | P1→P3 链路 | P1-01 → P3-01 → P3-03(合规) |
| 验证运行 | P4 独立 | P4-01 → P4-02 |
| 增量更新 | P6 全守护 | P1-01(G)→仅触发受影响下游 |

### Step 4 — 整合交付

- 常规交付：按受众封装（医生版/患者版/内部版），默认最简必要信息，用户说"展开"时揭示细节
- 管线跟踪：每次执行记录基元流转状态，输出执行摘要
- 效果验证：验证报告必须含前后对照数据和达标率判定

## 事实纪律

1. 医学事实必须基于已发表的同行评审文献，不可编造数据或引用
2. 所有医学声明必须标注证据等级（A荟萃/B RCT/C观察/D专家/待验证）
3. 药品信息必须引用 CFDA/NMPA 批准的适应症范围
4. 竞品缺陷的每项断言必须标注证据来源和证据等级
5. 服务包的价格/效果承诺不得夸大，价格锚点必须标注成本测算依据
6. 类比生成时必须保留"机制对照"字段，确保通俗表述不歪曲医学事实
7. 面向患者的材料不得暗示"替代药物治疗"，必须保留"遵医嘱"提示
8. 不确定的数据和引用必须标注"待验证"，不得以不确定信息作为结论支撑
9. 产品优势声明不可贬低竞品人格（如"骗局""骗子"），应转为机制层面客观对比
10. P3 所有输出必须通过合规守护单元校验后方可交付
11. P4 验证报告的数据解读不得超出 CGM 数据能支持的范围
12. 患者数据的采集和使用必须遵守隐私保护规范（去标识化存储）
