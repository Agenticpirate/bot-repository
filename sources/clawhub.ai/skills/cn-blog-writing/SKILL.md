# Blog Writing

写中文技术博客时，遵循以下规则消除 AI 痕迹。详细示范见 [references/examples.md](references/examples.md)。

## 初始化（首次使用时执行）

首次为用户写文章前，完成以下步骤：

1. **询问博客地址**："你的博客地址是什么？我先看看你现有的文章风格和内容布局。"
2. **访问博客**，分析以下内容：
   - 已有文章的主题分布和分类标签
   - 写作语气和用词习惯（口语化程度、是否用 emoji、人称习惯）
   - SEO 情况：标题风格、meta description 写法、内链密度
   - 内容空白点：哪些话题还没覆盖，哪些系列可以继续
3. **确认身份**：问用户"你希望以什么身份写？学生博主、独立开发者、还是其他？"
4. 将分析结果记住，后续写文章时直接复用，不再重复询问。

## 身份

根据初始化阶段获取的信息填充。默认假设：

- 作者是一个技术博主，语气像跟朋友聊天
- 读者是编程初学者和对技术感兴趣的开发者
- 用"你"称呼读者，用"我"分享真实经历
- 允许口语化、网络用语、自嘲

## 标点节奏（最重要）

1. **用逗号连接同一思维单元内的多个分句**，只在思维单元结束时用句号。不要每句话一个句号。
2. **一个段落 2-5 句话**，不要一句一段。话题没变就不换段。
3. **长短句交替**：长句铺信息，短句下判断。不要所有句子都差不多长。

## 语气

1. 直接给判断，不要替读者做推理。给一个结论，给一个例子，留白让读者自己想。
2. 语气是"自己在想"，不是"教你知识"。用"网站怎么发现你的？"而不是"网站通过以下四种方式检测 Selenium"。

## 结构

- 开头：痛点/场景 → 一句话方案 → 为什么这个方案牛。不要"本文将介绍"。
- 正文：H2 大板块，H3 步骤/子主题。步骤用编号+加粗字段名+解释。
- 结尾：自然收尾（个人感受/延伸阅读/号召互动）。不要写"总结"章节复述全文。
- 内链：用自然语气引入博客内其他文章，增强站内链接。

## SEO

- 标题含年份增强时效性。
- Meta Description 含核心关键词但语气自然。
- 分析用户博客已有标签体系，新文章沿用已有分类。
- 规划文章时考虑关键词搜索量和竞争度，优先写有流量潜力的话题。

## 规划下一篇文章

当用户问"下一篇写什么"时：

1. 回顾博客已有内容，找出可以延伸的系列或空白话题。
2. 分析已有文章之间的内链关系，优先补全断链。
3. 考虑 SEO：搜索量大但博客未覆盖的相关话题。
4. 给出 2-3 个选项，附上理由，让用户选。

## 禁止清单

- "本文介绍了"、"本文将"、"旨在帮助"
- "值得注意的是"、"需要强调的是"、"综合来看"
- "赋能"、"助力"、"生态"、"抓手"、"降本增效"
- "首先……其次……最后……"三段论
- "随着XX技术的快速发展"开头
- "我们来看看"、"让我们了解一下"
- "即"、"亦"、"其"等文言词（非必要场景）
- 满篇破折号（——）
- 被动语态（"被广泛应用于"）
- **每句话都用句号切断**
- **一句一段的 AI 排版**
- **替读者做推理，把因果链每一步都写出来**
