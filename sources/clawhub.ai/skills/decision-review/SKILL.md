# 决策复盘与反思助手

帮用户对关键决策/事件做有结构的复盘，把"发生了什么"变成"下次怎么做更好"。核心：**复盘不是写感想，而是产出可执行的改进项**。

## 适用场景
- 项目/任务结束后的行动后复盘（AAR）
- 一次失败/失误的根因分析
- 周期性（周/月）回顾，提炼规律
- 把复盘结论沉淀为"原则"，反哺未来决策

## 复盘框架（默认 AAR）
1. **背景**：当时要解决的问题、约束、已知信息
2. **预期**：原本期望的结果
3. **实际**：真实发生了什么（事实，非评价）
4. **差异**：预期 vs 实际，差距在哪
5. **根因**：用 5-Why 追问到可改变的因素
6. **得失**：做对了什么 / 做错了什么
7. **改进**：具体、可落地、可验证的下一步（每条带 owner/时限最佳）
8. **原则**：提炼一条可复用的决策原则

## 标准工作流
使用 `scripts/retro.py` 把零散记录整理成结构化复盘：
```bash
python scripts/retro.py \
  --background "..." --expected "..." --actual "..." \
  --output retro.md
```
或直接把一段自由记录丢给它，由模型（本 agent）按框架补全后，用脚本落盘。

也可交互式：`python scripts/retro.py --interactive` 逐项提示填写。

## 质量门禁
- [ ] 改进项是否具体可验证（避免"下次注意"这类空话）
- [ ] 是否区分了"事实"与"评价"
- [ ] 根因是否挖到"可改变的因素"（而非归咎于人/运气）

## 自进化学习系统
```bash
python scripts/learner.py record . --capability "决策复盘" [--fail --error <类型> --note <说明>]
python scripts/learner.py insight .
python scripts/learner.py reflect .
```
- 用户常补某类维度 → 记录，reflect 建议把该维度设为默认必填
- 提炼出的原则可 `prefer` 记录，未来自动带入

## 安全边界
- 复盘涉及个人/商业敏感信息时，结果仅保存在用户指定位置，不外传
