# ISO9001 质量管理体系文件生成器（基于过程和风险方法）

## 任务目标
- 本 Skill 用于：为企业快速生成符合 ISO9001:2015 标准的完整质量管理体系文件
- 核心方法：采用**过程方法**和**风险思维**，将标准要求转化为实际业务流程
- 能力包含：质量手册、程序文件、作业指导书、表单模板的智能生成
- 触发条件：用户需要建立或更新 ISO9001 质量管理体系文件

## 前置准备
- 依赖说明：脚本所需的依赖包及版本
  ```
  python-docx==1.1.2
  ```
- 参考文档：构建以过程和风险为基础的质量管理体系（Word文档已上传）

## 操作步骤

### 0. 企业信息档案管理

**档案文件**：
- 文件名：`./enterprise-info.json`（保存在用户工作区）
- 内容：包含所有强制信息（企业名称、范围、行业、规模、组织结构、职责分工、业务流程）
- 更新机制：仅保存**最新一次**的企业信息

**档案读取流程**：
1. 每次对话开始，检查是否存在 `enterprise-info.json`
2. 如果存在，读取档案并显示企业名称：
   ```
   检测到存在企业信息档案。

   当前档案企业：【某某制造有限公司】

   请确认：
     A. 使用当前企业信息继续生成
     B. 输入新企业信息（将覆盖当前档案）
   ```
3. 如果用户选择A：直接使用档案中的信息，跳过步骤1，进入步骤2
4. 如果用户选择B：执行步骤1收集新企业信息，覆盖档案文件

**生成时提示**：
- 每次生成任何文件前，必须显示：`正在为【某某制造有限公司】生成文件...`

### 2. 过程识别和分析（核心步骤）

**目的**：识别组织的关键过程，制作"乌龟图"，识别过程风险和控制措施。

**核心思想**：基于参考文档《构建以过程和风险为基础的质量管理体系》，采用**过程方法**和**风险思维**，将ISO9001标准要求转化为实际业务流程。

**过程分类**：
1. **顾客导向过程（COP）**：营销、设计开发、采购、生产、交付、服务
2. **支持过程（SOP）**：人力资源、设备管理、文件控制、仓库管理、测量设备管理
3. **管理过程（MOP）**：体系策划、管理评审、内审、纠正措施

**对话流程**：
```
智能体：现在开始进行过程识别和分析。

请识别贵公司的关键过程，我建议按照以下分类：

【顾客导向过程（COP）】
  ☐ 营销管理过程
  ☐ 设计开发过程（如适用）
  ☐ 采购过程
  ☐ 生产/服务提供过程
  ☐ 交付过程
  ☐ 服务过程（如适用）

【支持过程（SOP）】
  ☐ 人力资源过程
  ☐ 设备管理过程
  ☐ 文件控制过程
  ☐ 仓库管理过程
  ☐ 测量设备管理过程
  ☐ 其他支持过程（请说明）

【管理过程（MOP）】
  ☐ 体系策划过程
  ☐ 管理评审过程
  ☐ 内部审核过程
  ☐ 纠正措施过程

请选择或补充贵公司的关键过程：
```

**过程信息收集**：
对于用户选择的每个过程，收集以下信息（用于制作"乌龟图"）：
1. **过程名称**：如"营销管理过程"
2. **过程活动**：按步骤描述（如：潜在客户开发 → 询价报价 → 商务谈判 → 合同签订 → 订单管理）
3. **过程输入**：信息类（如年度经营计划、客户需求）、资源类（如原材料、设备）
4. **过程输出**：如销售合同、客户档案
5. **过程资源**：如销售团队、市场推广资源、ERP系统
6. **过程责任部门/岗位**：如销售部、销售总监
7. **过程关键绩效指标**：如销售达成率≥95%、客户满意度≥90%
8. **过程风险及控制措施**：如风险"客户需求识别不准确" → 措施"多次沟通确认需求"

**"乌龟图"制作说明**：
- "乌龟图"包含6个要素：过程、输入、输出、资源、方法与准则、关键绩效指标、风险
- 文件正文按照"乌龟图"活动顺序描述
- "乌龟图"中活动可以作为章节小标题
- 参考文档说明：先完成"1活动"分解，再按照活动每一步完成"2,3,4,5,6"，最后完成"7"，考虑最终形成几个文件

**过程信息汇总表**：
```
过程信息汇总：

过程1：营销管理过程
  - 过程活动：潜在客户开发 → 询价报价 → 商务谈判 → 合同签订 → 订单管理 → 客户档案维护
  - 过程输入：年度经营计划、客户需求、法律法规要求
  - 过程输出：销售合同、客户档案、报价单
  - 过程资源：销售团队、市场推广资源、资金
  - 过程责任部门：销售部
  - 过程关键绩效指标：销售达成率≥95%、客户满意度≥90%
  - 过程风险及控制措施：
    * 风险1：客户需求识别不准确 → 措施：多次沟通确认需求
    * 风险2：价格不合理 → 措施：市场调研定价

[其他过程...]
```

**参考文档**：见 [references/process-analysis-guide.md](references/process-analysis-guide.md)（何时读取：需要了解过程识别和"乌龟图"制作方法时）

**建议编号原则**（四级文件结构）：
```
一级文件（质量手册）：QM-001（QM = Quality Manual）
二级文件（程序文件）：QP-XXX（QP = Quality Procedure，XXX对应过程编号或条款号）
  示例：QP-COP-01（顾客导向过程第1个）、QP-SOP-01（支持过程第1个）
三级文件（作业指导书）：WI-XXX-YY（WI = Work Instruction，XXX对应过程编号，YY为序号）
```

### 8. 质量手册生成

**生成策略**：
- **基于过程方法**：将ISO9001:2015标准要求转化为过程管理要求，而不是照搬标准条款
- **采用四级文件结构**：一级手册、二级程序、三级作业指导书、四级表单
- **10个部分结构**：公司简介、手册颁布令、授权令、质量方针及目标、宣导与承诺、组织、文件体系、过程管理、绩效评价、改进
- **6个附录**：组织结构图与各部门职责、过程与部门职责矩阵表、业务流程图、程序文件目录、管理体系过程关系图、过程描述（"乌龟图"）

**生成步骤**：
1. 确认质量手册目录（已在步骤7中确认）
2. 生成质量手册的 Markdown 内容，**必须包含以下特殊章节**：
   - **正文部分**（9个部分）：
     - 公司简介
     - 手册颁布令
     - 授权令
     - 质量方针及目标
     - 宣导与承诺
     - 组织（组织结构图、各部门职责、职责分配表）
     - 文件体系（文件的层次、ISO9001要素与文件对照表）
     - 过程管理（各过程的"乌龟图"描述）
     - 绩效评价
     - 改进
   
   - **附录部分**（6个附件）：
     - 附件1：组织结构图与各部门职责
     - 附件2：过程与部门职责矩阵表
     - 附件3：业务流程图
     - 附件4：程序文件目录
     - 附件5：管理体系过程关系图
     - 附件6：过程描述（每个过程的"乌龟图"）
3. 调用 `scripts/generate_iso_docs.py` 生成 Word 文档
4. 文档包含：封面、目录、章节内容、附录

**关键提醒**：
- 在生成过程中，**必须真正理解用户提供的信息**，而不是简单填充模板
- 手册中的特殊章节（组织结构图、职责分配表、过程与部门职责矩阵表、业务流程图、过程描述）需根据企业实际情况定制
- 正文部分（4-10章）需要将标准要求转换为组织管理的具体要求，可以引出程序文件，但**不得照抄标准内容**
- 参考文档说明："手册本质上需要把质量管理体系过程描述清楚，包括质量管理体系过程清单、过程相互关系和过程分析（包含输入、输出、方法与准则、资源、关键绩效指标、责任人等）结果"

### 9. 程序文件生成

**生成策略**：
- **基于过程方法**：按照"乌龟图"活动顺序描述程序文件
- **7个基本要素**：目的、适用范围、职责、程序、输出、资源、关键绩效指标
- **文件编写要求**（参考文档）：
  1. **规范性**：文件的格式应当统一，有标题、日期、作者、索引编号
  2. **逻辑性**：内容安排和文字说明，要符合逻辑规律，流程顺畅，不能前后矛盾或说法不一
  3. **一致性**：手册、程序、作业指导书，三者内容要求一致、职责分工一致、文件记录要求一致
  4. **唯一性**：文件中可以互相引用，但一件事应当只有一个文件，不要有重复
  5. **准确性**：职责、岗位名称、表单记录名称应当准确。如果有ERP系统，尽可能与系统中名称一致
  6. **简练**：文件应当言简意赅，简明扼要，清晰且可操作
  7. **闭环**：文件当中要考虑PDCA的检查环节，做到闭环

**生成步骤**：
1. **必须等待程序文件清单确认**（步骤6已完成）
2. 根据步骤2收集的过程信息，为每个过程生成程序文件
3. 程序正文按照"乌龟图"活动顺序描述，活动作为章节小标题
4. 小标题内容：将"乌龟图"中的"谁"、"什么资源"、"什么信息"、"什么输出"组织成一段话
5. 内容中要考虑风险控制措施
6. 把标准的要求贯穿于文件内容中
7. 按确认的文件编号规则命名文件

## 注意事项
- **强制确认流程**：信息收集、目录/流程确认、质量目标方针确认等环节，必须坚持2次确认
- **过程方法和风险思维**：所有文件必须基于过程方法和风险思维，将标准要求转化为实际业务流程
- **"乌龟图"的使用**：每个过程都要有"乌龟图"，文件正文按照"乌龟图"活动顺序描述
- **四级文件结构**：采用一级手册、二级程序、三级作业指导书、四级表单的结构
- **用户执意不确认的处理**：使用通用模板 + 标注"【待补充】"，或生成后询问是否需要调整
- **真正理解企业信息**：根据用户提供的行业、组织、流程等实际情况定制内容，避免简单填充模板
- **文件编写要求**：规范性、逻辑性、一致性、唯一性、准确性、简练、闭环
- **标准与业务结合**：不得照抄标准内容，要将标准要求转换为组织管理的具体要求
- **后续完善提醒**：所有文档生成后，应提醒用户根据企业实际情况进行调整和完善
- **内部审核要求**：提醒用户生成的文件需要进行内部审核和修订
