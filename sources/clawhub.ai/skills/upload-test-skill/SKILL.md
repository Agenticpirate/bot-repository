# Upload Test Skill

## 目标

验证 Skill 包是否能完成以下最小链路：

1. 平台能识别 `SKILL.md` 的元数据。
2. 用户输入测试指令后能触发该 Skill。
3. Agent 能按固定流程处理输入。
4. 输出能稳定包含测试结论、输入摘要、风险提示和下一步建议。

## 适用场景

当用户表达以下意图时使用：

- 测试 Skill 上传是否成功。
- 验证 Skill 能否被 Agent 触发。
- 检查 Skill 输出格式是否稳定。
- 在 QClaw / OpenClaw / Codex 等 Agent 环境里做最小可用 Skill 联调。

## 输入要求

用户可提供一段测试文本，建议格式：

```text
测试目标：验证上传链路
测试场景：Skill 触发与输出
测试数据：脱敏样例，不含真实手机号、邮箱、身份证、银行卡等 PII
期望结果：返回固定结构的测试报告
```

若用户未提供测试文本，使用以下默认测试输入：

```text
测试目标：验证 Skill 上传成功
测试场景：最小触发链路
测试数据：无真实业务数据
期望结果：输出上传测试报告
```

## 工作流程

1. 识别用户是否在做上传 / 触发 / 联调测试。
2. 检查输入中是否包含真实 PII 或敏感业务数据。
3. 若发现疑似 PII，只输出风险提醒，不复述原文中的敏感字段。
4. 若未发现敏感数据，按固定格式输出测试报告。
5. 给出下一步联调建议。

## 安全边界

- 不处理真实客户数据。
- 不生成、存储、导出手机号、邮箱、身份证、银行卡等 PII。
- 不调用外部接口。
- 不承诺上传平台审核结果，只验证当前 Agent 是否能读取并执行本 Skill。

## 输出格式

使用以下 Markdown 格式输出：

```markdown
## 上传测试报告

结论：Skill 已触发 / 未触发

| 检查项 | 结果 | 说明 |
| --- | --- | --- |
| 元数据识别 | 通过 / 待确认 | 是否读取到 name 与 description |
| 输入解析 | 通过 / 待确认 | 是否识别测试目标与场景 |
| 安全检查 | 通过 / 阻塞 | 是否发现 PII 或敏感业务数据 |
| 输出格式 | 通过 | 是否按固定结构返回 |

### 输入摘要
- 测试目标：...
- 测试场景：...
- 测试数据：脱敏 / 未提供 / 存在风险

### 风险提示
- ...

### 下一步建议
1. ...
2. ...
3. ...
```

## 判断规则

| 情况 | 结论 |
| --- | --- |
| 输入为脱敏测试文本 | `Skill 已触发，上传链路可继续验证` |
| 未提供输入 | `Skill 已触发，已使用默认测试输入` |
| 输入含疑似 PII | `Skill 已触发，但安全检查阻塞` |
| 用户要求调用外部接口 | `当前 Skill 不支持外部接口调用，仅做本地触发测试` |
