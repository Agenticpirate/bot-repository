# 校园邮件模板

## 工作流程

1. 识别文稿场景、收件对象、发送渠道和用户期望的正式程度；明确区分正式通知、公文附件和直接发送的群发邮件。
2. 提取用户已提供的事实，包括身份、事项、日期、原因、成果、请求、附件和联系方式。
3. 打开 [references/templates.md](references/templates.md)，只读取并采用与当前场景对应的模板与调整规则；处理多个场景时读取相应的多个章节。
4. 选择普通邮件、申请书、自述、正式通知或群发邮件通知的正确结构，并按用户信息进行个性化改写。
5. 将未知但必要的信息标记为 `【待填写：字段】`，继续完成可用草稿，不因普通信息缺失而停下。
6. 先交付可直接复制的完整正文，再按需补充主题备选、附件清单或填写提示。
7. 按参考文件中的“交付前检查”逐项复核后输出。

## 信息处理规则

- 只使用用户提供或明确确认的事实，不虚构姓名、成绩、排名、竞赛、任职、病情、证明、附件、审批结果或协商情况。
- 用户要求“模板”时保留通用占位符；用户要求成稿时填入已有信息，仅为缺失的必要字段保留占位符。
- 使用统一格式 `【待填写：字段】`，不要混用下划线、圆括号或多个占位符样式。
- 保护个人隐私，只保留完成事项所必需的信息。病假默认概括为“身体不适”“需要就医/休息”，除非用户主动要求写明具体情况。
- 发现日期、身份、收件人或事实存在冲突时，简明指出冲突并采用占位符，不自行猜测。
- 将“今天”“明天”“下周”等相对时间换成明确日期；若无法从上下文可靠确定日期，则保留日期占位符并提醒用户核对。
- 对申请类邮件、申请书、自述、正式通知和群发邮件通知，必须在落款处输出日期。按“用户明确提供的日期 → 当前系统日期 → `【待填写：日期】`”的顺序取值，不得直接省略。
- 若学校、院系或招聘方提供了固定格式或投稿要求，以其要求为先，并在不确定时保留原字段名称。

## 文稿格式

### 邮件

按以下顺序组织：

1. 主题行
2. 准确称谓
3. 身份和写信目的
4. 必要背景、事实或成果
5. 明确请求或下一步行动
6. 附件说明（仅在确有附件时）
7. 致谢、祝颂语、署名与日期

让主题行包含“事项 + 识别信息 + 关键时间”中的必要元素。正文优先使用短段落；只有进度、材料或安排确实需要枚举时才使用列表。

### 申请书与自述

按“标题—称谓—身份与申请事项—事实依据—后续安排/申请请求—落款”组织。使用第一人称，保持真诚克制，用具体事实支撑申请，不写无法核实的空泛结论。

### 通知与群发邮件

- 用户要求“通知”“公文通知”且未指定通过邮件发送时，输出正式通知，按“标题—通知对象—目的—时间地点—参加对象—具体安排—报名/行动要求—联系人—发布单位与日期”组织。
- 用户要求“群发邮件”“邮件通知”“发到邮箱”时，输出邮件主题、收件人称谓、简短来意、结构化活动信息、行动要求、联系人、发布单位与日期；不要只输出没有主题行的正式通知正文。
- 把时间、地点、截止时间和行动要求放在易扫描的位置，避免在群发邮件外再重复嵌套一份内容相同的公文。

## 语言与语气

- 默认使用简体中文和正式、礼貌、自然的校园书面语。
- 保持尊重但不过度道歉、恭维或自我贬低；避免命令式请求、网络用语和表情符号。
- 对导师和任课教师使用尊敬而简洁的语气；对招聘负责人使用专业、匹配岗位的语气；对学生发布通知时使用清晰友好的语气。
- 只有在用户要求时才生成英文、双语、极简版、短信版或更口语化版本。
- 不为显得正式而堆砌套话；优先确保事实、时间、请求和下一步行动清楚。

## 输出约定

- 直接以文稿开头，不先复述用户需求或展示推理过程。
- 对邮件明确标注 `主题：`；对公文、申请书和通知给出独立标题。
- 输出申请类邮件、申请书、自述、正式通知或群发邮件通知前，逐项确认落款中包含署名/发布单位和日期；日期未知时保留占位符。
- 保留适合纯文本复制的段落和换行，不依赖表格呈现核心内容。
- 若用户信息很少，仍输出完整模板并保留必要占位符。
- 若成稿仍含占位符，在正文后追加一句“发送前请替换所有 `【待填写】` 内容”；不在正文中反复解释占位符。
- 若用户要求多个版本，明确区分版本用途，例如“正式版”“简洁版”，避免只替换少量同义词。
