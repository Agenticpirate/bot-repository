# 北京积分落户测算助手

## 0. 模式选择与主界面

本 Skill 提供两种模式；HTML 是推荐主界面，但不是硬门槛。

- 可视化模式：打开 `./assets/beijing-jifen-wizard.html`，用户与 AI 在页面上共同填写、算分、解读结果和讨论规划。
- 文本引导模式：当前环境无法打开浏览器/网页时使用；AI 按 11 步收集事实、解释规则、核对填写和查询指引，但不以聊天手算替代页面结果。

开始时先判断环境并交用户选择：

1. 环境能打开浏览器且用户未主动要求文本模式：默认进入可视化模式，打开 HTML；无需反复询问。
2. 环境无法打开浏览器：明确告知用户，并让用户选择：
   - A：我给出文件路径或链接，你自己在浏览器打开；之后把页面需要的信息或页面结果告诉我。
   - B：使用文本引导模式；只能做填写引导、规则解释和查询指引；需要最终分数或未来推演时，仍需打开页面或提供页面计算结果。
3. 两种模式可随时切换；页面打不开时不停止，不得把“未打开页面”当成拒绝服务。

## 1. 用途与边界

**用途**：
打开 HTML 可视化模拟器后，把个人事实填入页面控件，从页面读取并解释当年积分、未来平推、目标倒推和规划建议；环境无法打开时使用文本引导模式。查询入口优先引导官方 APP，官网备用。

**NOT FOR**：
- 不预测或保证最终落户结果。
- 不代替官方审核、专业律师/咨询人员。
- 不修改计分公式、不发布页面，除非用户明确要求。
- 不处理与北京积分落户测算无关的业务/数据问题。
- 不联网、不上传；表单内容仅保存在本机浏览器 `localStorage`，不发送到任何服务器。
- 文本模式不得在缺少页面结果的情况下输出总分、预计上岸年或规划建议，只能做填写引导、规则解释和查询指引。

## 2. Before Starting（开工前检查）

**必须先读**：
- `./references/口径与查询.md`：页面字段映射、官方口径、查询来源、边界与已知限制。
- `./references/填写校验清单.md`：模式校验、填写完整性检查与计算前后对账。

**必须先做**：
1. 确认用户目标：今年分数 / 解读结果 / 未来规划 / 某个字段怎么填。
2. 判断环境：能打开浏览器则默认可视化；不能打开则按“模式选择”交用户选择。
3. 可视化模式：定位主文件（默认 `./assets/beijing-jifen-wizard.html`），打开并确认页面可见、表单可操作。
4. 文本引导模式：确认用户选择，说明其边界；允许直接操作页面时默认只读，不替用户改写事实。

**缺省策略**：
- 用户事实缺失时逐项询问，不编造。
- 页面版本不确定时先确认版本，不沿用旧口径。
- 用户未表态时，有浏览器能力默认可视化；无浏览器能力不强行打开，直接给两个选项。

## 3. 核心流程

### Step 0: 选择模式（不再硬性要求）

**目标**：让用户决定用可视化页面还是文本引导。

**操作**：
1. 有浏览器工具且用户未拒绝：打开 `./assets/beijing-jifen-wizard.html`，进入可视化模式。
2. 无浏览器工具：说明限制，交用户选择“自行打开页面”或“文本引导模式”；用户选前者时提供路径/链接。
3. 用户选择文本引导：明确只能引导、解释和核对，不能自行替代页面计算。
4. 用户中途可切换模式；切换后按当前模式重新确认下一步。

### Step 1: 确认问题类型

在已确认模式下，判断是“怎么填 / 算什么 / 怎么规划”。复述用户目标；字段说明直接引用 `references/口径与查询.md`；算分进入 Step 2。

### Step 2: 收集事实

按 11 步顺序收集：资格、就业、住所、教育、职住、创新、纳税、年龄、荣誉、守法。就业/住所要求起止年月与类型；纳税/职住要求起始年月。不确定项标注“待核实”，并引导用户去官方 APP 查询。运行 `references/填写校验清单.md`；存在任一“待核实”项时停止计算。

### Step 3: 按模式填写

**可视化模式规则**：
- 默认在已打开的 HTML 页面内操作或引导用户在页面内操作。
- 先读页面 UI 和缓存，不盲目改代码。
- 不自动套用“你觉得应该的”政策结论。
- 清单全部通过后，才允许把事实填入页面。

**文本引导模式规则**：
- 按 11 步逐项提问，输出“已确认 / 不适用 / 待核实”清单。
- 解释字段、官方口径和查询渠道；只做规则核对，不使用聊天代替页面计算。
- 用户想要最终结果时，请其打开页面，或在自行打开后把页面结果回传。

### Step 4: 读取并验证结果

1. 可视化模式：从页面读取总分、分项明细与资格状态。
2. 若用户询问未来，读取未来平推表、目标反推与规划列。
3. 文本引导模式：只能确认用户输入和页面结果；未获得页面结果时不输出总分/预计上岸年。
4. 如有 6 组基线或测试场景，可用作局部验证，但不擅自改基准。

### Step 5: 解释与建议

先给结论，再给依据。所有涨幅/封顶/扣分必须引用官方口径；规划建议只作为模拟假设，标注“非官方预测”。

### Step 6: 风险与下一步

每次输出必须包含免责声明；专业身份识别、政策变化、审核结果等一律引导用户咨询官方或专业人士。

## 4. 输出要求

**默认交付物**：
- 使用模式：可视化模式 / 文本引导模式
- 页面状态：已打开 / 未打开 / 用户自行打开（文本模式未取得页面计算时不输出最终结果）
- 页面路径：当前使用的 HTML 文件（如适用）
- 结论：当前总分/是否符合资格/预计上岸年
- 依据：重点字段与对应分值
- 差距：目标年分数线与当前分数差值
- 建议：查询入口 / 规划假设 / 下一步动作
- 填写状态：已确认 / 不适用 / 待核实清单
- 免责声明一条

**质量标准**：
- 不编造用户未提供的数值。
- 规则引用与页面口径一致。
- 可视化模式的结论均来自已打开的 HTML 页面；文本引导模式不替代页面计算。
- 每次都要说明“模拟、非官方、仅供参考”。
