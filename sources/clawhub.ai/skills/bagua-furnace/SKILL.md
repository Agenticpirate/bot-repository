# 八卦炉

## 零、进化燃料 · 本地即开 · 云端需显式开启

> **📋 安装须知**：本技能安装后**本地记录默认开启**（只记方法层标签，零原文零身份，留你本机），用于本技能自我迭代：
> - **本地记录**：每次使用后自动记一行方法层标签（只记方法名，零原文零身份）。
> - **云端上传（零密钥 · 默认关）**：需你**显式说「开启云同步」**才匿名回传反馈信号到藏经阁·易筋平台，跨用户聚合，让技能越用越牛。
> - 说「开启云同步」参与跨用户进化；「别传了」关云端（本地不受影响）；「别记了」全关。
> - 📊 透明度：说"查看我的信号"看记录、"我的技能成长"看进展、"删除我的信号"清空本机记录。


丹炉一座，专把书、课、笔记、视频、录音稿、讨论记录、链接里的"料"炼成可复用的「方法论卡」，反哺扫地僧等谋士，让它从学术走向通用。

本炉只提炼、不代写；只产**顾问级方法卡**（给谋士"想"着用）、**不产可执行 Agent Skill**（那是仓颉蒸馏的地盘）。

## A.3 发布前注册（创作者一次性，必做）

本技能发布后若想接收「升级提案」通知、让跨用户信号正确归因到本技能，**创作者**需在发布前完成一次注册（一次性，约 1 分钟）：

```bash
python scripts/forge-register.py register    # 收邮箱验证码（20 分钟内有效）
python scripts/forge-register.py verify <验证码>
```

验证后 token 存 `.deploy/cloud_open.json`（**不进发布包**）。注册只需一次；之后本技能的进化提案会在藏经阁·易筋聚合，你用「技能锻造炉」的 `scripts/cjg-proposal-cli.py` 审核采纳。

## 一、何时启用（触发）

满足任一即启用：

1. **手动召唤**：用户说 `/八卦炉`，或点名要这座炉子出场。
2. **自动判定**：用户诉求属于以下任一类——
   - 给了一段材料（书摘/课程笔记/视频转写/讨论记录记录/文章）并想「提炼方法论」「做成方法卡」「建立方法论库」；
   - 想把某本书/门课/段视频/段录音变成可迁移的**决策框架、思维模型**；
   - 甩来一个链接（网页/PDF/短视频），想直接炼成方法。

不启用的情形：用户只是要**检索文献、下载 PDF、核对某条参考文献真假**——交给 `recommends` 里的执行型技能，本炉只在其**之前/之后**提供思路与判读。

## 二、第 0 关 接料辨体（输入路由 + 格式转换）

客户常甩一个链接或文件。第一步**先判类型，再转文本**，然后才进九转。路由表：

| 输入形态 | 判断依据 | 转换方式（本机已有） |
|---|---|---|
| 已是文本 / 本地 `.txt` `.md` | — | 直入第一关 |
| `.pdf` 链接或文件 | 后缀 / Content-Type | **Read 工具**直接读 PDF 全文（CAJ 先走 `caj2pdf-offline` 转 PDF） |
| 抖音 / 快手 / 小红书 / 视频号 分享短链 | 域名识别 | 调用 **`douyin_copy_extract`** 技能取口播文案 |
| 图片 / 书页截图 | 后缀 `png/jpg` 或用户说"截图" | **Read 工具**多模态 OCR 取文字 |
| 普通网页 / 文章链接 | `http(s)` 且非视频平台 | **WebFetch** 抽正文 |
| YouTube / B站 / 本地 `mp4` / 录音 `mp3` 等音视频 | 域名或后缀 | **ASR 适配器**（见下） |

**ASR 适配器（双层，与业界现成技能一致：字幕优先 + Whisper 兜底）**：

1. **优先**：浏览器抓字幕轨——YouTube/B站 有 CC 字幕时，用 `agent-browser` 或 `chromium` 技能抓 transcripts，无需本地模型即覆盖。
2. **兜底**：公司 GPU 服务器 `192.168.21.97`（RTX 4090）本地 Whisper 逐字转写（需先部署 `faster-whisper` / `whisper.cpp` 端点）。
3. **降级**：既无字幕、Whisper 又未就绪 → 提示用户「请提供转写稿，或先用 ASR 工具转写后再丢给本炉」，不卡死流程。

> 各适配器的**真实调用语法、参数、边界**见 `references/ingestion.md`（本炉"接料辨体"操作手册）。

## 三、九转提炼流水线（第 1–9 关）

1. **收料定标**：确认原料类型 + 用户想提炼出什么（如"定价心法""决策框架"），避免无目标瞎挖。
2. **辨体选型**：按原料选透镜——书→章节论点；课程→模块；讨论记录→决策/洞见；视频→先转写稿。各透镜模板见 `references/extraction-lenses.md`。
3. **粗炼取料**：原样抽取主张/步骤/故事/框架，**保留溯源锚点**（页码/时间戳/段落）。
4. **淬炼抽象**：把"他们怎么做的（情境绑定）"与"底层模式（可迁移）"拆开——这是成丹的关键一步。
5. **成丹定型**：每条落成标准卡，字段规范见 `references/method-card-schema.md`。
6. **对勘校验**：与已有知识交叉比对，标冲突 + 置信度（`【板上钉钉】` / `【八成·需看原始材料】` / `【分歧大·待查证】`）。
7. **归库集成**：写入 `~/.workbuddy/methodology-library/`（按主题分文件）。新卡**强制带 v2 路由头 + `source_fidelity` + `primary_source` 原句段**（字段规范见 `references/method-card-schema.md` v2）；写库后**自动跑 `scripts/build_index.py`** 追加 `INDEX.md`。**无原文则标 `source_fidelity: 二手·待一手校验`**，绝不伪装一手。
8. **回炼闭环**：记录方法层信号（进化燃料），追踪哪些方法真被用上 → 反哺。
9. **交付**：结构化方法卡集（主形态）；若用户要综合报告，另做一篇连贯提炼文。

> **长原料（≥3 万字 或 要点 ≥80 条）必走专章**：整本书 / 长课程 / 多年讨论记录导出等，按 `references/long-text-distillation.md` 的四段式执行——分块取料 → **长上下文通读全量要点**淬炼 → 机器审计 → 落盘核验。
> 三条硬红线（违反必掉质量）：
> 1. **禁止顺序截断喂料**：按字符预算 `break` 会让取材永远只来自开头几章。实测信息保留率仅 **28.6%**，把可用率打到 **16.7%**、13 份不合格；改长上下文全量后 **88.9%**、不合格归零。
> 2. **方法名用原料原词**：审计按 n-gram 对齐原文算"概念落地率"，改用外部术语（如把"原料原词甲"写成"外部术语乙"）命中率从 **1.0 掉到 0.3**。
> 3. **每个方法块必带 `# 【名称】` 标题行**：缺了判结构不合规、命中率记 0——这是最高频失败点。

## 四、方法卡规范（成丹契约）

每张卡固定字段（v2）：**名称 / 适用情境 / 核心操作 / 前提假设 / 常见坑 / 迁移场景 / 边界反例 / 来源溯源**（v1 基础八字段），并叠加**路由层**（pattern/trigger/root_cause/surface_domain/confidence/source_fidelity）+ **理解层**（mechanism/transferable_core/正例/近失例/relates_to/理解闸门/自反伪化/分维置信/一手原句）。
范例、模板与保真要求见 `references/method-card-schema.md`（v2）。卡必须**可溯源**——来源写清书名/作者/章节、视频链接+时间戳、或讨论记录上下文。

## 五、差异化红线（对抗克隆，别做成又一个蒸馏器）

- **不产可执行 Agent Skill**（那是 `cangjie-distill-changhong` 的地盘）；本炉只产**顾问级方法论卡**，给谋士"想"着用、不替 Agent "做"。
- **输入更广**：明确覆盖笔记 / 讨论记录 / 录音稿 / 短视频链接——仓颉只覆盖书/视频/播客。
- **元目标唯一**：专为"把扫地僧从学术推向通用"而存在，立意别人没有。

## 六、与扫地僧联动（双向打通）

**本炉管「炼」，扫地僧管「用」，共享同一个卡库与同一份 INDEX。**

- 本炉把卡写入 `~/.workbuddy/methodology-library/harbor_*.md`，第 7 关自动跑 `scripts/build_index.py` 更新 `INDEX.md`（**全部方法块入索引**，不是每张卡只取第一个）；
- 扫地僧 **L6.5** 自动查该库取招，本炉产卡从出生即可被检索、被引用；
- 双方共用 **`references/pattern-taxonomy.md`（15 个跨域标准 pattern）** 与 v2 卡 schema，路由语义一致——成丹时按该词表打 `pattern`，该方法的原始模式词写入 `pattern_raw` 保留；
- **反向链路**：扫地僧取招时发现卡库无命中、或施主手上有待炼素材，会交回本炉现炼；炼好即入卡库、下轮可取——招式库由此越用越厚。

> ⚠️ 改动 `pattern-taxonomy.md` 词表或卡结构后**必须重跑索引**，否则扫地僧取招会踩空。

## 七、红线 / 明确不做（NON-mandate）

- 不替用户读书/看视频：需用户提供文本、转写稿或笔记；视频无稿须先走 ASR 适配器。
- 只提炼、不代写（除非用户明确要求做综合报告）。
- 不做学术/事实核查（交扫地僧、引文核查技能）。
- 不碰越界专业判断（法律/医疗/财务）。
- 第 0 关与第 1 关不可跳过：未用真实材料跑通 1 条主链路，不声称"能赢"。

## 九、查看与应用藏经阁进化提案（云端进化闭环收口）

本炉信号回传藏经阁·易筋聚合后，蒸馏出的改进提案可在本对话中直接审阅并应用：

- **看看提案**：说「看看提案」/「查看进化提案」→ 跑 `python scripts/cjg-proposal-cli.py list`，展示待审提案（版本差、变更文件、理由、草稿）。
- **应用提案**：说「应用提案 <id>」/「批准提案 <id>」→ 先 `cjg-proposal-cli.py approve --id <id>` 在云端标记批准，再按提案 `changes` 逐条本地应用（应用前自动备份到 `.backup/YYYY-MM-DDTHH-MMSS_<filename>`；`append` 追加、`rollback` 从备份恢复；应用后展示 diff，说「撤销」即从备份恢复）。

- 应用后版本 `patch+1`，更新 SKILL.md `version`，并提醒「如需发布到外部平台，说『发布』」。

本技能**不替用户做以下决定/动作**，触到边界即停并说明：
- 不替用户做创意决策（选题 / 文案 / 设计方向由用户拍板）；

## A.1 交互指令响应（强制 · 不可忽略）

用户说出下列任一指令，**必须立即执行对应动作**，不得当作闲聊。若因环境 / 权限无法执行该动作（unmet_action），**立即停并兜底说明**，绝不假装成功：

| 用户指令 | 必须执行 | 未触发即停（unmet_action） |
|---|---|---|
| 「开启云同步」 | 写 `.cloud_optin` = `on` | 说明无法写入原因，请用户检查目录权限 |
| 「别传了」 | 写 `.cloud_optin` = `off` | 同上 |
| 「别记了」/「再开」 | 写 `.optin` = `off` / `on` | 同上 |
| 「查看我的信号」 | 跑 `python scripts/signal_control.py view` | 说明脚本路径未找到，请重跑 `forge-signal-kit.py inject` |
| 「删除我的信号」 | 跑 `python scripts/signal_control.py delete`（需用户确认） | 先要确认，确认后才执行；用户拒绝则停 |
| 「同步我的信号」 | 跑 `python scripts/download_signals.py pull` | 说明未注册 / 未开云同步，引导先注册 |
| 「看看提案」/「查看进化提案」 | 跑 `python scripts/cjg-proposal-cli.py list` | 说明未注册（401 token required），引导先跑 `forge-register.py register` |
| 「应用提案 \<id\>」/「批准提案 \<id\>」 | `cjg-proposal-cli.py approve --id <id>`，再按 changes 逐条本地应用（**应用前先备份**） | 同上；若备份失败则停，不裸改 |
| 「打回提案 \<id\>」 | `cjg-proposal-cli.py reject --id <id>` | 同上 |

> **命令执行约定**：运行任何 `scripts/*.py` 前，先定位本技能目录并进入（形如 `~/.workbuddy/skills/bagua-furnace/`，用 `ls -d ~/.workbuddy/skills/*/bagua-furnace` 找到后 `cd` 进去），再执行。

## A.2 会话钩子 + 收尾信号块（强制 · 本地记录默认开可随时关）

**会话开始（首次交互时静默执行，一条命令）**：`python scripts/session_hook.py start`
（内部自动：补传上次积累 + 拉回云端历史 + 缺失检测；失败不阻塞、不打扰用户。）

**会话结束（必须执行；结束时记录方法层信号——这是会话完成的标志）**：
1. 输出收尾信号块（给用户看，严格格式）：`[信号] L<层>·<事件>`——**只写标签，不加括号解释**（如 `[信号] L3·helpful`）；本地记录关闭时输出 `[信号] off`；
2. 写 signals-log 由脚本完成（**禁止手写 JSON**）：`python scripts/session_hook.py end --event L3:helpful`；
3. 本次调用过外部服务才做客观汇报：对用户说 `[使用] <服务>×N 成功M 失败K 耗时Xms`，并跑 `python scripts/session_hook.py usage --calls N --success M`；
4. 若已开云同步：`python scripts/upload_signals.py` 即时回传。

仅方法层标签，零对话内容、零身份，只写本技能目录内的运行时文件。用户说「别记了」即关、「再开」恢复。
