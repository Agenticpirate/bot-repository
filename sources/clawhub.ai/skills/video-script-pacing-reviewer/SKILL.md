# Video Script Pacing Reviewer

审查视频脚本和 PPT 演示稿件的节奏质量。不做生成，只做审查。

## When to Use

触发条件：

- 用户要求审查/检查视频脚本或 PPT 稿件
- "帮我看看这个脚本的节奏有没有问题"
- "review this script for pacing"
- "审一下这个 PPT 的节奏"
- "check script pacing / retention risk"
- "这个脚本在抖音/B站/YouTube 上会不会掉节奏"

不适用于：生成脚本、制作 PPT、视频剪辑。

## Required Inputs

向用户收集：

1. **脚本或稿件全文**（逐段/逐页）
2. **内容类型**：教程 / 种草 / 评测 / 知识讲解 / 投放素材 / 短视频 / 长视频 / PPT 演示
3. **目标平台**：B站 / 抖音 / YouTube / 小红书 / 其他
4. **目标时长**（如已知）
5. **旁白字数**（如已知，用于估算语速）
6. **画面描述**（如提供：每段对应的画面内容/分镜）

最少只需要 #1 和 #3 就能开始。其余缺省时给出假设并标注。

## Workflow

### Step 1 — 分段建表

将输入拆分为段落/页面单元，建表：

| 段号 | 内容摘要 | 旁白字数 | 估算时长 | 画面描述 |
|------|---------|---------|---------|---------|

语速假设（可按用户实际调整）：
- 中文口播：200–250 字/分钟
- 英文口播：130–150 词/分钟
- PPT 演讲：100–120 字/分钟

### Step 2 — 五维审查

逐段打分（1–10），按以下五个维度：

**① 时长分配合理性**
→ 读取 `references/pacing-rules.md`

- 前 15 秒是否有强钩子（决定留存）
- 每 60 秒是否有新的注意力锚点
- 单段停留时间是否过长（>90s 无变化）或过短（<5s 信息无法消化）
- 总时长是否符合平台偏好

**② 画面与旁白配合**
→ 读取 `references/visual-narration-sync.md`

- 旁白信息量 vs 画面复杂度是否匹配
- 有无"画面在动但旁白讲太慢"（走神风险）
- 有无"旁白信息密集但画面静止"（信息过载）
- 关键视觉是否有旁白引导

**③ 信息密度节奏**
→ 参考 antislop 的信息密度测试方法

- 标记"信息过密段"（一段塞太多新概念，>3 个/30s）
- 标记"空洞段"（画面好看但旁白无实质内容）
- 信息密度曲线是否呈波浪形（高-低-高-低交替），而非单调
- 每段是否有且仅有一个核心信息

**④ 钩子和过渡**
→ 读取 `references/hook-transition-framework.md`

- 段与段之间的过渡是否自然
- 有无"掉节奏"位置（前一段高潮结束，下一段从零开始爬坡）
- 每 60 秒是否有节奏变化（加速/转折/惊喜）
- 开头 5 秒和结尾 15 秒的钩子强度

**⑤ 平台适配**
→ 读取 `references/platform-adaptation.md`

- 按目标平台检查节奏是否符合平台用户习惯
- 检查时长是否在平台黄金区间
- 检查钩子类型是否匹配平台用户预期
- 检查 CTA 时机和方式是否平台适配

### Step 3 — 问题汇总

将所有得分 ≤6 的段标记为问题段，分类：

| 严重度 | 条件 | 处理 |
|-------|------|------|
| 🔴 Critical | 得分 ≤3 | 必须修改，否则严重影响完播率 |
| 🟡 Warning | 得分 4–6 | 建议修改，有优化空间 |
| 🟢 OK | 得分 7–10 | 节奏合理，可保持 |

### Step 4 — 留存曲线预测

基于五维评分，模拟一条预测留存曲线：

```
留存率%
100 ┤██
 90 ┤  ██
 80 ┤    ████
 70 ┤        ████████
 60 ┤                ████████████
 50 ┤                            ████████████████
    └────────────────────────────────────────────── 时间
     0s    15s    30s    60s    120s    180s   END
```

标注预测 drop-off 点及原因。

### Step 5 — 输出审稿报告

## Output Format

### 1. 概览卡片

```
📋 脚本节奏审查报告
━━━━━━━━━━━━━━━━━
内容类型：[类型]
目标平台：[平台]
总时长估算：[X分Y秒]
总段数：[N]
整体节奏评分：[X/10]
预测平均留存率：[X%]
最大掉段风险点：[段号X，原因]
```

### 2. 五维雷达评分

| 维度 | 评分 | 状态 |
|------|------|------|
| ① 时长分配 | X/10 | 🟢/🟡/🔴 |
| ② 画面旁白配合 | X/10 | 🟢/🟡/🔴 |
| ③ 信息密度节奏 | X/10 | 🟢/🟡/🔴 |
| ④ 钩子过渡 | X/10 | 🟢/🟡/🔴 |
| ⑤ 平台适配 | X/10 | 🟢/🟡/🔴 |

### 3. 逐段详细审查

每段输出：

- **段号 + 内容摘要**
- 五维小分
- 具体问题诊断
- 改写建议（给 1–2 个替代方案）

### 4. 预测留存曲线

ASCII 图 + drop-off 标注

### 5. 优先修改清单

按影响排序的 Top 5 修改建议：

| 优先级 | 段号 | 问题 | 建议动作 |
|--------|------|------|---------|

### 6. 平台专项建议

针对目标平台的 2–3 条具体优化建议。

## Safety

- 不发明事实。如果用户未提供画面描述，明确标注"画面信息缺失，仅基于旁白分析"
- 评分基于内容结构规律，不构成发布效果的保证
- 不替代专业视频制作团队的主观判断
- 合规风险不在本 skill 范围内（交给 creator-monetization-risk-checker）
