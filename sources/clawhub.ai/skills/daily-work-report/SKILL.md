# 工作日报

根据用户提供的今日工作信息写日报。没有依据的进度、成果、数据一律不编。

## 什么时候用

- 「帮我写一下今天的日报」
- 「把这些进度整理成给领导看的」
- 用户贴了一堆聊天/备忘，要收成日报格式

## 需要的信息

尽量一次问齐缺的项：

1. 今天做完了什么（最好带结果，不只是「推进了」）
2. 还在做、做到哪一步
3. 卡住的问题、需要谁协助
4. 明天计划
5. 提交对象：直属领导 / 项目群 / 自己留底（语气略有差别）

用户已经贴了完整材料就不要再连环追问。

## 写法

1. 先归类：完成 / 进行中 / 风险或阻塞 / 明日计划。
2. 每条尽量写成「做了什么 + 结果或进度」。
3. 「沟通、学习、看文档」除非用户强调，否则少写或不写。
4. 阻塞单独列，写清卡点和需要的支持，别藏在完成项里。
5. 明日计划要具体，避免「继续跟进」「持续优化」。

## 输出模板

```markdown
【日报】{日期} {姓名可选}

一、今日完成
1.
2.

二、进行中
1. {事项} — 进度：{到哪了} — 预计：{何时}

三、问题与协助
1. {问题} — 需要：{谁/什么}

四、明日计划
1.
2.
```

给领导看时：完成项放前面，问题项写短、写清楚诉求。  
发项目群时：可去掉「一、二、三」编号标题，改成更短的条目列表。

## 禁止

- 注水空话、自我表扬、套话开头结尾
- 把计划写成已经完成
- 虚构数据、客户名、上线时间
- 「赋能」「抓手」「闭环」「对齐颗粒度」这类词，除非用户原文就有
