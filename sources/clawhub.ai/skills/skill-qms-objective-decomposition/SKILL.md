# Quality objective decomposition · 质量目标分解辅助技能

## 一、技能定位与边界

### 能力介绍
本技能帮助质量管理从业者完成质量目标的**分解**与**审核**两件事：
- **分解模式**：把公司级质量方针 / 战略目标，拆解成可执行、可测量、可追溯的「部门/工序 × 时间」三维度目标矩阵，并逐条做 SMART 校验。
- **审核模式**：接收用户已有的质量目标分解文档，对照 ISO 9001:2015 第 6.2 条（质量目标及其实现的策划）做条款符合性诊断，给出带严重度的改进建议。

### 能做什么
- 生成公司级 → 部门级 → 工序级 → 季度里程碑的逐级分解矩阵
- 为每条目标补全「六要素」（责任部门 / 责任人 / 测量方法 / 考核频率 / 数据来源 / 支撑关系）
- 用脚本对每条目标做 SMART 可测量性校验
- 将分解结果锚定到质量方针 / 战略（用户提供的方针文本）
- 对现有文档做 6.2.1（a-g 七项）+ 6.2.2（策划五要素）条款审核

### 不能做什么（边界）
- 不代替管理决策：目标值、分解系数均为「示例基准」，最终须由用户结合企业实际确认
- 不生成虚假数据：缺少基线数据时标注「供参考 / 待确认」，绝不编造历史值
- 不替代体系认证审核：本技能的「审核」是文档符合性诊断，不是第三方认证审核
- 不处理与质量目标无关的内容（如纯生产排程、设备台账）——这类需求请转对应技能

## 二、通用交互规则（每次调用必须遵守）

> 以下 5 条为本工作空间技能生成规范强制项，调用本技能时逐条执行。

1. **调用前置说明**：每次开始都先向用户简述本技能的能力与边界，并明确「开始帮助用户前需要哪些输入」。若上下文（对话历史 / 已上传文件）已含这些信息，直接复用，不再重复索取；若缺失且属必需，主动提示用户补充。
2. **输入载体判断**：先判断用户输入的载体形式。纯文本直接处理；`.docx/.xlsx/.pdf` 等文档需调用 docx / markitdown 等文档处理技能解析为结构化文本后再处理；多文件 / 复杂表格优先用脚本解析。
3. **缺失信息标注**：执行中遇到缺失信息，必须主动向用户说明「该缺失对生成结果的影响」；若用户执意不提供，对应部分明确标注 `【供参考】` 或 `【待确认】`，不得伪装为已确认内容。
4. **输出形式与大纲确认**：先明确输出形式（对话内文字 / `.docx` 文档 / `.md` 文档）。**凡生成文档（.docx/.md 等文件），必须在生成前先向用户展示文档大纲，确认结构后再生成。** 默认输出为对话内文字版，用户要求时才生成文件。
5. **边界清晰**：始终区分「本技能能做的」与「不能做的」，遇到越界需求明确说明并建议转交合适技能。

## 三、两种模式总览

| 模式 | 触发条件 | 输入 | 输出 |
|------|----------|------|------|
| 分解模式 | 用户要「制定 / 分解 / 生成」质量目标 | 行业、组织架构、公司级目标清单、方针/战略（可选） | 三维度目标矩阵 + SMART 校验报告 |
| 审核模式 | 用户要「审核 / 检查 / 评审」现有目标文档 | 现有质量目标分解文档（.docx/.xlsx/.md 或文本） | 条款符合性审核建议（文字版，默认） |

调用时先判断用户意图归属哪种模式，再进入对应工作流。

## 四、分解模式工作流

### 步骤 1 · 前置信息收集（遵守规则 1、3）
需要以下信息，缺失则提示并标注影响：
- **行业 / 企业性质**（如汽车零部件、电子代工、食品、通用制造、服务业、建筑业）——影响默认部门与目标基准
- **组织架构**（部门 / 工序清单）——缺失时回退行业默认配置，输出中标注 `【待确认】按行业默认部门设置`
- **公司级目标清单**（每条含目标值 + 时限，如「产品合格率≥98%/年」）——这是分解的起点，缺失则无法分解，必须索取
- **质量方针 / 战略文本**（可选）——用于战略锚定；不提供时锚定环节标注 `【待提供方针后复核】`

### 步骤 2 · 输入载体判断（遵守规则 2）
- 目标以文本给出 → 直接进入步骤 3
- 目标在 `.xlsx` 表格 / `.docx` 文档中 → 用 docx / markitdown 技能解析，抽取「目标名称 + 目标值 + 时限 + 责任部门」列

### 步骤 3 · SMART 校验
对每条公司级目标运行 `scripts/smart_validator.py`，输出逐条 SMART 通过情况与修改建议。未通过的目标先给出改写建议，请用户确认后再进入分解。

### 步骤 4 · 矩阵分解
运行 `scripts/matrix_formatter.py` 生成三维度矩阵。脚本内含**分解系数（示例基准）**，输出会带 `coefficient_note` 字段，明确告知：
> 「分解系数为行业示例基准，反映各部门能力差异的通用假设，须由用户结合企业实际改善空间确认或调整。」

**严禁**声称「已差异化分解」而实际平推系数——脚本已就「能力差异化」做说明性标注，最终确认权在用户。

### 步骤 5 · 战略锚定（可选，呼应 qms-policy-assistant）
若用户提供方针文本，在矩阵末追加「目标—方针映射表」，每条目标标注其支撑的方针条款 / 战略锚点；未提供则整表标注 `【待提供方针后复核】`。

### 步骤 6 · 输出（遵守规则 4）
- 默认：对话内文字版矩阵 + SMART 报告
- 若用户要求文档：先展示 `assets/质量目标分解_输出模板.md` 的大纲，确认后再生成

## 五、审核模式工作流（新增能力）

### 步骤 1 · 输入载体判断（遵守规则 2）
- `.docx/.xlsx` → 调用 docx / markitdown 技能解析为文本 / 表格
- `.md/.txt` → 直接读取
- 解析后抽取「目标清单」：每条目标 + 所属层级（公司级 / 部门级 / 过程级）+ 当前值 / 目标值 + 负责人 + 期限 + 衡量方式 + 沟通 / 更新机制（若有）

### 步骤 2 · 缺失信息说明（遵守规则 3）
抽取后发现文档缺字段（如某目标无测量方法、无责任部门），说明「该缺失将导致无法判定其符合 6.2 哪条要求」，并在审核报告中标注 `【待确认】`。

### 步骤 3 · 运行审核引擎
运行 `scripts/objective_audit.py`，对照以下维度做结构化诊断（详见 `references/audit_checklist.md`）：
1. **条款符合性（ISO 9001 6.2.1 a-g）**：与方针一致(a)、可测量(b)、考虑适用要求(c)、关联产品符合性与顾客满意(d)、有监视(e)、已沟通(f)、适时更新(g)
2. **可测量性（SMART）**：复用 smart_validator 逻辑逐条校验
3. **战略锚定**：每条目标是否追溯到方针 / 战略锚点（用户提供方针时校验，否则标注待复核）
4. **分解逻辑合理性**：是否真正差异化分解，还是简单平分
5. **层级覆盖完整性**：公司级 → 部门级 → 过程级是否齐备
6. **6.2.2 策划要素**：每条目标是否有 what / who / when / resources / how-evaluated

### 步骤 4 · 严重度分级
- **不符合**（直接违反条款，如目标不可测量、未分层建立）→ 必须整改
- **建议改进**（战略未锚定、分解平推、缺 6.2.2 要素）→ 建议优化
- **符合**（标注良好实践，可保留）

### 步骤 5 · 输出审核建议（遵守规则 4，默认文字版）
默认在对话内给出：总评 + 分维度发现表 + 逐目标问题清单 + 优先级改进建议。
若用户要求生成 `.docx` 审核报告：先展示 `assets/审核报告_模板.md` 大纲，确认后再生成。
审核建议措辞须指向具体条款，给出可操作的修改方向，不泛泛而谈。

## 八、相关技能联动（战略分析工具链）

本技能是工具链的**质量落地环节**（质量场景专属）：把已落成/待分解的质量目标，分解到层级与部门并做审核。完整链路：

`pestel-analysis`（宏观外部）→ `porters-five-forces`（行业外部）→ `vrio-analysis`（内部）→ `swot-analysis`（收敛）→ `smart-goal-setter`（落成目标）→ **`qms-objective-decomposition`（质量分解落地）**

- **上游来源（质量场景链路）**：
  - `smart-goal-setter`：本技能内置的 SMART 校验即其质量子集；通用 SMART 优化详见该技能（交集关系）
  - `qms-policy-assistant`：公司级质量方针/战略锚点，本技能分解矩阵可映射回方针条款（"方针 → 目标 → 分解"体系链路）
  - 更广义上游：若质量目标源自 `swot-analysis` 的质量方向战略，链路为 SWOT → SMART → 本技能分解
- **工具链定位**：本技能是 6 个交互引导式战略技能中**唯一质量专属**的一环；其余 5 个（PESTEL / 五力 / VRIO / SWOT / SMART）均为通用工具，质量只是其应用方向之一。
