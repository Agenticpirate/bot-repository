# 商品认知录入(引导写规范 intro)

把用户口述的商品认知,引导整理成**严格冒号软标签** intro 文本。产出直接用于 AI 导购商品知识库(系统 0 模型规则解析入库)。

## 何时用
- 用户说"帮我把这个商品整理成认知卡 / 规范简介 / 录入格式"
- 用户要按软标签格式写 `ai_product_intro`
- 不是让你推荐/比价商品——那是导购能力,不走本 skill

## 契约与示例(按需读,勿凭记忆)
- **格式契约(唯一事实源)**:`规范.md` —— 标签全集、行首规则、受控词、合规红线、判定阈值(N≥3)。开始前先读它。
- **产出样例**:`examples.md` —— 水牛奶/土鸡蛋/5号电池 + 反例。

## 交互流程
1. 先问:这是什么商品?给谁用?能帮用户做成什么?(按需追问卖点、事实、适用人群、场景、关键词)
2. 边问边把内容归到 `规范.md` 的对应标签:
   - 核心卖点(营销主张)与关键事实(客观可核实)必须分开;事实带 `(来源)`,推断标 `[推断]`。
   - 能力写 `能力名<-证据1；证据2`,须由卖点/事实支撑。
   - 适用人群只能取受控词;归不进的场景/功效会被系统丢弃。
3. 遇合规问题(绝对化用语/超范围功效/医疗用语)当场提醒并改写:违规词进 `禁用表达`,合规说法进 `允许表达`。
4. 校验:标签数 ≥3 且核心卖点或关键事实非空;不够就继续追问补齐。
5. 输出最终 intro(只输出那几行标签,每行行首是标签名,不加解释、不加代码块),末尾问一句"需要调整哪一项?"。

## 输出后
提示用户:把这段文本**原样复制**到商品平台的「商品简介 / ai_product_intro」字段。

## 同源约束
标签名/别名/阈值改动,须同步 `规范.md` + `system-prompt.md` + Python `intro_parser.py` + Java `IntroSoftSpecParser`(见 `changelog.md`)。
