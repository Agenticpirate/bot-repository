# 麦肯锡资料库顾问（McKinsey Library Consultant）

一个**带方法论内核、带闸门、可自主编排**的咨询交付工作流。它把用户上传的零散材料（文档 / 数据 / 笔记 / 会议记录）结构化成一页页「有结论、有论证、有数据来源」的咨询交付物，并能在内部材料不足时**自主搜集外部资料**、在确认后**自主产出 PPT 与演讲稿**。

**本 skill 的方法论不是通用知识，而是直接来自用户提供的麦肯锡资料库**（见下方「方法论来源」）。所有框架名、步骤名、提问清单都从原资料摘录，不臆造。

---

## 四段 + 闸门工作流

```
Phase 1    提问锁定      ──►  Phase 1.5  外部资料搜集与评估  ──►  Phase 2  生成故事线 md  ──►  [闸门：客户确认]  ──►  Phase 3  生成 PPT + 演讲稿
 (七步成诗 Step1)           (08 诊断方法 + 28 以无可争议的内容)     (七步成诗 Step2-6 + 故事框架)                    (故事框架 + 视觉规范 + 演讲稿)
```

**硬规则（默认开启，可经授权跳过）：客户未明确确认故事线（Phase 2 产物）之前，绝不进入 Phase 3 生成 PPT 与演讲稿。** 这是麦肯锡「先画鬼图、后写故事、再整理文件」（七步成诗 Step 4/7）的纪律。

**端到端自主编排（编排模式）：** 当用户明确授权「你自己来 / 全自动 / 端到端」，skill 可一次性自主完成 Phase 1 → 1.5 → 2 → 3，把「故事线 md + PPT + 演讲稿」整包产出，并明确标注「待你确认 / 可直接用」。即便自主编排，仍**严格保留「故事线先行、PPT 后行」的顺序纪律，绝不跳步**。

## Phase 1 — 提问锁定（七步成诗 Step 1：陈述问题）

拿到客户材料后，**先不要写**，用 5–7 个问题锁死以下内容（对应原资料「问题背景情况 6 要素」+「清晰阐述问题的特点」）：

- **主导问题 / 假设**：是一个具体、行动性强、以决策者下一步行动为重点的单一问题，而非问题罗列或无可争议的主张。
- **决策者是谁**（决策者 / 影响决策者的主要因素 / 听众是谁）。
- **时间安排**：多快要答案？哪些节点？
- **成功标准 / 主要衡量标准**：决策者如何判断问题被解决？关心什么变量？
- **所需准确度**：要强有力的方向指导，还是要精确细致？
- **期望对方读完做什么**（行动号召）。

提问话术与「客户答案 → 故事线落点」映射表见 `references/intake_questions.md`。

## Phase 1.5 — 外部资料搜集与评估（08 诊断方法 + 28 以无可争议的内容）

当内部材料不足以支撑故事线的某条分支时，skill **主动组织外部情报搜集**，而不是空着等客户补料。本阶段直接锚定你资料库里的真实方法：

### 1.5.1 识别证据缺口
从 Phase 2 的逻辑树分支出发，逐支判断：哪些结论缺**行业基准 / 竞品对标 / 市场数据 / 政策口径 / 客户实证 / 专家判断**？列出「缺口清单」（分支 → 缺什么 → 影响哪条结论）。

### 1.5.2 搜集策略（源自 `08` 的 5 类诊断方法）
- **全身扫描（full-potential scan）**：广撒网，扫描行业 / 市场 / 政策 / 技术全景，定位关键外部变量与机会规模。
- **序列分析（sequential analysis）**：沿价值链或时间线顺序取数，得到连贯的外部证据链。
- **任务分析 / OVA（objective-value-analysis）**：从客户或用户的目标—价值出发，找对应的外部行为/偏好证据。
- **价值评估（value assessment）**：用外部基准量化机会/问题的规模，把「感觉」变成「数量级」。

### 1.5.3 工具与动作
- 用 `WebSearch`（多关键词组 `query_keyword_groups`、`topic` 过滤）做广覆盖检索；用 `WebFetch` 抓权威源正文。
- 必要时联网取数（统计局 / 央行 / 交易所 / 公司财报 / 研报），不轻信大线性计划、不轻信单一来源。
- 详细话术、来源分级、三角验证流程见 `references/external_research.md`。

### 1.5.4 可信度评估（源自 `28`「以无可争议的内容来陈述情况」）
- **来源分级**：一手（政府统计 / 监管文件 / 公司财报）＞ 二手（券商研报 / 咨询报告）＞ 媒体 / 自媒体。
- **三角验证**：每条关键外部证据至少 2 个独立来源交叉印证，否则标注「待验证」。
- **口径透明**：标注数据时点与统计口径，估算值不得伪装成精确值。
- 评估通过的证据回填到对应分支的「资料来源」，并在 PPT 中作脚注。

## Phase 2 — 生成故事线 md（七步成诗 Step 2–6 + 故事框架）

这是核心交付物，输出一份 `故事线_<主题>.md`（模板见 `references/storyline_template.md`，已含「外部资料缺口与搜集计划」与「演讲稿」两节）。

### 2.1 分解问题（Step 2：逻辑树）
用 MECE 逻辑树把主导问题拆成互不重叠、完全穷尽的部分。三种树型任选（见 `references/methodology.md`）：
- **以假设为主**（先给假设，再找原因验证/推翻）
- **问题图**（关键问题用是/否回答，按行动逻辑排序）
- **推论**（用推论找出问题，按阐述逻辑树结论）

### 2.2 淘汰非关键（Step 3：漏斗法）
用 80/20 法则 + 反复追问「那又会怎样」「你忘了什么」，砍掉不重要分支。

### 2.3 工作计划（Step 4）
对保留的分支列：问题 / 假设 / 分析 / 资料来源（含 Phase 1.5 外部来源）/ 责任人时间 / 最终成品。**最终成品 = 画鬼图 + 写故事**。

### 2.4 关键分析（Step 5）
**以事实为依据，以假设为驱动**。简化分析、估算数量级、用 80/20、从专家取数、不轻信大线性计划。选框架见 `references/methodology.md` 的 18 框架 + 5 诊断方法。

### 2.5 综合成故事线（Step 6：金字塔 + 故事框架）
按**故事框架**（源自「如何建立演讲技能」）搭结构：
- **引言**：树立主题 → 说明对听众的重要性 → 概述各要点。
- **正文**：选 3–5 个话题，用 **逻辑论证**（无可争议的情况 → 说明 → 意义「因此…」，证明必然走向）或 **逻辑组合**（论据1/2/3，一点被否其余仍支持）。
- **结论**：回顾要点 → 联系主题 → 提建议 → 明确今后步骤。

每一页用**行动型标题**（结论句，不是标签），每条过 So-what 测试。模板见 `references/storyline_template.md`。

## Phase 3 — 生成 PPT + 演讲稿（仅在确认后，故事框架 + 视觉规范 + 演讲逻辑）

### 3.1 PPT（可视化布局目录 + 可解释选型 + 复用引擎）
每页遵循麦肯锡纪律：**一页一念**，页标题是行动型标题；数据用定量图、定性用流程图/地图/组织图；每张图带**脚注：资料来源**（含 Phase 1.5 外部来源）。

**3.1.0 布局计划（生成前必做，AX Labs 式可解释选型）**
先按 `references/layout_selection.md` 走选型流程：判定每页意图 → 在 `references/visualization_layouts.md`（**50+ 模式库**）映射候选 → 用否决规则定 1 个 → 写一句选型理由 → 产出「布局计划表」附在生成脚本头部。该表是 critic 门（3.3）的核对蓝图。

**3.1.1 落地**
调用 `pptx` skill，或直接用本 skill 自带的 `assets/pptx_primitives.py`（复用配色/字体/卡片/原生图表引擎，含 Treemap/矩阵/瀑布/漏斗/仪表盘等面积类图，已落实「防损坏三层」）。图表选型速查见 `visualization_layouts.md` 末节与 `methodology.md`「图表与视觉规范」。

**3.1.2 图表叙事铁律（源自 34 Treemap 案例）**
- 层级占比用 **Treemap**，横向大类对比用 **Mekko**，二者不可混。
- 行动型标题只中性设问，让结论「藏在图里」由读者自己发现。
- 分项之和≠100% 时主动脚注 "Figures may not sum to totals, because of rounding"。

### 3.2 演讲稿（口语化完整口播稿）
在 PPT 之外，另产一份**完整演讲稿** `演讲稿_<主题>.md`（模板见 `references/storyline_template.md` 末节），用故事框架的引言/正文/结论逻辑写：
- **开场**：30 秒抓住注意力，抛核心结论 + 对听众的价值。
- **逐页口播**：每页一段口语稿，含过渡句、重音提示、可能的停顿点。
- **收尾**：回顾要点 → 重申建议 → 明确行动号召与今后步骤。
- **Q&A 预案**：预判 3–5 个尖锐提问（尤其针对外部证据的口径/来源）并备答。
- 同时 PPT 仍附精简版演讲备注（每页 2–3 句提示）。

> 编排模式下，Phase 3 与故事线一并产出，成「故事线 md + PPT + 演讲稿」三件套，标注「可直接用 / 待微调」。

### 3.3 Critic 视觉质量门（交付前强制）

PPT 生成后、**交付用户前必须走 critic 门**（详见 `references/critic_checklist.md`）：
1. LibreOffice 转 PDF → PyMuPDF 逐页转图；
2. 用子代理按 12 项清单（重叠/溢出/图表/装饰/页脚/间距/页边距/对齐/对比/字体/占位符/模式一致）逐页巡检；
3. 高严重度问题必修，中低酌情；修复后只重渲染问题页复检；
4. 复检通过后标注 **「可直接用 / 待确认」**（编排模式默认「待确认」）。

> critic 门不可跳过——即便编排模式全自动，质量门仍是硬开关。
