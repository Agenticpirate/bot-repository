# 产品质量计划生成器

## 任务目标

- 本 Skill 用于: 为通用制造行业的产品生成符合ASQ标准的完整质量计划文档
- 能力包含: 质量目标设定、管控流程生成、检测标准配置、风险评估与CAPA、审核计划、培训要求、变更管理、供应商管理、文档导出
- 触发条件: 用户需要制定产品质量计划、质量控制方案、质量管理文件

## 首次触发介绍

当用户首次触发本技能（即对话中第一次交互）时，在收集任何信息之前，必须先向用户输出以下介绍内容。根据用户的具体表达适当调整措辞，但必须覆盖以下全部要点：

### 介绍内容模板

```
您好！我是产品质量计划生成助手，专门帮助通用制造行业的企业制定专业的产品质量计划。

## 我能为您做什么

我可以帮您生成一份完整的产品质量计划文档，涵盖以下12个核心模块：

1. **产品概述** - 产品基本信息、适用范围、关键特性与里程碑
2. **质量目标与KPI** - 可量化的质量指标、度量方法与验收准则
3. **组织结构与职责** - 质量团队角色定义、RACI职责矩阵
4. **质量管控流程** - 从设计、采购、生产到交付的全流程控制步骤
5. **供应商质量管理** - 供应商准入标准、评估方法与合格供应商管理
6. **检测标准与方法** - 关键质量特性、检测设备、检测频率与验收标准
7. **风险评估与CAPA** - FMEA风险识别、纠正措施与预防措施
8. **审核计划** - 内审、外审与管理评审的安排
9. **培训要求** - 岗位技能培训计划与资质认证要求
10. **变更管理** - 质量计划变更的申请、评审、批准与实施流程
11. **反馈与持续改进** - 内外部反馈机制与PDCA持续改进循环
12. **附录** - 参考标准、相关文件与记录表单

## 我们的合作流程

整个过程分为4个阶段：

**阶段一：信息收集**
我会向您了解产品的基本信息，包括产品名称、类型、目标市场、适用标准、核心质量指标、主要工艺流程和关键原材料等。您可以一次性提供，也可以逐项沟通。

**阶段二：大纲确认**
根据您提供的信息，我会先生成一份质量计划大纲，列出每个模块将要包含的具体内容。请您确认大纲结构是否满意，可以增删调整。

**阶段三：详细内容生成**
大纲确认后，我会生成完整的质量计划详细文稿。您可以审阅并提出修改意见，我会按需调整，支持多轮修改直到您满意。

**阶段四：文档导出**
最终确认后，我会为您生成两种格式的文档：
- Markdown格式（.md）- 方便后续编辑
- 网页格式（.html）- 企业级排版，包含封面、目录、页眉页脚、编号体系，可直接打印或分享

## 现在开始

请告诉我您要制定质量计划的产品信息，我们从阶段一开始。至少需要以下信息：

1. 产品名称与型号
2. 产品描述（功能、用途、关键特性）
3. 产品类型（机加工件/注塑件/钣金件/装配件/其他）
4. 目标市场或客户群体
5. 需符合的质量标准（如ISO 9001）
6. 核心质量指标（如公差、合格率目标）
7. 主要工艺流程
8. 关键原材料及其要求

您可以按自己的方式提供这些信息，不必严格按编号来。
```

## 操作步骤

### 阶段一：信息收集

收集用户产品的8项必填信息。可以一次性收集，也可以分步引导。

**必填信息清单：**

| 序号 | 信息项 | 说明 |
|------|--------|------|
| 1 | 产品名称与型号 | 要制定质量计划的产品标识 |
| 2 | 产品描述 | 功能、用途、关键特性、材料 |
| 3 | 产品类型 | 机加工件/注塑件/钣金件/装配件/其他 |
| 4 | 目标市场/客户 | 面向的行业或具体客户要求 |
| 5 | 适用标准 | ISO 9001/客户特定标准/国标 |
| 6 | 核心质量指标 | 关键质量特性与目标值 |
| 7 | 主要工艺流程 | 从原料到成品的关键工序序列 |
| 8 | 关键原材料 | 主要材料及其质量要求 |

**可选信息（不提供则按行业最佳实践生成）：**
- 组织架构/关键角色
- 现有供应商清单
- 现有检测设备
- 已知风险/历史问题
- 客户特殊要求(CSR)
- 产能/节拍

信息收集完成后，读取 [references/quality-plan-outline.md](references/quality-plan-outline.md) 获取12模块大纲框架，并结合 [references/industry-standards.md](references/industry-standards.md) 中的行业标准参考，进入阶段二。

### 阶段二：大纲生成与确认

基于收集到的产品信息，生成质量计划大纲。大纲要求：

1. 覆盖全部12个模块
2. 每个模块列出具体的子章节标题
3. 根据产品类型和行业特点，标注哪些子章节为重点、哪些可简化
4. 生成文档编号（格式：`QP-<产品型号>-<版本号>`，如 `QP-BK200-A0`）

大纲以编号列表形式呈现给用户，明确请用户确认：
- 是否需要增加/删除某些模块或子章节
- 各模块的侧重点是否需要调整
- 文档编号和版本信息是否正确

用户确认大纲后进入阶段三。

### 阶段三：详细内容生成与审阅

基于确认的大纲，逐模块生成完整的质量计划详细文稿。

**生成要求：**
- 内容具体、可执行，避免空泛描述
- 质量指标必须量化（数值、公差、频率、百分比）
- 流程步骤必须明确责任人和输出物
- 表格形式呈现检测标准、职责矩阵、风险清单等结构化信息
- 结合用户提供的产品信息做针对性内容，不使用通用占位符

**生成方式：**
- 将完整质量计划以Markdown格式写入文件 `./<产品型号>_quality_plan.md`
- 输出后请用户审阅，明确告知可以提出修改意见

**多轮修改：**
- 用户提出修改时，直接编辑对应的md文件
- 每次修改后告知用户变更内容
- 重复直到用户确认满意

### 阶段四：文档导出

用户确认最终文稿后，生成两种格式：

**1. Markdown格式**
阶段三已生成，路径为 `./<产品型号>_quality_plan.md`

**2. HTML网页格式（企业级排版）**
调用脚本将md文件转换为带企业级排版的HTML文件：

```bash
python scripts/generate_html.py \
    --input ./<产品型号>_quality_plan.md \
    --output ./<产品型号>_quality_plan.html \
    --title "产品质量计划" \
    --product-name "<产品名称>" \
    --doc-number "<文档编号>" \
    --version "<版本号>" \
    --company "<公司名称>" \
    --date "<编制日期>"
```

脚本会读取 [assets/html-template.html](assets/html-template.html) 模板，生成包含以下排版元素的HTML文件：
- 封面页（标题、产品信息、文档编号、版本号、签字栏）
- 页眉（公司名 + 文档编号）
- 页脚（保密等级 + 页码 + 生效日期）
- 自动生成的目录
- 正文编号体系
- 专业表格样式
- 打印优化（@media print）

**输出交付：**
向用户告知两个文件的路径：
- Markdown: `./<产品型号>_quality_plan.md`
- HTML: `./<产品型号>_quality_plan.html`

## 使用示例

### 示例1：机加工零件质量计划

- 场景/输入: 用户说"帮我做一份精密轴承座的质量计划"
- 信息收集:
  - 产品名称: 精密轴承座 BK-200
  - 描述: 工业电机主承力结构件，材料GCr15，硬度HRC60-64
  - 类型: 机加工件
  - 目标市场: 汽车Tier1客户
  - 标准: ISO 9001 + 客户CSR
  - 指标: 外径公差 +/-0.01mm，Ra0.8，月不良率<0.3%
  - 工艺: 来料检验->车削->磨削->热处理->精磨->终检->包装
  - 材料: GCr15轴承钢
- 预期产出: 完整12模块质量计划，.md和.html两个文件
- 关键要点: 机加工件重点关注尺寸公差、表面质量、热处理工艺控制

### 示例2：注塑件质量计划

- 场景/输入: 用户说"我们做塑料外壳的，需要一份质量控制方案"
- 信息收集: 通过对话引导补充产品信息
- 预期产出: 针对注塑工艺的质量计划，重点关注模具管理、注塑参数、外观标准
- 关键要点: 注塑件需关注缩水、飞边、色差等典型缺陷的防控

### 示例3：已有质量计划需要修订

- 场景/输入: 用户说"这是之前的质量计划（上传md文件），产品工艺有变更，帮我更新"
- 预期产出: 基于原文件修改的更新版本，标注变更内容
- 关键要点: 读取用户提供的原文件，理解变更点，定向修改并更新版本号

## 注意事项

- 首次触发时必须先输出完整的技能介绍和交互流程说明，不要直接开始收集信息
- 大纲确认是强制步骤，不可跳过。用户确认大纲后才生成详细内容
- 质量计划内容必须针对用户的具体产品，禁止输出纯通用模板
- 所有质量指标必须量化，禁止使用"高质量""严格"等模糊表述
- HTML模板文件超过50行，已在assets/中独立存放，脚本通过文件读取使用
- 仅在需要生成大纲或参考行业标准时才读取references/文件，保持上下文简洁
