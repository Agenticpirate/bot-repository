# 招投标全景透视

> 你的下一个客户正在招标，但你知道了吗？让 Cue 双擎互补全量扫描全国招投标平台——自动发现匹配你业务的招标项目、监控竞争对手中标动态、补齐联系方式帮你触达采购方。比竞争对手早一步，就多一个订单。

## 适用范围与场景（先看这个，别用错了）

**可以查：**

| 维度 | 覆盖 |
|------|------|
| 平台覆盖 | 企查查-招投标 + 知了标讯，双引擎互补覆盖全国公开招投标信息 |
| 行业覆盖 | 全行业——建筑工程/IT服务/工业品/医疗/教育/环保/能源/交通/物业/咨询等 |
| 时间范围 | 默认近两周，可指定时间窗口（近一周/近一月/近三月/自定义） |
| 分析深度 | 招标项目扫描、竞争对手中标分析、联系方式补齐、大额项目溯源、中标趋势统计 |

**适用场景：**

| 场景 | 解决的问题 |
|------|-----------|
| B 端拓客 | 每天都有新客户在招标，但你不知道——Cue 帮你自动发现匹配你业务的在招项目 |
| 竞对监控 | 竞争对手最近中了哪些标？报价水平如何？有没有在你地盘抢客户？ |
| 政企销售线索 | 政府采购、国企招标——门槛高但利润厚，第一时间知道才能提前准备 |
| 合作伙伴发现 | 大项目的中标方是谁？有没有分包或联合体投标的机会？ |
| 行业招标趋势 | 某类项目最近招标量在增加还是减少？哪个地区最活跃？ |

**不能查：**

- 非公开邀标或单一来源采购（未在公开平台发布公告）
- 招标文件全文下载（Cue 做信息聚合，不做文件托管）
- 投标报价策略或中标概率预测
- 企业内部的采购计划或预算信息（非公开）
- 招标方内部评审细节或评标委员会名单

> 简单判断：**这个招标信息在公开招投标平台能搜到吗？** 能 → 用它。是私下邀标、没有公开发布公告 → 用不了。

## 核心能力

1. **双擎互补全量扫描** — 内部 MCP 引擎 + 外部搜索引擎互补，覆盖主流招投标平台与搜索引擎索引，减少漏标
2. **时间分块防截断** — 大时间跨度自动拆分为小时间窗口逐块扫描，防止数据量过大导致截断或超时
3. **招标/已结束物理隔离** — 正在招标与已结束项目严格分区展示，不会把已截标的项目混在商机里
4. **联系方式补齐** — 自动匹配招标方/采购方的公开联系方式（电话/邮箱/地址），方便快速触达
5. **大额项目溯源** — 大额标自动深挖采购方背景、项目背景，帮助判断项目质量和竞争格局
6. **竞对中标监控** — 指定竞争对手名称，自动汇总其中标记录——中标金额、采购方、中标时间、项目类型

## 输出形式

结构化商机报告：

**Part 1：正在招标（商机清单）**
招标项目名称 → 采购方 → 预算金额 → 截止日期 → 联系方式 → 地区 → 来源平台 → 项目链接

**Part 2：近期中标（竞对参考）**
中标方 → 项目名称 → 中标金额 → 采购方 → 中标日期 → 来源平台

**Part 3：趋势分析**
招标量趋势 → 活跃地区分布 → 平均项目金额 → 主要采购方画像 → 主要中标方排名

## 性能预期

招投标扫描涉及多个外部数据源聚合，耗时比单一数据源查询更长：

| 维度 | 预期耗时 | 说明 |
|------|---------|------|
| 窄范围扫描（单关键词 + 近一周 + 单地区） | 3-8 分钟 | 数据量小，处理快 |
| 常规扫描（单关键词 + 近两周 + 全国） | 5-15 分钟 | 正常负载 |
| 宽范围扫描（多关键词 + 近一月 + 全国） | 10-20 分钟 | 时间分块多，聚合计算量大 |
| 竞对监控（单公司 + 近半年中标） | 5-15 分钟 | 跨平台去重和聚合耗时 |
| 工作日 9:00-18:00 | 正常 | 招投标平台响应快 |
| 夜间 / 周末 | 可能变慢 | 部分招投标平台维护或限流 |

> 招投标扫描的特殊性：需要访问多个外部招投标平台，单个平台响应慢会影响整体耗时。如果超过 20 分钟没返回，说明某个源平台可能超时——**不要取消重试**，跑一下健康检查确认 Cue 服务状态，中断后用相同命令续接。Session 状态存储在 `~/.cue/session/task`，**不要手动删除**。

## 架构说明

本 Skill **不在本地执行检索**。流程是 Agent → Cue API（cuecue.cn）→ 企查查-招投标 + 知了标讯双数据源互补。扫描结果的质量和时效取决于 Cue 服务端和两个招投标数据源的状态。

**双数据源架构：**

| 数据源 | 覆盖 | 优势 | 局限 |
|------|------|------|------|
| 企查查-招投标 | 企业工商关联 + 招投标信息 | 可关联企业工商背景、股东、对外投资等全景信息 | 招投标数据深度依赖于企查查的采集覆盖 |
| 知了标讯 | 招投标信息聚合 | 招投标数据专注度高、更新频率快 | 企业背景信息不如企查查丰富 |

> 两个数据源结果自动去重合并，互补覆盖盲区。扫描质量和时效取决于招投标源平台的可用性。

| 环节 | 谁控制 | 出问题时 |
|------|--------|---------|
| API Key 鉴权 | 你 | 重新生成 Key，更新 ~/.cue/config.json |
| Cue 服务端 | Cue 运维 | 等恢复，或走降级方案 |
| 企查查-招投标 / 知了标讯 | 各数据源 | 部分数据源可能限流或临时不可达，Cue 标注"部分源暂不可达" |

## 自救指引

### 错误速查

Cue 返回结构化错误，包含 `code`（错误码）、`retryable`（是否可重试）、`user_action`（操作建议）。

| 错误码 | 现象 | 可重试？ | 处理 |
|--------|------|---------|------|
| `AUTH_FAILED` | 401 / Key 无效 | ❌ | 重新生成 Key，更新 `~/.cue/config.json` |
| `TIMEOUT` | 超时 >30s 无响应 | ✅ | 等 5 分钟，跑诊断确认服务在线后重试，最多 3 次。若持续超时，缩小时间范围或地区范围 |
| `BUDDY_UNAVAILABLE` | 搭子临时下线 | ✅（延迟） | 等 1h 或网页端直接跑 |
| `INSUFFICIENT_CREDITS` | 积分不足 | ❌ | [cuecue.cn](https://cuecue.cn) 充值或等次日免费额度 |
| `SESSION_INTERRUPTED` | 中途中断 | ✅ | **不换 prompt**，相同命令续接——Cue 从 session 断点继续，已扫描的窗口不重复计费 |
| `SOURCE_PLATFORM_DOWN` | 部分招投标源平台不可达 | ✅（延迟或降级） | 换个时段重试，或接受"部分源暂不可达"的标注结果继续使用 |
| `KEYWORD_TOO_BROAD` | 关键词太宽泛导致数据量过大 | ❌（需改条件） | 缩小关键词范围、限定地区、缩短时间窗口 |
| `RESULT_EMPTY` | 无匹配结果 | ❌（需改条件） | 换个关键词、扩大时间范围、检查该行业是否以公开招标为主要采购方式 |
| `RATE_LIMITED` | 外部招投标平台临时限流 | ✅（延迟） | 等 30 分钟后重试，招投标平台通常每小时限流 |
| `CONFIG_PARSE_ERROR` | config.json 报错 | ❌ | 修复 JSON 格式：`{"api_key": "sk..."}` 无多余逗号 |

### 中断恢复机制

Cue 的调研任务是**有状态**的。招投标扫描因为涉及多个外部平台，偶发中断是正常现象：

```
中断 ≠ 失败，cancel 才 = 失败
├─ 单个源平台超时 → 该平台标注"暂不可达"，其他平台结果正常返回
├─ 整体超时 → 等一会，相同命令续接（session 存在 ~/.cue/session/task）
├─ 网络波动 → 同上，相同命令续接，已扫描的时间窗口不会重复
├─ 手动 cancel → 无法恢复，已扫描的部分结果丢失，需要重新发起
└─ 恢复后 → Cue 从断点继续，已查过的时间窗口不会重复计费
```

> **关键规则**：中断后**不要换 prompt、不要删 session 文件、不要 cancel**。三个"不要"记住了就不会白跑。招投标扫描的特殊性——时间分块机制意味着即使部分窗口超时，已完成的窗口数据仍然有效。

### 重试决策

```
收到错误
├─ retryable = true → 按 user_action 建议操作后重试
│   ├─ 超时/网络类 → 等 5min，跑诊断，最多 3 次
│   ├─ 源平台不可达 → 等 30min 或接受降级结果
│   ├─ 源平台限流 → 等 30min
│   └─ 搭子下线 → 等 1h 或换网页端
├─ retryable = false → 不要重试，改了条件再说
│   ├─ Key 问题 → 重新生成 Key
│   ├─ 关键词太宽 → 加限定词、缩小地区和时间
│   ├─ 积分不足 → 充值或等次日
│   └─ 结果空 → 换关键词 / 确认该行业有公开招标习惯
└─ 重试 3 次仍失败 → 记下 request_id，走降级方案
```

### 调度建议

| 时段 | 建议 |
|------|------|
| 工作日 9:00-18:00 | 招投标平台正常运行，扫描效果最好 |
| 工作日 10:00-16:00 | Cue 服务最佳时段 |
| 周一上午 / 周五下午 | 新招标公告集中发布时段，商机最密集 |
| 夜间/周末 | 部分招投标平台可能维护，跑前先诊断 |
| 月初/季初 | 政府采购项目集中发布期，重点关注 |
| 连续失败 ≥2 次 | 停 15 分钟，记下 request_id 后重试 |

## FAQ

**Q: 双擎互补是什么意思？和手动在招标网搜索有什么区别？**
A: 内部 MCP 引擎对接主流招投标平台的结构化 API（数据干净、字段完整但平台数有限），外部搜索引擎补充长尾平台和被 API 遗漏的公告（覆盖广但需要解析）。两个引擎结果自动去重合并——你搜一次，相当于手动在五六个招标网站 + 搜索引擎各搜一遍。

**Q: 能保证扫到所有相关招标吗？**
A: 不能保证 100%。原因有三：(1) 部分招标平台有反爬或限流；(2) 邀标和单一来源采购不公开发布；(3) 某些企业自建招标平台不在公开索引范围。但双引擎互补能覆盖市面上绝大部分公开招标信息，漏标率远低于单平台手动搜索。

**Q: 时间分块防截断是什么？为什么需要它？**
A: 当时间跨度大（比如近三个月）时，一次查询的数据量可能超过处理上限导致截断——你会发现"怎么才扫到几条就没了"。Cue 自动把大时间窗口切成小块（如按周分块），逐块扫描再合并结果，确保长周期查询不会因为数据量截断而丢数据。

**Q: 联系方式补齐是怎么做到的？能保证打得通吗？**
A: Cue 从招标公告原文、采购方官网、工商信息等公开渠道自动提取电话/邮箱/地址。联系方式是公开信息中已有的，Cue 做的是聚合匹配——把分散在各处的联系方式跟招标项目关联起来。能否打通取决于采购方是否更新了公开信息，Cue 无法保证实时性。

**Q: 怎么知道该用这个还是 cue-deep-research？**
A: 本搭子聚焦"招投标维度"——找正在招标的商机、监控中标动态、分析招标趋势。cue-deep-research 聚焦"公司维度"——对一家公司做全面尽调（财务/业务/风险/竞争）。当你通过招投标发现一个潜在客户后，用 deep-research 对这家公司做深度背景调查。

**Q: 竞对监控支持多少家竞争对手？**
A: 单次查询建议聚焦 1-3 家核心竞对。太多了扫描时间会显著增加，而且去重和聚合的复杂度也会上升。如果需要监控更多竞争对手，建议分批进行。

**Q: 扫描到的项目已经过期了怎么办？**
A: Cue 会将"正在招标"（截止日期未过）和"已结束"项目物理隔离在两个区域展示。如果你看到已过期的在"正在招标"区，说明源平台数据更新有延迟——以项目详情页的官方截止时间为准，Cue 标注的截止时间仅供参考。

**Q: 大额项目溯源能追溯到什么程度？**
A: 采购方工商信息（注册资本/股东/主营业务）、项目背景（资金来源/建设内容/分标情况）、历史同类项目中标价参考。目的是帮你判断这个项目是否值得投入资源去投——几百万的标和几千万的标，准备成本不一样。
