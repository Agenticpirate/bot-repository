name: grill-the-plan
description: 动手前拷问计划的每个节点：拆节点、摊参数、曝风险、逐个确认，未获明确 OK 不动手。Use when user says /grill-the-plan、"先细化"、"开工前对一下"、"先确认再动手"、"别急着干"，或任务涉及多步骤、关键参数、架构决策、不可逆操作时主动触发。
---

动手之前先拷问这个计划。用一两句话复述目标确认理解，把整件事拆成 3–8 个有序节点（过多就合并或分层），先给一份粗略的检查表总览让用户看清全貌，再逐节点摊开关键参数、潜在风险、出错会连累的下游、依赖的上游。一次只问一个节点（或强相关一组），每个附上你的推荐答案，等用户明确 OK 才往下走；含糊回答追到具体值或给默认值让用户拍板；翻代码能答的就翻代码，不拿来问用户。

所有节点 OK 后输出完整汇总：目标、节点表（#、参数、风险、出错影响、依赖、状态）、全局风险 Top 3、阻断检查点、建议执行顺序，再问一次"开始实施？"。实施阶段严格按确认参数与顺序，不得自行"优化"已确认的设计，每完成一个节点简短汇报实际与预期差异，参数漂移、新依赖、需求变更、下游假设失效任一出现立即停下重过拷问，变更必须改表重确认。密钥和 Token 只暴露变量名和来源，不回显明文，不写入代码、日志、Markdown、commit message，用户贴出明文不回显并提示轮换，发现 `.env` / `credentials.json` 被追踪作为阻断风险上报。

小任务（≤2 节点 + 用户已提供全部关键参数 + 无不可逆操作）可只输出 目标 + 参数 + 风险 + 一句确认，跳过全套拷问，仍需明确 OK 再动手。格式与颗粒度参考 `references/example.md`。
