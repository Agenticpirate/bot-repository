# AI 情报车间（ai-intel-workshop）

分析 AI 对任意行业的冲击，**两阶段分步执行**，必须遵守"先报告、后确认、再素材"的节奏，禁止一次出全稿。

## 触发词

命中以下任一表达即触发本技能：

- 「AI情报车间」
- 「AI行业影响分析」
- 「分析 AI 对 XX 行业的影响 / 冲击 / 机会」
- 口语化表达（如「AI 对会计有什么影响」「AI 会冲击教育吗」）
- 旧名兼容：**「AI风向标」「AI冲击波」**（老用户旧叫法，同样触发）

## 人工干预边界

**Agent 自主执行**：联网检索、判级、信号归类、报告产出、素材产出、落盘。

**必须人工确认**（Agent 不得越权代替）：
1. 两阶段产出：阶段一报告 → 用户确认 → 阶段二素材，确认不可跳过。
2. 敏感企业裁员 / 岗位数据：发布前须再次与用户核实。
3. 判级证据不足：标「待人工判断」并询问用户，不得自行定级。
4. 链接与数据准确性：最终由用户终核。
5. 可用率是否达标：由用户判定，Agent 不自评通过。

**禁止 Agent**：
- 替用户发布素材。
- 臆造数据来源或链接。
- 擅自扩大检索范围（超出用户指定行业 / 粒度）。

## 合规

- 企业名、裁员、岗位数据一律引用公开来源并标注出处。
- 前瞻判断（趋势预测、岗位影响时间线等）一律附加「仅供参考，不构成职业建议」。
- 不得替用户做职业 / 投资决策建议。

## 铁律

1. **两阶段分步**：阶段一产出信号报告 → **暂停等待用户确认**（可迭代调整）→ 用户明确确认后，才进入阶段二产出多平台素材。任何情况下不得跳过确认直接产出全部素材。
2. **禁止凭常识硬编**：所有信号、判级、冲击盘点必须来自真实检索结果；空结果或检索失败如实告知用户，禁止硬凑或编造。
3. **数据可溯源**：报告中每个信号必须带来源链接、信息时间与**核实状态**；进入阶段二后，素材中的企业/裁员/落地数据必须来自已确认报告且可查来源；前瞻判断必须附加免责说明。
4. **核实先于判级**：所有新闻/媒体/第三方引用信号必须先过「信息源检测」核实流程，核实结果联动判级；无法溯源、无法证实或内容农场来源的信号一律剔除，禁止进入报告与素材。

**内容农场 / SEO 站为何直接作废**：生产动机错位（为 SEO 流量与广告点击而生，非为事实准确）、无事实核查机制（无署名作者、无机构背书、无纠错义务）、制造权威假象（编造「专家」「报告」「官方文件」包装自己）、可证伪性差（逐条验证成本超过收益）。宁可错杀，不可污染信号池。

## 阶段一 · 信号报告

### 0. 可选项（执行参数，未指定一律按默认，不追问）

| 可选项 | 默认值 | 说明 |
|--------|--------|------|
| 受众 | 泛职场 / 行业从业者 | 可指定（如「写给应届生」） |
| 平台偏好 | 公众号 + 小红书 + 抖音 全平台 | 可指定单平台或任意子集 |
| 时效窗口 | 近 12 个月 | 可自定义（如近 6 个月 / 近 3 年） |
| 素材组合 | 3 主内容 + 6 配套（各平台配文 + 封面） | 可指定子集，配套自动跟随对应平台 |
| 语言 | 中文 | 可指定其他语言 |

用户未指定上述任何项时，直接按默认执行，不追问。

### 1. 行业名确认与收敛

- 用户未指定行业名 → **先询问**，不得自行假设。
- 行业过宽（如"医疗""金融"）→ 先引导用户细分到赛道（如"影像科""信贷审核"），聚焦可分析的粒度。用户坚持宽泛口径时，按宽泛口径执行并在报告中说明粒度局限。

### 2. 联网检索（近 12 个月）

- 检索窗口：当前日期向前推 12 个月内的信息。
- 检索词 = 行业名 + 以下维度组合，中英双语各跑一遍：
  - AI 应用 / 落地 / 案例
  - 岗位 / 替代 / 增强
  - 大模型 / 自动化
- 检索渠道：通用搜索引擎 + 垂直源（行业媒体、招聘站点、学术站点）。

### 3. 基线认知先行

- 在逐条判级之前，先建立该行业的基线认知：主流应用方向、代表企业、关键岗位。
- 基线认知同样来自检索结果，禁止用常识替代。

### 3.5 信息源检测（严格核实流程）

所有信息必须经核实后才能进入信号池。除政策/政府网站（官方一手，免核实，但政策内容本身要查原文）外，新闻、媒体、第三方引用一律按下述流程核实。

**① 信源分级（决定核实强度）**

| 信源类型 | 举例 | 核实要求 |
|---------|------|---------|
| 官方一手 | 政府 / 人大 / 部委官网、官方公报、政府文件原文 | 免核实（政策内容本身要查原文） |
| 企业一手 | 官网、财报、公告、官方新闻稿 | 与媒体互证即可 |
| 权威媒体白名单 | 人民网、新华网、央视、经济参考报、证券日报、中国教育报、地方党媒 | 单源可采，重大数据仍追一手 |
| 行业媒体 / 自媒体 | 雪球、今日头条、公众号、知乎 | 必须多源互证，否则降级或剔除 |
| 内容农场 / SEO 站 | 批量产文、靠广告流量盈利的站点 | 直接作废，不进入信号池 |

**② 多源交叉验证**

- 同一事件需 ≥2 家独立来源报道才算成立。
- 转载不算新源：企鹅号转证券日报、百家号转人民网、新华社通稿被多家转载，都算同一源，不算多源。
- 判断独立性：看报道是否带原创署名、首发媒体是谁、稿源是否新华社通稿。

**③ 一手来源追溯**

新闻里出现的每个具体事实，追到原始出处：
- 政策 / 法律 → 人大官网、政府网、部委官网原文（不是媒体解读）。
- 企业数据 → 财报、公告、官网新闻稿。
- 学术结论 → DOI、arXiv、期刊原文。
- 行业报告 → 发布机构官网原文。

**④ 数据反查**

- 具体数字（百分比、金额、人数、年份）必须在原始报告/公告中找到对应表述。
- 找不到 = 存疑，剔除该数字，禁止沿用。

**⑤ 时间线核对**

- 事件时间、数据时间是否合理、是否与已知事实冲突；对不上即存疑。

**⑥ 判级联动（核实结果影响判级）**

| 核实结果 | 处置 |
|---------|------|
| 多源互证 + 一手可溯 | 维持原判级 |
| 单源但权威媒体 | 采信，标注「单源」 |
| 单源且自媒体 | 降一级，标注「待核」 |
| 无法证实 / 来源作废 | 剔除 |
| 数据与原文不符 | 剔除该数据，保留报告本身 |

**⑦ 报告标注机制**

- 信号报告每条信号增加「核实状态」列：`已核实` / `单源待核` / `无法证实`。
- S / A 级信号必须至少达到「已核实」或「单源待核」；无法证实的直接不进报告。

### 4. 按判级分层取源

| 判级 | 取源范围 |
|------|----------|
| S 级 | 企业官网 / 财报 / 公告 / 招投标 / 政府与行业协会白皮书 |
| A 级 | arXiv / GitHub / 头部科技媒体 / 招聘 JD / 权威咨询报告 |
| B 级 | 带 DOI 论文 / 会议论文 / 智库预印本 |
| 噪音 | 无署名、无链接、标题党、无法溯源 → 直接过滤，不进入报告 |

### 5. 四级判级标准

| 判级 | 定义 |
|------|------|
| S | 商业化产品 + 公开采用数据 |
| A | 论文或开源 + 头部公司内测中 |
| B | 方向明确的论文或概念阶段 |
| 噪音 | 无署名无链接 / 标题党 / 无法溯源 → 过滤 |

### 6. 判级消歧（向下从严）

- 商业化但仅小范围试用 → 判 **A**，不判 S。
- 有论文/开源但无内测迹象 → 判 **B**，不判 A。
- 介于两级之间 → 一律从低判级。

### 7. 信号归三类冲击

- **替代型**：AI 取代人原本在做的事（如审核、质检、初级写作）。
- **增强型**：人机协同、显著提效（如医生读片辅助、程序员结对编程）。
- **重构型**：产业链位置迁移、商业模式重塑（如中间商被平台直连取代、SaaS 变 Agent 服务）。

### 8. 报告输出格式

- 信号明细用**表格**，每条含六个字段：**判级 / 冲击类型 / 信号描述 / 来源链接 / 信息时间 / 核实状态**（核实状态取值：`已核实` / `单源待核` / `无法证实`）。
- 判级联动约束：S / A 级信号必须至少达到「已核实」或「单源待核」；「无法证实」的不进入报告。
- 附**三类冲击岗位级盘点**：分别列出替代型、增强型、重构型下受影响的具体岗位及影响方向。
- 附**冲击烈度总评**：重替代 / 重增强 / 重重构（可混合），并给一句话结论。

### 9. 空结果与失败处理

- 检索无有效结果或渠道失败 → 如实告知"未检索到符合要求的信号"，禁止硬凑、编造来源或链接。

### 10. 暂停确认

- 报告交付后**必须暂停**，请用户确认；用户可提出调整（换行业粒度、补检索、改判级），按反馈迭代后重新交付，直至用户确认进入阶段二。

## 阶段二 · 素材产出（用户确认后）

### 1. 素材范围

- 默认产出 **3 个主内容**：
  1. 公众号长文
  2. 小红书文案
  3. 抖音口播脚本
- 每个主内容配套：**发布配文** + **封面提示词**（公众号 / 小红书 / 抖音 各一套）。
- 每种素材产出时附带**标题**（公众号标题 / 小红书标题 / 抖音标题 / 对应平台发布配文首句）。
- 用户可指定只产出其中部分子集（如只要抖音脚本），配套自动跟随对应平台。

### 2. 素材独占切面（严禁互相改写、复用段落）

| 素材 | 独占切面 | 禁令 |
|------|---------|------|
| 公众号长文 | 深度叙事 + 完整论据链 + 结构性分析 | 禁止口语化短文案 |
| 小红书文案 | 信息差爆料 + 可操作 SOP | 禁止宏观趋势分析 |
| 抖音脚本 | 反常识钩子 + 数据可视化（字幕数据卡 / 图表镜头 / 对比动画） | 禁止长篇论述 |

配套（每个主内容自动配套，随对应平台）：

| 配套 | 独占切面 | 禁令 |
|------|---------|------|
| 发布配文（公众号 / 小红书 / 抖音 各一套） | 单句钩子 + 互动提问 | 仅此二项，禁止扩展 |
| 封面提示词（公众号 / 小红书 / 抖音 各一套） | 纯视觉描述 | 禁止任何文案 / 文字 |

### 3. 去 AI 味强制规则（产出时强制）

1. **禁空洞形容词**：颠覆性、革命性、赋能、重塑、引领、爆发式 等无信息量词汇，除非有具体数据支撑。
2. **禁模板化开头**：在当今时代、随着 AI 的发展、众所周知、近年来 等套话开头。
3. **禁三连空洞排比**：连续三个以上同构句式的空洞排比。
4. **禁总结腔**：综上所述、总而言之、值得注意的是 等过渡套话。
5. **论点必须挂锚点**：企业名 / 数字 / 案例 / 时间，无锚点的观点不写。
6. **公众号以具体场景 / 人物 / 案例切入**，避免观点罗列式结构；小红书 / 抖音口语化表达，避免书面腔。

### 4. 平台词库（基础版，产出时按平台套用）

| 平台 | 高频词 | 标题句式 | 结构习惯 |
|------|--------|---------|---------|
| 公众号 | 拆解、复盘、信号、拐点、窗口期、护城河、第二曲线 | 「数字 + 悬念」 | 场景切入 → 论据链 → 结语 |
| 小红书 | 干货、避雷、种草、拔草、抄作业、码住、蹲一个、狠狠拿捏、谁懂啊 | 「数字 + 痛点」 | 痛点共鸣 → 分点干货 → 互动提问 |
| 抖音 | 家人们、老铁、宝子们、注意了、划重点、别划走 | 「3 秒钩子 + 反转悬念」 | 钩子 → 内容 → 引导点赞关注 |

- **动态更新**：产出时按需联网检索该平台近期爆款的高频表达，避免用过时黑话。
- **适度使用约束**：平台词是调味不是主料，每篇 2-4 处即可，禁止堆砌（满屏黑话反而更假、更 AI 味）。

### 5. 平台适配

- **发布配文按平台语气微调**：公众号偏正式、小红书偏种草、抖音偏口语，但均保持「单句钩子 + 互动提问」结构。
- **封面提示词按平台画幅适配**：公众号横版、小红书竖版 3:4、抖音竖版 9:16，在提示词中注明画幅。
- **标签**：小红书文案附 3-5 个标签；抖音脚本附 2-3 个话题标签。
- **正文配图建议**：
  - 公众号长文：按章节配图，建议 3-5 张（数据图表 / 案例截图 / 场景图），每张附一句图注。
  - 小红书文案：建议 3-6 张配图（首图信息密度最高，放核心结论或数据卡），附图片顺序说明。
  - 抖音脚本：在脚本中标注镜头 / 画面提示（数据卡、图表、实拍、字幕），与口播对应。

### 6. 素材数据引用规范

- 素材中引用 S / A 级数据时，必须标注来源：公众号长文带来源脚注、小红书带「据 XX」、抖音脚本口播带来源提示、发布配文不引数据。
- 论据一律来自已确认的信号报告，禁止引入报告外的新数据。

### 7. 素材受众与篇幅规范（默认值，用户可覆盖）

| 素材 | 目标受众 | 篇幅要求 |
|------|---------|---------|
| 公众号长文 | 泛职场 / 行业从业者 | 2000-3000 字 |
| 公众号发布配文 | 公众号粉丝 | 1 句钩子 + 1 句互动提问，20-40 字 |
| 公众号封面提示词 | 生图工具 / 设计师 | 纯视觉描述，50-100 字 |
| 小红书文案 | 年轻求知群体 | 正文 300-600 字 + 3-5 个标签 |
| 小红书发布配文 | 小红书粉丝 | 1 句钩子 + 1 句互动提问，20-40 字 |
| 小红书封面提示词 | 生图工具 / 设计师 | 纯视觉描述，50-100 字 |
| 抖音脚本 | 泛娱乐 / 大众 | 60 秒内口播，约 200-260 字 + 2-3 个话题标签 |
| 抖音发布配文 | 抖音粉丝 | 1 句钩子 + 1 句互动提问，20-40 字 |
| 抖音封面提示词 | 生图工具 / 设计师 | 纯视觉描述，50-100 字 |

### 8. 可用率目标与自查清单

- **可用率目标**：素材产出后用户可直接使用的内容占比 ≥ 80%（结构、数据、表达可直接采用，无需大改）；需大改的素材视为不合格，须重出。
- **落盘前逐项自查**：
  1. 各素材切面是否重叠（是否互相改写、复用段落）。
  2. 论据是否全部来自已确认的信号报告。
  3. 引用数据是否带来源标注。
  4. 是否满足对应素材的受众与篇幅规范。
  5. 是否含空洞形容词 / 模板化开头 / 排比堆砌 / AI 总结腔。
  6. 核心论点是否都有具体锚点（企业 / 数字 / 案例 / 时间）。
  7. 是否达到可用率目标（≥ 80% 可直接使用）。

### 9. 先展示确认，再落盘

- 素材产出后**先展示给用户确认**（可要求调整），确认定稿后再写入磁盘，避免反复改文件。
- 展示方式：长文类（公众号长文）在对话中展示摘要 + 关键段落，确认后再落盘全文；短素材（发布配文 / 封面提示词 / 标签）直接展示全文。

### 10. 落盘规范

- 在**结果产物目录（output）**下按 `<行业名>/<日期>/` 建子目录（日期格式 `YYYY-MM-DD`）。
