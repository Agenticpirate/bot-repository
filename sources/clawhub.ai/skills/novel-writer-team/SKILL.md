# 写小说 — 多Agent协作创作系统

## 为什么需要这个系统

写小说不是坐下来就开始码字。专业的创作流程需要：先确定"写给谁看"（平台和读者），再设计"讲什么故事"（创意和冲突），然后构建"故事发生在哪里"（世界观），接着创造"谁来演"（角色），规划"怎么讲"（大纲和风格），最后才是"写出来"（正文）。跳过任何一步都会导致后面返工——没有大纲的长篇必然崩盘，没有风格规范的写作必然前后不一致。

这个系统用8个专业角色模拟一个完整的创作团队，确保每一步都扎实。

## 工作流程

### 第1步：理解用户意图

用户可能提供完整信息，也可能只有一个模糊想法。收集以下信息（已有则跳过，不要反复追问）：

1. **灵感**：想写什么？一句话、一个画面、一个概念都行
2. **目标平台**：发在哪里？如果不确定，根据内容类型推荐
3. **篇幅预期**：短篇/中篇/长篇？
4. **偏好**（可选）：想借鉴的作品？特别想要的元素？

**示例对话：**

```
用户：我想写一个都市重生文，发番茄
→ 信息充足，直接进入第2步

用户：我想写个小说
→ 追问：想写什么类型？发在哪个平台？

用户：我有个点子，一个人突然能听到别人的心声
→ 推断类型为都市/异能，推荐番茄或起点，确认后进入第2步
```

### 第2步：创意孵化（串行）

按顺序执行，每一步的输出是下一步的输入。

**2.1 赵构思（创意总监）— 从灵感中提炼故事核心**

读取 `references/agents.md` 中赵构思的详细定义，以及 `references/platforms.md` 中目标平台的规则。

输出故事梗概，包含：
- 故事名称、类型、目标平台、目标读者、预估篇幅
- 一句话概括（50字以内）
- 故事梗概（500字以内）
- 核心卖点（2-3个）
- 主题内核（一句话）
- 核心冲突（外部冲突 + 内部冲突）

**2.2 张世界（世界观架构师）— 构建故事发生的世界**

读取 `references/agents.md` 中张世界的详细定义。

输出世界观设定，包含：
- 时代背景（时代、年份、技术水平、社会形态）
- 地理环境（主要场景、地理特征）
- 社会结构（政治、阶级、经济、文化）
- 特殊体系（力量/魔法/科技体系，如需要）
- 势力分布
- 历史大事件
- 日常生活细节

设计原则：每个设定都要服务于故事核心冲突，没有用的设定是噪音。

**2.3 王角色（角色设计师）— 创造鲜活的角色**

读取 `references/agents.md` 中王角色的详细定义。

为每个核心角色输出角色卡，包含：
- 基本信息（姓名、年龄、身份）
- 外貌特征（至少一个记忆点）
- 性格画像（核心性格、优点、缺陷、口头禅）
- 动机与目标（表面目标、深层动机、最大恐惧）
- 成长弧光（起点→转折→终点）
- 人物关系
- 背景故事（3-5句话）
- 在故事中的功能

设计原则：好的角色不是完美的人，是真实的人。读者追的是角色命运。

**分步模式**：完成后暂停，展示梗概+世界观+角色，请用户确认。

### 第3步：结构+风格规划（并行 → 审核）

李大纲和刘风格可以同时工作，因为大纲管"写什么"，风格管"怎么写"，互不依赖。

**3.1 李大纲（结构编排师）— 规划全书骨架**

读取 `references/agents.md` 中李大纲的详细定义。

输出全书大纲，包含：
- 故事主线概括（3-5句话）
- 结构划分（每幕的章节规划，每章标注标题、内容、冲突、伏笔）
- 伏笔地图（埋设章节→回收章节）
- 节奏曲线
- 情感线规划

常用结构：
- 三幕结构（最通用）：开端25% → 发展50% → 高潮结局25%
- 英雄之旅（冒险/成长类）：12个阶段
- 起承转合（短篇/中篇）

**3.2 刘风格（风格打磨师）— 制定文风规范**

读取 `references/agents.md` 中刘风格的详细定义，以及 `references/platforms.md` 中目标平台的详细规则。

输出文风规范手册，包含：
- 叙事视角（第一人称/第三人称限知/全知/多视角）
- 章节规范（字数、结构、章末要求）
- 句式节奏（句子长度、段落长度）
- 对话风格（占比、特征、标签、禁忌）
- 描写密度（动作、环境、心理、感官）
- 语言风格（基调、用词、修辞、禁忌词汇）
- 爽点/情感点设计
- 参考风格（2-3部参考作品，说明借鉴方面）
- 禁忌清单

**3.3 陈总管（项目总管）— 审核**

审核大纲的完整性和文风规范与平台的匹配度。通过后进入正文写作。

**分步模式**：完成后暂停，展示大纲+文风规范，请用户确认。

### 第4步：正文创作（逐章循环）

这是最核心的生产环节。对每一章执行写稿→审稿循环。

**4.1 吴正文（正文写手）— 撰写章节**

读取 `references/agents.md` 中吴正文的详细定义。`references/workflows.md` 中单章写作循环的详细说明。

写作前准备：当前章节大纲、文风规范、相关角色档案、世界观设定、前1-3章正文（保持连贯）。

输出章节正文，包含：
- 章节信息（编号、标题、字数、所属阶段）
- 章节摘要（2-3句话）
- 本章任务（情节推进、人物发展、伏笔操作、情绪基调）
- 正文
- 章末钩子
- 与上下章的衔接

写作原则：展示而非讲述（不说"他很愤怒"，写"他攥紧了拳头"）。对话即性格。冲突即情节。钩子即留存。

**4.2 周编辑（资深编辑）— 审核章节**

读取 `references/agents.md` 中周编辑的详细定义。

按7个维度审查：
1. 情节逻辑：事件是否合理，因果关系是否成立
2. 人物一致性：角色言行是否符合设定
3. 节奏把控：是否符合平台要求
4. 伏笔操作：埋设/回收是否正确
5. 平台适配度：字数、开头、钩子、风格是否达标
6. 章末钩子：是否到位
7. 文字质量：错别字、语病、表达

输出审稿报告：通过/打回 + 具体修改意见。

**4.3 循环逻辑**

当周编辑审稿完成后，根据审稿结果执行以下流程：

**✅ 通过**
- 将章节存入 `chapters/` 目录
- 进入下一章

**❌ 打回**
1. 吴正文读取周编辑的审稿报告（`reviews/review-XX.md`），重点关注修改清单中的每一条问题和建议
2. 吴正文根据修改清单逐条修改章节正文，不能遗漏任何一条高优先级问题
3. 修改完成后，将修改稿重新提交给周编辑
4. 周编辑再审时，重点检查上次提出的问题是否已解决，同时检查修改是否引入了新问题
5. 如果通过，存入 `chapters/` 并进入下一章；如果仍有问题，再次打回

**循环上限**：最多3轮。第3轮仍不通过，陈总管介入评估：标记问题章节，决定是继续修改还是跳过进入下一章。

**分步模式**：每完成5章暂停一次，展示进度，请用户确认继续。

### 第5步：全书统稿（串行）

**5.1 刘风格 — 全书风格统一**
通读全书，统一句式、对话、描写风格。全书不能前半本口语化后半本文艺化。

**5.2 周编辑 — 终审**
通读全书，检查前后一致性、伏笔是否全部回收、人物弧光是否完成。

**5.3 陈总管 — 最终交付**
整理所有章节，生成完整小说文档。

## 输出结构

每本小说创建独立项目目录：

```
projects/[小说名]/
├── meta.md              # 项目元信息和进度
├── story-brief.md       # 故事梗概（赵构思）
├── world-setting.md     # 世界观设定（张世界）
├── characters/          # 角色档案（王角色）
│   ├── 主角A.md
│   └── ...
├── outline.md           # 全书大纲（李大纲）
├── style-guide.md       # 文风规范（刘风格）
├── chapters/            # 各章正文（吴正文）
│   ├── chapter-01.md
│   └── ...
├── reviews/             # 审稿记录（周编辑）
└── final/               # 最终成品
    └── complete-novel.md
```

## 参考资源

按需读取，不要一次性全部加载：

- **`references/agents.md`** — 8个Agent的详细角色定义、设计原则、输出要素。在执行对应角色时读取。
- **`references/platforms.md`** — 5大平台的适配规则（读者画像、章节字数、节奏、文笔、开头策略、对话风格、描写密度、禁忌）。在确定目标平台和制定文风规范时读取。
- **`references/workflows.md`** — 完整工作流和单章写作循环的详细说明。在需要了解流程细节时读取。
- **`references/templates.md`** — 所有输出模板。在生成对应输出时读取。
- **`references/example-project.md`** — 示例项目参考。在需要了解输出格式时读取。
