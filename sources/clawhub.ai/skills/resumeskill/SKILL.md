# Job Prep Kit — 求职准备套件

## Overview

本 Skill 面向实习、校招和社招求职场景，把「投前准备」拆成三段可执行链路：

1. **调研岗位** —— 用搜索工具把目标公司/岗位的面经、隐性门槛、业务动态、JD 真实诉求挖清楚。
2. **改写简历** —— 基于调研结论，把候选人真实经历翻译成岗位听得懂的语言，输出统一排版的 `.docx`。
3. **准备面试** —— 基于改写后的简历反推面试考点，逐条拆雷，并给出自我介绍与逐题话术。

全程只基于用户提供的真实经历进行改写，不编造经历、不捏造数据。两个关键确认点分别放在「简历改写前」和「面试话术前」，用户确认后再继续。

## 输入要求

触发本 Skill 的典型用户表述：

- "这是我的简历，我想申请 [公司] 的 [岗位]，JD 如下，帮我准备。"
- "帮我按这个 JD 改简历，再准备一下面试。"
- "我要投 [公司] [岗位]，简历在这，帮我全套准备。"
- "按我简历准备面试，目标岗位是 [岗位]。"

用户需提供：

1. **当前简历**（PDF / Word / 直接粘贴文本均可）
2. **目标公司名称**
3. **目标岗位名称**
4. **岗位 JD**（职位描述，越完整越好）
5. **可选补充**：个人偏好（想突出的方向、必须避开的表述、排版偏好等）

如果简历已经投出去改不了，用户可直接说「按我简历准备面试」，跳过第 2 步。

## Workflow

### Step 0 — 任务确认

收到用户请求后，先确认以下信息是否齐全：

- [ ] 简历内容已收到或可读取
- [ ] 目标公司已明确
- [ ] 目标岗位已明确
- [ ] JD 已收到

缺失信息时，用清单式追问，不要一次性问太多。确认完毕后告知用户将分三步走，并说明两个确认点位置。

### Step 1 — 调研岗位

目标：生成一份 `岗位调研.md`，为后续简历改写和面试准备提供岗位语境。

#### 1.1 读取岗位 JD

从 JD 中提取并整理：

- 岗位基本信息（职位名称、部门/业务线、工作地点、经验要求）
- 核心能力要求（按重要性排序）
- 硬性门槛（学历、年限、技术栈、语言等）
- 加分项 / 优先条件
- 软性要求（团队协作、沟通风格、抗压能力、出差等）

#### 1.2 搜索公司与岗位情报

使用 WebSearch 搜索以下方向：

- `[公司名] [岗位名] 面试经验 / 面经`
- `[公司名] [业务线] 2025 2026 最新动态 / 战略`
- `[岗位名] 面试风格 / 考察重点`
- `[公司名] 校招 / 实习 / 社招 流程`

搜索后整理：

- 面试风格（重项目深挖？重八股？重业务思考？重行为面？）
- 常考考点 / 高频问题
- 隐性门槛（学历偏好、项目类型、技能深度等）
- 业务背景（该部门最近在做什么、战略方向、产品形态）

#### 1.3 输出岗位调研.md

文件路径：`outputs/岗位调研.md`

结构模板：

```markdown

- 职位名称：

|---|---|---|---|

- 硬性门槛：
- 隐性门槛：

- 整体风格：
```

### Checkpoint 1 — 简历改写前确认

向用户展示 `岗位调研.md` 的核心结论（能力要求、面试风格、对简历改写的启示），并询问：

> "调研结论如上。我准备按这个方向改写简历，重点强化 XX、弱化 YY。是否继续？"

用户确认或调整方向后，再进入 Step 2。

### Step 2 — 改写简历

目标：基于调研结论，把真实经历翻译成岗位语言，输出 `改后简历.docx`。

#### 2.1 读取简历内容

提取简历中的所有经历：

- 教育背景
- 实习/工作经历
- 项目经历
- 校园/组织经历
- 技能与证书
- 其他亮点

对每条经历标注：

- 经历类型
- 时间跨度
- 当前表述质量（A/B/C）
- 与 JD 能力的对应关系

#### 2.2 经历改写策略

参考 `references/resume-playbook.md`，按以下原则改写：

- **目标定位优先**：简历的每个模块都服务于岗位核心能力。
- **能力迁移翻译**：把"学生工作"、"课程项目"、"社团活动"翻译成岗位所需能力。
- **STAR 法则**：情境 → 任务 → 行动 → 结果。
- **量化优先**：能补数据的地方尽量引导用户补充，但不捏造。
- **不编造经历**：只基于用户提供的原始经历改写。

对每个可改写的模块，按以下格式输出内部草稿：

```
【原表述】
...

【改写后】
...

【改写要点】
- 强化了...
- 弱化了...
- 需注意：...
```

#### 2.3 生成改后简历.docx

将改写后的内容交给 `scripts/generate_resume.py` 渲染为 Word 文档。

输出路径：`outputs/改后简历.docx`

脚本要求：

- 使用统一的中文简历模板
- 模块顺序：个人信息 → 教育背景 → 实习/工作经历 → 项目经历 → 校园/组织经历 → 技能与证书
- 排版专业、间距统一、一页优先（经历多时可两页）
- 字体：中文用微软雅黑或宋体，英文用 Calibri/Times New Roman

如果脚本执行失败或环境缺少依赖，回退到直接输出 Markdown 格式简历文本，并告知用户可手动粘贴到 Word。

### Checkpoint 2 — 面试准备前确认

向用户展示 `改后简历.docx` 的核心改动（或 Markdown 文本），并询问：

> "这是改后的简历版本，重点变化是... 如果你确认定稿，我就基于它准备面试；需要修改请直接指出。"

用户确认后，再进入 Step 3。

### Step 3 — 准备面试

目标：基于改后简历反推考点，生成 `面试准备.md`。

#### 3.1 反推考点

逐条审视改后简历中的每段经历，列出面试官可能追问的问题：

- **项目深挖**：为什么做这个项目？核心难点？你具体负责什么？指标怎么选的？结果怎么验证的？
- **能力验证**：这段经历如何体现 JD 要求的 XX 能力？
- **数据真实性**：这个数字怎么来的？如果重新做会怎么优化？
- **行为面延伸**：团队协作冲突、时间管理、压力场景、失败经历等。

#### 3.2 自我介绍

基于改后���历，撰写 1 分钟和 3 分钟两个版本的自我介绍：

- 1 分钟版：简洁有力，适合群面/初面
- 3 分钟版：完整，适合单面/主管面

结构建议：

```
开场（姓名 + 学校/背景 + 应聘岗位）
↓
核心优势（2-3 个与岗位最匹配的能力标签）
↓
经历证据（1-2 个最有代表性的项目/实习，STAR 简要版）
↓
结尾（为什么选这个公司/岗位 + 期待）
```

#### 3.3 逐题话术

对每个考点，按以下格式准备：

```markdown
### 问题：...

**考点**：...

**回答框架**：
1. ...
2. ...
3. ...

**推荐话术**：
...

**避坑提示**：
- ...
```

重点关注简历中"翻译后"容易被追问的地方：

- 能力迁移表述（如"把课程项目包装成产品能力"）
- 量化数字的来源
- 跨专业/转行动机
- 经历之间的逻辑一致性

#### 3.4 风险地图

输出一份简历风险清单：

```markdown
| 风险点 | 可能的问题 | 应对策略 | 严重度 |
|---|---|---|---|
```

#### 3.5 输出面试准备.md

文件路径：`outputs/面试准备.md`

结构模板：

```markdown

## 一、岗位面试画像
（从岗位调研.md 提炼：风格、高频考点、隐性门槛）

## 二、自我介绍
### 1 分钟版
...
### 3 分钟版
...

## 三、逐题话术
### 项目深挖
...
### 能力验证
...
### 行为面
...

## 四、简历风险地图
| 风险点 | 可能问题 | 应对策略 | 严重度 |

## 五、考前必读清单
- [ ] 公司最新动态
- [ ] 岗位核心能力词
- [ ] 自我介绍熟练度
- [ ] 风险点应对
```

## 输出物汇总

一次完整运行会产出：

| 文件 | 内容 | 说明 |
|---|---|---|
| `outputs/岗位调研.md` | 岗位情报与 JD 拆解 | Step 1 输出 |
| `outputs/改后简历.docx` | 排版好的改后简历 | Step 2 输出 |
| `outputs/面试准备.md` | 自我介绍 + 逐题话术 + 风险地图 | Step 3 输出 |

## 快速跳过逻辑

用户可能处于以下特殊情况，需灵活处理：

| 用户表述 | 处理 |
|---|---|
| "简历已经投了，按我简历准备面试" | 跳过 Step 2，直接进入 Step 3 |
| "只帮我改简历，不准备面试" | 只执行 Step 1 + Step 2 |
| "只帮我调研岗位" | 只执行 Step 1 |
| "我改好了简历，直接准备面试" | 跳过 Step 1-2，基于用户提供的改后简历进入 Step 3 |
