# 验收报告生成

> 输出为专业验收报告，供主理人存档和决策参考。

## 能力概述

将测试用例生成器、功能验收执行、性能安全评估三个Skill的输出汇总为**一份完整的7章验收报告**，输出最终验收结论。

## 输入数据

从以下来源汇总数据：
- **测试用例生成器** → 测试用例集（含覆盖维度、用例清单）
- **功能验收执行** → 逐项验收结果（通过/有条件通过/不通过）
- **性能安全评估** → 性能指标 + 安全风险清单
- **架构方案**（系统架构师输出）→ 背景参考

## 报告结构

### 第1章：测试概述
| 字段 | 内容 |
|------|------|
| 测试范围 | 哪些模块、哪些功能被测试 |
| 测试环境 | 硬件/软件/网络环境描述 |
| 测试时间 | 测试起止时间 |
| 测试版本 | 被测系统的版本号 |
| 测试方法 | 功能/性能/安全/兼容性各维度的测试方法 |
| 参与人员 | 测试执行者 |

### 第2章：测试结果汇总

| 统计项 | 数值 |
|-------|------|
| 总用例数 | N |
| ✅ 通过 | N / X% |
| ⚠️ 有条件通过 | N / X% |
| ❌ 不通过 | N / X% |
| 阻塞数(无法测试) | N |
| 通过率 | X% |

### 第3章：模块级详情

| 模块 | 用例数 | ✅通过 | ⚠️有条件 | ❌不通过 | 通过率 | 主要问题 |
|------|-------|-------|---------|---------|-------|---------|
| 模块A | 20 | 18 | 1 | 1 | 90% | ... |
| 合计 | ... | ... | ... | ... | ... | ... |

### 第4章：缺陷清单

| 缺陷ID | 模块 | 缺陷描述 | 等级 | 状态 | 关联用例 |
|--------|------|---------|------|------|---------|
| BUG-01 | 模块A | ... | P0 | 未修复 | TC-... |

### 第5章：性能评估结论

| 指标 | 实际值 | 目标值 | 评级 |
|------|-------|-------|------|
| 响应时间(P95) | ... | ... | 优秀/良好/需优化/不合格 |
| 最大并发 | ... | ... | 优秀/良好/需优化/不合格 |

### 第6章：安全评估结论

| 风险ID | 风险描述 | 等级 | 建议 |
|--------|---------|------|------|
| SEC-01 | ... | 高危/中危/低危 | 修复建议 |

### 第7章：验收结论

| 维度 | 结论 |
|------|------|
| 功能验收 | ✅ / ⚠️ / ❌ |
| 性能评估 | 优秀 / 良好 / 需优化 / 不合格 |
| 安全评估 | 安全 / 低风险 / 中风险 / 高风险 |
| **最终验收** | ✅ **通过** / ⚠️ **有条件通过** / ❌ **不通过** |

## 验收结论标准

| 结论 | 条件 |
|------|------|
| ✅ **通过** | P0全部通过，P1通过率≥90%，无高危安全风险 |
| ⚠️ **有条件通过** | P0全部通过，P1通过率≥70%，附带修复计划和时间表 |
| ❌ **不通过** | 存在P0缺陷或P1通过率<70%或存在高危安全风险 |

## 工作流程

1. **数据汇总**：收集三个测试Skill的输出结果
2. **结构填充**：按7章模板填充各章节
3. **数据校验**：检查数据一致性（用例数、通过率等）
4. **结论判定**：根据验收标准自动判定最终结论
5. **报告输出**：生成完整的结构化验收报告

## 输出格式

支持输出为：
- **Markdown文档**（默认，适合存档和展示）
- **结构化数据**（适合后续处理）
