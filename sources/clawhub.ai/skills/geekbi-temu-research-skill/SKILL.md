# 极鲸云Temu数据分析与市场调研

## 总体原则

- 将本 Skill 作为唯一入口。商品、图搜同款、店铺、类目、关键词和评论搜索是内部能力模块，不要求用户分别安装或指定技术名称。
- 只使用极鲸云返回的真实数据，明确区分接口事实、可复算指标和分析判断。
- 默认使用简体中文和绝对日期；保留站点、时间范围、筛选条件、分页范围、样本量和数据更新时间。
- 对缺失值、异常值、估算值和未完成分页作显式说明。数值为 `0` 时先判断是否可能未统计，不自动解释为真实为零。
- 面向用户只使用中文业务名称，不展示英文参数、响应字段、请求命令或原始 JSON。只有用户明确要求开发对接、故障排查或原始响应时，才展示必要技术信息并解释中文含义。
- 内部完成文档加载、能力路由、参数生成和脚本调用，不向用户汇报这些内部步骤；进度说明只描述正在解决的业务问题。
- 图搜同款与商品搜索使用完全相同的商品响应结构和完整字段。
- 商品、店铺、关键词和类目的详情链接是强制交付内容，不需要用户主动要求。只要结果对象返回非空 `linkUrl`，最终答复中每次展示该对象时，都必须把主要名称写成可点击的 Markdown 链接；简洁回答、表格、排行榜、候选清单和组合调研均不得省略。
- 服务端要求暂停查询时，按 [查询暂停与恢复流程](references/查询暂停与恢复流程.md) 处理：展示一级 `msg`，有 `jumpUrl` 时再展示可点击链接，不输出原始状态；恢复条件满足后原样重跑查询。普通查询错误没有有效 `msg` 时，才使用脚本生成的中文错误。

## 执行流程

1. 明确用户的决策问题、目标站点、市场边界、时间口径和硬性条件。不会显著影响结果时采用合理默认值并说明。
2. 按“能力路由”只加载完成当前任务所需的文档。
3. 所有能力共用站点列表返回的站点 ID。未指定站点或指定美国站时直接使用美国站默认值 `48`；只有用户指定其他国家或地区时，才运行 `scripts/temu_site_list.py` 实时解析站点 ID。无唯一匹配时请用户确认，不猜测站点。评论搜索可以省略站点参数并使用默认美国站，只有用户明确限定其他站点时才实时解析。
4. 生成最小必要查询条件并运行对应脚本：商品使用 `scripts/temu_goods_search.py`，图搜同款使用 `scripts/temu_image_search.py`，店铺使用 `scripts/temu_shop_search.py`，类目使用 `scripts/temu_category_search.py`，关键词使用 `scripts/temu_keyword_search.py`，评论使用 `scripts/temu_review_search.py`。
5. 所有业务脚本统一复用公共请求封装。服务端因未登录、额度不足、请求受限、需要充值、开通或升级等原因要求暂停时，按 [查询暂停与恢复流程](references/查询暂停与恢复流程.md) 处理；恢复条件满足后原样重跑查询。
6. 检查响应、分页、缺失字段、异常值、时间口径和可比性。未完成全量分页时明确标为样本。
   图搜同款任务中，用户要求全部结果或完整市场分析时，必须根据命中总数以单页 200 条继续翻页直至覆盖全部命中，不能把第一页条数当成同款总量。
7. 完成主查询后判断是否需要交叉验证。简单搜索直接回答，不强制扩展为完整报告。
8. 输出结论、数据口径、关键证据、机会与风险、下一步验证动作。发送最终答复前执行链接完整性检查，修复所有应当链接但仍为纯文本的名称。

## 组合调研链路

根据问题裁剪链路，不机械执行全部步骤：

```text
类目搜索：确定市场边界、类目 ID、规模与供需
    ↓
关键词搜索：验证具体需求、增长和搜索竞争
    ↓
商品搜索：寻找候选商品，核验价格、销量、同款竞争和上架时间
    ↓
评论搜索：核验用户卖点、痛点、规格风险和产品改良方向
    ↓
店铺搜索：核验竞品集中度、经营模式和头部卖家表现
```

- 用户提供图片或要求以图找同款时，先用图搜同款形成视觉候选商品池，再根据问题使用销量、价格、同款数、上架时间等商品条件筛选；不要先把图片主观描述成关键词替代图搜。
- 用户只查某个商品、店铺、类目、关键词或商品评论时，只调用对应主能力。
- 用户要求完整选品或市场机会分析时，优先按“类目 → 关键词 → 商品 → 评论 → 店铺”逐步缩小范围；只有已经取得明确商品 ID 且评论分析能影响决策时才增加评论搜索。
- 用户从明确关键词出发时，可以从关键词搜索开始，再进入商品验证；取得明确商品 ID 后，按问题需要追加评论或店铺验证。
- 用户从竞品店铺出发时，可以先查店铺，再用商品搜索分析其商品结构。
- 多能力对比必须统一站点、币种、时间窗和筛选边界；口径不同则停止直接排名。

## 共享业务口径

- 商品、图搜同款、店铺、类目、关键词和评论共用同一套 Temu 站点体系；商品、图搜同款、店铺、类目和关键词共用类目 ID。类目 ID 优先使用一级或二级，不根据名称猜测。
- 关键词和类目一般选择一个作为主筛选条件；只有用户明确要求交叉限定时才组合，并说明结果可能减少。
- 商品价格、平均价格和销售额使用当前 Temu 站点币种；供货价使用人民币。计算价差或利润前先统一币种并说明汇率口径。
- 商品库存为 `0` 时标注“可能未统计到，需进一步核实”，不直接认定为缺货或售罄。
- 同款数越高表示同行销售相同商品越多、核价通过概率通常越低。一般不超过 10 较优，超过 20 表示竞争增多，更高时除非具备工厂或供应链优势，否则竞争压力较大。
- 蓝海指数只作为供需综合信号，与需求规模、近期增长、商品数和店铺数交叉验证，不单独作为进入依据。

## 输出要求

### 名称链接硬性规则

1. 取得商品、店铺、关键词或类目数据后，先提取主要名称和服务端原样返回的 `linkUrl`，再组织表格、列表或分析文字。
2. 对每个非空 `linkUrl`，必须将对应名称写成可点击的 Markdown 链接：商品使用 `[商品标题](<linkUrl>)`，店铺使用 `[店铺名称](<linkUrl>)`，关键词使用 `[关键词](<linkUrl>)`，类目使用 `[类目名称或完整类目路径](<linkUrl>)`。
3. 同一对象在表格、列表、排名、候选清单或正文中再次出现时，名称仍然必须可点击；不能只在首次出现时添加链接。
4. 不单独设置裸链接列，不使用纯文本 URL，不用“查看详情”替代主要名称。不得修改、推断或重新拼接服务端返回的 `linkUrl`。
5. 发送最终答复前逐个结果块检查：非空 `linkUrl` 的对象数必须等于可点击名称数。数量不一致时先补齐链接再回答。仅处理服务端提供的非空链接，其他链接状态保持静默，不向用户说明接口、字段、缺失状态或链接来源。
6. 用户单独索要商品、店铺、关键词或类目链接时，直接返回对应的可点击名称，不附加数据表、接口说明、字段说明、链接类型说明或缺失情况说明。极鲸云详情链接就是本 Skill 默认交付的链接。

名称链接完整性是交付前置条件，不是可选的排版优化。

默认按以下顺序输出：

1. 一句话结论。
2. 数据口径：站点、时间、市场边界、条件、分页范围、样本量和更新时间。
3. 关键发现：只展示与决策直接相关的中文指标。
4. 机会与风险：区分事实、计算和判断，说明数据限制与置信度。
5. 行动建议：给出优先级、验证动作和进入门槛。

用户只要列表或简单查询结果时保持简洁，不强行生成完整市场报告。
