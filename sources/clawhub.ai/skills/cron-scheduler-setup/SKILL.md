## 操作步骤
### 1. 创建一次性提醒（主会话）

```bash
skill-platform cron add \
  --name "提醒事项" \
  --at "20m" \
  --session main \
  --system-event "20 分钟后检查日历" \
  --wake now \
  --delete-after-run
```

### 2. 创建周期性任务（独立会话）

```bash
skill-platform cron add \
  --name "晨间简报" \
  --cron "0 7 * * *" \
  --tz "Asia/Shanghai" \
  --session isolated \
  --message "总结昨晚的邮件和日历事件" \
  --announce \
  --channel telegram \
  --to "+8613800138000"
```

### 3. 创建带模型覆盖的深度任务

```bash
skill-platform cron add \
  --name "周报分析" \
  --cron "0 9 * * 1" \
  --tz "Asia/Shanghai" \
  --session isolated \
  --message "分析本周项目进展" \
  --model "opus" \
  --thinking high \
  --announce \
  --channel whatsapp \
  --to "+8613800138000"
```

## 常见问题FAQ

### Q1: 如何设置任务的执行时间？
A: 使用 Cron 表达式指定任务执行的时间，例如 `"0 7 * * *"` 表示每天早上7点执行。

### Q2: 如果任务执行失败，应该如何处理？
A: 检查任务定义是否正确，确认cron服务运行正常，并查看执行日志以确定失败原因。

### Q3: 可以将任务结果发送到特定的聊天频道吗？
A: 可以，通过配置 `--channel` 参数，可以将任务结果发送到指定的聊天频道。

### Q4: 如何查看任务的执行日志？
A: 任务执行日志存储在 `$HOME/.jsonl` 文件中。

### Q5: 定时任务是否会占用大量系统资源？
A: 不会，定时任务设计为轻量级，不会占用大量系统资源。

## 异常处置
针对定时调度器设置使用中可能遇到的常见问题,提供以下排查方案:

| 错误类型 | 原因分析 | 解决方案 |
|---------|---------|---------|
| API认证失败(401) | API密钥错误或过期 | 检查密钥配置,重新生成token |
| 接口限流(429) | 请求频率超出限制 | 降低调用频率,启用重试退避策略 |
| 响应超时(504) | 网络延迟或服务端负载过高 | 增加超时阈值,检查网络连接 |
| 文件不存在 | 路径错误或文件未创建 | 检查路径拼写,确认文件已生成 |
| 文件格式不支持 | 扩展名不在支持列表中 | 转换为支持的格式后重试 |
| 权限不足 | 当前用户无读写权限 | 检查文件权限,以管理员身份运行 |
| 命令执行失败 | 参数错误或环境依赖缺失 | 检查命令语法,确认依赖已安装 |
| 进程超时 | 命令执行时间过长 | 增加超时设置,优化命令参数 |
| 网络连接失败 | DNS解析失败或防火墙拦截 | 检查网络配置,确认代理设置 |

### 定时调度器设置通用排查步骤

1. **检查输入参数**: 确认所有必填参数已提供且格式正确
2. **查看日志输出**: 定位具体错误行和异常类型
3. **验证环境配置**: 确认依赖库版本和运行环境满足要求
4. **逐步调试**: 缩小问题范围,隔离故障模块

### 错误处理机制
本技能内置完整的错误处理(error handling)流程，确保任务执行过程中的异常情况得到妥善处理。

### 边界条件处理
- **空输入**: 当输入参数为空时，返回提示信息要求用户补充必要参数
- **超长输入**: 对超出长度限制的输入进行截断处理
- **边界值**: 对极端参数值进行范围校验

### 降级策略
- 当外部依赖不可用时，使用默认值降级处理，保证基本功能可用
- 网络请求失败时自动重试(retry)，采用指数退避(backoff)策略
- 断线时自动重连(reconnect)，最多重试3次
