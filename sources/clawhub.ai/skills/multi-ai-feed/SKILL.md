# 多平台AI信息源

## 📝 简介

一次调用即可扫描快手、公众号、B站、视频号、小红书五大平台的 AI 相关内容，按各平台主指标筛选爆款，智能聚类话题后生成一份统一的多平台 HTML 日报，并同步对每平台 TOP 话题执行多引擎 AI 情报调查。

> **重要**：快手/B站数据每日 15:00 更新前一天内容，公众号/视频号/小红书每日 16:00 更新。目标日期无数据时**禁止自动调用接口**，必须先告知用户并等待确认。

## 🌐 平台矩阵

| 平台 | 标识 | 排序主指标 | 展示指标 | 数据更新 | 单位 | 时间过滤 |
|------|------|-----------|---------|---------|------|---------|
| 快手 | `kuaishou` / `ks` | 互动量（赞+分享+评论） | 点赞 / 分享 / 评论 | 每日 15:00 | 条 | 支持 |
| 公众号 | `gzh` / `wechat` | 互动量（赞+分享+评论） | 点赞 / 分享 / 评论 | 每日 16:00 | 篇 | **不支持** |
| B站 | `bili` / `bilibili` | 点赞量 `likeCount` | 分享 / 点赞 / 评论 | 每日 15:00 | 条 | 支持 |
| 视频号 | `sph` / `channels` | 互动量（赞+分享+评论） | 点赞 / 分享 / 评论 | 每日 16:00 | 篇 | 支持 |
| 小红书 | `xhs` / `xiaohongshu` | 互动量（赞+分享+评论） | 点赞 / 分享 / 评论 | 每日 16:00 | 篇 | 支持 |

平台标识接受中文名、英文全称与缩写，大小写不敏感。`--platform all` 为默认值。

> **公众号特例**：接口不支持时间过滤，返回的是当前收录的最新文章，`--date` 只影响日报标题与可用性预检，不影响返回内容。
>
> **视频号特例**：作品不支持站外跳转，标题渲染为纯文本，无详情链接。

各平台接口契约（endpoint、`source` 值、翻页、时间参数格式、主题色、封面兼容处理）详见 [platforms.md](references/platforms.md)。

## 🔑 鉴权

数据查询接口通过请求头 `X-API-KEY` 鉴权，Key 按四级优先级解析：

1. 命令行 `--api-key`
2. 环境变量 `REDFOX_API_KEY`
3. shell 配置文件（`~/.zshrc`、`~/.bashrc`、`~/.bash_profile`、`~/.profile`）中的 `export REDFOX_API_KEY=`
4. 配置文件 `~/.qoder/apis/redfox.json` 的 `api_key` 字段

**API Key 获取**：前往 [红狐Hub 官网](https://redfox.hk?source=clawhub) 注册，登录后在个人中心获取，格式为 `ak_xxxxxxxx`。新注册用户获赠免费积分。

**配置方式**：
- **macOS/Linux**：将 `export REDFOX_API_KEY=<值>` 追加到 `~/.zshrc` 或 `~/.bashrc`，然后 `source` 使其生效
- **Windows**：`[Environment]::SetEnvironmentVariable("REDFOX_API_KEY", "<值>", "User")`（需重启终端）
- 配置后验证：`echo $REDFOX_API_KEY`（macOS/Linux）或 `echo %REDFOX_API_KEY%`（Windows）

各平台查询接口调用时通过 `source` 字段同步记录，无需额外请求保存接口。

**响应码处理**：`200` / `2000` 成功；`3108` 限频，sleep 5 秒后重试一次；`3106` / `3107` API Key 错误，终止并提示重新配置。

## 🔄 工作流程

### 第零步：日期有效性预检（必须执行，先于任何接口调用）

> ⛔ **核心规则：未经用户确认，禁止调用任何数据接口，禁止自动执行 `--latest`**
>
> **绝对不能**在用户未确认的情况下自动执行脚本获取数据。

**数据更新规则（按平台不同）**：
- 快手、B站：每日 **15:00** 更新前一天数据
- 公众号、视频号、小红书：每日 **16:00** 更新前一天数据

对应各平台的最新可用日期：
- 更新时刻前：最新可用日期 = T-2（前天）
- 更新时刻后：最新可用日期 = T-1（昨天）

**执行流程（每次查询前强制执行）**：

1. 获取当前系统日期 T 和当前时间，按上表逐平台计算最新可用日期
2. 判断用户请求的目标日期是否落在无数据区间（即 > 该平台最新可用日期）
3. **若目标日期对所有请求平台均有数据**：直接执行第一步，无需额外确认
4. **若目标日期对部分或全部平台无数据**，向用户输出以下提示：

```
**⚠️{查询日期}数据尚未更新**
数据更新规则：快手/B站每日15:00更新前一天数据，公众号/视频号/小红书每日16:00更新
当前可查询的最新日期：{最新可查询到数据的日期}

是否需要查询{最新可查询到数据的日期}的数据？
```

5. **等待用户明确确认后**，才能执行第一步（带 `--latest` 参数）
6. 若用户拒绝，则不执行任何接口调用

**脚本层双保险**：`main()` 在解析 API Key 与建立会话**之前**执行可用性预检。全部平台不可用时以退出码 0 结束并输出提示，**接口调用次数为 0，不扣积分**；部分平台不可用时跳过该平台并告警，其余平台正常执行。Agent 在第零步提前拦截，避免脚本层提示被忽略。

**示例对话**：

```
用户：查询今天的全平台AI日报
Agent：⚠️2026-09-02数据尚未更新
      数据更新规则：快手/B站每日15:00更新前一天数据，公众号/视频号/小红书每日16:00更新
      当前可查询的最新日期：2026-08-31

      是否需要查询2026-08-31的数据？
用户：好的
Agent：（执行 python3 "$SKILL_PATH/scripts/multi_ai_feed.py" --platform all --latest）
```

### 第一步：生成多平台爆款日报

```bash
# 全部平台最新一期日报（用户确认后执行，自动跳过无数据日期，不扣积分）
python3 "$SKILL_PATH/scripts/multi_ai_feed.py" --platform all --latest

# 指定多个平台
python3 "$SKILL_PATH/scripts/multi_ai_feed.py" --platform bili,xhs --latest

# 指定单个平台 + 历史日期（历史日期已有数据，无需确认）
python3 "$SKILL_PATH/scripts/multi_ai_feed.py" --platform 快手 --date 2026-08-30

# 全局自定义关键词（所有平台共用）
python3 "$SKILL_PATH/scripts/multi_ai_feed.py" --platform all --keywords "AI绘画,ComfyUI" --latest

# 逐平台覆盖关键词（分号分隔平台，冒号后为该平台关键词）
python3 "$SKILL_PATH/scripts/multi_ai_feed.py" --platform all --latest \
  --platform-keywords "bili:AI,大模型;xhs:AI绘画;ks:AI教程"

# 日期区间
python3 "$SKILL_PATH/scripts/multi_ai_feed.py" --platform all --date 2026-08-25~2026-08-30

# 结构化 JSON 输出（供 Agent 二次加工，日志走 stderr）
python3 "$SKILL_PATH/scripts/multi_ai_feed.py" --platform all --latest --json

# 关闭情报调查 / 不自动打开浏览器
python3 "$SKILL_PATH/scripts/multi_ai_feed.py" --platform all --latest --no-intel --no-open

# 订阅管理（固化当前 --platform 与 --keywords）
python3 "$SKILL_PATH/scripts/multi_ai_feed.py" --platform bili,xhs --keywords "AI绘画" --subscribe
python3 "$SKILL_PATH/scripts/multi_ai_feed.py" --show-subscription
python3 "$SKILL_PATH/scripts/multi_ai_feed.py" --unsubscribe
```

**关键词优先级**：`--platform-keywords` 中的平台级覆盖 > `--keywords` 全局关键词 > 各平台内置默认关键词。内置默认为：快手 `AI,人工智能,大模型,GPT,Agent,AI绘画,AI教程`；公众号 `AI,人工智能,大模型,GPT,Agent,AI绘画`；B站 / 视频号 / 小红书 `AI`。同一平台在 `--platform-keywords` 中只应出现一次，重复出现时后写的覆盖先写的。

**查询策略**：快手与 B站走 `batch` 接口，所有关键词一次性批量提交；公众号 / 视频号 / 小红书走单关键词接口，逐个关键词请求。快手与公众号支持翻页（快手 `pageSize=200` 最多 10 页，公众号 `pageSize=20` 首关键词最多 5 页、其余最多 2 页），达到 `--count` 目标即停。B站 / 视频号 / 小红书单次请求，不翻页。

**聚类算法（六步，全平台共用）**：标签提取 → 大组按第二标签拆分 → 小组合并（`min_group` 按样本量自适应）→ 过大组按标题高频词拆分 → 分类数不足 5 个时继续拆 → 按组内数量降序输出，组内按平台主指标降序，每组最多展示 `--top-n`（默认 5）篇。

### 第二步：执行AI情报调查

日报生成后，**必须**基于每平台聚类结果中的 TOP 话题执行 AI 情报调查（`--no-intel` 可关闭）：

1. 读取各平台聚类结果，每平台选取 TOP 3 热门话题
2. 为每个话题自动匹配调查模式（竞品 / 舆情 / 人物 / 验证）
3. 按三轮搜索策略执行调查（广域扫描 → 深度挖掘 → 交叉验证）
4. 输出结构化调查报告（参照 [investigation-templates.md](references/investigation-templates.md)）

单平台运行时，情报中的「跨平台对比建议」会指向本次一并查询的其它平台；`--platform all` 时指向其余四个平台。

### 第三步：交付产物

- **HTML 日报**：`~/Downloads/QoderReports/AI多平台日报_{平台标识}_{日期}.html`，默认自动打开浏览器。平台标识在查询全部平台时为 `all`，多平台时为各平台缩写用 `+` 连接（如 `bili+xhs`），单平台时即该平台缩写。文件名不含时间戳，同日期重复运行覆盖同一文件，报告内的日期导航因此始终有效。
- **终端输出**：平台数据速览表 + 各平台分类内容表 + 各平台 AI 情报调查指引。

## ⚠️ 可信度标注规范

| 标识 | 含义 | 判定标准 |
|------|------|---------|
| ✅ 已确认 | 信息可靠 | 2+个独立来源一致 |
| ⚠️ 待确认 | 有争议 | 来源说法矛盾 |
| ❌ 已否定 | 信息不实 | 权威信源反驳 |
| 🔍 单一来源 | 仅1个来源 | 需进一步验证 |

**信息源分级**：

| 级别 | 类型 | 示例 |
|------|------|------|
| A级 | 官方/政府/权威媒体 | gov.cn, reuters.com, xinhua.net |
| B级 | 行业媒体/专业平台 | 36kr, techcrunch.com |
| C级 | 社交媒体/自媒体 | weibo, zhihu, reddit |
| D级 | 匿名/未验证来源 | 贴吧, 4chan |

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `--platform` | 平台范围：`all` 或逗号分隔（接受中文名/英文全称/缩写） | `all` |
| `--keywords` | 全局搜索关键词，逗号分隔，所有平台共用 | 各平台内置关键词 |
| `--platform-keywords` | 逐平台覆盖关键词，格式 `"bili:AI,大模型;xhs:AI绘画"` | — |
| `--count` | 单平台目标条数，满足即停 | 各平台推荐值 |
| `--date` | 指定日期 `YYYY-MM-DD`，或区间 `YYYY-MM-DD~YYYY-MM-DD` | 今天 |
| `--start-time` | 自定义开始时间 `YYYY-MM-DD HH:MM:SS`（覆盖 `--date` 推算） | — |
| `--end-time` | 自定义结束时间 `YYYY-MM-DD HH:MM:SS`（覆盖 `--date` 推算） | — |
| `--latest` | 自动使用各平台共同的最新可查日期，跳过无数据区间，不扣积分 | — |
| `--top-n` | 每平台最大分类数 | `5` |
| `--no-intel` | 关闭 AI 情报调查 | 开启 |
| `--output-dir` | 输出目录 | `~/Downloads/QoderReports` |
| `--api-key` | 指定 API Key | 读取环境变量 `REDFOX_API_KEY` |
| `--no-open` | 不自动打开浏览器 | 自动打开 |
| `--json` | stdout 只输出归一化 JSON，进度日志转 stderr | — |
| `--no-color` | 关闭 ANSI 颜色（非 tty 环境自动关闭） | 自动 |
| `--subscribe` | 安装每日定时任务，固化当前 `--platform` / `--keywords` | — |
| `--unsubscribe` | 卸载定时任务 | — |
| `--show-subscription` | 查看当前订阅状态 | — |

**退出码**：`0` 正常（含「目标日期无数据」提示）；`1` API Key 缺失或订阅安装失败；`2` 参数错误（未知平台、关键词格式非法、日期格式非法）。

## 💬 自定义关键词查询场景

除默认 AI 日报外，用户可指定任意关键词组合进行定向查询与分析：

```bash
# 查询 AI 绘画方向（全平台统一关键词）
python3 "$SKILL_PATH/scripts/multi_ai_feed.py" --platform all \
  --keywords "Stable Diffusion,ComfyUI,Midjourney,AI绘画" --latest

# 查询 AI 工具/产品方向（仅 B站 + 小红书）
python3 "$SKILL_PATH/scripts/multi_ai_feed.py" --platform bili,xhs \
  --keywords "AI工具,ChatGPT,Claude,Coze" --latest

# 逐平台差异化查询（B站看技术、公众号看深度长文、小红书看教程）
python3 "$SKILL_PATH/scripts/multi_ai_feed.py" --platform all --latest \
  --platform-keywords "bili:RAG,向量数据库,微调,LoRA;gzh:大模型,AGI;xhs:AI教程,AI绘画"

# 特定技术方向 + 结构化输出供二次分析
python3 "$SKILL_PATH/scripts/multi_ai_feed.py" --platform all \
  --keywords "RAG,向量数据库,微调,LoRA" --latest --json
```

**自定义查询逻辑**：
- 用户提供的关键词按平台能力提交：快手 / B站批量一次查询，公众号 / 视频号 / 小红书逐个关键词查询
- 查询结果自动按 `photoId` 去重，聚类与情报调查报告均基于查询结果生成，与用户关注方向强关联

## 📁 目录结构

| 路径 | 用途 |
|------|------|
| `scripts/multi_ai_feed.py` | CLI 入口与多平台编排 |
| `scripts/feed_core.py` | 平台配置表与全部共享逻辑（鉴权、日期、取数、归一化、聚类、统计、情报、渲染、订阅） |
| `assets/report_template.html` | 统一多平台报告模板 |
| `references/platforms.md` | 五平台接口契约与聚类算法权威说明 |
| `references/engine-strategy.md` | 搜索引擎选择策略与高级搜索方法 |
| `references/investigation-modes.md` | 四种调查模式的搜索策略编排 |
| `references/investigation-templates.md` | 调查报告完整模板集 |
| `references/investigator-config.json` | 引擎与场景配置 |

新增平台只需在 `feed_core.py` 的 `PLATFORMS` 配置表加一项，无需改动其它代码。
