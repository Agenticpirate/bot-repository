你是這個任務的 AI。請為當前工作空間中的 TRPG 規則撰寫一份面向玩家的公開介紹，用於 README 或發布頁面。直接輸出一段完整的文字，可以複製貼上使用。同時將這份介紹文字儲存為 `[規則名稱]_介紹.txt` 檔案，存放在規則目錄中（與玩家規則書同層）。

資料來源：工作空間中 briefing_package 以外的主體規則檔案、劇本檔案、角色卡、以及其他相關正式檔案。從這些檔案中提取世界觀、核心機制、遊戲特色來撰寫。

🚨 不需要閱讀或修改 briefing_package 內的任何檔案。briefing_package 是給 AI GM 程式的內部格式，不是這份介紹的資料來源。

你正在撰寫介紹的 TRPG 規則，最終可能會被分享到 GitHub、itch.io 或 TRPG 社群。

🚨 所有中文必須使用繁體中文。玩家可見的遊戲術語採用「中文全稱（縮寫）」格式。

這份介紹的讀者是「潛在玩家」──他們想知道這套規則在玩什麼、有什麼特色、適不適合自己。這不是技術文檔，不是規格文件，是推廣文案。目標是讓看到的人想說「我想試試這個世界」。

請包含以下內容：

1. （如有）參考作品聲明 ── 如果這套 TRPG 規則的世界觀或核心設定參考了其他作品（動漫、小說、遊戲、電影等），須在介紹中明確標註。根據參考程度區分：
   - 直接轉化：規則是某個作品的 TRPG 改編（例如「《獵人》TRPG 改編」）。開頭明確寫出作品名稱和原作資訊
   - 借鑒啟發：規則借鑒了某個作品的部分元素但並非完整改編（例如「世界觀受到《迷宮飯》的地城生態啟發」）。使用「受到…啟發」「借鑒…元素」等措辭，避免讓人誤以為是官方授權改編
   如果完全原創無任何參考作品，此項可省略

2. 規則名稱 + 一句話定位 ── 這是一個什麼樣的世界？一句話的賣點，讓人在三秒內產生興趣

3. 世界觀簡介 ── 3-5 句話，讓讀者快速理解這個世界的獨特之處。時空背景、核心衝突、有什麼這個世界才有的設定？

4. 玩家扮演什麼角色？核心玩法是什麼？── 一個人在這個世界裡做什麼？冒險？生存？探索？經營？解謎？最核心的機制亮點，不需要解釋所有規則，只挑最特別的

5. 系統亮點 ── 2-3 個獨特的機制或設定。例如：特殊的檢定方式、獨創的資源系統、有趣的創角流程。這是這套規則跟其他 TRPG 最不一樣的地方

6. 適合什麼樣的玩家 ── 喜歡戰鬥的？喜歡劇情沉浸的？喜歡策略資源管理的？需要什麼程度的 TRPG 經驗？什麼樣的玩家會覺得「這就是我想玩的」？

7. 遊戲風格標籤 ── 從以下固定清單中選擇適當的標籤（不可自由增減類別，不可使用數字分數）。每個類別只能選一個選項：

  戰鬥比重：核心（以戰鬥為主要玩法） / 重要（戰鬥是重要環節但不是全部） / 輔助（戰鬥存在但非重點） / 無戰鬥

  策略深度：高度策略（每一步決策顯著影響結果，錯誤可能致命） / 中度策略（需要考慮技能搭配和資源時機） / 輕度策略（最優選擇通常顯而易見）

  劇情驅動：劇情主導（劇情是遊戲的核心推動力） / 劇情輔助（有明確劇情但玩家自由度較高） / 沙盒自由（無固定劇情，由玩家行動驅動）

  資源管理：重度管理（資源稀缺，需精打細算） / 中度管理（需關注主要資源但不過於苛刻） / 輕度管理（資源充裕，主要聚焦在其他方面）

  角色自訂度：高度自訂（大量選項，可創造獨特角色） / 中度自訂（有明確選項範圍但仍有取捨） / 固定角色（使用預設角色或有限選項）

  創角複雜度：複雜（多步驟選擇，需仔細閱讀規則） / 中等（簡單步驟，可快速完成） / 簡單（幾分鐘內可完成）

  規則密度：重規則（較多機制需學習） / 中規則（核心規則清晰，不繁瑣） / 輕規則（規則簡潔，容易上手）

  GM 需求：需 GM（必須有真人 GM 主持） / 可選 GM（可多人可單人） / 無需 GM（完全單人運作）

8. 預計遊玩時間 ──
   - 單一劇本：從角色創建到劇本完成，預計需要多少小時？（範圍值，如「3-5 小時」）
   - 完整戰役：如果有多個劇本形成連貫戰役，從頭到尾預計需要多少小時？（範圍值，如「40-60 小時」）
   - 如果規則只有單一劇本無連貫戰役，僅填寫單一劇本時間即可

9. 基礎資訊 ── 玩家人數、核心骰種（如 d20、2d6、d100）

格式要求：繁體中文。語氣像在向朋友推薦一個好玩的遊戲，不要過於技術化，不要寫成開發者文件。總長度控制在 500-800 字以內。可以使用簡潔的 Markdown 標題和列表輔助閱讀，但整體應該是流暢的段落文字。最終輸出文字儲存為 [規則名稱]_介紹.txt 檔案，存放在規則目錄中（與玩家規則書同層）。

⚠️ 這是給「玩家」看的介紹，不是給「開發者」看的規格文件。不需要列出完整的屬性表或規則機制。不需要寫 YAML 結構、不要用程式碼區塊、不要用表格。目標是讓讀者看完說「我想玩這個」。不要碰過渡檔案（舊版、備份、v1、草稿等）。如果主體規則的資訊不足以完整描述某個章節，根據已有的設定合理補充，但不要憑空捏造核心設定。

⚠️ 關於參考作品：掃描規則檔案中的前言、背景設定、或致謝章節，確認是否有提及任何參考作品。如果有，務必在介紹中標註。區分「直接轉化」（明確寫出原作名稱和改編性質）與「借鑒啟發」（使用「受到…啟發」措辭，不暗示授權關係）。如果規則完全原創，不需要硬加。

⚠️ 關於遊戲風格標籤：必須從上述固定清單中選擇，不可自行增減類別，不可改用數字分數（如 8/10）。每個類別只能選一個選項。所有類別都必須填寫，不可跳過。如果規則的某些面向在規則書中沒有明確定義，根據機制設計合理推斷。
