# 见势成策 · 行业深度报告

把“行业很热”转换为读者能够判断“谁该在什么条件下进入、先验证什么、何时停止”的报告。参考高雁 AI 硬件报告的论证节奏与留白视觉；继承组织方法，不继承原稿数字、确定性判断或固定章数。

## 先确定决策与范围

从用户材料和上下文确定读者、决策、地区、行业边界、时间窗、证据截止日期、可投入资源和交付格式。缺失且不妨碍推进时写明假设后继续。宽话题先定义客户、买方、付费问题和价值链；例如“AI 企业出海”不能把所有 AI 投资、所有软件收入和所有跨境业务合并成一个市场。

复刻源报告时建立可见内容、讲者口述和新增分析三种来源标签；截图或逐字稿缺失之处保留缺口，不把自创补写称为原文。原稿表达与审校意见分开呈现。新主题研究须重新取证。用户指定模板、章数、语言或视觉时优先遵守。

## 可调整的决策链

下列六段是推理依赖，不是固定目录。可合并或增补章节，但让每个关键结论有证据、机制、边界和行动后果。

1. **为什么现在值得关注。** 比较过去、现在与未来：究竟哪项成本、能力、需求或约束发生了变化？用同口径趋势、结构变化或成本曲线支持拐点；区分实绩与预测。说明延迟进入的代价和现在进入的代价。以采用、复购、预算或效率结果检验热度，寻找“增长快但基数小”“关注多却不付费”的反例。输出有条件的进入、试点、观望或退出判断。
2. **哪些驱动力共同改变机会。** 选择对主题真正有解释力的技术、需求、政策、供给、渠道等变量。每项写出“变化→降低何种约束→哪类客户受益→何时兑现”。政策对照表需有文件、主管机构、适用对象、生效时间、限制与实际可取得条件；不能把扶持金额当成人人可获补贴。技术演示不等于可靠交付，供应成熟不等于付费需求；用限制或未兑现案例检验因果链。输出地区、渠道或交付条件选择。
3. **细分机会在哪里。** 按买方、场景和商业模式分层，而非仅列热门产品。用可比较矩阵说明需求证据、可达客户、竞争替代、价格与成本、门槛、销售周期和风险。重点机会深入到具体客户问题与可交付产品，使用成功及失败案例解释差异。市场规模、出货量、公司估值不能放入同一排序尺度。输出优先验证的细分市场及不适合当前读者的方向，解释取舍。
4. **哪些能力成为瓶颈。** 从前章交付要求反推技能、组织、供应商、合规、销售或信任缺口。人才主题可用岗位与候选人比、招聘样本和薪资分布；标清方向、地区、资历、月薪/年薪及样本局限。用能力差距表连接“现有资产→待补能力→可验证作品/服务→目标角色”。招聘需求增长不等于所有初学者有溢价，低录用率也可能源于岗位质量。输出按起点区分的学习、招聘或合作路径。
5. **资源流向与价值捕获。** 研究资本、采购预算、渠道、产能或生态资源流向，并追问收益由谁获得。融资、估值、资本开支、营收、利润分别列示；全年与部分年度不直接比较，集中大额事件不代表普遍繁荣。用案例对照解释获客、交付、留存、数据与品牌壁垒；融资成功与被收购不自动等于产品成功。至少对重点机会建立可复算经济模型，含价格、直接成本、获客/交付成本、固定投入、回款与悲观情景。输出可承受投入和盈亏/现金流条件。
6. **读者现在具体做什么。** 回答不同角色各自最短可行路径。每条写出起点、交付物、期限、资源、验证指标、成功阈值和停止条件；数值阈值无实证时标为建议假设。把前章证据映射到行动，避免所有角色都得到“学习、关注、积极布局”。结尾给主要选择、尚待验证的关键假设和下一次应检查的信号。

## 证据与计算

为重要主张保留证据记录：主张、来源链接/文件定位、发布与观察日期、地区与人群、单位与分母、事实/来源估计/预测/模型假设/推断、支持范围及局限。优先直接可读的一手资料；公司数据标为公司披露，来源无法打开时不写成已核实。来源紧邻图表或主张，文末可附索引。

所有影响建议的数字可以追溯。重算增长率与 CAGR，写明年份间隔；不同币种、价格口径和市场定义先统一再比较。禁止把意愿当成交、出货当终端售出、采用当付费、流量当收入、毛利当净利、供给当需求、融资当收入。ARR 按来源的经常性收入定义记录；单月收入乘以 12 的 run-rate 是年化运行率；财务期间确认收入是当期会计口径，三者不可互换。计费事件不必然等于业务成功：核对事件定义、人工交接、重开/退款及客户结果。遇到互相矛盾的证据，解释定义/日期差异，无法调和则保留区间或降低结论强度。没有可比数据可用定性比较，不虚构精确评分。

主要建议需有能够使其失效的证据或情景；反例应改变边界、优先级或停止条件，不能只放在末尾作装饰。标题强度不得高于证据强度，“最佳时机”“唯一通道”“必然增长”等判断需要比较基准，否则改成有条件结论。

## HTML 表达与交付验收

按用户指定格式交付。适合分享时可用单文件 HTML，内嵌 CSS、必要 JavaScript 与 SVG，离线能读核心内容；无需强制任何共享渲染器。苹果式视觉可使用白/浅灰交替章节、宽留白、黑色大标题、少量蓝色重点、柔和卡片、清晰数据表及醒目结论。首屏呈现问题、日期、判断、关键证据和阅读入口。视觉层次服务证据，不以大量卡片代替分析。

图表有标题、单位、期间、来源、说明和可读数据；实绩与预测视觉区分。关系用流程图、对比用表格或条形图、变化用时间序列；没有数量关系不要装饰性画图。只加入有决策价值的交互，如角色切换、情景测算、来源展开。测算器标明模型假设，输入变动应同时更新结果与解释。至少验证基准、非正贡献、高用量、人工支持增加、非法/空输入与向上取整的整数边界；用独立精确计算核对，显示四舍五入不得改变后续计算。输入失效时清空或明确标记旧结果，恢复有效输入后重算。工时、客户数等阈值须可实现；没有非负可行解时直说无可行方案，不输出可被误认为行动目标的负阈值。

交付前实际检查桌面约 1440px 与手机约 390px：首屏与长页可读、没有页面横向溢出、标题不截断、锚点不被导航遮住、表格可访问、图表标签清晰、键盘操作和焦点可用。验证所有导航、来源链接、筛选、测算及打印模式；对关键计算用独立算式核对。保存实际截图或检查记录，说明通过项目与未完成项目。构建成功不能代替视觉或交互验收。最终提供可打开的报告路径、证据与模型文件，以及仍会影响决策的局限。
