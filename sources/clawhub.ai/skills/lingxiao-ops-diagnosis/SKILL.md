# 运营诊断

店铺"看起来在增长但不赚钱"，九成出在同一件事：
**用下单量算生意，用净结算发工资。** 这两个数之间隔着取消、退货、送达失败、
平台佣金、达人佣金和广告，每一层都在吃掉那个漂亮的 GMV。

## 接官网 MCP（不用注册）

把这段粘进 MCP 客户端（WorkBuddy、Cursor、Claude Code 写法都一样）：

```json
{ "mcpServers": { "lingxiao": { "url": "https://www.lingxiaochuhai.com/mcp" } } }
```

不填 key 就是匿名试用：每个 IP 每天 20 次工具调用。
`profit_estimate` 与 `etsy_fee_estimate` 在免费的 `public` 档，不花钱。

要更多次数：<https://www.lingxiaochuhai.com/app/membership?from=mcp-trial>

## 第一步：把口径换成净结算

诊断从换分母开始。**下单量不是收入，净结算才是。**

```
有效收入 = 下单 GMV
         − 取消（下单后未发货）
         − 退货退款（已送达后退回）
         − 送达失败（COD 市场尤其要单列）
```

这三层要分开统计，因为**它们指向三个完全不同的部门**：

| 掉在哪一层 | 病根多半在 | 该找谁 |
|---|---|---|
| 下单后取消 | 价格反悔、等太久、冲动消费退潮 | 定价与发货时效 |
| 送达失败 | 地址质量、COD 拒收、末端配送 | 物流与下单页 |
| 送达后退货 | 实物与详情页不符、QC | 供应链与详情页 |

把三层合成一个"退货率"来汇报，等于把三个部门的问题搅成一锅，谁都不用负责。

## 第二步：算单件真成本

```
profit_estimate({
  costCny: 45, priceLocal: 29.9, weightG: 380,
  baseCountry: "US", countries: ["US", "PH"],
  affiliateRate: 0.1, shippingCny: 12
})
```

返回给的是两种模式（跨境直发 / 海外仓）的毛利、差额、推荐模式和一个决策档，
以及被扣走的费用**总额**——够判断这个价能不能做。
费率与物流分档的逐项拆解要登录版，返回里会用 `detailWithheld` 标出来，
那是"这里不给"不是"数据缺失"，别拿总额去反推分项。

注意 `baseCountry` 是定价基准，**不会出现在对比行里**。

Etsy 卖家用这个，费用结构不一样：

```
etsy_fee_estimate({
  priceUsd: 39.9, goodsCostUsd: 11, shippingChargedUsd: 0,
  refundRate: 0.05, aftersalesUsd: 1.2, offsiteAds: "under10k"
})
```

它有一件事一定会做，不要当成多余：**恒定给出"被 Offsite 归因"的最坏情景**，
哪怕你说没开。Offsite 是按单归因的，哪一单被算上不由卖家选，
只看无广告那档等于按运气定价。

**不填退款率和售后成本，算出来的毛利是虚的。** 工具会显式警告，别忽略那条。

## 第三步：找瓶颈，一次只找一个

诊断的产出是一句话：**当前最大的一个瓶颈是什么，为什么是它。**
列出十条待优化项等于没有诊断。排序按"改动成本 ÷ 影响金额"，不按容易程度。

按顺序自问：

1. 流量够不够 — 曝光在跌还是转化在跌？两者的药完全不同。
2. 转化差在哪一步 — 点击到加购，还是加购到下单？前者是主图价格，后者是运费信任。
3. 单件赚不赚 — 用上面的测算，把广告和售后都摊进去，不要只算毛利。
4. 退掉多少 — 按上面三层拆，别合并。
5. 现金能不能转 — 备货占款周期比利润率更早杀死一家店。

要看**整店的实际发生数**——哪个 SKU 在吃预算、哪个渠道的净结算最健康、

## 边界

- 所有测算都是单件静态模型，不含固定成本分摊与资金占用。规模决策不能只看它。
- 汇率按当期口径取，长周期备货要自己留波动余量。
- COD 市场的送达失败率和信用卡市场差一个量级，两个市场的基准不能互相套用。
- 单月数据判不了趋势。至少要三个月同口径，才分得清季节性和真实衰退。
