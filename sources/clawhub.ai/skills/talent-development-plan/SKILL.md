# 职业教育人才培养方案编制技能

基于教学标准与行业报告生成**符合国家规范的职业院校人才培养方案（Markdown → DOCX）**。

## 触发条件

用户提出以下任一需求时触发此技能：

- 编制/撰写/生成 **人才培养方案**
- 基于 **教学标准 + 职业分析报告** 生成培养方案
- 中职 / 高职 / **中高职一体化** 培养方案设计
- 专业建设方案、课程体系设计
- 专业教学标准应用、职业分析报告整合

## 输入材料

### 必需材料

| # | 材料 | 必需 | 说明 |
|:--|:-----|:----:|:-----|
| 1 | **目标专业名称及代码** | ✅ | 如"汽车运用与维修（700206）中职"、"数字媒体技术（510204）中高职一体化"。**支持模糊匹配**，如"机械加工"可自动匹配到"机械加工技术" |
| 2 | **专业教学标准** | ⬜ | 国家/省级颁布的该专业教学标准文件（PDF/DOCX/TXT）。**可自动检索**：系统内置专业目录和教学标准库，用户仅提供专业名称即可自动获取（见 Phase 0.5） |
| 3 | **职业分析报告** | ✅ | 该专业的岗位调研/职业分析报告（PDF/DOCX/TXT） |

> 💡 **自动检索说明**：材料#2（专业教学标准）可由系统自动检索获取。系统内置以下数据源：
> - `assets/职业教育专业目录.xlsx`（1443条专业记录）：根据专业名称和层次获取专业代码
> - `assets/moe_pdfs_final.json`（579条PDF索引）：根据专业代码获取教学标准PDF URL
> - `assets/moe_pdfs_md/`（274个专业简介文件）：备选数据源，获取专业简介内容
>
> 检索优先级：**XLSX检索专业代码 → JSON检索PDF URL → MD检索专业简介 → 提示用户上传**
>
> 若自动检索未找到或用户需要特定版本的教学标准，可手动上传文件覆盖自动检索结果。

### 可选材料

| # | 材料 | 必需 | 说明 |
|:--|:-----|:----:|:-----|
| 4 | **自定义样例 Markdown** | ⬜ | 用户可提供自己的格式模板；**若未提供，则使用内置默认模板（见下方）** |

> ✅ **内置默认模板**：技能 `assets/` 目录已预置两套完整格式模板，根据用户指定的教育层次**自动选择**：
> - **中职** → 使用 `assets/人才培养方案-中职模板.md`（基于四川省中等职业学校数字媒体技术应用专业方案）
> - **高职** → 使用 `assets/人才培养方案-高职模板.md`（基于四川省高等职业院校数字媒体技术专业方案）
> - **中高职一体化** → 组合使用两套模板（中职段用中职模板 + 高职段用高职模板），以中职模板为主体框架，在衔接章节融合高职模板内容
>
> ⚠️ 若用户**自行上传了样例 MD 文件**，则**优先使用用户模板**，忽略内置模板。

## 执行流程

### Phase 0.5：自动检索专业教学标准（可选）

**触发条件**：用户仅提供专业名称和教育层次，未上传教学标准文件时自动执行。

**检索流程**：

```
用户输入（专业名称 + 教育层次）
        ↓
调用 scripts/search_major.py
        ↓
Step 1: 从 XLSX 职业教育专业目录检索 → 专业代码 + 类别代码
        ↓
Step 2: 用专业代码从 moe_pdfs_final.json 查询 PDF URL
        ↓
Step 3: 若无 PDF → 用类别代码从 moe_pdfs_md/ 查找专业简介
        ↓
Step 4: 均未找到 → 提示用户上传
```

**调用方式**：

```bash
python scripts/search_major.py -m "<专业名称>" -l "<教育层次>" -o <output.json>
```

**结果分支处理**：

| 结果状态 | 处理方式 |
|:---------|:---------|
| 找到 PDF URL | 下载 PDF → **使用 markitdown 解析**（优先）→ 进入 Phase 0 预处理 |
| 找到专业简介（MD） | 提示用户："未找到专业教学标准，将使用专业简介，是否继续？" → 用户确认后进入 Phase 0 |
| 多个候选专业 | 返回候选列表（最多5个），请用户选择 → 用选定专业代码重新检索 |
| 均未找到 | 提示用户："请上传该专业的教学标准文件（PDF/DOCX格式）" |

**JSON 输出关键字段**：

```json
{
  "major_code": "660102",       // 专业代码
  "category_code": "6601",      // 专业类代码
  "major_name": "机械加工技术",
  "pdf_url": "http://...",      // PDF URL（若有）
  "data_source": "primary",     // 数据源：primary/fallback/not_found
  "need_upload": false          // 是否需要用户上传
}
```

**用户交互提示示例**：

- 多候选："找到多个匹配的专业，请选择：1. 机械加工技术 (660102) 2. 机械制造技术 (660103)"
- 专业简介确认："⚠️ 未找到专业教学标准，但找到专业简介文件。是否继续使用专业简介？（Y/N）"
- 上传提示："❌ 未找到该专业的教学标准，请上传教学标准文件（PDF/DOCX格式）"

**与 Phase 0 的衔接**：

- 若检索成功（PDF URL）：
  1. 下载 PDF 到临时目录
  2. **优先使用 markitdown 解析 PDF**（命令：`markitdown <pdf_file>` 或调用 `scripts/preprocess.py`）
  3. 若 markitdown 不可用，降级为 `pdfplumber` 解析
  4. 解析后的 Markdown 文件路径传递给 Phase 0 继续处理
- 若检索成功（MD 文件路径）→ 直接读取 MD 文件进入 Phase 0
- 若用户上传文件 → 直接进入 Phase 0 预处理用户上传的文件

### Phase 0：材料预处理

对每份输入文档执行预处理：

```bash
# 使用 markitdown 将任意格式转为markdown（优先）
python scripts/preprocess.py <input_file> -o <output.md>
```

若 markitdown 不可用，降级为：
- DOCX → 使用 `python-docx` 提取全文+表格
- PDF → 使用 `pdfplumber` 提取全文+表格

**关键**：预处理时必须保留表格结构（用 `|` 分隔符标记），后续解析依赖此格式。

### Phase 1：解析样例结构

**模板选择逻辑（按优先级）**：

1. **优先**：若用户上传了自定义样例 Markdown → 读取用户文件
2. **默认**：用户未提供样例 → 根据目标专业教育层次自动选用内置模板：
   - `中职` / `中等职业` → `assets/人才培养方案-中职模板.md`
   - `高职` / `高等职业` / `专科` → `assets/人才培养方案-高职模板.md`
   - `中高职一体化` / `五年制` / `3+2` → 以中职模板为主体框架，高职模板补充衔接章节

读取选定的样例 Markdown 文件，提取：章节层级树（`#`~`####`标题及层级）、表格结构清单（列定义/行数/用途）、列表样式规范、占位符模式、特殊格式（代码块/引用块/加粗斜体）。保存为输出格式的**严格模板**。

### Phase 2：提取教学标准数据

**MANDATORY - READ ENTIRE FILE**: Before extracting course data, you MUST read [`references/national-standards.md`](references/national-standards.md) (~145 lines) completely to obtain public course standards, hour limits, and terminology requirements.

**Do NOT load**: `references/template-chapters.md` (only needed if Phase 1 parsing fails)

从教学标准文件中提取以下关键字段：

| 字段类别 | 具体内容 |
|:--------|:---------|
| **基本信息** | 专业代码、专业名称、入学要求、修业年限、职业面向（对应职业类/岗位群） |
| **培养目标** | 总体培养目标描述 |
| **培养规格** | 素质目标、知识目标、能力目标（分项列出） |
| **课程体系** | 公共基础课列表（含建议学时）、专业课（基础/核心/拓展）、实践教学环节 |
| **专业核心课详表** | 每门核心课程的**典型工作任务描述**、**主要教学内容与要求**→ ⚡课程目标核心数据源 |
| **学时学分** | 总学时/总学分建议、各类课程学时比例、理论与实践比例 |
| **毕业要求** | 毕业资格条件、证书要求 |

> 若教学标准公共基础课列表不完整，从已加载的 `references/national-standards.md` 补充。

### Phase 3：提取职业分析报告数据

从职业分析报告中提取：

| 字段类别 | 具体内容 |
|:--------|:---------|
| **行业背景** | 行业发展现状、人才需求趋势、区域产业对接情况 |
| **职业面向** | 主要就业岗位群、职业晋升路径 |
| **典型工作任务** | 岗位任务分解表（任务→能力→知识点映射） |
| **学习领域分析** | 各学习领域（LD）的学习目标、学习内容、教学方法、评价方式→ ⚡课程目标核心数据源，详见规则D |
| **学习情境设计** | 每个学习领域下的具体情境（名称、学时、学习目标、学习内容、教学方式、评价方式） |
| **职业技能等级证书** | 建议考取的X证书/职业资格证书 |
| **人才需求量化** | 区域内年需求量、薪资水平等（如有） |

### 映射关系参考（内置）

**教学标准→方案**：专业名称/代码/入学要求/修业年限→第1-3章；职业面向→第4章表1（与报告合并）；**培养目标→第5章（一），必须引用原文并按其结构撰写**；培养规格→第5章（二），能力目标需与报告职业能力对等合并；课程清单→第6章表5/6/7（与学习领域合并）；核心课教学内容与要求→表6主要内容/教学要求；实践教学→表8；学时→合规校验基准；师资/设施/质量保障→第8章；毕业要求→第9章。

**报告→方案**：工作任务→表3；**职业能力汇总表→第5章（二）能力目标（双源对等合并）**；学习领域(LD)学习目标/内容/方法/评价→表5-7课程目标/主要内容/教学要求（核心融合规则见规则D）；学习情境→对应课程主要内容/教学要求（项目案例载体，非独立实训）；行业趋势→第8章；证书→第4章表1。**⚡ 表3职业能力列禁止使用代码（如"1.1素描..."），必须写入具体的职业能力描述文字，详见下方"表3生成规范"**。

### Phase 4：融合数据并逐章生成

按照样例的**精确章节顺序和格式**，逐章生成内容，并遵循以下映射关系及特殊规则。

#### 章节映射规则

| 样例章节名（示例） | 数据来源 | 生成策略 |
|:-------------------|:---------|:---------|
| 封面 / 专业基本信息 | 用户指定 + 教学标准 | 直接填入专业名称/代码/层次 |
| 入学要求 | 教学标准 | 采用标准原文或适当改写 |
| 修业年限 | 教学标准 | 注明中职段/高职段的年限划分 |
| **职业面向** | 教学标准 ∪ 职业分析报告 | **合并两者**：标准提供框架和行业/职业类别代码，报告补充具体岗位名称和职业路径。详见下方"职业面向合并策略" |
| **培养目标** | 教学标准（主）+ 职业面向岗位 | 必须引用教学标准培养目标原文并按其结构撰写，补充职业面向主要岗位。详见下方"培养目标生成规范" |
| **培养规格** | 模板 + 教学标准 + 职业分析报告职业能力 | 三源整合：素质目标以模板中的**1. 职业素质要求**为主，**职业知识要求**以标准为主、报告补充；**能力目标对等整合**——标准能力条目+报告职业能力汇总表合并去重。详见下方"培养规格三源整合" |
| **课程体系** | 教学标准 + 职业分析报告学习领域 | **双源构建+合并**：教学标准课程与职业分析报告学习领域双向映射，合并相同/类似课程，学习领域无对应课程时新增转化。详见下方"课程体系双源构建与合并"。**⚡ 合并完成后，必须进入"课程体系交互确认"环节，经用户确认/调整后才能固化到最终方案。** |
| **教学进程安排表** | 教学标准 + 学时计算规则 + 职业分析报告建议学期 | 按学期分配课程，遵循下方"教学进程学期编排规则"，确保总学时达标 |
| **实施保障** | 教学标准 + 报告 | 师资队伍、实训条件、校企合作等 |
| **毕业要求** | 教学标准 | 毕业学分/证书/考核等条件 |

#### 职业面向合并策略（Phase 4 必经环节）

职业面向表必须**同时引用教学标准和职业分析报告的岗位信息**，两者分类体系不同时按以下规则合并：

**合并原则**：教学标准提供**框架**（行业代码、职业类别代码），职业分析报告提供**具体岗位细节**。

**步骤**：

1. **提取教学标准职业面向**：行业名称+代码、职业类别+代码、岗位群（如"汽车机电维修、汽车维修接待"）、职业类证书
2. **提取职业分析报告岗位信息**：具体岗位名称（如"汽车保养工、汽车维修技工、汽车故障诊断员、机动车检测员、汽车装配工"）、典型工作任务、职业晋升路径
3. **合并策略**：
   - "所属专业大类/对应行业/主要职业类别"：直接采用教学标准的分类与代码
   - "主要岗位（群）或技术领域"：以教学标准岗位群为**大类**，将报告中具体岗位作为**细分岗位**填入（如教学标准"汽车机电维修"→报告细化为"汽车保养工/汽车维修技工/汽车故障诊断员"）
   - 报告中有但教学标准未提及的岗位（如"汽车装配工""机动车检测员"）：补充纳入，标注来源为"职业分析报告"
   - "职业技能等级证书/资格证书"：两源合并去重
4. **输出格式**：以标准样例表格呈现（行业→职业类→主要岗位→职业资格），"主要岗位"列同时展示大类和细分岗位

#### 培养目标生成规范（Phase 4 必经环节）

培养目标**必须引用专业教学标准培养目标原文并按其结构撰写**，补充职业面向主要岗位。禁止脱离教学标准自行编写。

**步骤**：
1. **提取教学标准培养目标原文**：完整提取，记录其结构（通常为"培养面向XX行业XX岗位群，德智体美劳全面发展，具有XX素质，掌握XX知识，具备XX能力的高素质技术技能人才"）
2. **按结构改写**：保持原文句式框架，仅替换——"面向XX岗位群"替换为第4章职业面向表中实际主要岗位名称；"具有/掌握/具备"与第5章（二）培养规格三维目标呼应但不重复

**验证**：生成文本必须包含教学标准原文核心要素（面向行业、岗位群、素质/知识/能力关键词），不得遗漏。

#### 表3生成规范（职业岗位及典型工作任务分析表）

表3的数据来源于**职业分析报告的典型工作任务分析**和**职业能力汇总表**。生成时必须遵守以下规则：

**禁止使用代码**：职业能力列不得填写代码编号（如"1.1素描、色彩构成""Z001汽车维护能力"），必须写入**具体的职业能力描述文字**。

**各列填写规则**：

| 列 | 数据来源 | 填写规则 |
|:---|:---------|:---------|
| 职业岗位 | 职业分析报告"职业面向"或"典型工作任务分析"中的岗位名称 | 填入具体岗位名称（如"汽车机电维修工""汽车保养工"），非行业大类 |
| 典型工作任务 | 职业分析报告"典型工作任务分析"中的任务名称 | 填入任务名称（如"汽车定期维护""汽车发动机机械检修"），保持与报告一致 |
| 职业能力 | 职业分析报告"职业能力汇总表"中的能力描述 | **将代码替换为完整描述**：如"Z001"→"具有按照保养手册规范完成汽车定期保养操作的能力"。一个岗位对应多项能力时分行列出 |
| 知识 | 职业分析报告"典型工作任务分析"中的知识要求 | 改写为"掌握..."句式，每项任务列出2-4个核心知识点 |
| 技能 | 职业分析报告"典型工作任务分析"中的技能要求 | 改写为"能/能够..."句式，明确操作对象和结果标准 |
| 素质 | 职业分析报告"典型工作任务分析"中的素质要求 + 通用职业素养 | 改写为"具备/养成...意识/精神/习惯"句式 |

#### 培养规格三源整合（Phase 4 必经环节）

培养规格的三维目标（职业素质/职业知识/职业能力）必须同时引用模板、教学标准和职业分析报告，**能力目标尤其需要对等整合两源**。

**教学标准培养规格条目拆分策略**：

教学标准的培养规格条目常为"知识+能力"捆绑结构（如"掌握汽车机械常识、汽车电工电子基础等专业技术基础知识，具有汽车维修与运用基本技能"），必须拆分为独立的条目归入对应维度：

1. **识别结构**：每条中"掌握/了解/理解"后跟的为知识部分，"具有/能/能够"后跟的为能力部分，"树立/养成/具备...意识/精神/习惯"为素质部分
2. **拆分规则**：将混合条目按知识/能力/素质分别提取，归入对应维度。同一条原文可能拆出2-3个维度的条目
3. **示例**：条目(8)"掌握汽车维护技术技能，具有汽车维护作业能力" → 拆分为知识"掌握汽车维护的技术规范和工艺流程" + 能力"具有汽车各级维护作业能力"

**数据来源**：

| 维度 | 主源 | 补充源 | 整合方式 |
|:-----|:-----|:-------|:---------|
| **素质目标** | 模板"培养规格-职业素质要求"条目 | 职业分析报告中**社会能力**（如团队协作/沟通/责任感/环保意识）+ 工作态度/职业操守 + 标准中的素质条目 | 模板条目直接采用；标准素质条目嵌入；报告**社会能力**归入素质目标（标注"社会能力"） |
| **知识目标** | 教学标准"培养规格-知识"条目（拆分后） | 职业分析报告中典型工作任务→知识映射提取 | 标准条目直接采用；报告中标准未涵盖的专业知识条目补充纳入 |
| **能力目标** | 教学标准"培养规格-能力"条目（拆分后） | **职业分析报告"职业能力汇总表"**：**专业能力**（Z系列）+ **方法能力**（F系列） | **双源对等合并**（见下方规则） |

**职业能力分类归属规则**（职业分析报告的职业能力通常分三类）：

| 能力类别 | 代码前缀 | 归属维度 | 处理方式 |
|:---------|:---------|:---------|:---------|
| 专业能力 | Z001-Z0XX | 能力目标 | 与教学标准能力条目逐项比对合并 |
| 方法能力 | F001-F0XX | 能力目标（独立条目） | 直接纳入能力目标，标注"方法能力"，如"具有信息获取与处理能力（方法能力F001）" |
| 社会能力 | S001-S0XX | 素质目标 | 直接纳入素质目标，标注"社会能力"，如"具有团队协作能力（社会能力S001）" |

**能力目标双源合并规则**：

1. 提取教学标准中所有"能力"条目（经拆分后），形成集合A
2. 提取职业分析报告中"职业能力汇总表"中**专业能力**描述，形成集合B_Z；**方法能力**形成集合B_F
3. 逐项比对A与B_Z：若A与B_Z表述指向同一能力（语义等价或包含关系），保留教学标准表述（更规范），附注报告能力代码；若报告描述更具体，形成"总—分"结构
4. B_Z中存在但A中无对应的能力条目，直接纳入能力目标，标注来源为"职业分析报告"
5. B_F方法能力全部纳入能力目标，标注"方法能力"
6. 合并后的能力目标应覆盖报告中的**全部专业能力和方法能力**，不得遗漏
7. 能力目标的**语句结构**：按照**能力+行动**结构，句式为：具有/具备……能力，能够从事……工作/完成……任务/制作……作品/提供……服务/开发……产品/实施……设计/……

**输出要求**：在培养规格章末注明"本培养规格依据《XX专业教学标准》培养规格条款与《职业分析报告》职业能力汇总表整合编写，能力目标已覆盖报告全部专业能力（Z001-Z0XX）和方法能力（F001-F0XX），社会能力（S001-S0XX）已纳入素质目标。"

#### 课程体系双源构建与合并（Phase 4 必经环节）

课程体系的课程清单必须**同时来源于教学标准和职业分析报告的学习领域**，通过双向映射合并后确定最终课程列表。

**Step 1：提取双源课程集合**

集合A（教学标准）：专业基础课/核心课/拓展课的名称、建议学时、类别；集合B（职业分析报告）：各学习领域（LD）的名称、学时、学习目标摘要。

**Step 2：双向映射**

对A中每门课程在B中查找知识范围重合的LD；对B中每个LD在A中查找对应课程。映射依据：名称相似度、内容重叠度、任务与目标对应度。

**映射冲突处理策略**（以教学标准课程框架为准）：

| 冲突类型 | 处理方式 | 示例 |
|:---------|:---------|:-----|
| **一对多**：1个LD覆盖教学标准多门课程 | 以教学标准课程框架为准，将LD的"学习目标""学习内容"按知识模块拆分，分别补充到对应的各门课程中。LD的学习情境也按内容归属拆分到各课程 | LD003"汽车底盘检修"覆盖教学标准3门核心课（传动/行驶与转向/制动）→ LD003学习内容按"传动""行驶与转向""制动"三模块拆分，分别补充到对应课程；LD003的学习情境也按此三模块拆分归属 |
| **多对一**：教学标准多门课程映射到1个LD | 以教学标准课程框架为准，不合并课程；LD内容按知识领域分配到各课程 | 教学标准"汽车发动机控制系统检修"+"汽车车身电气设备检修"均与LD004"汽车电气系统检修"部分相关 → LD004内容按"发动机电控""车身电气"两部分分别补充 |
| **多对多**：N个LD的内容分散在M门教学标准课程中 | 逐一分析每个LD的知识模块，每个模块只归属到1门课程，避免同一知识点重复分配 | LD004"汽车电气系统检修"的"蓄电池/起动/充电"模块归入"汽车发动机控制系统检修"，"照明/信号/仪表/辅助电气"模块归入"汽车车身电气设备检修" |
| **LD跨领域**：1个LD涵盖多个技术领域 | 若LD内容明显可拆分为独立领域，则拆分为多个子模块分别映射；若领域间耦合紧密，则保留为1门综合课，标注"综合" | LD006"汽车空调检修与车身修复"→ 拆分为"空调检修"（映射到教学标准拓展课"汽车空调系统检修"）和"车身修复"（无对应课程，新增转化）两个子模块 |
| **LD属实践环节**：LD内容为综合实训/实习 | 不作为专业课程转化，归入"集中实践教学"环节，保留其学习情境作为实训项目 | LD008"汽车维修综合实训"240学时 → 归入表8"集中教学和实践实训项目" |

**Step 3：合并规则**

| 映射结果 | 处理方式 | 来源标签 | 示例 |
|:---------|:---------|:---------|:-----|
| A中有课程 C，B中有对应LD | 合并为1门课程，课程目标与主要内容按规则D双源整合 | 教学标准+学习领域 | 教学标准"汽车定期维护" + LD"汽车维护" → 合并为《汽车定期维护》 |
| A中有课程 C，B中无对应LD | 保留课程C，后续按规则D情况一/三生成内容 | 教学标准 | 教学标准"专业导论"无对应LD → 保留 |
| B中有LD，A中无对应课程 | **新增转化**：将LD转化为1门课程，名称取LD名称或提炼概括，学时取LD学时 | 学习领域转化 | LD"汽车发动机机械系统检修"无对应标准课程 → 新增《汽车发动机构造与维修》 |
| A、B均有但名称不同、内容高度重叠 | 合并为1门课程，名称以教学标准为准或综合表述，标注合并说明 | 双源合并 | 教学标准"图形图像处理" + LD"数字图像编辑" → 合并为《图形图像处理》，附注"含LD数字图像编辑内容" |

**Step 4：学时与类别处理**

- 双源均有时：学时取教学标准值与LD学时的**较大值**；仅单源时采用该源学时
- LD转化新增课程：根据LD内容归入对应类别，核心LD归入专业核心课
- 公共基础课不参与此合并，按规则B复用模板

**课程学时分配策略**（教学标准通常只给总学时和比例，不给每门课具体学时）：

| 课程类型 | 学时来源 | 分配方法 |
|:---------|:---------|:---------|
| **公共基础课** | `references/national-standards.md`中的标准学时 + 模板表4学时 | 优先采用国标建议学时，参照模板表4数值，可根据本校实际微调 |
| **专业基础课** | 教学标准无明确学时 → 根据课程性质和内容量推算 | 按每门课内容量估算：概论/文化类36-48学时，技术基础类64-96学时 |
| **专业核心课** | 教学标准无明确学时 → LD学时（如有）为主要依据 | 有对应LD的课程采用LD学时（可±10%微调）；无LD的课程按内容量估算，参考同类核心课学时 |
| **专业拓展课** | 教学标准无明确学时 → 根据课程内容量推算 | 每门32-64学时，确保选修课总学时占比≥10% |
| **集中实践** | 教学标准有明确周数 → 按每周30学时折算 | 认知实习1周=30学时，岗位实习按教学标准规定（一般6个月，但折算学时需符合国标） |

**校验**：所有课程学时之和 + 集中实践学时 = 教学标准规定的总学时（如中职3160学时）。若不匹配，按比例调整专业课学时，公共基础课学时不动。

**Step 5：输出合并结果**

生成合并后的课程清单，每门课标注：来源标签（教学标准/学习领域转化/教学标准+学习领域/双源合并）、对应LD编号（如有）、合并说明（如有）。此清单进入"课程体系交互确认"环节供用户审核。

#### 学时学分合规性检查（必须执行）

生成过程中及生成后，执行以下校验：

```
三年制中职：总学时 ≥3000，公共基础课 ≥33%，选修课 ≥10%
三年制高职：总学时 ≥2500，公共基础课 ≥25%，选修课 ≥10%
五年制/一体化：总学时 ≥4500，公共基础课 ≥25%，选修课 ≥10%
实践教学学时占总学时比例 ≥ 50%
```

详细规则见 `references/national-standards.md`。

**校验失败时的修复**：若校验不通过，**立即查阅** `references/error-recovery.md` 第一章，按步骤修复后重新校验。常见问题：
- 总学时不达标 → 增加专业课学时或计入岗位实习学时
- 公共基础课比例不足 → 减少专业课学时而非增加公共基础课学时
- 实践比例不足 → 增加课程实践学时或集中实践周数

### Phase 5：输出（Markdown → DOCX）

> **默认行为**：无论用户是否明确要求 DOCX，**始终**先输出 Markdown 文档，再转换为 DOCX。这是本技能的标准交付格式。

#### Step 5.1：生成完整 Markdown 文档

按照样例的**精确章节顺序和格式**，生成完整 Markdown 文本，遵循以下特殊规则：

##### 规则A：课程体系架构图嵌入

在 **"6. 课程体系及要求 → （一）课程体系"** 章节、**"专业课程体系示意图"** 位置，嵌入课程体系架构图：

**生成与引用流程**：

1. 调用 `scripts/create_curriculum_image.py` 生成 PNG 架构图（传入目标专业的实际课程数据）
2. **图片保存位置**：保存到**输出目录**的 `images/` 子目录下（与最终MD文件同级）
   - 输出目录结构：`<output_dir>/方案.md` + `<output_dir>/images/课程体系架构图.png`
3. **MD中的图片引用**：使用**相对路径**引用图片——`![课程体系架构图](images/课程体系架构图.png)`
   - 必须使用相对路径（`images/xxx.png`），不得使用绝对路径
   - 原因：pandoc从MD文件所在目录执行时，相对路径才能正确解析
4. **脚本特性**：自动按最长课程名计算列宽；长课程名自动换行；图片宽度自适应（默认≥1400px，按需扩展至2000px）；5类课程层次化布局
5. **中文显示**：Linux用`wqy-microhei`/`wqy-zenhei`，Windows用`msyh.ttc`/`simhei.ttf`，macOS用`PingFang`；加载失败时回退至系统默认字体
6. **嵌入校验**：pandoc转换后，**必须检查DOCX中是否包含图片**（`python-docx`读取`inline_shapes`长度≥1）；若图片缺失，pandoc仅输出WARNING不报错，DOCX中图片位置会退化为纯文本——必须主动发现并修复

```bash
# Step 1：生成架构图到输出目录的images子目录
python scripts/create_curriculum_image.py --data curriculum_data.json -o <output_dir>/images/课程体系架构图.png

# 或传入JSON字符串
python scripts/create_curriculum_image.py --data '{"major_name":"XX专业","level":"中职","public_courses":[...],"basic_courses":[...],"core_courses":[...],"elective_courses":[...],"practice_courses":[...]}' -o <output_dir>/images/课程体系架构图.png
```

**JSON数据结构**：`major_name`（专业名称）、`level`（中职/高职/中高职一体化）、`public_courses`（公共基础课列表）、`basic_courses`（专业基础课列表）、`core_courses`（专业核心课列表）、`elective_courses`（专业拓展/选修课列表）、`practice_courses`（集中实践教学列表）

##### 规则B：公共基础课表（表4）严格复用模板

无论是中职还是高职，**"表4 公共基础课程"必须从内置模板MD文件中提取，保持结构和国家标准内容不变**。

**操作步骤**：

1. 读取对应层次模板MD文件，定位"表4 公共基础课程"的完整Markdown表格
2. **整表复制**到输出Markdown——包括所有行（表头+数据行）、所有列（课程目标/主要内容/教学要求/学时/学分等）
3. **课程名称、课程目标中属于国家课程标准的内容、主要教学内容、教学要求的核心表述**不得修改
4. **允许替换**"课程目标"列中涉及**原模板专业名称**的表述（如"为学习数字媒体专业后续课程奠定基础"→替换为"为学习汽车运用与维修专业后续课程奠定基础"），但仅限专业名称/方向性文字，不得改写课程标准规定的知识能力描述
5. **仅允许调整**学时/学分数值以匹配本校方案的实际分配
6. **不得增删课程行**——公共基础课列表由国家统一规定，不得自行添加或删除
7. **验证**：逐行比对模板原文，确认除专业名称替换和学时调整外无其他修改

| 教育层次 | 表4来源 |
|:---------|:--------|
| 中职 | `assets/人才培养方案-中职模板.md` 中的 **表4 公共基础课程** 完整表格 |
| 高职 | `assets/人才培养方案-高职模板.md` 中的对应公共基础课表 |

> **理由**：公共基础课为国家统一规定课程（思政、语文、数学、英语、体育等），其课程标准、教学要求全国一致。但"课程目标"中可能包含专业方向性表述（如"为本专业后续课程奠定基础"），需替换为目标专业名称。

##### 规则C：其他章节正常生成

除上述两条规则外，其余章节（职业面向、培养规格、专业课程表、教学进程安排表、实施保障、毕业要求等）均基于教学标准+职业分析报告融合生成。

#### Step 5.2：转换为 DOCX

使用 pandoc 将 Markdown 转换为 Word 文档：

```bash
# 必须从MD文件所在目录执行，否则相对路径图片无法解析
cd <output_dir> && pandoc 方案.md -o 方案_no_border.docx --reference-doc=<skill_dir>/references/人才培养方案模板.docx

# 若无法cd到输出目录，使用 --resource-path 指定图片搜索路径
pandoc <output_dir>/方案.md -o <output_dir>/方案_no_border.docx --resource-path=<output_dir> --reference-doc=<skill_dir>/references/人才培养方案模板.docx
```

> **注意**：pandoc默认生成的表格**无边框**（使用`Normal Table`样式）。必须执行下一步后处理才能添加边框。

**DOCX后处理**（必须执行）：

```bash
# 为所有表格添加边框、设置表头加粗居中、调整字号和页边距
python <skill_dir>/scripts/postprocess_docx.py \
  --input <output_dir>/方案_no_border.docx \
  --output <output_dir>/方案.docx \
  --font-size 10 \
  --margins 2.54,2.54,3.17,3.17
```

后处理脚本功能：
- 为**所有表格添加边框**（上下左右+内部横竖线，single/4pt/auto样式）
- 表头行**加粗+居中**
- 表格正文统一**字号**（默认10磅，参数可调）
- 页边距设置（默认上下2.54cm、左右3.17cm）

**转换后校验**（必须执行）：

1. 用 `python-docx` 打开DOCX，检查 `doc.inline_shapes` 长度是否≥1（架构图是否嵌入成功）
2. 检查表格是否有边框：`doc.tables[0]._element.find(qn('w:tblPr')).find(qn('w:tblBorders')) is not None`
3. 若图片缺失：检查图片文件是否存在、路径是否正确、pandoc执行目录是否与MD文件同目录
4. 若表格无边框：确认后处理脚本已正确执行
5. 转换时参照 `references/人才培养方案模板.docx` 的格式风格（页边距、标题字体、表格样式等），确保符合正式公文排版规范

## 关键特性：课程体系交互确认

> **设计理念**：不同学校的师资条件、实训设备、区域产业对接差异巨大。教学标准给出的课程清单是"基准线"，各校需根据实际情况调整。本环节在生成完整方案前插入一个**用户确认节点**，让课程设置真正适配本校实际。

### 触发时机

在 **Phase 4 融合生成** 中，完成"课程体系双源构建与合并"后触发：

1. 已从教学标准提取课程集合A，从职业分析报告提取学习领域集合B
2. 已完成双向映射与合并（相同/类似课程已合并，无对应课程的LD已转化为新课程）
3. 已按样例格式构建合并后的课程列表（含建议学时、学分、学期安排、来源标签、对应LD编号）

**此时暂停自动生成**，进入课程确认流程。

### 确认流程

#### Step 1：呈现课程清单

将合并后的课程体系分类展示，每门课标注来源和对应LD编号。专业课程增加"来源"和"对应LD"两列，公共基础课仅标"国家规定"。来源标签：国家规定、教学标准、学习领域转化、教学标准+学习领域、双源合并、用户调整（含义见"课程体系双源构建与合并"Step 3）。底部统计总学时、各类比例、合并分类计数和合规状态。

#### Step 2：发起确认提问

向用户发起确认，提供选项：1.无需修改直接生成；2.删除部分课程；3.添加课程；4.既删又加。

#### Step 3：处理用户反馈

| 用户选择 | 处理方式 |
|:---------|:---------|
| **无需修改** | 直接进入 Phase 5 输出完整方案 |
| **删除课程** | 从对应类别移除 → **重新计算总学时和各类比例** → 重新执行合规校验 → 若比例跌破国标底线，**明确提示风险并询问是否继续** |
| **添加课程** | 将新课程归入合适类别，分配建议学时和学期 → 重新计算并校验 |
| **既删又增** | 按上述两条规则合并处理 |

#### Step 3.5：二次确认（循环）

若用户做了修改，**再次呈现更新后的课程清单**并重新确认。最多3轮调整。

#### 边界规则

- 删除核心课程时必须警告风险（影响毕业资格/证书考核）；调整学时导致比例偏离国标时给出偏差数值；支持替换同类课程（标注"学校自定替代"）；所有用户调整在课程表末尾备注

### 与原有流程的关系

Phase 0→1→2→3→Phase 4（职业面向合并策略→培养目标生成规范→培养规格三源整合→课程体系双源构建与合并→学时学分合规性检查→教学进程学期编排→课程体系交互确认）→Phase 5

> **注意**：课程确认仅影响课程相关章节，职业面向、培养目标、实施保障等不受此环节影响。

## 反模式（禁止行为）

- 不得直接复制样例的专业名称/课程名称 —— 必须全部替换为目标专业内容
- 不得省略样例中的任何一级/二级章节 —— 即使某章节材料缺失也要合理填充
- 不得杜撰数据 —— 材料未提供的字段标注"（建议）"或"（根据教学规律估算）"
- 不得混用口语化表达 —— 全程使用"立德树人""工学结合""岗课赛证融通"等规范术语
- 不得忽略学时校验 —— 即使样例本身有误，也须按国标修正并备注说明
- 不得将职业分析报告中的学习情境仅当作独立实训项目 —— 必须将其拆解融入对应专业课程的"主要内容"或"教学要求"中
- 不得仅以教学标准课程清单作为最终课程体系 —— 必须同时整合职业分析报告的学习领域，对无对应课程的LD执行"学习领域转化"新增
- 不得遗漏学习领域转化课程 —— 职业分析报告中的每个学习领域必须在课程体系中有对应课程或实践环节（匹配、转化或归入集中实践）
- 不得将名称不同但内容高度重叠的教学标准课程与学习领域作为两门独立课程保留 —— 必须合并为一门
- 不得在课程体系双源映射中忽略一对多/多对一/多对多冲突 —— 必须按"映射冲突处理策略"拆分或分配LD内容
- 不得将教学标准培养规格中"掌握...具有..."的捆绑条目直接整体归入一个维度 —— 必须按知识/能力/素质拆分为独立条目
- 不得将职业分析报告的方法能力（F系列）归入素质目标或遗漏 —— 必须纳入能力目标；社会能力（S系列）须纳入素质目标
- 不得将专业基础课简单归类为"无数据源"而仅凭LLM推理 —— 必须先在教学标准培养规格中搜索该课程名称关键词提取相关条目作为依据
- 不得将学习情境全部罗列到课程"主要内容"中 —— 必须按选取策略选取2-4个代表性情境，以项目模块格式融入
- 不得在教学标准无课程学时的情况下随意分配学时 —— 必须按"课程学时分配策略"确定：核心课用LD学时、基础课按内容量推算、总学时校验通过
- 不得将跨领域LD（如同时涵盖空调+车身修复）直接作为一门课程转化 —— 必须按技术领域拆分子模块后分别映射
- 不得将综合实训类LD（如"汽车维修综合实训"）作为专业理论课程转化 —— 必须归入"集中实践教学"环节
- 不得仅以教学标准培养规格作为最终能力目标 —— 必须同时整合职业分析报告的职业能力汇总表，报告中的全部能力项不得遗漏
- 不得在表3"职业能力"列填写代码编号（如"1.1素描""Z001汽车维护"） —— 必须将代码替换为完整的职业能力描述文字
- 不得将pandoc直接输出的DOCX作为最终交付 —— 必须执行postprocess_docx.py后处理，确保表格有边框、表头加粗居中
- 不得在双源匹配的课程目标合并中一律保留教学标准表述 —— 当报告描述更具体时，必须采用报告表述或形成"总—分"结构
- 不得脱离教学标准自行编写培养目标 —— 必须引用教学标准培养目标原文并按其结构撰写，补充职业面向主要岗位
- 不得改写表4公共基础课表中属于国家课程标准的内容 —— 必须从模板提取，仅允许专业名称替换和学时调整
- 不得使用模糊表述作为课程目标条目（如"了解相关知识""具有维护能力"） —— 知识条目须为完整动词+宾语；能力条目须为"能力+行动"结构（"具有XX能力，能够完成XX任务"）；素质条目须可观测可评价
- 不得在教学进程安排表中随意排课而不遵循基础先行、核心递进原则 —— 必须按学期编排规则编排
