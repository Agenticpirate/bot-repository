# 周计划自动分配日程器 (week-to-day-splitter)

把一份周工作计划，按子步骤的 `#周一/#周二/.../#周五` 时间标签，自动拆分成 5 个日工作计划。

## ⚠️ 阅读前必读：本 skill 的能力范围

本 skill **不只是"本地计划管理"**，还包含以下能力：

**执行能力**：
- 📁 **文件读写**（\`${NOTES_DIR}/00-工作计划/001周工作计划/\` 和 \`${NOTES_DIR}/00-工作计划/002日工作计划/\`）
- 📤 **推送 daily plan 到飞书**（每天 15:00，含任务名/截止日/地点/责任人）

**外发数据范围**（推送到飞书）：
- 任务标题（可能含客户名、项目名等）
- 项目截止日期（可能含商业敏感信息）
- 地点信息（可能含未公开拜访地点）
- 责任人（@客户名）
- 备注（可能含未公开商业策略）

**隐私影响**：
- 如果飞书 webhook 泄漏，daily plan 内容会被第三方获取
- 如果 daily plan 包含客户名/合同金额，**违规外发可能导致法律责任**
- 建议：仅在企业内部飞书 + 仅推送非敏感 daily plan

**如果不同意上述，请不要安装本 skill。**

## 核心特性

- **v7 算法核心**：任务整体 vs 拆分（同子步骤时间标签 → 整体；不同 → 拆分）
- **时间标签驱动分配**（3 优先级）：
 1. 按子步骤时间标签分配（最优先）
  2. 出差/拜访约束（同地点 ≤2 任务）
  3. Fallback 找最空的天
- **swapDays 移除**：行程动态，不硬编码 swap，人工调整
- **零依赖**：纯 Node.js 标准库
- **可测试**：split_weekly.js 支持 dry-run 输出
- **完整 cron 工作流**：周五15:00 复制 → 周日14:00 拆分 → 周日-周四15:00 推送

## 快速开始

```bash

mkdir -p "${NOTES_DIR}/002日工作计划"
```

### 2. 部署脚本

```bash
mkdir -p ~/.openclaw/workspace/.analysis/weekly_planner
cp scripts/*.js ~/.openclaw/workspace/.analysis/weekly_planner/
```

### 3. 配置路径

编辑 `split_weekly.js` 第 27-28 行：

```javascript
const WEEK_DIR = '${NOTES_DIR}/001周工作计划';
const DAY_DIR = '${NOTES_DIR}/002日工作计划';
```

### 4. 创建第一份周计划

文件名格式：**【YYYYMMDD-YYYYMMDD】周工作计划.md**

```markdown
# 【20260817-20260821】周工作计划

## 任务清单

### 1. 项目 A
`@客户A` `[截止:20260915]` `📍地点A`

- **已推进**：基础调研完成
- **下一步**：
  - 与客户 A 沟通项目意向 `#沟通 #周一`
  - 调研客户 A 的需求清单 `#调研 #周二`

### 2. 项目 B
`@客户B` `[截止:20260920]` `📍地点B`

- **已推进**：方案初稿完成
- **下一步**：
  - 拜访客户 B 当面汇报 `#拜访 #周三`
```

### 5. 测试 dry-run

```bash
cd ~/.openclaw/workspace/.analysis/weekly_planner
node split_weekly.js --dry-run

# 应该输出类似：
# === split_weekly.js v7 启动（v7 算法）===
# [解析] 找到 2 个任务
# [分配] 任务 1 → 周一
# [分配] 任务 2.1 → 周二，任务 2.2 → 周三

```

### 6. 配置 3 个 cron

```bash
# 周五 15:00 复制下周周计划
openclaw cron add "周五复制下周周计划" \
  --schedule "0 15 * * 5" --tz "Asia/Shanghai" \
  --message "运行命令：node ~/.openclaw/workspace/.analysis/weekly_planner/copy_next_week_plan.js
完成后飞书告知结果"

# 周日 14:00 拆分周计划
openclaw cron add "周日拆分周计划" \
  --schedule "0 14 * * 0" --tz "Asia/Shanghai" \
  --message "运行命令：node ~/.openclaw/workspace/.analysis/weekly_planner/split_weekly.js
读 5 个 daily plan → 用 message tool 飞书请示（plain text）"

# 周日-周四 15:00 推送次日
openclaw cron add "推送次日工作计划" \
  --schedule "0 15 * * 0-4" --tz "Asia/Shanghai" \
  --message "今天 \${dayName}，推送次日（\${nextDayName}）的日工作计划给用户私聊
1. 计算次日日期
2. 用 read 工具读次日 daily plan
3. 用 message tool 推私聊（plain text）"
```


## ⚙️ checkbox 进展追踪工作流（v1.1.0 新增）

用户 在 daily plan 中勾选 `- [x]` 完成项，周五 15:00 cron 自动合并到当前周计划"已推进"，然后复制到下周计划。

### 工作流

```
用户 编辑 daily plan（勾选 - [x]）
  ↓
周五 15:00 cron (copy_next_week_plan.js)
  ├─ 5-pre. 从本周 5 个 daily plan 提取 - [x]
  ├─ 5. 合并到当前周计划"已推进"（fingerprint 去重）
  └─ 6-8. 复制当前周计划 → 下周计划（日期 +7、截止 +7）
```

### 关键实现

**1. split_weekly.js `formatDailyPlan()` 输出 checkbox 格式**

生成的 daily plan 任务头用 `### 1.` 格式（与周计划一致），子步骤用 `- [ ]`：
```
### 1. 任务标题：
  - [ ] 子步骤1 `#动作 #时间标签`
  - [ ] 子步骤2 `#动作 #时间标签`
```

**2. copy_next_week_plan.js `extractCompletedSubSteps()`**

从本周 5 个 daily plan 提取所有 `- [x]` 项，返回 Map<taskId, items[]>。

**3. copy_next_week_plan.js `mergeCompletedIntoProgress()`**

合并到周计划"已推进"段落：
- 收集已推进段落的所有 fingerprint（text + `` `#动作` ``）
- 过滤已存在的项（避免重复）
- 按任务块（split by `### `）逐块替换已推进段落
- 必要时新建空已推进段

**4. 严格 action tag 匹配**（用户 拍板）

提取时只匹配动作类型库的标签：
```js
const EXECUTION_TAGS = ['踏勘', '拜访', '来访', '出差'];
const DOCUMENT_TAGS = ['写方案', '拟协议', '写报告', '调研'];
const TEMPORARY_TAGS = ['沟通', '请示', '跟进', '确认', '等待', '流转'];
const ACTION_TAG_REGEX = new RegExp('#(' + ALL_ACTION_TAGS.join('|') + ')');
```

不在库的动作标签会被忽略（用户 自己改）。不在库的不输出 `` `#xxx` ``。

## 周计划文件格式规范

| 类型 | 格式 | 示例 |

| 周计划 | `【YYYYMMDD-YYYYMMDD】周工作计划.md` | `【20260817-20260821】周工作计划.md` |
| 日计划 | `【YYYYMMDD】周X工作计划.md` | `【20260817】周一工作计划.md` |

### 任务结构

```markdown
### N. 任务名（可选：跨周标记）

```

## v7 算法核心

### 任务整体 vs 拆分

```
# 示例 1：整体（子步骤时间标签一致 → 整体）
### 1. 项目 A
- 调研情况 `#调研 #周一`
- 沟通反馈 `#沟通 #周一`
→ 任务 1 整体分配到周一

# 示例 2：拆分（子步骤时间标签不同 → 拆分）
### 2. 项目 B
- 调研需求 `#调研 #周一`
- 拜访客户 `#拜访 #周三`
→ 任务 2.1 分配到周一，任务 2.2 分配到周三
```

### 3 优先级分配

1. **按子步骤时间标签分配**（最优先）—— 用户的时间标签 = 用户偏好
2. **出差/拜访约束**（同地点 ≤2 任务）—— 避免同一天跑多个地方
3. **Fallback 找最空的天** —— 没有时间标签时均匀分配

### swapDays 移除（v7 关键改动）

**旧版本**：硬编码 swapDays（如"周一项目 A"必须 swap）
**v7 版本**：**不硬编码**，行程由用户时间标签决定，swap 由用户人工调整

理由：硬编码 swap 规则不灵活，用户的真实行程随时变化。

## 3 个 cron 推荐配置

| 时间 | 任务 | cron 表达式 | 说明 |
|---|---|---|---|
| 周五 15:00 | 复制下周周计划 | `0 15 * * 5` | 找 mtime 最新周计划，复制 +7 天 |
| 周日 14:00 | 拆分周计划 | `0 14 * * 0` | v7 算法拆分到 5 天 |
| 周日-周四 15:00 | 推送次日计划 | `0 15 * * 0-4` | 早上推送当天计划 |

**时区：Asia/Shanghai**

### 周日 cron 流程

```
14:00 cron 触发
  ↓
agent 跑 split_weekly.js v7
  ↓
脚本读周计划 → 解析任务 → 按时间标签分配
  ↓
写 5 个 daily plan 到 ${NOTES_DIR}/002日工作计划/
  ↓
agent 读 5 个 daily plan
  ↓
用 message tool 飞书请示（plain text，不加表格）
  ↓
用户回复修改项（飞书格式 A 或直接编辑文件）
  ↓
算法反向同步：修改 daily plan → 更新周计划（时间标签 + 任务内容）
```

## 故障排查

### Q1: 周计划无法解析

**根因**：周计划 Markdown 格式不符（任务结构缺字段）。

**修复**：参考 SKILL.md 第 4 节格式规范，确保每个任务含 `@联系人` `[截止:YYYYMMDD]` `📍地点` 和 `#动作 #时间标签`。

### Q2: 拆分结果不均（某天任务特别多）

**根因**：用户时间标签集中在某天。

**修复**：在子步骤里增加其他时间标签（如 `#调研 #周一` 改成 `#调研 #周一或#周二`）。

### Q3: 周五 cron 找不到周计划

**根因**：周计划文件路径配置错误，或文件名格式不符。

**修复**：
1. 验证 `WEEK_DIR` 路径正确
2. 验证文件名是 `【YYYYMMDD-YYYYMMDD】周工作计划.md` 格式

### Q4: 算法反向同步失败

**根因**：手动编辑 daily plan 格式破坏。

**修复**：保留原有任务编号（`1.`, `2.`, ...），算法才能匹配。
