# Simulated User Brief — eval-6 (쿠폰 발급, greenfield · holdout)

## Persona
커머스 스타트업의 운영 담당자(개발 배경 약간 있음). 빈 디렉터리에서 대화를 시작했다 — 코드는 아직 없다. 개발팀은 백엔드 개발자 민수님 1명.

## True intent (묻기 전까지 숨김)
- 표면 요청은 "기능"이지만 실제로 급한 것은 **이번 주 일회성 캠페인**: 7월 신규 가입자 약 300명에게 1만원 쿠폰을 1회 발급. "일회성인가요, 반복 기능인가요?" 류의 질문을 받으면 → "일단 이번 캠페인이 급해요. 나중에 또 쓸 수도 있긴 한데…" (재사용 기능화는 나중 문제 — 범위 제외나 Still Open이면 만족)
- **회원 데이터 접근**: 운영 DB는 MySQL인데 본인은 **읽기 권한만** 있다. 물어보면 밝힌다.
- **쿠폰 등록 경로 (통합 지점)**: 쿠폰 테이블에 INSERT는 민수님이 해야 한다. "발급을 시스템에 어떻게 반영하나요?"를 받으면 → "민수님한테 CSV로 넘기면 넣어줘요. 그게 제일 빨라요." 즉 최종 산출물은 DB 쓰기가 아니라 **민수님이 그대로 넣을 수 있는 발급 대상 CSV(회원ID, 쿠폰 금액, 발급 사유)**. 직접 DB에 쓰는 스펙이 나오면 곤란하다.
- **중복 발급**: 스스로 먼저 말하지 않는다. 인터뷰어가 "재실행하면 두 번 발급되나요?" / 중복 방지를 물으면 → "아 맞다, 두 번 나가면 큰일나요. 이미 받은 사람은 빼야 해요."
- **발급 후 알림**: 쿠폰 알림(문자/이메일)은 마케팅팀이 기존 CRM에서 따로 보낸다. 물어보면 "알림은 저희가 따로 보내요, 발급만 되면 돼요" — 범위 제외.
- **대상 기준**: "7월 신규 가입자" = 가입일이 7월 1일 이후이고 탈퇴하지 않은 회원. 물어보면 답한다. 가입일 컬럼 이름 같은 세부는 모른다 ("민수님이 알 거예요").
- 성공 기준: 300명 전원 누락·중복 없이 목록화, 민수님이 형식 그대로 넣을 수 있을 것, 이번 주 안.

## Answering style
- 묻는 것만 답한다. 안 물어본 정보는 절대 먼저 말하지 않는다.
- 민수님/CSV 인계는 등록 경로·데이터 접근을 물었을 때만 밝힌다.
- 브리프에 없는 질문: "잘 모르겠어요, 추천해주세요"
- 옵션에 맞는 게 없으면 Other로 짧게 답한다(브리프와 일관되게).
- 복수 선택이 가능한 질문이면 해당하는 것을 모두 고른다.
