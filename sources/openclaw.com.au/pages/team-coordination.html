🤝 AI Agent Team Coordination

Build systems where multiple specialized AI agents work together seamlessly. Learn orchestration patterns, delegation strategies, and real-world multi-agent workflows.

Why Multi-Agent Systems?

A single AI agent can be powerful, but a coordinated team of specialized agents can handle complex, ongoing operations that would overwhelm any individual—human or AI.

🎯

Specialization

Each agent masters one domain instead of being average at everything

⚡

Parallelization

Multiple agents work simultaneously on different tasks

🔄

Continuous Operation

24/7 workflows without human bottlenecks

📈

Scalability

Add new agents as your operation grows

🏗️ Team Structure Patterns

Pattern 1: Chief of Staff + Specialists

Best for: Solo businesses, agencies, complex personal automation

Team Hierarchy 
Ana (Chief of Staff) — Coordination & Strategy
├── Content Writer — Blog posts, SEO content
├── SEO Specialist — Audits, rankings, technical
├── Client Manager — Communications, reporting
├── Lead Generator — Outreach, qualification
└── Data Analyst — Metrics, insights, alerts

How it works:

  • Chief of Staff (main agent) delegates tasks to specialists via sessions_spawn
  • Specialists complete work in isolated sessions
  • Results automatically announce back to the coordinator
  • Human reviews and approves before external action
Delegation Example 
// Ana delegates to Content Writer
sessions_spawn({
  agentId: "content-writer",
  task: "Write 1500-word SEO blog post about 'AI automation for small business'. Target keyword: 'AI business automation'. Include practical examples.",
  cleanup: "keep"
})

// Content Writer completes work
// Result announces back to Ana's session
// Ana reviews, edits if needed, publishes

Pattern 2: Peer Network

Best for: Research teams, content production, distributed monitoring

Agents work independently on parallel tasks, coordinating via shared memory files:

Peer Coordination 
// Each agent checks shared task queue
const taskQueue = JSON.parse(fs.readFileSync('memory/task-queue.json'))
const myTask = taskQueue.find(t => t.assignee === 'agent-name')

// Agent completes task
// Updates shared state
taskQueue.myTask.status = 'complete'
fs.writeFileSync('memory/task-queue.json', JSON.stringify(taskQueue))

Use cases:

  • Content pipeline: Writer → Editor → Publisher
  • Research: Gatherer → Analyzer → Reporter
  • Monitoring: Site Health → Rankings → Competitors

Pattern 3: Assembly Line

Best for: Sequential workflows with clear handoffs

Content Assembly Line 
Stage 1: Research Agent
→ Finds topic opportunities
→ Saves brief to content/briefs/

Stage 2: Writing Agent (triggered when brief appears)
→ Writes draft from brief
→ Saves to content/drafts/

Stage 3: SEO Agent
→ Validates SEO elements
→ Saves to content/ready/

Stage 4: Publishing Agent
→ Publishes to WordPress
→ Logs in content/published/

Each stage triggers the next via cron jobs that check for new files in the handoff folder.

🎯 Coordination Techniques

1. Shared Memory Files

Agents coordinate via JSON state files in the workspace:

memory/team-state.json 
{
  "contentWriter": {
    "status": "active",
    "currentTask": "Kwikclamp installation guide",
    "completedToday": 2,
    "queueSize": 5
  },
  "seoSpecialist": {
    "status": "idle",
    "lastAudit": "2026-02-11T08:00:00Z",
    "nextAudit": "2026-02-14T08:00:00Z"
  },
  "clientManager": {
    "status": "active",
    "reportsGenerated": 3,
    "pendingApproval": ["weekly-flooring-guys.html"]
  }
}

2. Task Queue Pattern

Central task queue that agents pull from:

memory/task-queue.json 
[
  {
    "id": "task-001",
    "type": "content",
    "assignedTo": "content-writer",
    "status": "in-progress",
    "priority": "high",
    "details": {
      "client": "Kwikclamp",
      "topic": "AS1657 Compliance",
      "targetWords": 3500,
      "deadline": "2026-02-12"
    }
  },
  {
    "id": "task-002",
    "type": "audit",
    "assignedTo": "seo-specialist",
    "status": "queued",
    "priority": "medium",
    "details": {
      "client": "Hunter Bathrooms",
      "focusArea": "Core Web Vitals"
    }
  }
]

3. Handoff Folders

File-based handoffs between agents:

Content Pipeline Folders 
content/
├── briefs/          ← Research Agent outputs here
├── drafts/          ← Content Writer outputs here
├── ready/           ← SEO Agent validates & moves here
├── published/       ← Publishing Agent archives here
└── rejected/        ← Human sends back for revision

Cron jobs trigger next agent when files appear in their input folder.

4. Sessions Communication

Direct agent-to-agent messaging via sessions_send:

Agent Communication 
// SEO Specialist notifies Content Writer
sessions_send({
  label: "content-writer",
  message: "Found high-priority keyword opportunity: 'galvanised handrail fittings Brisbane' - low competition, 720 monthly searches. Add to Kwikclamp queue."
})

// Content Writer acknowledges
sessions_send({
  label: "seo-specialist",
  message: "Added to queue. Will write this week. Thanks for the intel!"
})

🛠️ Building Your AI Team

Step 1: Define Roles

Identify specialized functions in your operation:

  • What tasks require deep expertise?
  • What work happens in parallel?
  • What needs 24/7 monitoring?
  • What requires human review vs autonomy?

Step 2: Create Agent Personas

For each specialist, create:

  • SOUL.md - Defines personality, standards, process
  • IDENTITY.md - Role, responsibilities, boundaries
  • TOOLS.md - Specific tools and credentials for this agent
  • memory/ - Agent-specific memory folder
Example: Content Writer Directory 
workspace/agents/content-writer/
├── SOUL.md           ← Writing philosophy & standards
├── IDENTITY.md       ← Role definition
├── TOOLS.md          ← WordPress access, style guides
├── MEMORY.md         ← Topics covered, client preferences
└── memory/
    └── content-log.json  ← Published pieces tracker

Step 3: Set Up Coordination

Choose your coordination pattern:

  • Centralized: Chief of Staff delegates via sessions_spawn
  • Distributed: Shared task queue + cron jobs
  • Hybrid: Chief coordinates strategy, agents handle execution

Step 4: Start Small, Scale Up

  1. Launch with 1 coordinator + 1 specialist
  2. Perfect their handoff over 1 week
  3. Add 2nd specialist once workflow is smooth
  4. Document patterns that work
  5. Expand to full team

✨ Team Coordination Best Practices

✅ Clear Boundaries

Each agent has a well-defined scope. Overlapping responsibilities create confusion.

✅ Explicit Handoffs

Don't assume agents will figure out who does what. Document handoff points clearly.

✅ Shared Context

All agents read core files: USER.md, memory/YYYY-MM-DD.md for continuity.

✅ Human Review Gates

Before external actions (emails, posts, purchases), require human approval.

✅ Progress Tracking

Agents log their work. Coordinator summarizes daily. Human stays informed without micromanaging.

✅ Error Recovery

When agents fail, they log the issue and notify coordinator. Don't fail silently.

❌ Avoid: Too Many Agents Too Soon

Start with 2-3 agents max. Add more only when current team runs smoothly.

❌ Avoid: Circular Dependencies

Agent A waiting for B, B waiting for C, C waiting for A = deadlock. Map dependencies before building.

🔥 Advanced Patterns

Dynamic Agent Spawning

Coordinator creates specialists on-demand based on workload:

Adaptive Team Size 
// Check content queue size
const queue = JSON.parse(fs.readFileSync('memory/content-queue.json'))

if (queue.length > 10) {
  // Heavy load: spawn 3 content writers
  for (let i = 0; i < 3; i++) {
    sessions_spawn({
      agentId: "content-writer",
      task: `Write article: ${queue[i].topic}`,
      cleanup: "delete"  // Clean up when done
    })
  }
} else if (queue.length > 0) {
  // Light load: spawn 1 writer
  sessions_spawn({
    agentId: "content-writer",
    task: `Write article: ${queue[0].topic}`,
    cleanup: "delete"
  })
}

Agent Collaboration

Multiple agents working on the same deliverable:

Collaborative Report Generation 
// Coordinator spawns 3 agents in parallel
sessions_spawn({ agentId: "data-analyst", task: "Analyze traffic trends for client report" })
sessions_spawn({ agentId: "seo-specialist", task: "Analyze ranking changes for client report" })
sessions_spawn({ agentId: "content-writer", task: "Summarize published content for client report" })

// Each agent saves their section to reports/sections/
// When all 3 announce completion, Coordinator compiles final report

Self-Improving Teams

Agents analyze their own performance and suggest improvements:

Weekly Team Retrospective 
// Cron job: Every Monday 9am
{
  "schedule": { "kind": "cron", "expr": "0 9 * * 1" },
  "sessionTarget": "isolated",
  "payload": {
    "kind": "agentTurn",
    "message": "Review last week's agent performance. Read memory/team-metrics.json. Identify bottlenecks, errors, inefficiencies. Suggest process improvements. Update AGENTS.md with lessons learned."
  }
}

🔧 Troubleshooting Multi-Agent Systems

Problem: Agents duplicating work

Solution: Implement task claiming in shared queue:

// Before starting work, claim the task
const queue = JSON.parse(fs.readFileSync('memory/task-queue.json'))
const myTask = queue.find(t => t.status === 'queued')
myTask.status = 'in-progress'
myTask.claimedBy = 'agent-name'
myTask.claimedAt = new Date().toISOString()
fs.writeFileSync('memory/task-queue.json', JSON.stringify(queue))

Problem: Lost context between handoffs

Solution: Include full context in handoff files, not just results.

Problem: Agents waiting indefinitely

Solution: Set timeouts and fallback behaviors:

// Run timeout is set globally in config, not per call:
//   agents.defaults.subagents.runTimeoutSeconds: 1800   // 30 min max
sessions_spawn({
  agentId: "content-writer",
  task: "Write blog post...",
  cleanup: "keep"  // Keep session for debugging if it fails
})

Problem: Too much coordination overhead

Solution: Batch related tasks instead of spawning for every tiny job.
