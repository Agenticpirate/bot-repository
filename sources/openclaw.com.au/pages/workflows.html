🔄 Automation Workflows

Proven AI Agent Patterns

Real-world automation workflows and recipes for OpenClaw. From simple scheduled tasks to complex multi-agent systems.

🎯 What Are Workflows?

A workflow is a repeatable pattern for automating tasks with OpenClaw. Think of them as recipes: proven combinations of cron jobs, tools, skills, and memory strategies that solve specific problems.

This guide covers real workflows being used in production by OpenClaw users — from autonomous content publishing to client monitoring systems.

📝 Content Creation Workflows

🤖 Autonomous Blog Publishing

Goal: Research, write, and publish blog posts without human intervention

Daily Content Job (2pm) 
{
  "schedule": { "kind": "cron", "expr": "0 14 * * *", "tz": "Australia/Brisbane" },
  "sessionTarget": "isolated",
  "payload": {
    "kind": "agentTurn",
    "message": "Research trending topic in [niche]. Write 1500-word SEO blog post. Publish to WordPress. Update content tracker."
  },
  "delivery": { "mode": "announce", "channel": "telegram" }
}

Tools needed:

  • Web search for research
  • WordPress REST API skill
  • Memory files to track published topics
  • Internal content tracker tool

Pro tips:

  • Store published topics in memory/content-published.json to avoid duplicates
  • Use competitor analysis for content gaps
  • Schedule follow-up jobs to add internal links to new posts

📊 SEO Content Pipeline

Goal: Move content from draft → review → published with quality checks

Workflow stages:

  1. Draft generation: Agent creates content, saves to content/drafts/
  2. SEO validation: Automated checks (keyword density, headings, meta tags)
  3. Approval queue: Human reviews in Kanban tool on port 8125
  4. Publication: One-click publish after approval
Quality Check Before Publishing 
// In content-qa tool (port 8129)
- Minimum 1500 words
- Target keyword in H1, first paragraph, conclusion
- 2-4 H2 sections
- Meta description 150-160 chars
- Alt text on all images
- Internal links to 3+ related posts
- External links to 2+ authority sources

📈 Business Monitoring Workflows

🚨 Client Health Monitoring

Goal: Detect issues before clients notice them

Multi-Check Health Job (Every 6 hours) 
{
  "schedule": { "kind": "every", "everyMs": 21600000 },
  "sessionTarget": "isolated",
  "payload": {
    "kind": "agentTurn",
    "message": "Check all 5 clients: uptime, SSL certs, Core Web Vitals, ranking changes. Alert if any issues."
  }
}

What gets checked:

  • Site uptime & response time (Site Health Monitor - port 8118)
  • SSL certificate expiration
  • Core Web Vitals (Speed Audit - port 8096)
  • Keyword ranking changes (Rank Alerts - port 8120)
  • Broken links & 404s
  • Google Search Console errors

Alert thresholds:

  • 🔴 Critical: Site down, SSL expired, Top 3 keyword dropped to page 2+
  • 🟠 Warning: Response time >3s, CWV fail, Top 10 keyword dropped 5+ positions
  • 🟡 Info: Minor ranking fluctuations, new GSC warnings

💰 Revenue Protection System

Goal: Protect monthly recurring revenue by catching churn signals early

Weekly Client Risk Assessment 
// MRR Dashboard (port 8131) + Client Rescue (port 8132)
Check weekly:
- Last contact date (>14 days = risk)
- Deliverables sent vs approved
- Support response time
- Result metrics (traffic, leads, rankings)
- Invoice payment status

Intervention triggers:

  • No contact in 2+ weeks → Schedule check-in call
  • Deliverables pending approval >7 days → Send reminder
  • Traffic down 20%+ → Proactive investigation + fix
  • Invoice overdue → Automated follow-up sequence

🚀 Lead Generation Automation

Goal: Find qualified leads and send personalized outreach automatically

Lead Finder + Outreach (3x per week) 
// Tuesday, Thursday, Saturday at 10am
1. Find 10 Brisbane businesses needing SEO (Local Lead Finder - port 8162)
2. Analyze their site for issues (SEO Opportunity Finder - port 8146)
3. Generate personalized outreach email (Outreach Generator - port 8094)
4. Save to Lead Tracker (port 8099) for manual review
5. Optional: Auto-send if confidence score >85%

Qualification criteria:

  • Business in target niche (trades, retail, professional services)
  • Website has obvious SEO issues (missing meta, slow, no schema)
  • Not already working with SEO agency (check footer)
  • Active business (recent updates, working phone number)
  • Local to Brisbane (geo-targeted services)

🤖 Advanced Multi-Agent Workflows

🏗️ Project Swarm Pattern

Goal: Tackle complex projects by spawning specialized sub-agents

Coordinated Multi-Agent Build 
Main Agent (Ana) coordinates:

1. Researcher Agent (isolated)
   → Task: "Research top 10 SEO tools for 2026, compile features + pricing"
   → Runs autonomously, reports back findings

2. Writer Agent (isolated)
   → Task: "Write comparison article based on research findings"
   → Uses research output as context

3. Developer Agent (isolated)
   → Task: "Build interactive comparison table tool"
   → Takes article content, creates filterable table

4. Publisher Agent (isolated)
   → Task: "Publish article + embed tool, optimize for SEO"
   → Final deployment step

Why this works:

  • Each agent has focused task = better output quality
  • Agents run in parallel when possible = faster completion
  • Main agent orchestrates = maintains project coherence
  • Isolated sessions = clean context, no token bloat

⏰ Cron vs Heartbeat vs Isolated Jobs

If you pick the wrong execution pattern, your agent gets noisy, brittle, or both. Here’s the clean operator rule:

💓 Use Heartbeat for flexible check-ins

Heartbeat is best when timing can drift a bit and you want the agent to bundle multiple checks into one run.

Best for: inbox sweeps, calendar checks, weather, lightweight triage, “anything urgent?” scans.

Why: it reuses main-session context and keeps periodic work conversational instead of spawning a fresh job every time.

🕒 Use main-session cron for reminders

Main cron jobs enqueue a system event and wake the normal assistant flow. That makes them perfect for reminders and context-aware nudges.

Best for: “remind me in 20 minutes,” “check this after the meeting,” and scheduled prompts that should land in your normal chat.

Why: the Gateway persists the schedule, survives restarts, and can wake the next heartbeat or fire immediately.

🚀 Use isolated cron for background work

Isolated cron runs a dedicated agent turn in its own cron:<jobId> session with optional announce, webhook, or silent delivery.

Best for: reports, monitoring, recurring research, content generation, and anything noisy enough to clutter your main thread.

Why: you get a fresh run each time, cleaner failure boundaries, and more production-friendly delivery controls.

2026 operator trend: serious agent stacks are moving toward recoverable autonomy — scheduled jobs that are isolated, auditable, and easy to deliver or silence on purpose. That’s exactly why OpenClaw’s cron model is getting stronger while heartbeat stays lightweight and contextual.
Fast decision rule 
If exact timing matters → use cron
If context + batching matter → use heartbeat
If the task is noisy or should run in a fresh lane → use isolated cron
If it’s just a reminder in your normal chat → use main-session cron

🎨 Workflow Design Principles

1. Start Small, Scale Smart

Begin with simple, single-task cron jobs. Add complexity only after proving the basic workflow works.

Example: Start with "check client uptime" before building full health monitoring system.

2. Build Checkpoints

For high-stakes workflows, add human approval steps. Use "Waiting for Approval" Kanban columns.

Example: Don't auto-send client emails until you've reviewed a few batches.

3. Log Everything

Workflows should write to memory files. Track what was done, when, and what the outcome was.

Pattern: memory/workflow-name-YYYY-MM.md for monthly logs.

4. Fail Gracefully

External APIs fail. Networks drop. Design workflows to handle errors and retry intelligently.

Example: If WordPress API fails, save content locally and retry in next run.

5. Batch When Possible

Combine related checks in one cron job to reduce API calls and improve efficiency.

Example: One "morning checks" job > separate jobs for email, calendar, weather.

6. Use Right Tool for Job

Heartbeats: Flexible, batched checks
Cron: Precise timing, isolated tasks
Sub-agents: Complex projects needing coordination

Copy these proven templates and customize for your needs:

Daily Morning Brief

{
  "name": "Morning Brief",
  "schedule": { "kind": "cron", "expr": "0 8 * * *", "tz": "Your/Timezone" },
  "sessionTarget": "isolated",
