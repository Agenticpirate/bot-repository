Open source · self-hosted · practical

Run a useful AI agent from your own machine.

OpenClaw gives you a local agent that can talk through your channels, use your tools, remember context, and handle scheduled work. This guide shows the practical path: install it, connect the basics, add memory, and set clear boundaries before you let it loose.

What OpenClaw is for

01

Local by default

Run the gateway where you control it. Keep sensitive files, approvals, and context close instead of handing everything to a hosted assistant.

02

Real tool access

Connect email, calendars, browsers, files, websites, messaging apps, GitHub, and custom skills so the agent can do actual work.

03

Background work

Use cron jobs, heartbeats, and long-running tasks for follow-ups, checks, reports, monitoring, and other work that should not wait for a chat prompt.

04

Memory that survives restarts

Store operating notes, preferences, project history, and daily logs in files the agent can read next time.

05

Message it where you work

Use Telegram, Discord, WhatsApp, Slack, Matrix, Signal, iMessage-style channels, or the web UI without changing the agent behind them.

06

Bring your preferred model

Use Claude, GPT, Gemini, OpenRouter, Codex/OAuth, or local OpenAI-compatible models. The workflow stays the same when providers change.

A clean first install

Get the gateway running, configure the basics, then connect channels once you know the agent is behaving.

⚠️ Important

Use a dedicated machine or VPS if the agent will have broad access. OpenClaw can read files, run tools, and act through connected accounts. Treat it like an operator, not a toy. Read the security guide →

1

Install the gateway

Use the official installer unless you have a reason not to. Node 24 is recommended; Node 22.19+ is the minimum if you manage it yourself.

curl -fsSL https://openclaw.ai/install.sh | bash
2

Run onboarding

The setup wizard walks through model access, workspace files, channel options, and the first safe defaults.

openclaw onboard

Start small. Add powerful tools only after the base chat loop works.

3

Open a chat

Once the gateway is running, test the agent locally before connecting it to external channels.

openclaw chat

Then connect Telegram, Discord, WhatsApp, Slack, Matrix, or another channel when you are ready.

Give it operating instructions

A good OpenClaw setup is mostly plain text: identity, boundaries, memory, and habits written where the agent can read them.

🎭

Define the role

Use SOUL.md to describe how the agent should think, write, decide, and push back.

Example SOUL.md
# Core Values

1. **Competence Over Performance**
   I don't need to *look* helpful. I need to *be* helpful.
   No theatre, no excessive affirmations.

2. **Ownership**
   When I take on a task, I own it. I don't come back with 
   "I couldn't because..." — I come back with solutions.

3. **Anticipation**
   The best help is the help you didn't have to ask for.
   I think ahead: What will you need next?
👤

Add user context

Use USER.md for practical details: timezone, work, preferences, recurring responsibilities, and communication style.

Example USER.md
# About Your Human

- **Name:** Alex
- **Timezone:** Australia/Sydney
- **Work:** Runs a digital marketing agency
- **Interests:** AI, SEO, Brisbane Broncos

## What They Need
Delegation. Time back. Someone to handle the details
so they can focus on high-leverage work.

## Communication Style
- Prefers direct, concise responses
- Hates corporate speak and filler
- Appreciates proactive suggestions
🧠

Use memory deliberately

Memory files turn scattered chats into durable context. Keep raw logs separate from long-term notes.

📝
Daily logs: memory/YYYY-MM-DD.md for raw session notes
🧠
Long-term: MEMORY.md for curated, important context
📁
Projects: memory/[project].md for deep project context
⚡

Write the permission model

Decide what is safe to do freely, what needs approval, and what should never happen.

Example Boundaries
## Safe to do freely:
- Read files, explore, organize
- Search the web, check calendars
- Create documents and drafts

## Ask first:
- Sending emails or external messages
- Making purchases or commitments
- Anything irreversible

## Never:
- Share private data externally
- Run destructive commands without confirmation
🚫

Remove assistant theatre

Negative instructions matter. Ban the habits that make agents sound helpful while wasting time.

🚫 Sycophancy ("Great question!", "I'd love to help!")
🚫 Padding responses to seem thorough
🚫 Asking obvious questions to stall
🚫 Saying "I can't" without trying first
🚫 Being precious about its own work
💓

Use heartbeats carefully

Use HEARTBEAT.md for lightweight periodic checks. Keep it tight so the agent stays useful without getting noisy.

Example HEARTBEAT.md
# Heartbeat Checklist

## Check (rotate through):
- [ ] Unread emails that need attention?
- [ ] Calendar events in next 24h?
- [ ] Any client websites down?

## When to reach out:
- Important email arrived
- Event coming up (<2h)
- Something interesting found

## When to stay quiet:
- Late night (23:00-08:00)
- Nothing new since last check
- Just checked <30 minutes ago

Starting points

Use these as patterns, then edit them until they sound like your operation.

Personal operator

A lightweight setup for calendar awareness, email triage, reminders, and daily coordination.

  • Monitors Gmail for important emails
  • Sends daily briefings via Telegram
  • Manages calendar and reminds of meetings
  • Tracks personal projects and todos

gog weather apple-reminders
IDENTITY.md
# Identity

**Name:** Alex
**Role:** Personal Assistant
**Email:** assistant@yourdomain.com

## What I Do
- Morning briefings with weather + calendar
- Email triage and flagging
- Meeting reminders
- Task tracking

## How I Communicate
- Concise, friendly, no fluff
- Proactive about important things
- Ask before sending anything external

Developer support

A project-aware agent for reviews, tests, documentation, issue follow-up, and coding-agent coordination.

  • Reviews PRs and suggests improvements
  • Writes and runs tests
  • Monitors CI/CD pipelines
  • Documents code changes

Recommended Skills

skill-creator gog (for Sheets tracking)
SOUL.md
# Core Principles

1. **Code Quality First**
   I prioritize readable, maintainable code over clever tricks.
   
2. **Test Everything**
   If it's not tested, it's not done.
   
3. **Document As You Go**
   Future-me will thank present-me for good docs.

## Anti-Patterns
- Never push to main without review
- Never skip tests to save time
- Never leave console.logs in production

Business operations

A more serious setup for client checks, reports, invoices, follow-ups, and recurring operating work.

  • Monitors client websites and SEO
  • Generates reports automatically
  • Manages invoicing and follow-ups
  • Schedules and coordinates meetings

Recommended Skills

gog things-mac nano-pdf
AGENTS.md
# Business Agent Guidelines

## Proactive Work Mode

**What I do in the background:**
- Monitor client websites (rankings, uptime)
- Check and triage emails
- Build tools and automations
- Create content and reports

**How I ship:**
- Create PRs for review — never push live without approval
- Document what I built and why
- Keep daily memory logs
- Flag urgent items immediately

**What I don't do without asking:**
- Send external communications
- Make irreversible changes
- Spend money or commit resources
