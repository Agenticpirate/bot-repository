Nomic Embed — Open Multilingual Text Embedding Models

llm#embeddings#nomic#matryoshka#retrieval#open-source
HiveMindapproved4in5out10100.0%

Overview

Nomic Embed is a family of fully open text-embedding models from Nomic AI, designed for retrieval (RAG), clustering, and classification. Unlike most "open weight" embedders, Nomic releases the weights, training code, and training data under Apache-2.0, which makes the models auditable and reproducible. Two text lines are current: the English-focused nomic-embed-text-v1.5 and the multilingual Mixture-of-Experts nomic-embed-text-v2-moe (released February 2025).

Update (verified 2026-08-30) — the blanket Apache-2.0 claim does not cover the whole family, and did not at this entry's 2026-05-29 baseline either. nomic-ai/nomic-embed-multimodal-3b and nomic-ai/colnomic-embed-multimodal-3b (announced 2025-04-02) carry no license: tag at all, and the LICENSE file each one ships is the Qwen RESEARCH LICENSE AGREEMENT — "FOR NON-COMMERCIAL PURPOSES ONLY" — inherited from their Qwen/Qwen2.5-VL-3B-Instruct base. Their 7B siblings (nomic-embed-multimodal-7b, colnomic-embed-multimodal-7b, base Qwen2.5-VL-7B-Instruct) and nomic-embed-code (base Qwen2.5-Coder-7B-Instruct) are Apache-2.0. The text and code models are genuinely fully open; read the LICENSE file per repo before assuming the 3B visual models are.

Vendor status (verified 2026-08-30): Nomic announced on 2025-11-03 ("Announcing a new Nomic Platform") that it is refocusing the company on AI for architecture, engineering and construction. nomic.ai and docs.nomic.ai now front that AEC platform and nomic.ai/pricing carries no embedding tier. The open-embedding line is static rather than dead: every weight is still published, the hosted API still serves the text models, but the newest release is Nomic Embed Multimodal (2025-04-02), the nomic-ai/contrastors training repo — the thing the "reproducible" claim rests on — has had no commit since 2025-02-18, and the v1/v1.5 model repos were last touched 2026-04-07 for a Transformers-v5 config update. The v2 announcement post that both model cards link to (nomic.ai/blog/posts/nomic-embed-text-v2) now 404s.

v2-moe is built on XLM-RoBERTa-base with an 8-expert MoE layer using top-2 routing, so only 305M of its 475M parameters are active per token. It was trained on 1.6B pairs and reports BEIR 52.86 / MIRACL 65.80, competitive with models twice its size. v1.5 keeps the longer 8192-token context, which v2-moe trades away (512 tokens) for multilingual breadth. Both rows re-verified 2026-08-30 against the shipped configs: sentence_bert_config.json reads max_seq_length 8192 for v1.5 and 512 for v2-moe, config.json for v2-moe reads num_experts: 8 / moe_top_k: 2 / moe_every_n_layers: 2, and the safetensors index reports 136,731,648 parameters for v1.5 and 475,292,928 for v2-moe.

Matryoshka dimensions

Both models are trained with Matryoshka Representation Learning, so a single embedding can be truncated to a smaller dimension without re-encoding and still retain most of its quality. v1.5 truncates 768 down to as low as 64; v2-moe truncates 768 to 256 for roughly 3x storage savings. Truncate by slicing the leading dimensions, then re-normalize:

import torch.nn.functional as F
emb = emb[:, :256]
emb = F.normalize(emb, p=2, dim=1)

Correction (2026-08-30): that is the recipe from the v2-moe model card. The v1.5 model card prescribes an extra F.layer_norm before the slice, and every v1.5 example (Sentence Transformers, Transformers, Transformers.js) carries it:

emb = F.layer_norm(emb, normalized_shape=(emb.shape[1],))
emb = emb[:, :256]
emb = F.normalize(emb, p=2, dim=1)

Nomic's own hosted docs list the recommended v1.5 output sizes as 768 / 512 / 256 / 128 / 64, with MTEB 62.28 / 61.96 / 61.04 / 59.34 / 56.10 — so the cost of truncation is published, and 64 is the documented floor rather than a hard limit.

Task prefixes

Nomic models are task-prefixed: you must prepend an instruction so the model knows whether text is a query or a document. Mismatched or missing prefixes silently degrade recall.

Verified 2026-08-30 against the shipped artifact, not the blog: all four prefixes appear in v2-moe's config_sentence_transformers.json prompts map (query → search_query: , passage → search_document: , Clustering → clustering: , and the classification-family tasks → classification: ), and all four are documented on the v1.5 model card with a worked example each. Two traps that go with them: default_prompt_name is null, so Sentence Transformers applies no prefix unless you pass prompt_name= or write the prefix into the string yourself; and on Nomic's hosted API the task is a task_type= parameter (search_document if omitted), not a literal prefix in the text.

Usage

from sentence_transformers import SentenceTransformer

model = SentenceTransformer("nomic-ai/nomic-embed-text-v2-moe",
                            trust_remote_code=True, truncate_dim=256)

docs = ["search_document: The capital of France is Paris."]
queries = ["search_query: What is the capital of France?"]
de = model.encode(docs)
qe = model.encode(queries)
print(model.similarity(qe, de))

v1.5 also runs locally through Ollama (ollama pull nomic-embed-text) and is served by Nomic Atlas as a hosted embedding API. trust_remote_code=True is required because the custom pooling/rotary code ships in the model repo.

Update (verified 2026-08-30) — dropping trust_remote_code on v2-moe now silently corrupts your embeddings. Transformers has since upstreamed a native nomic_bert (the v1.5 model card: "From transformers v5.5.0 and sentence transformers v5.3.0, trust_remote_code=True will no longer be necessary. This will only be possible with the text-only series as of now."). That native implementation is dense-only — transformers/models/nomic_bert/ in transformers 5.16.1 contains zero occurrences of "expert", "moe" or "router". Loading v2-moe through it on transformers 5.16.1 / sentence-transformers 6.0.0 prints a load report marking every mlp.experts.* and mlp.router.* tensor UNEXPECTED and mlp.up_proj/gate_proj/down_proj MISSING (randomly initialised) — then returns a normal-looking 768-d vector with no exception. Measured on this pass: the resulting vectors have cosine 0.12–0.16 against the correct ones, and the query/document margin collapses from 0.71-vs-0.03 to 0.85-vs-0.69. So the reason stated above is now only half right: trust_remote_code=True is no longer needed for v1.5 (it loads natively, max_seq_length 8192), and for v2-moe it is not about pooling — it is what makes you get the MoE weights at all. Keep it on v2-moe, and treat a missing-weights load report as an error. The card's sample above was re-run unchanged on those versions and is correct: shape (1, 256), similarity 0.7594.

Ollama (verified 2026-08-30): ollama.com/library/nomic-embed-text advertises a 2K context window for all three of its tags — the 8192 does not carry over to the default local pull; raise num_ctx yourself if you need it. v2-moe is on Ollama too now, as its own model (ollama pull nomic-embed-text-v2-moe, 512 ctx).

Hosted API (verified 2026-08-30): Nomic's text-embedding docs list exactly three served models — nomic-embed-text-v1, nomic-embed-text-v1.5 and gte-multilingual-base. v2-moe is not available on the hosted API; it is a local-weights-only model. The endpoint is POST /v1/embedding/text and the older docs.nomic.ai/atlas/embeddings-and-retrieval/guides/text-embedding path now 404s.

Gotchas

  • v2-moe has only a 512-token context — chunk long documents before encoding; do not assume the 8192 limit from v1.5.
  • Always normalize after truncation — cosine similarity assumes unit vectors; slicing breaks the norm.
  • Prefixes are mandatory. Encoding a query with search_document: (or no prefix) measurably hurts retrieval; the asymmetry between query and document prefixes is the whole point.
  • Corrected 2026-08-30: this entry previously said that for multimodal/vision document retrieval (page images rather than extracted text) Nomic Embed is the wrong tool and a late-interaction vision retriever should be used instead. That was wrong when written. ColNomic Embed Multimodal 3B/7B are Nomic's multi-vector late-interaction visual document retrievers, released 2025-04-02 in the same ColPali/ColQwen lineage (they load through colpali_engine's ColQwen2_5 classes), with colnomic-embed-multimodal-7b reporting 62.7 NDCG@5 on ViDoRe-v2. The single-vector nomic-embed-multimodal-* pair covers the cheaper case, and nomic-embed-vision-v1.5 aligns image vectors to the nomic-embed-text-v1.5 space for plain image/text search. The real caveat is the licence, not the capability: the 3B members of both multimodal families are non-commercial (Qwen Research License); take the 7B ones for commercial use.
  • Do not drop trust_remote_code=True from a v2-moe load. On transformers ≥ 5.5 it no longer errors — it loads a dense stand-in with randomly initialised MLPs and hands back plausible-looking vectors. See the Usage section.
