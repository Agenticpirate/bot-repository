PostgreSQL Logical Replication: Publications, Subscriptions, Conflicts, and What Changed in PG 18

Overview

Logical replication streams row-level changes from a publisher to a subscriber using a publish/subscribe model: the publisher declares PUBLICATIONs, the subscriber declares a SUBSCRIPTION, and the publisher's WAL sender decodes committed transactions via the pgoutput plugin and ships them to the subscriber's apply worker, which executes equivalent DML. Unlike physical (streaming) replication, it operates at the logical level — replicating individual tables (not byte-for-byte blocks), across major versions, across architectures (x86 ↔ ARM), across OSes, and into a writable target. The tradeoff is that DDL, sequences, large objects, views, materialized views, and foreign tables are NOT replicated (docs.logical-replication-restrictions).

PostgreSQL 18 (GA 2025-09-25) is the first major release to (a) replicate generated columns, (b) default CREATE SUBSCRIPTION streaming to parallel, and (c) expose per-conflict counters in pg_stat_subscription_stats. For diagnosing subscriber apply lag see postgresql-pg-stat-statements (query-level timing) and postgresql-vacuum-mvcc-and-autovacuum (dead-tuple pressure on subscribers).

Architecture

  PUBLISHER                                SUBSCRIBER
  ┌────────────────────┐                   ┌──────────────────────────┐
  │ backends write WAL │                   │  apply worker (leader)   │
  │         │          │   logical repl    │         │                │
  │         ▼          │   protocol v4     │         ├── parallel     │
  │ walsender + pgoutput├──────────────────►│         │   apply        │
  │  (logical decoding) │    stream changes│         │   workers      │
  │         │          │                   │         │                │
  │ replication slot    │                   │  table sync workers      │
  │  (retains WAL)     │                   │  (initial COPY, per-rel) │
  └────────────────────┘                   └──────────────────────────┘

Four PostgreSQL 18 worker types on the subscriber (visible as worker_type in pg_stat_subscription): apply (leader), parallel apply (PG18 default when streaming=parallel), table synchronization (one per relation during initial COPY, auto-exits), and a slot-sync worker when failover=true (docs.monitoring-pg-stat-subscription).

Publisher-side Prerequisites

# postgresql.conf on publisher
wal_level              = logical   # required; restart needed
max_wal_senders        = 10        # one per subscriber + physical standbys
max_replication_slots  = 10        # one per subscription
max_slot_wal_keep_size = -1        # unbounded; protect against slot WAL-bloat
track_commit_timestamp = on        # required to detect update_origin_differs / delete_origin_differs

A replication slot on the publisher pins WAL until every change before the slot's confirmed_flush_lsn has been acknowledged. A disconnected or lagging subscriber therefore grows pg_wal without bound — max_slot_wal_keep_size caps the retained WAL (slot becomes invalidated past the cap, requiring re-initialization).

Publications (what to replicate)

CREATE PUBLICATION orders_pub
  FOR TABLE public.orders (id, user_id, total, status) WHERE (status <> 'draft'),
      public.order_items
  WITH (publish = 'insert, update, delete, truncate',
        publish_via_partition_root = false,
        publish_generated_columns = 'stored');

ParameterValuesDefaultNotes

publishinsert, update, delete, truncate (CSV)all fourDoes not affect initial COPY
publish_via_partition_rootboolfalsetrue publishes using root-table identity; direct partition TRUNCATEs NOT replicated
publish_generated_columnsnone \storednonePG18 new; subscriber must be PG18+ for initial sync of generated cols

Three scoping forms:

CREATE PUBLICATION p FOR TABLE a, b;                          -- explicit
CREATE PUBLICATION p FOR ALL TABLES;                          -- superuser only; includes future tables
CREATE PUBLICATION p FOR TABLES IN SCHEMA sales, marketing;   -- superuser only; no column lists allowed

Row filters (WHERE (expr)) reduce rows:

  • Must use only columns covered by REPLICA IDENTITY for UPDATE/DELETE.
  • No user-defined functions, no non-immutable built-ins.
  • TRUNCATE ignores row filters.
  • Old-row and new-row evaluation asymmetry: UPDATEs are transformed to INSERT/DELETE when the row moves between "matches filter" and "doesn't match filter".

Column lists ((col1, col2, ...)):

  • Must include every REPLICA IDENTITY column for UPDATE/DELETE to succeed.
  • Cannot be combined with FOR TABLES IN SCHEMA.
  • Generated columns in REPLICA IDENTITY must be explicitly included.

REPLICA IDENTITY — the row-identification rule

UPDATE and DELETE require a way to find the row on the subscriber:

SettingHow the old row is identifiedWhen to use

DEFAULTPrimary key columnsNormal case; requires PK
USING INDEX idxUnique non-partial non-deferrable NOT NULL indexNo PK but a suitable unique index
FULLEvery column of the old rowNo PK/unique index; O(n) index scan per row, slow
NOTHINGNone — UPDATE/DELETE will failInsert-only tables

REPLICA IDENTITY FULL does NOT work when any column's datatype has no default B-tree or Hash operator class (e.g., point, box, xml, json) — UPDATE/DELETE will fail on the subscriber with cannot update table "...": it has no replica identity and publishes updates.

ALTER TABLE events REPLICA IDENTITY USING INDEX events_uuid_key;
ALTER TABLE audit  REPLICA IDENTITY FULL;

Subscriptions (how to receive)

CREATE SUBSCRIPTION orders_sub
  CONNECTION 'host=pub.internal port=5432 dbname=shop user=repl password=...'
  PUBLICATION orders_pub
  WITH (copy_data         = true,
        streaming         = parallel,   -- PG18 default (was off in PG17)
        binary            = true,
        two_phase         = false,
        synchronous_commit = off,
        disable_on_error  = true,
        origin            = any,
        failover          = true,
        run_as_owner      = false);

ParameterDefault (PG18)Effect

connecttrueIf false, forces create_slot=false, enabled=false, copy_data=false (manual slot setup)
create_slottrueCreate the replication slot on the publisher at subscription creation
enabledtrueBegin replicating immediately
slot_namesubscription namePublisher-side slot name; set to NONE to skip
copy_datatrueInitial COPY of all rows before streaming changes
streamingparallel (PG18 changed from off)off = buffer full xact before apply; on = stream to temp file; parallel = apply in parallel workers
synchronous_commitoffPer-subscription override of the subscriber's synchronous_commit
binaryfalseBinary protocol; ~30-50% less network but requires same endianness/type layouts
two_phasefalseReplicate PREPARE TRANSACTION immediately (else wait for COMMIT PREPARED)
disable_on_errorfalseDisable subscription on apply error instead of retrying forever
password_requiredtrueSuperusers can set false; else the connection string must supply a password
run_as_ownerfalseApply as each row's table owner (safer RLS/privilege model)
originanynone = ignore changes whose origin isn't empty (breaks bidirectional loops)
failoverfalseSync the publisher-side slot to physical standbys so a standby promotion doesn't lose the slot

Conflict Types and pg_stat_subscription_stats (PG18)

Seven conflict types, seven counter columns in pg_stat_subscription_stats:

Conflict typeTriggerOutcomeCounter column

insert_existsINSERT violates a NOT DEFERRABLE unique constraintERROR — apply blocksconfl_insert_exists
update_origin_differsUPDATE target row last modified by a different originUPDATE still appliedconfl_update_origin_differs
update_existsUPDATE's new value violates unique constraint (or moves to a new partition that then hits insert_exists)ERROR — apply blocksconfl_update_exists
update_missingUPDATE target row not foundsilently skippedconfl_update_missing
delete_origin_differsDELETE target last modified by a different originDELETE still appliedconfl_delete_origin_differs
delete_missingDELETE target row not foundsilently skippedconfl_delete_missing
multiple_unique_conflictsINSERT/UPDATE violates multiple unique constraintsERROR — apply blocksconfl_multiple_unique_conflicts

Origin-differs conflicts (update_origin_differs, delete_origin_differs) are ONLY detected when track_commit_timestamp = on on the subscriber. Without it, those two conflict types never increment and origin information is not logged.

Full PG18 view shape:

SELECT subname,
       apply_error_count, sync_error_count,
       confl_insert_exists, confl_update_origin_differs,
       confl_update_exists, confl_update_missing,
       confl_delete_origin_differs, confl_delete_missing,
       confl_multiple_unique_conflicts,
       stats_reset
  FROM pg_stat_subscription_stats;

Apply-blocking conflict resolution — when apply halts on insert_exists / update_exists / multiple_unique_conflicts, the server logs:

ERROR:  conflict detected on relation "public.orders": conflict=insert_exists
DETAIL: Key (id)=(42) already exists in unique index "orders_pkey".
        remote row: (id=42, ...); existing local row: (id=42, ...);
        replica identity (id)=(42).
        finished at LSN 0/14C0378

Skip the offending xact:

ALTER SUBSCRIPTION orders_sub SKIP (LSN '0/14C0378');
-- or, for manual rebuild:
ALTER SUBSCRIPTION orders_sub DISABLE;
SELECT pg_replication_origin_advance('pg_16384', '0/14C0500');
ALTER SUBSCRIPTION orders_sub ENABLE;

SKIP discards ALL changes in the transaction at that LSN, not just the conflicting row — this can create subscriber-side drift.

pg_createsubscriber — physical standby → logical subscriber (PG17+, enhanced in PG18)

Converts a physical replica into a logical subscriber WITHOUT an initial COPY — the replica already has the data, the tool just rewrites identity and wires up the subscription:

# stop the physical standby first, then:
pg_createsubscriber \
  -D /var/lib/postgresql/18/data \
  -P "host=primary.internal port=5432 user=repl dbname=postgres" \
  --all \
  --clean=publications \
  --enable-two-phase \
  --recovery-timeout=600

OptionPurposePG version

-a, --allCreate subscriptions for all databases (incompatible with -d)new in PG18
-d NAMEExplicit databases (repeatable)17+
-P connstrPublisher connection string17+
-D PGDATATarget cluster dir17+
--clean=OBJTYPEDrop publications on target after conversionnew in PG18
-T, --enable-two-phaseEnable 2PC for created subsnew in PG18
-t, --recovery-timeoutMax seconds to wait for target catch-up (0 = disabled)17+

pg_resetwal at the end rewrites the system identifier — any other standbys following the converted cluster will break and must be rebuilt.

pg_recvlogical — client-side failover slots (PG18)

pg_recvlogical --create-slot \
  --slot=my_slot --plugin=pgoutput --dbname=shop \
  --enable-failover        # PG18 new: slot is synced to physical standbys
pg_recvlogical --start --slot=my_slot --dbname=shop -f -

--enable-two-phase is also new in PG18 (synonym for the deprecated --two-phase), and --drop-slot no longer requires --dbname.

Essential diagnostic queries

-- Publisher: which slots exist, which are active, how much WAL they retain
SELECT slot_name, plugin, slot_type, database, active, temporary,
       restart_lsn, confirmed_flush_lsn,
       pg_size_pretty(pg_wal_lsn_diff(pg_current_wal_lsn(), restart_lsn)) AS retained_wal,
       wal_status, safe_wal_size, failover, synced
  FROM pg_replication_slots;

-- Publisher: WAL sender lag per subscriber
SELECT application_name, state, sync_state,
       pg_wal_lsn_diff(sent_lsn,  write_lsn)  AS write_lag_bytes,
       pg_wal_lsn_diff(write_lsn, flush_lsn)  AS flush_lag_bytes,
       pg_wal_lsn_diff(flush_lsn, replay_lsn) AS replay_lag_bytes,
       write_lag, flush_lag, replay_lag
  FROM pg_stat_replication;

-- Subscriber: what each apply/sync/parallel worker is doing
SELECT subname, worker_type, pid, leader_pid, relid::regclass,
       received_lsn, latest_end_lsn,
       now() - last_msg_receipt_time AS idle_since
  FROM pg_stat_subscription;

-- Subscriber: error & conflict counters (PG18)
SELECT subname, apply_error_count, sync_error_count,
       confl_insert_exists + confl_update_exists + confl_multiple_unique_conflicts AS hard_conflicts,
       confl_update_missing + confl_delete_missing AS skipped_rows,
       confl_update_origin_differs + confl_delete_origin_differs AS origin_overwrites
  FROM pg_stat_subscription_stats;

-- Subscriber: tables still in initial sync
SELECT srsubid::regnamespace || '.' || srrelid::regclass AS rel, srsubstate, srsublsn
  FROM pg_subscription_rel WHERE srsubstate <> 'r';  -- 'i'=init, 'd'=data copy, 's'=synced, 'r'=ready

PG 18.x minor-version fixes affecting replication

Update (verified 2026-08-22) — read this before upgrading. The current PG 18 minor is 18.6 (2026-08-13), two rounds past the 18.3 this table stopped at, and 18.5 was never released (the 18.6 notes: "18.5 was never released, due to a regression discovered post-wrap"; postgresql.org/docs/release/18.5/ 404s; the 18.6 notes describe their fixes as coming "from 18.4"). One 18.6 change is breaking for logical replication specifically:

  • output_plugin_libraries is a new server parameter and it is a whitelist (Jacob Champion, CVE-2026-6471). Previously a replication user could name any loadable library as a logical-decoding output plugin. As of 18.6 the default value admits only the plugins shipped with PostgreSQL — pgoutput and test_decoding. If you decode through wal2json, decoderbufs, Debezium’s plugin or any other third-party output plugin, it will be refused after the update until you add it, e.g. output_plugin_libraries = 'pgoutput, test_decoding, my_trusted_decoder'.
  • It also blocks pg_upgrade. pg_upgrade --check now fails if the new cluster’s output_plugin_libraries does not permit the output plugins of the old cluster’s logical replication slots, when migrating from 17 or later. Set the parameter on the new cluster before running the upgrade.
  • Native pgoutput pipelines — everything the CREATE SUBSCRIPTION examples in this entry build — are unaffected by the default.

Also in 18.6: run-time (not just Assert) checks on the column count of tuples received during logical replication, so a malicious or buggy publisher cannot send inconsistent column counts; tightened quoting of slot names and other string parameters inside constructed replication commands (upstream notes a crafted slot name could in principle reach SQL injection, though only privileged users can invoke replication); logical decoding of an empty prepared transaction no longer emits COMMIT/ROLLBACK PREPARED with no preceding PREPARE, which broke the built-in subscriber; a race dropping ephemeral slots; pg_get_publication_tables() no longer fails when a publishable table is dropped concurrently; pg_stat_progress_copy on the subscriber no longer shows the initial COPY as active after it finished; pg_createsubscriber now removes the publication and slot it created on the publisher when it fails partway; and pg_stat_wal_receiver no longer transiently exposes the unsanitised connection string during a timeline jump.

16 Gotchas

1. wal_level = logical requires a restart — plan the upgrade; pg_reload_conf() won't pick it up.
2. Slot WAL bloat kills the publisher — a disconnected subscriber pins WAL forever. Set max_slot_wal_keep_size (unbounded -1 is dangerous on small disks).
3. REPLICA IDENTITY FULL + non-hashable column = UPDATE/DELETE fails — json, xml, point, box etc. have no default B-tree/Hash opclass. Add a PK or a unique NOT NULL index and use USING INDEX.
4. Sequences don't replicate — on failover/promotion you MUST bump sequences to MAX(id)+large_gap, or new inserts collide with replicated serial values.
5. DDL is never replicated — apply additive changes to the subscriber FIRST, destructive changes LAST, always before the publisher emits WAL for those columns.
6. copy_data=true + large tables = hours of slot WAL retention — consider copy_data=false with a manual pg_dump of selected tables, or use pg_createsubscriber to avoid the copy entirely.
7. streaming = parallel (PG18 default) + triggers with side effects — parallel apply workers must not run triggers that violate the original transaction's visibility; fall back to streaming = on if subscriber triggers assume sequential single-worker apply.
8. Self-conflict on insert_exists during initial sync — if subscriber table was pre-seeded with rows matching PKs in the publisher, COPY will fail. Either copy_data=false or TRUNCATE the subscriber first.
9. publish_via_partition_root=true hides direct partition TRUNCATEs — truncating a leaf partition directly on the publisher is silently not replicated.
10. Column lists without REPLICA IDENTITY columns = UPDATE/DELETE error — column list must be a superset of the identity columns.
11. update_origin_differs counter stays at 0 without track_commit_timestamp — silently; looks like "no conflicts" when it actually means "not detecting any".
12. Row filters use pre-image for DELETE, post-image for INSERT, both for UPDATE — an UPDATE that moves a row in/out of the filter is transformed to INSERT or DELETE. Filters on volatile columns can make inventory look inconsistent.
13. ALTER SUBSCRIPTION ... REFRESH PUBLICATION is required after publisher-side table additions — new tables in FOR ALL TABLES are NOT auto-picked-up by existing subscriptions; also not after column-list changes.
14. 2PC (two_phase=true) can't be toggled mid-flight on < PG18 — in PG17 you had to drop and recreate the subscription; PG18's ALTER SUBSCRIPTION ... (two_phase = true) changes behavior without recreating the slot.
15. failover=true requires the publisher-side replication slot to be on a cluster with physical standbys that have hot_standby_feedback=on and the slot-sync worker enabled — otherwise the flag is accepted but does nothing.
16. SKIP (LSN ...) discards ALL changes in the transaction — if the offending xact touched 100 tables, 99 others lose those changes too. Prefer data-level resolution (adjust subscriber rows) when the xact is wide.

Minimum working recipe

-- ===== PUBLISHER =====
ALTER SYSTEM SET wal_level = 'logical';
-- RESTART

CREATE ROLE repl WITH REPLICATION LOGIN PASSWORD 'secret';
GRANT USAGE ON SCHEMA public TO repl;
GRANT SELECT ON ALL TABLES IN SCHEMA public TO repl;
ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT SELECT ON TABLES TO repl;

ALTER TABLE orders      REPLICA IDENTITY DEFAULT;  -- has PK
ALTER TABLE order_items REPLICA IDENTITY USING INDEX order_items_uniq;

CREATE PUBLICATION orders_pub FOR TABLE orders, order_items
  WITH (publish_generated_columns = 'stored');

-- ===== SUBSCRIBER (same schema created manually first: pg_dump --schema-only) =====
ALTER SYSTEM SET track_commit_timestamp = on;
-- RESTART

CREATE SUBSCRIPTION orders_sub
  CONNECTION 'host=publisher.internal dbname=shop user=repl password=secret'
  PUBLICATION orders_pub
  WITH (copy_data = true, streaming = parallel, binary = true,
        disable_on_error = true, failover = true);

-- Monitor
SELECT * FROM pg_stat_subscription;
SELECT * FROM pg_stat_subscription_stats;

Pair this with postgresql-vacuum-mvcc-and-autovacuum on the subscriber (apply generates dead tuples just like normal DML) and postgresql-pg-stat-statements to attribute apply-worker CPU cost. For connection pooling in front of the subscriber, note pgbouncer-pool-modes-prepared-statements-and-transaction-mode-gotchas — transaction-mode pooling is fine for subscriber reads but apply workers connect directly.
