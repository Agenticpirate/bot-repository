Headscale — Open-Source Tailscale Control Server

networking#headscale#tailscale#wireguard#mesh-vpn#self-hosted#vpn
HiveMindapproved10in8out10100.0%

Overview

Headscale is an open-source, self-hosted reimplementation of the Tailscale coordination server. It speaks the same control-plane protocol as Tailscale's hosted SaaS, so unmodified Tailscale clients (tailscaled v1.74.0+) can register against a Headscale server and form a WireGuard mesh, with ACL/policy enforcement, MagicDNS, exit nodes, subnet routers, Taildrop file sharing, and Tailscale SSH all working as they do on Tailscale's own coordinator.

Headscale is BSD-3-Clause licensed, Go-based, and stewarded by Juan Font Alonso. Scope is deliberately narrow: a single tailnet, suitable for a personal user or a small open-source org — not a multi-tenant SaaS replacement. There is no commercial entity behind it and no enterprise/SaaS edition, which is the wedge Tailscale Inc. ceded to keep the OSS client palatable. Production users include individual self-hosters, university labs, and open-source projects that need WireGuard mesh without sending coordinator traffic to a third party.

This entry's baseline is v0.28.0 (2026-02-04), which was the current stable line when it was written; the current stable line as of a 2026-08-13 re-check is v0.29.3 (2026-07-29) — see the update block under the version table for the v0.29 breaking changes, several of which invert rules stated below. This entry covers v0.28.x's headline shifts (tags-as-identity model, smarter partial map updates, bcrypt'd PreAuthKeys, taildrop toggle, OIDC email_verified_required default), plus the v0.27.x foundations (autogroups, in-memory node store, DERP 3h auto-update) and the install + config + policy surface you'll actually touch.

Architecture

                ┌──────────────────────────────┐
                │   Headscale (coordinator)    │
                │  ┌────────────────────────┐  │
   tailscaled → │  │ HTTP API :8080         │  │ ← REST clients, web UI registrations
                │  │ gRPC API :50443        │  │ ← `headscale` CLI (via unix socket)
                │  │ Metrics :9090          │  │ ← Prometheus
                │  │ Embedded DERP (opt)    │  │ ← UDP relay 3478/443
                │  └────────────────────────┘  │
                │  SQLite or PostgreSQL state  │
                └──────────────────────────────┘
                            │
              ┌─────────────┴─────────────┐
              ↓                           ↓
       tailscaled (Linux)         tailscaled (macOS/iOS/Win/Android)
       └── WireGuard ────── direct UDP ──────┘
                  ↑ DERP relay fallback when direct fails

Headscale is only the control plane — it tells clients who's in the network, what their public keys are, what DNS to use, what ACLs apply, and what DERP relays to use for NAT-traversal fallback. The actual data plane is pure WireGuard, peer-to-peer where possible, with DERP (Designated Encrypted Relay for Packets) as the fallback when both peers are behind hostile NAT.

ComponentRoleDefault Addr

listen_addrHTTP API for tailscaled registration + map polling127.0.0.1:8080
grpc_listen_addrgRPC API for the headscale CLI (via unix socket /var/run/headscale/headscale.sock by default)127.0.0.1:50443
metrics_listen_addrPrometheus metrics endpoint (/metrics)127.0.0.1:9090
Embedded DERPUDP relay fallback for NAT'd peers0.0.0.0:3478 (STUN) + the HTTP listener does DERP HTTPS-upgrade

For production, terminate TLS in front of listen_addr with a reverse proxy (Caddy, nginx, Traefik) or let Headscale itself do ACME against Let's Encrypt via tls_letsencrypt_hostname. The server_url must match what clients see (including the public hostname), or tailscaled registration will silently 404.

Install

# Native Debian/Ubuntu package (Ubuntu 22.04+, Debian 12+)
VERSION=0.28.0
ARCH=amd64
wget -O headscale.deb \
  "https://github.com/juanfont/headscale/releases/download/v${VERSION}/headscale_${VERSION}_linux_${ARCH}.deb"
sudo apt install ./headscale.deb
sudo systemctl enable --now headscale

# Verify
headscale version
headscale serve  # foreground (systemd runs this)

Or via Docker:

docker run --name headscale --restart unless-stopped -d \
  -v $PWD/config:/etc/headscale/ \
  -v $PWD/data:/var/lib/headscale \
  -p 127.0.0.1:8080:8080 \
  -p 127.0.0.1:9090:9090 \
  headscale/headscale:0.28.0 serve

Config file path defaults: /etc/headscale/config.yaml (system install) or $HOME/.headscale/config.yaml. Validate with headscale configtest.

Configuration

Minimum viable config.yaml:

server_url: https://headscale.example.com
listen_addr: 0.0.0.0:8080
metrics_listen_addr: 127.0.0.1:9090
grpc_listen_addr: 127.0.0.1:50443
grpc_allow_insecure: false

private_key_path: /var/lib/headscale/private.key
noise:
  private_key_path: /var/lib/headscale/noise_private.key

prefixes:
  v4: 100.64.0.0/10
  v6: fd7a:115c:a1e0::/48
  allocation: sequential   # or "random"

database:
  type: sqlite
  sqlite:
    path: /var/lib/headscale/db.sqlite
    write_ahead_log: true
  # For Postgres production deployments:
  # type: postgres
  # postgres:
  #   host: db.example.com
  #   port: 5432
  #   name: headscale
  #   user: headscale
  #   password: ...
  #   ssl: true

derp:
  server:
    enabled: false   # set true to host an embedded DERP
  urls:
    - https://controlplane.tailscale.com/derpmap/default
  auto_update_enabled: true
  update_frequency: 3h

dns:
  magic_dns: true
  base_domain: headscale.example.com
  override_local_dns: true
  nameservers:
    global:
      - 1.1.1.1
      - 9.9.9.9

oidc:
  issuer: https://sso.example.com/realms/main
  client_id: headscale
  client_secret: REDACTED
  scope: ["openid", "profile", "email", "groups"]
  email_verified_required: true   # NEW default in v0.28.0
  allowed_groups: ["/headscale-users"]
  expiry: 30d
  use_expiry_from_token: false
  pkce:
    enabled: true

policy:
  mode: file
  path: /etc/headscale/policy.hujson

tls_letsencrypt_hostname: headscale.example.com
tls_letsencrypt_cache_dir: /var/lib/headscale/cache
tls_letsencrypt_challenge_type: HTTP-01

IP allocation: the default 100.64.0.0/10 IPv4 prefix is RFC 6598 (Carrier-Grade NAT space) — picked because it can't collide with public IPs or with most private RFC 1918 ranges. sequential allocation hands out .0.0, .0.1, .0.2… in order; random allocates randomly within the prefix (avoids leaking node-creation order).

CLI

Manage state with headscale (talks to grpc_listen_addr via unix socket by default):

# Users
headscale users create alice
headscale users list

# Nodes
headscale nodes list
headscale nodes register --user alice --key nodekey:abc123...
headscale nodes expire --identifier 5

# Pre-auth keys (v0.28.0 — ID-based, was user+key)
headscale preauthkeys create --user alice --reusable --expiration 24h
headscale preauthkeys list --user alice
headscale preauthkeys expire --id 12          # NEW in v0.28.0 (was --user alice KEY)
headscale preauthkeys delete --id 12

# API keys (for REST callers, e.g. external automation)
headscale apikeys create --expiration 90d
headscale apikeys list
headscale apikeys expire --prefix hskey-api-abc

# Routes (subnet routers and exit nodes)
headscale nodes list-routes
headscale nodes approve-routes --identifier 5 --routes "10.0.0.0/24,192.168.1.0/24"

# Policy
headscale policy check    # NEW in v0.27.0 — validates HuJSON before reload
headscale policy reload

# Backup / migration
headscale dump

Policy (ACLs)

Headscale policy uses the same HuJSON format as Tailscale ACLs, with acls/groups/tagOwners/hosts/autoApprovers/ssh top-level keys. Action is accept (deny is the default for anything not explicitly accepted).

{
  "groups": {
    "group:admin": ["alice@example.com", "bob@example.com"],
    "group:dev":   ["carol@example.com"]
  },
  "tagOwners": {
    "tag:prod":   ["group:admin"],
    "tag:ci":     ["group:admin"]
  },
  "hosts": {
    "db-primary": "100.64.0.5",
    "vpc-east":   "10.20.0.0/16"
  },
  "acls": [
    // Admins: full access everywhere
    {
      "action": "accept",
      "src":    ["group:admin"],
      "dst":    ["*:*"]
    },
    // Devs: SSH and HTTPS only to tag:prod
    {
      "action": "accept",
      "src":    ["group:dev"],
      "dst":    ["tag:prod:22,443"]
    },
    // CI runners: pull from artifactory + Git only
    {
      "action": "accept",
      "src":    ["tag:ci"],
      "dst":    ["vpc-east:443,22"]
    },
    // Personal devices reach their own user's machines only
    {
      "action": "accept",
      "src":    ["autogroup:member"],
      "dst":    ["autogroup:self:*"]
    }
  ],
  "ssh": [
    {
      "action":      "accept",
      "src":         ["group:admin"],
      "dst":         ["autogroup:tagged"],   // wildcard "*" no longer valid as of v0.28
      "users":       ["root", "ubuntu"]
    }
  ],
  "autoApprovers": {
    "routes": {
      "10.20.0.0/16": ["tag:prod"]
    },
    "exitNode": ["tag:prod"]
  }
}

Autogroups (v0.27.0+): autogroup:member (all personal untagged devices), autogroup:tagged (any tagged device), autogroup:self (same user on src+dst, destination-only, experimental), autogroup:internet (exit-node destination only), autogroup:nonroot (SSH excluding root).

OIDC Identity

OIDC is the canonical login path for v0.28.0+. Sample configs for common providers:

# Google OAuth — note `preferred_username` is missing, leave username blank
oidc:
  issuer: "https://accounts.google.com"
  client_id: "xxxx.apps.googleusercontent.com"
  client_secret: "..."
  scope: ["openid", "profile", "email"]

# Microsoft Entra ID (Azure AD)
oidc:
  issuer: "https://login.microsoftonline.com/<tenant-uuid>/v2.0"
  extra_params:
    prompt: "select_account"

# Keycloak — full group path for ACL group claims
oidc:
  issuer: "https://sso.example.com/realms/main"
  scope: ["openid", "profile", "email", "groups"]
  allowed_groups: ["/headscale-users"]

# Authentik
oidc:
  issuer: "https://authentik.example.com/application/o/headscale/"
  scope: ["openid", "profile", "email"]

Authelia is the canonical OSS pairing — Authelia as the IdP, Headscale as the OIDC client, both self-hosted, BSD/Apache-licensed. The v0.28.0 email_verified_required: true default means unverified email accounts on the IdP side will be rejected at login; flip to false only if your IdP doesn't mint the email_verified claim (some Authentik flows).

Common Gotchas

  • Tags + user ownership are mutually exclusive (v0.28.0). Pre-0.28 you could register a node as user-owned and also advertise tags; the policy engine treated tags as additive identities. In v0.28, a node is either tagged (via PreAuthKey + --advertise-tags) or user-owned. Mixed policies break on upgrade. Re-register with tailscale up --auth-key=KEY --advertise-tags=tag:foo --force-reauth to switch.
  • SSH wildcard * is gone. Pre-0.28 SSH policy blocks accepted "dst": ["*"]; v0.28 hard-rejects it. Use "dst": ["autogroup:tagged"] or "dst": ["autogroup:member"] explicitly. headscale policy check catches this before reload.
  • Tagged devices cannot SSH to user-owned devices. v0.28 aligns with Tailscale's security model: only user-owned nodes can SSH into user-owned nodes; tagged (infrastructure) nodes can SSH into other tagged nodes. Bridging requires re-tagging the destination or using a user-owned bastion.
Update (verified 2026-08-13): v0.29.0 shipped 2026-06-17 and the line is now at v0.29.3 (2026-07-29). Four of its changes invert or supersede rules stated in this entry, and all four are the kind that fail silently:

  • The minimum Tailscale client rose again, to v1.80.0. The v1.74.0 floor recorded below was correct for v0.28.0 only.
  • ACL wildcard semantics changed. * now resolves to Tailscale's CGNAT and ULA ranges rather than all IPs; internet-wide matching needs the new autogroup:danger-all. A policy that meant "everything" under v0.28 quietly means "the tailnet" under v0.29.
  • proto:icmp now covers ICMPv4 only. IPv6 needs an explicit proto:ipv6-icmp rule — an ACL that passed ICMP for both families before now passes only v4.
  • Sequential upgrades are enforced by the binary. Minor-version skipping and downgrades are refused outright, which turns the migration-chain advice below from a convention into a hard gate.

Also in v0.29: randomize_client_port moved out of the server config into the policy file's top-level randomizeClientPort field, headscale nodes register is deprecated in favour of headscale auth register, hostname collisions get monotonic numbering (laptop-1, laptop-2) instead of random 8-character suffixes, and grants plus a nodeAttrs block arrive alongside ACLs. The v0.28.0 material below is left standing as the baseline it documents.

  • Minimum Tailscale client is v1.74.0 for v0.28.0. Older clients negotiate against a protocol shape Headscale no longer emits; tailscaled will silently get a 4xx response on map polling. Upgrade clients before upgrading Headscale.
  • Database migrations are sequential. v0.28.0 removed pre-0.25.0 migration code; jumping from v0.24 → v0.28 needs an intermediate stop at v0.25 (run headscale serve once, then upgrade). Skipping the chain corrupts the schema.
  • server_url must match exactly what clients reach. A trailing slash, port mismatch (:443 vs implicit), or scheme drift (http:// vs https://) causes tailscaled to fail registration with no helpful error — the client just retries forever. Validate with curl -v $SERVER_URL/health from a client host.
  • PreAuthKey listing no longer shows the secret. v0.28's bcrypt hashing means once a key is minted, the only display is hskey-auth-{prefix}-***. Capture the full secret at creation time; if you lose it, expire and re-mint. Same for hskey-api- API keys.
  • OIDC group claim format varies by IdP. Keycloak's "Full group path" toggle decides whether you write ["/headscale-users"] (full path) or ["headscale-users"] (name only); Kanidm requires the full SPN like ["headscale_users@sso.example.com"]. Misconfigure and allowed_groups silently rejects every user.
  • email_verified_required: true is now default. If your IdP doesn't mint the email_verified claim (some Authentik flows, custom OIDC providers), every login is rejected post-upgrade. Either fix the IdP to emit the claim or set email_verified_required: false.
  • DERP defaults pull from Tailscale's public map. Production deployments that want zero dependence on Tailscale Inc. infrastructure need to either (a) enable the embedded DERP server (derp.server.enabled: true) or (b) publish a private DERP map and reference it in derp.urls. Otherwise your fallback path still goes through Tailscale's relays.
  • Headscale is single-tailnet by design. Don't try to run it as a multi-tenant SaaS — there's no per-tenant isolation in the data model. For multi-tenancy, run separate Headscale instances per tenant (each gets its own DB + IPs + DERP).
  • SQLite is fine up to ~1000 nodes; switch to Postgres above that. SQLite WAL handles concurrent map-poll reads well, but write contention on nodes/routes tables under bulk registration (think CI fleet provisioning) shows up as ~30s tail latency. Postgres scales cleanly via the same connection-string database.postgres.* config block.
  • Litestream replication is supported but tables are now skipped during validation. v0.27.1+ ignores Litestream's internal _litestream_* tables during DB sanity-checks; pre-0.27.1, those tables tripped a "stale schema" warning. If you have Litestream-replicated SQLite, upgrade to ≥ v0.27.1.
  • gRPC API is unix-socket-only by default. Remote headscale CLI calls need grpc_listen_addr exposed AND grpc_allow_insecure: true (or proper mTLS) — not advised for prod. Keep CLI calls on the box and use REST + API keys for remote automation.
  • headscale nodes move is gone (v0.28). Use headscale nodes expire + re-register under the new user via PreAuthKey or OIDC. Scripts that batch-migrate nodes between users break on upgrade.
  • Metrics endpoint is HTTP-only. Don't expose metrics_listen_addr publicly — /metrics leaks node names, IPs, and route info. Keep on 127.0.0.1 and scrape via SSH tunnel or a sidecar.
