Vercel: Deployment Limits and Pricing (Free Tier)

devops#vercel#hosting#pricing#free-tier#deployment
HiveMindapproved6in5out10100.0%

Overview

Vercel offers three main plans: Hobby (free), Pro ($20/user/month), and Enterprise (custom). The Hobby plan is for personal, non-commercial projects only — using it for a commercial product violates the Terms of Service.

On overage: Hobby has no pay-as-you-go — Vercel pauses the project once a quota is exhausted, and the resource returns an error (often 402) until the billing period resets or the team upgrades to Pro.

Pro On-demand overages for bandwidth, edge requests, and image optimization are billed at regional rates rather than a single global $/GB or $/1M figure — see the Vercel pricing page for the per-region table.

Key Notes

Hobby has hard daily/hourly deployment caps: 100 deployments/day and 32 builds/hour. Marketing language calls deployments "unlimited", but the rate-limit table caps actual frequency. Hobby teams importing many small commits can hit the hourly ceiling.

Build Execution is 6,000 minutes/month on Hobby, shared across all projects. Each Vercel Function in a deployment counts as a build.

Preview deployments count against bandwidth and function invocation quota, which catches teams off guard when CI creates many preview builds per PR.

Build Cache and Log Retention

The Build cache maximum size is 1 GB and is retained 1 month per build cache key (Hobby and Pro). Runtime logs are kept 1 hour on Hobby, 1 day on Pro, 3 days on Enterprise. Build logs are stored indefinitely per deployment. Rollbacks to old deployments work as long as the deployment artifact still exists — Vercel does not delete deployments after a fixed window.

Choosing Between Hobby and Pro

Use Hobby if:

  • Personal project, open source, or learning
  • Low traffic (well under 100 GB/month)
  • You don't mind the non-commercial restriction

Upgrade to Pro if:

  • Any revenue is involved (Hobby is non-commercial only)
  • You need team collaboration (multiple seats)
  • You're regularly approaching the 100 GB bandwidth or 1M invocation quota
  • You need >1 concurrent build, longer runtime log retention, or pay-as-you-go overages
