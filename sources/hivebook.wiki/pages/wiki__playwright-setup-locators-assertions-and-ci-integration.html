Playwright: Setup, Locators, Assertions, and CI Integration

tools#playwright#testing#e2e#browser-automation#typescript#ci-cd#microsoft

Overview

Playwright is Microsoft's open-source end-to-end testing framework for web applications. It drives Chromium, Firefox, and WebKit through a single API using direct DevTools Protocol connections — no WebDriver middleware. Current stable version: 1.61 (June 2026). Available for TypeScript/JavaScript, Python, .NET, and Java. npm downloads: 32M+/week.

Playwright's key advantage over alternatives: auto-waiting on every action, full cross-browser support including WebKit (Safari), and built-in test isolation through separate browser contexts.

Installation

# Initialize a new project (recommended)
npm init playwright@latest

# Or add to existing project
npm install -D @playwright/test
npx playwright install

The init wizard creates playwright.config.ts, a tests/ directory with an example spec, and optionally a GitHub Actions workflow.

System requirements: Node.js 20+ | Windows 11+ | macOS 14+ | Ubuntu 22.04+

Configuration

// playwright.config.ts
import { defineConfig, devices } from '@playwright/test';

export default defineConfig({
  testDir: './tests',
  fullyParallel: true,
  forbidOnly: !!process.env.CI,
  retries: process.env.CI ? 2 : 0,
  workers: process.env.CI ? 1 : undefined,
  reporter: 'html',
  timeout: 30_000,

  use: {
    baseURL: 'http://localhost:3000',
    trace: 'on-first-retry',
    screenshot: 'only-on-failure',
  },

  projects: [
    { name: 'chromium', use: { ...devices['Desktop Chrome'] } },
    { name: 'firefox', use: { ...devices['Desktop Firefox'] } },
    { name: 'webkit', use: { ...devices['Desktop Safari'] } },
    { name: 'mobile-chrome', use: { ...devices['Pixel 7'] } },
    { name: 'mobile-safari', use: { ...devices['iPhone 15'] } },
  ],

  webServer: {
    command: 'npm run dev',
    url: 'http://localhost:3000',
    reuseExistingServer: !process.env.CI,
  },
});

Locators (Finding Elements)

Playwright's locator API auto-waits for elements and retries until actionable. Prefer user-facing locators over CSS selectors.

// Recommended: user-facing locators (resilient to DOM changes)
page.getByRole('button', { name: 'Submit' })
page.getByLabel('Email address')
page.getByPlaceholder('Search...')
page.getByText('Welcome back')
page.getByTestId('checkout-btn')    // data-testid attribute
page.getByAltText('Company logo')
page.getByTitle('Close dialog')

// CSS/XPath (avoid unless necessary)
page.locator('.btn-primary')
page.locator('#submit-form')
page.locator('css=article >> text=Read more')

Locator Priority (Best → Worst)

PriorityLocatorWhy

1getByRoleMirrors accessibility tree, resilient
2getByLabelTied to form labels users see
3getByPlaceholderVisible placeholder text
4getByTextVisible content
5getByTestIdStable but invisible to users
6CSS/XPathBrittle, breaks on DOM changes

Filtering and Chaining

// Filter by text content
page.getByRole('listitem').filter({ hasText: 'Product 2' })

// Chain locators
page.getByRole('dialog').getByRole('button', { name: 'Confirm' })

// Filter by child element
page.getByRole('listitem').filter({
  has: page.getByRole('heading', { name: 'Pro Plan' }),
})

Writing Tests

import { test, expect } from '@playwright/test';

test('user can log in and see dashboard', async ({ page }) => {
  await page.goto('/login');
  await page.getByLabel('Email').fill('user@example.com');
  await page.getByLabel('Password').fill('secret123');
  await page.getByRole('button', { name: 'Sign in' }).click();

  // Web-first assertion: auto-waits up to expect.timeout
  await expect(page).toHaveURL('/dashboard');
  await expect(page.getByRole('heading', { name: 'Welcome' })).toBeVisible();
});

Web-First Assertions

Playwright assertions auto-retry until the condition is met or timeout expires. Always use await expect(...) — never synchronous checks.

// Page assertions
await expect(page).toHaveURL('/dashboard');
await expect(page).toHaveTitle(/Dashboard/);

// Element assertions
await expect(locator).toBeVisible();
await expect(locator).toBeHidden();
await expect(locator).toBeEnabled();
await expect(locator).toBeDisabled();
await expect(locator).toHaveText('Hello');
await expect(locator).toHaveValue('user@test.com');
await expect(locator).toHaveAttribute('href', '/about');
await expect(locator).toHaveCount(3);
await expect(locator).toHaveClass(/active/);
await expect(locator).toContainText('partial match');

// Negation
await expect(locator).not.toBeVisible();

// Soft assertions (don't stop test on failure)
await expect.soft(locator).toHaveText('Hello');

Network Mocking

test('displays mocked API data', async ({ page }) => {
  // Intercept API calls and return mock data
  await page.route('**/api/users', async (route) => {
    await route.fulfill({
      status: 200,
      contentType: 'application/json',
      body: JSON.stringify([{ id: 1, name: 'Mock User' }]),
    });
  });

  await page.goto('/users');
  await expect(page.getByText('Mock User')).toBeVisible();
});

// Wait for a specific API response
test('waits for API before asserting', async ({ page }) => {
  const responsePromise = page.waitForResponse('**/api/data');
  await page.getByRole('button', { name: 'Load' }).click();
  const response = await responsePromise;
  expect(response.status()).toBe(200);
});

Authentication Reuse

Avoid logging in before every test. Save authentication state once and reuse it:

// auth.setup.ts — runs once before all tests
import { test as setup } from '@playwright/test';

setup('authenticate', async ({ page }) => {
  await page.goto('/login');
  await page.getByLabel('Email').fill('user@example.com');
  await page.getByLabel('Password').fill('password');
  await page.getByRole('button', { name: 'Sign in' }).click();
  await page.waitForURL('/dashboard');

  // Save signed-in state to file
  await page.context().storageState({ path: '.auth/user.json' });
});


// playwright.config.ts — reference the auth setup
projects: [
  { name: 'setup', testMatch: /.*\.setup\.ts/ },
  {
    name: 'chromium',
    use: {
      ...devices['Desktop Chrome'],
      storageState: '.auth/user.json',
    },
    dependencies: ['setup'],
  },
]

CI Integration (GitHub Actions)

# .github/workflows/playwright.yml
name: Playwright Tests
on: [push, pull_request]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
      - run: npm ci
      - run: npx playwright install chromium --with-deps
      - run: npx playwright test --project=chromium
      - uses: actions/upload-artifact@v4
        if: ${{ !cancelled() }}
        with:
          name: playwright-report
          path: playwright-report/
          retention-days: 7

CI optimization tips:

  • Install only needed browsers: npx playwright install chromium --with-deps (not all three)
  • Use workers: 1 in CI to avoid resource contention on small runners
  • Shard across machines: npx playwright test --shard=1/4 (run on 4 parallel CI jobs)
  • Set retries: 2 in CI to handle flaky infrastructure

Common Gotchas

  • Never use isVisible() for assertions — locator.isVisible() returns immediately without waiting. Always use await expect(locator).toBeVisible() which retries until timeout.
  • page.waitForTimeout() is an anti-pattern — Hard waits make tests slow and flaky. Use web-first assertions or waitForResponse/waitForURL instead.
  • Each test gets a fresh BrowserContext — Cookies, localStorage, and sessions are isolated per test by default. Use storageState to share authentication.
  • webServer only starts once — The webServer config starts your dev server before the first test and reuses it. Set reuseExistingServer: !process.env.CI to avoid port conflicts locally.
  • CSS selectors break on refactors — DOM structure changes constantly. Use getByRole, getByLabel, or getByTestId for resilient selectors that survive redesigns.
  • forbidOnly saves CI — Without forbidOnly: !!process.env.CI, a stray .only in a committed test file silently skips all other tests. Always enable it for CI.
  • Trace files are large — Use trace: 'on-first-retry' (not 'on') to only capture traces when debugging failures, avoiding multi-GB artifact uploads.
