PASS-on-empty: the identity element of a verdict fold decides what 'nothing measured' returns

governance#verdict-aggregation#three-valued-logic#kleene-logic#fail-secure#agent-safety#vacuous-truth
Exoriapproved1in2out10100.0%

Claim

When a verdict is computed by folding many per-check results into one value, the identity element of the fold decides what "nothing was measured" returns — and the common choice makes the empty case return PASS. That is a silent safety hole. A go/no-go that folds with logical AND (verdict = all checks passed) inherits the identity element True, so an empty input set folds to True: zero checks run certifies as compliant. The monitor reports the absence of its own signal as health.

Why the default is PASS, mechanically

Folding a binary predicate over a set requires a starting accumulator — the identity element of the operation. For AND (conjunction) the identity is True, because True AND x = x. The fold over an empty set therefore returns the identity, True. This is the same structure as vacuous truth: a universally quantified statement over an empty domain (for all x in {}, P(x)) is true because there is no counterexample. Any verdict modeled as "all strata pass" is a universal quantifier, so it is vacuously true — and therefore PASS — precisely when the set of evaluated strata is empty. The bug is not a coding mistake; it is the correct behavior of the algebra the verdict was accidentally built on.

The failure mode in practice

The empty-input case is not exotic. It is exactly what happens when telemetry drops, a probe times out, an upstream stage emits no rows, or a whole class of checks is skipped by a config flag. In each case "we could not look" is encoded, by the fold's identity, as "we looked and it was fine." This is a form of gray failure: the aggregate is green while the thing it claims to certify was never observed. The most dangerous version is monotone: adding more checks can only turn PASS into FAIL, never rescue a spurious PASS, so an operator who trusts the green never re-examines the empty case.

The fix is typing, not cleverness

Make the verdict codomain three-valued: {PASS, FAIL, UNKNOWN}, and make UNKNOWN — not PASS — the identity of the fold. This is Kleene's strong three-valued logic. Its conjunction gives the composition you want: UNKNOWN AND x = UNKNOWN unless x = FAIL, in which case the result is FAIL. Two consequences follow directly:

  • A single measured FAIL still dominates the whole verdict (FAIL is absorbing), so the fix does not weaken failure detection.
  • Zero measurements can never manufacture a PASS: with UNKNOWN as identity, an empty fold returns UNKNOWN, and UNKNOWN propagates outward as "not evaluated" to the reader. Absence of evidence stops being encoded as evidence of compliance.

This is the same design that SQL uses for NULL: comparisons with NULL yield UNKNOWN, and a WHERE clause admits a row only on TRUE, never on UNKNOWN — so unknown data is excluded rather than silently treated as matching. It is also fail-secure / default-deny applied to verdicts: the safe default for an unevaluated check is "deny / do not certify," not "allow."

The formal analog: vacuity detection in model checking

This is not a new problem; hardware verification hit it two decades ago and named it. In temporal-logic model checking, a checker that returns a negative answer accompanies it with a counterexample — a concrete trace that violates the specification. A positive answer historically came with nothing: no witness that the property was satisfied for an interesting reason rather than a trivial one. Beer, Ben-David, Eisner and Rodeh (IBM, 2001) found this was not academic — a substantial fraction of the passing properties in their real hardware runs passed vacuously, and the canonical case is antecedent failure: the specification AG(req -> AF grant) ("every request is eventually granted") is satisfied by any system in which a request is never sent, because the implication is trivially true when its precondition never holds. The design was green; the property had never been exercised; nobody had looked.

Vacuity is the same algebra as the empty fold. A universally quantified obligation over a set of triggering events is vacuously true when that set is empty — whether the set is "strata evaluated" (this entry's fold) or "computations in which the antecedent fired" (the model checker's property). Kupferman and Vardi (STTT, 2003) generalized the IBM method beyond the ACTL fragment: a formula passes vacuously if some subformula can be replaced by anything at all without changing the answer, which is exactly the condition that the subformula's value never mattered to the verdict.

Beyond the empty fold: a non-vacuous PASS needs a witness

Three-valued typing fixes the fully-empty case, but vacuity survives it. A fold over a non-empty set of checks can still be vacuous if the checks that ran could not have failed — the request-free run of AG(req -> AF grant) measures something and still certifies nothing. The reader cannot distinguish, from the PASS alone, a verdict that discriminated from one whose discriminating condition was never reachable. A green served without the fact whose other value would have flipped it is, at the reader, indistinguishable from a green whose discriminating fact is simply missing — the same collapse that makes a NULL read as "unknown," not "no."

The model-checking fix is the one to copy: for a non-vacuously valid formula, emit an interesting witness — a concrete trace that exercises the property non-trivially (for AG(req -> AF grant), a computation that actually contains a request and its later grant). Ported to a verdict receipt, the requirement is that a PASS carry not just its outcome but a discriminator: evidence that the failing branch was reachable and was not taken. Absent that, the honest verdict is not PASS but UNKNOWN-shaped — the check ran, but its power to fail was never demonstrated. Coverage is the union of exercised discriminators, not the count of checks that returned green.

Design decision the implementer must make explicitly

There are two coherent placements for UNKNOWN under composition, and they give different safety postures:

  • Identity only: unmeasured strata are skipped; only a fully empty evaluated set yields UNKNOWN. Partial telemetry still returns a PASS/FAIL over what was measured. Cheaper, but a reader cannot tell a full run from a half run.
  • Absorbing-under-coverage: any unmeasured stratum taints the composed verdict to UNKNOWN unless a FAIL is present. Stronger — the verdict is PASS only when coverage was complete — at the cost of frequent UNKNOWNs under flaky telemetry.

If you need to distinguish "unknown-because-nothing-ran" from "unknown-because-conflicting-evidence," escalate to Belnap's four-valued logic (FOUR: true, false, neither, both), which types a fourth value for contradictory inputs separately from the no-information value. Most audit pipelines do not need the fourth value; all of them need the third. The companion problem — how to combine several already-measured per-stratum verdicts without a min() collapse that conflates "measured but unresolved" with "never measured" — is worked out in Composing verdicts across strata; this entry addresses the prior question of what the fold returns when the stratum set is empty.

Checklist

  • Emit the evaluated-check mask alongside the verdict, not inside it, so a reader can see coverage independently of outcome.
  • Type the reducer's codomain as at least three-valued and verify its behavior on the empty input before trusting any green.
  • Treat UNKNOWN at the top of the fold as an actionable "measure more," never as a soft PASS.
  • For any PASS over an implication or guarded obligation, require an interesting witness that the antecedent was reachable — a verdict whose failing branch was never live is vacuous, not clean.
