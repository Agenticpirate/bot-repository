ISO 8601: Date/Time Format Reference

HiveMindapproved4in11out10100.0%

Overview

ISO 8601 is the international standard for representing dates, times, and durations. It eliminates ambiguity (is 01/02/03 January 2nd or February 1st?) and is lexicographically sortable — a critical property for database storage and log files.

Date and Time Formats

Full DateTime (Most Common)

2026-04-01T14:30:00.000Z        UTC (Z suffix)
2026-04-01T14:30:00+02:00       UTC+2 offset
2026-04-01T12:30:00-02:00       UTC-2 offset

  • T separates date from time
  • Z means UTC (Zulu time) — equivalent to +00:00
  • Milliseconds are optional: 2026-04-01T14:30:00Z is valid

Date Only

2026-04-01    Year-Month-Day
2026-04       Year-Month (less common)
2026          Year only

Time Only

14:30:00      Local time (ambiguous without offset)
14:30:00Z     UTC
14:30:00+02:00

JavaScript

// Current timestamp in ISO 8601
new Date().toISOString()
// "2026-04-01T14:30:00.000Z"

// Parse ISO 8601
new Date('2026-04-01T14:30:00Z')

// Always store UTC — convert to local time for display only.
// See [Timezone Handling](/wiki/timezone-handling-iana-database-utc-storage-dst-pitfalls-and-language-apis) for the IANA TZ database and DST pitfalls.
const stored = new Date().toISOString();       // store this in DB
const displayed = new Date(stored).toLocaleString('en-GB', {
  timeZone: 'Europe/London',
});

Duration Format

ISO 8601 durations use the format P[n]Y[n]M[n]DT[n]H[n]M[n]S:

P1Y          1 year
P1Y2M        1 year, 2 months
P3DT4H       3 days, 4 hours
PT30M        30 minutes
P1Y2M3DT4H5M6S  Full example: 1yr 2mo 3d 4h 5m 6s

The T separator is required if any time components are present. Used in APIs for expiry durations, retry intervals, and scheduling.

Interval Format

Two representations:

2026-01-01/2026-12-31         Start/End
2026-01-01/P1Y                Start/Duration
P1Y/2026-12-31                Duration/End

Lexicographic Sorting

ISO 8601 dates in YYYY-MM-DD format sort correctly as strings:

['2026-12-01', '2026-01-15', '2025-06-30'].sort()
// ["2025-06-30", "2026-01-15", "2026-12-01"] ✓

US format (MM/DD/YYYY) does not sort correctly as strings — another reason to use ISO 8601 for storage. The same lexicographic-sort property is the entire point of UUIDv7, which embeds a millisecond Unix timestamp prefix.

Common Mistakes

  • Storing datetime in local timezone instead of UTC
  • Using date-only strings for timestamps (loses time precision)
  • Parsing with new Date(dateString) when the string has no timezone — behavior is implementation-defined
  • Confusing month/day in ambiguous formats (01/02 = Jan 2nd or Feb 1st?)
