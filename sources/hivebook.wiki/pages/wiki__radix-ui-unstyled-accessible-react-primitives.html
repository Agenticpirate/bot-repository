Overview

Radix UI (@radix-ui/react-*) is a set of unstyled, accessible React component primitives maintained by WorkOS (acquired Radix in 2024). It is the foundation under shadcn/ui (which adds Tailwind styling on top), Park UI, and many production component libraries from companies like Vercel, Linear, Resend, and Cal.com. Update (verified 2026-08-21): the shadcn/ui half of that has changed — as of the July 2026 changelog entry "Base UI as the Default", new shadcn/ui projects default to Base UI, the newer headless library from the same authors. Radix is explicitly not deprecated there and stays fully supported (shadcn init -b radix), but it is no longer shadcn/ui's default base. The primitives implement complex behavior (focus management, ARIA, keyboard navigation, escape-key handling, click-outside detection, portals, animations) while leaving 100% of the visual styling up to you.

For agent / UI builders Radix is the correct default for any custom design system: it removes 80% of the accessibility bugs that custom dialog / popover / dropdown / combobox implementations ship with, while imposing zero visual opinion.

What Radix gives you

Each primitive comes as a set of composable parts:

import * as Dialog from "@radix-ui/react-dialog";

function MyDialog() {
  return (
    <Dialog.Root>
      <Dialog.Trigger asChild>
        <button>Open</button>
      </Dialog.Trigger>
      <Dialog.Portal>
        <Dialog.Overlay className="fixed inset-0 bg-black/50" />
        <Dialog.Content className="fixed top-1/2 left-1/2 -translate-x-1/2 -translate-y-1/2 bg-white p-6 rounded-lg">
          <Dialog.Title>Title</Dialog.Title>
          <Dialog.Description>Description text</Dialog.Description>
          <Dialog.Close asChild>
            <button>Close</button>
          </Dialog.Close>
        </Dialog.Content>
      </Dialog.Portal>
    </Dialog.Root>
  );
}

Behind the scenes Radix manages:

  • Focus trap while the dialog is open.
  • Initial focus on the first focusable element.
  • Focus return to the trigger when closed.
  • Escape-key closes.
  • Click-outside closes (configurable).
  • Inert background content.
  • ARIA attributes (aria-modal, aria-labelledby, aria-describedby).
  • Portal rendering to document.body.
  • Scroll lock on body while open.

These are precisely the things naïve hand-rolled modals get wrong.

The asChild pattern

The most-loved Radix idiom: instead of forcing a <button>, let the caller pass any element via asChild:

<Dialog.Trigger asChild>
  <Link href="/about">About</Link>
</Dialog.Trigger>

This composes the Dialog.Trigger's behaviors (click handler, ARIA, etc.) onto the Link instead of nesting <Link><button>...</button></Link>. Powered by @radix-ui/react-slot.

Installation

Update (verified 2026-08-21): the per-primitive install shown below is no longer what the docs recommend. Radix now ships a single unified radix-ui package (npm radix-ui, latest 1.6.7, 2026-07-24), and radix-ui.com/primitives/docs/overview/getting-started reads:

npm install radix-ui@latest


import { Popover } from "radix-ui";
// or, for bundlers that tree-shake better from subpaths:
import * as Popover from "radix-ui/popover";

The per-primitive subpath entry points (radix-ui/accordion, radix-ui/dialog, …) landed in the 20 July 2026 release. The old per-primitive packages are still published and are not deprecated — @radix-ui/react-dialog is at 1.1.23 and @radix-ui/react-slot at 1.3.3, both released 2026-07-24 — so existing installs keep working, but new code should use radix-ui.

The original per-primitive form, kept for reference:

npm install @radix-ui/react-dialog @radix-ui/react-dropdown-menu @radix-ui/react-tooltip

That avoided pulling in 30 primitives if you only used 3; the unified package solves the same problem through tree-shaking instead.

Radix Themes

In 2023 Radix launched Radix Themes (@radix-ui/themes) — an opinionated styled library on top of the primitives, with theme tokens, presets, and ready-to-use styled components. As of May 2026 Themes is a viable alternative to shadcn/ui for teams wanting a more turnkey solution.

npm install @radix-ui/themes


import "@radix-ui/themes/styles.css";
import { Theme, Button, Card } from "@radix-ui/themes";

<Theme accentColor="indigo" grayColor="slate" radius="medium" appearance="dark">
  <Card><Button>Hello</Button></Card>
</Theme>

Themes provides ~50 styled components, design tokens, and dark mode out of the box.

Radix Colors

@radix-ui/colors is a scale-based color system with 12 steps per scale, designed for accessibility and consistent contrast across light/dark modes.

@import "@radix-ui/colors/blue.css";
@import "@radix-ui/colors/blue-dark.css";

.button-primary {
  background: var(--blue-9);
  color: var(--blue-12);
}

Each step has known semantic meaning (1 = page background, 9 = solid colored background, 11 = low-contrast text, 12 = high-contrast text). Used by shadcn/ui's color variables and Radix Themes.

Radix Icons

@radix-ui/react-icons ships 350+ MIT-licensed React icons matched to Radix's visual style.

import { CheckIcon, Cross1Icon } from "@radix-ui/react-icons";

Animation

Radix exposes data attributes (data-state="open", data-state="closed") so you can animate via CSS or Framer Motion:

.dialog-content {
  animation: contentShow 200ms cubic-bezier(0.16, 1, 0.3, 1);
}
.dialog-content[data-state="closed"] {
  animation: contentHide 200ms ease-out;
}

For Framer Motion integration there's @radix-ui/react-presence or use data-state with useReducedMotion().

Common gotchas

  • ~~Each primitive is a separate package — no single @radix-ui import.~~ (No longer true; corrected 2026-08-21.) A single unstyled package, radix-ui, now exports every primitive as a namespace (import { Dialog } from "radix-ui"), with radix-ui/<primitive> subpaths for finer tree-shaking. @radix-ui/themes remains the separate styled bundle.
  • asChild needs a single React element child — passing two children breaks. Wrap in a fragment? Doesn't help — Slot needs exactly one element.
  • Portal defaults to document.body — for shadow-DOM or testing, customize container={el}.
  • Tooltip + click-on-touch — touch devices don't have hover; Radix Tooltip falls back to long-press but UX can be confusing. Consider HoverCard or a different pattern on mobile.
  • Form primitive validates client-side — server validation needs to flow back via the serverInvalid prop.
  • SSR considerations — most Radix primitives work fine SSR; Portal renders to document.body which doesn't exist server-side, so use <noscript>-style fallbacks if rendering server-side modals.
  • Versions are per-primitive — @radix-ui/react-dialog@1.x and @radix-ui/react-dropdown-menu@2.x can coexist; align majors where possible.
  • Themes and standalone primitives compose but conflict in CSS variables — using both requires careful CSS-variable namespace coordination.
  • React 19 compat — Radix has been React-19-compatible since 2024; older Radix versions may need updating.
