Overview

Envoy is a high-performance C++ L4/L7 proxy originally built at Lyft (2015), open-sourced 2016, accepted to CNCF 2017-09-13 and graduated 2018-11-28 as CNCF's third graduated project after Kubernetes and Prometheus. It is the data plane underneath every major service mesh and most modern API gateways: Istio, Consul Connect, Gloo, Contour, AWS App Mesh, GCP's Service Directory / HTTPS LB, and every Gateway API implementation except Linkerd (which uses its own Rust proxy) and Cilium (Envoy is embedded but optional for Layer-7). If you run Istio or Kubernetes Gateway API, you run Envoy. Current stable is v1.38.0 (2026-04-23).

Envoy follows a fixed quarterly cadence: a new minor on the 15th of Jan/Apr/Jul/Oct, with 12 months of support afterwards (security + stability backports). Plan an upgrade at least once per year, since skipping four quarters drops you off the security policy.

Architecture

Envoy is a single-process, multi-threaded, shared-nothing, non-blocking event-driven proxy. Each worker thread owns its own event loop, listener sockets (SO_REUSEPORT), connection pools, and xDS state snapshot. Threads do not share connection state, which is why Envoy scales linearly with CPU but why stats across workers require explicit aggregation.

The core object graph, outer to inner:

ObjectScopeRole

Listenerper IP:portNamed bind socket (TCP/UDP/pipe), accepts downstream connections
Listener filter chainper listenerPre-TLS inspection: SNI, ALPN, PROXY protocol, JA3/JA4, original_dst
Filter chainper listenerSelected by SNI/ALPN/source/destination match; holds network filters
Network filterL4tcp_proxy, http_connection_manager, redis_proxy, mysql, ...
HTTP connection managerinside L4Decodes HTTP/1.1, HTTP/2, HTTP/3, runs L7 filter chain, router
HTTP filterL7router, ext_authz, rbac, oauth2, jwt_authn, ratelimit
Router / Route tableL7Matches path/headers/query to a cluster
Clusterper upstreamGroup of logically similar upstream hosts, LB policy, outlier, HC
Endpoint / Hostper IP:portA single upstream address; health state, weight, locality

A request flows: downstream TCP, listener accept, listener filters (SNI), filter chain match, HTTP connection manager, L7 filter chain (authn, authz, rate limit), router, cluster LB pick, upstream pool, upstream endpoint.

Terminology reminder: downstream is the client side (talks into Envoy); upstream is the backend side (Envoy talks out). Request headers that carry client identity (x-forwarded-for, x-envoy-external-address) are always viewed from Envoy's perspective — from downstream.

Hot restart, drain, and graceful shutdown are first-class: a new Envoy binary can take over listening sockets from the old one without dropping connections, and listeners can be drained individually.

xDS — Dynamic Configuration

Envoy can be fully static (single YAML) or driven by a control plane via the xDS family of APIs. Every xDS variant is a gRPC bidi stream (or REST long-poll) that pushes configuration resources by type:

ServiceResource typeManages

LDSListenerBound sockets and their filter chains
RDSRouteConfigurationVirtual hosts and route tables
CDSClusterUpstream cluster definitions (no endpoints)
EDSClusterLoadAssignmentEndpoints (addresses) for a cluster
SDSSecretTLS certificates and keys (certificate/CA)
VHDSVirtual host (in RDS)On-demand per-virtual-host routes
SRDSScopedRouteConfigurationScoped route tables (rare)
ECDSExtensionConfigDynamic per-filter config
RTDSRuntime (key/value)Runtime feature flags

ADS (Aggregated Discovery Service) multiplexes all of the above onto a single gRPC stream. ADS is the only way to get consistent sequencing across xDS types (e.g. CDS before EDS before LDS/RDS), which is essential to avoid the "cluster not found" or "no healthy endpoints" race on startup or reconnect. Istio, Consul, and most modern control planes default to ADS.

Two wire-protocol variants exist:

  • State-of-the-World (SotW) — every response contains the full set of subscribed resources. Original protocol. Simpler, higher CPU/network on large configs.
  • Delta xDS (incremental) — responses contain only added/changed/removed resources. Lower steady-state cost; harder to reason about.

Every response carries a version_info and a nonce; the client ACKs by echoing the nonce in its next request (empty error_detail means ACK, non-empty means NACK). NACKs are sticky — the control plane keeps retrying until the client ACKs a good config.

Minimal Listener + HTTP Connection Manager (static YAML)

static_resources:
  listeners:
  - name: listener_http
    address:
      socket_address: { address: 0.0.0.0, port_value: 10000 }
    filter_chains:
    - filters:
      - name: envoy.filters.network.http_connection_manager
        typed_config:
          "@type": type.googleapis.com/envoy.extensions.filters.network.http_connection_manager.v3.HttpConnectionManager
          stat_prefix: ingress_http
          codec_type: AUTO
          access_log:
          - name: envoy.access_loggers.stdout
            typed_config:
              "@type": type.googleapis.com/envoy.extensions.access_loggers.stream.v3.StdoutAccessLog
          route_config:
            name: local_route
            virtual_hosts:
            - name: backend
              domains: ["*"]
              routes:
              - match: { prefix: "/api/" }
                route:
                  cluster: backend_api
                  timeout: 15s
                  retry_policy:
                    retry_on: "5xx,reset,connect-failure,refused-stream"
                    num_retries: 2
                    per_try_timeout: 5s
              - match: { prefix: "/" }
                direct_response:
                  status: 404
                  body: { inline_string: "not found" }
          http_filters:
          - name: envoy.filters.http.router
            typed_config:
              "@type": type.googleapis.com/envoy.extensions.filters.http.router.v3.Router

  clusters:
  - name: backend_api
    connect_timeout: 2s
    type: STRICT_DNS
    dns_lookup_family: V4_ONLY
    lb_policy: LEAST_REQUEST
    load_assignment:
      cluster_name: backend_api
      endpoints:
      - lb_endpoints:
        - endpoint:
            address:
              socket_address: { address: backend.svc, port_value: 8080 }
    health_checks:
    - timeout: 2s
      interval: 10s
      unhealthy_threshold: 3
      healthy_threshold: 2
      http_health_check: { path: "/healthz" }
    outlier_detection:
      consecutive_5xx: 5
      base_ejection_time: 30s
      max_ejection_percent: 50
    circuit_breakers:
      thresholds:
      - priority: DEFAULT
        max_connections: 1024
        max_pending_requests: 1024
        max_requests: 1024
        max_retries: 3

The filter order in http_filters is load-bearing: router must be last (it terminates the filter chain). ext_authz, rbac, jwt_authn, oauth2 go before router; mutation filters (lua, wasm) usually go before authz so they can set headers the authz filter reads.

Clusters & Load Balancing

Cluster discovery types:

  • STATIC — addresses fixed in YAML
  • STRICT_DNS — gethostbyname every dns_refresh_rate, full set
  • LOGICAL_DNS — one address at a time (round-robin on each new connection)
  • EDS — endpoints pushed via xDS (mesh default)
  • ORIGINAL_DST — address taken from the downstream socket's SO_ORIGINAL_DST (iptables redirect)

Load-balancing policies:

PolicyUse for

ROUND_ROBINSafe default for uniform backends
LEAST_REQUESTNon-uniform backends or variable latency
RING_HASHSticky sessions (consistent hashing)
MAGLEVLow-variance consistent hashing (65537-entry table lookup)
RANDOMOnly when you need to avoid LB coordination
LOCALITY_WEIGHTEDZone/region-aware traffic steering

Outlier detection (passive health check) and active health_checks are separate — an endpoint is excluded only if the cluster marks it unhealthy by EITHER mechanism. A cluster with only active health checks but no outlier detection will keep routing to a silently misbehaving host that returns 5xx but answers TCP.

Security Posture

Per the upstream threat model, Envoy's data plane is hardened against untrusted downstream and upstream peers — the proxy expects that client and server traffic may be malicious. The control plane (xDS) is assumed trusted; wire-level xDS exploits are not in-scope, but configuration content (regexes, match rules) from multi-tenant sources must still be safe.

Default config is NOT safe for availability. The upstream docs say this explicitly: memory, CPU, and connection limits must be configured. Production operators MUST set:

  • overload_manager with RSS and CPU actions (shrink heap, stop accepting new connections, drain)
  • Per-cluster circuit_breakers (connections, pending requests, retries)
  • Listener per_connection_buffer_limit_bytes and HCM max_request_headers_kb
  • HTTP/2 max_concurrent_streams (default 100, raise only after measuring backend impact)
  • A drain_timeout (default 600s) lower than your rolling-restart budget

Envoy classifies every extension by security posture:

  • robust_to_untrusted_downstream_and_upstream — suitable for edge deployments (routing, TLS, HTTP/1,2,3 codecs, router, rbac, ext_authz core)
  • robust_to_untrusted_downstream — OK to expose to internet on the downstream side only
  • requires_trusted_downstream_and_upstream — mesh-internal only (most contrib filters)
  • unknown — do not expose to untrusted traffic

Run envoy --extension-security-details to see the posture of every compiled-in extension.

What Changed in v1.38.0 (2026-04-23)

1. enforce_rsa_key_usage now defaults to true on upstream TLS. TLS handshakes fail if the peer cert has a keyUsage extension incompatible with the key type. The flag itself will be removed in v1.39 — test this before upgrading.
2. tcp_proxy.max_early_data_bytes is now required when upstream_connect_mode is ON_DOWNSTREAM_DATA or ON_DOWNSTREAM_TLS_HANDSHAKE (not IMMEDIATE). Existing configs without the field fail validation at startup. Revert with explicit max_early_data_bytes: 0.
3. On-demand CDS no longer performs internal redirects after a successful CDS fetch; earlier filters (ext_authz, ratelimit) are no longer invoked twice. Opt-out: envoy.reloadable_features.on_demand_cluster_no_recreate_stream.
4. BoringSSL/FIPS flag rename: --define=boringssl=fips removed; use --config=boringssl-fips.
5. OpenSSL build alternative: --config=openssl selects OpenSSL over BoringSSL. HTTP/3 (QUIC) is disabled in OpenSSL builds, and OpenSSL builds are explicitly NOT covered by the Envoy security policy. This is a regulatory-compliance option (FIPS-140 outside BoringSSL FIPS), not a production recommendation.
6. Dynamic Modules vastly expanded: new extension points for TLS cert validators, custom clusters, LB policies, tracers, listener/UDP listener filters, bootstrap extensions; Rust SDK gains declare_all_init_functions! and an opt-in CatchUnwind panic wrapper. Modules built against the v1.38 SDK are forward-ABI-compatible with v1.39.
7. MCP (Model Context Protocol) router gained full method coverage: resources/list|read|subscribe|unsubscribe, resources/templates/list, prompts/list|get, completion/complete, logging/setLevel, notifications/cancelled, notifications/roots/list_changed. SSE streaming for tools/call and fan-out aggregation for tools/list, initialize, resources/list, prompts/list. New MCP JSON REST Bridge filter transcoding JSON-RPC to REST. Parsing for the A2A (Agent2Agent) JSON-RPC protocol added.
8. Coalesced LB rebuilds during EDS batch host updates — significant CPU-spike reduction on large clusters (10k+ endpoints). Zero-config; just upgrade.
9. OAuth2 improvements: per-route configuration, TLS_CLIENT_AUTH (RFC 8705 mTLS client authentication), OauthExpires cookie cleared on logout. The oauth2_encrypt_tokens runtime guard was removed — encryption is now the default, opt out via disable_token_encryption.
10. ext_authz gained shadow_mode (writes the decision to filter state without terminating requests — great for gradual rollouts), path_override, and honoring status_on_error on 5xx/HTTP-call failures.
11. RBAC header matcher now validates each header value individually (behind a runtime guard) to prevent concatenation-based bypasses (CVE-2026-26308 family). Query-parameter values added via query_parameter_mutations are now URL-encoded.
12. timeout: 0s now means "no timeout" on HTTP ext_authz and HTTP rate-limit filters. Previously 0s meant "immediate timeout" (i.e. all requests failed authz). Breaking for configs that set 0s intentionally.
13. Prometheus admin endpoint supports the protobuf exposition format and native histograms — meaningful improvement for high-cardinality stat sets over the text format.
14. cgroup v2 support in the CPU-utilization resource monitor, with automatic v1/v2 detection. Finally fixes the long-standing "cgroup v2 host reports 0% CPU" issue on modern systemd distros.
15. Per-connection SPIFFE trust-domain selection — lets a single Envoy serve multiple SPIFFE trust domains on different connections. Reduces file-watch overhead; supports watched_directory for atomic cert swaps. Pairs with Cosign/Sigstore SPIFFE OIDC verification.
16. New sse_to_metadata HTTP filter extracts values from SSE event streams into dynamic metadata (built for LLM token-usage metrics). New file_server HTTP filter serves static files directly from disk.
17. HTTP/2 max_header_field_size_kb raises the nghttp2 64 KiB per-header cap (for extremely large tokens); the nghttp2 CVE-2026-27135 patch is applied.
18. HickoryDnsResolver — DNS resolver backed by Hickory DNS (pure-Rust) as an alternative to c-ares.
19. Router returns DEADLINE_EXCEEDED (instead of UNAVAILABLE) on router-enforced gRPC timeouts. Opt-in; breaks dashboards and alerts that match on UNAVAILABLE.
20. Contrib binaries now carry a -contrib version suffix. Pin your container image tags.

--concurrency N sets the worker-thread count (default = hardware concurrency). Set it explicitly in containers — the default reads the host CPU count, not the cgroup quota, so a 2 vCPU pod on a 128-core host otherwise spins up 128 worker threads.

Minimum Production Recipe

# 1. Run pinned, signed image (keyless verify with cosign; see Cosign entry)
IMAGE=envoyproxy/envoy:v1.38.0
cosign verify --certificate-identity-regexp '^https://github.com/envoyproxy/envoy/' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  "$IMAGE"

# 2. Pin --concurrency to CPU request (not host cores)
envoy -c /etc/envoy/envoy.yaml --concurrency 2 \
  --drain-time-s 60 --drain-strategy immediate \

# 3. Admin on localhost ONLY (0.0.0.0 = remote shutdown + cert dump)
# admin: { address: { socket_address: { address: 127.0.0.1, port_value: 9901 } } }

Gotchas

1. Default config is NOT safe for availability. No circuit breakers, no overload manager, no concurrency caps. Copy-pasted tutorial configs WILL OOM under load. Upstream docs say this explicitly in the threat model.
2. Admin interface on 0.0.0.0 is remote code execution. /quitquitquit kills the process, /reset_counters nukes stats, /config_dump?include_eds leaks your entire topology, /certs dumps in-memory keys. Bind to 127.0.0.1 always, or gate with network policy.
3. --concurrency reads host CPU by default, not the cgroup quota. Inside containers, set it to the CPU request, since otherwise a 2-core pod spins 128 worker threads, each with its own xDS state and connection pools, and OOMs.
4. Filter order is load-bearing. router must be last. Authz filters after mutation filters mean mutation can bypass authz. ext_authz before rbac means RBAC runs on authz-mutated headers; swap at peril.
5. HTTP/2 max_concurrent_streams default is 100 on downstream; the upstream default (to servers) varies. Raising it without raising backend capacity is a classic DoS amplifier.
6. request_timeout vs route timeout vs per_try_timeout are three different knobs. request_timeout is per-request inside HCM and covers the full request including retries; route timeout covers one try (plus retries of that try); per_try_timeout covers a single attempt. The three can blow out retry budgets silently.
7. Outlier detection needs traffic to work. With low RPS, consecutive_5xx: 5 never trips. Pair it with active health_checks or a lower threshold.
8. Hash-based LB requires hash-key stability. If the hash is the session cookie and a proxy strips it upstream, every request rehashes and sticky sessions are lost silently.
9. ADS is the only way to get consistent xDS sequencing. Without ADS, a control plane that pushes LDS before CDS causes a burst of "cluster not found" responses. Istio and Consul default to ADS; custom control planes often do not.
10. xDS NACKs are sticky. A single bad config push makes the client NACK forever until the control plane withdraws OR the client restarts. envoy.config_update_rejected and the xds.client stats are the canaries; alert on them.
11. Hot restart requires the parent and child to share a cgroup and file-lock path. Running the new binary in a different container or namespace defeats the feature; the new binary silently starts fresh.
12. drain_timeout: 600s is the default. Rolling restarts that set a 30-second terminationGracePeriodSeconds SIGKILL Envoy mid-drain and drop in-flight requests. Lower drain_timeout to match your pod grace period.
13. STRICT_DNS caches records per the resolver's TTL. If an operator expects 5-second failover, set dns_refresh_rate and respect_dns_ttl: false explicitly, or move to EDS.
14. ORIGINAL_DST clusters are iptables-dependent. Without SO_ORIGINAL_DST (i.e. no iptables redirect upstream), endpoints are never populated and requests fail with "no healthy upstream".
15. Stats explode with cardinality. envoy_cluster_*_upstream_rq_time per cluster per response code per per-try = hundreds of thousands of series for a large mesh. Use stats_config.stats_matcher (v1.38 added cluster-level and listener-level matchers) to suppress — Prometheus will OOM otherwise.
16. Lua filter is single-threaded per worker and runs every request. A 5 ms Lua script caps p99 at 5 ms. For CPU-bound logic, use WASM or an external filter via ext_proc.
17. WASM filter VMs are per-worker-thread. Shared state across workers requires shared_data explicitly; simple locals do not cross workers.
18. Envoy's HTTP/3 QUIC support in OpenSSL builds is NOT in the security policy. New in v1.38. BoringSSL builds are the supported path for HTTP/3.
19. timeout: 0s semantics flipped in v1.38 for HTTP ext_authz and HTTP rate-limit filters — from "immediate timeout" to "no timeout". Audit configs that explicitly set 0s.
20. Deleting a listener over xDS does NOT close existing connections — the listener is removed from the accept path, but in-flight streams continue until their own timeouts. For eviction, combine listener removal with drain_listeners?graceful against the admin.

Envoy wins where you need: (a) dynamic configuration over gRPC streams, (b) uniform L4/L7 observability (stats, tracing, access logs), (c) broad protocol matrix (HTTP/1.1, HTTP/2, HTTP/3, gRPC, Redis, Thrift, MySQL, Postgres TLS inspection, MCP, A2A, Kafka-metadata). It loses where you need a single-file static config (NGINX/HAProxy are simpler) or minimal memory footprint in a sidecar (Linkerd2-proxy is 3-5x smaller RSS).
