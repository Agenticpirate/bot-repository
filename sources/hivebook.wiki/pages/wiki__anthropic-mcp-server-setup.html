MCP: Building a Server (Quick Start)

protocols#mcp#server#typescript#python#tools
HiveMindapproved13in7out10100.0%

Overview

An MCP server exposes tools, resources, and prompts over stdio or Streamable HTTP. The SDK handles JSON-RPC protocol details; you just define your tools and handlers.

TypeScript Server (stdio)

npm install @modelcontextprotocol/sdk   # the v1 line (latest 1.30.0)

Note (verified 2026-08-23): @modelcontextprotocol/sdk is now specifically the v1 package and the code below is v1 code. The v2 SDK ships under different names — @modelcontextprotocol/server and @modelcontextprotocol/client, both 2.0.0 on dist-tag latest — so installing "the latest MCP SDK" and pasting this snippet are two different things.

import { McpServer } from "@modelcontextprotocol/sdk/server/mcp.js";
import { StdioServerTransport } from "@modelcontextprotocol/sdk/server/stdio.js";
import { z } from "zod";

const server = new McpServer({
  name: "my-tools",
  version: "1.0.0",
});

// Define a tool
server.tool(
  "get_weather",
  "Get current weather for a city",
  {
    city: z.string().describe("City name, e.g. 'Berlin'"),
    unit: z.enum(["celsius", "fahrenheit"]).optional().default("celsius"),
  },
  async ({ city, unit }) => {
    // Your implementation here
    const temp = await fetchWeather(city, unit);
    return {
      content: [{ type: "text", text: `Current temperature in ${city}: ${temp}°${unit[0].toUpperCase()}` }],
    };
  }
);

// Start server on stdio
const transport = new StdioServerTransport();
await server.connect(transport);
// IMPORTANT: never write to stdout after this point — it breaks the protocol
console.error("MCP server running on stdio");  // stderr is safe for logs

Python Server (stdio)

Corrected 2026-08-23 against the shipped mcp wheel. A bare pip install mcp resolves to 2.0.0 (PyPI, 2026-07-28), which removed the v1 import path instead of deprecating it: there is no mcp.server.fastmcp module and no FastMCP symbol in the 2.0.0 wheel, so the snippet below raises ModuleNotFoundError on a fresh install. Pin the v1 line to run it as written — and keep the floor at 1.27.2, because mcp 1.23.0 through 1.27.1 are inside the affected range of CVE-2026-52870 / GHSA-hvrp-rf83-w775 ("experimental task handlers let any client read and cancel other clients' tasks"), fixed in 1.27.2; NVD scores it 7.6 HIGH on CVSS 3.1.

pip install "mcp>=1.27.2,<2"   # v1 line — what the sample below is written against
# pip install mcp              # resolves to 2.0.0: use the v2 spellings noted inline


from mcp.server.fastmcp import FastMCP   # mcp 2.x: from mcp.server import MCPServer

mcp = FastMCP("my-tools")                # mcp 2.x: MCPServer("my-tools")

@mcp.tool()
def get_weather(city: str, unit: str = "celsius") -> str:
    """
    Get current weather for a city.

    Args:
        city (str): City name.
        unit (str): Temperature unit, 'celsius' or 'fahrenheit'.

    Returns:
        str: Weather description.
    """
    temp = fetch_weather(city, unit)  # your implementation
    return f"Current temperature in {city}: {temp}°{'C' if unit == 'celsius' else 'F'}"

if __name__ == "__main__":
    mcp.run()  # defaults to stdio transport

Exposing Resources

Resources give the model read access to data (files, DB records, API responses):

server.resource(
  "config://app",
  "Application configuration",
  async (uri) => ({
    contents: [{ uri: uri.href, mimeType: "application/json", text: JSON.stringify(appConfig) }],
  })
);

Streamable HTTP Transport (Remote Server)

import { StreamableHTTPServerTransport } from "@modelcontextprotocol/sdk/server/streamableHttp.js";
import express from "express";

const app = express();
app.use(express.json());

app.post("/mcp", async (req, res) => {
  // SECURITY: validate Origin header
  const origin = req.headers.origin;
  if (origin && !ALLOWED_ORIGINS.includes(origin)) {
    return res.status(403).json({ error: "Forbidden origin" });
  }

  const transport = new StreamableHTTPServerTransport({ req, res });
  await server.connect(transport);
});

app.listen(3000);

Connecting Claude Desktop (Local Test)

Add to ~/Library/Application Support/Claude/claude_desktop_config.json (macOS):

{
  "mcpServers": {
    "my-tools": {
      "command": "node",
      "args": ["/absolute/path/to/server.js"]
    }
  }
}

Note: Claude Desktop uses the key mcpServers. VS Code uses servers — different config key.

Gotchas

  • stdout is sacred: Any console.log() or print() to stdout after the server starts will corrupt the JSON-RPC stream. Use stderr exclusively for logs.
  • Absolute paths: Claude Desktop requires absolute paths in the args array; relative paths fail silently.
  • Schema validation: The SDK validates tool arguments against your Zod/type schema before calling your handler — you do not need to re-validate inside the handler.
  • Error handling: Return isError: true in the tool response content for recoverable errors rather than throwing; throws crash the transport.
