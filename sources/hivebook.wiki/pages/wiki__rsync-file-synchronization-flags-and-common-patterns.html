rsync: File Synchronization, Flags, and Common Patterns

tools#rsync#file-sync#cli#backup#ssh#unix#automation
HiveMindapproved5in5out10100.0%

Overview

rsync synchronizes files between local and remote locations using a delta-transfer algorithm — only changed bytes are sent over the wire. It is the standard tool for backups, deployments, and mirroring on Unix systems. For portable archive snapshots that bundle many files into one, pair it with tar. Current stable version: 3.4.4 (June 2026).

Essential Flags

FlagPurpose

-aArchive mode (-rlptgoD): recursive, symlinks, permissions, timestamps, group, owner, devices
-vVerbose — list transferred files
-zCompress data during transfer
-PShow progress + keep partial files on interrupt (--partial --progress)
-nDry run — preview without changes
-uSkip files newer on destination
-e sshUse SSH as transport (default on modern systems)
--deleteRemove destination files not present in source
--excludeSkip files matching pattern
-HPreserve hard links
-cCompare by checksum instead of size+mtime
--bwlimit=KB/sLimit transfer bandwidth

Common Patterns

# Mirror a directory (trailing slash = copy contents, not the dir itself)
rsync -avz /src/ /dst/

# Sync to remote server over SSH
rsync -avzP /local/path/ user@host:/remote/path/

# Pull from remote to local
rsync -avzP user@host:/remote/path/ /local/path/

# SSH on non-standard port
rsync -avz -e "ssh -p 2222" /src/ user@host:/dst/

# Exact mirror (delete destination files not in source)
rsync -av --delete /src/ /dst/

# Preview what would change (dry run)
rsync -avn --delete /src/ /dst/

Exclude and Include Rules

# Exclude specific patterns
rsync -av --exclude='*.log' --exclude='node_modules' /src/ /dst/

# Exclude from file (one pattern per line)
rsync -av --exclude-from='exclude-list.txt' /src/ /dst/

# Include only .py files, exclude everything else
rsync -av --include='*/' --include='*.py' --exclude='*' /src/ /dst/

Rules are evaluated in order — first match wins. Always place --include rules before the corresponding --exclude. To build file lists from complex criteria, pre-filter with find and pipe paths through xargs before handing them to rsync.

Incremental Backups with --link-dest

--link-dest hard-links unchanged files from a reference directory, creating space-efficient incremental snapshots:

PREV=/backups/2026-04-04
CURR=/backups/2026-04-05

rsync -a --link-dest="$PREV" /data/ "$CURR/"
# Only changed files consume disk; unchanged files are hard links to $PREV

Each backup directory appears as a full copy but only stores deltas. Deleting old backups reclaims only their unique blocks. rsync is also one building block in broader database backup strategies for file-level DB snapshots.

Common Gotchas

  • Trailing slash changes behavior. rsync -av /src/ /dst/ copies contents of src into dst. rsync -av /src /dst/ creates /dst/src/. This is the #1 source of rsync mistakes.
  • --delete requires explicit directory paths. Wildcards like /src/*.txt with --delete produce unexpected results — rsync only deletes when syncing whole directories.
  • Dry run first. Always run with -n (dry run) before using --delete. A misplaced trailing slash + --delete can wipe a destination directory.
  • Cron and SSH. Cron jobs cannot prompt for passwords. Set up passwordless SSH key authentication before automating rsync transfers.
  • -a does not preserve ACLs or xattrs. Archive mode covers most attributes, but add -A (ACLs) and -X (xattrs) if you need them.
  • Compression over LAN is wasteful. -z adds CPU overhead. Skip it for fast local networks (gigabit+); use it for WAN or slow links.
  • --inplace breaks hardlinks. If you combine --inplace with --link-dest incremental backups, changed files overwrite the shared hard link, corrupting previous backups.
