Neon: Database Branching for Dev/Preview

Overview

Neon's branching feature lets you create a full copy of your database in about one second using copy-on-write semantics — no data duplication at creation time, no waiting for a dump/restore. Each branch gets its own independent compute endpoint and connection string.

How Copy-on-Write Works

When you create a branch, Neon doesn't copy any data. Instead it marks the current WAL (Write-Ahead Log) position as a branch point. The new branch shares storage pages with the parent and only writes new pages when you modify data. This means:

  • Branch creation: ~1 second regardless of database size
  • Storage cost: zero until you modify data in the branch
  • Fully isolated: writes in a branch never affect the parent

# Create a branch via Neon CLI
neon branches create --name feature/new-schema --parent main

# List branches
neon branches list

# Delete a branch (does NOT affect parent)
neon branches delete feature/new-schema

Vercel Integration: Auto-Branch Per PR

The official Neon-Vercel integration automatically creates a database branch for every pull request:

1. PR opened → Neon creates a branch from main (or your configured parent)
2. Vercel preview deployment gets the branch's connection string as an env var
3. Preview environment has real data (from the parent branch), fully isolated
4. PR merged/closed → branch is automatically deleted

Configure in the Vercel Dashboard under Integrations → Neon, or via the Neon Console under Integrations → Vercel.

# The integration sets these env vars in your Vercel preview deployments:
DATABASE_URL=postgresql://...@ep-branch-xxx-pooler.us-east-2.aws.neon.tech/mydb
DATABASE_URL_DIRECT=postgresql://...@ep-branch-xxx.us-east-2.aws.neon.tech/mydb

Use Cases

Feature Branch Development

# Create a branch for your feature, run migrations against it
neon branches create --name feat/add-user-roles --parent main
export DATABASE_URL=$(neon branches get feat/add-user-roles --format=url)
npx drizzle-kit migrate
# develop, test, and iterate safely

Data Experiments / Analytics

Branch production data, run destructive analytics queries, discard the branch without touching production.

Staging Environment

Create a long-lived staging branch from main. Run your CI tests against it. Periodically reset it:

# Reset staging branch to match current main
neon branches reset staging --parent main

Compute Endpoints

Each branch has its own compute endpoint (its own Postgres process). You can:

  • Configure different compute sizes per branch (e.g., smaller compute on dev branches)
  • Suspend a branch's compute manually to save CU hours
  • Each compute scales to zero independently
