Redis Data Types: Core Structures, Commands, and When to Use Each

Overview

Redis stores all data as key-value pairs, but the value can be one of many data structures — each with specialized commands and O(1) or O(log N) operations. Choosing the right type determines performance and memory efficiency. Redis 8.0 (GA 2025) consolidated JSON, time series, probabilistic structures, and vector search as built-in types — no separate modules needed.

Strings

Binary-safe, up to 512 MB. Not just text — use for serialized JSON, counters (INCR/DECR), and bitmaps. Strings back most caching strategies (cache-aside, write-through, TTL), and a SET … EX key is the storage layer behind session-based auth.

SET user:42:session "abc123" EX 3600    # expires in 1 hour
SETNX lock:order:99 "worker-1"          # set only if not exists (distributed lock)
INCR api:rate:192.168.1.1               # atomic counter

Lists

Doubly-linked list. O(1) push/pop at both ends. BLPOP/BRPOP for blocking queue consumers.

RPUSH queue:emails "{\"to\":\"a@b.com\"}"   # enqueue
BLPOP queue:emails 30                        # blocking dequeue (30s timeout)

Sets and Sorted Sets

Sets: unordered, unique members. Sorted sets: each member has a float score for ordering — score ranges implement sliding-window rate limiting.

SADD tags:article:1 "redis" "database" "nosql"
SINTER tags:article:1 tags:article:2           # common tags

ZADD leaderboard 1500 "player:42"              # score-based ranking
ZRANK leaderboard "player:42"                  # 0-based rank

Hashes

Field-value maps within a single key. Memory-efficient for small objects (listpack encoding under 128 fields / 64-byte values — called ziplist prior to Redis 7). Redis 8.0 added HGETEX, HSETEX, HGETDEL for atomic fetch-and-expire/delete.

HSET user:42 name "Alice" email "a@b.com" login_count 0
HINCRBY user:42 login_count 1

Streams

Append-only log with consumer groups (like Kafka, built into Redis). Each entry gets an auto-generated ID (<ms>-<seq>). For full coverage of XADD options, consumer-group semantics, XAUTOCLAIM, the Pending Entries List, idempotent producers (8.6+), and 25 operational gotchas, see Redis Streams.

XADD events * type "order" user_id "42"
XGROUP CREATE events processors $ MKSTREAM
XREADGROUP GROUP processors worker-1 COUNT 10 BLOCK 5000 STREAMS events >
XACK events processors 1680000000000-0

Common Gotchas

  • String max 512 MB but practical limit is much lower — large values block the single-threaded event loop during serialization.
  • KEYS command is O(N) over all keys — never use in production. Use SCAN with a cursor instead.
  • Sorted set scores are IEEE 754 doubles — integer precision is safe up to 2^53. Scores beyond that lose precision.
  • Hash listpack threshold: Hashes with >128 fields or values >64 bytes switch from memory-efficient listpack to hashtable encoding. Tune hash-max-listpack-entries and hash-max-listpack-value (aliases hash-max-ziplist-entries / hash-max-ziplist-value still work).
  • Streams grow unbounded — use MAXLEN or MINID with XADD to cap stream length, or XTRIM periodically.
  • Redis 8.0 ACL change: JSON, time series, and probabilistic commands now fall under standard @read/@write categories — users without +@write cannot execute JSON.SET.
