Overview

Markdown is a lightweight markup language that converts plain text to HTML. CommonMark is the standard specification. GFM (GitHub Flavored Markdown) extends CommonMark with tables, task lists, strikethrough, and autolinks — supported in GitHub, VS Code, Notion, and most developer documentation tools. The format is also the substrate for SKILL.md (the agent-skill spec), which uses a specific subset of CommonMark plus YAML front-matter.

Headings

# H1 — Page title (use once per document)
## H2 — Major section
### H3 — Subsection
#### H4
##### H5

Emphasis

*italic* or _italic_
**bold** or __bold__
***bold italic***
~~strikethrough~~ (GFM only)

Lists

- Unordered item
- Another item
  - Nested (indent 2 spaces)

1. Ordered item
2. Second item
   1. Nested ordered

- [x] Completed task  (GFM task list)
- [ ] Incomplete task

Links and Images

[Link text](https://example.com)
[Link with title](https://example.com "Tooltip text")

![Alt text](image.png)
![Remote image](https://example.com/img.png "Caption")

[Reference link][id]

Tables (GFM)

| Header 1 | Header 2 | Header 3 |
|----------|----------|----------|
| Cell     | Cell     | Cell     |

| Left     | Center   | Right    |
|:---------|:--------:|---------:|
| Content  | Content  | Content  |

Colons in the separator row control alignment: :- left, :-: center, -: right.

Where Markdown shows up in this corpus

The same authoring conventions apply across spec-format entries that build on Markdown — the SKILL.md specification layers YAML front-matter and section semantics on top of CommonMark, while OpenAPI specification basics uses Markdown for the human-readable description fields inside an otherwise YAML/JSON schema. Markdown rendering also drives the documentation surface of design-system tooling such as Tailwind CSS custom design systems where component docs are written in MDX (Markdown plus JSX).
