Ruff: Python Linter and Formatter — Configuration, Rule Sets, Suppressions, and What Changed in 0.15

Overview

Ruff is an extremely fast Python linter and formatter written in Rust by Astral. A single binary replaces Flake8, isort, pyupgrade, autoflake, eradicate, pydocstyle, parts of pylint, and Black, while running 10-100x faster than the legacy tools. Ruff 0.15.12 (2026-04-24) was current at this entry's baseline; as of 2026-08-26 the latest release is 0.16.4 (2026-08-20) and the 0.15 line ended at 0.15.22 (2026-07-16). Ruff is still pre-1.0 but production-ready and used by every major Python project (Pandas, FastAPI, Apache Airflow, Pydantic, Hugging Face Transformers, CPython itself for its devtools). Ruff is the linter half of Astral's Python tooling — pair it with uv for end-to-end Python workflows. Biome 2.4 is the JS/TS-side analogue — the same single-Rust-binary model with formatter, linter and import organizer in one tool. Other Python entries are indexed at Python (disambiguation).

Versioning and Release Cadence

Update (verified 2026-07-24): Ruff 0.16.0 was released 2026-07-23 with significant breaking changes: the default rule set jumps from 59 to 413 enabled rules (expect large new-diagnostic waves on upgrade - see the migration guide), Python code blocks in Markdown files are now formatted by default, new # ruff: ignore[...] suppression comments work like noqa, fixes are shown in check/format --check output, and several JSON output fields may now be null. The 0.15 line's final release is 0.15.22 (2026-07-16). This entry's feature baseline is 0.15; pin ruff==0.15.x until you have run the 0.16 migration.

Update (verified 2026-08-26): The 0.16 line is now at 0.16.4 (2026-08-20) — 0.16.1 (2026-07-30), 0.16.2 (2026-08-06), 0.16.3 (2026-08-13), 0.16.4 (2026-08-20), all on the Thursday cadence. The 0.15 baseline below still stands; what follows was re-derived from the shipped ruff==0.16.4 wheel rather than the docs:

  • No rule code was removed or renumbered between 0.15.12 and 0.16.4. ruff rule --all --output-format json returns 956 rules at 0.15.12 and 969 at 0.16.4 across the same 59 linter categories, and every 0.15.12 code still resolves at 0.16.4. The only rename is PYI033 type-comment-in-stub → legacy-type-comment (code unchanged). The "18 removed rules" in 0.16.0 were removed from the default set, not from the tool — select = ["E711"] still works.
  • No configuration key was removed and no boolean default was inverted. Diffing every ruff config <key> default between the two binaries yields four changes: lint.select (see below), include gains **/ruff.toml and **/.ruff.toml, and two new keys appear (output-prefer-rule-codes = false, lint.pylint.max-statements-in-try = 5). The config block in this entry is accepted verbatim by 0.16.4, and an unknown key is still a hard startup error, not a silent no-op.
  • The default-rule-set jump only bites projects that set no select. Measured over 400 real stdlib .py files: with no configuration, 1048 diagnostics at 0.15.12 versus 3848 at 0.16.4; with the select = ["E", "W", "F", "I", "B", "UP", "SIM"] block below, 4375 at both versions. Astral's migration guide restores the old behaviour with [lint] select = ["E4", "E7", "E9", "F"].
  • Python formatter output is unchanged. ruff format produced byte-identical output from 0.15.12 and 0.16.4 over those same 400 files. Ruff 0.16 ships no new style guide — the 2026 style guide is still the default. The one formatter behaviour change is Markdown.
  • ruff format now formats fenced Python inside Markdown by default. At 0.15.12 the same command errors with "Markdown formatting is experimental, enable preview mode"; at 0.16.4 it just reformats. *.md is already in the default include list on both lines, so a CI ruff format --check . that was green on 0.15 can go red on 0.16 with no configuration change.
  • The ruff: ignore family left preview. # ruff: ignore[F401] (end of line, or on the preceding logical line) and # ruff: file-ignore[F401] free-text reason both suppress on a plain ruff check at 0.16.4 with no --preview; at 0.15.12 the identical comment needs --preview. New --add-ignore[=<REASON>] inserts them automatically, and --add-noqa now takes an optional reason too.
  • JSON consumers should re-check. filename, location, end_location, fix.edits[].location and fix.edits[].end_location may now be null rather than "" / row 1 column 1. format --check also gained the linter's full --output-format set (concise, json, junit, github, gitlab, sarif, …), so the formatter step can annotate CI diffs the way the linter step does.
  • Nothing security-relevant, licence unchanged, project very much alive. OSV returns zero records for ruff on PyPI and on crates.io (queried 2026-08-26). LICENSE at tag 0.16.4 is MIT (Copyright 2022 Charles Marsh) followed by the vendored upstreams' own MIT texts, matching PyPI's license_expression: MIT; no carve-out arrived with the minor bump. commits/main.atom shows commits landing on 2026-08-26.

Configuration

Ruff reads (in priority order) pyproject.toml (under [tool.ruff]), ruff.toml, or .ruff.toml. The minimum useful config:

[tool.ruff]
line-length = 88            # default; matches Black
indent-width = 4            # default
target-version = "py312"    # falls back to project.requires-python if unset
exclude = [".venv", "build", "dist"]   # in addition to a sensible default list

[tool.ruff.lint]
select = ["E", "W", "F", "I", "B", "UP", "SIM"]   # rule sets to enable
ignore = ["E501"]                                  # line-too-long (formatter handles it)
fixable = ["ALL"]                                  # which rules `--fix` may auto-fix

[tool.ruff.format]
quote-style = "double"          # default (Black-compatible)
indent-style = "space"          # default
skip-magic-trailing-comma = false
docstring-code-format = true    # opt-in: format Python in docstrings
docstring-code-line-length = "dynamic"

Default select was ["E4", "E7", "E9", "F"] (a subset of pycodestyle errors plus all of Pyflakes) through 0.15.x — ruff check --show-settings --isolated on 0.15.12 enables exactly 59 rules. Ruff 0.16 replaced that with a curated 413-rule default set, verified the same way on 0.16.4: I001, plus much of B, UP, RUF, SIM, PT, S and others, are now on out of the box, while 18 opinionated rules were dropped from the default set (E401, E402, E701, E702, E703, E711, E712, E713, E714, E721, E731, E741, E742, E743, F403, F405, F406, F722 — all still selectable by hand). Complexity (C901) and E501 are off by default in both lines, and so is every W rule except W605. Setting select explicitly pins you out of all of this, which is why the numbers above are identical across the two versions for this config. select replaces the rule set; extend-select adds to it. Mixing the two is a common foot-gun.

Command-Line Interface

ruff check                    # lint current directory
ruff check src/               # lint specific path
ruff check --fix              # auto-fix what's safely fixable
ruff check --fix --unsafe-fixes  # also apply fixes that change behavior
ruff check --add-noqa         # add `# noqa` to suppress every existing violation
ruff check --statistics       # rule-frequency summary
ruff check --output-format=json    # machine-readable
ruff check --output-format=github  # GitHub Actions inline annotations
ruff check --output-format=concise # one-line per violation

ruff format                   # format current directory in place
ruff format --check           # exit 1 if any file would be reformatted (CI)
ruff format --diff            # show what would change without writing

ruff check --select I --fix && ruff format   # sort imports + format (no unified command yet)

ruff server                   # native LSP server (replaces deprecated ruff-lsp)
ruff config                   # print resolved settings for current dir
ruff rule E501                # describe a specific rule
ruff version                  # print version
ruff clean                    # delete `.ruff_cache` directories

ruff format does not sort imports. Run ruff check --select I --fix first; a unified command is on Astral's roadmap but still not shipped (re-verified against 0.16.4 on 2026-08-26).

Suppression Syntax

import unused_module  # noqa: F401          # suppress one rule on this line
import another  # noqa                       # suppress all rules on this line (discouraged)

# fmt: off
matrix = [
    1, 0, 0,
    0, 1, 0,    # don't reformat this block
    0, 0, 1,
]
# fmt: on

# ruff: noqa: F401              # file-level: suppress F401 across this whole file
# ruff: noqa                    # file-level: suppress everything

# Block suppression (Ruff 0.15+)
# ruff: disable[N803]
def legacy(legacyArg1, legacyArg2): ...
# ruff: enable[N803]

# Logical-line suppression: `--preview` on 0.15.11+, stable from 0.16.
# The codes MUST be bracketed. `# ruff:ignore PLR0913` suppresses nothing.
result = some_call(a, b, c)  # ruff: ignore[PLR0913]

# File-level, stable from 0.16, optional free-text reason after the bracket
# ruff: file-ignore[F401] Re-exported for backwards compatibility

# noqa must list exact rule codes — # noqa: E is a no-op (does not suppress all E rules). Block suppression # ruff: disable[X] requires a matching # ruff: enable[X] or it leaks to end of file. The # ruff: file-ignore[...] and # ruff: ignore[...] forms were preview-gated at 0.15.12. Update (verified 2026-08-26): both are stable from 0.16 — they suppress on a plain ruff check with no --preview, and ruff check --add-ignore[=<REASON>] inserts them for you. # ruff: disable[X] / # ruff: enable[X] is unchanged; an unmatched disable is caught by RUF104 (unmatched-suppression-comment) and a bracket-less comment by RUF103 (invalid-suppression-comment), but neither is in the 0.16 default rule set — add them to select if you use these comments at all.

The Ruff Formatter

ruff format is a drop-in replacement for Black with > 99.9% formatting equivalence on real-world code. Astral ships a new style guide each year:

  • 2025 style — default through Ruff 0.14.x
  • 2026 style — default in Ruff 0.15.x (released 2026-02-03) and still the default in 0.16.x; no 2027 style guide had shipped as of 2026-08-26, and ruff format output was byte-identical between 0.15.12 and 0.16.4 across 400 real Python files

Style guide changes are breaking within a major-zero series. Pinning ruff exact-version in CI prevents the formatter from rewriting your codebase when a new style ships. Specific 2026 changes worth knowing:

  • Lambda parameters stay on one line; lambda bodies parenthesize and break across multiple lines (was the reverse in 2025).
  • Python 3.14 target-version triggers PEP 758 unparenthesized except A, B, C: rewrites.
  • Single blank line at the start of function bodies is preserved (was stripped in 2025).
  • Alpine base image bumped to 3.23; Debian to 13 "Trixie".

The formatter exposes deliberately few knobs: quote-style, indent-style, line-ending, skip-magic-trailing-comma, docstring-code-format, docstring-code-line-length. Astral's stated philosophy is Black-style minimalism — most "config" requests are closed as wontfix.

Pre-commit Integration

# .pre-commit-config.yaml
repos:
  - repo: https://github.com/astral-sh/ruff-pre-commit
    rev: v0.16.4   # latest 2026-08-26; v0.15.22 is the last 0.15 tag
    hooks:
      - id: ruff
        args: [--fix]
      - id: ruff-format

The two hooks (ruff and ruff-format) are independent. args: [--fix] is required to enable auto-fixing — without it, the hook only reports violations and fails. On 0.16+ the ruff-format hook will also reformat Python blocks in your .md files; because pre-commit passes explicit paths, extend-exclude = ["*.md"] alone does not stop it — set force-exclude = true as well. See git hooks for the underlying mechanism.

GitHub Actions Integration

# .github/workflows/ruff.yml
name: Ruff
on: [push, pull_request]
jobs:
  ruff:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: astral-sh/ruff-action@v4.1.0
        with:
          version: 0.16.4   # pin exact
          args: "check --output-format=github"
      - uses: astral-sh/ruff-action@v4.1.0
        with:
          version: 0.16.4
          args: "format --check"

--output-format=github emits ::error file=...,line=... annotations that GitHub renders inline on PR diffs. Update (verified 2026-08-26): ruff-action is at v4.1.0 (2026-07-05); v4.0.0 (2026-04-12) moved to immutable releases, so there is no floating v4 tag — astral-sh/ruff-action@v4 returns 404 and you must pin a full version. @v3 still resolves (last moved 2026-01-30) but is a major version behind. Since 0.16, format --check accepts --output-format=github too, so the formatter step can annotate the diff the same way. One fail-open to know about: ruff-action verifies the download against a checksum table baked into the action at build time, and v4.1.0's table stops at 0.15.20 (src/download/checksum/known-checksums.ts at tag v4.1.0, 191 entries). For any newer pin — 0.15.22, or anything in the 0.16 line — validateChecksum() finds no key, logs at core.debug level and returns without validating; the step still goes green, just unverified. Pass the checksum: input explicitly to close that (the value is in the release's .sha256 sidecar, e.g. https://github.com/astral-sh/ruff/releases/download/0.16.4/ruff-x86_64-unknown-linux-gnu.tar.gz.sha256), and remember the value is per-platform, so it has to match your runner. See GitHub Actions limits for runner constraints.

Editor / LSP

Ruff ships its own native LSP server in the main ruff binary as of v0.4.5 (May 2024). Use ruff server to start it. The legacy ruff-lsp Python wrapper is archived — GitHub reports "This repository was archived by the owner on Dec 16, 2025. It is now read-only", so it receives no fixes at all, critical or otherwise (corrected 2026-08-26; this entry previously said it still received critical fixes, which was already untrue when it was written). Migrate any python -m ruff_lsp invocations to ruff server. The native LSP supports format-on-save, code actions, hover, and configuration auto-reload from pyproject.toml. VS Code's official Ruff extension, JetBrains' bundled support, and Helix / Zed all use the native server out of the box.

Common Gotchas

  • Pin the exact version in CI. Style-guide changes, default-rule-set changes and new-rule additions all ship in patch and minor versions. ruff==0.16.4 (or ruff==0.15.22 to stay on the old line) prevents a Thursday morning "all PRs failing" surprise — Ruff ships on Thursdays.
  • ruff format does not sort imports. Still true at 0.16.4 (re-checked 2026-08-26), and there is still no unified format-and-lint command — run ruff check --select I --fix first, otherwise import order drifts from what isort would produce. One 0.16 nuance: I001 is in the new default rule set, so on a project that sets no select a plain ruff check --fix now sorts imports without --select I.
  • select replaces, extend-select adds. Setting select = ["B"] disables Pyflakes; you almost always want extend-select = ["B"] instead.
  • # noqa: <category> is a no-op. Codes must be exact: # noqa: E501 works; # noqa: E silently does nothing. Use --add-noqa to bulk-suppress existing violations during onboarding.
  • Default config does NOT enable McCabe (C901), and enables almost no W. True on both lines — add them to select explicitly. Even the 413-rule 0.16 default set excludes C901, E501, and every W rule except W605 (checked with ruff check --show-settings --isolated on 0.16.4).
  • select = ["ALL"] enables conflicting rules. D203/D211, D212/D213, and several E/W pairs cannot coexist. Always pair ALL with an ignore list, or use extend-select with curated subsets.
  • Format-affecting rules conflict with the formatter. Disable E501 (line-too-long), W191 (tab indent), E111/E114/E117 (indent), D206, D300, Q000-Q003, and COM812/COM819/ISC001/ISC002 when running ruff format — the formatter handles them. Astral's docs ship a canonical [tool.ruff.lint] ignore = [...] list for the format-vs-lint conflict set.
  • Block suppression leaks if you forget enable. # ruff: disable[N803] without a matching # ruff: enable[N803] suppresses to end of file. Wrap each block tightly.
  • target-version defaults to py310 if not set and requires-python is missing. Corrected 2026-08-26 against the shipped binaries: this entry said py39, which stopped being true in 0.14.0 (2025-10-07), before the entry was written. ruff config target-version prints Default value: "py310" on both 0.15.12 and 0.16.4, and "py39" only as far back as 0.13.3. Set it explicitly, or set project.requires-python, rather than relying on a fallback that has already moved once.
  • Preview rules can change between minor versions. preview = true unlocks new rules earlier but rule names, codes, and behavior can change in 0.x.0 bumps. Pin exact versions if you depend on preview.
  • magic-trailing-comma forces multi-line formatting. A trailing comma in a function call or collection forces the formatter to break across lines. Set skip-magic-trailing-comma = true if you want the formatter to ignore them, but this conflicts with Black's default behavior.
  • docstring-code-format = true only formats fenced or doctest blocks. Plain indented code in docstrings is not formatted unless it sits inside a fenced python code block or follows a doctest >>> prompt (re-verified on 0.16.4).
  • ruff check --fix may apply behavior-changing fixes only with --unsafe-fixes. Without that flag, fixes that could alter runtime semantics (e.g., reordering function calls, changing is None checks) are skipped. Always review the diff after a first-time --unsafe-fixes run.
  • On 0.16+, ruff format reformats Python inside .md files by default. *.md is in the default include list on both lines, but ruff format README.md errors with "Markdown formatting is experimental, enable preview mode" on 0.15.12 and silently reformats on 0.16.4. Opt out with extend-exclude = ["*.md"] — and add force-exclude = true when paths are passed explicitly, which is exactly what pre-commit does, because an explicit path otherwise bypasses exclude. To keep Markdown formatting but skip one fence, wrap it in <!-- fmt: off --> / <!-- fmt: on --> HTML comments.
  • .ruff_cache/ is per-CWD. Add .ruff_cache/ to .gitignore. CI runners can persist it between runs (actions/cache@v4 keyed on pyproject.toml hash) for ~3-5x speedup on warm runs.
  • respect-gitignore = true is the default, but it only applies to directory traversal. Corrected 2026-08-26: this entry said Ruff skips gitignored files "even if you pass them explicitly". It does not — on 0.15.12 and 0.16.4 alike, ruff check gen.py lints a file listed in .gitignore, and only ruff check . skips it. That matters for pre-commit, which passes explicit paths. --no-respect-gitignore widens the directory scan to include ignored files; to actually keep an explicitly-named file out, use extend-exclude together with force-exclude = true, which does gate explicit paths (force-exclude has no effect on the .gitignore rule).
  • # fmt: off / # fmt: on are formatter-only. They don't suppress lint rules — use # ruff: noqa blocks for that.
  • per-file-ignores globs match recursively — "tests/*" is not one level deep. Corrected 2026-08-26: this entry claimed "tests/*" = ["S101"] ignores tests/foo.py but not tests/sub/foo.py. It ignores both, and tests/a/b/deep.py as well, on 0.15.12 and 0.16.4 alike — verified against a control run that reports S101 on all three paths with the mapping removed. Read "tests/*" as whole-subtree suppression, which is wider than it looks; to scope one file, name it ("tests/foo.py", which does narrow correctly).
  • Astral's ty type checker is separate. Ruff has never been a type checker; for typing see Python type hints. Astral's ty targets the mypy/pyright space but ships as a separate binary — still pre-1.0 at ty 0.0.74 (2026-08-22), which PyPI classifies as "Development Status :: 4 - Beta".
