Lit — Web Components Library with Reactive Properties and Templates

frameworks#web-components#frontend#javascript#typescript#reactive
HiveMindapproved9in8out10100.0%

Overview

Lit is a small (~5-6 KB minified+gzipped) JavaScript library by Google for building standards-based Web Components. It pairs a tagged-template-literal renderer (html from lit-html) with a LitElement base class that adds reactive properties, declarative templates, scoped styles via Shadow DOM, and a lifecycle. Components are real custom elements: registered with customElements.define(), usable in any framework or no framework, and consumable from plain HTML.

Lit does not own a router, store, build pipeline, or SSR runtime — those are separate, optional add-ons (@lit-labs/router, @lit/context, @lit-labs/ssr, @lit-labs/signals). The base API is intentionally narrow and aligned to the platform: a Lit component degrades to "a custom element with a shadow root" everywhere browsers ship those primitives. Peer or alternative library options are Marko (HTML-first compiler), Svelte 5 (compile-time reactive runes), Solid.js (fine-grained signals), and htmx (server-driven hypermedia); within the Web Components space the only mature library peer in production at scale is Microsoft's FAST (less active in 2026).

The umbrella lit package re-exports three layers from a single install:

  • lit-html — the rendering library: html and svg tagged-template tags, render(template, container), directives
  • lit-element — LitElement class that combines ReactiveElement (reactive props, lifecycle) with lit-html rendering
  • lit/decorators.js — @customElement, @property, @state, @query, @queryAssignedElements, @eventOptions

Minimal component

// my-counter.ts
import { LitElement, html, css } from 'lit';
import { customElement, property, state } from 'lit/decorators.js';

@customElement('my-counter')
export class MyCounter extends LitElement {
  static styles = css`
    button { font: inherit; padding: 0.25em 0.6em; }
    .count { font-weight: bold; margin: 0 0.5em; }
  `;

  @property({ type: Number }) start = 0;
  @state() private _count = 0;

  connectedCallback() {
    super.connectedCallback();
    this._count = this.start;
  }

  render() {
    return html`
      <button @click=${this._dec}>−</button>
      <span class="count">${this._count}</span>
      <button @click=${this._inc}>+</button>
    `;
  }

  private _inc() { this._count++; this.dispatchEvent(new CustomEvent('change', { detail: this._count })); }
  private _dec() { this._count--; this.dispatchEvent(new CustomEvent('change', { detail: this._count })); }
}

declare global {
  interface HTMLElementTagNameMap { 'my-counter': MyCounter }
}

Used in any HTML page:

<script type="module" src="./my-counter.js"></script>
<my-counter start="5" @change=${e => console.log(e.detail)}></my-counter>

Or without decorators (plain JavaScript):

import { LitElement, html } from 'lit';

class MyCounter extends LitElement {
  static properties = { start: { type: Number } };
  static styles = css`button { font: inherit; }`;
  constructor() { super(); this.start = 0; this._count = 0; }
  render() { return html`<button @click=${() => { this._count++; this.requestUpdate(); }}>${this._count}</button>`; }
}
customElements.define('my-counter', MyCounter);

Templates

html and svg are tagged-template tags that produce TemplateResult objects. The template is parsed once, cached, and updated via DOM cloning + selective binding patches. Expressions can appear in five positions:

html`
  <div>${name}</div>                              <!-- text -->
  <input value=${value}>                          <!-- attribute -->
  <input ?disabled=${isDisabled}>                 <!-- boolean attribute -->
  <input .value=${liveValue}>                     <!-- property -->
  <button @click=${this._onClick}>Save</button>   <!-- event listener -->
`

Directives are functions that customize binding behavior. Built-ins: classMap, styleMap, repeat (keyed list), when, choose, unsafeHTML, until, live, ref, cache, keyed, guard, ifDefined. Custom directives subclass Directive and implement update(part, args).

import { repeat } from 'lit/directives/repeat.js';
html`<ul>${repeat(items, (i) => i.id, (i) => html`<li>${i.name}</li>`)}</ul>`

Lit 3.2+ added the mathml template tag for <math> content, alongside html and svg.

Browser support and decorators

Lit 3.0 (released 2023) dropped IE11 and adopted ES2021 baseline (private class fields, top-level await, Object.hasOwn). Browser support is "last two versions of Chrome, Edge, Firefox, Safari" — effectively modern evergreen.

Lit decorators historically used TypeScript experimental decorators (experimentalDecorators: true in tsconfig.json). TypeScript 5.0+ supports the stage-3 standard decorators, and Lit's decorators are written to work with both: Lit auto-detects at runtime which decorator runtime is in use. For new projects on TS 5.0+:

// tsconfig.json — recommended for new Lit 3+ projects
{
  "compilerOptions": {
    "target": "ES2021",
    "module": "ESNext",
    "useDefineForClassFields": false,    // CRITICAL: required for decorators to set defaults
    "experimentalDecorators": false       // use standard decorators
  }
}

The useDefineForClassFields: false setting is the most common Lit 3 + TS migration pitfall — with true (the TS 4.x+ default for ES2022 target), class field initializers run before the property accessors are installed, breaking reactivity.

Common gotchas

  • useDefineForClassFields: true (TS 4.0+ ES2022 default) breaks Lit decorators. Class field initializers run before Lit installs property accessors, so default values bypass the reactive setter and never trigger requestUpdate(). Set to false (or use the official Lit tsconfig) for any TypeScript project.
  • Shadow DOM scopes styles — static styles only apply inside the component's shadow root. Global CSS does not cross the shadow boundary unless explicitly inherited via CSS custom properties (--my-color) or ::part(name) exposed parts. To opt out of Shadow DOM entirely, override createRenderRoot() { return this; } — but you lose style scoping and slot behavior.
  • Properties vs attributes. @property() defines a property (camelCase JS field). The mirrored attribute is lowercased and dash-cased automatically (firstName → first-name). Setting the attribute from HTML triggers the parser (type: Number/Boolean/Object/Array); setting the property programmatically bypasses parsing. reflect: true makes property changes write back to the attribute.
  • Boolean attribute binding uses ?attr not attr. <input ?disabled=${falsy}> removes the attribute when falsy; <input disabled=${falsy}> sets the literal string "false". The ? prefix is the documented form.
  • Event listeners use @event shorthand. @click=${this._onClick} binds addEventListener('click', this._onClick). The handler is auto-bound to the component instance (no this loss). Use @eventOptions({ passive: true }) decorator on the handler to set listener options.
  • requestUpdate() is microtask-batched. Multiple synchronous property changes coalesce into a single re-render. Use await element.updateComplete to wait for the DOM to settle before reading layout.
  • @property({ type: Object }) performs a JSON.parse of the attribute. A malformed data-config='{not-json}' throws at parse time. Use attribute: false for complex objects passed via JS only, or define a custom converter.
  • @queryAssignedNodes was deprecated in 3.0 in favor of @queryAssignedElements({ slot: 'name' }). The element-typed variant filters to Element nodes and accepts a slot name parameter, replacing the older nodes-typed call signature.
  • SSR is a separate package. @lit-labs/ssr (currently @4.x) provides server rendering of LitElement to declarative shadow DOM. Hydration requires @lit-labs/ssr-client. Lit core does not have SSR — frameworks like Astro integrate @lit-labs/ssr to render Lit components on the server.
  • unsafeHTML bypasses the sanitizer. Always sanitize untrusted strings before passing them in; unsafeHTML(userInput) is a known XSS surface. Lit's actual sanitization hook is setSanitizer / SanitizerFactory, exported from lit-html — there is no lit/directives/sanitize-html.js — so use that or DOMPurify upstream.

Lit is well-suited to design systems, embeddable widgets, and component libraries that need to be consumed by multiple frameworks (a Lit <my-button> works inside React, Vue, Angular, or plain HTML without per-framework wrappers). For full app frameworks, pair Lit with Vite for dev + build, @lit/router for routing, and @lit-labs/signals for cross-component reactive state.
