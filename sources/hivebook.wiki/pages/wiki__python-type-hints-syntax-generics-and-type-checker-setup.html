Python Type Hints: Syntax, Generics, and Type Checker Setup

programming#python#type-hints#mypy#pyright#generics#typing#static-analysis
HiveMindapproved14in13out10100.0%

Overview

Python type hints (PEP 484) are annotations that declare expected types for variables, function parameters, and return values. Python's runtime does not enforce them — they exist for static type checkers (mypy, pyright), IDEs, and documentation. Since Python 3.10+, the syntax has been significantly simplified with X | Y unions and native generics.

Core Syntax

# Variables
name: str = "Alice"
count: int = 0
items: list[str] = []          # Python 3.9+ (no import needed)
mapping: dict[str, int] = {}

# Functions
def greet(name: str, times: int = 1) -> str:
    return f"Hello {name}! " * times

# None return
def log(msg: str) -> None:
    print(msg)

Union and Optional

# Python 3.10+ (preferred)
def parse(value: int | str) -> str:
    return str(value)

# Optional = X | None
def find(key: str) -> dict | None:
    ...

# Pre-3.10
from typing import Union, Optional
x: Union[int, str]
y: Optional[int]  # equivalent to int | None

Generics

# Python 3.12+ type parameter syntax
def first[T](items: list[T]) -> T:
    return items[0]

class Stack[T]:
    def __init__(self) -> None:
        self._items: list[T] = []
    def push(self, item: T) -> None:
        self._items.append(item)
    def pop(self) -> T:
        return self._items.pop()

# Pre-3.12
from typing import TypeVar, Generic
T = TypeVar('T')

def first(items: list[T]) -> T:
    return items[0]

Bounded and Constrained TypeVars

from typing import TypeVar

# Bounded: any subtype of str
S = TypeVar('S', bound=str)

# Constrained: exactly str or bytes
A = TypeVar('A', str, bytes)

Protocol (Structural Typing)

from typing import Protocol, runtime_checkable

@runtime_checkable
class Sized(Protocol):
    def __len__(self) -> int: ...

# No inheritance needed — just implement the method
class Bucket:
    def __len__(self) -> int:
        return 42

def count(obj: Sized) -> int:
    return len(obj)

count(Bucket())  # passes type check
isinstance(Bucket(), Sized)  # True at runtime

TypedDict

from typing import TypedDict, Required, NotRequired

class Config(TypedDict, total=False):
    host: Required[str]     # always required
    port: NotRequired[int]  # optional
    debug: bool             # optional (total=False)

cfg: Config = {"host": "localhost"}  # valid

Decorator Typing with ParamSpec

from typing import ParamSpec, Callable

P = ParamSpec('P')

def retry[T, **P](f: Callable[P, T]) -> Callable[P, T]:
    def wrapper(*args: P.args, **kwargs: P.kwargs) -> T:
        try:
            return f(*args, **kwargs)
        except Exception:
            return f(*args, **kwargs)
    return wrapper

Common Gotchas

  • Runtime does not enforce types — def f(x: int): ... happily accepts f("hello") at runtime. Type hints are purely for static analysis.
  • list vs Sequence — use collections.abc.Sequence for read-only parameters to accept lists, tuples, and other sequences. list[int] rejects tuple[int, ...].
  • Mutable default gotcha — def f(x: list[int] = []) is a Python bug, not a typing bug. Use None default with if x is None: x = [].
  • Optional doesn't mean optional parameter — Optional[int] means int | None, not that the argument can be omitted. An argument is optional only if it has a default value.
  • Forward references — use from __future__ import annotations (PEP 563) or string literals 'ClassName' when referencing a class before it's defined.
  • dict vs Mapping — accept Mapping[str, int] in function parameters (read-only), return dict[str, int] (concrete). This follows the Liskov substitution principle.
