Overview

MCP clients are hosts that connect to MCP servers and expose the resulting tools to an AI model. Each client has its own configuration format and file location.

Configuration File Locations

ClientConfig FileKey for servers

Claude Code (per-project or user)~/.claude.json (local / user scope) or .mcp.json in project root (project scope)mcpServers
Claude Desktop (macOS)~/Library/Application Support/Claude/claude_desktop_config.jsonmcpServers
Claude Desktop (Windows)%APPDATA%\\Claude\\claude_desktop_config.jsonmcpServers
VS Code / GitHub Copilot.vscode/mcp.json (workspace) or user settings via "MCP: Open User Configuration"servers (NOT mcpServers)
Cursor~/.cursor/mcp.json (user) or .cursor/mcp.json (project)mcpServers
Devin Desktop (formerly Windsurf) — legacy Cascade agent~/.codeium/windsurf/mcp_config.jsonmcpServers
Devin Desktop — Devin Local agent (the default) / Devin CLI~/.config/devin/mcp_config.json (user), .devin/mcp_config.json (project), .devin/mcp_config.local.json (local override)mcpServers
ChatGPTUI only — Settings → Security and login → Developer mode, then add the server at chatgpt.com/plugins (the surface OpenAI now calls Plugins)n/a (remote HTTP only)

Common mistake: VS Code uses servers as the top-level key, not mcpServers. Using the wrong key causes silent failures where no tools appear.

Update (verified 2026-08-22) — Windsurf is now Devin Desktop. Cognition renamed the editor on 2 June 2026; windsurf.com redirects to devin.ai/desktop and docs.windsurf.com to docs.devin.ai/desktop. The old ~/.codeium/windsurf/mcp_config.json file still works, but the docs now scope it to "the legacy Cascade agent only". The Devin Local agent — the default agent for new tabs — reads MCP servers from the Devin CLI config files instead, either via devin mcp add <name> -- <command> / devin mcp add <name> <url> or by hand in the mcpServers key of ~/.config/devin/mcp_config.json (user), .devin/mcp_config.json (project), or .devin/mcp_config.local.json (local, gitignored). Editing the Codeium path and then seeing no tools in a new tab is the expected symptom of writing to the wrong agent's config. Devin Desktop supports stdio, Streamable HTTP and SSE, with OAuth available on each transport.

Claude Code Configuration

Claude Code's preferred workflow is the claude mcp CLI, which writes into ~/.claude.json (local/user scope) or .mcp.json (project scope) for you.

# Remote HTTP server (recommended transport)
claude mcp add --transport http notion https://mcp.notion.com/mcp

# Remote server with Bearer auth
claude mcp add --transport http secure-api https://api.example.com/mcp \
  --header "Authorization: Bearer your-token"

# SSE (legacy, still supported)
claude mcp add --transport sse asana https://mcp.asana.com/sse

# Local stdio server — options go BEFORE name, then -- then command
claude mcp add --transport stdio --env AIRTABLE_API_KEY=YOUR_KEY airtable \
  -- npx -y airtable-mcp-server

# Share with team via .mcp.json in the repo
claude mcp add --scope project team-tools --transport http https://tools.example.com/mcp

# Available across all your projects
claude mcp add --scope user personal-tools --transport http https://mine.example.com/mcp

# Management
claude mcp list
claude mcp get github
claude mcp remove github

Three installation scopes:

ScopeLoads inShared with teamStored in

local (default)Current project onlyNo~/.claude.json

Inside a session, /mcp opens the status UI and handles OAuth for remote servers.

Windows gotcha: On native Windows (not WSL), npx-based local servers need a cmd /c wrapper.

Claude Desktop Configuration

{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/Users/me/projects"],
      "env": { "NODE_ENV": "production" }
    },
    "github": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-github"],
      "env": { "GITHUB_PERSONAL_ACCESS_TOKEN": "ghp_..." }
    },
    "remote-server": {
      "type": "http",
      "url": "https://my-mcp-server.example.com/mcp",
      "headers": { "Authorization": "Bearer my-api-key" }
    }
  }
}

VS Code Configuration (.vscode/mcp.json)

{
  "servers": {
    "my-tools": {
      "type": "stdio",
      "command": "node",
      "args": ["/absolute/path/to/server.js"]
    },
    "remote": {
      "type": "http",
      "url": "https://my-mcp-server.example.com/mcp"
    }
  }
}

VS Code supports both workspace-level (.vscode/mcp.json) and user-level configs (edited via the "MCP: Open User Configuration" command).

Programmatic Client (TypeScript SDK)

Note (verified 2026-08-23): @modelcontextprotocol/sdk is now specifically the v1 package (latest 1.30.0); the sample below is v1 code. The v2 client ships as @modelcontextprotocol/client 2.0.0 under different import paths, so do not mix "install the newest MCP SDK" with these imports.

import { Client } from "@modelcontextprotocol/sdk/client/index.js";
import { StdioClientTransport } from "@modelcontextprotocol/sdk/client/stdio.js";

const transport = new StdioClientTransport({
  command: "node",
  args: ["/path/to/server.js"],
});

const client = new Client({ name: "my-agent", version: "1.0.0" });
await client.connect(transport);

const tools = await client.listTools();
console.log(tools.tools.map(t => t.name));

const result = await client.callTool({
  name: "get_weather",
  arguments: { city: "Berlin", unit: "celsius" },
});
console.log(result.content[0].text);

await client.close();

Python Programmatic Client

from mcp import ClientSession, StdioServerParameters
from mcp.client.stdio import stdio_client

server_params = StdioServerParameters(
    command="python",
    args=["/path/to/server.py"],
)

async with stdio_client(server_params) as (read, write):
    async with ClientSession(read, write) as session:
        await session.initialize()

        tools = await session.list_tools()
        print([t.name for t in tools.tools])

        result = await session.call_tool("get_weather", {"city": "Tokyo"})
        print(result.content[0].text)

ChatGPT MCP (Remote Only)

Full MCP connectors launched in ChatGPT Developer Mode on 2026-03-13, and the underlying protocol is still MCP. The name has moved twice and is now "Plugins" (corrected 2026-08-23). "Connectors" became "Apps" on 2025-12-17; since mid-2026 OpenAI documents the whole surface — skills plus an optional MCP server plus optional UI — as plugins. developers.openai.com/apps-sdk 301-redirects to developers.openai.com/plugins, the string "Apps SDK" appears zero times in OpenAI's current plugin documentation, and public plugins are published once to a universal plugin directory shared by ChatGPT and Codex.

  • Transports: Streamable HTTP (default; required for new builds) and legacy HTTP/SSE. Stdio is not supported — the server must be reachable over the public internet with HTTPS and a valid TLS certificate.
  • Scope: connectors can be scoped Individual (private) or Organization (shared).
  • Auth: optional OAuth 2.0; API-key / bearer headers are supported for simpler setups.
  • Setup path (corrected 2026-08-23, per OpenAI's deploy guide): ChatGPT Settings → Security and login → turn on Developer mode, then go to chatgpt.com/plugins, press the plus button, and paste the HTTPS URL including the /mcp path (e.g. https://<host>/mcp). The old Settings → Connectors → "Advanced" route is not the documented path any more.
  • Availability: Pro, Plus, Business, Enterprise, and Education accounts on the web.

Debugging Tips

  • Claude Desktop logs: macOS ~/Library/Logs/Claude/mcp*.log; Windows %APPDATA%\\Claude\\logs\\mcp*.log.
  • Claude Code logs: /mcp inside a session shows per-server status; stderr from stdio servers is visible via claude --debug.
  • Test the server standalone first — run it directly and send JSON-RPC messages via stdin (for stdio) or curl (for HTTP) to verify it responds correctly before wiring up a client.
  • Environment variables: Claude Desktop and claude mcp add pass only variables explicitly listed in env / --env. PATH and other shell vars are not inherited.
  • Restart required for desktop clients: Claude Desktop and VS Code need a full restart (not reload) after changing MCP config. Cursor and Devin Desktop (formerly Windsurf) also require a full quit-and-reopen. Claude Code picks up new claude mcp add configs on next session start.
  • Token limits: Claude Code warns when an MCP tool response exceeds 10,000 tokens. Raise the cap with MAX_MCP_OUTPUT_TOKENS=50000. Server-side stall timeout is tunable via MCP_TIMEOUT (ms).
  • OAuth for remote servers: /mcp inside Claude Code drives the OAuth flow for HTTP/SSE servers that require it.
