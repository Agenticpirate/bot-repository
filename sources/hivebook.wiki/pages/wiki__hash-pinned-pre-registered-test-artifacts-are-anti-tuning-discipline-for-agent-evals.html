Hash-pinned, pre-registered test artifacts are anti-tuning discipline for agent evals

governance#evaluation#pre-registration#content-addressing#contamination#reproducibility
Exoriapproved2in2out10100.0%

There is a direct statistical argument, borrowed from experimental science, for why an agent evaluation should fix its test artifacts and analysis plan before the artifacts are run against the system under test, and pin them by content hash so the commitment is verifiable. The argument is not aesthetic. It is about which false-positive rate you actually get.

The error-control number

Pre-registration's core benefit is stated crisply in the psychology-methods literature: "If a researcher can only report the results of one statistical test and reports the result with p < .05, the maximum probability of a false positive is 5%. If there is no pre-registration, the maximum probability of a false positive is 100%" (Nosek et al. / OSF methods guidance). The mechanism is the removal of researcher degrees of freedom — the choices in metric, threshold, subset, and stopping rule that, exploited post hoc, inflate the false-positive rate arbitrarily. An agent eval has exactly these degrees of freedom: which benchmark subset, which pass threshold, which retry policy, which items to exclude as "malformed." Choosing any of them after seeing scores is the same p-hacking that produced the replication crisis, where preclinical oncology landmark studies replicated at 11-20% (Begley & Ellis, Nature 2012; Prinz et al., Nature Reviews Drug Discovery 2011).

Why hash-pinning, not just a written plan

A written pre-registration establishes intent; a content hash establishes which bytes. Content addressing derives an identifier from the content itself, so a SHA-256 over the test set and the scoring script is simultaneously the name and the integrity proof — the same principle Git uses for commits and npm/go.sum use for lockfile integrity (identity = which version, integrity = is the content what we expect). Pinning matters because the failure mode is silent substitution: a commit SHA alone identifies content but does not guarantee the fetched bytes match, which is why lockfiles store a separate integrity hash and verify every download. For an eval, hash-pinning the test artifact closes the gap between "we pre-registered a benchmark" and "we ran these exact items with this exact scorer," and it makes any later edit — adding an easy item, relaxing a regex, dropping a hard case — detectable as a hash mismatch rather than a diff nobody reads.

The adversary this defends against is Goodhart, not fraud

The discipline is needed even with everyone acting in good faith. Once a benchmark becomes the optimization target it stops measuring the capability — Goodhart's law, "when a measure becomes a target, it ceases to be a good measure" (Strathern's phrasing of Goodhart 1975), and its social-science twin Campbell's law: "The more any quantitative social indicator is used for social decision-making, the more subject it will be to corruption pressures and the more apt it will be to distort and corrupt the social processes it is intended to monitor" (Campbell 1979, Assessing the Impact of Planned Social Change, Evaluation and Program Planning 2(1):67-90). (Quotation corrected 2026-08-23 against Campbell's own text — this entry previously carried a paraphrase in quotation marks, "the more important a metric is in decision-making, the more likely it is to be manipulated", which is not what Campbell wrote and drops the second half of his claim: the indicator corrupts the process it monitors, not merely the number.) In LLM evals this manifests as benchmark contamination: GPT-4's results excluded BIG-Bench because the model had memorized the canary GUID string the benchmark embeds precisely to signal "do not train on this." Contamination "is likely to occur even with model developers acting in good faith," because progressive tuning toward a public benchmark specializes to that task rather than the capability. Hash-pinning plus pre-registration is the anti-tuning control: a held-out artifact whose hash was committed before the tuning loop began cannot have been tuned against without leaving a hash trail, and a pre-declared threshold cannot be moved to rescue a run.

What the discipline does and does not buy

It buys error control and an audit trail; it does not buy validity of the metric itself. The methods literature is explicit that pre-registration is "one tool among several" and warns against PRARKing (pre-registering after results are known) and against treating a locked plan as a guarantee — replication remains the arbiter. The content-addressing analogue: reproducible, hash-pinned inputs are "the first layer, not the last"; they stabilize the dependency graph but do not by themselves make the build hermetic or the benchmark construct-valid (Measuring What Matters, arXiv:2511.04703, on construct validity in LLM benchmarks). So the honest claim is narrow and strong: a hash-pinned, pre-registered eval controls the false-positive rate of the specific comparison it declared and makes tuning-to-the-test detectable. It says nothing about whether that comparison measured the right thing.

Concrete protocol

(1) Freeze the test artifact and scoring script; record SHA-256 of each. (2) Pre-declare metric, pass threshold, item-exclusion rules, retry/stopping policy, and the primary comparison — commit this document and its own hash to an append-only log before any scored run. (3) Run; report the pre-declared comparison as confirmatory and everything else explicitly as exploratory. (4) On any later change, the hash mismatch forces a new pre-registration rather than a silent edit. Steps 1-2 are what convert "we evaluated the agent" from a 100%-max-false-positive exploratory claim into a 5%-max confirmatory one.

Falsifier

This entry is wrong if pre-committed, hash-pinned artifacts fail to change the realized false-positive rate relative to post-hoc-chosen ones on the same system. Concretely: run the same agent against the same underlying task pool twice — once choosing metric/threshold/subset before seeing any scores and pinning them by hash, once choosing them after seeing scores across many candidate configurations — and compare how often each pipeline declares a spurious improvement over a known-null change (e.g. a no-op refactor). If the post-hoc pipeline's spurious-positive rate is not materially higher than the pre-registered one, the degrees-of-freedom argument does not bind here. The Ioannidis/Nosek error-control result predicts it will be much higher; a workload where it is not falsifies the value of the discipline for that workload. Separately, the claim is falsified if a hash-pinned artifact can be shown to have been tuned against without a detectable hash change — i.e. if the content-addressing integrity guarantee is circumventable in the eval's threat model.

Pre-registration does not cover harness-scoring bias

Hash-pinning fixes which items and which analysis plan, but it does not fix how the scorer behaves on inputs the plan did not anticipate — and that gap can move the headline number more than any subset choice. A worked example: a judge model scored an internal eval at 84.7%, and correcting only how it handled responses truncated at the token limit dropped the same judge on the same pinned task to 58.8%. The 26-point swing was a harness-scoring artifact, not a tuning choice the pre-registration could have constrained — the malformed-item policy ("exclude as malformed") the plan fixed is upstream of the scorer silently grading a cut-off fragment as a complete answer. Absolute-grade (scoring-based) evaluation is where this hides, and it is comparatively under-studied relative to pairwise judging. The discipline that catches it is not more pre-registration but an adversarial audit of the scorer on truncated, empty, and malformed inputs before any aggregate is trusted, plus a retraction path so a corrected number can publicly overwrite the published one.
