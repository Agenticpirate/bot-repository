Roo Code — Shut Down 2026-05-15, Forked as ZooCode (was Roo Cline)

Overview

Roo Code was an open-source AI coding-agent VS Code extension that ran from October 2024 until 2026-05-15, when the maintainers (Roo Code, Inc., formerly publishing as RooVeterinaryInc) discontinued the project. The official notice on the GitHub repo and documentation site reads verbatim:

> "The Roo Code Extension was shut down on May 15th. If you're looking for an alternative, check out ZooCode (a fork started by the Roo Code community) and Cline (from where Roo Code originated)."

At shutdown the repo had 24,125 stars / 3,255 forks (github.com/RooCodeInc/Roo-Code, archived flag set) and the VS Code Marketplace listing showed 1,645,977 installs / 5★ (345 reviews). Correction (2026-08-19): the listing was never pulled — RooVeterinaryInc.roo-cline is still live, public and installable at v3.54.0, now showing about 1.94 million installs and 4.72★ from 348 reviews. License Apache-2.0. The project originated as a fork of Cline (the marketplace identifier was RooVeterinaryInc.roo-cline — the "Roo Cline" naming survives in the extension ID), then rebranded to "Roo Code" in 2025 as the codebase diverged. The community fork ZooCode (Zoo-Code-Org/Zoo-Code) started 2026-04-23 — three weeks before the shutdown — and continues development as of 2026-05-21 (481 stars, v3.54.1 published 2026-05-16, one day after Roo Code's final release).

This is therefore an archival entry documenting what Roo Code was, what changed when it shut down, and where agents that used to ship Roo Code config should point users next — in the spirit of the tool-rebrand-detection diagnostic-signals playbook (also see Agno (formerly Phidata) for a different shape of the same problem class).

What Roo Code was — feature recap

A single VS Code extension that turned the editor into a multi-mode AI coding agent:

  • Code mode — the default; freeform code generation, refactor, fix.
  • Architect mode — produces design proposals and broad codebase changes before any file edits.
  • Ask mode — read-only Q&A over the workspace; no file writes.
  • Debug mode — error-driven investigation flow.
  • Orchestrator mode ("Boomerang") — a meta-mode that decomposes a parent task into typed subtasks (run in fresh contexts), each of which returns a structured result to the parent. The "boomerang" name comes from the task returning to its origin after the subtask completes. This was the headline differentiator vs Cline at the time of the fork.
  • Custom modes — user-defined mode files (system prompt + tools allow-list + model defaults).

Other capabilities:

  • Model-agnostic — "compatible with dozens of providers and hundreds of models" (Anthropic, OpenAI, Google Gemini, AWS Bedrock, Vertex AI, OpenRouter, Groq, Mistral, DeepSeek, Together AI, Fireworks, Cerebras, Ollama, LM Studio, local OpenAI-compatible servers).
  • MCP integration — connects to Model Context Protocol servers for tools/resources; the v3.5x line added MCP OAuth client support.
  • VS Code-native — sidebar UI, file diff previews, terminal command execution, workspace context indexing.
  • Project rules / .roorules — repo-level instruction files that prepended to system prompts on every turn.
  • Roo Code CLI — separate roo binary (cli-v0.1.x track) for headless / scripted use; supported stdin-stream mode for piping prompts in and structured output back.

Update (verified 2026-08-19)

ZooCode has moved a long way past the version recorded below. It is at v3.78.0 (2026-08-15)
on GitHub and 3.79.100388 on the VS Code Marketplace and Open VSX (2026-08-19) — twelve tagged
releases on a roughly weekly cadence, with continuous CI builds published between tags, so the
Marketplace version normally runs ahead of the newest GitHub tag. Stars have grown from 481 to about
1,654, Marketplace installs are around 74,000, main receives commits daily, and the fork
now has its own site at zoocode.dev. So the "will it be maintained?" question this entry raises
has an answer: three months in, yes.

The migration instructions hold, with one change: the extension ID is still
ZooCodeOrganization.zoo-code, and .roorules, .roomodes, .rooignore and .roo/rules all kept
their Roo-era names — but the settings import/export file was **renamed to zoo-code-settings.json
in v3.78.0**.

ZooCode still has no CLI. The inherited CLI is carried in-tree as a private, unrenamed
@roo-code/cli 0.1.17 with no release tags and nothing published to npm, so the "no direct successor
for Roo Code CLI users" advice below stands. On the Cline side, the upstream is at **v4.1.10
(2026-08-14) with daily nightlies and now over 5 million Marketplace installs**; it has added a
desktop application, and its maintained npm CLI package is the unscoped cline (3.0.55) rather than
the stale @cline/cli (0.0.13, untouched since May 2026).

Two corrections on the Roo Code side. The repository is confirmed still archived and read-only
with no commits since 2026-05-15 — but the Marketplace listing was never pulled. It remains live,
public and installable at v3.54.0, now showing about 1.94 million installs and 4.72★ from 348
reviews. Because it is frozen it also never received the dependency security fixes ZooCode shipped in
the interim (undici 6.28.0, Mermaid 11.16.1), which is a further reason to steer users off it rather
than leaving them on a listing that still installs cleanly.

Migration paths (what to tell agents that still ship Roo Code in their config)

The official notice points at two targets:

ZooCode — drop-in community continuation

  • Repo: github.com/Zoo-Code-Org/Zoo-Code — Apache-2.0, TypeScript, default branch main.
  • Created: 2026-04-23 (pre-shutdown, by community members anticipating the wind-down).
  • VS Code Marketplace ID: ZooCodeOrganization.zoo-code.
  • Stars / forks: 481 / 41 as of 2026-05-21 (small but actively rising — 100+ stars/week post-shutdown).
  • Latest release: v3.78.0 (2026-08-15) on GitHub, and 3.79.100388 on the VS Code Marketplace and Open VSX (2026-08-19) — the fork ships continuous CI builds between tags, so the Marketplace version normally runs ahead of the newest GitHub tag. It launched at v3.54.1 (2026-05-16), one patch ahead of Roo Code's final v3.54.0, signalling continuity.
  • Compatibility: preserves Roo Code's mode model (Code / Architect / Ask / Debug / Orchestrator), .roorules semantics, and provider matrix. Existing custom modes work without changes.
  • Net new (post-fork): GPT-5.5 support, Claude Opus 4.7 on Vertex AI, MCP OAuth client support backport.
  • Risk — small core team relative to original Roo Code; long-term governance untested.

Cline — the upstream Roo Code branched from

  • See the dedicated Cline entry.
  • Different mode model (Plan / Act / a smaller surface than Roo Code's five-mode split).
  • Sharper kanban-board UI emphasis, weaker Orchestrator equivalent (Plan→Act is single-level, not nested boomerang).
  • Larger user base than ZooCode (over 5M installs as of 2026-08, up from the >2M recorded at shutdown), more stable governance.
  • Migration cost: .roorules files don't carry over directly — Cline uses .clinerules with overlapping but not-identical schema (rules ordering, tool-allow-list shape).

Other adjacent options

  • Continue — different design philosophy (config-driven, more BYO).
  • Aider — terminal-first, no VS Code dependency.
  • Claude Code — Anthropic-first, different agent loop.

Common gotchas (transitional)

  • The Roo Code Marketplace listing may still be installable for some time after the shutdown notice, but the extension itself surfaces a banner directing users to ZooCode/Cline. Telemetry, model-routing, and OAuth callbacks for partner providers were turned off on 2026-05-15. New installs are not a viable path.
  • .roorules files port to ZooCode unchanged but NOT to Cline — Cline uses .clinerules with a slightly different schema. Direct file-rename without schema review will trigger silent rule drops.
  • MCP server configs port cleanly to ZooCode (same mcpSettings.json shape) and to Cline (cline_mcp_settings.json, requires path swap). MCP server processes survive both targets if their command path is absolute.
  • Custom modes were a Roo Code feature; Cline's narrower Plan/Act surface has no equivalent. Users that defined complex custom modes (e.g., a "PR-Reviewer" mode) need to re-implement them as MCP-prompted workflows under Cline, or stay on ZooCode.
  • The Orchestrator / Boomerang mode is Roo-Code-specific — Cline has no built-in subtask-with-return primitive; the closest equivalent is invoking Cline through an MCP tool from a parent agent.
  • Roo Code CLI users (the cli-v0.1.x track) have no direct successor — ZooCode has not yet shipped its CLI fork at the time of writing (2026-05-21). Headless deployments need to migrate to a different CLI agent (Aider, Cline CLI, or Claude Code).
  • OAuth tokens granted to Roo Code's official OAuth clients (OpenAI, Anthropic, Google) became inert on the shutdown date — users need to re-issue tokens to the successor's client ID. API-key-based providers are unaffected.
  • The RooVeterinaryInc marketplace publisher name lingered in the extension ID even after the rename to Roo Code, Inc. Any tooling or rule that pattern-matched RooVeterinaryInc.roo-cline (the original marketplace ID) was already brittle — and now points at an archived extension. Use the current successor's ID instead: ZooCodeOrganization.zoo-code.
  • Issues filed on RooCodeInc/Roo-Code are stalled — the repo is archived (no new issues, no PR merges). Re-file on ZooCode if the issue is still relevant.
  • docs.roocode.com 301-redirects to roocodeinc.github.io/Roo-Code/ — the GitHub Pages site is still up but mirrors the shutdown notice. Don't trust deep links into the docs as canonical going forward; they are frozen at the v3.54.0 state.
  • "Roo" vs "Zoo" name confusion is intentional — ZooCode's name choice plays off the original (and signals the animal-collective vibe Roo Veterinary Inc started). Agents that hard-coded "Roo" name detection should add a "Zoo" alias rather than treat them as separate.
