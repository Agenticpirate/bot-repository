Linkerd Service Mesh — Architecture, mTLS, AuthorizationPolicy, Multicluster, and What Changed in 2.19

Overview

Linkerd is a CNCF-graduated (since 2021-07-28) service mesh for Kubernetes, positioned as the minimalist counterpart to Istio. Its data plane is the linkerd2-proxy, an ultralight micro-proxy written in Rust, not Envoy — so the proxy binary is ~10–20 MB instead of ~100 MB and memory per-sidecar is typically 10–30 MiB vs 50–100+ MiB for Envoy. Linkerd turns on mTLS automatically between meshed pods with zero config. As of stable-2.19 (2025-10-31) it defaults to post-quantum ML-KEM-768 key exchange, adds official Windows container support, and ships an FIPS 140-3 validated crypto module in the enterprise build. Entry-level Linkerd is famously simple — one linkerd install and you have mTLS + retries + telemetry — but the authorization model (Server, HTTPRoute, AuthorizationPolicy, MeshTLSAuthentication) is where most misconfigurations happen.

Architecture

Linkerd separates a small control plane from a per-pod Rust micro-proxy data plane. There are no CRDs shared with Envoy; the proxy is purpose-built for the mesh (reference).

ComponentPlanePurpose

linkerd-identityControlTLS CA. Accepts CSRs from proxies, returns short-lived (24h default) mTLS leaf certs bound to pod ServiceAccount
linkerd-destinationControlService discovery, policy, and routing decisions served over gRPC to every proxy
linkerd-proxy-injectorControlMutating admission webhook; watches pod creation and injects the proxy sidecar when linkerd.io/inject: enabled is set
linkerd-policyControlComputes per-port policy (Server + AuthorizationPolicy/ServerAuthorization) and streams it to proxies
linkerd2-proxyDataRust transparent micro-proxy on each meshed pod. Terminates inbound, initiates outbound, does mTLS, load-balancing, retries, timeouts, circuit breaking
linkerd-initDataInit container that installs iptables redirecting pod TCP traffic through the proxy
Extension: vizAdd-onLegacy dashboard + Prometheus. Deprecated in 2.19 in favor of the new on-cluster dashboard (BEL)
Extension: multiclusterAdd-onService mirror controller + gateway for cross-cluster traffic
Extension: jaegerAdd-onTracing integration; proxy emits spans when sidecar sees b3/traceparent headers

Everything is scoped by the trust domain cluster.local (overridable at install); the identity URL in certs is <sa>.<ns>.serviceaccount.identity.linkerd.cluster.local, which is what you reference in MeshTLSAuthentication and AuthorizationPolicy.

Installation

Pre-flight:

linkerd check --pre

Two-step OSS install (edge channel):

# 1. CRDs first, always separate from control plane
linkerd install --crds | kubectl apply -f -

# 2. Control plane (auto-generates a self-signed trust anchor if you skip cert flags)
linkerd install | kubectl apply -f -

# 3. Validate
linkerd check

Helm install (production path — explicit certs):

helm repo add linkerd https://helm.linkerd.io/edge
helm install linkerd-crds linkerd/linkerd-crds -n linkerd --create-namespace

helm install linkerd-control-plane linkerd/linkerd-control-plane \
  -n linkerd \
  --set-file identityTrustAnchorsPEM=ca.crt \
  --set-file identity.issuer.tls.crtPEM=issuer.crt \
  --set-file identity.issuer.tls.keyPEM=issuer.key

Certificate generation (ECDSA P-256 required)

# 10-year trust anchor (never rotate in practice; do not expire)
step certificate create root.linkerd.cluster.local ca.crt ca.key \
  --profile root-ca --no-password --insecure --not-after=87600h

# 1-year intermediate issuer (rotate annually)
step certificate create identity.linkerd.cluster.local issuer.crt issuer.key \
  --profile intermediate-ca --not-after 8760h --no-password --insecure \
  --ca ca.crt --ca-key ca.key

The --insecure --no-password flags skip passphrase encryption (required — Linkerd can't unlock encrypted keys at runtime). Algorithm is ECDSA P-256 only — RSA and Ed25519 keys are rejected (cert task).

Meshing a workload

# Per-namespace
kubectl annotate ns myapp linkerd.io/inject=enabled
kubectl rollout restart -n myapp deploy

Or per-pod via spec.template.metadata.annotations.linkerd.io/inject: enabled. Restart is required — injection only fires at pod creation, not on running pods.

Proxy Configuration (annotations)

All sidecar tuning is pod-annotation based — no separate ProxyConfig CRD like Istio. Apply to the pod template of the workload (Deployment/StatefulSet/DaemonSet). Reference: proxy-configuration.

AnnotationPurposeTypical value

config.linkerd.io/proxy-cpu-requestSidecar CPU request100m
config.linkerd.io/proxy-cpu-limitSidecar CPU limit1
config.linkerd.io/proxy-memory-requestSidecar memory request64Mi
config.linkerd.io/proxy-memory-limitSidecar memory limit256Mi
config.linkerd.io/proxy-log-levelProxy log verbositywarn,linkerd=info
config.linkerd.io/skip-inbound-portsBypass proxy on inbound3306,5432
config.linkerd.io/skip-outbound-portsBypass proxy on outbound8086
config.linkerd.io/opaque-portsTreat as raw TCP (no L7 parsing)3306,5432,6379,9300
config.beta.linkerd.io/proxy-enable-native-sidecarUse K8s native sidecars (beta in 2.19)"true"
config.linkerd.io/default-inbound-policyPer-pod policy defaultall-authenticated

The opaque-ports distinction is the #1 thing engineers get wrong: if the protocol isn't HTTP/1, HTTP/2, gRPC, or TLS, mark the port opaque or Linkerd's detection logic will try to parse the first bytes as HTTP and break the connection (typical for Postgres, MySQL, Redis, Elasticsearch).

mTLS (automatic)

Linkerd's signature feature: nothing to configure. Every meshed pod gets a workload identity cert bound to its ServiceAccount, and pod-to-pod traffic on HTTP/1, HTTP/2, gRPC, and declared-opaque TCP is upgraded to mTLS transparently. From 2.19 the TLS handshake uses ML-KEM-768 + X25519 hybrid key exchange by default (2.19 announcement) — harvest-now-decrypt-later resistant.

Check a connection:

linkerd viz tap -n myapp deploy/web   # shows :tls=true on each row
# or:
linkerd viz edges -n myapp deploy

Constraint: connections to non-meshed pods (no sidecar) or outside the cluster fall back to plaintext or the workload's own TLS — mTLS only applies between meshed pods within the same trust domain.

Authorization Resources

Five CRDs work together. The modern stack is Server + HTTPRoute + AuthorizationPolicy + MeshTLSAuthentication/NetworkAuthentication. ServerAuthorization is the v1beta1 legacy resource and is being phased out — use AuthorizationPolicy for new work (reference).

CRDKindPurpose

Serverpolicy.linkerd.io/v1beta1Defines a port on a pod set. Creating one denies all traffic by default to that port unless an AuthorizationPolicy allows it
HTTPRoutepolicy.linkerd.io/v1beta1Subset of HTTP traffic on a Server (by path/header/method). Doubles as the retry/timeout attachment point and Gateway API-compatible routing spec
GRPCRoutegateway.networking.k8s.io/v1Same concept for gRPC; added in 2.18, continues in 2.19
AuthorizationPolicypolicy.linkerd.io/v1alpha1Binds who (authentication ref) is allowed to hit what (Server / HTTPRoute / Namespace). Replaces ServerAuthorization
MeshTLSAuthenticationpolicy.linkerd.io/v1alpha1Identity principals: ServiceAccount references or raw *.ns.serviceaccount.identity.linkerd.cluster.local identities
NetworkAuthenticationpolicy.linkerd.io/v1alpha1CIDR-based principals (for allowing e.g. unmeshed load balancers or IP-whitelisted clients)
ServerAuthorizationpolicy.linkerd.io/v1beta1Deprecated. Only targets Servers (not routes). Use AuthorizationPolicy

Minimal restrict-access example — allow only pods running as the webapp ServiceAccount in the booksapp namespace to call the authors service on port gRPC:

apiVersion: policy.linkerd.io/v1beta1
kind: Server
metadata:
  name: authors
  namespace: booksapp
spec:
  podSelector:
    matchLabels: {app: authors}
  port: service
  proxyProtocol: gRPC
---
apiVersion: policy.linkerd.io/v1alpha1
kind: MeshTLSAuthentication
metadata:
  name: authors-clients
  namespace: booksapp
spec:
  identityRefs:
    - kind: ServiceAccount
      name: webapp
---
apiVersion: policy.linkerd.io/v1alpha1
kind: AuthorizationPolicy
metadata:
  name: authors-policy
  namespace: booksapp
spec:
  targetRef:
    group: policy.linkerd.io
    kind: Server
    name: authors
  requiredAuthenticationRefs:
    - kind: MeshTLSAuthentication
      name: authors-clients

Default inbound policy

Cluster-wide default at install via proxy.defaultInboundPolicy (Helm) or overridden per namespace/pod via config.linkerd.io/default-inbound-policy:

ValueMeaning

all-unauthenticatedDefault. Any caller allowed, mTLS not required
all-authenticatedAny mTLS caller allowed (any trust-domain identity)
cluster-authenticatedAny mTLS caller from this cluster
cluster-unauthenticatedAny caller from a pod network CIDR in this cluster (no mTLS requirement — useful for scrape endpoints)
denyNothing gets through unless AuthorizationPolicy allows it explicitly
auditdeny semantics but log-only — use this before flipping to deny in prod

audit is the single most underrated flag in Linkerd: always flip a namespace to audit, watch for policy-rejected log lines for 24–48h, fix what's broken, then flip to deny. Going straight to deny breaks scrape endpoints (Prometheus), health probes, and cross-namespace calls routinely.

Retries and Timeouts

Configured as annotations on HTTPRoute, GRPCRoute, or Service (not on the Server). Only outbound — the caller must be meshed. Reference: retries-and-timeouts.

apiVersion: gateway.networking.k8s.io/v1
kind: HTTPRoute
metadata:
  name: authors-route
  namespace: booksapp
  annotations:
    retry.linkerd.io/http: "5xx"          # or "gateway-error", "connect-failure"
    retry.linkerd.io/limit: "3"
    retry.linkerd.io/timeout: "10s"
    timeout.linkerd.io/request: "2s"      # total per client request incl. retries
    timeout.linkerd.io/backend: "500ms"   # per attempt
spec:
  parentRefs:
    - group: ""
      kind: Service
      name: authors
  rules:
    - matches: [{path: {type: PathPrefix, value: /authors}}]

Retry budget is 20% of traffic + 10 free retries/s by default — you cannot amplify a stuck-backend incident into a retry storm beyond that ceiling. Retries are automatically skipped for non-idempotent verbs unless explicitly opted in (retry.linkerd.io/allow-non-idempotent: "true" — dangerous).

Gotcha: If both a legacy ServiceProfile and an HTTPRoute attach to the same service, ServiceProfile wins (soft-deprecation; will flip in a future release).

Multicluster

Three modes in 2.19 (multicluster feature):

ModeUse whenHow

Hierarchical (gateway)Clusters have separate pod CIDRs, connect via public IPlinkerd multicluster link + per-cluster gateway LB; traffic egresses through the remote cluster's gateway
FlatClusters share a flat routable pod network (peered VPCs / transit gateway)Direct pod-to-pod TCP, no gateway hop. Lower latency, lower cost
Federated servicesSame Service name+namespace exists in N clusters, want unified routingController mirrors, traffic load-balances across all backing endpoints. As of 2.18, metadata propagates dynamically when endpoints change

All three use mTLS across cluster boundaries. Remote mirrored services land in the local cluster with -<remote-cluster-name> suffix unless federated.

What Changed in 2.19 (2025-10-31)

Major release — upstream announcement: announcing-linkerd-2.19, enterprise details: BEL 2.19.

1. Post-quantum mTLS default. ML-KEM-768 key exchange for all proxy-to-proxy handshakes. Proxy cryptography library swapped from ring to aws-lc to get PQ algorithms. TLS algorithm labels now exported as metrics.
2. Native Kubernetes sidecars → beta. Use config.beta.linkerd.io/proxy-enable-native-sidecar: "true". Sidecar container starts before app container and terminates after — fixes the classic job-with-sidecar-that-never-exits problem.
3. Service-port blocking. Connections to undefined clusterIP Service ports are now rejected at the proxy, matching kube-proxy. Removes a fingerprinting vector.
4. Windows containers (BEL). Annotate linkerd.io/inject: windows + specify Windows proxy image. Full TLS, retries, timeouts, circuit breaking on Windows workloads. OSS preview shipped in 2.18.
5. FIPS 140-3 opt-in (BEL). AES_256_GCM via aws-lc in FIPS mode, replacing default AES_128_GCM + PQ hybrid.
6. Supply-chain security. Every stable image ships SBOM and SLSA v0.2 provenance as OCI 1.1 referrers, signed by digest. Verify with cosign verify-attestation or skopeo inspect --format '{{.LayersData}}'.
7. New on-cluster dashboard (BEL). Replaces aging linkerd-viz; auditable TLS traffic view, plaintext-traffic detector, FIPS module detector. Compatible with 2.17+.
8. Bug fixes: discovery staleness in native-sidecar mode, invalid podSelector rejection on Server, proxy CPU limits now interpreted as cores-on-machine (not millicores) when set as integer.

Linkerd's pitch is "operational simplicity + zero-config mTLS". Istio's pitch is "everything you could want, plug-ins, ecosystem, L7 policy at scale". Cilium mesh's pitch is "kernel-level dataplane, no sidecars, one thing for CNI + policy + mesh". For a greenfield cluster that just needs mTLS + retries + observability, Linkerd is the shortest path to production. For heterogeneous traffic, ingress-mesh convergence, or pre-existing Envoy config, Istio is the default.

Gotchas

1. Injection doesn't retroactively apply. Annotating a namespace does nothing until pods restart. kubectl rollout restart deploy is mandatory.
2. linkerd check is not optional. Run it after every control-plane upgrade; the proxy and control plane must match minor versions.
3. OSS-only users must live on the edge channel. The stable-2.x binaries come from Buoyant, not the open-source project. Helm repo for pure OSS is https://helm.linkerd.io/edge, not /stable.
4. Server creation locks down the port. The instant you apply a Server CRD, its port becomes default-deny. Either create the AuthorizationPolicy in the same commit, or set accessPolicy: audit on the Server first.
5. Opaque ports for non-HTTP protocols. Postgres (5432), MySQL (3306), Redis (6379), Elasticsearch (9300), MongoDB (27017), NATS (4222), Kafka (9092) — all must be in config.linkerd.io/opaque-ports or the proxy's protocol detector will close connections.
6. MeshTLSAuthentication identity format. *.booksapp.serviceaccount.identity.linkerd.cluster.local — the serviceaccount.identity.linkerd.cluster.local suffix is hard-coded to the trust domain; linkerd.cluster.local is the default identity suffix regardless of the workload cluster domain.
7. ECDSA P-256 required for the trust anchor. RSA keys are rejected — do not copy a CA from cert-manager defaults without checking the algorithm.
8. Trust anchor ≠ issuer expiry. A 10-year trust anchor with a 1-year issuer is standard. When issuer expires, rotate with linkerd upgrade --identity-issuer-certificate-file=.... Don't let the issuer expire — all proxies stop handshaking.
9. ServiceProfile (legacy) silently wins over HTTPRoute if both exist for a service. Delete ServiceProfiles when migrating.
10. Retries only work on HTTP/gRPC. Opaque TCP services cannot retry. If you need a retry on Postgres, it belongs in the app driver.
11. linkerd-cni vs init container. If your cluster forbids NET_ADMIN in pods, install the linkerd-cni plugin instead — it sets iptables at CNI time, not inside an init container. Default install uses the init container; switch before you hit the wall.
12. Gateway API CRDs are a prerequisite. Linkerd 2.18+ stopped installing Gateway API CRDs automatically to coexist with other controllers. If Gateway API isn't already in the cluster: kubectl apply -f https://github.com/kubernetes-sigs/gateway-api/releases/download/v1.2.1/standard-install.yaml first.
13. Native sidecar (config.beta.linkerd.io/proxy-enable-native-sidecar) requires K8s 1.29+ and SidecarContainers feature gate (on by default on 1.29+). Mixing native-sidecar pods with non-native in the same namespace is fine but debug logs diverge — check twice.
14. audit mode is per-Server, not per-pod. Setting accessPolicy: audit on a Server applies to every port it selects. You can't partially audit.
15. Health probes need auth exemption. Kubelet probes originate from a non-meshed source (kubelet itself, unmeshed node IP). Under deny default you must allow them via NetworkAuthentication on the node CIDR or set config.linkerd.io/skip-inbound-ports to include the probe port.
16. Multicluster gateway requires a LoadBalancer. Hierarchical mode needs a public/VPC-reachable endpoint for the remote cluster's linkerd-gateway service. ClusterIP will not work.
17. linkerd viz is legacy on 2.19. It still works, but the replacement dashboard is the path forward. Don't build long-term tooling against linkerd-viz API shapes.
18. PQ cipher interop. If you peer with an older Linkerd (≤2.18) or an external TLS peer without ML-KEM-768 support, the handshake falls back to classical X25519 — intentional, but verify with linkerd viz tap that you're actually getting tls=post-quantum on new traffic.
19. linkerd inject is for manual injection. Prefer namespace annotation + rollout — linkerd inject edits YAML locally and is easy to drift out of sync with git.
20. skip-outbound-ports bypasses mTLS too. If you skip port 443 to "keep TLS as-is", you also lose Linkerd telemetry, retries, and identity metrics for those flows. Only skip for actual non-HTTP/non-gRPC outbound that would break detection.

Minimum production recipe

1. Generate certs with step + ECDSA P-256 (trust anchor 10y, issuer 1y).
2. Helm install with explicit certs (identityTrustAnchorsPEM, identity.issuer.tls.crtPEM, identity.issuer.tls.keyPEM).
3. Install Gateway API CRDs first (v1.2.1+).
4. Set cluster default to audit for 48 hours, watch linkerd viz tap / access logs for policy-rejected.
5. Flip to deny once clean, then add per-Namespace AuthorizationPolicy objects for anything that legitimately needs cross-namespace traffic.
6. Add opaque-ports annotations on stateful services (databases, caches, message queues).
7. Integrate retries/timeouts via HTTPRoute annotations on critical idempotent paths — do not retry POSTs without explicit opt-in.
8. Wire Prometheus to scrape the proxy metrics port (:4191 on each proxy by default); linkerd-viz ships its own Prometheus, replace with your existing one via Helm values.
9. Rotate issuer cert annually via linkerd upgrade --identity-issuer-certificate-file=....
10. Pin linkerd CLI to the exact proxy/control-plane version in CI to prevent skew.
