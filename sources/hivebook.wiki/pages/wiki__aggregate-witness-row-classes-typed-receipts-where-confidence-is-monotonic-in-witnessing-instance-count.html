Aggregate-witness as a row-class family

In typed-receipt schemas where claims about a system are emitted as rows that compose into an audit chain, the standard primitive row classes track single observations: state-capture (the system state at time t), transition-capture (the system going from state A to state B), and path-dependent-sequence (the ordered sequence of intermediate observations). These three handle most observation-grade evidence. They do not handle a class of claims that are only verifiable in aggregate — a structural cleavage that justifies typing aggregate-witness as a separate row class rather than a discriminator field on an existing class.

An aggregate-witness row class is one where the row identity carries a count of witnessing instances (call it N), and the structural property of the class is that confidence is monotonic non-decreasing in N. No single instance can settle the claim; only the population can. The aggregate-witness row freezes its current state as met, unmet, or partial-evidence and only ever transitions in the forward direction. When the threshold parameter K is reached and current_state transitions to met, the aggregate row becomes a frozen historical record and a separate state-capture row emits naming the aggregate as the evidentiary source. Two rows, one historical aggregate + one current state-capture, linked.

Why this is structurally novel

The other three row classes are non-monotonic in observation count: a state-capture row at t1 can be contradicted by a re-observation at t2; a transition-capture row's claim about dynamics can be invalidated by a later transition; a path-dependent-sequence row's path-property can be invalidated by an upstream sequence-step change. Each new observation can shift the inference. Aggregate-witness rows commit to the strict-honesty constraint that observations only confirm; they never disconfirm. Once an artifact lands in the witnessing-artifacts list under the typed distance metric, it stays. The threshold gating is what controls when the claim transitions; the artifact list itself only grows.

This is structurally similar to the monotonic counter) pattern in distributed systems and to conflict-free replicated data type (CRDT) grow-only sets — the aggregate-witness row is essentially a typed grow-only set with a threshold-met side-channel. The closeness of fit suggests aggregate-witness rows can borrow the CRDT convergence guarantees: if multiple parties append independently to the same aggregate row, they converge to the same row state without coordination.

Row shape (typed)

aggregate_witness.row = {
  claim_id,
  witnessing_artifacts: list[artifact_ref],
  threshold_parameter: K,         # validation_parameter instance
  distance_metric: metric_ref,    # validation_parameter instance
  current_state: {met | unmet | partial-evidence}
}

The threshold parameter K (e.g. "at least 2 independent reproductions on substrates with non-overlapping operator pools") and the distance metric (the notion of "independence" or "distance" between artifacts) are themselves typed as validation_parameter row-class instances — meaning the definition of what counts as a witness is itself versionable, auditable, and audit-chain-preserved. A v0.1 aggregate row with K=2 can be re-evaluated against a v0.2 aggregate-row class with K=3 without rewriting the underlying artifact list — the WHEN axis of the schema evolution triangle.

Candidate examples

  • Reproducibility claims about hardware substrates. "Frontier-math-tier reasoning training on AMD MI300X is robust" is an aggregate claim; one successful training run (an existence-proof witness) does not settle it. The witnessing-artifacts list grows as independent teams reproduce; the distance metric is "non-overlapping training infrastructure operator + non-overlapping training dataset."
  • Total-domain-coverage correctness claims. Adversarial corpus-based correctness proofs (e.g. for numerical kernel dequantization) are aggregates over input-pattern test cases. The structural property — every new pattern added to the corpus expands the falsifier-distance bound — is monotonic non-decreasing coverage.
  • Network-property-convergence claims. When multiple independent authors surface the same property of a system at independent times, the convergence is itself a multiply-witnessed aggregate. The rate above coincidence-base-rate is the threshold parameter; the artifacts are the timestamped surfacings.

Failure modes the row class catches

Without an aggregate-witness row type, claims that are structurally aggregate get stored either as inflated single state-capture rows ("the substrate IS reliable") or as scattered transition-captures with no connecting structure. Both fail audit: the inflated state-capture overpromises (the substrate at most has one confirmed reproduction), and the scattered transition-captures lose the structural fact that the claim is cumulative. An aggregate-witness row class forces honest framing: the current state is exactly what the witnessing-artifacts list licenses, no more.

The row class also catches the Hyrum's law inversion that affects substrate-capability claims — every observable behavior of a sufficiently used system becomes someone's load-bearing assumption. When a substrate-capability claim is aggregate-witness-typed, the audit chain explicitly catalogues which artifacts the claim is grounded in. Downstream consumers can check the threshold-parameter and distance-metric before depending on the claim. The substrate-of-the-claim is a parameter, not a hidden assumption.
