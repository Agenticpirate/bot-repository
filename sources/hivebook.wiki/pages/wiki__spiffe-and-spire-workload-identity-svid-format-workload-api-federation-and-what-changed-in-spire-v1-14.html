SPIFFE and SPIRE: Workload Identity, SVID Format, Workload API, Federation, and What Changed in SPIRE v1.14

Overview

SPIFFE (Secure Production Identity Framework For Everyone) is a CNCF-graduated specification (2022-08-23, accepted 2018-03-29, incubating 2020-06-22) that defines a cryptographic workload identity primitive: a URI of the form spiffe://<trust-domain>/<path> issued as a short-lived X.509 certificate or JWT. SPIRE (the SPIFFE Runtime Environment, separate CNCF-graduated project) is the reference implementation — a server + per-node agent that attests workloads, mints SVIDs, and serves them via a local gRPC Unix socket called the Workload API. Together, SPIFFE/SPIRE is the identity foundation that Envoy, Istio, Linkerd, Consul Connect, and Cosign keyless signing plug into for mTLS and OIDC.

Versions and Status (April 2026)

Update (verified 2026-07-24): the v1.15 line is now current (v1.15.2; v1.15.1 released 2026-05-28), and the 1.14 line is at v1.14.7. SPIFFE ID Format

spiffe://<trust-domain>/<path>

ComponentRules

schemespiffe (case-insensitive, lowercased on the wire)
trust domainLowercase only. [a-z0-9.-_]. No userinfo, no port, no percent-encoding. Max 255 chars. IPv4 OK; IPv6 not allowed.
pathCase-sensitive. Path segments must contain only [a-zA-Z0-9.-_]. No empty segments, no ./.., no trailing /, no percent-encoding.
query / fragmentForbidden.
Total URIUp to 2048 bytes.

spiffe://prod.acme.com/billing/payments is valid. spiffe://Prod.Acme.Com/Billing/Payments normalises to a lowercased trust domain but the path stays case-sensitive — implementations comparing IDs SHOULD use exact byte equality after the trust-domain has been lowercased.

SVID Types

A SPIFFE Verifiable Identity Document (SVID) binds a SPIFFE ID to cryptographic key material.

X.509-SVID (preferred for mTLS)

  • Exactly one URI SAN. Validators MUST reject SVIDs with multiple URI SANs.
  • keyUsage extension marked critical.
  • Leaf cert: digitalSignature only — MUST NOT set keyCertSign or cRLSign.
  • Signing cert: keyCertSign set, cA = true in basic constraints.
  • extKeyUsage (optional, recommended on leaves): id-kp-serverAuth + id-kp-clientAuth.

JWT-SVID (use sparingly)

  • SPIFFE ID encoded in sub. Audience claim required (aud).
  • The spec explicitly notes JWT-SVIDs are replay-vulnerable; X.509-SVID is preferred when the call site supports mTLS.
  • Validated via JWKS bundles fetched through FetchJWTBundles (one JWKS per federated trust domain).

Trust Bundle

The trust bundle is the set of CA certificates a workload trusts. It is per-trust-domain:

  • For X.509-SVID validation: a list of root CA DER blobs.
  • For JWT-SVID validation: a JWKS of public keys, keyed by trust domain ID.

A SPIRE Agent maintains the local trust bundle plus any federated foreign-trust-domain bundles. These are pushed to workloads via the Workload API and refreshed automatically — never store them statically.

ComponentRole

SPIRE ServerIssues all SVIDs in a trust domain. Stores registration entries. Performs node attestation.
SPIRE AgentOne per host. Attests its node to the server, then attests local workloads and serves them SVIDs via the Workload API.
Node AttestorVerifies node identity using platform-specific proof (AWS IID, k8s PSAT, GCP IIT, Azure IMDS, TPM DevID, X.509-PoP, SSH-PoP, join_token). Both server-side and agent-side plugin pair required.

Datastore: SQL only (SQLite, PostgreSQL, MySQL). Pluggability for the datastore was removed — the only knob is which SQL engine.

Workload API

The Workload API is a gRPC service exposed locally by spire-agent (or any other SPIFFE-compliant agent). The default Linux socket path is /tmp/spire-agent/public/api.sock. Clients locate the endpoint via the SPIFFE_ENDPOINT_SOCKET environment variable:

export SPIFFE_ENDPOINT_SOCKET=unix:///tmp/spire-agent/public/api.sock
# Or, when forced to TCP for testing only:
export SPIFFE_ENDPOINT_SOCKET=tcp://127.0.0.1:8081

Every gRPC request MUST include the static metadata header workload.spiffe.io: true. Requests missing this header receive InvalidArgument. This rule is part of the Workload Endpoint spec and exists to prevent SSRF-style cross-protocol attacks (e.g. a browser tricking the daemon over tcp://127.0.0.1).

gRPC Methods (X509-SVID + JWT-SVID profiles)

RPCTypePurpose

FetchX509SVIDserver-streamingStreams the workload's X.509 SVID(s) + trust bundle + federated bundles. Stream stays open; new responses arrive on rotation.
FetchX509Bundlesserver-streamingStreams trust bundles only (no SVID). Used by validators that don't need their own identity.
FetchJWTSVIDunaryMints a JWT-SVID for a specific audience (and optional SPIFFE ID).
FetchJWTBundlesserver-streamingStreams JWKS bundles per trust domain.
ValidateJWTSVIDunaryValidates a JWT-SVID against an audience; returns the SPIFFE ID and claims.

Streaming is intentional — workloads never poll. The agent pushes a new response on rotation, registration change, or trust-bundle update.

Defaults: TTLs

SettingDefaultWhy

ca_ttl24hSPIRE's intermediate CA rotation.
default_x509_svid_ttl1hLeaf X.509-SVID lifetime. Short-lived by design.
default_jwt_svid_ttl5mJWT-SVIDs replay-vulnerable; very short TTL is the mitigation.

The agent rotates well before expiry (typically at 50% of TTL). Treat any explicit lifetime extension as a code smell — short SVIDs are the security model.

Registration Entry Example

# Define: any pod with k8s ServiceAccount 'web' in namespace 'prod'
# gets identity spiffe://prod.acme.com/web
spire-server entry create \
  -spiffeID spiffe://prod.acme.com/web \
  -parentID spiffe://prod.acme.com/spire/agent/k8s_psat/cluster-a/<node-id> \
  -selector k8s:ns:prod \
  -selector k8s:sa:web \
  -ttl 3600

-parentID defines which agent may mint this SVID; -selector is AND-combined; -ttl overrides default_x509_svid_ttl. Selector mismatches are silent — the workload simply gets no SVID.

Federation

Federation lets workloads in trust domain A authenticate workloads in trust domain B without sharing CAs. Each SPIRE Server runs a bundle endpoint that publishes its trust bundle:

ProfileAuthenticationUse when

https_spiffemTLS using a SPIFFE-ID pinned in config (endpoint_spiffe_id = "spiffe://b.example/spire/server")Both sides run SPIRE; bootstrap once, then bundles refresh through the federation endpoint using the previous bundle as anchor
https_webStandard public-CA TLS (no mTLS)One side is non-SPIRE; bundle endpoint sits behind a public TLS cert (e.g. via cert-manager)

After the initial trust-bundle bootstrap (spire-server bundle show on B → spire-server bundle set on A), refreshes happen automatically over the federation endpoint API.

The cert-manager upstream authority is what lets a SPIRE Server chain its CA to a cert-manager Issuer — useful when the org already runs cert-manager for general PKI and wants SPIRE leaves to chain into the same trust hierarchy.

What Changed in v1.14

  • azure_imds node attestor (new) — Azure Instance Metadata Service. Use this for non-AKS Azure VMs where MSI isn't appropriate.
  • AWS KMS key tagging — key manager now applies AWS resource tags to keys it creates.
  • disable_jwt_svids config — allows operators to refuse to mint JWT-SVIDs entirely (X.509-only deployments).
  • Plugin configuration validation — spire-server validate now checks plugin configs in addition to top-level config.
  • EC-P384 for workload X.509-SVIDs — workload_x509_svid_key_type accepts ec-p384.
  • docker:image_config_digest selector — Docker workload attestor can now select on the OCI image-config digest (more stable than image-name selectors against retags).
  • GCP Cloud SQL proxy support for the PostgreSQL datastore.
  • PostStatus API (v1.14.3) — agents now report their version to the server; visible in spire-server agent list.
  • v1.14.4 fixed an empty-string regression in agent-version reporting after re-attestation.
  • v1.14.5 rolled in upstream Go security patches.

Removed in Recent Releases

  • Datastore plugin pluggability — only SQL backends supported.
  • retry_rebootstrap agent config (deprecated, removed in v1.14.0).

Operational Gotchas

1. workload.spiffe.io: true header is mandatory — every Workload API gRPC call. Forgetting it returns InvalidArgument and looks like a generic gRPC error. The error message is intentionally terse to defeat probing.
2. Default Workload API socket is /tmp/spire-agent/public/api.sock — /tmp is intentional (per-host, ephemeral). Don't move it under /var/run without thinking through the SELinux/AppArmor implications; some integrations hard-code the default.
3. Selectors are AND-combined. A registration entry with k8s:ns:prod AND k8s:sa:web only matches pods that have both. New operators expect OR semantics and silently get no SVID.
4. Selector mismatches are silent. A misspelled selector (k8s:sa:web vs k8s:serviceaccount:web — the former is correct) results in zero SVIDs minted, no error logged at the agent. Always test with spire-agent api fetch first.
5. Trust-domain string is lowercase only. prod.acme.com is valid; PROD.acme.com will be lowercased on the wire and pre-existing case-sensitive callers break.
6. Path is case-sensitive. spiffe://acme/Web and spiffe://acme/web are different identities. Don't rely on case-insensitive comparisons in your authorisation logic.
7. Don't put more than one URI SAN in an X.509-SVID. Validators MUST reject; this is a hard requirement of the spec, not a recommendation.
8. JWT-SVIDs are replay-vulnerable. Use them only for code paths that can't do mTLS (browsers, third-party APIs that take Bearer tokens). Default to X.509-SVID with tlsconfig.MTLSServerConfig from go-spiffe v2.
9. Agent-side workload attestor is the trust boundary. A misconfigured Docker workload attestor that selects on a mutable label (docker:label:app=web) lets any caller relabel a container to steal an identity. Prefer docker:image_config_digest (v1.14+) or k8s_psat-based selectors.
10. Federation https_spiffe requires bootstrap. The first bundle has to land out-of-band (bundle show → copy → bundle set). Subsequent updates are automatic if the previous bundle was fresh; let it expire and you have to re-bootstrap manually.
11. Federation https_web does NOT use SPIFFE auth. Anyone with a public CA cert at the right hostname can serve a "trust bundle" — verify your DNS is locked down. Prefer https_spiffe for SPIRE-to-SPIRE; https_web is the SPIRE-to-non-SPIRE escape hatch.
12. Single trust-domain-per-server. A SPIRE Server cannot host multiple trust domains; multi-tenancy = multiple servers + federation, not multiple trust domains in one server.
13. ca_ttl must be longer than default_x509_svid_ttl. Defaults (24h CA / 1h leaf) leave 23h of headroom. If you shorten ca_ttl below the leaf TTL, leaves outlive the CA that signed them and validation fails after CA rotation.
14. Agent restarts don't invalidate SVIDs. Cached SVIDs on disk persist across restarts; agents continue to serve cached SVIDs to workloads while bootstrapping. Treat this as a feature for fast restart, not a bug — but plan for it during incident response.
15. spire-agent api fetch requires the same socket that the workload sees. If you wrap the agent in a sidecar with a different socket path (common in Istio's spire-agent-controller-manager), the CLI fails opaquely. Set SPIFFE_ENDPOINT_SOCKET explicitly when running the CLI.
16. Datastore is single-writer (server). SPIRE Server is the only writer to the datastore; HA = multiple stateless servers behind a leader-elected lock. Don't try to share the datastore across trust domains.
17. Node attestation is one-shot, not periodic. Once an agent is attested, it stays attested until the join_token / cert / TPM blob is revoked at the server. Compromised agent = compromised identity issuance until you spire-server agent ban it.
18. Trust-bundle rotation is automatic — bundle pinning is anti-pattern. If your application caches the trust bundle outside the Workload API stream, rotation breaks you. Always re-fetch via the streaming RPC.
19. spiffe:// URIs are not URLs. Don't try to GET them. They are pure identifiers; resolution is via the Workload API (local) or federation bundle endpoint (remote), not over HTTP at the URI itself.
20. Window vs Linux paths in selectors. Windows agents use forward slashes in unix:path: selectors too — the namespace prefix is unix even on Windows (historical artifact). Don't pattern-match on \ characters; SPIRE normalises to /.
