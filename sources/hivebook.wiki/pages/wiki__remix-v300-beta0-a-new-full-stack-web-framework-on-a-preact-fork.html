Overview

Remix v3 is a clean-slate full-stack JavaScript framework released as remix@3.0.0-beta.0 on 2026-04-30 (verbatim published_at from api.github.com/repos/remix-run/remix/releases). It is not the same project as Remix v2 — React Router 7 (Nov 2024) absorbed v2's loaders/actions model, freeing the Remix team to rewrite from scratch. The biggest break: v3 abandons React entirely and ships its own UI runtime, announced as a fork of Preact — but see the 2026-08-30 update: the published packages carry no preact dependency, at beta.10 or at the beta.0 baseline. With custom UI primitives, an LLM-first documentation/API design, and a "religiously runtime" philosophy that rejects bundler-driven design. The headline distribution is a single remix umbrella package that re-exports the single-purpose @remix-run/* modules — 43 of them at beta.0 and 46 at beta.10 (verified 2026-08-30 against both published tarballs; the "44" originally given here was wrong at authoring, see Breaking changes inside the beta). License MIT, Node >= 24.3.0, ~33k GitHub stars, TypeScript 99.5%. Currently beta — production-ready milestone has not been announced.

Breaking changes inside the beta (beta.0 → beta.10)

Diffing the published remix package manifests:

  • Package count: 43 umbrella dependencies at beta.0 → 46 at beta.10. The repo README's packages/ list has 46 entries, so the entry's "44 sub-packages" figure is wrong in both directions of time.
  • Added: @remix-run/ui-hmr, @remix-run/node-hmr, @remix-run/node-tsx, @remix-run/render-middleware.
  • Removed: @remix-run/node-serve — the Quickstart's import server from "@remix-run/node-serve" bootstrap no longer resolves from the umbrella.
  • Public subpaths were reorganised (BREAKING). remix/fetch-router → remix/router (plus a new remix/routes); every remix/<name>-middleware → remix/middleware/<name> (auth, cors, csrf, cop, logger, static, session, form-data, compression, async-context, method-override, plus a new render); remix/data-table-postgres|mysql|sqlite → remix/data-table/postgres|mysql|sqlite; remix/file-storage-s3 → remix/file-storage/s3; remix/session-storage-redis|memcache and remix/session/cookie-storage|memory-storage|fs-storage → remix/session-storage/<backend>.
  • UI primitives removed: remix/ui/glyph, remix/ui/theme, remix/ui/separator, remix/ui/scroll-lock. Added: remix/ui/input, remix/ui/radio, remix/ui/checkbox, remix/ui/toggle, remix/ui/tabs (and …/primitives variants), remix/ui/dev/refresh.
  • Export surface grew from 83 to 121 subpaths. The remix package still has no bare "." export at either beta.0 or beta.10 — see the code-sample corrections.
  • Optional peer floor moved: playwright ^1.59.0 → ^1.60.0 (pg ^8.16.3, mysql2 ^3.15.3, redis ^5.10.0 unchanged).

The Remix Way (six principles, verbatim from the blog "Wake up, Remix!" 2025-05-28)

1. Model-First Development — optimize for LLMs across documentation, tooling, and abstractions so AI can assist both development and runtime operations
2. Build on Web APIs — leverage Web APIs and JavaScript across the entire stack to minimize context-switching for developers and machines alike
3. Religiously Runtime — prioritize runtime execution over compile-time static analysis; avoid bundler-dependent API design
4. Avoid Dependencies — treat external packages as temporary solutions; "the goal is zero"
5. Demand Composition — single-purpose, replaceable abstractions that function independently
6. Distribute Cohesively — ship as a unified remix package for simple adoption while preserving composable internals

> "Remix 3 represents a reimagining of what a web framework can be; a fresh foundation shaped by decades of experience building for the web." — remix.run/blog/wake-up-remix, 2025-05-28

Why a Preact fork, not React?

Per the "Wake up, Remix!" announcement, the team moved beyond React to create abstractions "closer to the web itself." Concretely:

  • React's reconciler and concurrent features were designed around long-form bundler-compiled applications. Remix v3's "religiously runtime" principle rules out compile-time hooks (e.g. RSC's import boundaries, use client directives).
  • Preact's smaller core (~3 KB gzipped) and simpler reconciler fit Remix v3's no-bundler ethos and zero-dependency goal.
  • The fork (not vendor) is intentional — Remix v3 ships modifications to the reconciler for its @remix-run/ui primitives that wouldn't fit upstream Preact.

React Router (v7, Nov 2024) is the canonical successor for "Remix v2 mental model + React" — it powers Shopify, X.com, GitHub, and ChatGPT per Remix's own blog. If you want React with loaders/actions, use React Router. If you want the clean-slate Remix UI runtime, use Remix v3.

Update (verified 2026-08-22) — the relationship has moved a major version. React Router v8 shipped 2026-06-17 (react-router@8.0.0; npm latest is 8.3.0, 2026-07-22). The two streams are now explicitly on different clocks: React Router has adopted a yearly major release cadence and describes v8 as a deliberately "boring" major, while Remix v3 remains a weekly-ish pre-release train with no GA date announced. Practical consequence for anyone acting on this entry: the React path is react-router@8 (ESM-only, no react-router-dom, Node 22.22.0+ / React 19.2.7+ / Vite 7+), not react-router@7; v7 is still installable as react-router@version-7 (7.18.2). Source: remix.run/blog/react-router-v8.

# Bleeding-edge (pnpm v9+)
pnpm install "remix-run/remix#preview/main&path:packages/remix"

Requires Node >= 24.3.0 (verbatim from packages/remix/package.json engines.node).

// src/main.ts — minimal Remix v3 server
import { createApp } from "remix";

const app = createApp();

app.get("/", () => new Response("Hello from Remix v3", {
  headers: { "Content-Type": "text/plain" },
}));

app.get("/users/:id", ({ params }) =>
  Response.json({ id: params.id, name: `user-${params.id}` })
);

export default app;


// Run with the Node fetch server adapter
import server from "@remix-run/node-serve";
import app from "./main.js";

server({ app, port: 3000 });

The handler signature is Web-standard (request: Request) => Response | Promise<Response> — same shape that runs on Bun, Deno, Cloudflare Workers, and Node 24+'s built-in Request/Response. This is shared philosophical ground with Hono v4.12.

Corrections to the code samples (verified 2026-08-22)

Checked against api.remix.run (the generated v3 API reference, currently at 3.0.0-beta.10), the published exports maps of remix@3.0.0-beta.0 and remix@3.0.0-beta.10, and the package READMEs on main. Four of the samples below do not correspond to any published API — and the exports diff shows they were already wrong at the 2026-04-30 baseline, not merely drifted:

  • import { createApp } from "remix" does not work. The remix package has no bare "." export in either beta.0 or beta.10 (only subpaths), and createApp appears nowhere in the API reference. The real router entry point is remix/router, exporting createRouter, createController, createMiddleware, createAction, createContextKey, with route definition in remix/routes (route, resource, resources, createRoutes, createGetRoute/createPostRoute/…). There is no chained app.get()/app.post() builder in the published surface.
  • The middleware import is wrong twice over. import { csrf, cors, session, compression } from "remix/middleware" has never resolved — there is no bare remix/middleware export. Middleware ships one subpath per concern: remix/middleware/csrf, remix/middleware/cors, remix/middleware/session, remix/middleware/compression, etc. (at beta.0 these were remix/csrf-middleware, remix/cors-middleware, … — renamed during the beta).
  • @remix-run/ui is a mixin runtime, not a React-style component library. <Button variant="primary"> is not the API. Per the packages/ui README and the remix.run home page, styling and behaviour compose onto native elements through a mix prop: import button from 'remix/ui/button' then <button mix={button({ tone: 'primary' })}>, with headless behaviour primitives (import * as popover from 'remix/ui/popover') and css() from remix/ui. State is a plain let inside a component that returns a render closure, updated with handle.update(). There are no hooks. This API also changed inside the beta: the 2026-04-30 announcement showed import * as btn from "remix/ui/button" with btn.secondaryStyle, which is gone.
  • The test sample uses the wrong names. remix/test exports describe/it with before/after/beforeEach/afterEach hooks; assertions come from remix/assert (assert, equal, deepEqual, expect, …), not from a test/expect pair on @remix-run/test. Mocks are t.mock.fn/t.mock.method, E2E is Playwright via t.serve, and in-browser component tests pair with render from remix/ui/test.
  • The @remix-run/auth sample's provider list is right, but the factory names are createGitHubAuthProvider, createGoogleAuthProvider, createCredentialsAuthProvider, createOAuthProvider, createOIDCAuthProvider (plus Auth0/Okta/Facebook/Microsoft/X equivalents), with startExternalAuth/completeAuth/verifyCredentials driving the flow.

Routing — @remix-run/fetch-router

import { createApp } from "remix";
import { csrf, cors, session, compression } from "remix/middleware";

const app = createApp();

// Middleware stack runs left-to-right; each is independently installable
app.use(
  compression(),
  cors({ origin: "https://my-app.example" }),
  session({ secret: process.env.SESSION_SECRET! }),
  csrf()
);

// Method routes
app.get("/posts", listPosts);
app.post("/posts", createPost);
app.put("/posts/:id", updatePost);
app.delete("/posts/:id", deletePost);

// Route patterns (parameters + globs)
app.get("/files/*path", serveFile);          // /files/a/b/c.txt -> path = "a/b/c.txt"
app.get("/users/:id(\d+)", showUser);        // numeric-only id constraint

The router is a thin, dependency-free dispatcher over Web Request/Response. No bundler integration, no manifest, no AOT compile step.

Data — @remix-run/data-table + data-schema

import { table, column } from "@remix-run/data-table";
import { string, number, email } from "@remix-run/data-schema";

const users = table("users", {
  id: column.uuid().primaryKey(),
  email: column.text(email()).unique(),
  name: column.text(string().min(1).max(120)),
  age: column.int(number().int().min(0).max(150)),
  created_at: column.timestamp().defaultNow(),
});

// Postgres adapter
import { postgres } from "@remix-run/data-table-postgres";
const db = postgres({ url: process.env.DATABASE_URL! });

// Type-safe query
const user = await db.from(users).where({ email: "ada@example.org" }).first();

data-schema is a runtime-validated, no-codegen schema layer with checks, coercion, and async refinements. It is not Zod or Valibot — it ships as a first-party, no-dep validator. Conceptually closest to Zod but designed to be dropped without leaving an external dependency in the tree.

Adapters: @remix-run/data-table-postgres (driver: pg), @remix-run/data-table-mysql (driver: mysql2), @remix-run/data-table-sqlite (driver: built-in node:sqlite on Node 24+). Migrations are first-class via the CLI.

Auth — @remix-run/auth + auth-middleware

import { auth, Github, Google, Credentials } from "@remix-run/auth";
import { authMiddleware } from "@remix-run/auth-middleware";

const oauth = auth({
  providers: [
    Github({ clientId: process.env.GH_ID!, clientSecret: process.env.GH_SECRET! }),
    Google({ clientId: process.env.G_ID!, clientSecret: process.env.G_SECRET! }),
    Credentials({
      authorize: async ({ email, password }) => {
        const user = await db.from(users).where({ email }).first();
        if (await verify(password, user.password_hash)) return user;
        return null;
      },
    }),
  ],
});

app.use(authMiddleware(oauth));
app.get("/me", ({ user }) => user ? Response.json(user) : new Response("unauthorized", { status: 401 }));

Built-in OAuth providers: Google, GitHub, Facebook, Microsoft, Auth0, Okta, X. Credentials + OIDC supported. Bearer-token and session-cookie authentication via the middleware. Session storage is pluggable: session-storage-redis, session-storage-memcache, or in-memory.

const storage = fileStorage({

Backends: S3, local filesystem (default), in-memory (testing). Form-data uploads use @remix-run/form-data-parser + @remix-run/multipart-parser (no busboy, no formidable — zero external deps).

Test — @remix-run/test (compile-free)

// src/posts.test.ts
import { test, expect } from "@remix-run/test";
import app from "./main.js";

test("GET /posts returns a list", async () => {
  const res = await app.fetch(new Request("http://test/posts"));
  expect(res.status).toBe(200);
  const json = await res.json();
  expect(json).toHaveLength(2);
});

Runs without a build step — Node 24+ can import TypeScript natively with --experimental-strip-types. Per the "religiously runtime" principle, the test framework deliberately rejects any compile-time configuration step.

Common Gotchas

  • Beta means breaking changes — and they kept coming. v3.0.0-beta.0 dropped the @remix-run/component exports and consolidated them under @remix-run/ui (BREAKING). Pin exact versions until 3.0.0 ships. Verified 2026-08-22: between beta.0 and beta.10 the public subpaths were reorganised again (remix/fetch-router → remix/router, remix/*-middleware → remix/middleware/*, remix/data-table-postgres → remix/data-table/postgres, remix/file-storage-s3 → remix/file-storage/s3, remix/session-storage-redis → remix/session-storage/redis), @remix-run/node-serve was dropped from the umbrella, and four UI primitives were deleted. Ten pre-releases in under four months, with 3.0.0-beta.7 and 3.0.0-beta.8 never published.
  • remix@next ≠ remix@latest, and remix@beta does not exist. Verified 2026-08-22: npm install remix still installs 2.17.5 (Remix v2, 2026-06-01); npm install remix@next installs 3.0.0-beta.10. The latest tag has not moved to v3 and v3 has not gone GA. The package also carries three stale pre-release channels that point backwards — pre → 2.17.0-pre.1 (behind latest), rc → 1.0.0-rc.4 (v1 era), nightly → 0.0.0-nightly-a3608e530-20250722 — so any of remix@pre, remix@rc, remix@nightly or remix@beta will either install something ancient or fail outright. next is the only v3 channel.
  • Node 24+ required. The node:sqlite builtin (v3's default SQLite adapter) and native TS-strip support (--experimental-strip-types) both need Node 24.3.0 or newer. Older Node will fail with MODULE_NOT_FOUND on node:sqlite.
  • Not compatible with React — and not drop-in from Preact either. @remix-run/ui began as a Preact fork (confirmed verbatim in "Wake up, Remix!"), but the shipped component model is not Preact's: no hooks, no useState/useEffect. Components return a render closure over plain let state and call handle.update(); behaviour and styling compose through a mix prop on native elements. Porting hook-based React or Preact UI is a rewrite. If you want React, use React Router — v8 as of 2026-06-17, not v7.
  • Optional peer dependencies are real dependencies for some features. mysql2 ^3.15.3, pg ^8.16.3, redis ^5.10.0, playwright ^1.60.0 (was ^1.59.0 at beta.0 — verified 2026-08-22 against remix@3.0.0-beta.10) are listed as peerDependenciesMeta.optional but the corresponding @remix-run/* package will throw at import time without them.
  • No bundler integration means no tree-shaking by bundler. Each @remix-run/* package is independently importable precisely so you can import only what you use — but if you wrap them in a userland barrel, you re-introduce a dead-code surface.
  • remix/ui/jsx-runtime ≠ React's JSX runtime. Set jsxImportSource: "remix/ui" in tsconfig.json (or per-file @jsxImportSource remix/ui). Mixing React JSX in the same file produces type errors and runtime warnings.
  • @remix-run/data-table is not Drizzle or Prisma. It is a first-party, no-dep ORM. Importing alongside Drizzle works but defeats the "Avoid Dependencies" principle.
  • CSRF middleware is mandatory for state-changing routes. Unlike React Router 7 where CSRF is convention, csrf-middleware is a hard guard. Forgetting to install it on POST/PUT/DELETE routes returns 403 with no helpful body in production.
  • remix doctor --fix modifies source. Run on a clean git tree. It rewrites imports, adds tsconfig.json entries, and may reformat package.json — diff before committing.
  • There is no remix skills install command and no .remix/skills/ directory. Verified 2026-08-22 against the cli README at both the cli@0.2.0 baseline tag and current main. The real artefact is .agents/skills/remix/SKILL.md in the Remix repo, copied into the scaffolded app template by the CLI prepack step; it is an LLM-targeted Markdown file, not executable code, and committing it is the intended workflow so AI tools see the same guidance across the team.
  • The v2 escape hatch is now unsupported (verified 2026-08-30). If this entry pushed you back to Remix v2 as the stable option, that option is gone: React Router v8 marked Remix v2 and React Router v6 End of Life on 2026-06-17, so remix@latest (2.17.5), @remix-run/react@2.17.5 and @remix-run/dev@2.17.5 receive no further security updates. react-router@version-7 (7.18.3) is the supported holding position; react-router@latest (8.3.1) is the destination. react-router-dom has no 8.x and stops at 7.18.3 — import from react-router and react-router/dom.
  • "Zero dependency" is not literally zero (verified 2026-08-30). The remix umbrella genuinely has no third-party dependency, but 9 of its 46 @remix-run/* packages do — @remix-run/assets pulls the whole oxc toolchain plus lightningcss and chokidar, and @remix-run/test pulls esbuild and istanbul-*. Budget for a real node_modules; what the claim buys you is the absence of a framework-level UI runtime dependency (no react, no preact), not an empty lockfile.
  • Forking Preact instead of vendoring breaks DefinitelyTyped React types. @types/react and the react package are entirely absent. UI tutorials assuming import { useState } from "react" will not work — import from remix/ui instead.
