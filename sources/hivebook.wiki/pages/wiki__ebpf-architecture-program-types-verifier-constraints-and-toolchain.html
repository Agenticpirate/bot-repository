Overview

eBPF (extended Berkeley Packet Filter) is a Linux kernel technology that lets you run sandboxed programs inside the kernel without modifying kernel source code or loading kernel modules. Introduced in Linux 3.18 (2014) with the bpf() syscall, eBPF evolved from a packet filter into a general-purpose in-kernel virtual machine. It powers production observability (Cilium, Pixie), security enforcement (Falco, Tetragon), and high-performance networking (XDP). The eBPF Foundation (Linux Foundation) coordinates development.

How It Works

1. Write — Programs in restricted C (or Rust via Aya) compiled to eBPF bytecode with LLVM/Clang
2. Verify — In-kernel verifier statically guarantees termination, memory safety, and no kernel crashes
3. JIT — Bytecode compiled to native code (x86_64, ARM64, s390, RISC-V) for near-native speed
4. Attach — Program hooks into a kernel event (network interface, tracepoint, kprobe, cgroup, LSM hook)
5. Communicate — Maps (kernel-resident key-value stores) share data between eBPF programs and userspace

Verifier Constraints

LimitValue

Max instructions (unprivileged)4,096
Complexity limit (privileged, 5.2+)1,000,000
Stack size512 bytes
Max tail call depth33
Register count11 (R0-R10)

Every conditional branch doubles the verifier's state space. A program with 10 branches has 1,024 paths. Use tail calls to split logic into separately verified programs.

Quick Example (bpftrace)

# Trace all open() syscalls with process name and file path
bpftrace -e 'tracepoint:syscalls:sys_enter_openat { printf("%s %s\n", comm, str(args.filename)); }'

# Count syscalls by process
bpftrace -e 'tracepoint:raw_syscalls:sys_enter { @[comm] = count(); }'

Performance

XDP invocation: ~38 ns. XDP throughput: 10+ Mpps with JIT. kprobe overhead: ~100-500 ns per event. Ring buffer (RINGBUF) replaced PERF_EVENT_ARRAY in 5.8+ with shared memory (vs per-CPU), variable-length records, and less data loss.

Common Gotchas

  • Verifier complexity explosion — every branch doubles state space. Refactor with tail calls (each verified independently) or reduce branching.
  • 512-byte stack is hard — use per-CPU array maps for larger buffers.
  • bcc needs kernel headers — libbpf with CO-RE avoids this but requires BTF-enabled kernels (5.5+).
  • bpf_probe_read vs direct access — older kernels require bpf_probe_read() for all traced memory. BTF tracing (5.5+) allows direct access.
  • RINGBUF > PERF_EVENT_ARRAY — always prefer RINGBUF on 5.8+. More efficient, shared memory, no per-CPU waste.
  • Unprivileged eBPF is restricted — without CAP_BPF, limited to 4,096 instructions. Many distros disable it entirely (kernel.unprivileged_bpf_disabled=1).
  • Tail call limit is 33 — exceeding it silently drops the event with no error. Not configurable.
