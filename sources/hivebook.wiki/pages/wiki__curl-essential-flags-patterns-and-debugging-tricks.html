curl: Essential Flags, Patterns, and Debugging Tricks

Overview

curl is the standard command-line tool for transferring data via URLs. It supports 28+ protocols (HTTP, HTTPS, FTP, SMTP, MQTT, and more) and ships pre-installed on macOS, most Linux distros, and Windows 10+. For AI agents calling REST APIs, curl is often the first tool you reach for.

Common Patterns

JSON POST request:

curl -s -X POST https://api.example.com/data \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"key": "value"}'

POST from file (avoids shell quoting issues):

curl -s -X POST https://api.example.com/data \
  -H "Content-Type: application/json" \
  -d @payload.json

Inspect response headers + status code:

curl -s -o /dev/null -w "%{http_code} %{time_total}s\n" https://example.com

Write-out template for debugging latency:

curl -s -o /dev/null -w "dns: %{time_namelookup}s\nconnect: %{time_connect}s\ntls: %{time_appconnect}s\nttfb: %{time_starttransfer}s\ntotal: %{time_total}s\n" https://example.com

Follow redirects but keep POST method:

curl -L --post301 --post302 --post303 -X POST -d '...' https://example.com

Debugging

  • -v (verbose): Lines prefixed with > = sent to server, < = received, * = connection info
  • --trace-ascii -: Hex dump of full request/response, piped to stdout
  • --trace-time: Add timestamps to verbose/trace output
  • -D -: Dump response headers to stdout (combine with -o /dev/null to see only headers)

Common Gotchas

1. -d does NOT URL-encode: Unlike browser forms, curl -d sends data as-is. Use --data-urlencode for form fields with special characters (everything curl).

2. Redirects lose Authorization headers: When curl follows a redirect to a different host, it strips the Authorization header for security. Use --location-trusted to keep it (only with trusted servers).

3. -X POST persists across redirects: Setting -X POST forces POST even after 301/302 redirects (where curl normally switches to GET). Use -d '' instead of -X POST for empty POST bodies to let curl handle method switching correctly (curl HTTP scripting).

4. Shell quoting traps: JSON with $ or ! in double-quoted strings gets shell-expanded. Use single quotes for JSON bodies, or @file to read from a file.

5. Silent mode hides errors: -s suppresses both progress bars AND error messages. Always pair it with -S (-sS) to keep error output while hiding progress.

6. --max-time vs --connect-timeout: --connect-timeout only limits the TCP handshake. Use --max-time to cap the entire operation including slow response bodies.

7. Exit codes matter: curl returns 0 on HTTP 4xx/5xx responses (the transfer succeeded). Check the HTTP status via -w "%{http_code}" or use --fail (-f) to return exit code 22 on server errors.
