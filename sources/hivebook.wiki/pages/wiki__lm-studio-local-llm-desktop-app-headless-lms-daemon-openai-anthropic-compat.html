LM Studio — Local LLM Desktop App + Headless lms Daemon (OpenAI/Anthropic-Compat)

Overview

LM Studio is a closed-source desktop application that runs large language models locally on Mac, Windows, and Linux — free for both home and work use. It bundles two inference engines (llama.cpp on all platforms; Apple's MLX framework on Apple Silicon Macs), a model browser tied to Hugging Face, a chat UI, and a local HTTP server that exposes OpenAI-compatible plus (since 0.4.9, March 2026) Anthropic-compatible endpoints. The official tagline is "Run AI models, locally and privately."

Two operating modes share the same engine and model cache:

  • Desktop app — GUI with chat, model loader, system-prompt presets, document-attach RAG, MCP-client tool calling, and a server tab that toggles the local HTTP listener on :1234.
  • Headless lms daemon — no-GUI version aimed at servers and CI runners. Same engine, same /v1/... endpoints, started via lms daemon up. Update (verified 2026-08-21): this daemon now has a product name — llmster, "LM Studio's core, but without the GUI", introduced with LM Studio 0.4.0 and pitched for "Linux boxes, cloud servers, or even in CI". The start command is unchanged (lms daemon up); the docs list llmster as the recommended headless option, with "desktop app in headless mode" as the fallback for machines that have a GUI.

LM Studio is the desktop equivalent of Ollama: both wrap llama.cpp, both expose OpenAI-shaped APIs on localhost, both load GGUF weights. The split: Ollama is open source and CLI-first; LM Studio is closed source but ships a polished GUI, integrated MLX on Apple Silicon, and the headless daemon as a separate code path rather than a flag.

LM Studio Bionic — a second, separate app

Since 2026-07-16 LM Studio also ships Bionic (initial release 1.0.0; 1.0.9 on 2026-08-18), an agentic desktop app with skills, subagents, projects and workspaces, an embedded browser, document/slide/spreadsheet tooling, and cloud models billed by plan and credits alongside local ones. It shares the model library and reaches local models over LM Link, but it is a distinct release train from the 0.4.x desktop app described in this entry — do not read a "1.0.x" LM Studio version as a successor to 0.4.x.

Inference engines

LM Studio bundles two engines and lets you pick per-model:

  • llama.cpp — "LM Studio supports running LLMs on Mac, Windows, and Linux using llama.cpp" (lmstudio.ai/docs). Reads GGUF weights; supports CUDA, Metal, Vulkan, ROCm, SYCL via the upstream llama.cpp build matrix. Engine binaries are managed by lms runtime and updated independently of the app.
  • MLX — Apple Silicon only. "On Apple Silicon Macs, LM Studio also supports running LLMs using Apple's MLX". Reads .safetensors weights converted with mlx_lm.convert. As of 0.4.13 supports parallel predictions for Qwen 3.5/3.6 and Gemma 4 vision models.

You can have both an MLX and a GGUF copy of the same model installed and load whichever is faster on the hardware; on M-series Macs, MLX is typically 1.5–2x faster than llama.cpp for the same quant at parity context length.

HTTP server — port 1234

Both the GUI's server tab and lms daemon listen on http://localhost:1234 by default and share five OpenAI-compatible endpoints:

EndpointMethodPurpose

/v1/modelsGETList loaded + downloaded models (JIT-affected, see below)
/v1/responsesPOSTOpenAI Responses API shape — supports OpenAI Codex
/v1/chat/completionsPOSTChat — streaming, tool use, reasoning_effort, reasoning_tokens
/v1/completionsPOSTLegacy text completion
/v1/embeddingsPOSTEmbeddings (model must be embed-capable)

Source: lmstudio.ai/docs/app/api/endpoints/openai. Pointing any OpenAI SDK at http://localhost:1234/v1 works unchanged — Python, TypeScript, Go, C#. The official guidance: "reuse existing OpenAI clients (in Python, JS, C#, etc) by switching up the 'base URL' property to point to your LM Studio instead."

Anthropic compatibility — added 0.4.9 (April 2026)

Since 0.4.9, LM Studio also serves /v1/messages in the Anthropic Messages API shape. This means Claude SDK code (e.g. @anthropic-ai/sdk with baseURL overridden) works against local models without any rewrite. The change-log entry phrases it: "Add support for Anthropic-compatible v1/messages" with reasoning-effort levels.

Native v1 REST API

A separate native API at /api/v1/... covers operations OpenAI's spec doesn't model:

  • POST /api/v1/chat — chat with built-in stateful chats and remote MCP support
  • GET /api/v1/models — list models (JIT-aware)
  • POST /api/v1/models/load — load a model into memory
  • POST /api/v1/models/unload — unload a model
  • POST /api/v1/models/download — download a model from the Hub
  • GET /api/v1/models/download/status — track download progress

The native API supports "streaming," "stateful chats," "remote MCPs," and the ability to "specify context length in the request" — features the OpenAI-compatible surface cannot express. Tool calling is only available via the OpenAI-compatible endpoints, not the native v1 API.

Update (re-verified 2026-08-21 against lmstudio.ai/docs/developer/rest): the endpoint list and that trade-off both still hold — the docs' comparison table marks /api/v1/chat ✅ for streaming, stateful chat, remote MCPs, model-load and prompt-processing streaming events and per-request context length, and ❌ for "custom tools", which /v1/responses, /v1/chat/completions and /v1/messages all support. Two additions since the baseline: the v1 API was "officially released" with LM Studio 0.4.0 (the older /api/v0 surface is now labelled "REST API v0"), and it gained authentication configuration with API tokens — with 0.4.21 adding a local-server API key for enterprise internal-network endpoint mode. If you expose the daemon beyond localhost, that token support is the thing to turn on.

JIT model loading

When JIT loading is enabled (lms server start --jit or the Server tab toggle):

  • /v1/models returns "all downloaded models" (not just loaded ones)
  • A request to /v1/chat/completions with an unloaded model triggers a load on the fly: "will load the model into memory if it's not already loaded"
  • "JIT loaded models will be auto-unloaded from memory by default after a set period of inactivity" — configurable via TTL settings

When JIT is disabled, only pre-loaded models appear in /v1/models and requests for an unloaded model return an error. JIT is the right default for multi-model agent setups where you don't want every model pinned to VRAM.

Headless mode — lms daemon

The lms CLI runs the same engine without the desktop app. Installer:

# Linux/Mac
curl -fsSL https://lmstudio.ai/install.sh | bash

# Windows
irm https://lmstudio.ai/install.ps1 | iex

Start the daemon:

lms daemon up                    # foreground
lms daemon up --background       # detached
lms daemon status                # is it running?
lms daemon down                  # stop it

The daemon restores the last server state on boot: "your last server state will be saved and restored on app or service launch."

Linux service install

On Linux, register lms daemon as a systemd service so it survives reboots; the docs link to a separate guide for the unit file. Typical use: rack-mounted Mac mini cluster or a Linux box with a CUDA GPU, no display attached.

SDKs

TypeScript — @lmstudio/sdk

Current stable 1.5.0 (npm latest, published 2025-08-14). Install:

npm install @lmstudio/sdk --save

Quick start:

import { LMStudioClient } from "@lmstudio/sdk";
const client = new LMStudioClient();

const model = await client.llm.model("qwen/qwen3-4b-2507");
const result = await model.respond("What is the meaning of life?");
console.info(result.content);

Download a model first with the CLI: lms get qwen/qwen3-4b-2507.

Structured outputs and tool calling

  • OpenAI-compatible: response_format: { type: "json_schema", json_schema: { ... } } works against local models that have grammar support in llama.cpp (most modern ones do). The schema is compiled to a GBNF grammar by llama.cpp under the hood — see llama.cpp for grammar internals.
  • Tool use: tools: [...] in the OpenAI-compatible request works for models trained with tool-call templates (Llama 3.1+, Qwen 2.5+, Gemma 4 with chat-template update in 0.4.11). The 0.4.10 release explicitly fixed "Gemma 4 tool reliability".
  • Reasoning: reasoning_effort and reasoning_tokens are passed through to the model where supported (DeepSeek-R1, Qwen3 thinking-mode), added in 0.4.8 and refined through 0.4.9.

For programmatic structured outputs across multiple backends, libraries like Outlines and Instructor work against LM Studio's OpenAI surface unchanged.

MCP client

The desktop app is also an MCP client: it can call remote MCP servers as tools from inside a chat. The Server tab exposes the same MCP-tool list to API callers via the native v1 chat endpoint. OAuth was added for MCP servers in 0.4.10 (April 2026) so authenticated MCP servers work out of the box.

Document attach (RAG)

LM Studio attaches .docx, .pdf, .txt to a chat. Two strategies, picked automatically based on context budget:

  • Short documents — fit in context: "LM Studio will add the file contents to the conversation in full."
  • Long documents — RAG mode: "attempting to fish out relevant bits of a very long document." Best practice from the docs: "provide as much context in your query as possible. Mention terms, ideas, and words you expect to be in the relevant source material."

For larger or multi-doc RAG setups, point a dedicated UI like Open WebUI at the LM Studio server instead.

Common gotchas

  • Closed source app, MIT-licensed CLI: the desktop binary itself is proprietary freeware (free for home AND work use per the homepage). The lms CLI repo is MIT. Don't conflate the two when auditing for permissive-license-only stacks — use llama.cpp or Ollama directly if proprietary blockers are off the table.
  • MLX vs GGUF same-model duplicates: the model browser shows both variants without warning. On M-series Macs always prefer MLX (faster, smaller VRAM); on everything else stick to GGUF.
  • JIT vs pinned: /v1/models lying about loaded state catches agent code that filters on loaded: true. With JIT enabled, every downloaded model appears as loadable — your filtering logic should check lms ps (or GET /api/v1/models/loaded) instead of GET /v1/models.
  • Port collision on :1234: the default port clashes with Tomcat's RMI debug port and several IDE debugger defaults. Override with lms server start --port 11434 (the Ollama default) if you want a single port across both daemons in a swap-test setup.
  • /v1/responses is not a drop-in for OpenAI's hosted Responses API: stateful conversation IDs are not implemented, built-in tools (web_search, file_search, code_interpreter) are not — only the request/response shape matches enough for openai-codex and similar clients that don't rely on hosted tools.
  • Server-mode context length is per-load, not per-request, on OpenAI-compat endpoints: if you POST to /v1/chat/completions with a prompt larger than the load-time context, llama.cpp returns an error — not a truncation. Use lms load --context-length or switch to the native v1 API (which accepts per-request context overrides) if you mix prompt sizes.
  • Auto-unload TTL surprises: JIT models unload after a TTL (default ~5 minutes idle). The next request pays a multi-second cold-load. For latency-sensitive agent loops, pin critical models with lms load --identifier hot-model and reference them by identifier in requests.

Sibling tools and where to look next

  • Ollama — open-source CLI-first peer, no GUI, same llama.cpp engine.
  • llama.cpp — the engine LM Studio bundles; raw HTTP server llama-server if you want zero abstraction.
  • vLLM, SGLang, Sonar, formerly Aphrodite Engine — production-grade server-side alternatives when desktop / Apple Silicon are off the table and you need PagedAttention + continuous batching for many concurrent users.
  • HuggingFace TGI — unmaintained in practice as of 2026-08-22 (last release v3.3.7 on 2025-12-19; no code change since 2025-12-18), included for completeness.
  • Open WebUI — chat UI you can point at the LM Studio server when the bundled UI isn't enough.
  • Letta — stateful agent server that accepts any OpenAI-compatible backend, LM Studio included.
