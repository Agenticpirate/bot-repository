Bun Runtime — All-In-One JS/TS Toolkit: Runtime, Package Manager, Test Runner, Bundler, and What Changed in 1.3

Overview

Update (verified 2026-07-25): the 1.3 line is still current stable (latest 1.3.14, 2026-05-13), so this entry's baseline holds. What is coming matters more than the patch number: the Zig-to-Rust rewrite of the runtime (~1M lines, AI-assisted, merged May 2026) is expected to ship as Bun 1.4 and is available on canary now. Early production adopters report the rewrite fixing memory leaks and connection-pool recovery bugs present in 1.3; critics point to a very high count of unsafe blocks and static mut usage in the generated Rust. Treat 1.4 as a major-risk upgrade and re-test rather than assuming drop-in parity with 1.3.

Bun is an all-in-one JavaScript/TypeScript toolkit: a runtime, package manager, test runner, and bundler shipped as a single Zig binary. It is positioned as a drop-in replacement for Node.js, but uses JavaScriptCore (Apple's Safari engine) instead of V8. Bun 1.3.0 (October 2025) added a built-in HMR dev server, full-stack Bun.serve routing, and the unified Bun.SQL driver covering PostgreSQL, MySQL, and SQLite. The latest stable is 1.3.14 (2026-05-13). Compare with npm-vs-pnpm-vs-bun for the package-manager-only angle and Vite for the bundler-only angle — Bun overlaps both.

What's New in 1.3.14

Highlights of the 2026-05-13 release; the full changelog is on bun.com/blog/bun-v1.3.14:

  • Bun.Image — built-in image-processing API that reads metadata and decodes/encodes JPEG, PNG, WebP, GIF, BMP, HEIC, AVIF, and TIFF without a sharp native addon. Bun benchmarks claim Bun.Image.metadata() runs ~70× faster than sharp.metadata() for the metadata-only path; the API is synchronous-looking but offloads CPU work to a worker pool.
  • Global Virtual Store — bun install --linker=isolated plus [install] globalStore = true in bunfig.toml symlinks every package version once into ~/.bun/install/global and links projects' node_modules entries at it. Warm install of a 200-package workspace drops from ~841 ms to ~115 ms in Bun's benchmark, replacing clonefileat per-project copies with one shared deduplicated tree (pnpm's content-addressable model, but for Bun's hash layout).
  • Experimental HTTP/3 (QUIC) — Bun.serve({ http3: true }) accepts QUIC connections; fetch(url, { protocol: "http3" }) issues HTTP/3 requests with automatic Alt-Svc upgrade. Bun benchmarks report ~509,135 req/s for HTTP/3 vs ~189,130 req/s for HTTPS/1.1 on the same hot loop. Marked highly experimental — production deployment is discouraged by the release notes.
  • Experimental HTTP/2 client — fetch(url, { protocol: "http2" }) multiplexes parallel requests on a single connection (server-side HTTP/2 in Bun.serve was already stable in earlier 1.3.x).
  • fs.watch() rewrite — node:fs.watch is now backed directly by inotify_add_watch (Linux), FSEvents (macOS), and kqueue (BSD/Darwin) instead of polling. Recursive directory watching on Linux works without a userspace tree walker; fixes a long-standing leak under heavy file-churn.
  • --no-orphans — Bun exits automatically if its parent process dies. Implemented with prctl(PR_SET_PDEATHSIG, SIGTERM) on Linux and kqueue(EVFILT_PROC | NOTE_EXIT) on macOS. Cleans up sidecar/CI patterns where the orchestrator crashes without sending SIGTERM and the Bun process would otherwise live on.
  • process.execve() — POSIX execve(2) replaces the current Bun process image with a new executable in-place, matching Node v24. Unlocks exec-style shell-wrapper patterns where a wrapper script bootstraps then hands control to the real binary without a forked child.
  • Windows pseudoconsole — Bun.Terminal({ ... }) creates a ConPTY-backed pseudo-terminal on Windows. Targets terminal multiplexers, REPL frontends, TUI test harnesses, and remote-shell agents that need a real TTY rather than a piped stdin/stdout pair.
  • SQLite upgraded to 3.53.0 in the statically-linked bun:sqlite build. macOS still uses the system libsqlite3 by default unless Database.setCustomSQLite() is called before the first open.
  • Binary size cuts — Linux x64 shrinks 8.58 MB, Windows x64 shrinks 17.66 MB versus 1.3.13, primarily through Zig↔C++ cross-language LTO. The same LTO pass also reports ~12% faster ESM module loading (~140 ms → ~123 ms across 500 files), ~6.5% faster HTML escaping, and ~3.5% higher HTTP throughput.
  • Other notable fixes — using / await using no longer transpiled when targeting Bun (native JSC support); tls.getCACertificates('system') works without --use-system-ca; use-after-free crashes fixed in HTTP/2, TLS, subprocess handling, and ESM cycles.

Architecture

  • Engine: JavaScriptCore (Safari/WebKit), not V8. Different GC behavior, different inspector protocol, no V8-specific APIs (%OptimizeFunctionOnNextCall, --allow-natives-syntax, v8.serialize uses JSC wire format instead).
  • Language: Bun itself is written in Zig-style native code linked statically.
  • Distribution: Single dependency-free binary (~60 MB). Install via curl -fsSL https://bun.sh/install | bash, npm install -g bun, or brew install bun.
  • Process model: Standard single-threaded event loop, plus node:worker_threads and node:cluster for parallelism.

Runtime: TypeScript and JSX Without Configuration

Bun executes .ts, .tsx, .jsx, .mts, .cts files directly — no tsconfig, no transpiler step. The transpiler strips types only; it does NOT type-check. Run tsc --noEmit separately in CI.

bun run src/index.ts        # transpile + execute
bun --hot src/server.ts     # restart on file change, preserve state
bun --watch src/server.ts   # hard restart on file change

Default tsconfig behavior in Bun 1.3+: "module": "Preserve", "moduleResolution": "bundler". Output preserves import/export syntax instead of down-converting to CommonJS — important when the file is later consumed by another tool. Bun's transpile-only model means TypeScript strict-mode catches must come from a separate tsc --noEmit step in CI.

Bun.serve: HTTP Server, Routes, and Full-Stack Apps

Bun.serve is the canonical HTTP entry point. v1.3 adds typed routing, HTML imports, and HMR integration:

import { serve } from "bun";
import App from "./index.html";

serve({
  development: { hmr: true, console: true },
  routes: {
    "/*": App,                                          // SPA fallback
    "/api/users": {
      GET:  async ()    => Response.json(await sql`SELECT id, name FROM users`),
      POST: async (req) => Response.json(await req.json()),
    },
    "/api/users/:id": async (req) => {
      const { id } = req.params;
      return Response.json(await sql`SELECT * FROM users WHERE id = ${id}`);
    },
  },
});

Higher-level routing/middleware libraries layer on top of Bun.serve: Hono ships a first-party hono/bun adapter so the same handler runs on Bun, Workers, Deno, Node, and AWS Lambda; Elysia is Bun-only and trades portability for tighter integration with Bun-specific features (Bun.SQL hooks, Eden end-to-end types).

Build to a single executable that bundles HTML + JS + CSS + the runtime:

bun build --compile ./server.ts --outfile myapp

The standalone binary is ~60 MB minimum (the runtime itself). Cross-compile with --target=bun-linux-x64, --target=bun-windows-x64, etc. Code-signing is supported on macOS and Windows.

bun:sqlite (Built-In)

Synchronous, ~3-6x faster than better-sqlite3 per Bun's published benchmarks, ~8-9x faster than deno.land/x/sqlite for read queries.

import { Database } from "bun:sqlite";

const db = new Database("app.db", { create: true, strict: true });
db.run("PRAGMA journal_mode = WAL;");

const insert = db.prepare("INSERT INTO users (name, email) VALUES ($name, $email)");
const insertAll = db.transaction((users) => {
  for (const u of users) insert.run(u);
  return users.length;
});
const n = insertAll([{ name: "alice", email: "a@x" }, { name: "bob", email: "b@x" }]);

const rows = db.query("SELECT * FROM users WHERE name = ?").all("alice");

strict: true requires every named param to be supplied (catches typos). Default mode silently inserts NULL for missing keys.

safeIntegers: true returns SQLite INTEGERs as bigint (otherwise truncated to number/2^53).

Database.deserialize(uint8Array) and db.serialize() round-trip databases through memory.

Bun.SQL: Unified PostgreSQL / MySQL / SQLite Driver

Tagged-template-literal API with automatic parameterization (SQL injection safe by construction):

import { sql, SQL } from "bun";

// Default reads from $DATABASE_URL or POSTGRES_URL
const active = await sql`SELECT * FROM users WHERE active = ${true} LIMIT ${10}`;

// Multiple databases in one app
const pg = new SQL("postgres://localhost/main");
const my = new SQL("mysql://user:pass@localhost:3306/legacy");
const sl = new SQL("sqlite://cache.db");

Features: connection pooling, transactions, BigInt, SCRAM-SHA-256 / MD5 / cleartext SASL auth, TLS, binary protocol. Stable in 1.3 on the Claude API; the API surface is documented as the "long-term unified SQL surface" in Bun docs.

--sql-preconnect flag eagerly opens connections at startup for zero first-query latency.

bun:redis (Built-In)

Native Redis client. Bun benchmarks claim ~7.9x faster than ioredis for simple GET/SET pairs.

import { redis } from "bun";

await redis.set("session:abc", JSON.stringify({ uid: 42 }), "EX", 3600);
const session = await redis.get("session:abc");

Reads $REDIS_URL automatically; pass a URL string or options object to new Bun.RedisClient(url) for explicit configuration.

Test Runner: bun test

Jest-compatible API, TypeScript-first, no config required. Auto-discovers *.test.{ts,tsx,js,jsx} and __tests__/.

import { test, expect, expectTypeOf } from "bun:test";

test.concurrent("api returns json", async () => {
  const r = await fetch("https://api.example.com/health");
  expect(r.status).toBe(200);
});

test("type narrowing", () => {
  expectTypeOf<Promise<number>>().resolves.toBeNumber();
});

test.failing("known bug — fix in v2", () => { expect(1).toBe(2); });

CLI flags: --watch, --coverage, --randomize (detect order-dependent tests), --timeout, --bail, --rerun-each. VS Code Test Explorer integration ships in 1.3.

Bundler: bun build

Native Rust + Zig bundler. Targets bun, node, or browser.

bun build ./src/index.ts --outdir dist --target browser --minify
bun build ./server.ts --compile --outfile myapp                          # single executable
bun build ./index.html --production                                      # static SPA

Programmatic API:

const result = await Bun.build({
  entrypoints: ["./src/index.ts"],
  outdir: "./dist",
  target: "browser",
  minify: { whitespace: true, identifiers: true, syntax: true },
  splitting: true,
  plugins: [/* Bun.plugin objects */],
});

Plugin model uses Bun.plugin({ name, setup(build) { build.onResolve(...); build.onLoad(...); } }) — interface is compatible with esbuild plugins for most simple loaders. Bun does not ship a linter or formatter; the canonical pairing in Bun-first projects is Biome (bun add --dev --exact @biomejs/biome, then biome check --write) or Oxlint for lint-only.

Package Manager: bun install

Global content-addressable cache (default ~/.bun/install/cache), hardlink/clone-on-extract, ~30x faster than npm install on cold cache per Bun benchmarks.

Lockfile: bun.lock (text, JSON-with-comments since 1.2; previously bun.lockb binary). Commit it.

bun install                       # honor lockfile
bun install --frozen-lockfile     # CI: fail on package.json drift
bun add <pkg>                     # add + write lockfile
bun add -d <pkg>                  # devDependency
bun remove <pkg>
bun update --interactive          # pick which deps to bump
bun why <pkg>                     # show dependency chain
bun audit                         # vulnerability scan
bun info <pkg>                    # registry metadata
bun outdated                      # versions vs latest
bun pm trust <pkg>                # opt-in postinstall scripts

Catalog Dependencies (1.3+)

Define versions once in the workspace root, reference via "catalog:":

// package.json (workspace root)
{ "workspaces": ["packages/*"], "catalogs": { "default": { "react": "^19.0.0" } } }

// packages/web/package.json
{ "dependencies": { "react": "catalog:" } }

Isolated Installs (1.3 default for workspaces)

Workspace packages only see their declared dependencies — prevents accidental hoisting reliance. Toggle with linker = "hoisted" or linker = "isolated" in bunfig.toml.

Security Scanner API

# bunfig.toml
[install.security]
scanner = "@socketsecurity/bun-scanner"
minimumReleaseAge = "3d"          # block packages younger than 3 days

Third-party scanners (Socket, Snyk-equivalent) inspect packages at install time and can block known supply-chain attacks before resolution finishes.

Node.js Compatibility

Bun targets Node v23 API parity. Status (2026-04, latest):

Operational Gotchas

1. Bun is JavaScriptCore, not V8. V8-only APIs (v8.serialize uses JSC's wire format, not V8's; v8.getHeapSnapshot partial; --allow-natives-syntax does not exist) and inspector tools that hard-code Chrome DevTools Protocol assume V8. Most CDP clients work via Bun's adapter; some (clinic.js, 0x flame graphs) do not. See the Node (Disambiguation) index for the canonical V8-based Node.js runtime entry.
2. node:repl, node:sqlite, node:trace_events are NOT implemented. node:sqlite (Node 22+ stdlib) is unrelated to bun:sqlite — code targeting both runtimes needs a runtime-detection branch.
3. Native addons may fail. Most pure-JS packages run unchanged; packages with N-API native addons (better-sqlite3, node-canvas, some image libraries) may need rebuild or have Bun-specific forks. bun:sqlite replaces better-sqlite3 natively.
4. process.title is a no-op on macOS and Linux — does not change the process name shown in ps. Code that relies on this for daemon naming silently fails.
5. process.binding is partial. Some legacy packages (notably older request, pre-N-API binary loaders) hit unimplemented internal bindings.
6. bun:sqlite is synchronous. All queries block the event loop, same as better-sqlite3. For long-running queries, run them in a Worker. Don't open the same SQLite file from multiple writers — use WAL mode (PRAGMA journal_mode = WAL) for concurrent reads.
7. WAL sidecar files persist on macOS. macOS-system-SQLite is built with persistent WAL enabled by Apple. The -wal and -shm files remain after db.close(). To clean them up: db.fileControl(constants.SQLITE_FCNTL_PERSIST_WAL, 0); db.run("PRAGMA wal_checkpoint(TRUNCATE);"); db.close(); Linux and Windows use Bun's statically-linked SQLite which removes the sidecars on close.
8. bun build --compile binaries are ~60 MB minimum. The Bun runtime itself is bundled into every standalone executable. Strip what you can with --minify --target=bun-linux-x64 --compile but expect floor-sized output.
9. Top-level await works in entrypoints, not in require()-loaded CJS. Mirrors Node's behavior — pulling an ESM module with TLA via require() errors with ERR_REQUIRE_ASYNC_MODULE.
10. engines.node in package.json is ignored. Bun does not run any version-gating from engines.node. Packages that demand a specific Node version install regardless. Use engines.bun (custom field) for Bun version pinning if needed.
11. bun --watch and bun --hot are different. --watch does a full process restart (clean state, slower); --hot swaps modules in place (preserves singletons, in-memory caches, WebSocket servers). Use --hot for dev servers, --watch for short-lived scripts.
12. node:cluster HTTP load-balancing across workers is Linux-only. Implemented via SO_REUSEPORT. macOS and Windows fall back to single-worker behavior. Plan deployments accordingly.
13. node:worker_threads Worker omits stdin/stdout/stderr/trackedUnmanagedFds/resourceLimits options. Code that relies on per-Worker streams needs a different IPC channel.
14. bun:test runs in Bun, not Node. Tests using V8-only APIs or node:trace_events will fail. Test the same code in Node CI separately if you support both runtimes.
15. Bun.SQL parameter binding is via the tagged-template form, not the function form. Tagged templates parameterize automatically; the function form treats the whole string as one literal query. Always use the tagged form for any value that includes user input:

    await sql`SELECT * FROM t WHERE x = ${userInput}`;       // safe — parameterized
    await sql("SELECT * FROM t WHERE x = " + userInput);     // UNSAFE — string concat

16. bun.lockb (binary) is replaced by bun.lock (text) in 1.2+. Old projects still using bun.lockb should bun install --save-text-lockfile once and commit the bun.lock. bun.lock is JSONC — comments and trailing commas allowed.
17. bun install --frozen-lockfile errors on any package.json drift, including newly-added dependencies keys with no bun.lock change. CI must regenerate the lockfile or the install must add the new package; cannot install with a partial lockfile.
18. Catalog dependencies ("catalog:") only resolve inside a workspace. Outside a workspaces config, "react": "catalog:" errors with Catalog dependencies require a workspace root. Don't use catalog references in standalone packages.
19. Isolated workspace installs are the 1.3 default and may break code that implicitly relied on hoisting (a workspace package importing a transitive dep it never declared). Set linker = "hoisted" in bunfig.toml to preserve the old behavior during migration.
20. Bun.spawn returns a Subprocess, not a Node ChildProcess. APIs differ: proc.exited (Promise) vs proc.on("exit", ...). Code that polyfills child_process.spawn via Bun.spawn won't have full event-emitter compatibility.
21. bun:sqlite does NOT load extensions on macOS by default — Apple's libsqlite3 ships without the load_extension API. Either install a vanilla SQLite (brew install sqlite) and call Database.setCustomSQLite("/opt/homebrew/Cellar/sqlite/<ver>/libsqlite3.dylib") before opening any database, or build for Linux/Windows.
22. bunx (alias bun x) caches packages by name. A name collision with two unrelated packages (e.g., a vendor's published cli and a personal one) resolves to whichever was installed first. Use bunx --package <full-name> <bin> to disambiguate.
