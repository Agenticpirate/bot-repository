Overview

Ghostty is a GPU-accelerated terminal emulator written in Zig with native macOS (SwiftUI/AppKit, Metal) and Linux/FreeBSD (GTK 4 + libadwaita, OpenGL) front-ends, sharing a single core terminal engine and libghostty extraction. 1.3.0 shipped 2026-03-09 ("ghost 2"-cycle release, 6 months / 180 contributors / 2,858 commits since 1.2) and 1.3.1 shipped 2026-03-13 as a fast-follow fix for a macOS phantom-mouse-event regression. The release brings scrollback search (cmd+f / ctrl+shift+f), native scrollbars, click-to-move-cursor inside shell prompts (OSC 133 cl=line), command-finished notifications, chained keybinds + named key tables + catch_all, rich clipboard (text/plain + text/html), Unicode 17 + Brahmic-script shaping, AppleScript preview (macOS only, tell application "Ghostty"), Sparkle "unobtrusive updates", and a massive renderer-lock reduction (2x-5x) plus a major scrollback memory leak fix (existed since 1.0, triggered by Claude Code - explicitly cited in the release notes). The build now requires Zig 0.15 (was 0.14 on 1.2), minimum macOS stays at 13 Ventura for 1.3 but the release notes explicitly state 1.4 raises the floor to macOS 14, and the GTK floor stays at GTK 4.14 + libadwaita 1.5. Windows is still not planned but libghostty is the staging area for an eventual port. Ghostty officially became a non-profit during the 1.3 cycle with five contributor contracts signed (community / graphics / Unicode / GTK / Discord-GitHub integrations, ~300 billable hours).

1.3.0 extracts libghostty as a standalone Zig module sharing almost all of its code with the GUI builds, alongside a work-in-progress C API. The 1.3.0 release notes say the team is not ready to tag a versioned release of either module yet, that dozens of free and commercial projects already use libghostty, and that libghostty and the desktop app now have deliberately separate versioning and release schedules. Library consumers can embed Ghostty's terminal engine without the macOS or GTK chrome - making it the natural foundation for future Windows + custom-UI builds.

v1.3.0 - the big features

Scrollback search

cmd+f       (macOS)      Open scrollback search
ctrl+shift+f (GTK)        Open scrollback search

Highlights all matches in the viewport, navigates between them, draggable search bar. Runs on a dedicated thread so an active search does not block the terminal main loop - "consumes no resources when inactive" per release notes.

Native scrollbars

New scrollbar config option (default: system):

scrollbar = system   # follows OS scrollbar conventions (overlay on macOS)
scrollbar = never    # disable (pre-1.3 behavior)

Overlay styling - scrollbars do not reserve terminal columns. system and never are the only accepted values: the Scrollbar enum in src/config/Config.zig at v1.3.1 has exactly those two enumerants, and there is no always.

Click to move cursor inside shell prompts

Implements the Kitty click-events extension and the OSC 133 cl=line specification verbatim. After clicking inside an active shell prompt, Ghostty synthesizes the right number of left/right arrow keys to reposition the cursor.

Native support shipped in Fish 4.1+ and Nushell 0.111+ (see Nushell 0.112 for the corresponding shell-side semantic-prompt support). zsh/bash require the shell-integration script that Ghostty's auto-injection installs.

Command-finished notifications

notify-on-command-finish = unfocused   # never | unfocused | always
notify-on-command-finish-action = bell,notify
notify-on-command-finish-after = 10s   # default 5s

notify-on-command-finish-action accepts comma-separated tokens negated with a no- prefix (no-bell,notify) - a leading - is not accepted - and defaults to bell on, notify off. notify-on-command-finish itself defaults to never. Drives desktop notifications (FreeDesktop / NSUserNotification) and/or the BEL (0x07) terminal bell.

Key tables, chained keybinds, and catch_all

# Named key table (tmux-style modal mode): bindings are prefixed <table>/
keybind = ctrl+a=activate_key_table_once:tmux

# Bindings that live in the tmux table:
keybind = tmux/c=new_tab
keybind = tmux/n=next_tab
keybind = tmux/catch_all=ignore   # swallow unbound keys

# Chained actions on one key: chain= appends to the keybind above it
keybind = ctrl+shift+t=new_tab
keybind = chain=goto_split:next

Three concepts:
1. Key tables - named sets of bindings written as <table>/<binding> (e.g. foo/ctrl+a=new_window); a table name may contain anything except /, =, + and >, and <name>/ on its own clears the table. Activate and deactivate with the activate_key_table:<name> and deactivate_key_table actions (deactivate_all_key_tables unwinds the whole stack); there is no leave_key_table action. One-shot mode is its own action, activate_key_table_once:<name>, which deactivates after the first non-catch_all binding fires - it is not a ,one_shot flag on activate_key_table. Lookup runs from the innermost table outward, so outer bindings stay live unless explicitly unbound. UI indicator surfaces the active table name on both platforms.
2. Chained keybinds - chain is a continuation line, not an action parameter: bind the key normally, then add one or more keybind = chain=<action> lines, each appending an action to the most recently defined keybind (sequences and table bindings included). There is no chain:a,b form, and chained lines take no global: / unconsumed: prefixes - the original keybind's flags apply to the whole chain.
3. catch_all - special key that matches any key not otherwise bound. It works at the root level as well as inside a table, and combines with modifiers (ctrl+catch_all=...) and with sequences (ctrl+a>catch_all=...); lookup tries catch_all with the event's modifiers first and falls back to bare catch_all.

Fine-grained working-directory inheritance

window-inherit-working-directory = true   # new windows inherit (default)
tab-inherit-working-directory = true      # new tabs inherit
split-inherit-working-directory = true    # new splits inherit

Decouple inheritance per surface kind. Pre-1.3 had a single global toggle.

Rich clipboard copy

The default format of the copy_to_clipboard binding action changed to mixed (was text in 1.2 - breaking change). There is no clipboard-copy-format configuration option - the format lives on the binding action, and the 1.3.0 release notes say that if the new default causes problems "you must rebind copy_to_clipboard with a specific format". On copy, Ghostty now sets BOTH text/plain and text/html clipboard types, so pasting into a rich-text editor (e.g. Slack, Notion, Pages, LibreOffice) preserves colors and formatting; pasting into a plain editor still gets unstyled text.

keybind = cmd+c=copy_to_clipboard:mixed
keybind = cmd+shift+c=copy_to_clipboard:plain
keybind = cmd+alt+c=copy_to_clipboard:html
keybind = cmd+ctrl+c=copy_to_clipboard:vt   # raw VT escape sequences

Unicode 17 + Brahmic script shaping

  • Upgraded to Unicode 17 with full grapheme clustering conformance.
  • Improved Brahmic script rendering: Devanagari, Bengali, Tibetan, Javanese, Tai Tham, Chakma all shape with proper ligatures, combining marks, and joining behavior (see UTF-8 encoding for the underlying byte model).
  • VS15 (text presentation) and VS16 (emoji presentation) handling fixed for emoji-base codepoints.
  • Wide grapheme-cluster rendering fixed for Devanagari clusters that span multiple cells.
  • Keypad variation sequences now respect VS16.

Renderer-lock + I/O performance

The release notes cite two concrete numbers, both from analysis of 4 GB of public asciinema recordings:

  • I/O processing: replay time minutes -> tens of seconds (multiple-orders-of-magnitude improvement on pathological streams).
  • Renderer lock hold time: 2x to 5x reduction (renderer redesign so the terminal lock is released for compute-heavy work).

Stability fixes (must-know)

  • Memory leak triggered by Claude Code - existed since 1.0, fixed. Cause: scrollback pruning on non-standard-sized pages.
  • AFL++ fuzz testing fixed ~10 crashes in the escape sequence parser.
  • Tripwire tool for systematic errdefer cleanup testing - new internal CI guard.
  • Alt-screen memory now allocated on-demand - saves megabytes per terminal that never enters alt-screen.

v1.3.0 macOS-specific

AppleScript - preview feature

tell application "Ghostty"
    set theTerm to focused terminal of selected tab of front window
    input text "ls -la\n" to theTerm
end tell

Controlled by macos-applescript (default: true) and gated at runtime by macOS Automation (TCC) permissions. Marked preview - breaking API changes expected in 1.4. The scripting dictionary (macos/Ghostty.sdef at v1.3.1) defines the classes application, window, tab and terminal - there is no split class - and commands including new window, new tab, split, focus, close, select tab, input text ... to <terminal>, send key, send mouse button / position / scroll and perform action ... on <terminal>. Two traps: focused terminal is a property of tab, not of the application (focused terminal of selected tab of front window), and the input text parameter is to, not into. A terminal exposes only id, name and working directory, so AppleScript cannot read a terminal's contents back out - no text of property exists.

Split drag-and-drop

Grab handle appears at the top of each split; drag to reorder splits within a tab. Preserves terminal contents, working directory, and child processes. Hooks into undo/redo. GTK implementation planned for a future release - macOS only in 1.3.

Unobtrusive updates (Sparkle)

auto-update = check         # off | check | download (unset by default)

When an update is available, a small pill appears in the titlebar or window corner (not a modal). Right-click to dismiss; "Update and Restart" available as a command-palette entry.

Other macOS 1.3 additions

  • background-blur (there is no macos-background-blur option) now supports macOS 26 native liquid-glass blurring as well as the prior NSVisualEffectView blur on older macOS.
  • "Set Ghostty as Default Terminal App" convenience menu item.
  • Double-click a tab title for inline rename (Enter confirms, Escape cancels).
  • command-palette-entry = ... for user-defined command-palette entries.
  • Right-click a tab to assign a color.
  • close_all_windows and toggle_background_opacity binding actions.
  • Native cmd+home / cmd+end jump to scrollback top / bottom.
  • Apple Shortcuts intent to focus a specific terminal by ID.
  • Mouse buttons 8/9 (back/forward) now encoded.
  • Secure Keyboard Input overlay animation - ~35% CPU reduction.

v1.3.0 GTK-specific (Linux / FreeBSD)

  • Two-finger left/right swipe switches tabs.
  • Spatial split navigation wraps at edges.
  • +new-window CLI flag now accepts -e and --working-directory.
  • Cgroups revamped for per-surface scoping (was per-window in 1.2).
  • Split-modifying actions no longer flicker the entire window.

  • paste_from_clipboard returns false for non-text content (e.g. image-only clipboard) instead of pasting garbage.

v1.3.0 breaking changes

Only TWO breaking changes - the release explicitly lists them in a dedicated section:

1. Clipboard copy format default flipped from text (1.2) to mixed (1.3). Pasting into rich-text apps now gets HTML; if a downstream parser breaks on the second clipboard type, rebind the action explicitly (keybind = cmd+c=copy_to_clipboard:plain) - there is no clipboard-copy-format option to set.
2. GTK font hinting defaults to light hinting instead of full hinting. Aligns with typical GTK application behavior. Revert with freetype-load-flags = +hinting,+force-autohint or similar; full per-flag combinations in the config docs.

No breaking changes for keybinding syntax, no config-file format changes, no removed actions. Existing 1.2 configs load on 1.3.0 verbatim. The chain= and <table>/ key-table syntax is purely additive.

v1.3.0 security

CVE-2026-26982 (NVD primary CVSS 3.1 8.8 HIGH, AV:N/AC:L/PR:N/UI:R/S:U/C:H/I:H/A:H; the vendor advisory GHSA-4jxv-xgrp-5m3r carries a lower secondary score of 6.3 Moderate) - control characters in pasted or drag-and-dropped text were not being sanitized, allowing crafted clipboard contents to execute arbitrary shell commands when pasted into an interactive shell. Fixed by replacing unsafe control characters with spaces during paste / drop. Affects 1.0.0 through 1.2.3; upgrade to 1.3.0 or later if you handle untrusted clipboard contents. Confirmation prompt also tightened (unsafe-paste confirmation text field is now read-only - was previously editable, which created its own confused-deputy surface).

Update (verified 2026-08-22): no newer Ghostty advisory has been published - GHSA-4jxv-xgrp-5m3r (2026-03-09) is still the most recent entry in the repository's security advisories, and NVD lists the fix as landing in 1.3.0, so 1.3.1 has no known outstanding CVE.

Common gotchas

1. The default copy format flipped to mixed in 1.3 - if a downstream paste consumer parses the second clipboard type (HTML) instead of the first (plain), you'll see HTML markup instead of plain text. There is no clipboard-copy-format setting to revert; rebind the action, e.g. keybind = cmd+c=copy_to_clipboard:plain (plain / html / vt / mixed are the four accepted parameters).
2. GTK font hinting default flipped to light in 1.3 - if you preferred 1.2's full hinting, set freetype-load-flags = +hinting,+force-autohint. Affects only the GTK build.
3. .ghostty extension is new in 1.3.0 - if you previously named your file ~/.config/ghostty/config.toml or config.conf, neither was being read. Ghostty only reads config or config.ghostty (no .toml, no .conf, no .cfg). The TOML-like syntax misleads; it is NOT TOML.
4. Scrollback search is a dedicated thread - on macOS the search bar still respects "reduce motion" / accessibility prefs; on GTK it inherits libadwaita's animation settings. If you see the search bar "snap" rather than slide, that's accessibility, not a bug.
5. scrollbar = system shows an overlay on macOS but a persistent bar on most GTK themes - the styling is theme-driven. Set scrollbar = never if you want consistent cross-platform behavior, but you lose mouse-driven scrolling indication.
6. OSC 133 cl=line requires the shell to emit the new sub-sequence - Fish 4.1+, Nushell 0.111+ do this natively; zsh/bash need Ghostty's auto-installed shell-integration script. If your prompt is custom (Powerlevel10k transient prompt, Starship), the click-to-move-cursor support depends on whether the prompt-framework forwards OSC 133 - many do not. zsh fix in 1.3.1 addresses dynamic-theme prompt marking specifically.
7. catch_all is not table-only - keybind = catch_all=ignore and keybind = ctrl+catch_all=ignore are valid at the root binding level and swallow anything not otherwise bound, which is a very effective way to make your terminal feel broken. Inside a sequence, an unbound key with a catch_all=ignore binding drops the whole sequence. Ghostty matches catch_all with the pressed modifiers first, then bare catch_all.
8. AppleScript is a preview feature - the release notes explicitly state "expected breaking API changes in 1.4". Pin your automation to a specific Ghostty version range or expect scripts to break on the 1.4 upgrade.
9. Split drag-and-drop is macOS-only in 1.3 - on GTK the grab handle does not appear. GTK implementation deferred to a future release.
10. window-inherit-working-directory ONLY affects new windows opened via new_window keybind or +new-window CLI - it does NOT affect the FIRST window when Ghostty launches. The first window always uses working-directory config (which itself supports ~/ tilde expansion as of 1.3.1).
11. Command-finished notifications fire on ANY terminating command - including cd, ls, etc., if they happen to exceed notify-on-command-finish-after (default 5s). Set notify-on-command-finish-after = 30s or longer to avoid noisy alerts during day-to-day shell use.
12. notify-on-command-finish-action is a flag set negated with no- - bell is on by default and notify off, and the documented way to swap them is notify-on-command-finish-action = no-bell,notify. A leading - (-bell) is not accepted syntax. Setting both simply does both; the bell does not feed back into the desktop notification.
13. Bash bash-preexec dependency removed for Bash 4.4+ - if you previously sourced bash-preexec.sh manually for OTHER tools (Atuin, Starship, etc.), those tools still need bash-preexec and will still work. Ghostty's removal is internal-only.
14. zsh prompt-marking fix in 1.3.1 affects Powerlevel10k transient prompts specifically - if you're on 1.3.0 and see broken OSC 133 with Powerlevel10k, upgrade to 1.3.1 rather than disabling transient prompts.
15. OSC 5522 (Kitty clipboard) and iTerm2 OSC 1337 are PARSED but NOT IMPLEMENTED in 1.3 - terminals that auto-detect "iTerm2 clipboard support" via OSC 1337 will see Ghostty advertise the parser but get no clipboard side-effect. Workaround: use OSC 52 (standard) instead, which Ghostty fully supports.
16. macOS phantom-mouse-event bug in 1.3.0 - drag/selection/scroll events fired after focus loss - if you saw spurious text selection or scrolling when alt-tabbing in/out of Ghostty on 1.3.0, that's it. Fixed in 1.3.1, no workaround for 1.3.0.
17. macOS 13 Ventura is the floor for 1.3 - 1.4 will require macOS 14 Sonoma (release notes state this explicitly). Apple ended security support for macOS 13 in fall 2025. If you're on macOS 13 plan your upgrade path before 1.4 ships in September 2026.
18. GTK prefers-color-scheme CSS media queries need GTK 4.20+, not "4.2" - the feature landed as "support GTK 4.20 media queries in runtime & custom css". Since Ghostty 1.3's own floor is GTK 4.14, the range that actually matters is 4.14-4.18: those builds run fine but will not re-evaluate custom CSS on a system dark-mode toggle. (GTK 4.0/4.1 cannot run Ghostty 1.3 at all.)
19. tip (nightly) tag rebuilds on every push to main - if you git clone --depth 1 --branch tip you get whatever is current; do NOT script-pin to tip for reproducible builds. Use a numbered tag (v1.3.1) instead.
20. Build requires Zig 0.15 specifically - Zig 0.14 fails the build, Zig 0.16 will also fail (Ghostty has not yet migrated to 0.16). Package maintainers should pin Zig 0.15.x in their CI.
21. libghostty has NO versioned release as of 1.3.1 - the release notes say "first versioned release timing TBD". If you're embedding it, vendor the source rather than expecting a stable ABI, and pin to a Ghostty version + commit, not to "libghostty 1.x".
22. auto-update is unset by default, not check - when unset, Ghostty defers to Sparkle's stored user-defaults preference. check checks but does not download; download downloads automatically; off disables. The release channel is a separate option, auto-update-channel (stable / tip, defaulting to the channel of the running build). Auto-update is macOS-only - distribution package managers are the update path on Linux/FreeBSD.
23. window-padding-x / window-padding-y were never coupled - they are separate horizontal and vertical options (each taking one value, or left,right / top,bottom as a pair), and 1.3 changed nothing about them. Padding is only redistributed if you opt in with window-padding-balance, which still defaults to false.
24. Brahmic-script wide-grapheme rendering only fixed in 1.3 - 1.2 rendered Devanagari clusters spanning multiple cells with overlapping glyphs. If you live-tail Hindi/Bengali/Tibetan text, 1.3+ is the floor.
25. CVE-2026-26982 affects 1.0.0 through 1.2.3 inclusive - if you handle untrusted clipboard content (paste-from-web, drag-and-drop from a browser, Lampoon-targeted phishing scenarios), upgrade to 1.3.0+ as a security hardening step.
