MCP Tools vs Agent Skills: When to Use Each

Overview

MCP Tools and Agent Skills (SKILL.md) are often confused because both extend what an agent can do. They operate at different layers of the stack and complement each other.

Conceptual Distinction

DimensionMCP ToolsAgent Skills (SKILL.md)

LayerCapabilities (what the agent can access)Procedures (how the agent should work)
Examplesread_file, run_sql, call_apicode-review, write-prd, triage-bug
Defined byServer author (JSON Schema)Team / individual (Markdown + YAML)
Triggered byModel decides autonomouslyExplicit invocation or keyword trigger
Lives inMCP server process.claude/skills/ directory or ~/.claude/skills/ (Claude Code); tool-specific path for other agents
Side effectsAlways possible (reads/writes real systems)No side effects; purely instructional

MCP Tools: The Capabilities Layer

An MCP tool is a discrete function with a name, description, and JSON Schema input definition. The model reads the description and decides when to call it. Tools are the mechanism by which agents interact with the real world — databases, APIs, file systems, browsers.

// Tool definition (as seen by the model)
{
  "name": "run_sql_query",
  "description": "Execute a read-only SQL query against the analytics database.",
  "inputSchema": {
    "type": "object",
    "properties": {
      "query": { "type": "string", "description": "SQL SELECT statement" }
    },
    "required": ["query"]
  }
}

Agent Skills: The Procedure Layer

A SKILL.md file teaches an agent methodology — the workflow, output format, and definition-of-done for a type of task. It doesn't connect to anything; it shapes how the agent reasons and responds.

---
name: code-review
description: >
  Perform a structured code review. Triggered when asked to review a pull
  request or diff. Covers correctness, security, style, and test coverage.
version: 1.2.0
allowed-tools: [read_file, run_tests, search_codebase]
---

## Review Process

1. Read the diff fully before commenting.
2. Check for: logic errors, SQL injection, missing null checks, hardcoded secrets.
3. Verify test coverage for changed lines.
4. Output a structured report: **Summary → Critical → Major → Minor → Nits**.

Using Both Together

The most effective agent setups pair skills with tools:

  • The skill defines the code-review methodology (what steps to follow)
  • MCP tools give the agent access to the codebase, CI results, and issue tracker

User: "Review PR #142"
  ↓
Skill: code-review (procedure loaded)
  ↓
MCP Tools: read_file (diff) → run_tests (CI) → create_comment (GitHub)

Decision Guide

  • Need to connect to an external system? → MCP Tool
  • Need to teach an agent a repeatable process or output format? → SKILL.md
  • Defining what "done" looks like for a task type? → SKILL.md
  • Accessing live data the model can't know? → MCP Tool
