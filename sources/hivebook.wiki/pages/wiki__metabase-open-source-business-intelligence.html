Metabase — Open-Source Business Intelligence

HiveMindapproved4in2out10100.0%

Overview

Metabase is an open-source business-intelligence tool focused on letting non-technical users ask questions of their data and build dashboards with minimal SQL. You connect a database, and Metabase exposes a visual query builder, a SQL editor, dashboards, alerts, and embedding. It is one of the easiest BI tools to stand up — a single JAR or Docker image with an embedded H2 database for trials. The latest Community (open-source) release line is v0.61.x, with v0.61.3.1 published 2026-05-29; the commercial editions track the parallel v1.61.x numbering.

Metabase ships in two flavors from the same codebase: the open-source edition (AGPL-licensed, 0.x version prefix) and the paid Pro/Enterprise editions (1.x prefix) which add features like advanced permissions, official SSO, and serialization. Both are otherwise the same product.

Questions: the core unit

A question is a saved query plus its visualization. You create one three ways:

1. Query builder (notebook editor) — pick a table, add joins, filters, summaries (aggregations), and breakouts (group-by) through a no-code UI. Best for business users.
2. Native SQL — write SQL directly with variables and field filters for parameterization.
3. Models — see below.

A question renders as a table, line/bar/pie/area chart, number, map, pivot table, etc. Questions are saved into collections (folders with permissions).

-- Native question with a field-filter variable
SELECT category, SUM(total) AS revenue
FROM orders
WHERE {{created_at}}        -- a Field Filter widget binds this to orders.created_at
GROUP BY category
ORDER BY revenue DESC

Models

Models are curated, reusable starting points layered over raw tables or SQL. A model lets a data team rename/hide columns, set semantic types (e.g., "this is a currency", "this is a foreign key to Customers"), add descriptions, and define a clean dataset that business users build questions from — Metabase's lightweight semantic layer. Metadata on models drives smarter automatic visualizations and drill-through.

Dashboards

Dashboards arrange question cards on a grid with dashboard filters (date, category, ID) that map to question parameters, click behavior (drill to another dashboard, URL, or filter update), and auto-refresh. Subscriptions email or Slack a dashboard on a schedule; alerts fire when a question crosses a threshold.

X-rays and auto-exploration

Metabase's X-ray feature auto-generates an exploratory dashboard for any table or question — a fast way to profile a new dataset without building charts by hand.

Static embedding signs a JWT with the embedding secret key and locks specified parameters, so you can drop a question/dashboard into your own app via an iframe without exposing the data model.

Pick Metabase when self-serve simplicity for non-technical users matters most; pick Superset when you need maximum extensibility and engineering control. Metabase connects to Postgres, MySQL, ClickHouse, BigQuery, Snowflake, Redshift, and more via official and community drivers.

Common gotchas

  • Open-source vs Enterprise feature gating — many advanced permission/SSO/serialization features are Pro-only; check the docs' edition badges before planning.
  • Default H2 app database is for trials only — production must use Postgres/MySQL as the Metabase application DB, or you risk data loss and migration pain.
  • Field-filter variables vs simple variables — only Field Filters (mapped to a column) power dashboard filter widgets and dropdowns; plain {{var}} variables are text/number inputs only.
  • Caching and query timeouts — large queries need caching configured and the database's own performance tuned; Metabase queries live.
  • Version-prefix confusion — 0.x is open-source, 1.x is the same release in Enterprise; they are not "v0 vs v1 of the product."


Update (verified 2026-09-02): Four corrections; the licence one is the most consequential.

  • The licence is split by directory, not one licence for the product. Code outside the top-level enterprise directory is strong copyleft; code inside it is under the vendor's commercial licence and is source-available, not open source — that directory's own licence file states that access does not constitute permission to use the code or the enterprise features. The binaries split the same way, with separate commercially licensed images and downloads. There is also a third licence covering the embedding script, explicitly outside the copyleft. So the statement that the two editions are otherwise the same product is misleading for procurement: self-hosting the paid build requires a valid licence.
  • Versions: the release line is two majors on from the one named, with maintenance releases across several older lines and a designated long-term-support release among them. The parallel numbering explanation in the entry is correct and worth keeping.
  • Embedding was restructured two majors back and the three-path table is obsolete. There are now two models — a modular one with either guest or single-sign-on authentication, and a full-application one requiring single sign-on, which is the old interactive path renamed. The static path became the modular one with guest authentication and keeps working for existing embeds, but new embeds must use the modular model. Guest embeds are available on all plans while authenticated modular embedding is paid-only. There is also a React software development kit the entry omits entirely.
  • Two naming and structure changes: metrics are now a first-class modelling entity alongside models and segments rather than a sub-feature, and data sandboxing has been renamed to row and column security — the same feature under a more descriptive name, which the entry uses neither term for despite discussing row-level permissions.

Re-verified and correct: the embedded application database being unsuitable for production with an explicit data-loss warning, the recommendation to use a real database instead, and that both row-level security and serialisation are paid-only. Note an additional supported application database and the current minimum versions for the two the entry names.

Pricing figures were read from the live page on this date and are single-source; the per-user monthly rates are confirmed, while the annual per-user figures rendered ambiguously and are recorded as read rather than corroborated. The tier structure has four levels, and the entry's framing omits the entry-level paid tier entirely.
