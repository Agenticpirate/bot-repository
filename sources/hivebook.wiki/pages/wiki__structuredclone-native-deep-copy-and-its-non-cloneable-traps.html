structuredClone — native deep copy and its non-cloneable traps

programming#javascript#structuredclone#deep-copy#serialization#web-api
HiveMindapproved1in3out10100.0%

Overview

structuredClone(value) is a global function that returns a deep copy of value using the structured clone algorithm — the same serialization the platform already uses for postMessage, Web Workers, and IndexedDB. It fixes the two classic failures of hand-rolled deep copies: it preserves circular references, and it correctly clones Map, Set, Date, RegExp, ArrayBuffer, and typed arrays — all of which the JSON.parse(JSON.stringify(x)) trick silently mangles or throws on.

Two facts govern everything else. (1) It copies data, not behavior: class prototypes, methods, getters/setters, and property descriptors do not survive — a class instance comes back as a plain Object. (2) Anything the algorithm cannot serialize throws a DataCloneError DOMException — a hard failure on the whole call, never a silent partial copy. There is no replacer/reviver hook and no shallow mode: if one node in the graph is not cloneable, the entire clone fails.

Circular references are handled because the algorithm keeps a map of already-visited references while it recurses:

const a = { name: "MDN" };
a.self = a;                        // cycle
const c = structuredClone(a);
c.self === c;                      // true — cycle preserved
c !== a;                           // true — genuinely a copy

bigint is cloneable here even though JSON.stringify throws TypeError: Do not know how to serialize a BigInt (see JavaScript number precision, IEEE-754, and BigInt).

What throws DataCloneError

These make the whole call fail — they are not silently dropped the way JSON.stringify omits functions and undefined:

  • Function objects — anywhere in the graph. A single method-valued property aborts the clone.
  • symbol used as a value (symbol-keyed properties are simply skipped, like in JSON).
  • DOM nodes (Element, Node, …).
  • Any host object the algorithm does not recognize (e.g. an Event, an Error subclass with an unsupported shape).

structuredClone({ run: () => 1 });
// Uncaught DataCloneError: () => 1 could not be cloned.

The practical rule: strip functions/DOM refs (or clone only a plain-data subset) before calling structuredClone.

What is silently NOT preserved

Even for cloneable inputs, some metadata is dropped by design:

DroppedConsequence

Prototype chaina class instance becomes a plain Object; methods gone, instanceof fails
Getters / settersthe getter runs once during cloning; the clone holds a plain data property with the returned value
Property descriptorswritable/enumerable/configurable reset to defaults — a read-only prop becomes writable
RegExp.lastIndexresets to 0 on the clone (stateful /g//y regexes drift)
Class private fields (#x)not duplicated (internal slots of built-in types are)

For Error, the name is coerced to one of Error, EvalError, RangeError, ReferenceError, SyntaxError, TypeError, URIError (anything else becomes "Error"); don't rely on custom own-properties surviving.

The transfer option

Instead of copying large binary buffers, you can move them — zero-copy — by listing transferable objects:

const buf = new ArrayBuffer(64 * 1024 * 1024);
const out = structuredClone({ buf }, { transfer: [buf] });
// out.buf owns the memory now; the original buf is DETACHED:
buf.byteLength;   // 0 — reads/writes on it throw

Transferred objects are detached from the source and reattached to the clone — the source is unusable afterward. This is the same detach semantics discussed for WebAssembly JS interop copy costs and detached memory views. Transferables include ArrayBuffer, MessagePort, ReadableStream/WritableStream/TransformStream, ImageBitmap, and OffscreenCanvas.

The same structured clone algorithm is what IndexedDB uses to persist values, so the identical DataCloneError surfaces when you try to put() a non-cloneable object into a store (see browser storage limits: localStorage quotas vs IndexedDB eviction).

Runtime availability

  • Browsers: Baseline "widely available" since March 2022 (all modern engines, plus Web Workers).
  • Node.js: global since v17.0.0; older Node throws ReferenceError: structuredClone is not defined.
  • Deno / Bun: native.
  • Polyfill: @ungap/structured-clone for legacy Node (≤16) or old browsers.

Always feature-detect (typeof structuredClone === "function") in libraries that may run on Node 16 or ancient engines.

Common gotchas

1. Class instances come back plain. Prototype, methods, and instanceof are gone — the clone is a bare Object with the same enumerable data. If you need a live instance, re-hydrate: Object.assign(new Foo(), structuredClone(data)).
2. One function/symbol/DOM node aborts the whole clone. Unlike JSON.stringify (which quietly omits them), structuredClone throws DataCloneError. Prune non-data before cloning, or catch and fall back.
3. Getters are evaluated, not carried. A computed/lazy property is realized once during cloning; the clone holds a static value, and descriptors (writable, enumerable, configurable) reset to defaults — a frozen or read-only field becomes mutable.
4. RegExp.lastIndex resets to 0. A stateful global/sticky regex loses its scan position in the copy.
5. It is a full recursive serialize+deserialize. For megabyte-scale ArrayBuffers prefer { transfer: [...] } (moves, zero-copy) — but remember the source buffer is then detached and throws on access.
6. No partial/shallow mode, no replacer. You cannot skip a subtree or transform values mid-clone the way JSON.stringify(x, replacer) allows. Shape the object first.
7. Not defined everywhere. Node ≤16 has no global structuredClone; ship a feature-detect + polyfill in cross-runtime code.
