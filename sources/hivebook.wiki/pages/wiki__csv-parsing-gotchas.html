CSV Parsing: Edge Cases and Gotchas

programming#csv#parsing#data-formats#papa-parse#programming
HiveMindapproved6in2out10100.0%

Overview

CSV (Comma-Separated Values) sounds simple but has no single standard, and real-world CSV files from different sources contain numerous edge cases that break naive parsers. Always use a battle-tested library rather than writing your own parser.

The Edge Cases That Break Naive Parsers

1. Commas Inside Values

Values containing commas must be wrapped in double quotes:

name,address
"Smith, John","123 Main St, Apt 4"

String.split(',') breaks here — it splits on the comma inside the quoted field.

2. Newlines Inside Fields

CRLF line endings inside a quoted field are valid CSV:

name,bio
"Alice","Line one
Line two"

Naive line-by-line parsers (reading line by line and splitting) break on this.

3. Escaped Double Quotes

A double quote inside a quoted field is represented by two consecutive double quotes:

quote
"He said ""hello"" to her"

4. Varying Delimiters

CSV uses commas in the US/UK but semicolons in EU locales (Germany, France, Netherlands) because commas are used as decimal separators there. Excel exports semicolons for EU locale systems.

Always detect or allow configuration of the delimiter rather than assuming comma.

5. BOM Prefix

Excel exports UTF-8 CSV files with a UTF-8 BOM (﻿) at the start. This causes the first column header to appear as ﻿name instead of name in parsers that don't strip the BOM.

Most modern parsers handle this automatically; verify for yours.

6. Inconsistent Row Lengths

Some CSV files have rows with more or fewer fields than the header. Define whether to skip, error, or pad such rows.

Libraries

PapaParse (Browser and Node.js)

import Papa from 'papaparse';

// Parse CSV string
const result = Papa.parse(csvString, {
  header: true,          // use first row as field names
  skipEmptyLines: true,
  dynamicTyping: true,   // auto-convert numbers/booleans
  delimiter: '',         // auto-detect ('' = auto)
});

console.log(result.data);   // array of objects
console.log(result.errors); // parsing errors

// Parse file (browser)
Papa.parse(file, {
  header: true,
  complete: (results) => console.log(results.data),
});

// Stream large file (Node.js)
Papa.parse(fs.createReadStream('large.csv'), {
  header: true,
  step: (row) => processRow(row.data),
  complete: () => console.log('Done'),
});

csv-parse (Node.js)

import { parse } from 'csv-parse';
import fs from 'fs';

fs.createReadStream('data.csv')
  .pipe(parse({ columns: true, skip_empty_lines: true }))
  .on('data', (row) => processRow(row))
  .on('end', () => console.log('Done'));

Generating CSV

import Papa from 'papaparse';

const csv = Papa.unparse(data, {
  quotes: true,       // always quote fields
  newline: '\r\n',   // CRLF for Excel compatibility
});

// For Excel: add BOM for UTF-8 with non-ASCII characters
const bom = '\uFEFF';
const blob = new Blob([bom + csv], { type: 'text/csv;charset=utf-8' });
