Kubernetes Gateway API: Resources, HTTPRoute Features, and Migration from Ingress

Overview

The Kubernetes Gateway API is the successor to Ingress: a role-oriented, expressive, portable set of CRDs for north/south and mesh traffic. Core types (GatewayClass, Gateway, HTTPRoute) have been GA/Standard since v1.0.0 (October 2023). The current release is v1.6.1 (July 16, 2026). v1.4.0 graduated BackendTLSPolicy, named route rules, and supportedFeatures in GatewayClass status to Standard; since then v1.5.0 promoted TLSRoute and XListenerSet to Standard, and v1.6.0 graduated TCPRoute and UDPRoute to GA — so all core Layer-4 route types are now Standard, not experimental.

Gateway API is not built into core Kubernetes — CRDs are installed separately from the kubernetes-sigs/gateway-api release artifacts, then a conformant controller (Envoy Gateway, Istio, Cilium, NGINX Gateway Fabric, Kong, GKE Gateway, AWS Load Balancer Controller, etc.) reconciles them.

Routes bind to Gateways via parentRefs. A Gateway listener may restrict which namespaces can attach routes via allowedRoutes.namespaces.from (Same default, All, or Selector).

Gateway Example

apiVersion: gateway.networking.k8s.io/v1
kind: Gateway
metadata:
  name: public
  namespace: infra
spec:
  gatewayClassName: envoy
  listeners:
  - name: https
    protocol: HTTPS
    port: 443
    hostname: "*.example.com"
    tls:
      mode: Terminate
      certificateRefs:
      - name: example-com-tls
    allowedRoutes:
      namespaces:
        from: Selector
        selector:
          matchLabels:
            gateway-access: "true"

HTTPRoute

A route is a list of rules; each rule has matches, optional filters, and backendRefs. Matchers: path (Exact / PathPrefix / RegularExpression), headers, queryParams, method. Only one rule may match a given request — precedence is (1) exact > prefix > regex, (2) longer path wins, (3) more header/query matches win.

apiVersion: gateway.networking.k8s.io/v1
kind: HTTPRoute
metadata: { name: api, namespace: apps }
spec:
  parentRefs:
  - name: public
    namespace: infra
    sectionName: https
  hostnames: ["api.example.com"]
  rules:
  - name: v2-canary
    matches:
    - path: { type: PathPrefix, value: /v2 }
    filters:
    - type: RequestHeaderModifier
      requestHeaderModifier:
        set: [{ name: x-api-version, value: "2" }]
    timeouts: { request: 30s, backendRequest: 10s }
    backendRefs:
    - { name: api-v2, port: 8080, weight: 90 }
    - { name: api-v1, port: 8080, weight: 10 }

Timeouts & Weights

  • timeouts.request: total client-to-response budget.
  • timeouts.backendRequest: per-backend attempt — must be ≤ request.
  • backendRefs[].weight: integer, default 1. Weight 0 drops traffic but keeps the ref addressable.

Ingress annotations do not port — they were always implementation-specific. Most controllers ship a translator or a migration guide (Envoy Gateway, NGINX Gateway Fabric).

Channels

Gateway API ships two CRD bundles per release:

  • Standard — GA. Safe for production. Includes Gateway, GatewayClass, HTTPRoute, GRPCRoute, ReferenceGrant, BackendTLSPolicy, and — since v1.5–v1.6 — TLSRoute, TCPRoute, UDPRoute, XListenerSet.
  • Experimental — alpha features, x-kubernetes-* fields, Mesh, XBackendTrafficPolicy, XBackend, CORS, externalAuth. Breaking changes allowed; pin your manifests to a specific release.

Install exactly one bundle — mixing Standard and Experimental CRDs is unsupported. Verify with kubectl get crd gateways.gateway.networking.k8s.io -o jsonpath='{.metadata.annotations.gateway\.networking\.k8s\.io/bundle-version}'.

Common Gotchas

1. Routes default to same-namespace. If your Gateway is in infra and your HTTPRoute in apps, attach fails silently until allowedRoutes.namespaces.from: All or a label selector matches — check status.parents[].conditions[type=Accepted].
2. Cross-namespace backendRef requires a ReferenceGrant in the backend's namespace. Without it the route is accepted but the backend resolves to 500.
3. Only one rule matches per request — overlapping prefixes silently fall through to the highest-specificity match. Use named rules (v1.4) so status tells you which rule owned the request.
4. URLRewrite and RequestRedirect are mutually exclusive in the same filter chain — the controller rejects the route.
5. CRD and controller versions must match. Installing v1.4 CRDs against a controller that only knows v1.2 types causes schema errors on unknown fields; check the controller's declared supportedFeatures.
6. hostname wildcards only match a single DNS label. *.example.com matches api.example.com but not v2.api.example.com.
7. TLS passthrough needs TLSRoute (Standard since v1.5) — Gateway.listener.tls.mode: Passthrough without a TLSRoute silently drops traffic.
8. Experimental fields survive a Standard reinstall with garbage — removing Experimental CRDs does not strip x- fields from stored objects. Delete resources first, then swap CRD bundles.
9. backendRequest > request is rejected by admission — align timeouts with your graceful-shutdown budget (see process signals).
10. Ingress annotations don't migrate automatically. Rate limiting, OAuth, body-size limits, buffering — all were annotation-driven and now live in controller-specific ExtensionRef filters or policy CRDs. Audit your Ingress before flipping the switch.
