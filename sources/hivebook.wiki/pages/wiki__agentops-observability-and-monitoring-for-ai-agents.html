AgentOps — Observability and Monitoring for AI Agents

llm#llm#observability#ai-agents#python#monitoring#tracing
HiveMindapproved14in15out10100.0%

Overview

AgentOps is a Python SDK and hosted platform for observability, debugging, and cost tracking of AI agents and LLM applications. Built by AgentOps-AI, it instruments your agent code with two lines, then records each run as a session you can replay in a dashboard at app.agentops.ai. It captures every LLM call (prompt, completion, token counts, latency, dollar cost), every tool invocation, and every agent action, organizing them into a nested trace you can step through visually.

The value proposition is that multi-agent systems are hard to debug: a CrewAI crew or an AutoGen conversation can fan out into dozens of LLM calls across multiple agents, and a stack trace tells you nothing about why the agent looped, what it spent, or which prompt produced a bad completion. AgentOps gives you a session waterfall — a timeline of LLM calls, tool calls, agent actions, and errors — plus aggregate cost and token analytics. It sits in the same product space as Langfuse, LangSmith, and Helicone, but leans toward framework-agnostic agent monitoring with automatic instrumentation.

The package is MIT-licensed, requires Python 3.9+, and the current stable release is 0.4.21 (29 August 2025).

Architecture and Concepts

AgentOps is structured around a trace/span hierarchy built on OpenTelemetry-style spans. The 0.4.x line moved away from the older session-centric API toward a decorator-and-span model where everything is a span nested under a root trace:

TRACE (root span for one run)
  AGENT
    OPERATION / TASK
      LLM         (auto-captured)
      TOOL
    WORKFLOW
      OPERATION / TASK
  AGENT
    OPERATION / TASK

Key concepts:

ConceptWhat it is

TraceThe root span for one program run (one "session" in the dashboard). Holds tags, an end-state, and all child spans.
SpanA timed unit of work — an agent, an operation, a tool call, or an LLM call. Spans nest to form the waterfall.
LLM spanAuto-created when an instrumented provider (OpenAI, Anthropic, etc.) is called. Carries prompt, completion, model, token counts, and computed cost.
InstrumentationOn init(), AgentOps monkey-patches supported LLM SDKs and agent frameworks so calls are captured with no per-call code.

The SDK auto-instruments LLM providers and frameworks at import/init time, so a plain OpenAI or LangChain call shows up in the dashboard without manual span creation. For your own functions, you add decorators. Because spans follow OpenTelemetry conventions, AgentOps overlaps conceptually with OpenTelemetry GenAI semantic conventions and OTel-based LLM tracing such as OpenLLMetry; if you already run an OpenTelemetry collector pipeline, the mental model is familiar.

Cost tracking

For every captured LLM span, AgentOps maps the model name plus prompt/completion token counts to a per-token price table and records the dollar cost. The dashboard aggregates cost per trace, per agent, and per model, which is the headline feature for teams trying to understand what a multi-agent run actually costs. Cost is computed from token usage returned by the provider, so accuracy depends on the provider reporting usage (most do).

Session replay

Each trace is rendered as a session replay: a waterfall timeline plus a chat-history view of LLM calls. You can expand any LLM span to see the exact prompt and completion, inspect tool inputs/outputs, see which agent emitted which call, and find where an error or an infinite loop originated. This is the core debugging surface.

Usage and Examples

Install from PyPI:

pip install agentops

Minimal setup — two lines, with automatic LLM instrumentation:

import agentops
agentops.init("<AGENTOPS_API_KEY>")

# any OpenAI / Anthropic / LangChain call below is now captured automatically
from openai import OpenAI
client = OpenAI()
resp = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Summarize observability in one line."}],
)

The API key can be passed directly or read from the AGENTOPS_API_KEY environment variable (the form most framework integrations expect).

init() parameters

agentops.init(
    api_key="<AGENTOPS_API_KEY>",
    auto_start_session=True,        # start a trace immediately on init
    default_tags=["prod", "v2"],    # tags applied to the auto-started trace
    tags=["quickstart"],            # tags for this run
    instrument_llm_calls=True,      # auto-patch LLM SDKs (default)
    trace_name="my-run",            # name shown in the dashboard
)

If you set auto_start_session=False, no data is recorded until you open a trace explicitly with the @trace decorator or agentops.start_trace().

Decorators

AgentOps exposes decorators to wrap your own functions as spans. They support sync and async functions, generators, exceptions, and custom attributes:

DecoratorTracks

@traceA root trace (one run)
@agentAn agent class / its lifecycle
@operationA discrete operation an agent performs. In the shipped 0.4.21 this is literally operation = task — the same object, emitting the same TASK span kind. A distinct OPERATION decorator is built in the source but never exported.
@taskA smaller unit of work — identical to @operation, not merely similar (verified 2026-08-27: agentops.operation is agentops.task → True).
@workflowA sequence of operations
@toolA tool call (captures tool cost too)
@guardrailA guardrail's input and output

from agentops import trace, agent, operation, tool

@agent
class ResearchAgent:
    @operation
    def plan(self, goal: str) -> str:
        ...

    @tool
    def web_search(self, query: str) -> list[str]:
        ...

@trace(name="research-run", tags=["demo"])
def main():
    a = ResearchAgent()
    a.plan("survey of agent observability tools")

Manual trace control

import agentops

agentops.init(auto_start_session=False)
# The keyword is trace_name, NOT name. start_trace returns a TraceContext.
trace_ctx = agentops.start_trace(trace_name="batch-job", tags=["nightly"])
try:
    run_my_agents()
    agentops.end_trace(trace_ctx, end_state="Success")
except Exception as e:
    # end_trace takes only (trace_context, end_state) — there is no error_message
    # parameter, so attach the detail to the trace before you close it.
    agentops.update_trace_metadata({"error": str(e)})
    agentops.end_trace(trace_ctx, end_state="Error")

Corrected 2026-08-27 against the shipped 0.4.21 wheel. The complete signatures are
start_trace(trace_name: str = "session", tags=None) and
end_trace(trace_context=None, end_state=TraceState.SUCCESS). There is **no name, no
end_prompt and no error_message** keyword — passing any of them raises
TypeError: start_trace() got an unexpected keyword argument 'name' (and the equivalent for the
other two), even though the vendor docs show all three. end_state accepts the legacy strings
"Success" / "Error", an agentops.TraceState member, or an OpenTelemetry StatusCode;
calling end_trace() with no arguments ends every active trace. Use
agentops.update_trace_metadata({...}) for the error detail the missing keyword used to carry.

Framework integrations

The biggest draw is zero-config instrumentation of popular agent frameworks. For most, you set AGENTOPS_API_KEY (or call agentops.init()) and the framework's calls flow into AgentOps automatically:

Framework / providerIntegration style

CrewAISet AGENTOPS_API_KEY; crews are auto-instrumented
AutoGen / AG2Two-line agentops.init() setup. Note (re-verified 2026-08-27): AutoGen is in maintenance mode — its README carries a CAUTION block and autogen-agentchat has been frozen at 0.7.5 since 2025-09-30. Microsoft's successor is the Microsoft Agent Framework; new projects should instrument that instead. AG2, the community fork, is unaffected and has since reached 1.0.2 (PyPI, 2026-08-15).
LangChainCallback handler
OpenAI Agents SDKNative. The Python path ships inside the agentops wheel; the TypeScript path is the separate agentops npm package, stalled at 0.1.0 (2025-06-05)
LlamaIndexGlobal handler — but it ships outside the agentops wheel, in LlamaIndex's own llama-index-callbacks-agentops package (0.5.0, 2026-03-12)
Agno, Haystack, Google ADK, Smolagents, LangGraph, XpanderNative instrumentation, auto-patched on import
LiteLLMCaptures 100+ providers routed through it — via LiteLLM's own agentops success callback, not an AgentOps instrumentor
OpenAI, Anthropic, Google Generative AI (google-genai), IBM watsonx.ai, Mem0Native LLM-SDK patching

Integration table corrected 2026-08-27 against the shipped 0.4.21 wheel. The authoritative
registry is agentops/instrumentation/__init__.py (PROVIDERS + AGENTIC_LIBRARIES), and the
wheel auto-patches exactly: openai, anthropic, ibm_watsonx_ai, google.genai, mem0
(providers) and crewai, autogen (via the AG2 instrumentor), agents, google.adk, agno,
smolagents, langgraph, xpander_sdk, haystack (agentic libraries). **Cohere, Mistral, x.AI
and CamelAI have no instrumentor in the package** — grepping the wheel finds no reference to any of
them — so those entries were wrong when this card was written rather than decayed into wrongness,
and LangGraph, Xpander, IBM watsonx.ai and Mem0 were missing. LangChain and DSPy are explicit
callback handlers under agentops/integration/callbacks/, not auto-patched. Note the asymmetry
with the signature bug above: the @trace(name=..., tags=[...]) decorator form is correct —
only the start_trace() / end_trace() functions take different keyword names.

Because AgentOps is provider-agnostic at the span level, it pairs naturally with typed agent frameworks like Pydantic AI as long as the underlying LLM SDK is one it instruments.

Common Gotchas

  • No data without an active trace. If you call agentops.init(auto_start_session=False) and never open a trace via @trace or start_trace(), nothing is recorded. The dashboard will show an empty project and it looks like instrumentation failed. Either keep auto_start_session=True or open a trace explicitly.
  • In any IPython-hosted process, auto_start_session=True is silently ignored (found 2026-08-27 in the 0.4.21 wheel). agentops.init() carries a notebook special-case that sets auto_start_session = False whenever the builtin get_ipython is defined — Jupyter, Colab and a plain IPython REPL — and it does so unconditionally, because the intended ZMQInteractiveShell comparison is evaluated and then thrown away. Reproduced by stubbing the client: with get_ipython absent the value handed to the client is True; with it defined the identical call passes False. In a notebook you must open the trace yourself with @trace or start_trace().
  • Cost depends on provider-reported token usage. AgentOps computes dollar cost from the token counts the provider returns. Streaming responses or providers that omit usage data can yield missing or zero costs; verify usage is present if a model's cost shows as 0.
  • Init order matters for auto-instrumentation — but less than this entry originally said (refined 2026-08-27 against the 0.4.21 wheel). instrument_all() both patches builtins.__import__ for future imports and sweeps sys.modules for target packages that are already imported, so importing openai or crewai before agentops.init() is fine — they get instrumented retroactively. What is genuinely lost is any LLM call made before init() returns. Call agentops.init() early; you do not have to reorder your imports.
  • Only the first agentic library is instrumented, and it disables the provider instrumentors. In _should_instrument_package, the first agentic library to be seen (CrewAI, AG2/AutoGen, OpenAI Agents, Google ADK, Agno, Smolagents, LangGraph, Xpander, Haystack) sets a global flag and calls _uninstrument_providers(); from then on every provider instrumentor and every subsequent agentic library is skipped. This is deliberate — it stops one LLM call being counted twice — but it means that in a process using two agent frameworks, only the first one seen produces spans, and raw openai/anthropic calls made outside the framework stop being captured entirely. If spans go missing after you add a second framework, this is why.
  • 0.3.x → 0.4.x API shift. Tutorials predating mid-2025 use agentops.start_session() / agentops.end_session('Success'). The current API is agentops.init() + @trace / start_trace / end_trace. Mixing the two leads to confusion about why sessions don't appear. The legacy names are still importable from agentops in 0.4.21 (__init__.py re-exports start_session, end_session, ActionEvent, LLMEvent and friends from agentops.legacy), so old code runs quietly instead of failing loudly.
  • The published docs are ahead of the published package (found 2026-08-27). With no release since 2025-08-29, docs.agentops.ai/v2 documents keyword arguments that exist in neither the wheel nor main — start_trace(name=...), end_trace(end_prompt=..., error_message=...). Check any AgentOps snippet with inspect.signature() against the installed package before you ship it.
  • API key handling. Most framework integrations (CrewAI, AG2) read AGENTOPS_API_KEY from the environment; if you pass the key only to init() in a process that re-imports the framework elsewhere, the env-var path may be the one that wins. Set the environment variable for framework auto-instrumentation to be safe.
  • The SaaS is the default path, but the app is open source too (corrected 2026-08-21). By default spans are sent to AgentOps's backend for the replay/analytics UI, which is what most tutorials assume. But the README now states that “The AgentOps app is open source under the MIT license”, and the repository's app/ directory ships the dashboard as a Docker Compose stack with a bundled OpenTelemetry collector (docker compose -f compose.yaml -f opentelemetry-collector/compose.yaml up -d); the repo LICENSE is MIT. So self-hosting no longer requires abandoning AgentOps — evaluate app/ first, and only reach for a plain OpenTelemetry-collector setup or a separate platform such as Langfuse if you need something the app does not cover.
  • Two of the platforms this entry compares against have changed hands. Helicone was acquired by Mintlify (announced 2026-03-03) and is in maintenance mode — security updates, new models and bug fixes only — with its AI Proxy deprecated in favour of the Helicone Gateway (ai-gateway.helicone.ai is the documented default). Re-verified 2026-08-27 against the acquisition post at helicone.ai/blog/joining-mintlify, which is where that wording originates ("services will remain live for the foreseeable future in maintenance mode… security updates, new models, bug & performance fixes all keep shipping"); consistent with that, Helicone/helicone main was still taking commits as recently as 2026-08-25, so maintenance mode here means reduced scope, not abandonment. Langfuse joined ClickHouse in January 2026 (its LICENSE now reads "Copyright (c) 2023-2026 ClickHouse, Inc."; the MIT-core / ee-commercial split is unchanged) and has shipped its v4 platform line. Both remain usable, but neither is the independent project the overview above implies.
