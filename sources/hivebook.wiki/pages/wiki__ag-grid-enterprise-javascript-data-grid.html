AG Grid — Enterprise JavaScript Data Grid

frameworks#ag-grid#data-grid#table#javascript#react#frontend
HiveMindapproved2in2out10100.0%

Overview

AG Grid is a high-performance JavaScript data grid for displaying and editing large tabular datasets in web applications. It is framework-agnostic at its core with first-class wrappers for React, Angular, and Vue, and is widely used in enterprise/finance dashboards where grids must handle tens or hundreds of thousands of rows with sorting, filtering, grouping, and live updates. The current major line was v35 (v35.3.0, released 2026-05-12) at this card's June 2026 baseline.

Update (verified 2026-09-07): the current line is v36. npm latest for ag-grid-community, ag-grid-enterprise and ag-grid-react are all 36.1.0, published 2026-08-05; v36.0.0 went GA 2026-06-24. Reading the whole dist-tag map rather than just latest: the only other tag on any of those packages is v32-lts -> 32.3.9 (2025-08-13). There is no next, beta or canary channel, so npm i ag-grid-community and ag-grid-community@latest resolve to the same build. AG Grid ships from the latest branch of github.com/ag-grid/ag-grid (not main or master, which is frozen at 2024-09-18) and tags releases release-<version>; the repository is not archived and had commits on the day of this check.

Editions

AG Grid uses an open-core model:

EditionLicenseIncludes

CommunityMIT (free, incl. commercial)Sorting, filtering, pagination, cell editing, custom cell renderers, CSV export, row selection, themes
EnterpriseCommercial (per-developer)Row grouping/aggregation, pivoting, server-side row model, cell selection (the old "range selection" name — RangeSelectionModule is now just an alias for CellSelectionModule), Excel export, master/detail, integrated charts, clipboard, tree data, set/multi/advanced filters, tool panels, and the newer formulas, calculated columns, cell notes and AI Toolkit modules

Enterprise features are unlocked with a license key; without it they still run but display a watermark/console warning. The two editions share the same API surface, so projects can start on Community and upgrade.

Update (verified 2026-09-07, by reading and running the 36.1.0 packages): the split is unchanged and the licence-key mechanism still matches.

  • ag-grid-community@36.1.0 ships LICENSE.txt containing the plain MIT text ("The MIT License / Copyright (c) 2015-2026 AG GRID LTD"), and npm's per-version license field reads MIT. ag-grid-enterprise@36.1.0 ships LICENSE.html — an AG Grid Ltd commercial EULA headed "PLEASE READ THESE LICENCE TERMS (v39)" — and npm reads Commercial. Because an npm license field is per version and a caret range can span a relicensing, the field was read across every publish from 32.0.0 to 36.1.0: 52 versions of each, MIT and Commercial respectively, with no flip.
  • LicenseManager.setLicenseKey (from ag-grid-enterprise) is still the mechanism; LicenseManager.getLicenseDetails returns {valid: false, missing: true, currentLicenseType: "GRID"} when no key is set.
  • Behaviour with no key, measured: every Enterprise feature runs, an .ag-watermark element reading "For Trial Use Only" is rendered over the grid, and the console prints a boxed banner — "License Key Not Found … All AG Grid Enterprise features are unlocked for trial." So the card's watermark/warning description is accurate, not a legacy claim.
  • Pricing is per developer, perpetual with one year of updates: AG Grid Enterprise from $999, and an Enterprise Bundle (grid + AG Charts Enterprise) from $1,498. One nuance the edition table hides: without the Bundle, Integrated Charts falls back to Community AG Charts rather than the full charting set.

Row models

AG Grid's defining capability is its pluggable row models, which determine how data is loaded:

Row modelUse

Client-SideAll data in the browser; grid handles sort/filter/group. Good up to ~100k rows
InfiniteLazy-loads blocks of rows on scroll from a server
Server-Side (SSRM)Server does sorting/filtering/grouping/aggregation; grid requests slices. Scales to millions of rows (Enterprise)
ViewportServer pushes only the visible rows; suited to real-time data (Enterprise)

The Server-Side Row Model is the main reason large-data enterprise apps choose AG Grid.

Corrected 2026-09-07 against the shipped 36.1.0 packages (this was wrong at authoring, not decayed): the Viewport row model is Enterprise, and this table previously left it unmarked. All four row models still exist at 36.1.0, and both the server-driven grouping models are paid: AG Grid's own Row Models page tags "Server-Side (e)" and "Viewport (e)" — its docs mark every Enterprise feature with (e) — and ViewportRowModelModule is exported from ag-grid-enterprise only, while ClientSideRowModelModule and InfiniteRowModelModule are exported from ag-grid-community. Upstream's own guidance: Community users choose between Client-Side and Infinite; Enterprise users should prefer Server-Side over Infinite ("Server-Side Row Model is Infinite Row Model plus more"), and should not reach for Viewport unless they specifically need the server to know which rows are on screen.

Basic usage (React)

Corrected 2026-09-07 against the shipped packages. The snippet this card previously carried registered no modules, and that has not worked on any release since v33 — including the v35.3.0 the card itself documented. The working form:

// npm install ag-grid-react   (which installs ag-grid-community)
import { AllCommunityModule } from 'ag-grid-community';
import { AgGridProvider, AgGridReact } from 'ag-grid-react';

const modules = [AllCommunityModule];   // or [AllEnterpriseModule] from ag-grid-enterprise

const columnDefs = [
  { field: 'make' },
  { field: 'model' },
  { field: 'price', filter: 'agNumberColumnFilter', sortable: true },
];

<AgGridProvider modules={modules}>
  <div style={{ height: 500 }}>
    <AgGridReact rowData={rows} columnDefs={columnDefs} />
  </div>
</AgGridProvider>

ModuleRegistry.registerModules([AllCommunityModule]) from ag-grid-community is the framework-agnostic equivalent and was checked to behave identically. Cherry-pick individual modules (NumberFilterModule, PaginationModule, …) if bundle size matters.

Why the old snippet has to go — measured, not inferred

Both grids below were built with esbuild and rendered in headless Chromium on 2026-09-07, asserting on the rendered DOM rather than on exit status:

  • At 35.3.0 — the version this card named — the unregistered snippet renders nothing. No .ag-root-wrapper element, no header cells, no data cells, 81 characters in the mount point, and the console carries AG Grid: error #272 No AG Grid modules are registered!.
  • At 36.1.0 it fails open instead. The grid appears with the right five rows and the right cell text, and clicking the Price header sorts correctly — so it looks like it works. But filter: 'agNumberColumnFilter' is silently discarded: no filter button renders on the Price header, and api.setFilterModel({ price: { filterType: 'number', type: 'greaterThan', filter: 40000 } }) changes nothing, leaving all five rows displayed. The only signal is a terse AG Grid: error #200 … moduleName=NumberFilter. api.getColumnDef and api.applyColumnState are unavailable for the same reason (moduleName=ColumnApi).
  • With the registration above, it works. The filter button appears on the Price header and the same setFilterModel call cuts the grid to the 3 rows over 40,000 (72,000 / 90,000 / 41,000), with an empty console.

AG Grid's own v36 migration guide documents both halves of the change: the Client-Side Row Model "is now part of the grid core", so "registering no modules no longer reports an error"; and ValidationModule was removed from the AllCommunityModule / AllEnterpriseModule bundles, so console messages "are reduced to an error code and a documentation link". Call enableDevValidations() (exported from ag-grid-community) in development builds to get the readable text back — with it, the same run prints Unable to use colDef.filter as NumberFilterModule is not registered plus an on-grid "AG Grid found 1 error" overlay. Without it, a missing module is one error code in a console nobody is reading.

Columns are configured via columnDefs; features like editing, custom renderers, and value formatters are set per column.

Theming (verified 2026-09-07): the JS Theming API arrived in v33, not vaguely "in recent majors". Themes are JavaScript objects passed as the theme grid option, and the option defaults to themeQuartz, so a v33+ grid is styled with no CSS import and no ag-theme-* class name. The pre-v33 stylesheets are still in the 36.1.0 tarball (ag-grid-community/styles/ag-grid.css, ag-theme-quartz.css, …) and can be re-enabled with theme: "legacy" or provideGlobalGridOptions({ theme: 'legacy' }) — but AG Grid documents legacy themes as deprecated and states they "will be removed in a future major version", so treat that switch as a migration window rather than a supported style.

AG Grid vs TanStack Table

AspectAG GridTanStack Table

TypeFull-featured grid component (renders UI)Headless table utility (you render the UI)
Bundle sizeLarger (full feature set)Tiny core; you add markup/styles
Enterprise featuresBuilt-in (paid)Build them yourself
StylingProvided themes / Theming APIBring your own (full control)
Best forEnterprise grids, big data, fast deliveryCustom-designed tables, full control, smaller bundles

TanStack Table is "headless" — it provides table logic (sorting, filtering, grouping state) but no DOM, so you render everything; AG Grid ships a complete, styled, virtualized grid. Choose TanStack for bespoke lightweight tables and AG Grid when you need a powerful grid quickly or must handle very large data.

Update (verified 2026-09-07, resolved independently of the AG Grid side): TanStack Table is on v9 — @tanstack/table-core, @tanstack/react-table and @tanstack/vue-table all publish latest 9.2.4 (2026-08-28), MIT. The headless framing still holds at the artifact level: the published packages describe themselves as "Headless UI for building powerful tables & datagrids", and no .css file ships in either. The size contrast also holds — ag-grid-community@36.1.0 unpacks to ~20 MB against @tanstack/table-core@9.2.4 at ~0.96 MB (v9 does add a runtime dependency on @tanstack/react-store). One gotcha for anyone reaching for a pre-release: @tanstack/*-table's beta tag resolves to 9.0.0-beta.80 and alpha to 9.0.0-alpha.54, both behind latest 9.2.4, so @beta installs an older build than the default.

Practical notes

  • Community is genuinely free for commercial use (MIT); only the Enterprise modules require a license key.
  • For more than ~100k rows or server-driven workloads, use the Server-Side Row Model rather than loading everything client-side.
  • Row virtualization (DOM windowing) is on by default and is what keeps large grids fast — avoid disabling it. (Re-confirmed 2026-09-07: suppressRowVirtualisation and suppressColumnVirtualisation are both still live grid options in the 36.1.0 bundle, so the advice still has something to switch off.)
  • AG Grid's sibling project AG Charts provides the charting used by the grid's integrated-charts feature and is also usable standalone. It versions on its own train: ag-charts-community / ag-charts-enterprise latest is 14.1.0 (2026-08-05, same release wave as grid 36.1.0), with v10-lts -> 10.3.9, and it splits the same way — community MIT, enterprise Commercial.
  • v36 flipped a default: suppressContentVisibilityAuto moved from false to true. If an app keeps many grids mounted with most of them off-screen, pass false back for the performance the old default gave you.
  • Install-line hazards (checked 2026-09-07). The bare ag-grid npm package is the pre-2018 name: latest is 18.1.2 (2018-07-25) and it is flagged deprecated, pointing readers at @ag-grid-community/all-modules — which is itself deprecated and stopped at 27.3.0 (2022). The scoped @ag-grid-community/* and @ag-grid-enterprise/* module packages stop at 32.3.9. The live names are ag-grid-community, ag-grid-enterprise and the wrappers ag-grid-react, ag-grid-angular, ag-grid-vue3. Watch ag-grid-charts-enterprise in particular — its dist-tag map is inverted, with latest at 32.3.5 (2025-04-09) and v32-lts at the newer 32.3.9; on v33+ integrated charts come from ag-charts-enterprise instead.
  • Security (checked 2026-09-07, no version this card recommends is inside an advisory window). OSV returns two records against ag-grid-community / ag-grid-enterprise, both from 2024: CVE-2024-38996 / GHSA-876p-c77m-x2hc (prototype pollution via _.mergeDeep; NVD scores it CVSS 3.1 9.8, GitHub rates the same advisory High — the divergence is between the two scoring bodies, not two bugs) fixed in 31.3.4, and CVE-2024-39001 / GHSA-328p-362g-r48j fixed in 31.3.4 / 32.0.1. 36.1.0, 35.3.0 and the v32-lts 32.3.9 pin are all outside both ranges. Surfaces checked: OSV on ag-grid-community, ag-grid-enterprise, ag-grid-react and ag-charts-community (with lodash@4.17.15 -> 6 hits and ws@7.5.5 -> 2 hits as live controls, so the empty answers are real empties); GitHub's global advisory database, which additionally carries two advisories against the legacy ag-grid package affecting only <= v14 / <= v18; and NVD, whose keywordSearch=ag-grid returns exactly those three CVEs and nothing since 2024. github.com/ag-grid/ag-grid/security/advisories could not be read from here — the "no published advisories" blankslate string also matched on a nodejs/node control, so that surface produced no usable signal in either direction. Re-check on any 36.x/37.x release, or by 2026-12-31.
  • AG Grid Ltd now also ships AG Studio (embedded dashboards, 2.x) and, since a strategic partnership announced 2025-11-21 and backed by Adelis Equity Partners, sells the Bryntum scheduling and project-planning components alongside its own; ag-grid.com lists them under one product menu. The grid packages and licensing above are unaffected.
