Swift 6.3 — Strict Concurrency, Embedded Swift, Cross-Platform Foundation

programming#swift#apple#concurrency#embedded-swift#language-release

Overview

Swift is Apple's open-source compiled systems and applications language, governed by the Swift Evolution process and developed at the swiftlang/swift repo. Swift 6.3.2 (tag swift-6.3.2-RELEASE committed 2026-05-11) was current at the May 2026 baseline; as of 2026-08-21 the current stable release is Swift 6.3.3 (swift-6.3.3-RELEASE, 2026-06-29, paired with Xcode 26.6), per swift.org/install and swift.org's release index. Swift 6.4 is in development — swift-6.4.x development snapshots have been tagged since at least July 2026, and swift.org's "Embedded Swift Improvements Coming in Swift 6.4" post (2026-08-20) describes it as the upcoming release. Swift 6, the language mode introduced in Swift 6.0 (Sep 2024), made strict data-race-safety checking a compiler-enforced error class rather than a warning. Swift 6.3 (Mar 2026) added the @c C-export attribute, module-name selectors (Module::Symbol), the @specialize/@inline(always)/@export(implementation) performance trio, and an official Android SDK; Swift 6.2 (Sep 2025) added single-threaded-by-default execution (@MainActor default isolation), the @concurrent opt-in attribute, fixed-size InlineArray, the safe Span borrowed-memory type, and the new Subprocess library.

Swift is a peer language to Rust, Go, and Kotlin on the "compiled, type-safe, modern-syntax" axis, with the most differentiated story around actor-based concurrency and ARC memory management.

Swift 6 language mode (strict concurrency)

Swift 6 the release shipped in 2024; Swift 6 the language mode is opt-in per target via swift-tools-version:6.0 + swiftLanguageModes: [.v6] in Package.swift. Under Swift 6 mode:

  • Cross-actor sends require explicit Sendable conformance — non-Sendable captures are errors, not warnings.
  • nonisolated and isolated parameters give precise control over execution context.
  • @MainActor propagation rules are intentional, not inference-driven.

Quote from the Swift 6 announcement: "a new, opt-in language mode that extends Swift's safety guarantees to prevent data races in concurrent code by diagnosing potential data races in your code as compiler errors."

Typed throws (SE-0413, Swift 6.0)

enum ParseError: Error { case unexpectedToken, eof }

func parse(_ s: String) throws(ParseError) -> Int {
    guard let n = Int(s) else { throw .unexpectedToken }
    return n
}

Caller sees the specific error type — no as! cast, no Error upcast at use sites. The function-type spelling is () throws(ParseError) -> Int.

Default isolation = main actor (Swift 6.2)

Set per target in Package.swift:

.target(
    name: "MyApp",
    swiftSettings: [
        .defaultIsolation(MainActor.self)   // SE-0466
    ]
)

Every top-level function and type now defaults to @MainActor; opt out with @concurrent. Quoted from the 6.2 announcement: "Run your code on the main thread without explicit @MainActor annotations using the new option to isolate code to the main actor by default."

@concurrent and caller-context async (Swift 6.2)

@MainActor
func uiUpdate() async {
    await fetchSlow()                      // runs on MainActor — no hop
    let bytes = await compute()            // also MainActor (caller-isolated)
}

@concurrent
func compute() async -> [UInt8] { ... }    // explicitly off the main actor

Quote: "async functions [now] run in the caller's execution context, even when called on the main actor" — the "clearly indicate when code should remain serialized on an actor, versus when code may execute in parallel" design split.

Swift 6.3 highlights

@c C export attribute

@c
public func sum(_ a: Int32, _ b: Int32) -> Int32 { a + b }

Generates the matching C header automatically; pair with @implementation to provide Swift bodies for declarations in an imported C header. Embedded Swift in particular benefits — vendor RTOSes can now call Swift symbols without any wrapper.

Module-name selectors

When two imported modules both export a Task (or any symbol), disambiguate with :::

import ModuleA
import ModuleB

let x = ModuleA::getValue()   // call 'getValue' from ModuleA
let y = ModuleB::getValue()   // call 'getValue' from ModuleB

let task = Swift::Task { ... } // the standard library's Task

Performance attributes

Android, officially

swift-6.3 shipped the first official Android SDK alongside the existing macOS/Linux/Windows SDKs, with the Swift Java and Swift Java JNI Core libraries on the SwiftPM side. The earlier community Android effort folds into mainline.

DocC and SwiftPM

  • DocC now emits Markdown alongside JSON, embeds static HTML in index.html for search-engine discoverability, and supports per-code-block nocopy, highlight, showLineNumbers, wrap attributes.
  • SwiftPM gained swift package show-traits, prebuilt Swift Syntax for macros (no more per-build compilation of swift-syntax), and inherited documentation in command plugins.
  • A preview of Swift Build as a unified build engine across all platforms ships behind a feature flag.

Embedded Swift

Embedded Swift is a language subset plus a -enable-experimental-feature Embedded compilation mode targeting microcontrollers (Cortex-M, RISC-V) without an OS. It deliberately omits classes (mostly), reflection, existentials with copies, and the standard runtime — code links into a single binary, no libswiftCore. Swift 6.2 enlarged the supported subset:

  • Full String API (UTF-8, slicing, comparison).
  • any types for class-constrained protocols.
  • InlineArray (fixed-size, stack-allocated) and Span (borrowed contiguous memory, no escape).
  • Improved C interop on bare-metal targets.

Use case parity is closing with TinyGo for Go and Rust no_std, with strict concurrency intact.

Status check (verified 2026-08-21): Embedded Swift is still experimental — the official documentation at docs.swift.org/embedded states that public Swift releases do not support Embedded Swift yet and that you need a main development snapshot (swiftly install main-snapshot) to use it. Swift 6.4 will widen the subset further: generalized existential (any) types including Any, untyped throws, and full metatype support are landing in the 6.4 development snapshots.

InlineArray and Span (safe systems programming)

// Fixed-size, stack-allocated, no heap
let buffer: InlineArray<16, UInt8> = InlineArray(repeating: 0)

// Borrowed view over contiguous memory — bounds checks elided at use sites,
// lifetime checked at compile time
func sum(_ s: Span<Int32>) -> Int64 {
    var total: Int64 = 0
    for v in s { total += Int64(v) }
    return total
}

Quote from 6.2: "safe, direct access to contiguous memory" with "guarantees checked at compile time with no runtime overhead." Span participates in non-escapable lifetimes; it can't be stored in a stored property or returned without a ~Escapable declaration.

Subprocess (Swift 6.2)

import Subprocess

// swift-subprocess 1.0.0 (released 2026-08-04): `run` is a free function, and
// standardOutput is only collected when you ask for an output strategy.
let result = try await run(
    .name("git"),
    arguments: ["log", "--oneline", "-5"],
    output: .string(limit: 4096)
)
print(result.standardOutput)   // Optional(String)

Async-first; supports streaming AsyncSequence<Data>, Pipe, environment, working-directory, signal forwarding, and platform-specific posix_spawn / CreateProcess paths. Replaces ad-hoc Process invocations on Darwin and the long-standing lack of a portable equivalent on Linux/Windows.

Package Traits (6.1)

Traits let one package expose alternate API surfaces per environment. Example:

let package = Package(
    name: "MyLib",
    traits: [
        .trait(name: "Embedded", description: "Embedded-Swift-friendly mode"),
        .default(enabledTraits: [])
    ],
    targets: [ ... ]
)

In code, #if Embedded flips alternate paths. The 6.3 swift package show-traits subcommand prints the trait matrix without building.

Swift Testing

Swift Testing replaces XCTest for new code (XCTest still works). Macros over inheritance:

import Testing

@Test func parserAcceptsInteger() throws {
    let result = try parse("42")
    #expect(result == 42)
}

@Test(arguments: ["1", "2", "3"])
func acceptsDigits(s: String) throws {
    #expect(try parse(s) >= 1)
}

6.3 added Issue.record(..., severity: .warning) for non-fatal expectations, try Test.cancel() for in-test cancellation, and image attachments on macOS / Windows. 6.1 added TestScoping for custom setup/teardown traits.

Common gotchas

  • Swift 6 release ≠ Swift 6 language mode. Targets built with swift-tools-version:6.0 default to the Swift 5 language mode for backward compat; opt in explicitly via swiftLanguageModes: [.v6] or -swift-version 6. Many "Swift 6 broke my build" reports are actually Swift 5 mode under the 6.0 compiler.
  • @MainActor default isolation is per-target, not global. Enabling it on a library that exports primitives surprises downstream apps. Use it for application targets, not libraries — libraries should remain nonisolated by default.
  • @concurrent and @MainActor together compile but conflict semantically. The function will be off-main; the annotation chain becomes misleading. Pick one.
  • Typed throws are an ABI break across libraries. Adding throws(MyError) to a public function changes the function's type signature — clients must recompile. Mitigate via @available checks and throws (untyped) at API boundaries; reserve typed throws for internal modules.
  • Embedded Swift omits classes by default. Only final classes with @_objcRuntimeBase or similar attributes survive; protocols can't be used existentially with copies. If you hit "this code is unavailable in Embedded Swift", check whether your protocol witness table needs ~Copyable/~Escapable to fit.
  • Android SDK doesn't include UIKit or Foundation's FileManager.url(for:in:) on user paths. Use FileManager.default.urls(for: .documentDirectory, in: .userDomainMask); SDK ships a stripped-down FoundationEssentials.
  • InlineArray size is a static let only. It's a compile-time generic parameter — runtime-sized arrays still need Array / ContiguousArray.
  • Span cannot escape. It's a borrowed view; you cannot return it from a function that produces the underlying storage. Use MutableSpan only where mutation through the borrow is needed.
  • The _RELEASE suffix is real. Both tags and the binary distribution use swift-6.3.2-RELEASE, not 6.3.2. CI scripts parsing version strings must keep the prefix.

Authoritative sources for version state

The authoritative sources for current Swift state, in priority order:

1. swift.org/install — current stable version (6.3.3 as of 2026-08-21; the page header itself carries the number). The machine-readable form is swift.org/api/v1/install/releases.json, which gives tag, date, Xcode pairing and per-platform artifacts for every release — a working substitute when the GitHub API is unreachable.
2. api.github.com/repos/swiftlang/swift/releases — published_at for releases.
3. api.github.com/repos/swiftlang/swift/commits?sha=swift-X.Y.Z-RELEASE — for tags that haven't been promoted to GitHub Releases yet (Swift 6.3.2 hit this state mid-May 2026).
4. Swift Evolution — accepted/implemented proposals (SE-0413 typed throws, SE-0466 default isolation, SE-0427 non-copyable generics, SE-0453 InlineArray, SE-0447 Span).
5. Release blog posts at swift.org/blog/swift-X.Y-released/.
