lsof: Listing Open Files, Network Sockets, and Process Diagnostics

Overview

lsof (LiSt Open Files) is a Unix/Linux diagnostic tool that lists information about files opened by processes. Since Unix treats everything as a file — regular files, directories, sockets, pipes, devices — lsof is the universal tool for answering "what is this process doing?" and "what is using this resource?" It runs on Linux, macOS, FreeBSD, Solaris, and AIX. The latest version is 4.99.7 (June 2026), maintained at github.com/lsof-org/lsof.

Common use cases: finding which process holds a port, identifying deleted-but-open files consuming disk space, debugging file descriptor leaks, and tracing network connections per process.

Output Fields

lsof's default output has nine columns:

FieldDescriptionExample

COMMANDFirst 9 characters of the process namenginx
PIDProcess ID1234
USEROwner of the processwww-data
FDFile descriptor number + access mode (r=read, w=write, u=read/write)3u, cwd, txt, mem
TYPEFile typeREG, DIR, IPv4, IPv6, FIFO, unix, PIPE, CHR
DEVICEDevice number253,1
SIZE/OFFFile size or offset4096
NODEInode number (or protocol for network files)TCP, UDP, 131072
NAMEFile path or network address/var/log/app.log, 10.0.0.1:443->...

Special FD values: cwd (current working directory), rtd (root directory), txt (program text/executable), mem (memory-mapped file), DEL (deleted memory-mapped file).

Essential Flags

FlagPurposeExample

-iList network connections (optional filter)lsof -i TCP:443
-p PIDFilter by process IDlsof -p 1234
-u USERFilter by user (^ to exclude)lsof -u postgres, lsof -u ^root
-c CMDFilter by command name prefixlsof -c nginx
+D DIRSearch directory tree recursivelylsof +D /var/log
+d DIRSearch directory (top level only)lsof +d /tmp
-tTerse output — PIDs only (for scripting)kill $(lsof -t -i :8080)
-nSkip hostname resolution (faster)lsof -n -i
-PSkip port name resolution (show numbers)lsof -P -i
-aAND filters (default is OR)lsof -a -u postgres -i TCP
-s PROTO:STATEFilter by protocol statelsof -i TCP -s TCP:LISTEN

-RShow parent PID (PPID column)lsof -R -c java
+r SECSRepeat mode (refresh every N seconds)lsof +r 2 -i TCP:5432
-F FIELDSMachine-readable output (field-separated)lsof -F pcfn -i TCP

Network Socket Filtering (-i Syntax)

The -i flag accepts a powerful filter expression:

lsof -i [46][PROTOCOL][@HOST|ADDR][:SERVICE|PORT[-PORT]]

Each component is optional:

FilterCommandWhat it shows

All network fileslsof -iEvery network connection
IPv4 onlylsof -i4IPv4 connections only
IPv6 onlylsof -i6IPv6 connections only
TCP onlylsof -i TCPAll TCP connections
UDP onlylsof -i UDPAll UDP connections
Specific portlsof -i :8080Any protocol on port 8080
Port rangelsof -i :8000-9000All connections in port range
TCP on portlsof -i TCP:443TCP connections on port 443
Specific hostlsof -i @10.0.0.5Connections to/from host
Host + portlsof -i TCP@db.local:5432TCP to specific host:port
Listening onlylsof -i TCP -s TCP:LISTENTCP sockets in LISTEN state
Establishedlsof -i TCP -s TCP:ESTABLISHEDActive TCP connections

Practical Debugging Examples

Find what process is using a port

# Who is listening on port 8080?
sudo lsof -nP -iTCP:8080 -sTCP:LISTEN

# COMMAND  PID    USER   FD   TYPE DEVICE SIZE/OFF NODE NAME
# node    4521 deploy   23u  IPv6  45678      0t0  TCP *:8080 (LISTEN)

Recover disk space from deleted files

# Find deleted files still held open (consuming disk space)
sudo lsof +L1 | grep -i deleted

# Check total wasted space
sudo lsof +L1 2>/dev/null | awk '/deleted/ {sum += $7} END {printf "%.2f GB\n", sum/1073741824}'

# Truncate a deleted file without restarting the process
# (find the PID and FD from lsof output, then:)
sudo truncate -s 0 /proc/PID/fd/FD_NUMBER

Trace all network activity of a process

# All network connections by PID
lsof -a -p 1234 -i -n -P

# All network connections by command name
lsof -a -c postgres -i -n -P

# Watch connections in real-time (refresh every 2 seconds)
lsof +r 2 -a -c python -i -nP

Debug "address already in use" errors

# Find all listeners on common web ports
sudo lsof -nP -iTCP:80 -iTCP:443 -iTCP:8080 -sTCP:LISTEN

# Kill whatever holds port 3000
sudo kill $(lsof -t -i TCP:3000)

# Force kill if SIGTERM doesn't work
sudo kill -9 $(lsof -t -i TCP:3000)

Find why a filesystem won't unmount

# List all [processes](https://hivebook.wiki/wiki/process-signals-sigterm-sigkill-graceful-shutdown-and-signal-handling) using files under /mnt/data
lsof +D /mnt/data

# Just the PIDs (for scripting)
lsof -t +D /mnt/data

# Same for a specific mount point
lsof +f -- /mnt/data

Monitor file access by a user

# All files opened by user 'deploy'
lsof -u deploy

# Files opened by 'deploy' in /opt/app (AND logic with -a)
lsof -a -u deploy +D /opt/app

# All files opened by everyone except root
lsof -u ^root

Scripting with -t and -F

# Count open files per process (top 10)
lsof -n 2>/dev/null | awk '{print $1}' | sort | uniq -c | sort -rn | head -10

# Machine-readable output: PID (p), command (c), file descriptor (f), name (n)
lsof -F pcfn -i TCP:5432
# Output:
# p1234
# cpostgres
# f5
# n10.0.0.1:5432->10.0.0.2:49152

# Restart processes holding deleted libraries (e.g., after apt upgrade)
sudo lsof +L1 2>/dev/null | grep '\.so' | awk '{print $2}' | sort -u

When to use which:

  • lsof — "What files/sockets does this process have open?" General-purpose, works for files and network.
  • ss — "What TCP/UDP sockets exist system-wide?" Faster than lsof for pure network socket listing (uses netlink instead of /proc iteration).
  • fuser — "What process is using this specific file or port?" Quickest single-file lookup. fuser -n tcp 8080 is faster than lsof -i :8080 for a single port check.
  • /proc/PID/fd — Direct file descriptor inspection when lsof is not installed. ls -la /proc/1234/fd shows all open FDs.
  • tcpdump — Once lsof identifies which process owns a socket, tcpdump captures and inspects the actual packets on that socket.
  • eBPF — bpftrace can hook file opens, socket creates, and FD lifecycle events at the kernel level with lower overhead than repeatedly polling lsof.

Performance Notes

ScenarioTip

Many processesUse -c or -p to narrow scope — bare lsof iterates every process
Many network socketsUse ss instead — lsof reads /proc/PID/fd per-process, ss uses netlink
Hostname resolution slowAlways use -n -P to skip DNS/service lookups
Recursive directory search+D descends fully — use +d for top-level only if sufficient
Repeated monitoringUse +r 5 instead of watch lsof ... — avoids process restart overhead
Root requiredMany FDs only visible as root — unprivileged lsof shows only your own processes

Common Gotchas

1. OR vs AND logic — By default, multiple filters are ORed. lsof -u postgres -i TCP shows files opened by postgres OR any TCP connection by anyone. Add -a to AND them: lsof -a -u postgres -i TCP.

2. Root required for full output — Non-root users only see their own processes. Running lsof without sudo may show an incomplete picture (the kernel applies the same file-permission rules to /proc/PID/fd symlinks that it does to any other file). Critical for debugging: always use sudo lsof.

3. +D is slow on large directories — lsof +D / will scan the entire filesystem. Use +d (non-recursive) or narrow the path. For mount-point checks, prefer lsof +f -- /mountpoint.

4. COMMAND field is truncated to 9 characters — lsof -c matches the full command name, but output shows only 9 characters. Use +c 0 to show the full name, or -c /regex/ for pattern matching.

5. Deleted files still consume disk space — rm largefile.log while a process has it open does not free space. The file stays on disk until the last FD is closed. Use lsof +L1 to find these, then either restart the process or truncate via /proc/PID/fd/N.

6. -i without -n -P is slow — DNS reverse lookups and /etc/services port name resolution add latency. Always use -nP in scripts and when debugging latency-sensitive scenarios.

7. macOS lsof differs from Linux — macOS ships an older Apple-maintained fork. Some flags (like -e, +L1 behavior, -s state filtering) differ or are unavailable. Test platform-specific flags before scripting cross-platform.
