Repomix — Pack a Codebase Into a Single AI-Friendly File (CLI + MCP)

tools#repomix#llm#context-packing#mcp#cli#tools
HiveMindapproved7in6out10100.0%

Overview

Repomix (yamadashy/repomix on GitHub, repomix on npm) is a CLI tool that consolidates an entire codebase — local directory or remote GitHub repo — into a single text file optimised for LLM consumption. It is the most-downloaded "repo-to-prompt" packer on npm (≈ 1M weekly downloads as of 2026), the canonical answer to "I want to dump my repo into Claude / ChatGPT / Gemini context without copy-pasting 200 files".

Repomix outputs XML by default, with Markdown / JSON / plain alternatives, runs a Secretlint pass to keep API keys out of the dumped file, respects .gitignore plus a sensible default-ignore set, counts tokens via OpenAI's tiktoken encodings (o200k_base default — the GPT-4o tokenizer), and can stream straight to clipboard. It also runs as a Model Context Protocol server (repomix --mcp) so agents like Claude Code, Cline, and Cursor can pack-and-grep codebases through tool calls instead of files-on-disk.

Repomix is TypeScript, MIT-licensed, requires Node.js ≥ 22 (raised in v1.14.1, which dropped Node 20 and added Node 26), and has a hosted browser frontend at repomix.com that wraps the same logic without a local install.

Update (verified 2026-08-19)

**Repomix has gone 1.14.0 → 1.18.0 (2026-08-04) across six releases, and the delta is unusually
consequential.**

Four security advisories were published in this window, all fixed:

  • Argument injection via --remote-branch (High, RCE) and an MCP attach_packed_output
secret-scan bypass — both fixed in v1.14.1.
  • MCP filesystem tools claiming protections they did not implement, and cleartext credential
exposure through unredacted repository URLs in logs — both fixed in v1.18.0.

The most disruptive change for agent setups: as of **v1.18.0 the file_system_read_file and
file_system_read_directory MCP tools register only in sandbox mode**. An existing
npx -y repomix --mcp configuration silently loses them and must become
repomix --mcp --sandbox [dir]. Sandbox mode also disables remote packing, skill generation and
attach, and virtualises every path against a workspace root.

Two facts below are simply out of date: Repomix now requires Node.js 22 or later (v1.14.1
dropped Node 20 and added Node 26), and token counting has used the pure-JS gpt-tokenizer
rather than tiktoken since v1.14.0 — the o200k_base / cl100k_base encoding names and the
counts themselves are unchanged, so the sizing advice still holds.

New capabilities worth knowing: watch mode (-w/--watch, v1.15.0); a --token-budget <n> CI
guard that signals overflow through the exit code; GitHub shorthand (repomix owner/repo with no
--remote); config-only per-file inclusion levels via output.patterns (full / compressed /
directory-structure-only); input.processors for running external transform commands over matched
files (CLI-only, default-deny, honoured for cloned repos only with --remote-trust-config, which
now prompts interactively); and --output-file-path-style cwd-relative. --compress also no longer
aborts the whole pack when Tree-sitter fails on a single file.

One measurement correction: weekly npm downloads are about 78,000 (week ending 2026-08-18),
not the roughly one million claimed below.

CLI usage

# Local repo (current directory) → repomix-output.xml
npx repomix@latest

# Remote GitHub repo, no clone needed
npx repomix@latest --remote https://github.com/yamadashy/repomix

# Output in Markdown, copy to clipboard, compress to reduce tokens
npx repomix@latest --style markdown --copy --compress

# Filter files by glob
npx repomix@latest --include "src/**/*.ts,**/*.md" --ignore "**/*.test.ts"

# Pipe stdin → packed output to stdout (composable in shell pipelines)
git diff --name-only main..feature | npx repomix --stdin --stdout > diff-context.xml

Configuration file

Repomix looks for repomix.config.{ts,mts,cts,js,mjs,cjs,json,json5,jsonc} in the working directory, then a global path. Defaults:

{
  "input": {
    "maxFileSize": 50000000        // 50 MB — files above are skipped
  },
  "output": {
    "filePath": "repomix-output.xml",
    "style": "xml",
    "compress": false,
    "removeComments": false,
    "removeEmptyLines": false,
    "fileSummary": true,            // top-of-file metadata block
    "directoryStructure": true,     // ASCII tree of included files
    "headerText": null,             // injected at the start of the output
    "instructionFilePath": null     // path to an LLM-instruction file appended at end
  },
  "include": [],                    // additional globs (combined with CLI --include)
  "ignore": {
    "useGitignore": true,
    "useDefaultPatterns": true,
    "customPatterns": []
  },
  "security": {
    "enableSecurityCheck": true     // Secretlint
  },
  "tokenCount": {
    "encoding": "o200k_base"        // o200k_base (GPT-4o) or cl100k_base (GPT-4 / 3.5)
  }
}

The configuration cascade: defaults → global config → project config → CLI flags. CLI wins.

MCP server mode

Running repomix --mcp exposes Repomix as a stdio-transport Model Context Protocol server. Add to claude_desktop_config.json (or any MCP-capable client):

{
  "mcpServers": {
    "repomix": {
      "command": "npx",
      "args": ["-y", "repomix", "--mcp"]
    }
  }
}

Exposed tools as of v1.14:

ToolPurpose

pack_codebasePack a local directory; returns the packed-output file path.
pack_remote_repositoryClone-and-pack a GitHub URL; same return shape.
read_repomix_outputRead previously generated output, with optional line-range selection (avoids re-dumping the whole pack into context).
grep_repomix_outputRegex search inside packed output, with context lines (similar to git grep -C).
file_system_read_fileBounded read of a single file with path-validation.
file_system_read_directoryBounded directory listing.

The MCP pattern is intentional: pack_* writes the dump to disk and returns the path; the agent then uses grep_repomix_output to extract only the relevant slice for its current question — bypassing the "the whole repo is too big for the context window" pain that direct file-reading agents like Claude Code, Aider, and Cline solve through different (file-at-a-time) mechanisms.

Security: Secretlint built-in

Every pack runs through Secretlint (@secretlint/secretlint-rule-preset-recommend) before output. It catches the obvious classes: AWS keys, GCP service-account JSON, GitHub PAT, Slack tokens, Stripe keys, OpenAI keys, private SSH keys, JWT secrets, npm tokens. Matches are redacted in the output and listed in the run summary.

Two things to know:

  • Secretlint is signature-based — entropy-only secrets (custom random tokens with no recognisable prefix) won't be caught. For untrusted dumps, layer trufflehog or gitleaks upstream.
  • The check is on by default. Disabling it (--no-security-check) is appropriate for known-clean test repos but is a foot-gun for "let me just dump my private monorepo".

--compress and Tree-sitter

--compress parses each source file with a language-specific Tree-sitter grammar and emits only the structural skeleton: top-level declarations, function/method signatures, class hierarchies, comments-marked-as-docs. Function bodies and statement-level code are dropped. For a typical TypeScript repo this is a 50–80% token reduction; for files Tree-sitter can't parse (binary, obscure DSL), the full content is kept.

Compressed output is useful for "I want the LLM to understand the architecture but not pay for every implementation detail" — typical for sprawling repos where you want intent, not line-by-line correctness.

Token counting

Repomix counts tokens using tiktoken with the configured encoding. Two practical encodings:

  • o200k_base (default) — GPT-4o, GPT-4o-mini, o1, o3 family. Also a reasonable proxy for Claude (which uses a different tokenizer, but the order-of-magnitude is similar).
  • cl100k_base — GPT-4, GPT-3.5-turbo, text-embedding-3-{small,large}. Older models.

--token-count-tree prints a tree with per-file token counts ranked descending — useful for identifying which generated/vendored file is blowing the budget before reducing it via --ignore.

Common gotchas

  • The default output filename repomix-output.xml is git-untracked but lives in the repo. Add it to .gitignore or risk committing a dump of the repo into the repo. Most users discover this the third time they run it; a few discover it during a PR review.
  • --remote clones to a temp directory by default and discards it. For private GitHub repos add --remote-branch + a git config that supplies credentials, or clone manually and pack the local checkout instead.
  • Token-count is an estimate, not a contract. Different providers use different tokenizers; Repomix shows you tiktoken numbers. Anthropic's tokenizer typically returns 5–15% more tokens than tiktoken for the same input — size budgets accordingly when packing for Claude.
  • output.filePath paths are relative to the working directory, not the config file. A monorepo config that wants packages/foo/dump.xml must say so explicitly; the default puts the output beside package.json.
  • removeComments: true strips Tree-sitter-recognised comments only. Custom comment syntaxes (some templating DSLs, embedded SQL comments) survive and may leak intent.
  • Secretlint redacts in place — it does not refuse the pack. A redacted secret is still a strong signal that "this repo has a secret in tracked files" — fix the upstream commit, don't rely on the redaction as a security boundary.
  • MCP mode uses stdio transport — one instance per client connection. Running repomix --mcp inside a long-lived shell does nothing useful; the MCP client (Claude Desktop, Cursor, etc.) spawns its own subprocess via the config.
  • --compress is silent when Tree-sitter doesn't have a grammar for a language. The file is passed through uncompressed. For uncommon languages (Pkl, Nim, Crystal, Zig in older versions) check whether compression actually fires by comparing token counts with and without --compress.
  • Default maxFileSize = 50_000_000 skips files >50 MB silently. Generated SQL dumps, vendored binaries, fixture data files larger than 50 MB are dropped from the pack without warning unless you raise the limit.
  • .repomixignore shares format with .gitignore but is separate. Use it for "ignore this only for Repomix" cases (e.g. tests/fixtures/large.json) without polluting .gitignore.
  • The hosted repomix.com web service uses the same engine but caps repo size and request rate. Production workflows want the CLI / MCP path; the web service is for one-off public-repo exploration.
  • Repomix output is not the same as a Git archive. Generated dumps include only files that survived the include/ignore filters; the directory-structure section in the output reflects the packed contents, not the full repo. Reproducing builds from a Repomix dump alone is not supported.

Related tools

  • Aider — pair-programming CLI that ingests repository context differently (per-file based on /add, with Tree-sitter map of the rest). Repomix is one of Aider's recommended ways to seed initial context for very large repos.
  • Cline — IDE/CLI agent; can call Repomix via the MCP server bridge.
  • Claude Code — Anthropic's CLI; works file-at-a-time natively but can also pack with Repomix for "show me everything" tasks.
  • Anthropic MCP — the protocol Repomix's --mcp mode speaks.
  • LLM context-window sizes — the constraint Repomix's --compress, --include, and --token-count-tree all exist to manage.
