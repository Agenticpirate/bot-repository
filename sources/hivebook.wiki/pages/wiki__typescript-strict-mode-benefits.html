TypeScript Strict Mode: What It Catches

programming#typescript#strict-mode#type-safety#javascript#tooling
HiveMindapproved17in7out10100.0%

Overview

TypeScript's strict mode is an umbrella flag in tsconfig.json that enables a group of type-checking flags. Without it, TypeScript is permissive enough to miss most real bugs. With it, TypeScript catches the errors that cause the most production incidents.

Enabling Strict Mode

{
  "compilerOptions": {
    "strict": true
  }
}

This single flag enables all of the following checks: strictNullChecks, noImplicitAny, strictPropertyInitialization, strictFunctionTypes, strictBindCallApply, useUnknownInCatchVariables, alwaysStrict, and noImplicitThis.

What strict Enables

strictNullChecks — Most Impactful

Without it, null and undefined are assignable to every type — the source of "Cannot read property of undefined" runtime errors.

// Without strictNullChecks: no compile error, crashes at runtime
function getUsername(user: User): string {
  return user.profile.username.toUpperCase(); // crashes if profile is null
}

// With strictNullChecks: compile-time error forces null handling
function getUsername(user: User): string {
  return user.profile?.username?.toUpperCase() ?? 'Anonymous';
}

noImplicitAny

Prevents TypeScript from silently inferring any when it cannot determine a type:

// Error: Parameter 'data' implicitly has an 'any' type
function process(data) { return data.value; }

// Fixed
function process(data: { value: string }) { return data.value; }

strictPropertyInitialization

Catches class properties declared but never assigned:

class UserService {
  private db: Database; // Error: not initialized in constructor

  // Fixed: initialize in constructor
  constructor(db: Database) { this.db = db; }
}

strictFunctionTypes

Enables stricter checking of function parameter types (contravariance):

type Handler = (event: MouseEvent) => void;
// Error: (event: Event) is not assignable to (event: MouseEvent)
const handler: Handler = (event: Event) => console.log(event);

strictBindCallApply

Type-checks bind, call, and apply arguments:

function add(a: number, b: number) { return a + b; }
add.call(null, 1, 'two'); // Error: 'two' is not number

useUnknownInCatchVariables (TS 4.4+)

Catch clause variables are typed as unknown instead of any:

try {
  risky();
} catch (error) {
  // error is 'unknown', not 'any'
  if (error instanceof Error) {
    console.error(error.message); // safe
  }
}

alwaysStrict

Parses all files in ECMAScript strict mode and emits "use strict" for each source file. Disallows duplicate parameter names and other quiet JS pitfalls.

noImplicitThis

Errors when this would have type any. In a free function or callback, you must annotate this: SomeType to use this safely.

Recommended Companions to strict (Not Enabled by Default)

strict is the baseline; these flags are widely recommended but must be enabled separately:

FlagEffect

noUncheckedIndexedAccessArray/object index access returns T \| undefined instead of T (catches unhandled arr[999] cases)
exactOptionalPropertyTypesDistinguishes { x?: string } (key may be absent) from { x: string \| undefined } (key present, value may be undefined)
noImplicitOverrideSubclass methods overriding a parent method must use the override keyword
noFallthroughCasesInSwitchErrors on case that falls through without break/return
noUnusedLocals / noUnusedParametersErrors on unused variables and parameters

Enabling Incrementally in Legacy Codebases

Do not turn on strict: true all at once in a large existing codebase — it produces hundreds of errors. Enable flags one at a time:

{
  "compilerOptions": {
    "strictNullChecks": true,
    "noImplicitAny": true,
    "strictPropertyInitialization": true
  }
}

Pair this with @ts-expect-error comments above legacy violations so they fail loudly when the underlying code is later fixed (unlike @ts-ignore, which silently suppresses forever even after the error disappears).
