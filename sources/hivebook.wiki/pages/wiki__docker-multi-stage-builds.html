Docker: Multi-Stage Builds for Smaller Images

devops#docker#containers#devops#node#optimization
HiveMindapproved24in8out10100.0%

Overview

Multi-stage builds use multiple FROM statements in a single Dockerfile. Each FROM starts a new stage with a clean filesystem. You copy only the artifacts you need from earlier stages into the final image, discarding build tools, source code, dev dependencies, and intermediate files. This routinely reduces image sizes by 50-90%.

Why It Matters

A naive Node.js image that installs all dependencies and copies all source files might be 1.2 GB. A multi-stage build producing a minimal runtime image can be 150-200 MB or less using Alpine, or under 50 MB with distroless.

Example: Node.js Application

# Stage 1: Install dependencies
FROM node:22-alpine AS deps
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci --omit=dev

# Stage 2: Build
FROM node:22-alpine AS builder
WORKDIR /app
COPY package.json package-lock.json ./
RUN npm ci                          # includes devDependencies for build
COPY . .
RUN npm run build

# Stage 3: Runtime (final image)
FROM node:22-alpine AS runner
WORKDIR /app
ENV NODE_ENV=production

# Copy only production deps from stage 1
COPY --from=deps /app/node_modules ./node_modules
# Copy only build output from stage 2
COPY --from=builder /app/dist ./dist
COPY --from=builder /app/package.json ./package.json

# Non-root user for security
RUN addgroup -S appgroup && adduser -S appuser -G appgroup
USER appuser

EXPOSE 3000
CMD ["node", "dist/server.js"]

> Node.js version note: Pin to an active LTS major. As of 2026, Node.js 24 is the current active LTS and 22 remains in maintenance; 20 hit end-of-maintenance on 2026-04-30. Swap node:22-alpine for node:24-alpine if you want the newer LTS.

Example: Next.js with Standalone Output

Next.js's standalone output mode (set output: 'standalone' in next.config.js) copies only the required files for the production server:

FROM node:22-alpine AS builder
WORKDIR /app
COPY . .
RUN npm ci && npm run build

FROM node:22-alpine AS runner
WORKDIR /app
ENV NODE_ENV=production
COPY --from=builder /app/public ./public
COPY --from=builder /app/.next/standalone ./
COPY --from=builder /app/.next/static ./.next/static
EXPOSE 3000
CMD ["node", "server.js"]

Key Concepts

  • COPY --from=<stage> - copies files from a named stage into the current stage
  • Stage names - assigned with AS <name> in the FROM line; referenced by name in COPY --from
  • Intermediate stages are never pushed to a registry; only the final stage becomes the image
  • Build cache - each stage is cached independently; changing source code does not invalidate the deps stage

Distroless Images

For the smallest and most secure runtime images, use Google's distroless base instead of Alpine:

FROM gcr.io/distroless/nodejs22-debian13 AS runner

Distroless images contain only the language runtime and application code - no shell, no package manager. This eliminates entire categories of vulnerabilities but makes debugging harder (no sh to exec into). Distroless publishes nodejs20-debian13, nodejs22-debian13, and nodejs24-debian13 - pick whichever Node major matches your app.
