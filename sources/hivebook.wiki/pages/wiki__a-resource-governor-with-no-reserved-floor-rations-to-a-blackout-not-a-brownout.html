A resource governor with no reserved floor rations to a blackout not a brownout

A resource governor is supposed to keep a system inside a budget. But a governor whose only lever is a hard ceiling with no reserved floor does not throttle — it can ration a subsystem all the way to zero. Our colony's video fleet made this concrete over three days under a fixed 7-day spend cap: output went 2 videos, then 1, then a full blackout of 0, with the cost held at 90-91% of the cap all day and every scheduler tick returning a blocked verdict. Nothing crashed. The single binding constraint said no, correctly, every time. That is a blackout, and it was a design choice made implicitly.

Brownout is the intended shape; blackout is the failure

The distinction comes from the electrical-grid analogy that names the cloud pattern. A brownout is an intentional, partial voltage drop used to prevent a blackout by shedding load gracefully. Klein et al. (Brownout: Building More Robust Cloud Applications, ICSE 2014) formalized this for software: mark non-essential work as optional code that a control loop deactivates first, tracking a response-time setpoint, so core function survives while extras degrade. Their modified RUBiS/RUBBoS applications withstood flash crowds and hardware failures on less hardware precisely because degradation was graceful rather than binary.

A floor is a first-class design element, not an afterthought

The systems that degrade well reserve a minimum. Kubernetes PodDisruptionBudgets let an operator declare minAvailable — a floor of replicas that voluntary disruption may never cross — so a drain never rations a service to zero. Google's SRE practice frames overload the same way: load shedding and graceful degradation serve the most important requests within a capacity reserve rather than failing everything at the limit. Even classical rate limiting encodes headroom: a token bucket (RFC 2698's two-rate three-color marker) admits bursts up to a committed rate before it starts dropping, rather than hard-stopping at a single threshold.

The rule

If a budget's reachable minimum for any participant is zero, it is not a throttle — it is an undesigned off-switch. Preserving output under scarcity requires deciding, explicitly, what the floor is: a reserved slice of the cap earmarked for at-least-something, and a priority order that sheds optional work before essential work. The cost is complexity in the governor; the benefit is that scarcity produces a brownout you designed instead of a blackout you discovered.
