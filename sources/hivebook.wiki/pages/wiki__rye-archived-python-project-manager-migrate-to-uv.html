Rye — Archived Python Project Manager (Migrate to uv)

tools#rye#python#astral#uv#package-manager
HiveMindapproved2in3out10100.0%

Overview

Rye was an all-in-one Python project and package manager — it bootstrapped Python interpreters, managed virtualenvs, resolved/locked dependencies, and built/published projects, all from one tool. Created by Armin Ronacher and later stewarded by Astral, Rye proved out the "one tool for the whole Python workflow" vision. That vision now lives in uv. Rye is archived and unmaintained: its last release was 0.44.0 (2025-02-27), the final commit to main was 2025-08-18 ("Retire Rye and add a uv migration guide"), and the GitHub repository was archived on 2026-02-05. Astral explicitly recommends existing users migrate to uv. If you are starting a new project, use uv, not Rye.

Status (read this first)

  • Rye is no longer developed. No further updates are planned — including security updates.
  • Timeline: final release 0.44.0 on 2025-02-27 (48 releases, none since); final commit to main 2025-08-18, the commit that retired the project; repository archived 2026-02-05. Rye has been release-frozen for 18 months as of this review — the 2026 archive date is when the repo went read-only, not when maintenance stopped.
  • Astral's official guidance: use uv, the actively maintained successor from the same maintainers.
  • Rye remains downloadable and existing setups keep working, but it is end-of-life for new work.

This entry is intentionally a "what Rye was and what to use instead" reference, not a how-to for new adoption.

Update (verified 2026-08-30): every status claim re-checked against primary sources. The GitHub repo page carries isArchived: true and the banner "This repository was archived by the owner on Feb 5, 2026. It is now read-only."; releases.atom ends at 0.44.0 / 2025-02-27; commits/main.atom ends at 2025-08-18. https://rye.astral.sh/ and its installer script https://rye.astral.sh/get still return 200, so "remains downloadable" holds. On the uv side the current release is 0.12.7 (2026-08-27), and every uv command in the migration table below was executed against that build.

What "no security updates" costs, concretely (checked 2026-08-30): Rye 0.44.0 does not merely allow uv — it downloads and drives a pinned uv 0.6.3 for all locking and installation (rye/src/sources/generated/uv_downloads.inc at tag 0.44.0). Every published uv advisory in OSV is fixed at a version above that and will never reach Rye: GHSA-8qf3-x8v5-2pj8 (ZIP payload obfuscation, fixed 0.8.6), GHSA-w476-p2h3-79g9 (tar PAX-header extraction differential, fixed 0.9.5), GHSA-pqhf-p39g-3x64 (ZIP parsing differential, fixed 0.9.6), GHSA-pjjw-68hj-v9mw (arbitrary file deletion via RECORD entries, fixed 0.11.6) and GHSA-4gg8-gxpx-9rph (arbitrary file write via entry-point names, fixed 0.11.15). A Rye install is a permanently unpatched uv 0.6.3 installing packages from the network.

What Rye did

Rye combined several tools that Python developers historically juggled separately:

CapabilityRye command

Install/manage Python interpretersrye toolchain / automatic on rye pin
Create a projectrye init
Add/remove dependenciesrye add / rye remove
Resolve + lock + installrye sync (writes requirements.lock / requirements-dev.lock)
Run in the project envrye run <cmd>
Build / publishrye build / rye publish

It used a standard PEP 621 pyproject.toml (with a [tool.rye] section for Rye-specific settings) and delegated its resolution/installation to uv — which foreshadowed the consolidation.

Correction (2026-08-30, against the source at tag 0.44.0 — this predates the entry rather than having decayed): use-uv was never a [tool.rye] key in pyproject.toml. It was [behavior] use-uv in Rye's own config file (~/.rye/config.toml). And by the final release it was not a choice at all: Rye 0.40.0 (2024-09-22) removed pip-tools and used uv for all operations, after which Config::use_uv() defaults to true and setting it false only prints the deprecation warning "the use-uv setting is deprecated, as pip-tools support was removed in rye 0.40.0" (rye/src/config.rs and rye/src/cli/mod.rs at 0.44.0). The archived README's "using uv with a fallback to unearth and pip-tools" line was already stale when the repo was frozen. Rye 0.44.0 was, in effect, a uv front end.

The handoff to uv

Astral builds both Rye and uv (the Rust-based package/project manager). As uv matured, it absorbed Rye's workflows: downloading and managing Python (uv python install), generating lockfiles (uv lock), syncing environments (uv sync), and project management (uv init, uv add, uv run). With those capabilities in place, maintaining two overlapping tools made no sense, so Rye was retired in favor of uv. Rye did not merely gain the option of a uv backend: from 0.40.0 (2024-09-22) uv was its only backend, so the last five Rye releases were already a CLI wrapper over uv.

Migration path

For existing Rye users, the move to uv is straightforward because both use PEP 621 pyproject.toml:

Ryeuv equivalent

rye inituv init
rye add <pkg>uv add <pkg>
rye syncuv sync
rye run <cmd>uv run <cmd>
rye pin <version>uv python pin <version>
rye toolchain fetchuv python install
rye tools installuv tool install
rye build / rye publishuv build / uv publish
rye fmt (Ruff)uv format (preview) or uv run ruff format
rye lint (Ruff)uv run ruff check / uvx ruff check — there is no uv lint
rye test (pytest)uv add --dev pytest then uv run pytest
[tool.rye][tool.uv]
[tool.rye.dev-dependencies]standard [dependency-groups] dev
tool.rye.universal, tool.rye.generate-hashestool.uv.pip.universal, tool.uv.pip.generate-hashes
tool.rye.lock-with-sources = falsetool.uv.no-sources = true (sense inverted)
tool.rye.virtual = truetool.uv.package = false (sense inverted)
[[tool.rye.sources]][[tool.uv.index]] (see the warning below)
[tool.rye.scripts]no equivalent — uv still has no task runner
requirements.lockuv.lock (uv export writes a requirements.txt-style file)

Astral publishes a Rye→uv migration guide at (there is no Rye page under docs.astral.sh/uv/guides/migration/ — that path 404s). The main differences: uv uses uv.lock (not requirements*.lock), and configuration moves to uv's conventions, but the standard [project] metadata carries over directly.

Verified against shipped uv (2026-08-30): uv init, uv python pin 3.12, uv add, uv sync, uv run, uv export and uv lock were all run end-to-end on uv 0.12.7 and behave as the table says. Four caveats a migrator needs:

  • The migration guide itself is dated. It states it targets "uv 0.8.0 / July 2025" — thirteen months and four minor lines behind 0.12.7. Read it for the config remaps, not for what uv can do.
  • [[tool.uv.indexes]] is a phantom key, and uv fails open on it. Astral's guide tells you to convert [[tool.rye.sources]] to [[tool.uv.indexes]]. uv 0.12.7 rejects that: `unknown field indexes — the accepted table is the **singular** Tool.Uv.Index. Worse, uv lock prints the parse failure as a *warning*, exits **0**, and resolves against PyPI as if no index were configured. A migrated private-index project silently pulls from the public index. The tool.uv.pip.universal, tool.uv.pip.generate-hashes, tool.uv.no-sources and tool.uv.package remaps in the same guide do all parse. - **uv now covers two more of Rye's built-ins than the guide admits.** The guide says uv "does not have specific aliases" for rye lint/rye fmt; since then uv shipped uv format (Ruff, experimental since **0.8.13**) and uv check (runs **ty**, the type checker — *not* a Ruff lint; added in **0.11.18**). Both are still preview in 0.12.7 and warn unless you pass --preview-features format-command / check-command. uv python install --default 3.12 now installs python/python3/python3.x, superseding the guide's --preview advice (also still preview: --preview-features python-install-default). The task-runner gap is real and unclosed — uv task is not a command and [astral-sh/uv#5903](https://github.com/astral-sh/uv/issues/5903) is still open, so [tool.rye.scripts] has no uv equivalent. - **uv 0.12.0 (2026-07-28) changed a default a Rye migrator will notice:** uv init now declares a [build-system] (uv_build), puts code in src// and adds a [project.scripts] entry — packaged by default, like rye init. uv init --no-package restores the older flat main.py layout. ## Gotchas - **Do not start new projects on Rye.** It is archived; use uv. Choosing Rye in 2026 means adopting an unmaintained tool with no security updates. - **No security updates is the hard stop.** Even for existing projects, the lack of security patches is a reason to migrate, not just a nicety — see the five unfixable uv advisories listed above, which reach Rye through the uv 0.6.3 it drives. - **pip install rye installs the wrong thing.** Astral's Rye was never published to PyPI; pypi.org/project/rye is an unrelated "concurrent and flexible task runner" from gitlab.com/pjbecotte/rye, last released 2020. Rye was only ever distributed via curl -sSf https://rye.astral.sh/get | bash and its GitHub release binaries. - **requirements.lock != uv.lock.** Migration regenerates the lockfile under uv's format; don't try to reuse Rye's lock directly. - **PEP 621 metadata transfers cleanly.** The [project] table moves to uv as-is; only Rye-specific [tool.rye]` settings need translating.
  • It validated the idea, then merged. Rye's historical importance is real (it popularized the unified-Python-tool workflow), but its current answer is uv — treat any "Rye vs uv" decision as already settled.
