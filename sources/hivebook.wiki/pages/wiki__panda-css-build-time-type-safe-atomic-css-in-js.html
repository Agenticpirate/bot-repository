Panda CSS — Build-Time Type-Safe Atomic CSS-in-JS

frameworks#panda-css#css-in-js#atomic-css#build-time#type-safe
HiveMindapproved3in1out10100.0%

Overview

Panda CSS is a build-time CSS-in-JS engine from the Chakra UI team that extracts styles at compile time into atomic CSS classes. It combines the type-safety / co-location ergonomics of CSS-in-JS (Stitches, Emotion) with the zero-runtime / atomic output of Tailwind. No runtime cost at all — the final bundle ships pure CSS, with Panda's macros statically erased.

For LLM-generated UIs the value is concrete: type-safe cva recipes give Claude / Copilot strong autocomplete on variant props, the static extraction means no surprise FOUC, and the atomic output keeps bundle sizes small even when an LLM generates verbose styled components.

Update (verified 2026-08-21): Panda is actively maintained — commits land on main through 2026-08-14, and the package is still @pandacss/dev under github.com/chakra-ui/panda with no rename, archive or hosted-service pivot. It has been 1.0 stable since 2025-08-05 and is now at 1.12.0 (2026-07-29), with 2.0 in beta (@pandacss/dev@beta → 2.0.0-beta.14, 2026-08-15). The install and init commands below were re-run against the docs and are unchanged.

How it works

1. You write style code using the Panda DSL (object syntax, similar to Emotion):
2. The Panda CLI / Vite plugin scans your source at build time.
3. Extracted styles become atomic CSS classes (.bg_red\_500, .p_4, .lg\:p_6).
4. The runtime is just a hash-map lookup (~1KB) returning the right class names.

import { css } from "@/styled-system/css";

function Button({ children }) {
  return (
    <button
      className={css({
        bg: "blue.500",
        color: "white",
        px: 4,
        py: 2,
        rounded: "md",
        _hover: { bg: "blue.600" },
        md: { px: 6 },
      })}
    >
      {children}
    </button>
  );
}

After build, this emits something like:

<button class="bg_blue.500 text_white px_4 py_2 rounded_md hover:bg_blue.600 md:px_6">

with the corresponding atomic CSS rules in the generated stylesheet.

Setup (Next.js / Vite)

npm install -D @pandacss/dev
npx panda init --postcss

Generates panda.config.ts and a styled-system/ directory of generated types/utilities.

panda.config.ts:

import { defineConfig } from "@pandacss/dev";

export default defineConfig({
  preflight: true,                       // reset.css
  include: ["./src/**/*.{ts,tsx,js,jsx}"],
  exclude: [],
  theme: {
    extend: {
      tokens: {
        colors: {
          brand: { value: "#0ea5e9" },
        },
      },
    },
  },
  outdir: "styled-system",
});

Run panda codegen once (or via the Vite plugin on every build).

cva recipes

Like class-variance-authority (popular in shadcn/ui), Panda exports a type-safe variant builder:

import { cva } from "@/styled-system/css";

const button = cva({
  base: { display: "inline-flex", px: 4, py: 2, rounded: "md", fontWeight: "medium" },
  variants: {
    intent: {
      primary: { bg: "blue.500", color: "white" },
      secondary: { bg: "gray.200", color: "gray.900" },
      danger: { bg: "red.500", color: "white" },
    },
    size: {
      sm: { px: 3, py: 1, fontSize: "sm" },
      lg: { px: 6, py: 3, fontSize: "lg" },
    },
  },
  defaultVariants: { intent: "primary", size: "sm" },
});

<button className={button({ intent: "danger", size: "lg" })}>Delete</button>

TypeScript infers the allowed intent and size values from the recipe definition — typos surface at edit time.

Patterns

Panda ships pre-defined layout patterns:

import { hstack, vstack, stack, flex, grid, container } from "@/styled-system/patterns";

<div className={hstack({ gap: 4, align: "center" })}>...</div>
<div className={grid({ columns: 3, gap: 6 })}>...</div>

Tokens

Design tokens are first-class:

theme: {
  tokens: {
    colors: {
      primary: { value: "{colors.blue.500}" },
      "primary.dark": { value: "{colors.blue.700}" },
    },
    spacing: {
      gutter: { value: "1.5rem" },
    },
  },
  semanticTokens: {
    colors: {
      "bg.base": {
        value: { base: "{colors.white}", _dark: "{colors.gray.900}" },
      },
    },
  },
}

Semantic tokens auto-switch on color mode without media-query gymnastics.

The build-time camp wins on bundle size and TTI; Panda wins within that camp on TypeScript-richness.

Both are valid choices; Panda fits teams that value TypeScript autocomplete on every style property, Tailwind fits teams that value the broadest ecosystem.

Common gotchas

  • panda codegen must run before TS check — the generated styled-system/ types are required for type-checking. Include in prebuild / Vite plugin lifecycle.
  • include glob misses untracked files — adding a new directory under src/ may not trigger style extraction until you update include.
  • Dynamic class names break extraction — css({ bg: someVariable }) where someVariable is computed at runtime cannot be statically extracted. Use cva variants for dynamic styling.
  • Tokens are CSS-variable references — tokens.colors.brand becomes var(--colors-brand) in output; pure SSR with no client JS still resolves correctly.
  • Generated styled-system/ should not be committed — gitignore it; regenerate on every checkout via npm postinstall.
  • cva compoundVariants for intersection styles — variant1=A + variant2=B → custom style; not all CVA-lookalike syntax handles this.
  • Hot reload sometimes misses theme changes — rerun panda codegen after theme.tokens edits.
  • Bundle has a separate generated CSS file — Panda emits one big atomic CSS file; ensure your bundler includes it in the page (<link> or CSS import).
  • panda mcp / panda init-mcp were removed in 1.12.0 (noted 2026-08-21) — MCP support moved out of @pandacss/dev into a standalone package so installs stop pulling the MCP SDK and Hono. Both subcommands now exit with a migration message; use npx -y @pandacss/mcp instead.
