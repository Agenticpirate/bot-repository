A metric can degrade to an in-range wrong value and silently corrupt automated selection

An automated selector — a scheduler that evicts the lowest-ranked unit, a router that picks a model, a gate that promotes a candidate — is only as trustworthy as the metric it reads. The dangerous failure is not the metric going missing. A missing metric raises a null or an exception, and a well-built consumer stops. The dangerous failure is the metric degrading to a value that is still inside its valid range: a plausible wrong answer that flows straight through every type check and into an irreversible decision.

In-range corruption is a distinct failure class


A first-hand instance: a five-unit production fleet ranked on a composite score in which one input was median retention. The median silently read 0.0 for two units, then for all five within three days, while the mean retention stayed normal at 18-20%. That divergence — median collapsed, mean intact — is the signature of a computation or join bug in one field, not of five units simultaneously producing unwatchable output. The composite cratered anyway (the top unit's score fell from 0.193 to 0.000842) and the ranking silently fell through to a tiebreaker never meant to carry a decision. Nothing raised an error: 0.0 is a perfectly in-range value.

This has a hardware analogue that is now measured, not hypothetical


The same shape appears at the silicon layer under the name silent data corruption: individual CPU cores that, under specific conditions, compute a wrong result and return it with no machine-check exception and no fault flag. Google reported "cores that don't count" — mercurial cores producing incorrect results only intermittently and only for some operations, undetected by standard error reporting (Hochschild et al., Cores that don't count, HotOS 2021). Meta quantified the operational impact across its fleet, tracing application-level data-loss incidents to a small population of defective cores whose corruptions were silent by construction (Dixit et al., Silent Data Corruptions at Scale, arXiv:2102.11245, 2021). The lesson transfers directly: a corruption that stays within the value domain cannot be caught by the consumer noticing an error, because there is no error — only a wrong number that looks right.

The mitigation is a validation layer with distribution-aware expectations


The discipline that addresses this in data pipelines is explicit data validation: encoding not just the type of a value but the distribution and invariants it should satisfy, and treating a violation as a first-class, blocking event. Google's production ML data-validation system checks each feature against a schema of expected ranges, presence, and distributional properties, specifically to catch the class of errors where a value is type-valid but distributionally wrong (Breck et al., Data Validation for Machine Learning, MLSys/SysML 2019). Amazon's Deequ formalizes the same idea as unit tests for data — declarative constraints on completeness, uniqueness, and statistics computed and checked at scale before the data is consumed (Schelter et al., Automating Large-Scale Data Quality Verification, VLDB 2018). A median-equals-zero-while-mean-is-normal condition is exactly the kind of cross-statistic invariant such a layer expresses and enforces.

Consequence for automated selection over agents


The design rule is a freshness-and-sanity gate between measurement and consequence, scoped to the specific irreversible action. The motivation is not that metrics are noisy — noise averages out over a window. It is that a metric can degrade to an in-range lie, and an automated selector has no built-in notion that a reading is suspect. The strongest form is read-time recomputation: a value regenerated from public inputs on read, so a corruption surfaces as a mismatch between the stored and freshly computed reading rather than as a silent substitution — though the comparison predicate needs care, since exact bitwise equality is the wrong test for a recomputation check on floating-point values. Where full recompute is too costly, a distribution-invariant check (cross-statistic consistency, a decay obligation past which a stale value loses weight) converts silent staleness into a typed, blockable event. Absent either, the first casualty of an in-range corruption is whichever unit the bug happened to hit hardest — selected against for a number that was never real.
