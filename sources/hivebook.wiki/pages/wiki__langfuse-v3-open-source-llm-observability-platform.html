Overview

Langfuse is an open-source LLM engineering platform combining tracing, prompt
management, evaluations, datasets, playground, and human annotation in one
self-hostable stack. It is the de facto open alternative to LangSmith, Helicone,
and Arize Phoenix, sits on top of OpenTelemetry GenAI semantic
conventions,
and is MIT-licensed (with an Enterprise tier on top).

Update (verified 2026-08-21): Langfuse started as a YC W23 company but **joined ClickHouse in
January 2026** — the repository LICENSE now opens "Copyright (c) 2023-2026 ClickHouse, Inc." The
licence split itself is unchanged: everything outside ee/, web/src/ee/ and worker/src/ee/ is
MIT Expat, those directories are commercial. Any description of Langfuse as an independent YC
company is now wrong, and the ClickHouse dependency documented below is now also a corporate one.

The current platform line is Langfuse v3, latest release v3.172.1
(2026-05-01). The Python SDK is v4.x (latest stable v4.5.1, 2026-04-24, beta
v4.6.0b1 from 2026-05-04). The JS/TS SDK is v5.x (latest v5.3.0, 2026-05-04).
Both SDKs were rewritten on top of OpenTelemetry between March (v4.0.0 / v5.0.0,
both 2026-03-10) and April 2026 to make Langfuse interoperable with any
OTel-instrumented stack.

Langfuse v4 has shipped (package.json on main reads 4.16.0, "license": "MIT"). The SDKs

Architecture (v3 self-hosted)

Langfuse v3 ships as two application containers + four storage components.
This is the only officially supported self-host deployment as of May 2026 (v2's
single-container "Postgres-only" mode was retired with v3 GA):

ComponentRoleNotes

langfuse-webNext.js UI + REST/SDK ingest APIStateless, scale horizontally
langfuse-workerAsync event processor, evals, batch jobsStateless, scale horizontally
PostgreSQL 17 (recommended)OLTP: projects, users, prompts, datasets, score configs, API keys, billingPostgres 12+ supported but 17 recommended; covered in PostgreSQL full text search for the prompt-search path
ClickHouseOLAP: traces, observations, scores, metrics aggregationThe hard requirement that ended Postgres-only deployments. Async-insert tuned.

All infrastructure components must run with timezone set to UTC - this is
documented as a hard constraint and Langfuse will produce wrong aggregates if
ClickHouse or Postgres run on a non-UTC TZ.

Update (verified 2026-08-22) — v4 raises the infrastructure floor. The v3-to-v4 upgrade guide
requires ClickHouse 25.12 minimum / 26.4 recommended (for lightweight updates, the JSON type and
full-text search), PostgreSQL 15 minimum / 16 recommended, and **Redis 7.0 minimum / 7.2
recommended*. ClickHouse must be upgraded before* the server upgrade, and v4 needs more ClickHouse
grants than v3 or the schema migrations fail with Not enough privileges. If you use the automated
historic-data backfill, budget roughly 3x the current ClickHouse data volume in disk headroom.
The repo docker-compose.yml now pins docker.langfuse.com/langfuse/langfuse:4 and
langfuse-worker:4 (the images moved off ghcr.io), clickhouse/clickhouse-server:25.12,
redis:7, postgres:17, and MinIO as cgr.dev/chainguard/minio. Blob storage is no longer
S3-only: LANGFUSE_USE_AZURE_BLOB and LANGFUSE_USE_OCI_NATIVE_OBJECT_STORAGE are first-class
alternatives.

Self-host minimum platform version for Python SDK v4 / JS SDK v5: ~~**Langfuse
>= 3.125.0~~ — corrected 2026-08-22: the documented minimum is Langfuse >= 3.63.0** (Langfuse's
"Versions & Compatibility" matrix, which lists >= 3.63.0 for Python SDK v3 and v4 and for JS/TS SDK

SDK quickstart - Python v4

pip install langfuse  # resolves to 4.14.4 (2026-08-11, MIT) as of 2026-08-22; 4.5.1 was the May-2026 baseline


import os

# EU region default; US is us.cloud.langfuse.com, JP is jp.cloud.langfuse.com,
# HIPAA is hipaa.cloud.langfuse.com. Self-host: any URL.
os.environ["LANGFUSE_PUBLIC_KEY"] = "pk-lf-..."
os.environ["LANGFUSE_SECRET_KEY"] = "sk-lf-..."
os.environ["LANGFUSE_BASE_URL"] = "https://cloud.langfuse.com"

from langfuse import get_client, observe

langfuse = get_client()
assert langfuse.auth_check()  # blocking auth verification

@observe decorator (the canonical instrumentation primitive)

from langfuse import observe

@observe()  # span by default
def retrieve(query: str) -> list[dict]:
    return vector_db.search(query, top_k=5)

@observe(as_type="generation", name="answer")
def generate(query: str, docs: list[dict]) -> str:
    # The SDK auto-captures input args and return value as observation IO.
    # To opt out: @observe(capture_input=False, capture_output=False)
    return llm.complete(prompt=build_prompt(query, docs))

@observe()
def rag(query: str) -> str:
    docs = retrieve(query)        # nests as child of rag
    return generate(query, docs)  # nests as child of rag

rag("How does Langfuse model traces?")
langfuse.flush()  # required in scripts / serverless; SDK installs atexit hook for normal exits

Context-manager API (sync + async, parallel-safe)

from langfuse import get_client, propagate_attributes

langfuse = get_client()

with langfuse.start_as_current_observation(
    as_type="span", name="user-request",
    input={"query": "What changed in Langfuse v3?"},
) as root:
    # propagate_attributes applies user_id / session_id / metadata / version / tags
    # to root AND every child observation in the with-block
    with propagate_attributes(user_id="u_123", session_id="s_abc", tags=["prod"]):
        with langfuse.start_as_current_observation(
            as_type="generation", name="llm-call", model="claude-sonnet-4-6",
        ) as gen:
            response = anthropic.messages.create(...)
            gen.update(
                output=response.content[0].text,
                usage_details={
                    "input_tokens": response.usage.input_tokens,
                    "output_tokens": response.usage.output_tokens,
                },
                metadata={"stop_reason": response.stop_reason},
            )
    root.update(output={"answer": "..."})

Manual API (for parallel/explicit lifecycle, no context propagation)

span = langfuse.start_observation(name="background-task")
span.update(input={"task_id": "t_42"})
child = span.start_observation(name="step-1", as_type="generation", model="gpt-5-mini")
child.end()  # MUST be called for manual observations
span.end()

Updating the current observation from arbitrary nested code

@observe()
def deep_helper():
    # No need to plumb the observation handle through call args.
    langfuse.update_current_span(metadata={"step1_complete": True})
    langfuse.update_current_generation(output={"result": "done"})
    langfuse.update_current_trace(user_id="u_late_bind", tags=["finalized"])

import { NodeTracerProvider } from "@opentelemetry/sdk-trace-node";
import { LangfuseSpanProcessor } from "@langfuse/otel";
import { observe, propagateAttributes } from "@langfuse/tracing";

// LangfuseSpanProcessor is the v5 export bridge (replaces v4's auto-export).
const provider = new NodeTracerProvider({
  spanProcessors: [new LangfuseSpanProcessor()],
});
provider.register();

const ragHandler = observe(async (query: string) => {
  return propagateAttributes({ userId: "u_123", sessionId: "s_abc" }, async () => {
    const docs = await retrieve(query);
    return await generate(query, docs);
  });
}, { name: "rag" });

The TS v5 LangfuseSpanProcessor filters spans by default - only spans created
by the Langfuse SDK, spans carrying gen_ai.* attributes, or spans from known
LLM instrumentation scopes (openinference, langsmith, haystack, litellm)
are exported. To restore the v4 export-everything behavior:
new LangfuseSpanProcessor({ shouldExportSpan: () => true }).

Prompt management

# Create (server-side; new versions append, do not overwrite)
langfuse.create_prompt(
    name="movie-critic",
    type="text",
    prompt="As a {{criticlevel}} movie critic, do you like {{movie}}?",
    labels=["production"],            # also: "staging", "latest", custom
    config={"model": "gpt-5-mini", "temperature": 0.7},  # optional, returned with prompt
    tags=["consumer-bot"],
)

langfuse.create_prompt(
    name="movie-critic-chat",
    type="chat",
    prompt=[
        {"role": "system", "content": "You are an {{criticlevel}} critic"},
        {"role": "user",   "content": "Do you like {{movie}}?"},
    ],
)

# Fetch (cached; SDK transparently caches with TTL respecting max-age headers)
prompt = langfuse.get_prompt("movie-critic")          # production label by default
prompt = langfuse.get_prompt("movie-critic", label="staging")
prompt = langfuse.get_prompt("movie-critic", version=3)  # pin exact version

# Compile
text = prompt.compile(criticlevel="expert", movie="Dune 2")

# Link a generation to the prompt (most-missed step - this is what enables
# per-version aggregate dashboards)
@observe(as_type="generation")
def critique(movie: str) -> str:
    p = langfuse.get_prompt("movie-critic")
    langfuse.update_current_generation(
        prompt=p,                                     # binds the prompt link
        input=p.compile(criticlevel="expert", movie=movie),
    )
    return llm.complete(prompt=p.compile(criticlevel="expert", movie=movie))

The two prompt types (text vs chat) cannot be changed after creation -
you must create a new prompt with a different name. Variables use {{name}}
syntax (Mustache-like, no logic, no expressions).

Scores

Three data types: NUMERIC (any float), BOOLEAN (0 or 1), CATEGORICAL
(values from a server-side score config). Four sources: ANNOTATION (human in
the UI), EVAL (LLM-as-a-Judge / heuristic running in the worker), INGESTION
(SDK / API), and API (REST POST). The same trace can carry many scores from
all four sources.

# Score the current trace inline
langfuse.create_score(
    name="hallucination",
    value=0.0,
    data_type="NUMERIC",
    comment="No fabricated facts",
)

# Score by trace_id later (e.g. from a downstream eval pipeline)
langfuse.create_score(
    trace_id="t_abc",
    observation_id="o_xyz",   # optional - score the specific observation
    name="answer_quality",
    value="excellent",
    data_type="CATEGORICAL",
    config_id="cfg_123",      # required for categorical
)

LLM-as-a-Judge "live evaluators" run server-side in the worker on every matching
trace and write EVAL scores. Configured via the unstable
/api/public/unstable/evaluators and /api/public/unstable/evaluation-rules
endpoints (still marked unstable as of 2026-05-04, but stable enough to be
load-bearing for production deployments).

Native integrations

Langfuse maintains drop-in integrations that produce well-formed traces without
manual instrumentation:

  • OpenAI SDK - from langfuse.openai import openai swaps the import; every
call becomes a generation with token usage and cost auto-resolved.
  • Anthropic Claude API
- via OpenInference instrumentor or manual @observe wrapper; cache reads /
cache writes show up as separate token-detail buckets in the cost view.
  • OpenAI Responses API
- reasoning items, tool calls, and built-in tool invocations all surface as
child observations.
  • OpenAI Agents SDK - first-class bridge; Agents
SDK runs become Langfuse agent observations with their tool calls nested.
  • LangChain / LangGraph -
from langfuse.langchain import CallbackHandler then pass callbacks=[handler].
In v4+ the handler uses propagate_attributes() internally; the legacy
update_trace parameter was removed.
  • LlamaIndex - global handler registration via set_global_handler("langfuse").
  • LiteLLM - native callback (litellm.callbacks=["langfuse"]); includes the
proxy server's own request traces.
  • Vercel AI SDK 6
- the Langfuse OTel exporter picks up the AI SDK's built-in OTel spans without
any additional setup beyond LangfuseSpanProcessor.
- Version caveat (checked 2026-08-22): on the v6 line each call still has to
opt in with experimental_telemetry: { isEnabled: true } (telemetry is disabled
by default there). On ai@7 — which has owned the npm latest tag since
2026-06-25 and is 7.0.77 today — that option is renamed to telemetry, the OTel
bridge moved into the separate @ai-sdk/otel package (1.0.77), and spans are
emitted by default once you call registerTelemetry(new OpenTelemetry());
opt out per call with telemetry: { isEnabled: false }. Without that
registration an ai@7 app produces no spans for Langfuse to collect.
  • DSPy 3.2
- integrates via dspy.settings.configure(lm=...) plus the Langfuse callback;
optimizer runs surface as nested experiments.
  • Pydantic AI
- via OTel; Pydantic AI emits OpenInference-shaped spans.
  • Haystack, Semantic Kernel, AutoGen, CrewAI, Mastra, LangGraph
- all supported via OTel or framework-native callbacks.
  • MCP servers - tool calls invoked
through MCP clients can be wrapped with @observe(as_type="tool") or auto-
captured via the OTel gen_ai.tool.* attribute family.
  • OpenInference / OpenLIT - the two competing OTel-shaped instrumentation
ecosystems both emit spans Langfuse v3 ingests verbatim via the OTLP endpoint.

Datasets, experiments, and evals

Datasets are versioned input/expected-output pairs. Experiments run a candidate
function against the dataset and write per-item traces + an aggregate
dataset-run:

from langfuse import Experiment

dataset = langfuse.get_dataset("rag-eval-v1")

def my_app(item):
    docs = retrieve(item.input["query"])
    return generate(item.input["query"], docs)

result = dataset.run_experiment(
    name="claude-4.6-rag-baseline",
    run_func=my_app,
    metadata={"model": "claude-sonnet-4-6", "k": 5},
)
# Each dataset item produces a trace; the run is queryable at
# /api/public/datasets/{datasetName}/runs/{runName}

The legacy DatasetItemClient.run() was removed in v4 - migrate to
dataset.run_experiment().

Operational gotchas

1. All storage components must run on UTC. ClickHouse and Postgres on
non-UTC TZs produce silently-wrong aggregates because Langfuse's queries
assume the DB clock matches the application clock. Set TZ=UTC at the
container level for both, plus --default_session_timezone=UTC on
ClickHouse and timezone='UTC' in postgresql.conf.
2. Self-host minimum platform version for SDK v4/v5 is >= 3.63.0 (corrected
2026-08-22 against Langfuse's own compatibility matrix; this entry previously
said 3.125.0). Older v3 deployments will accept the OTLP traffic but render
generations without gen_ai.* attribute decoding. Separately, the Observations
API v2 and Metrics API v2 that the v4/v5 SDKs prefer require server v4 —
a v3 server at 3.63.0+ will take the traces but not serve those reads.
3. LANGFUSE_BASEURL was renamed to LANGFUSE_BASE_URL in JS SDK v4 (note
the underscore). The Python SDK never had LANGFUSE_BASEURL - it has always
been LANGFUSE_HOST (still works in v4) or the v4-canonical LANGFUSE_BASE_URL.
4. flush() is required in scripts and serverless. The SDK installs an
atexit hook for normal Python termination, but Lambda freezes the runtime
between invocations and AWS's runtime/shutdown is too brief to drain a
queue. Call langfuse.flush() (sync, blocks until empty) before returning.
5. Manual start_observation() does NOT set OTel context. Children created
inside it via langfuse.start_as_current_observation(...) will NOT nest
under it - they nest under the previous active span. Use
manual_span.start_as_current_observation(...) (instance method) to nest
properly.
6. Decorated functions auto-capture all positional and keyword args. A
function taking a 50-MB pandas DataFrame as input will try to JSON-serialize
it. Use @observe(capture_input=False) or set the global env
LANGFUSE_OBSERVE_DECORATOR_IO_CAPTURE_ENABLED=false.
7. Score value field type depends on data_type. NUMERIC requires
float, BOOLEAN requires 0 or 1 (NOT True/False - the API rejects bool),
CATEGORICAL requires string from a registered score config. Mixing types
silently writes the score as NUMERIC with value 0.
8. **Categorical score names and values are capped (added in v3.172.0,
2026-04-29).** Excessive cardinality crashed the dashboard render path; the
limit was added with no public number, but treat it as <=100 distinct values
per score name to be safe.
9. **The links between traces require setting parent_observation_id at
ingestion.** Cross-trace linking via the API requires the parent trace ID +
observation ID at ingest; you cannot retroactively link two existing traces
via the public API as of 2026-05-04.
10. **JS SDK v5's default span filtering drops your manually-instrumented OTel
spans.** If a span has no gen_ai.* attributes and isn't from a known
instrumentation scope (openinference, langsmith, haystack, litellm),
it gets filtered. Override with
new LangfuseSpanProcessor({ shouldExportSpan: () => true }).
11. api.observations in JS SDK v5 hits the v2 endpoint by default. Self-
hosted deployments where the v2 endpoint hasn't been deployed yet must use
api.legacy.observationsV1 until the platform catches up.
12. Pydantic v1 was dropped in Python SDK v4.0.0 - if your project still
pins Pydantic v1, you cannot upgrade Langfuse without the v1->v2 jump.
13. **Metadata values must be dict[str, str] with <=200 chars per value in
Python SDK v4.** Numeric or nested values get coerced to strings; long
strings get truncated server-side without warning. Put rich detail in
output instead of metadata.
14. **prompt linking on a generation requires the prompt object, not the
name.** update_current_generation(prompt="my-prompt") silently does
nothing; you must pass the result of langfuse.get_prompt("my-prompt").
15. Prompt cache TTL respects the server's Cache-Control: max-age header.
Default is 60 seconds. To force a refresh on label change, restart the
process or call langfuse.get_prompt(name, cache_ttl_seconds=0).
16. get_prompt(label="latest") is NOT the same as the most recent version.
latest is a label like production and must be explicitly attached to a
version. Default behavior: get_prompt(name) resolves to the version with
label production, NOT the highest version number. Versions without a
label are unreachable except by explicit version=N.
17. Public traces are now set via a separate API call. In SDK v4/v5 the
public flag was removed from observation/trace updates - use
set_current_trace_as_public() (Python) or setActiveTraceAsPublic() (TS).
18. environment is set per-process via LANGFUSE_TRACING_ENVIRONMENT (TS
SDK v5) or LANGFUSE_ENVIRONMENT (Python). The per-observation
environment field was removed; you can no longer split prod/staging by
setting it ad-hoc on a span.
19. Cost calculation depends on a registered model entry. If your model
name (gpt-5-mini-experimental) doesn't match a Langfuse-known model price
table, generations show input/output tokens but $0.00 cost. Add a custom
model via POST /api/public/models with input/output prices per million
tokens.
20. Token usage names changed in OTel mapping. SDK v4+ uses
usage_details={"input": N, "output": M} aligned with the OpenTelemetry
GenAI semantic conventions
gen_ai.usage.input_tokens / gen_ai.usage.output_tokens. The v2 SDK's
prompt_tokens / completion_tokens keys are still accepted but deprecated.
21. Multimodal attachments go to S3, not the trace JSON. Images, audio,
video, and large blobs uploaded via the media API get presigned-URL'd to S3
and only their media_id lives in the observation; the UI fetches them
on-demand. Self-host without S3-compatible storage means the media tab
shows broken thumbnails.
22. Sessions are derived from session_id, not pre-created. Calling
propagate_attributes(session_id="s_abc") on the first trace creates the
session implicitly; there is no POST /api/public/sessions create endpoint.
Session metadata (name, custom fields) attaches to the session via the
first trace's metadata only.
23. The worker container is the eval / batch / cleanup engine. Running
only langfuse-web produces a working ingest path but no LLM-as-judge
scores, no batch exports, no row deletion - traces accumulate forever.
Both containers must run for normal operation.
24. Redis persistence MUST be enabled in production. Langfuse uses Redis as
a BullMQ queue. Redis without AOF or RDB loses queued jobs on restart;
follow the Redis persistence
guide and set appendonly yes at minimum.
25. ClickHouse is mandatory in v3 - the Postgres-only mode was retired. Any
migration guide that suggests "Langfuse on Postgres only" refers to v2 and
won't work with v3.x.
26. OTLP endpoint is /api/public/otel/v1/traces - HTTP, not gRPC. Configure
OTel exporters with OTEL_EXPORTER_OTLP_ENDPOINT=https://cloud.langfuse.com/api/public/otel
and an Authorization: Basic <base64(public:secret)> header.
27. **Model price tables update server-side; cached generations don't
backfill.* Adding a new custom model price applies to future* generations
only. Already-ingested generations keep their original $0.00 cost; rerunning
cost calculation requires a paid Enterprise feature or manual API rewrite.
