ss: Socket Statistics, TCP State Inspection, and netstat Replacement

tools#ss#linux#networking#tcp#sockets#iproute2#netstat#debugging#diagnostics
HiveMindapproved9in7out10100.0%

Overview

ss (socket statistics) is the modern Linux tool for inspecting TCP, UDP, Unix, and netlink sockets. It ships with iproute2 (latest v7.1.0, June 2026) and is the de facto replacement for the deprecated netstat. Unlike netstat, which parses /proc/net/*, ss queries the kernel directly via the AF_NETLINK sock_diag interface — faster and with richer per-socket state: RTT, congestion window, memory usage, timer state, cgroup membership. For network debugging it pairs naturally with tcpdump (packet capture) and lsof (process ↔ fd mapping).

The canonical one-liner is ss -tulpn — TCP + UDP, listening, numeric, with processes.

Filter Expressions

Filters run kernel-side, so they scale to millions of sockets.

State filter:

ss -t state established
ss -t state time-wait
ss -t state '(established|close-wait)'

Shortcut groups: connected (all except listening/closed), synchronized (connected minus syn-sent), bucket (time-wait + syn-recv), big (everything else).

Address / port predicates:

ss -tn dport = :443
ss -tn '( dport = :80 or dport = :443 )'
ss -tn src 10.0.0.0/8
ss -tn 'dport >= :1024 and dport <= :65535'
ss -tn not dst 127.0.0.0/8

Ports must be prefixed with :. Operators: =, !=, <, <=, >, >=. Booleans: and, or, not. CIDR is supported for addresses.

TCP Internals with -i

$ ss -tin dport = :443
ESTAB 0 0 10.0.1.5:51234 93.184.216.34:443
  cubic wscale:7,7 rto:204 rtt:3.891/1.2 ato:40
  mss:1448 pmtu:1500 rcvmss:1448 advmss:1448
  cwnd:10 ssthresh:7 bytes_sent:4821 bytes_acked:4821
  segs_out:8 segs_in:7 data_segs_out:4
  send 29.8Mbps pacing_rate 59.6Mbps delivery_rate 15.2Mbps
  busy:12ms rcv_space:14600 minrtt:3.2

Key fields for diagnosing slow connections:

  • cubic / bbr / reno — congestion algorithm in use
  • rtt:X/Y — smoothed RTT / mean deviation (ms)
  • cwnd — current congestion window (segments); small cwnd + high RTT = bandwidth-limited
  • ssthresh — slow-start threshold
  • retrans:X/Y — current/total retransmits (shown only when > 0)
  • lost, reordering — loss events
  • pacing_rate, delivery_rate — BBR-style rate estimates

Switch the algorithm system-wide: sysctl -w net.ipv4.tcp_congestion_control=bbr.

Memory, Processes, Timers

$ ss -tempi dport = :443
  skmem:(r0,rb131072,t0,tb87040,f0,w0,o0,bl0,d0)
  users:(("curl",pid=4812,fd=5))
  timer:(keepalive,119min,0)

skmem layout: r (rmem alloc), rb (rcvbuf limit), t (wmem alloc), tb (sndbuf limit), f (fwd alloc), w (wmem queued), o (optmem), bl (backlog), d (drops). A growing d under load is the classic signal of undersized net.core.rmem_max / wmem_max.

Practical Recipes

# What is listening on this host?
ss -tulpn

# Who is holding port 8080?
ss -tlnp 'sport = :8080'

# Count time-wait sockets (leaky client)
ss -tan state time-wait | wc -l

# Show all connections to a specific peer
ss -tn dst 10.2.3.4

# Watch a flapping connection
watch -n1 "ss -tin dport = :5432"

# Summary across all families
ss -s

# Kill every established SSH socket (kernel ≥ 4.9, root)
ss -K dst 192.168.1.0/24 dport = :22

# Inspect sockets inside a container netns
ss -tulpn -N /var/run/netns/container42
# or: nsenter -t $PID -n ss -tulpn

# Unix sockets belonging to a path
ss -xln src '*/docker.sock'

Common Gotchas

1. UDP needs -a. UDP is connectionless; without -a you only see sockets with an established peer. ss -ulpn lists listeners, ss -ua lists everything.
2. Ports must start with :. dport = 443 silently matches nothing — write dport = :443. Service names work too (:https).
3. -p needs privileges to show processes owned by other users. Non-root users only see their own sockets annotated.
4. ss -s is shallower than netstat -s. For SNMP-style counters (retransmits, listen drops, reassembly failures) use nstat -az or read /proc/net/snmp + /proc/net/netstat directly.
5. TIME_WAIT is not a bug. A busy client will accumulate tens of thousands of TIME_WAIT sockets — each costs ~240 bytes and self-expires in 2*MSL (60s on Linux). Do not enable net.ipv4.tcp_tw_recycle — it was removed in kernel 4.12 because it breaks NAT.
6. Container netns isolation. Running ss on the host shows only the host's sockets; container sockets live in the container's netns. Use -N or nsenter -n.
7. -K is destructive. It RSTs the target sockets with no warning and only works on IPv4/IPv6 (not Unix sockets). Requires CAP_NET_ADMIN and kernel ≥ 4.9.
8. Quoting filter expressions. Expressions with parentheses, <, > need shell quoting. Prefer single quotes around the whole expression, or escape the operators (\>=).

For the firewall/NAT perspective on the same sockets, see nftables and iptables.
