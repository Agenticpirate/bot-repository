Activepieces — Open-Source AI Workflow Automation

Overview

Activepieces is an MIT-licensed, open-source workflow automation platform built in TypeScript — a developer-friendly alternative to Zapier, Make, and n8n. You build automations visually by connecting pieces (integrations), self-host the whole platform with Docker, and extend it by writing your own TypeScript pieces. Launched in 2022, Activepieces leans into AI-first automation and the Model Context Protocol (MCP): every piece is automatically available as an MCP server usable by LLMs in Claude Desktop, Cursor, or Windsurf. Its fully-open MIT license differentiates it from n8n's fair-code model.

It is self-hosted via Docker (with Postgres + Redis) or available as a managed cloud offering. ~60% of pieces are community-contributed, and all pieces are published as packages on npm.

Core concepts

  • Flows — the automation: a trigger followed by a sequence/branch of actions across pieces.
  • Pieces — the integrations (300+), each providing triggers and actions for an app (Stripe, Slack, Google Workspace, HubSpot, Airtable, etc.). Pieces are TypeScript packages; you can author custom ones.
  • Triggers — webhooks, schedules, polling, or app events that start a flow.
  • Code piece — run custom TypeScript directly in a flow for logic the built-in pieces don't cover.
  • Branches and loops — conditional routing and iteration over lists.

Pieces as MCP servers (AI integration)

Activepieces' standout 2026 feature: every piece is automatically exposed as an MCP server. That means an LLM agent (in Claude Desktop, Cursor, Windsurf, or any MCP client) can call Activepieces integrations as tools — sending a Slack message, creating a Stripe charge, querying Airtable — through the standardized Model Context Protocol. Contributing a piece to Activepieces makes it instantly available both as a no-code building block and as an AI-agent tool, turning the integration catalog into a tool library for agents.

Extending with TypeScript pieces

A piece declares actions/triggers with typed properties. Authoring a custom action looks roughly like:

import { createAction, Property } from '@activepieces/pieces-framework';

export const greet = createAction({
  name: 'greet',
  displayName: 'Greet',
  props: { name: Property.ShortText({ displayName: 'Name', required: true }) },
  async run(context) {
    return { message: `Hello, ${context.propsValue.name}` };
  },
});

The framework handles UI generation from the typed props, so the action appears in the visual editor automatically. This TypeScript-first extensibility is Activepieces' core developer appeal.

Choose Activepieces if a permissive MIT license, TypeScript extensibility, and native MCP/AI-agent tooling matter most; choose n8n for a larger integration catalog and more mature AI features (accepting the fair-code license).

Practical advice and gotchas

  • MIT vs fair-code is the key differentiator — if you need a truly open-source (commercially unrestricted) automation platform, Activepieces qualifies where n8n does not.
  • Self-host with Postgres + Redis — like other automation platforms, the production setup needs a real database and Redis for the queue; don't rely on minimal/dev configs at scale.
  • Pieces are npm packages — you can pin, fork, or write your own; community pieces vary in maintenance quality, so check a piece before depending on it for critical flows.
  • Leverage pieces-as-MCP — if you already run Activepieces, you get an MCP tool catalog for free; point an MCP-capable LLM client at it to let agents drive your integrations.
  • Younger ecosystem — fast-moving (frequent 0.x releases); pin the version and re-test flows on upgrade, as APIs/pieces evolve quickly.
  • Secure triggers and credentials — webhook triggers are public; protect them and store integration credentials securely, especially when exposing pieces to AI agents.
