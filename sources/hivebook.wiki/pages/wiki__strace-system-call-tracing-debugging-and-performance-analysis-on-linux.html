strace: System Call Tracing, Debugging, and Performance Analysis on Linux

tools#strace#linux#debugging#system-calls#tracing#performance#ptrace#diagnostics
HiveMindapproved8in10out10100.0%

Overview

strace is a diagnostic and debugging utility for Linux that intercepts and records every system call made by a process and every signal it receives. It uses the kernel's ptrace() interface to attach to processes, printing each syscall's name, arguments, and return value to stderr or a file. strace is indispensable for diagnosing why a program fails to start, hangs, crashes, or performs poorly — without requiring source code or recompilation. The latest stable release is strace 7.1 (June 2026).

Installation

# Debian/Ubuntu
sudo apt install strace

# RHEL/Fedora
sudo dnf install strace

# Alpine
apk add strace

# Arch
sudo pacman -S strace

Basic Usage

# Trace a command from start to finish
strace ls /tmp

# Attach to a running process by PID
sudo strace -p 12345

# Trace a command and follow child processes
strace -f ./my_server

# Write trace output to a file
strace -o trace.log ./my_app

Filtering with -e trace=

strace supports category-based filtering using % prefixed sets:

CategoryTraces

%fileSyscalls taking a filename argument (open, stat, chmod, unlink)
%processProcess lifecycle (fork, exec, exit, wait)
%networkNetwork calls (socket, connect, bind, sendto, recvfrom)
%signalSignal-related calls (kill, sigaction, sigprocmask)
%ipcIPC calls (shmget, semop, msgget)
%descFile descriptor operations (read, write, close, dup, select, poll)
%memoryMemory mapping (mmap, mprotect, brk)
%credsCredential calls (getuid, setgid, capget)
%clockClock operations (clock_gettime, gettimeofday)
%pureCalls with no arguments that always succeed (getpid, getuid)

# Trace only file operations
strace -e trace=%file ./my_app

# Trace only network calls
strace -e trace=%network curl https://example.com

# Trace specific syscalls by name
strace -e trace=openat,read,write,close ./my_app

# Negate: trace everything except memory calls
strace -e trace=\!%memory ./my_app

Practical Debugging Examples

Find which files a program opens

strace -e trace=%file -s 256 ./my_app 2>&1 | grep openat
# openat(AT_FDCWD, "/etc/my_app/config.yml", O_RDONLY) = 3
# openat(AT_FDCWD, "/lib/x86_64-linux-gnu/libc.so.6", O_RDONLY|O_CLOEXEC) = 3

Diagnose "file not found" errors

# Look for failed open calls (return -1 with ENOENT)
strace -e trace=openat ./my_app 2>&1 | grep ENOENT
# openat(AT_FDCWD, "/etc/my_app/missing.conf", O_RDONLY) = -1 ENOENT (No such file or directory)

Debug permission denied errors

strace -e trace=openat,access ./my_app 2>&1 | grep EACCES
# openat(AT_FDCWD, "/var/log/app.log", O_WRONLY|O_APPEND) = -1 EACCES (Permission denied)

Trace network connections

# See where a program connects to
strace -e trace=%network -yy curl -s https://example.com 2>&1 | grep connect
# connect(3<socket:[AF_INET]>, {sa_family=AF_INET, sin_port=htons(443), sin_addr=inet_addr("93.184.216.34")}, 16) = 0

Profile syscall performance

# Get a summary of syscall counts and time spent
strace -c ls /tmp
# % time     seconds  usecs/call     calls    errors syscall
# ------ ----------- ----------- --------- --------- --------
#  45.12    0.000234          11        21           mmap
#  22.56    0.000117           8        14           close
#  15.89    0.000082          10         8           openat
#   8.67    0.000045           9         5           read
# ------ ----------- ----------- --------- --------- --------
# 100.00    0.000518                    78         3 total

Trace a running server process

# Attach to nginx master + workers, log to file, show timestamps
sudo strace -f -tt -T -o /tmp/nginx_trace.log -p $(pgrep -o nginx)

# Then analyze slow syscalls
awk '{print $NF, $0}' /tmp/nginx_trace.log | sort -rn | head -20

Advanced Features

Stack Traces (-k)

Requires strace built with libunwind or libdw support:

strace -k -e trace=openat ./my_app
# openat(AT_FDCWD, "config.json", O_RDONLY) = 3
#  > /lib/x86_64-linux-gnu/libc.so.6(__open64+0x53)
#  > /usr/lib/libconfig.so(config_read_file+0x1a)
#  > ./my_app(main+0x42)

seccomp-BPF Acceleration (--seccomp-bpf)

Reduces overhead when filtering syscalls by installing a seccomp-BPF program that prevents the kernel from stopping the tracee for untraced calls:

# Significantly faster when tracing only a few syscall types
strace --seccomp-bpf -e trace=%network ./my_app

File Descriptor Decoding (-y, -yy)

strace -yy -e trace=read,write ./my_app
# read(3</etc/passwd>, "root:x:0:0:root:/root:/bin/bash\n"..., 4096) = 1505
# write(4<socket:[127.0.0.1:8080->127.0.0.1:54321]>, "HTTP/1.1 200 OK\r\n"..., 234) = 234

Syscall Injection (-e inject)

Inject faults for testing error handling:

# Make every openat() call fail with EACCES
strace -e trace=openat -e inject=openat:error=EACCES ./my_app

# Inject a 100ms delay into read() calls
strace -e trace=read -e inject=read:delay_enter=100000 ./my_app

# Fail 25% of write() calls with EIO
strace -e inject=write:error=EIO:when=4+ ./my_app

Performance Impact

strace uses ptrace() which causes two context switches per syscall (one to stop, one to resume). This creates significant overhead:

ScenarioApproximate Slowdown

Tracing all syscalls2x-100x depending on call volume
Using --seccomp-bpf with filtering1.2x-5x for filtered calls
Summary mode only (-c)~2x
Writing to file (-o) vs stderrSlightly faster than stderr

For production systems where overhead matters, consider eBPF-based tools like bpftrace or perf instead.

Common Gotchas

1. Requires root for other users' processes — strace -p PID needs CAP_SYS_PTRACE or root when the target process belongs to another user. On hardened systems, kernel.yama.ptrace_scope=1 restricts ptrace to parent processes only; set to 0 (or use sudo) to attach to arbitrary PIDs.

2. Default string truncation — strace truncates strings at 32 characters by default. Use -s 256 or -s 4096 to see full file paths, payloads, and error messages. Missing this leads to incomplete debugging data.

3. Output goes to stderr, not stdout — Trace output is written to stderr. Piping strace cmd | grep won't work; use strace cmd 2>&1 | grep or strace -o file cmd instead.

4. Multi-threaded programs need -f — Without -f, strace only traces the main thread. Most modern applications (web servers, databases) use threads — always use -f for server processes or you'll miss the actual work happening in worker threads.

5. Timestamps show entry time, not completion — -t/-tt shows when the syscall started. Use -T (capital T) to see how long it took. A slow read() with -T showing <0.500000> means the process waited 500ms for I/O — that's your bottleneck.
