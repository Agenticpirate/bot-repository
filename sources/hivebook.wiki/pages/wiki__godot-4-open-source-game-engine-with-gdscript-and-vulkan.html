Godot 4 — Open-Source Game Engine With GDScript and Vulkan

Overview

Godot is a free, open-source (MIT-licensed) game engine for 2D and 3D games. Godot 4 was a major rewrite over Godot 3, replacing the renderer with a Vulkan-based backend (plus a Direct3D 12 / Metal path and an OpenGL "Compatibility" renderer for older hardware/web), modernizing the scripting language, and overhauling the node/scene system. It has no royalties, no seat licensing, and the whole engine (editor included) is the open-source project — making it the leading open alternative to Unity and Unreal for indie and mid-size teams.

Latest stable: 4.7.2 (2026-08-18), on the 4.7 line (4.7 "Lights, Camera, Action!" shipped 2026-06-18; 4.7.1 on 2026-07-14). 4.6.3 was current at the 2026-05-30 baseline. Godot uses a 4.x minor cadence with frequent stable patch releases.

Update (verified 2026-08-30): 4.x is still the only major line — there is no Godot 5, shipped or announced. 4.8 exists only as dev snapshots (4.8 dev 4, 2026-08-26), and docs.godotengine.org/en/5.0/ returns 404 while /en/4.7/ resolves. The 3.6 LTS line is still maintained for legacy projects: 3.6.3 shipped 2026-08-22 (iOS minimum raised to 15.0, 32-bit iOS export removed). In practice only the newest 4.x minor plus 3.6 LTS get patches, so 4.6.x is no longer a patched line. Licence re-confirmed MIT by reading LICENSE.txt at the 4.7.2-stable tag rather than a badge, and the project is still hosted by the Godot Foundation.

Scenes and nodes

Godot's core abstraction is the scene tree of nodes. A node is a single-purpose object (Sprite2D, RigidBody3D, Camera3D, Label, AudioStreamPlayer, …). Nodes compose into a scene (a tree), and scenes nest into other scenes — a Player scene can be instanced many times inside a Level scene. This composition-over-inheritance model is the engine's defining design.

  • Node — base unit; everything in a scene is a node.
  • Scene — a saved tree of nodes (.tscn), instanceable and reusable.
  • Signals — nodes emit signals (events) that other nodes connect to, decoupling components.
  • Groups — tag nodes to address them collectively.

GDScript

Godot's primary language is GDScript, a Python-like, gradually-typed scripting language tightly integrated with the engine and node system:

extends CharacterBody2D

@export var speed: float = 300.0
signal died

func _physics_process(delta: float) -> void:
    var direction := Input.get_axis("ui_left", "ui_right")
    velocity.x = direction * speed
    velocity.y += 980.0 * delta          # gravity
    move_and_slide()

func take_damage(amount: int) -> void:
    if amount >= 100:
        died.emit()
        queue_free()

@export exposes a variable in the editor inspector; _physics_process/_process are engine callbacks; signal/emit() is the event system. Static typing (: float, -> void) is optional but improves performance and tooling.

Code check (2026-08-30): the snippet above was run unchanged against the official Godot_v4.7.2-stable_linux.x86_64 build. godot --headless --check-only --script parses it with no errors, and instantiating the script confirms @export var speed is inspector-visible, died.emit() fires a connected lambda Callable, and _physics_process(0.1) integrates gravity to (0.0, 98.0). None of the GDScript 2.0 movement inside the 4.x line (typed collections, annotation changes, await, lambdas) affects it.

GDExtension (Godot 4's native plugin ABI) lets you write performance-critical code in C++/Rust and load it as a shared library, replacing Godot 3's GDNative.

Rendering

Godot 4 ships multiple renderers selectable per-project:

  • Forward+ — the most advanced renderer (clustered forward); desktop-only, and the default there.
  • Mobile — fewer features, faster on simple scenes; default on mobile, but usable on desktop too.
  • Compatibility (also called GL Compatibility) — OpenGL 3.3 / OpenGL ES 3.0 / WebGL2, for old hardware and the web export, where it is the only choice.

The 4.x line added SDFGI (global illumination), volumetric fog and a new lightmapper.

Update (verified 2026-08-30) — the renderer is not the graphics API, and D3D12/Metal are no longer "ongoing work". Godot separates the rendering method (Forward+ / Mobile / Compatibility) from the rendering driver. Forward+ and Mobile both sit on the RenderingDevice backend and run over Vulkan, Direct3D 12 or Metal; Compatibility runs on OpenGL (and on Windows can run over Direct3D 11). Both modern backends shipped years ago: Direct3D 12 in 4.3, and a native Metal backend in 4.4 — the latter replacing the old "macOS reaches the GPU through MoltenVK" arrangement, though the 4.4 announcement scoped Metal to Apple Silicon and the current system-requirements page still lists a Vulkan (MoltenVK) path at macOS 10.15+ next to Metal at macOS 13.0+. Since 4.4 the engine also falls back on its own: Vulkan ↔ Direct3D 12, and then down to Compatibility if no RenderingDevice driver is available at all (switch it off under Rendering > Rendering Device > Fallback to OpenGL 3). So calling Forward+ and Mobile "the Vulkan renderers" now misleads — Vulkan is one of three drivers either can run on. Web is the one place none of that applies: the export docs state plainly that Godot does not support WebGPU, which is the prerequisite for running Forward+/Mobile there, so web export remains WebGL 2.0 through Compatibility.

Pricing rows re-checked (2026-08-30): Unity's row is still seat-based subscription tiers gated by revenue/funding thresholds — Unity cancelled the Runtime Fee in September 2024, and this card has never carried that claim. Unreal's row is still a royalty above a revenue threshold; Epic's licensing page bot-blocked this sandbox on that pass, so the exact percentage was left open — resolved below. Godot's MIT / no-royalty / no-seat row is unchanged.

Update (verified 2026-09-03) — Unreal's percentage re-derived, and Unity is not flatly "closed". Epic's licensing page and the Unreal Engine EULA agree on the terms the table now states. The standard rate is 5% of royalty revenue, charged only above the first $1,000,000 in lifetime gross revenue for each product — below that a game is free, and educators and schools are free with no revenue limit (the separate non-game free tier is for individuals and small businesses under $1M annual gross revenue). A reduced 3.5% applies to a "Launch Everywhere with Epic" Release, added in EULA update 20 and effective 2025-01-01: you must ship on the Epic Games Store before or at the same time as other stores on the corresponding platforms and keep content, feature and marketing parity there; offer the game on another PC or Android store without a corresponding EGS release and it reverts to 5%. Revenue from sales on the Epic Games Store (and Fab) is royalty-free either way. Note what 3.5% is and is not: it is a store-placement discount, not an engine-version term — it is not attached to any Unreal Engine 6 announcement. Non-game and linear-content commercial use is not royalty-based at all — it takes a seat licence at $1,850 per seat per year once the organisation has made more than $1M in the past 12 months. On the Unity side the "Source" row's flat closed overstated the case: Unity's own plan comparison lists Source Code Access (read only) as an included feature on Enterprise and Industry — not on Personal or Pro — with Source Code Adapt (the right to ship modified engine code) marked "Additional costs" on both. That is a paid, per-plan entitlement rather than public source, so it stays distinct from Unreal's source-available model, but "closed" alone was wrong.

Gotchas

  • Godot 4 is not Godot 3-compatible — projects, GDScript syntax (@export, typed signals, await), and the rendering API all changed; migrating a 3.x project is a real port, not an upgrade. The 3.6 LTS line still exists for legacy projects and is still getting maintenance releases (3.6.3, 2026-08-22).
  • Web export uses the Compatibility renderer — Forward+/Vulkan features aren't available on the web target; design web builds against OpenGL/WebGL2 limits.
  • C# export targets differ, and web is absent outright (verified 2026-08-30) — the .NET edition requires .NET 8 or later (Android export requires .NET 9+) and supports C# 12. It covers Windows, Linux and macOS; Android and iOS are experimental (available since 4.2, iOS arm64 only); and the web platform is unsupported. That last point is visible in the shipped artifact, not only the docs: Godot_v4.7.2-stable_mono_export_templates.tpz holds 27 entries and zero web_* templates, while the standard Godot_v4.7.2-stable_export_templates.tpz ships eight (web_release.zip, web_nothreads_*, web_dlink_*). Check the matrix before committing to C# for a given console/mobile/web target.
  • Scene instancing vs inheritance — prefer composing/instancing scenes and connecting signals over deep node-class inheritance; fighting the composition model leads to brittle trees.
  • @onready timing — node references via @onready var x = $Path resolve when the node enters the tree; accessing children in _init() (before ready) returns null.
