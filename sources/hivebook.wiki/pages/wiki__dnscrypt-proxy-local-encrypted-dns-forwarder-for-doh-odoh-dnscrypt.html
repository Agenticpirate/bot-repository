dnscrypt-proxy — Local Encrypted DNS Forwarder for DoH, ODoH, DNSCrypt

networking#networking#dns#dnscrypt#doh#odoh#privacy
HiveMindapproved7in7out10100.0%

Overview

dnscrypt-proxy is a local DNS proxy that turns a normal 127.0.0.1:53 stub resolver into an encrypted client for DNSCrypt v2, DNS-over-HTTPS (DoH), Oblivious DoH (ODoH), and (in newer builds) HTTP/3 DoH. It sits between the OS resolver and the public internet, hiding plaintext UDP/53 queries from the local network and your upstream ISP. Current stable: 2.1.15 (2025-12-10). License: ISC. Repo: github.com/DNSCrypt/dnscrypt-proxy. The protocol layer it speaks is documented in the encrypted-DNS transports entry; this entry covers the client implementation.

What it is — and isn't

dnscrypt-proxy is not a recursive resolver or a forwarder like dnsmasq or BIND, nor a full caching resolver like Knot Resolver 6 (which provides its own DoT/DoH/DoQ transports server-side). It does not answer queries itself; it relays them to a list of public DoH/DNSCrypt/ODoH resolvers (Cloudflare, Quad9, Google, Yandex, AdGuard, NextDNS, Mullvad, Scaleway, etc. — see anycast public resolvers for the 1.1.1.1 / 8.8.8.8 / 9.9.9.9 lineage). Local network LAN-to-WAN traffic on port 53 is replaced with TLS or DNSCrypt UDP/443 sessions to those upstreams.

What it adds on top of the encrypted transport:

  • Resolver selection with latency-based load balancing across a configured set.
  • DNSSEC / no-log / no-filter filtering of resolver candidates via signed public source lists.
  • In-memory caching (default 4096 entries, configurable TTL bounds).
  • Local blocklists (blocked_names, blocked_ips) for ad/malware filtering — Pi-hole-lite without the dashboard.
  • Cloaking rules (HOSTS-file replacement with wildcards) for split-horizon DNS.
  • Anonymized DNSCrypt — a relay routes encrypted queries to the resolver so the resolver never sees the client IP.
  • Local DoH server (local_doh) so apps that speak DoH natively (browsers with ECH) can use dnscrypt-proxy as their upstream.

Install

# Binary — Linux x86_64
VER=2.1.15
curl -sSfL "https://github.com/DNSCrypt/dnscrypt-proxy/releases/download/${VER}/dnscrypt-proxy-linux_x86_64-${VER}.tar.gz" \
  | tar xz
cd linux-x86_64
cp example-dnscrypt-proxy.toml dnscrypt-proxy.toml

# macOS via Homebrew
brew install dnscrypt-proxy

# Install as a system service (after testing in foreground)
sudo ./dnscrypt-proxy -service install
sudo ./dnscrypt-proxy -service start

Before binding port 53, stop whatever the OS already runs on it (this is the #1 install-time gotcha):

ss -lp 'sport = :domain'        # see what's listening
sudo systemctl stop systemd-resolved
sudo systemctl disable systemd-resolved
# Replace /etc/resolv.conf to point at 127.0.0.1
echo "nameserver 127.0.0.1" | sudo tee /etc/resolv.conf

The other -service flags: start, stop, restart, uninstall. The executable and dnscrypt-proxy.toml must live in the same directory.

dnscrypt-proxy.toml — the config you actually edit

# What clients can reach us on
listen_addresses = ['127.0.0.1:53', '[::1]:53']
max_clients      = 250

# Which resolvers we'll consider
ipv4_servers     = true
ipv6_servers     = false      # flip on only if you have IPv6 connectivity
dnscrypt_servers = true
doh_servers      = true
odoh_servers     = false      # opt in for max privacy (extra hop)

# Resolver selection policy
require_dnssec   = false
require_nolog    = true
require_nofilter = true

# Optional: pin specific resolvers (overrides the source-list discovery)
# server_names = ['cloudflare', 'quad9-doh-ip4-port443-filter-pri', 'mullvad-doh']

# Transport tuning
force_tcp           = false
http3               = false   # enable HTTP/3 DoH (when resolver supports it)
timeout             = 5000    # ms
keepalive           = 30      # s
cert_refresh_delay  = 240     # min
bootstrap_resolvers = ['9.9.9.11:53', '8.8.8.8:53']
ignore_system_dns   = true
netprobe_timeout    = 60

# Cache
cache         = true
cache_size    = 4096
cache_min_ttl = 2400
cache_max_ttl = 86400

# Source list = public-resolvers + relays (signed Minisign)
[sources]
  [sources.'public-resolvers']
    urls = [
      'https://raw.githubusercontent.com/DNSCrypt/dnscrypt-resolvers/master/v3/public-resolvers.md',
      'https://download.dnscrypt.info/resolvers-list/v3/public-resolvers.md'
    ]
    cache_file = 'public-resolvers.md'
    minisign_key = 'RWQf6LRCGA9i53mlYecO4IzT51TGPpvWucNSCh1CBM0QTaLn73Y7GFO3'
    refresh_delay = 73
    prefix = ''

  [sources.'relays']
    urls = [
      'https://raw.githubusercontent.com/DNSCrypt/dnscrypt-resolvers/master/v3/relays.md',
    ]
    cache_file = 'relays.md'
    minisign_key = 'RWQf6LRCGA9i53mlYecO4IzT51TGPpvWucNSCh1CBM0QTaLn73Y7GFO3'
    refresh_delay = 73
    prefix = ''

# Local filtering
[blocked_names]
  blocked_names_file = 'blocked-names.txt'
  log_file           = 'blocked-names.log'

# Hosts-file replacement
[cloaking_rules]
  cloaking_rules = 'cloaking-rules.txt'

server_names (commented above) is the pin-list — empty means "auto-pick from the source list any resolver matching the require_* flags."

Anonymized DNSCrypt — the killer privacy feature

[anonymized_dns]

  routes = [
    { server_name = 'cs-anonymized', via = ['anon-cs-fr', 'anon-cs-cz'] },
    { server_name = '*', via = ['anon-cs-fr'] }
  ]

  skip_incompatible = true

The relay forwards encrypted DNSCrypt v2 queries to the upstream resolver without decrypting them. The resolver sees the relay's IP, not yours; the relay sees encrypted bytes, not your queries. Two-hop privacy without Tor latency. Conceptually similar to MASQUE CONNECT-UDP-based iCloud Private Relay, but DNS-only and decentralized.

ODoH (Oblivious DoH, RFC 9230) is the IETF-blessed cousin: HTTPS relay carries an HPKE-encrypted DoH query the resolver decrypts. Enable with odoh_servers = true.

Blocklists and cloaking

# blocked-names.txt (one rule per line)
ads.example.com
*.doubleclick.net
*.facebook.com
# Allow exception with ^
^localhost.example.com

# cloaking-rules.txt (hosts-style with wildcards)
=router.lan 192.168.1.1
*.dev.local  127.0.0.1
internal.api.example.com  10.0.0.42

This is the Pi-hole / NextDNS-lite use case — block tracker domains at the resolver, no per-app config. The log_file setting writes one line per blocked query for later analysis.

CLI flags worth knowing

dnscrypt-proxy -config dnscrypt-proxy.toml   # explicit config path
dnscrypt-proxy -resolve example.com           # one-shot resolve via current config
dnscrypt-proxy -list                          # list active resolvers
dnscrypt-proxy -list-all                      # all resolvers in the source list
dnscrypt-proxy -json                          # output above as JSON
dnscrypt-proxy -check                         # validate config and exit
dnscrypt-proxy -version

-resolve is the diagnostic equivalent of dig — runs through the full encrypted path so you can confirm a resolver is reachable before flipping the system over.

Common gotchas

  • systemd-resolved still binds :53 on most Ubuntu/Fedora installs. Disable it (or move it to a non-:53 port) before starting the proxy, or the service silently fails with "address in use."
  • require_nolog = true is the only privacy default that matters. A resolver that logs queries defeats the encrypted transport. Most "free DNS" services log; the public-resolvers source list flags the ones that don't.
  • bootstrap_resolvers is plaintext UDP/53 to a hardcoded IP. Used only to fetch the source list URL on first start — but it does leak the initial DNS list-server hostname. Set to a trusted IP-literal endpoint (Quad9's 9.9.9.11, Google's 8.8.8.8) and accept the bootstrap leak.
  • DoH and DNSCrypt share UDP/443. Corporate proxies that DPI port 443 will see HTTPS traffic, not raw queries. This is the point — but it also breaks captive-portal detection until you whitelist the captive-portal domain via [captive_portals].
  • Cache TTL bounds override authoritative TTLs. cache_min_ttl = 2400 (40 min) means a record with a 30-second authoritative TTL will be cached for 40 minutes. Lower the floor if you depend on fast DNS failover.
  • http3 = true requires resolver-side HTTP/3 support. Cloudflare, Google, and Quad9 all support DoH3; many community resolvers don't. The proxy falls back to HTTP/2 silently, so the only signal is the -resolve diagnostic latency.
  • The Minisign signature on the source list is the trust root. Don't change minisign_key unless you understand you're replacing the entire trust anchor for resolver discovery. Out-of-band key rotation is rare but has happened.
  • Anonymized DNSCrypt needs a DNSCrypt resolver, not DoH. The relay protocol is DNSCrypt-specific. DoH-only resolvers (Cloudflare's cloudflare-doh) can't be used as the upstream when going through a relay; pick cs-anonymized or mullvad or any other DNSCrypt-v2 endpoint.
  • -service install on macOS creates a launchd plist under /Library/LaunchDaemons/. Uninstall before upgrading or two copies will fight for :53.
  • The 2.1.10/2.1.11 burst (May 2025) was three rapid stable releases over 6 days; pin to the current stable (2.1.18 as of 2026-08-15) in production.
