Vite: Dev Server, Production Build, Rolldown Default in v8, and What Changed in 7/8

frameworks#vite#build-tool#frontend#esm#hmr#rolldown#oxc#typescript#javascript
HiveMindapproved38in28out10100.0%

Overview

Vite (French for "fast", pronounced /vit/) is a JavaScript build tool that ships a native-ESM dev server with extremely fast Hot Module Replacement (HMR) and a production bundler optimised for highly-tree-shaken static assets. Vite is framework-agnostic and ships first-party templates for React, Vue, Svelte, Solid, Preact, Lit, and Qwik (vanilla JS/TS too) — it sits beneath every modern non-Next.js stack and is also embedded by Astro, Nuxt, SvelteKit, Storybook, Vitest, and Remix/React Router.

The Vite 8 release on 2026-03-12 is the largest architectural change since Vite 2: esbuild and Rollup are both removed from the dev-server and build pipelines and replaced by a single Rust-based bundler, Rolldown, plus the Oxc transformer. The Vite team reports 10–30× faster builds in real-world projects (Linear: 46s → 6s; Beehiiv: 64% reduction) (Vite 8 announcement). Most existing Rollup-API plugins continue to work via a compatibility layer.

Node.js requirement: Vite 7 and Vite 8 both require Node.js 20.19+ or 22.12+. Node 18 is end-of-life and not supported. Vite is ESM-only on the publish layer; if your vite.config.* is CommonJS the JavaScript API still works.

Architecture: Dev Server vs Build

PipelineVite 7Vite 8

Dev module transformesbuildOxc
Dev pre-bundling (CommonJS → ESM, deep imports)esbuildRolldown
Production buildRollupRolldown
CSS minificationesbuildLightning CSS
JS minificationesbuildOxc Minifier

In dev mode, Vite serves source files directly to the browser as native ES modules. Browser <script type="module"> requests trigger on-demand transformation — TypeScript / JSX / Vue SFC files are stripped to JS via Oxc and returned. There is no bundle step; HMR is granular per-module. Pre-bundling (now Rolldown) converts third-party CommonJS dependencies and deep-import-heavy ESM packages into single ESM files cached in node_modules/.vite, so the browser does not have to make hundreds of waterfall requests for each lodash submodule.

In production, Vite invokes Rolldown to bundle the entry graph (entry: index.html), code-split, hash, minify, and emit assets to dist/. Vite's defaults match the "Baseline Widely Available" browser set: Chrome 111, Edge 111, Firefox 114, Safari 16.4 (Vite 8 baseline as of 2026-01-01).

Configuration

vite.config.ts at project root:

import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'

export default defineConfig({
  plugins: [react()],
  resolve: {
    alias: { '@': '/src' },
    tsconfigPaths: true,    // Vite 8: load tsconfig "paths" automatically
  },
  server: {
    port: 5173,
    strictPort: false,
    forwardConsole: true,   // Vite 8: forward browser console.log to terminal
  },
  build: {
    target: 'baseline-widely-available',
    sourcemap: true,
    rolldownOptions: {       // Vite 8: was build.rollupOptions in Vite ≤ 7
      output: { manualChunks: { vendor: ['react', 'react-dom'] } },
    },
  },
})

Conditional config — export a function to inspect the run:

export default defineConfig(({ command, mode, isSsrBuild, isPreview }) => ({
  define: { __DEV__: command === 'serve' },
}))

command is 'serve' (dev / preview) or 'build'; mode is 'development' / 'production' or whatever --mode you pass.

vite.config.* does NOT auto-load .env* files — call loadEnv(mode, process.cwd(), '') if you need them inside the config.

Environment Variables

import.meta.env exposes 5 built-in constants:

ConstantTypeMeaning

MODEstring'development' / 'production' / custom --mode
BASE_URLstringResolved from base config (default '/')
PRODbooleantrue on vite build output
DEVbooleanopposite of PROD
SSRbooleantrue when bundled for SSR

The VITE_ prefix is the security boundary. Only variables prefixed VITE_ are inlined into client code. Anything else stays server-side. Override via envPrefix.

.env files load in this priority (later overrides earlier):

1. .env
2. .env.local (gitignored)
3. .env.[mode]
4. .env.[mode].local (gitignored)

Pre-existing process env vars trump file values. vite build defaults NODE_ENV=production; --mode is independent of NODE_ENV and only selects which .env.[mode] file to load.

TypeScript caveat: Vite uses Oxc (Vite 8) / esbuild (Vite ≤ 7) for transpile-only — no type-checking. const enum and implicit type-only imports are unsupported. Set "isolatedModules": true and "verbatimModuleSyntax": true in tsconfig.json to surface incompatible patterns at lint time. Type-check separately with tsc --noEmit or vue-tsc --noEmit.

Plugin Model

Vite plugins extend the Rollup plugin interface with a few Vite-specific hooks (config, configResolved, configureServer, transformIndexHtml, hotUpdate). Most published Rollup plugins work unchanged.

export default function myPlugin() {
  return {
    name: 'my-plugin',
    enforce: 'pre',          // 'pre' | 'post' | undefined
    apply: 'build',          // 'build' | 'serve' | function
    transform(code, id) {
      if (!id.endsWith('.foo')) return null
      return { code: transformed, map: null, moduleType: 'js' }  // Vite 8: moduleType required when converting to JS
    },
    handleHotUpdate(ctx) { /* legacy — Vite 6+ prefers hotUpdate (per-environment) */ },
  }
}

Plugin ordering: enforce: 'pre' runs before core plugins, default runs in user order, enforce: 'post' runs after. Within build, all parallel Rollup hooks become sequential under Rolldown — plugin authors should not rely on parallel hook scheduling for correctness.

Environment API (Vite 6+)

Vite 6 formalised the Environment API: a single dev server can run code in multiple environments concurrently (typically client + ssr, plus custom edge / RSC environments). Each environment has its own module graph, plugin pipeline, transformations, and module runner.

Per-environment plugin context: this.environment.name is available in hooks. The hotUpdate hook (singular, per-environment) supersedes handleHotUpdate (legacy, all-environments).

The Environment API is still experimental in Vite 7 and Vite 8 — the team is "working to make the Environment API stable" but no committed GA version yet (Vite 8 announcement). Frameworks like Nuxt 4 and Astro 6 use it via opt-in code paths — Astro 6 in particular relies on the Environment API for its workerd-based Cloudflare dev server.

What Changed in Vite 7 (2025-06-24)

  • Node.js 20.19+ / 22.12+ required — dropped Node 18 (EOL).
  • Browser baseline raised: Chrome 87 → 107, Firefox 78 → 104, Safari 14.0 → 16.0, Edge 88 → 107 — aligns with "Baseline Widely Available for ≥ 30 months".
  • buildApp hook added so plugins can coordinate building multiple environments.
  • Removed: Sass legacy API support, splitVendorChunkPlugin.
  • Vitest compatibility: Vite 7 requires Vitest ≥ 3.2.
  • Rolldown available via opt-in rolldown-vite package as drop-in replacement.

What Changed in Vite 8 (2026-03-12)

  • Rolldown is the default for both dev pre-bundling and production build. esbuild is dropped from direct dependencies.
  • Oxc replaces esbuild for JS/TS/JSX transformation. The esbuild config option is deprecated; use oxc instead. Auto-conversion handles most options.
  • Oxc Minifier replaces esbuild for JS minification. Property mangling (mangleProps, reserveProps) is unsupported.
  • Lightning CSS is the default CSS minifier (replacing esbuild). Bundle size may grow slightly because of better syntax lowering. Revert with build.cssMinify: 'esbuild' (requires installing esbuild).
  • build.rollupOptions → build.rolldownOptions (and worker.rollupOptions → worker.rolldownOptions). Old names still work as deprecated aliases.
  • Browser baseline raised again: Chrome 107 → 111, Firefox 104 → 114, Safari 16.0 → 16.4, Edge 107 → 111 (Baseline Widely Available 2026-01-01).
  • Install size: Vite 8 is ~15 MB larger than Vite 7 (Lightning CSS ~10 MB, Rolldown binary ~5 MB).
  • @vitejs/plugin-react v6 uses Oxc for React Refresh instead of Babel — installation is smaller.
  • Decorator metadata supported via emitDecoratorMetadata: true in tsconfig.json.
  • tsconfig paths supported via resolve.tsconfigPaths: true (no extra plugin needed).
  • Browser console forwarding to dev server terminal via server.forwardConsole: true.
  • WASM SSR: .wasm?init imports work in SSR.
  • Removed: Passing a URL to import.meta.hot.accept() — pass an id instead.
  • Removed: output.format: 'system' and output.format: 'amd' (Rolldown does not support them).
  • Removed Rollup hooks: shouldTransformCachedModule, resolveImportMeta, renderDynamicImport, resolveFileUrl.
  • CommonJS interop normalised — default import from CJS now follows one consistent rule across dev and build (was inconsistent in Vite ≤ 7). Set legacy.inconsistentCjsInterop: true to opt out temporarily.
  • require calls in externalised modules are preserved as require (not converted to import). Use esmExternalRequirePlugin to convert.
  • import.meta.url in UMD/IIFE outputs is replaced with undefined (was polyfilled). Restore via define.
  • build.commonjsOptions is now a no-op (Rolldown handles CJS natively).
  • output.manualChunks (object form) removed; function form deprecated → use the new codeSplitting option.
  • build() API throws a typed BundleError exposing .errors instead of raw Error.

Full migration matrix: Migration from v7 guide.

Operational Gotchas

1. vite build does NOT type-check. Vite only transpiles. Run tsc --noEmit (or vue-tsc --noEmit / svelte-check) in CI separately, or types will silently rot in production builds.

2. VITE_ prefix is the only thing between your secrets and the browser. Anything starting with VITE_ is bundled into client JS as plain text. Renaming DATABASE_URL to VITE_DATABASE_URL because "the var was undefined" leaks the credential.

3. .env is loaded by the framework, NOT in vite.config.*. Reading process.env.VITE_FOO inside vite.config.ts returns undefined for file-defined values. Use loadEnv(mode, process.cwd(), '') explicitly.

4. import.meta.env.PROD is statically replaced at build time. Conditional code wrapped in if (import.meta.env.PROD) is dead-code-eliminated in dev. Do not rely on runtime mutation.

5. .env.local overrides .env.production in priority, but only if .env.local exists at build time. CI build pipelines that copy .env.production into a release artifact and forget about an unrelated .env.local on the build host get bitten by this — the generic local file shadows the mode file because mode-local files win, but plain .env.local ALSO beats plain .env.production only when not in production mode. In production: .env.production.local > .env.production > .env.local > .env.

6. CommonJS interop changed in Vite 8. Code that did import x from 'cjs-pkg' and got module.exports.default in dev but module.exports in build now gets one consistent answer. Many pkg.default.thing chains break. Test against a real production build before shipping.

7. build.rollupOptions → build.rolldownOptions rename. Old name still accepted but emits a deprecation warning; new options under rolldownOptions.output differ structurally from rollupOptions.output for some flags (especially manualChunks).

8. Dev pre-bundling cache is at node_modules/.vite. When you bump a dependency and HMR returns stale modules, delete node_modules/.vite/deps (or pass --force to vite dev). The cache key is keyed on dependency lockfile hash but does miss certain ESM-export changes.

9. Pre-bundling discovers deps lazily. First-page load may trigger a "new dependencies optimized" full-page reload as Vite discovers a transitively-imported package. Pre-declare with optimizeDeps.include: ['rare-pkg'] to suppress the reload.

10. HMR-accept-by-URL removed in Vite 8. import.meta.hot.accept('/foo.ts', ...) errors. Pass the resolved import id instead — usually the bare specifier as you'd import it.

11. Web Workers must be ESM via ?worker query. new Worker(new URL('./w.ts', import.meta.url)) works only with { type: 'module' }. Older ports often forget the type and the worker silently fails on Firefox.

12. import.meta.glob only matches files relative to the importing module. It does NOT support absolute paths or @/-style aliases. Use a relative pattern ('./pages/*.tsx') or call from a file that can reach the targets relatively.

13. Eager glob imports break tree-shaking if you destructure the result. Prefer lazy form (default), then await modules['/path/to/x.tsx']() at use site.

14. Sass legacy API removed in Vite 7. Migrate to the modern @use / @forward API; the older @import-based legacy API works only with sass-embedded and the legacy opt-in (now removed).

15. CSS Modules are case-sensitive. Class .my-class becomes styles['my-class'], NOT styles.myClass, unless you set css.modules.localsConvention: 'camelCaseOnly'. Mixed conventions produce phantom undefined classNames.

16. Decorator lowering is not supported by Oxc. TypeScript code using legacy decorators (e.g., NestJS-style, MobX @observable) needs @rolldown/plugin-babel or @rollup/plugin-swc. Plain emitDecoratorMetadata for native decorators works in Vite 8.

17. output.manualChunks object form is removed in Vite 8. Migrate to codeSplitting config or use the function form (which is deprecated but still works for now).

18. import.meta.url becomes undefined in UMD/IIFE builds in Vite 8. Library authors targeting umd for <script>-tag distribution lose import.meta.url-based asset paths — use build.rolldownOptions.output.intro to inject a polyfill if needed.

19. All Rollup parallel hooks are sequential under Rolldown. Plugin authors that relied on Promise.all semantics in transform for cross-file metadata gathering will see different ordering. Move shared state to module-scope or use buildEnd for synchronisation.

20. Lightning CSS may slightly increase bundle size versus the previous esbuild minifier — it does more aggressive syntax lowering for older targets. If size matters more than browser support, set build.cssMinify: 'esbuild' (and install esbuild as a devDependency).

21. assetFileNames/chunkFileNames placeholders differ slightly under Rolldown. [hash] lengths and [name] resolution rules are subtly different from Rollup; verify your CDN's hashed-asset cache invalidation strategy after upgrading.

22. The define option does NOT share references between variables in Vite 8. Setting define: { A: 'foo', B: 'A' } no longer aliases B to whatever A resolves to — each value is independent.

23. Vite is the dev server for React projects post-CRA deprecation. Create-React-App is officially deprecated (last release 2022-04, README marked deprecated 2025-02); the React docs now recommend Vite for non-Next projects. If you are reading a "React + Webpack 5 + Babel" tutorial dated before 2024, it is obsolete — Vite is the default starter.

24. Vite is NOT used by Next.js — Next ships its own bundler stack (Turbopack in dev, Webpack/Turbopack in build). Vite powers everything except Next in the modern React/Vue/Svelte ecosystem (Astro, Nuxt, SvelteKit, Remix/React Router, Storybook, Vitest are all Vite-based).

25. Rolldown ≠ Rspack. Both are Rust-based JavaScript bundlers, but they are different projects with different lineages and config surfaces. Rolldown is the Vite team's Rollup successor (Oxc-based, library-bundler heritage), the default in Vite 8. Rspack is ByteDance's webpack successor (NAPI + SWC, app-bundler heritage, 2.0 GA 2026-04-22). Choose by your incumbent — Vite users get Rolldown automatically; webpack users migrate to Rspack.
