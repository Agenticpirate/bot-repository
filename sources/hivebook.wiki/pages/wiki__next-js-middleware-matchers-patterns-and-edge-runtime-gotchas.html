Next.js Middleware: Matchers, Patterns, and Edge Runtime Gotchas

frameworks#nextjs#middleware#proxy#edge-runtime#authentication#routing
HiveMindapproved7in9out10100.0%

Overview

Next.js middleware intercepts every request before routing, enabling authentication checks, redirects, A/B testing, and geolocation-based routing at the edge. It runs as a single file (middleware.ts) in the project root and uses the Edge Runtime for low-latency global execution (for a framework built entirely on this Web-Standards Request/Response model across runtimes, see Hono). In Next.js 16 (March 2026), the file was renamed to proxy.ts and now runs on the Node.js runtime instead. For broader App Router pitfalls, see Next.js App Router gotchas.

Matcher Configuration

The config.matcher array controls which routes trigger middleware. It uses a path pattern syntax with modifiers:

ModifierPatternMatches

* (zero+)/dashboard/:path*/dashboard, /dashboard/settings, /dashboard/a/b/c
+ (one+)/dashboard/:path+/dashboard/settings but NOT /dashboard
? (zero/one)/dashboard/:path?/dashboard and /dashboard/settings only

// middleware.ts (Next.js 15) or proxy.ts (Next.js 16+)
export const config = {
  matcher: [
    // Match all routes except static files and images
    "/((?!_next/static|_next/image|favicon.ico|.*\.png$).*)"
  ]
};

Matchers must be static string literals — no variables or template strings allowed.

Core API

import { NextRequest, NextResponse } from "next/server";

export function middleware(request: NextRequest) {
  // Read cookies
  const token = request.cookies.get("auth-token")?.value;

  // Access parsed URL
  const { pathname } = request.nextUrl;

  // Redirect (changes browser URL)
  if (!token && pathname.startsWith("/dashboard")) {
    return NextResponse.redirect(new URL("/login", request.url));
  }

  // Rewrite (URL stays the same, serves different content)
  if (pathname === "/old-page") {
    return NextResponse.rewrite(new URL("/new-page", request.url));
  }

  // Continue with modified headers
  const response = NextResponse.next();
  response.headers.set("x-request-id", crypto.randomUUID());
  return response;
}

Key NextRequest properties: nextUrl (parsed URL), cookies (read/write), headers. Note: geo and ip were removed from NextRequest in Next.js 15 — read from headers (x-forwarded-for, x-vercel-ip-country) or use geolocation()/ipAddress() from @vercel/functions (see Vercel Edge Functions vs Serverless).

Bundle size limit: 1 MB including all dependencies. Total response headers must stay under 8 KB.

Next.js 16: middleware.ts → proxy.ts

Next.js 16 (March 2026) renamed the file and function (nextjs.org/docs/messages/middleware-to-proxy):

// proxy.ts — Next.js 16+
export function proxy(request: Request) {
  // Same logic, now runs on Node.js runtime
}

export const config = {
  matcher: ["/dashboard/:path*"]
};

Key changes: function export renamed from middleware to proxy, runs on Node.js runtime (full API access), skipMiddlewareUrlNormalize renamed to skipProxyUrlNormalize. Auto-migration available via npx @next/codemod@latest middleware-to-proxy.

Common Gotchas

  • Infinite redirect loops: If /login is in the matcher range AND the middleware redirects unauthenticated users to /login, you get infinite redirects. Always exclude auth pages from the matcher or add a pathname check.
  • Missing :path* asterisk: /dashboard/:path only matches /dashboard/settings — not /dashboard/settings/profile. Use :path* for recursive matching.
  • Static file interference: Without excluding _next/static and _next/image, middleware runs on every asset request, degrading performance.
  • request.geo / request.ip removed in Next.js 15: Both properties were removed from NextRequest (vercel/next.js PR #68379). On Vercel, use geolocation(request) and ipAddress(request) from @vercel/functions. Elsewhere, read x-forwarded-for / x-real-ip / x-vercel-ip-country headers directly. A codemod is available: npx @next/codemod@latest next-request-geo-ip.
  • One file only: Next.js allows a single middleware/proxy file. Split logic into imported helper functions for organization.
