Istio Service Mesh — Architecture, Sidecar vs Ambient, CRDs, and What Changed in 1.29

Overview

Istio is a CNCF-graduated service mesh for Kubernetes (and VMs) built on Envoy that adds zero-trust mTLS, advanced traffic management, and L7 observability without application code changes. Founded by Google, IBM and Lyft in 2016, Istio ships two data-plane modes: traditional sidecar mode (one Envoy per pod) and ambient mode (per-node ztunnel + optional per-namespace waypoint) — both driven by the same control plane (istiod) and the same CRDs. This entry covers v1.29 (the current stable at the time of writing, 2026-04-23). For progressive delivery on top of Istio see Flagger and Argo Rollouts; for the Kubernetes-native ingress API Istio also implements, see Gateway API.

Version Baseline (2026-04-23)

Update (verified 2026-07-22): current stable is now 1.30 (1.30.0 released 2026-05-18, latest patch 1.30.3; supported on Kubernetes 1.32-1.36). The 1.29 line is at 1.29.6 (2026-07-16) and remains supported; 1.28 end-of-life has been announced (final patch 1.28.10). Notable in 1.30: experimental agentgateway support - a new data-plane proxy built for AI-agent and MCP-server traffic that replaces Envoy on the gateway pod, wired in as the istio-agentgateway GatewayClass (Gateway API only, not sidecar/waypoint). Installation

istioctl (recommended for getting started)

# Install istioctl
curl -L https://istio.io/downloadIstio | ISTIO_VERSION=1.29.2 sh -
export PATH="$PWD/istio-1.29.2/bin:$PATH"

# Sidecar-mode production install (no demo add-ons)
istioctl install --set profile=default -y

# Enable sidecar injection for a namespace
kubectl label namespace default istio-injection=enabled
# Restart workloads to get sidecars injected
kubectl rollout restart deployment -n default

Ambient-mode install

istioctl install --set profile=ambient -y
# Opt namespaces in — no pod restart required
kubectl label namespace default istio.io/dataplane-mode=ambient

> Note the label key: istio.io/dataplane-mode=ambient in recent docs (the older docs referenced istio.io/dataplane=ambient — both are accepted at time of writing, but istio.io/dataplane-mode is canonical).

helm repo add istio https://istio-release.storage.googleapis.com/charts

# Ambient adds two more charts:

Tunneling protocol in ambient: ztunnel uses HBONE (HTTP/2 CONNECT over mTLS) to carry pod-to-pod traffic between nodes. HBONE is visible on port 15008; do not block it in NetworkPolicy. Source: istio.io/latest/docs/overview/dataplane-modes, istio.io/latest/docs/ambient/overview.

Istio's v1 API group supersedes the old v1beta1/v1alpha3; the CRDs are served under both for compatibility, but v1 is canonical from 1.22+ and required for the newer fields.

VirtualService (minimal)

apiVersion: networking.istio.io/v1
kind: VirtualService
metadata:
  name: reviews
spec:
  hosts:
  - reviews.prod.svc.cluster.local
  http:
  - match:
    - uri: { prefix: "/v2" }
    route:
    - destination: { host: reviews.prod.svc.cluster.local, subset: v2 }
      weight: 25
    - destination: { host: reviews.prod.svc.cluster.local, subset: v1 }
      weight: 75
    timeout: 5s
    retries:
      attempts: 3
      perTryTimeout: 2s
      retryOn: gateway-error,connect-failure,refused-stream
    fault:
      delay:
        percentage: { value: 5 }
        fixedDelay: 2s
    mirror:
      host: reviews.prod.svc.cluster.local
      subset: v3
    mirrorPercentage: { value: 10 }

DestinationRule (with subsets + outlier detection)

apiVersion: networking.istio.io/v1
kind: DestinationRule
metadata:
  name: reviews
spec:
  host: reviews.prod.svc.cluster.local
  trafficPolicy:
    loadBalancer: { simple: LEAST_REQUEST }
    connectionPool:
      tcp: { maxConnections: 100 }
      http:
        http2MaxRequests: 1000
        maxRequestsPerConnection: 10
    outlierDetection:
      consecutive5xxErrors: 7
      interval: 30s
      baseEjectionTime: 30s
      maxEjectionPercent: 50
    tls: { mode: ISTIO_MUTUAL }
  subsets:
  - name: v1
    labels: { version: v1 }
  - name: v2
    labels: { version: v2 }

PeerAuthentication (mesh-wide STRICT mTLS)

apiVersion: security.istio.io/v1
kind: PeerAuthentication
metadata:
  name: default
  namespace: istio-system        # mesh-wide scope
spec:
  mtls: { mode: STRICT }

STRICT rejects plaintext. Stage with PERMISSIVE on a per-namespace or per-workload PA first so non-mesh callers don't break during migration. Per-port overrides go in portLevelMtls and reference the workload's container port, not the Service port. See mTLS (Mutual TLS).

AuthorizationPolicy (identity-based)

apiVersion: security.istio.io/v1
kind: AuthorizationPolicy
metadata:
  name: reviews-allow
  namespace: prod
spec:
  selector:
    matchLabels: { app: reviews }
  action: ALLOW
  rules:
  - from:
    - source:
        principals: ["cluster.local/ns/prod/sa/productpage"]
    to:
    - operation:
        methods: ["GET"]
        paths:   ["/reviews/*"]

Default when at least one ALLOW AP selects a workload: anything not matched is denied. DENY policies always win over ALLOW. CUSTOM action delegates to an external authz service registered in meshConfig.extensionProviders (e.g. OPA).

The Request-Path Decision Order

For any request arriving at an Istio-captured workload, config is evaluated in this order (remember it — 70% of "why isn't my route working" questions are because a step matched or didn't match earlier than the author expected):

1. Gateway matches host / port / TLS → selects an ingress proxy
2. VirtualService matches hosts + path/header/method → picks a route (a list of destinations with weights)
3. ServiceEntry resolves any out-of-mesh hosts
4. DestinationRule applies per-destination policy (loadBalancer, connectionPool, outlierDetection, subset TLS) — only after VirtualService has picked the destination
5. Sidecar scopes what the outbound proxy knows about (shrinks xDS push size)
6. PeerAuthentication decides inbound mTLS
7. AuthorizationPolicy runs DENY rules, then CUSTOM, then ALLOW
8. Telemetry emits metrics / traces / logs

Gateway API (newer, preferred over Gateway + VirtualService for ingress)

Istio 1.29 ships Gateway API v1.4 core conformance plus beta support for the Inference Extension (behind ENABLE_GATEWAY_API_INFERENCE_EXTENSION). Most new installs should reach for Gateway + HTTPRoute rather than Istio's own Gateway + VirtualService — Gateway API is portable across implementations (Istio, Cilium, Envoy Gateway, Contour) and is under active CNCF development. The two APIs coexist on the same cluster.

apiVersion: gateway.networking.k8s.io/v1
kind: Gateway
metadata:
  name: edge
  namespace: istio-system
spec:
  gatewayClassName: istio
  listeners:
  - name: http
    port: 80
    protocol: HTTP
    allowedRoutes: { namespaces: { from: All } }
---
apiVersion: gateway.networking.k8s.io/v1
kind: HTTPRoute
metadata:
  name: reviews
  namespace: prod
spec:
  parentRefs:
  - { name: edge, namespace: istio-system }
  hostnames: ["reviews.example.com"]
  rules:
  - matches:
    - path: { type: PathPrefix, value: /v2 }
    backendRefs:
    - { name: reviews, port: 9080 }

What Changed in 1.29 (2026-02-16, latest patch 1.29.2 on 2026-04-13)

  • Kubernetes support: 1.31–1.35
  • Ambient dnsCapture default on: cni.ambient.dnsCapture=true is now the default; pod DNS resolution goes through ztunnel's local resolver so ambient ServiceEntry hostnames resolve without sidecar help
  • Ambient iptables/nftables reconciliation on CNI startup: cni.ambient.reconcileIptablesOnStartup=true repairs redirection rules on upgrade — no more manual pod restarts after a istio-cni DaemonSet roll
  • Gateway API Inference Extension → beta: conformant to Gateway API Inference Extension v1.0.1 (ENABLE_GATEWAY_API_INFERENCE_EXTENSION)
  • Ambient multi-network multicluster → beta: (AMBIENT_ENABLE_MULTI_NETWORK_INGRESS still required for some paths)
  • CRL in ztunnel (#58733): Certificate Revocation List support for external CAs; configure via values.pilot.crlConfigMapName
  • Debug endpoint authz default on: port 15014 debug endpoints now gated by namespace-based authz (breaking for scripts that scraped /debug/* anonymously)
  • Optional NetworkPolicy: global.networkPolicy.enabled=true deploys K8s NetworkPolicies for istiod / istio-cni / ztunnel automatically
  • Custom cipher suites at the Gateway: gateway.istio.io/tls-cipher-suites (#58366)
  • LEAST_REQUEST + circuit breaking for gRPC proxyless: xDS-native gRPC clients now honor DestinationRule.trafficPolicy beyond round-robin
  • Wildcard ServiceEntry hosts for TLS (alpha): ENABLE_WILDCARD_HOST_SERVICE_ENTRIES_FOR_TLS + DYNAMIC_DNS resolution mode (#54540) — beware: wildcard hosts without strict SNI checking can leak traffic to attacker-controlled names
  • New locality label precedence: topology.istio.io/locality overrides the older istio-locality label
  • Telemetry: Formatter custom-tag type; waypoint traces now include istio.downstream.workload / istio.upstream.workload spans; timeout + headers in ZipkinTracingProvider (#58348)
  • sidecar.istio.io/statsCompression annotation deprecated → moved to proxyConfig.statsCompression (set via proxy.istio.io/config annotation or meshConfig.defaultConfig) (#48051)
  • GOMEMLIMIT at 90% of pod memory limit (was 100%) — fewer OOMKills on istiod
  • Kiali addon bumped to 2.21.0
  • CNI termination grace period default raised to 30s (#58572) — prevents long-lived pod termination dropping connection mid-drain

Sources: istio.io/latest/news/releases/1.29.x/announcing-1.29, change-notes.

Gotchas (20)

1. kubectl label ns ... istio-injection=enabled alone does nothing — existing pods keep running without sidecars. You must also kubectl rollout restart (sidecar mode). Ambient mode does not need the restart.
2. Don't mix injection labels: istio-injection=enabled is the v1 annotation; istio.io/rev=<revision> replaces it for revision-based upgrades. Set one or the other — both on the same namespace silently wins via a documented precedence.
3. PeerAuthentication portLevelMtls port numbers are workload container ports, not Kubernetes Service ports. A common confusing failure is DISABLEing port 8080 when your Service targets container port 80.
4. AuthorizationPolicy with no rules: is a DENY-all trap. It's valid YAML but will lock you out. Use action: ALLOW with at least one matching rule to open specific traffic.
5. DENY always beats ALLOW. If two policies select the same workload and one says DENY, the request is denied regardless of ALLOW rules.
6. principals: must be cluster.local/ns/<ns>/sa/<sa> form, not bare service account names. The trust domain defaults to cluster.local but may be different if meshConfig.trustDomain was customized.
7. Outlier detection needs active traffic to trigger. consecutive5xxErrors: 7 does not eject a cold pod that has handled 0 requests. Combine with http2MaxRequests + healthy load balancer state.
8. VirtualService routes are order-sensitive. The first http[] rule whose match matches wins — even if a later rule is more specific. Put the narrowest match first.
9. gateways: [mesh, my-gateway] is two selectors, not intersected. A rule with gateways: [mesh] alone applies only to sidecars; [my-gateway] alone applies only at the gateway. Most ingress-routing bugs are forgetting to list both.
10. ServiceEntry resolution modes matter: NONE = use original dest IP, STATIC = use endpoints:, DNS = per-proxy DNS lookup, DYNAMIC_DNS (1.29 alpha) = wildcard with TLS. Wrong mode silently black-holes external traffic.
11. DestinationRule.trafficPolicy.tls.mode: ISTIO_MUTUAL on an external ServiceEntry breaks the handshake — external TLS endpoints don't speak SPIFFE; use SIMPLE or MUTUAL with your own certs.
12. Ambient mode and sidecar mode on the same namespace don't overlap cleanly. A namespace should be labeled for one or the other; cross-mode traffic works via HBONE but L7 policies written for sidecars don't automatically bind to waypoints.
13. Ambient L7 policies need a waypoint. AuthorizationPolicy rules that reference request.* (path, method, headers) are no-ops in ambient unless a waypoint is deployed for the destination service account/namespace.
14. HBONE port 15008 must not be blocked in NetworkPolicy — ambient traffic rides over it. istio.io/dataplane-mode=ambient does not auto-allow it.
15. PILOT_ENABLE_NETWORK_POLICY is not a thing. Don't conflate Istio's AuthorizationPolicy (L7/L4 identity-based, enforced by the proxy) with Kubernetes NetworkPolicy (L3/L4 CIDR/label-based, enforced by the CNI). You usually want both.
16. VirtualService.http.mirror (and mirrorPercentage) doubles outbound writes to mirrored hosts — mirroring a POST to a payment service charges twice. Mirror only to idempotent read endpoints.
17. Sidecars inject an init container that does iptables redirection. Pods with securityContext.runAsNonRoot: true at pod level break injection unless values.global.proxy_init.runAsNonRoot=true — or switch to ambient + istio-cni.
18. istioctl analyze catches 80% of misconfigs (orphaned DestinationRule subsets, conflicting Gateway hosts, unreachable VirtualService rules). Run it in CI, not just at 2 AM.
19. istioctl x precheck before every upgrade — it catches removed CRDs and deprecated field usage (e.g. sidecar.istio.io/statsCompression flagged in 1.29).
20. Revision-based upgrade pins an istiod version via istio.io/rev=<rev> — the canary path. Keep one revision per supported minor rather than relying on the default tag, so rollbacks don't touch every namespace at once.
