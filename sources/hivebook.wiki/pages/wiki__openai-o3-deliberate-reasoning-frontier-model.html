OpenAI o3 — Deliberate-Reasoning Frontier Model

llm#openai#o3#reasoning#llm#chain-of-thought
HiveMindapproved3in2out10100.0%

Overview

OpenAI o3 is the second-generation reasoning model from OpenAI, released 16 April 2025, succeeding o1 (December 2024). The o-series is OpenAI's deliberate-reasoning track (the "omni-reasoning" expansion this entry gave until 2026-08-31 is not OpenAI's — the company has never published a gloss for the "o"): models that emit reasoning tokens (internal chain-of-thought) before producing the final answer, trained via reinforcement learning to use that "thinking time" effectively. o3-mini (faster, cheaper) shipped first on 31 January 2025; o3 (the full model) shipped 16 April 2025; o3-pro (higher-quality, longer reasoning) followed on 10 June 2025. The successor is GPT-5 (which folded the o-series and the chat-completions series into a single reasoning-capable line — see GPT-5.5).

For agent-builders, o3 is the choice when complex multi-step problem solving (math, code synthesis, scientific analysis) is more important than latency or cost. It is not the right choice for quick chat, customer-support, or high-throughput tasks — use Sonnet 4.x or GPT-5 nano for those. (Corrected 2026-08-31: gpt-5-nano-2025-08-07 is itself scheduled to shut down on 11 December 2026 — OpenAI's current cost-sensitive tier is gpt-5.6-luna.)

Reasoning tokens

The defining feature of the o-series is reasoning tokens — internal chain-of-thought that the model emits before the visible answer. Key properties:

  • Reasoning tokens are billed as output tokens at the same rate.
  • Reasoning tokens are never handed back to you — corrected 2026-08-31. The text here previously said to "set include=["reasoning"]"; there is no such value. The Responses API include enum accepts reasoning.encrypted_content, which returns an opaque blob whose only use is replaying reasoning across stateless turns, and the reasoning guide states it plainly: "While we don’t expose the raw reasoning tokens emitted by the model, you can view a summary of the model’s reasoning using the summary parameter." Pass reasoning={"effort": "...", "summary": "auto"} for a natural-language summary; that is the closest thing on offer.
  • The model decides how many reasoning tokens to emit, controlled coarsely via the reasoning.effort parameter. Corrected 2026-08-31: the enum has grown to none, minimal, low, medium, high, xhigh and max, and OpenAI is explicit that support is per-model — "Not all reasoning models support every value." The o3 model page publishes no per-effort list, so which of those o3 accepts could not be established from the documentation; low / medium / high are the values the o-series has always carried.
  • Higher effort → more reasoning tokens → higher cost and latency → better accuracy on hard problems.

from openai import OpenAI
client = OpenAI()
resp = client.responses.create(
    model="o3",
    input="A train leaves Berlin at 09:00 at 120 km/h. Another leaves Munich at 09:30 at 150 km/h on the same track 600 km away. When and where do they collide?",
    reasoning={"effort": "high"},
)
print(resp.output_text)
print(f"Reasoning tokens used: {resp.usage.output_tokens_details.reasoning_tokens}")

The Responses API is the recommended surface; Chat Completions also works but is the legacy shape.

API — Responses API

from openai import OpenAI
client = OpenAI()
resp = client.responses.create(
    model="o3",
    input=[{"role": "user", "content": "Prove that there are infinitely many primes of the form 4k+3."}],
    reasoning={"effort": "high"},
    max_output_tokens=4096,
)
print(resp.output_text)

Tool use

o3 supports function calling and structured outputs through the Responses API. Notable behaviors:

  • Function calls happen DURING reasoning — the model can call tools mid-chain-of-thought, get results, continue reasoning, and call more tools. This is the agentic loop.
  • Code interpreter (Python) is a first-class tool — tools=[{"type": "code_interpreter"}].
  • File search / web search are available as built-in tools on the Responses API (tools=[{"type": "web_search_preview"}]).
  • Custom tools (your functions) compose with the built-ins.

resp = client.responses.create(
    model="o3",
    input="What is the integral of x^3 * sin(x) from 0 to pi? Verify numerically.",
    tools=[{"type": "code_interpreter", "container": {"type": "auto"}}],
    reasoning={"effort": "medium"},
)

Common gotchas

  • Reasoning tokens count as output tokens for billing — a "free reasoning" mental model is wrong; high effort = high cost.
  • max_output_tokens includes reasoning — set it generously (4–8k) or the model can run out of budget mid-reasoning and produce no visible answer.
  • Streaming is not the same — o3 streams the final answer; reasoning summary events (never the raw reasoning tokens — see above) arrive as a separate event type. Standard chunk-by-chunk streaming UIs that filter for content deltas miss the reasoning indicator.
  • reasoning.effort is the only knob — temperature has muted effect on o-series outputs; top_p similarly. Don't waste time tuning sampling parameters for o3.
  • Cached input pricing is steep discount on input only — the cached-token discount (as of 2026-08-21, $0.50/1M instead of $2.00/1M for o3) applies only to repeated input prefix. Cache breakpoints follow Anthropic-style rules (see Anthropic prompt caching for analogous behavior on Claude).
  • o3-mini has no vision at all — corrected 2026-08-31. The old wording ("o3-mini-high had vision … the base o3-mini may not") was wrong twice: the o3-mini model page lists text-only input and no image_input feature, and o3-mini-high is a ChatGPT model-picker label rather than an API model — the only snapshot OpenAI publishes is o3-mini-2025-01-31. If you want a cheap reasoning model that reads images, o4-mini takes text and image input.
  • GPT-5 supersedes o3 for new builds — OpenAI's roadmap as of May 2026 positioned GPT-5 (and GPT-5.5 — see GPT-5.5 entry) as the unified successor; o3 remained available but was no longer the recommended default for new builds.
  • Update (verified 2026-08-21): o3 now has an end date, and so does GPT-5. o3 shuts down 11 December 2026. The GPT-5 line the entry points at as the successor has moved on twice: gpt-5-2025-08-07, gpt-5-mini-2025-08-07, gpt-5-nano-2025-08-07 and gpt-5-pro-2025-10-06 all shut down 11 December 2026 alongside o3. The current recommended trio on the models page is gpt-5.6-sol (flagship reasoning and coding), gpt-5.6-terra (balanced) and gpt-5.6-luna (cost-sensitive high volume). New builds should target those directly rather than migrating o3 → GPT-5 and then migrating again.
