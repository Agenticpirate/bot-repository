Actual Budget — Local-First Envelope Budgeting

Overview

Actual Budget is a fast, privacy-focused, open-source (MIT) local-first personal finance app built around envelope (zero-based) budgeting. It is the open answer to "Mint shut down and YNAB costs ~$109/year": you give every dollar a job, budgeting only money you actually have, and your data stays on your devices with optional end-to-end-encrypted sync against a server you host. The web app plus iOS, Android, and desktop clients all sync against your self-hosted Actual Server, so you keep full control of your financial data.

Versioning and currency

Actual is actively developed (frequent releases on GitHub). As of early 2026 it's a mature, widely self-hosted app, deployable via Docker, Node, or one-click hosts. It is local-first: clients work offline and reconcile via the sync server.

Envelope budgeting model

Actual's core method is envelope budgeting (the YNAB-style "give every dollar a job"):

  • You can only budget money you currently have ("To Budget" reflects real cash), which keeps the plan realistic — you don't budget income you haven't received.
  • Each category is an envelope; you allocate available money into envelopes, and spending draws them down.
  • Overspending in one envelope is visibly covered from another, forcing honest reallocation rather than hidden deficits.
  • Rollover: unspent envelope balances carry to next month.

This is fundamentally different from a ledger/reporting tool — the budget is the primary artifact.

Architecture and sync

  • Local-first — the app holds a local copy of your data; it works fully offline. Changes are synced when connected.
  • Sync server — a self-hosted Actual Server coordinates changes across devices using CRDT-style distributed-systems techniques, so concurrent edits from multiple devices merge cleanly.
  • End-to-end encryption — optional E2E encryption means the sync server stores only ciphertext; your budget data is encrypted with a key the server never sees.
  • Data ownership — the underlying data is exportable; you are not locked in.

Bank sync

Actual supports automatic transaction import via GoCardless (formerly Nordigen) for European banks and SimpleFIN for US banks; imported transactions are matched to accounts and categories. You can also import files (CSV/QFX/OFX) manually. Bank sync requires configuring the relevant connector with credentials.

Actual Budget vs Firefly III

Both are open-source self-hosted finance tools but differ in philosophy:

AspectActual BudgetFirefly III

Primary modelEnvelope (zero-based) budgetingDouble-entry bookkeeping + budgets
ArchitectureLocal-first JS app + sync serverPHP web app + database
EncryptionOptional end-to-endServer-side (self-hosted)
StrengthFast, focused budgeting UX, offlineDetailed accounting, rules, reporting, API
Best forHands-on zero-based budgetersFull bookkeeping and analysis

Actual is the lighter, budgeting-first, local-first/offline option; Firefly III is the heavier accounting-oriented ledger. Choose Actual if envelope budgeting and a snappy offline experience matter most; choose Firefly III for full double-entry bookkeeping and rich reporting.

Practical advice and gotchas

  • Envelope budgeting is a discipline, not just an app — the value comes from allocating every available dollar and reallocating when you overspend; using it like a passive expense tracker misses the point.
  • Self-host the sync server for multi-device — a single device works standalone, but syncing across phone/desktop needs the Actual Server; it's lightweight (Docker) and the E2E option keeps the host blind to your data.
  • Bank sync is region-specific — GoCardless (EU) and SimpleFIN (US) cover different regions and require setup/credentials; many users import CSV/OFX manually instead, which always works.
  • Back up your data/server — even local-first, back up the sync server's data; if you rely on a single device, export regularly so a lost device doesn't lose your budget.
  • Reconcile regularly — match imported transactions and reconcile account balances against statements so envelopes reflect reality; stale data undermines the zero-based plan.
  • End-to-end encryption means key responsibility — if you enable E2E and lose the encryption password, the server can't recover your data. Store the key safely.
