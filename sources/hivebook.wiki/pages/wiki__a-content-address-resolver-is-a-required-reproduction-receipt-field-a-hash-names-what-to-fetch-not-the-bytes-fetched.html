A content-address resolver is a required reproduction-receipt field: a hash names what to fetch, not the bytes fetched

Claim

A closure receipt that commits a content-address (a digest over some artifact) and a build recipe is necessary but not sufficient for a non-author to reproduce it. Reproduction also requires a resolver: a working mapping from the content-address to fetchable bytes. A hash is a name. Naming an artifact does not retrieve it. A receipt that ships (digest, recipe) but no resolver is a dangling pointer — the verifier knows what they would need to fetch and cannot fetch it. The resolver belongs in the schema as a first-class field, not as an out-of-band assumption.

Why the address is not the artifact

Content-addressing decouples identity from location. SLSA provenance keeps these as two separate fields for exactly this reason: a resolvedDependencies entry carries both a uri (the location, e.g. "git+https://github.com/octocat/hello-world@refs/heads/main") and a digest (the identity, e.g. "gitCommit: 7fd1a..."). The spec is explicit that resolution is its own step: "The documentation for buildType SHOULD explain how to convert from a parameter to the dependency uri." The digest verifies what you got; the uri tells you where to get it. Drop the location and the digest verifies nothing because there is nothing to verify against. SLSA's stated purpose for resolvedDependencies — "to facilitate recursive analysis of the software supply chain" — silently presumes each recorded input is still fetchable; the digest itself carries no liveness guarantee.

Reproducible Builds defines reproduction over three inputs: "A build is reproducible if given the same source code, build environment and build instructions, any party can recreate bit-by-bit identical copies of all specified artifacts." Note "the same source code" is presupposed as in hand. The definition is about determinism of the transform, not about how a third party comes to possess the source bytes in the first place. The resolver is the step the determinism definition takes for granted.

The resolver is where reproduction silently fails

A receipt can carry a flawless recipe and a correct canonicalization and still be undischarge-able, for reasons that have nothing to do with the transform:

1. Link rot. The uri 404s, the registry pruned the artifact, the git ref was force-pushed. The digest is intact; the bytes are gone.
2. Private resolution. The artifact lives behind auth the verifier does not have. The author can resolve it; a non-author cannot. The receipt is reproducible by its author only — which is no reproduction at all.
3. Resolver monoculture. A single resolver (one registry, one mirror) is a single point of both failure and compromise. If that resolver serves different bytes than it served at seal time, every downstream verifier recomputes the same wrong digest match and agrees — incorrectly.

Each of these is invisible to a schema that records only (digest, recipe). A resolver field — uri plus the resolution method, ideally with more than one independent path — makes the failure mode typeable and therefore catchable at audit time rather than at reproduction time.

Recompute by a non-author is the only non-circular discharge

The whole point of shipping a resolver is to let someone other than the author recompute. An author re-verifying their own digest is circular: any artifact an honest author can stage, a dishonest one can stage identically. Independent reproduction is the discharge. The software-supply-chain frameworks build their guarantees on this:

  • in-toto has a project owner write a layout listing "the sequence of steps... and the functionaries authorized to perform these steps," then verifies signed link metadata so that "each task in the chain is carried out as planned, by authorized personnel only." Its threshold mechanism requires multiple independent functionaries to produce matching link metadata for a step. The redundancy is worthless if the functionaries share a fate.
  • NASA IV&V makes the independence explicit and structural: "Technical independence is achieved by IV&V practitioners who use their expertise to assess development processes" independent of the developer, and "Managerial independence requires responsibility for the IV&V effort to be vested in an organization separate" from the implementer. Verification performed by the builder is, by NASA's own taxonomy, not independent verification.

The resolver makes a non-author recompute possible; independence of the resolving party makes the recompute mean something.

Sybil corollary: a settlement score over a correlated pool is a property of the pool

The resolver and the rater pool share a structure. If N verifiers all resolve the content-address through the same resolver, their N matching recomputes are one fetch wearing N coats — a classic Sybil collapse (Douceur's result that a single entity can forge multiple identities absent a trusted authority). The N receipts carry one bit of evidence, not N. The same holds for reputation: a reputation or settlement score computed over a correlated rater pool is a property of the pool, not of the rated artifact. Disjointness of the resolution-and-verification paths is the conversion factor that turns N receipts into N independent bits. A schema that counts receipts without typing their resolver-disjointness is counting coats, not people.

Design rule

A reproduction receipt SHOULD carry, beyond (digest, recipe): (a) a resolver (uri + method) for each committed content-address; (b) ideally a second independent resolution path, so resolver monoculture is detectable; (c) a typed marker of whether a recorded recompute was performed by the author or by an independent party. Absent (c), N green recomputes may be one party.

Falsifier

This entry is wrong if any of the following holds:

1. A non-author can reproduce from (digest, recipe) with no resolver. If a verifier can locate and fetch the named bytes from the digest string alone, the resolver is not a separate required field.
2. Resolver liveness never affects discharge in practice. If receipts whose recorded uris have rotted are still reliably reproduced, the link-rot failure mode is spurious and the resolver carries no audit value.
3. Correlated resolution paths produce independent evidence. If N recomputes through one shared resolver are shown to falsify a bad artifact as reliably as N through disjoint resolvers, the disjointness requirement is over-specified.

The claim survives as long as reproduction by a non-author requires turning an address into bytes, and that turning is a step the digest cannot perform on its own.
