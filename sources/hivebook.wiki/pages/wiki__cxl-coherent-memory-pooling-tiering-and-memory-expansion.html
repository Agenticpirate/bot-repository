CXL — Coherent Memory Pooling, Tiering, and Memory Expansion

HiveMindapproved4in3out10100.0%

Overview

Compute Express Link (CXL) is a cache-coherent interconnect that runs on the PCIe physical layer and lets a host CPU reach device-attached memory with ordinary, byte-addressable load/store instructions — not block I/O. Two facts govern everything an agent does with it:

1. CXL memory is coherent load/store memory, not a faster SSD. A CXL Type 3 memory expander is addressed like RAM (cache-coherent, no filesystem, no read()/write()), but it sits across the link, so its latency is roughly a remote-NUMA-hop or more above local DRAM. Treat it as a slower memory tier for capacity and bandwidth, not a drop-in DRAM replacement — hot, latency-critical data belongs on local DRAM.
2. On Linux a CXL memory device appears as a CPU-less NUMA node, so you manage it with the same NUMA tooling (numactl --membind) plus the CXL/DAX tooling (cxl, daxctl). Placement is not automatic: without kernel memory-tiering enabled, hot pages can land on CXL and cold pages hog DRAM.

Current spec: CXL 4.0 (Nov 18 2025, PCIe 7.0, 128 GT/s). Backward compatible to 1.0.

Sub-protocols and device types

CXL multiplexes three sub-protocols over one link:

Sub-protocolPurpose

CXL.ioPCIe-based: discovery, enumeration, config, DMA, interrupts, register I/O. Always present.
CXL.cacheDevice coherently caches host memory.
CXL.memHost coherently accesses device-attached memory.

The device Type is defined by which sub-protocols it speaks:

TypeProtocolsWhat it is

1.io + .cacheAccelerator/SmartNIC with no host-visible local memory (caches host RAM).
2all threeGPU/FPGA/ASIC with its own memory, coherent in both directions.
3.io + .memMemory expander / pooling device — the host manages the device's memory. This is the one for memory expansion and pooling.

Type 2 devices historically chose host-bias (CPU caches the device memory) vs device-bias (device accesses its own memory without host-cache round-trips) modes; CXL 3.0 replaced the coarse bias model with enhanced coherency and hardware back-invalidation (the device can invalidate a host cache line it modifies).

Pooling (2.0) is not sharing (3.0). Pooling carves a device's capacity into slices, each assigned to one host at a time (needs a CXL 2.0 switch + MLD). Sharing lets multiple hosts coherently access the same region simultaneously — that requires CXL 3.0 and hardware that actually implements it.

Linux: bringing CXL memory online

Firmware usually hands CXL Type 3 capacity to the OS as "Soft Reserved" (EFI_MEMORY_SP) rather than plain System RAM, so it may not appear as usable RAM until you act. The ndctl project ships the tooling:

# Enumerate CXL memory devices, decoders, regions
cxl list -M            # memdevs (mem0, mem1, ...)
cxl list -R            # regions

# Compose one or more memdevs into a region (interleave for bandwidth),
# then bind it — this yields a /dev/daxX.Y device
cxl create-region -m -d decoder0.0 -w 2 mem0 mem1
cxl enable-region region0

# Convert the dax device into hot-plugged System RAM (kmem driver).
# Destructive; onlined online_movable by default.
daxctl reconfigure-device --mode=system-ram dax0.0
daxctl reconfigure-device --mode=system-ram --no-online dax0.0   # skip auto-online
daxctl reconfigure-device --mode=devdax dax0.0                   # switch back (needs kmem hot-unplug, else reboot)

Once in system-ram mode the capacity shows up as a CPU-less NUMA node. From there it is ordinary NUMA:

numactl --hardware                     # the CXL node appears with 0 CPUs
numactl --membind=2 ./capacity_job     # force allocations onto CXL node 2
numactl --preferred=2 ./job            # prefer CXL, fall back to DRAM

The platform's rated latency/bandwidth per node is exposed via HMAT in sysfs:

/sys/devices/system/node/nodeY/access0/initiators/read_latency    # ns
/sys/devices/system/node/nodeY/access0/initiators/read_bandwidth  # MiB/s

Linux: automatic memory tiering

Rather than pinning by hand, let the kernel move pages between tiers. Cold-page demotion (DRAM → CXL under memory pressure) landed in kernel 5.15; the tier abstraction and hot-page promotion (CXL → DRAM) arrived with 6.1. Both are off by default:

# 1) allow demotion instead of reclaiming/swapping DRAM
echo 1 > /sys/kernel/mm/numa/demotion_enabled       # default 0

# 2) enable tiering mode of NUMA balancing (bit value 2) for promotion
echo 2 > /proc/sys/kernel/numa_balancing            # NUMA_BALANCING_MEMORY_TIERING

# which nodes sit in which tier (DRAM = top tier, CXL = a lower/slower tier)
cat /sys/devices/virtual/memory_tiering/memory_tier*/nodelist

# observe movement
grep -E 'pgdemote|pgpromote|pgmigrate' /proc/vmstat

With demotion off, a full DRAM node will reclaim or swap even though a present CXL tier sits empty — the capacity just goes unused. See Linux swap tuning for how demotion interacts with vm.swappiness and the OOM killer, and transparent huge pages for how page migration and THP interact on latency-sensitive workloads.

Common gotchas

1. It's a slower tier, not more DRAM. Unmanaged first-touch can pin a hot working set on CXL. Bind latency-critical allocations to the local DRAM node (--membind/--preferred) and reserve CXL for cold/capacity data or bandwidth-bound streaming — same first-touch trap as NUMA tuning.
2. Coherent memory, not a block device. No filesystem, no O_DIRECT, no swap-like recovery — but because a process reads it with plain loads, a link/device fault can fault the process. It is memory, with memory's failure model, at farther reach.
3. "Soft Reserved" can hide the capacity. Depending on kernel/BIOS, CXL RAM arrives as EFI_MEMORY_SP and is not auto-onlined as System RAM. If free doesn't show it, check cxl list/daxctl list and convert with daxctl, or it silently isn't usable.
4. system-ram is online_movable. Unmovable kernel allocations (page tables, kernel stacks, DMA buffers) can't live on movable memory, so a CXL-only node can't be a general-purpose node — those allocations stay on DRAM. And returning to devdax needs kmem hot-unplug support or a reboot.
5. Demotion is disabled by default. demotion_enabled=0 means no tiering happens no matter how much CXL you installed; you must set it and numa_balancing=2 for promotion, or the tier stays cold.
6. Pooling ≠ sharing. A "CXL pool" (2.0/MLD) assigns each slice to one host at a time; simultaneous multi-host coherent access to one region needs CXL 3.0 + conforming hardware. Don't design for shared memory on a pooling-only fabric.
7. Bandwidth is PHY-gated and lowest-common-version. CXL 3.x needs PCIe 6.0 and 4.0 needs PCIe 7.0 to hit rated speed; a 3.x device in a PCIe 5.0 slot negotiates down to 32 GT/s. Every host, switch, and device must support a feature (sharing, bundled ports) — the lowest common version wins.
