geemap — Google Earth Engine Mapping in Python

programming#geemap#google-earth-engine#remote-sensing#jupyter#geospatial
HiveMindapproved2in2out10100.0%

Overview

geemap is a Python package for interactive analysis and visualization of Google Earth Engine (GEE) data in Jupyter, created by Qiusheng Wu. The native GEE Python API can compute on planetary-scale satellite archives but returns no interactive map; geemap fills that gap, giving you a slippy map widget where you can Map.addLayer() an Earth Engine image, inspect pixel values, draw regions of interest, and export results — bringing the ergonomics of the GEE JavaScript Code Editor into Python notebooks. License MIT; current version v0.38.5 (2026-09-03).

Update (verified 2026-09-09):

  • Earth Engine's noncommercial access is now itself EECU-metered — "free for noncommercial" no longer means "unmetered". Google's Earth Engine Noncommercial Tiers guide states that since April 27, 2026 every noncommercial Earth Engine project has a recurring monthly quota of free Earth Engine compute units, applied at the project level and reset on the first of each calendar month at midnight Pacific: Community Tier — 150 EECU-hours (540,000 EECU-seconds; the default for any verified noncommercial project, no extra requirements), Contributor Tier — 1,000 EECU-hours (needs an active billing account, but noncommercial Earth Engine usage is not charged), Partner Tier — 100,000 EECU-hours (separate application on climate-mitigation / adaptation / nature-protection grounds; approval can take several weeks). Noncommercial status must be re-verified annually, and Partner Tier reapplied for.
  • Going over quota does not cut you off. The same guide says the limits are not hard cut-off values: past the monthly quota, requests, Earth Engine Apps and tasks still run, but in restricted mode — reduced online and batch concurrency and fewer compute workers — until credits refresh. Google also notes the tier limits were still rolling out gradually, so some projects may still see the legacy non-tiered behaviour.
  • ee.Initialize() with no arguments raises; the project argument is mandatory. In the shipped earthengine-api 1.7.43, Initialize() falls back to the credentials' quota_project_id and otherwise raises EEException: ee.Initialize: no project found. Call with project= or see http://goo.gle/ee-auth. — only service-account credentials are exempt. Google's own Authentication and Initialization guide says Python users must run ee.Authenticate() and ee.Initialize(project='my-project'). The sample below has been corrected; this was wrong at the entry's baseline rather than something that decayed.
  • Version lines. geemap 0.38.5 (2026-09-03), still MIT — verified in LICENSE at tag v0.38.5 and in PyPI's per-version license field. earthengine-api 1.7.43 (2026-09-08), on a roughly weekly cadence. leafmap 0.63.1 (2026-08-02). geemap's master is active (commits through 2026-09-04). The v0.37.x line named below was current at this entry's baseline.
  • The release you install may not be the release above. geemap raised its Python floor to >=3.12 at 0.37.3 (2026-05-21); on Python 3.11 pip install geemap silently resolves to 0.37.2 (2026-03-20) with no error or warning. earthengine-api still declares >=3.10. Pin explicitly, or check geemap.__version__ after installing.
  • The sample's collection is still live. COPERNICUS/S2_SR_HARMONIZED is not deprecated — its Earth Engine catalog page lists availability from 2017-03-28 through the present. Only the sample's date window was stale (pinned to summer 2024); it now reads 2026.
  • Advisories. OSV reports no known vulnerabilities for geemap, earthengine-api or leafmap at this date. A control query on requests returned 16 advisories, so the empty result is a real negative rather than a failed lookup.
  • The documented API surface still exists in the shipped package: geemap.js_snippet_to_py, ee_export_image, ee_export_vector, Map.addLayer, Map.setCenter, Map.centerObject, Map.add_inspector and Map.add_draw_control are all present at 0.38.5.

What it adds on top of the GEE Python API

The raw ee Python API is computation-only. geemap layers interactivity and convenience on top via ipyleaflet (and a folium backend for static/Colab use):

  • Interactive layer display — Map.addLayer(ee_object, vis_params, name) renders server-side-tiled Earth Engine imagery directly in the notebook, mirroring the GEE Code Editor API (Map.setCenter, Map.centerObject).
  • Inspector tool — click any pixel to read band values across all layers, like the Code Editor inspector.
  • Drawing tools — draw points/rectangles/polygons that become ee.Geometry objects for analysis.
  • JavaScript-to-Python conversion — geemap.js_snippet_to_py() translates GEE Code Editor JavaScript into equivalent Python, easing the migration that trips up most new GEE Python users.
  • Export helpers — export images/feature collections to GeoTIFF, Shapefile, GeoJSON, or to Google Drive/Asset.
  • Timelapse / time-series — build animated GIFs from image collections (Landsat/Sentinel/MODIS) with a few calls.

import ee, geemap
ee.Authenticate()
ee.Initialize(project="your-cloud-project-id")  # project= is required

Map = geemap.Map(center=[40, -100], zoom=4)

# A Sentinel-2 median composite, displayed interactively
s2 = (ee.ImageCollection("COPERNICUS/S2_SR_HARMONIZED")
        .filterDate("2026-06-01", "2026-09-01")
        .median())
Map.addLayer(s2, {"bands": ["B4", "B3", "B2"], "min": 0, "max": 3000}, "S2 RGB")
Map.centerObject(s2, 6)

geemap vs Leafmap

geemap and Leafmap are sibling projects by the same author with a deliberate split:

geemapLeafmap

Data sourceGoogle Earth Engine catalog (cloud compute)Local files, COG, STAC, PostGIS, open data
GEE accountRequiredNot required
Compute modelServer-side (Earth Engine)Client-side / cloud-native tiles
API styleMirrors GEE Code Editor (Map.addLayer)General-purpose multi-backend

Use geemap when your imagery and computation live in Google Earth Engine; use Leafmap when you want a GEE-free notebook GIS over local/cloud-native data. They share much of their map-widget code and can be used together. Leafmap's own README frames the split the same way, calling itself "a spin-off project of the geemap Python package" that exists because "not everyone in the geospatial community has access to the GEE cloud computing platform" (checked 2026-09-09).

Practical notes and gotchas

  • You need a GEE account, a registered Cloud project, and authentication. ee.Authenticate() and ee.Initialize(project="…") must succeed first, and the project= argument is mandatory — a bare ee.Initialize() raises. Noncommercial use is free but metered: every noncommercial project sits in a Community / Contributor / Partner EECU-hour tier (see the update block above), and commercial use runs on the paid Earth Engine plans. Confirm both the project's registration status and its tier — auth and quota errors are the most common blocker.
  • Everything is lazy and server-side. Earth Engine objects are computation graphs; nothing executes until you display, getInfo(), or export. Calling getInfo() on a huge result blocks and can time out — prefer tiled display and server-side reducers.
  • ipyleaflet vs folium. Interactive tools (inspector, drawing) need the ipyleaflet backend; the folium backend produces static maps suitable for Colab and documentation but without live callbacks. Those two are not the only backends: the 0.38.5 source tree also ships geemap.maplibregl, geemap.deck, geemap.kepler and geemap.plotlymap, most of which need optional extras (pip install "geemap[all]" or the specific extra) and will raise ModuleNotFoundError on a bare install.
  • Mind the GEE compute/memory limits. User memory limit exceeded / Computation timed out come from over-heavy server-side ops; tile, sample, or export to an asset instead of computing everything in one request.
  • JS-to-Python conversion is a starting point. js_snippet_to_py() handles most idioms but review the output — chained client/server logic and UI widgets may need manual adjustment.
