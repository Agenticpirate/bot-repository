WireGuard: Configuration, Cryptokey Routing, and Performance

Overview

WireGuard is a modern, Layer 3 VPN protocol designed for simplicity, auditability, and high performance. Created by Jason A. Donenfeld, its Linux kernel module is approximately 4,000 lines of code — compared to ~100,000 for OpenVPN and ~13,000 for IPsec XFRM. It operates exclusively over UDP (default port 51820), uses a fixed set of modern cryptographic primitives, and has been in the Linux mainline kernel since version 5.6 (March 2020). Native clients exist for Windows, macOS, iOS, Android, and FreeBSD.

Cryptographic Design

WireGuard uses the Noise Protocol Framework (Noise_IKpsk2 handshake pattern):

ComponentAlgorithmPurpose

Key exchangeCurve25519 (ECDH)Derive shared secrets
EncryptionChaCha20-Poly1305 (RFC 7539)Authenticated encryption
HashingBLAKE2sMAC and key derivation
Key derivationHKDF (RFC 5869)Session keys from handshake

The handshake completes in 1 round trip, provides perfect forward secrecy, and rotates session keys every 120 seconds. No cipher negotiation — the fixed primitive set eliminates downgrade attacks.

Key Generation

Similar to SSH key generation:

umask 077 && wg genkey > privatekey
wg pubkey < privatekey > publickey
# Combined one-liner
wg genkey | tee privatekey | wg pubkey > publickey

Configuration

Server (/etc/wireguard/wg0.conf):

[Interface]
PrivateKey = SERVER_PRIVATE_KEY
Address = 10.0.0.1/24
ListenPort = 51820
PostUp = nft add rule inet filter forward iifname wg0 accept
PostDown = nft delete rule inet filter forward iifname wg0 accept

[Peer]
PublicKey = CLIENT_PUBLIC_KEY
AllowedIPs = 10.0.0.2/32

Client:

[Interface]
PrivateKey = CLIENT_PRIVATE_KEY
Address = 10.0.0.2/32
DNS = 1.1.1.1

[Peer]
PublicKey = SERVER_PUBLIC_KEY
Endpoint = 203.0.113.1:51820
AllowedIPs = 0.0.0.0/0, ::/0
PersistentKeepalive = 25

PostUp/PostDown can run nftables rules. Enable as a systemd service: systemctl enable --now wg-quick@wg0.

Cryptokey Routing

WireGuard's core concept maps each peer's public key to allowed tunnel IPs (AllowedIPs):

  • Sending: AllowedIPs = routing table — destination IP determines which peer's key encrypts the packet
  • Receiving: AllowedIPs = ACL — after decryption, source IP must match or the packet is dropped

AllowedIPs = 0.0.0.0/0 = full tunnel. AllowedIPs = 10.0.0.2/32 = split tunnel.

Performance

Official benchmarks (Intel i7, gigabit Ethernet, iperf3):

MetricWireGuardIPsec (AES-GCM)OpenVPN

Throughput1,011 Mbps881 Mbps258 Mbps
Ping latency0.403 ms0.508 ms1.541 ms
CPU saturatedNoYesYes

Connection establishment: milliseconds (1 RTT) vs 1–5s for IPsec/IKEv2 and 5–15s for OpenVPN.

Common Gotchas

No dynamic IP resolution: Endpoint hostnames resolve only at startup. Use PersistentKeepalive = 25 for peers with changing IPs.

No built-in key distribution: No PKI or certificates. Keys exchanged out-of-band. For scale, use Tailscale, Netmaker, or Headscale.

MTU must be correct: Encapsulation adds 60 bytes (IPv4) or 80 bytes (IPv6). Set WireGuard MTU to 1420 on standard 1500-byte links. Wrong MTU causes mysterious packet loss.

UDP only: No TCP fallback. Corporate firewalls blocking UDP will block WireGuard. Workaround: udp2raw or wstunnel TCP wrappers.

NAT traversal: Set PersistentKeepalive = 25 on clients behind NAT to prevent mapping table expiry.
