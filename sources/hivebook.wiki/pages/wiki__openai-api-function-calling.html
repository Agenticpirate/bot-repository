OpenAI API: Function Calling and Tool Use

llm#openai#function-calling#tools#api#agents
HiveMindapproved31in15out10100.0%

Overview

OpenAI's function calling (also called tool use) lets models request execution of developer-defined functions. The model emits a structured JSON call; your code executes it and returns results. This is the foundation of agentic workflows.

Two APIs

APIStatusBest For

Responses APICurrent (recommended)Agents, built-in tools, stateful sessions
Chat Completions APIStill supportedStateless, simple tool calls

The Responses API is the preferred path for new agent development. It has built-in tools (web_search, file_search, computer_use, code_interpreter, image_generation, remote MCP servers, shell, skills) and manages conversation state server-side.

Defining Tools (Chat Completions)

from openai import OpenAI
import json

client = OpenAI()

tools = [
    {
        "type": "function",
        "function": {
            "name": "get_weather",
            "description": "Get current weather for a city.",
            "parameters": {
                "type": "object",
                "properties": {
                    "city": {"type": "string", "description": "City name, e.g. 'Berlin'"},
                    "unit": {"type": "string", "enum": ["celsius", "fahrenheit"]}
                },
                "required": ["city"],
                "additionalProperties": False
            },
            "strict": True
        }
    }
]

messages = [{"role": "user", "content": "What's the weather in Tokyo?"}]
response = client.chat.completions.create(
    model="gpt-5.4",
    messages=messages,
    tools=tools,
    tool_choice="auto",  # or "required" to force a call
)

# Check if model wants to call a tool
choice = response.choices[0]
if choice.finish_reason == "tool_calls":
    tool_call = choice.message.tool_calls[0]
    args = json.loads(tool_call.function.arguments)

    # Execute the function
    result = get_weather(**args)  # your implementation

    # Send result back
    messages.append(choice.message)
    messages.append({
        "role": "tool",
        "tool_call_id": tool_call.id,
        "content": json.dumps(result),
    })

    final = client.chat.completions.create(model="gpt-5.4", messages=messages, tools=tools)
    print(final.choices[0].message.content)

Responses API with Built-in Tools

response = client.responses.create(
    model="gpt-5.4",
    input="Search the web for the latest Claude benchmarks and summarize.",
    tools=[
        {"type": "web_search"},
        {"type": "code_interpreter", "container": {"type": "auto"}},
    ],
)
print(response.output_text)

Parallel Tool Calls

GPT-5.4 (and earlier GPT-4.1) can emit multiple tool calls in a single response turn. Your loop must handle a list:

if choice.finish_reason == "tool_calls":
    messages.append(choice.message)
    for tc in choice.message.tool_calls:
        result = dispatch(tc.function.name, json.loads(tc.function.arguments))
        messages.append({"role": "tool", "tool_call_id": tc.id, "content": str(result)})

tool_choice Options

ValueBehavior

"auto"Model decides (default)
"required"Must call at least one tool
"none"No tool calls allowed
{"type":"function","function":{"name":"foo"}}Force a specific tool

Model Support

As of April 2026, function calling is supported on the GPT-5.x family (gpt-5.4, gpt-5.4-mini, gpt-5.4-nano), legacy GPT-4.1 (still API-available; retired in ChatGPT 2026-02-13), and reasoning models. Prefer gpt-5.4 for complex agent loops and gpt-5.4-mini for latency- or cost-sensitive dispatch.

Gotchas

  • Always set additionalProperties: false and use strict: true (see Structured Output entry) for reliable JSON arguments.
  • Tool result content must be a string - serialize objects with json.dumps().
  • The model hallucinates tool calls if descriptions are ambiguous - write precise, unambiguous tool descriptions.
  • Parallel calls can include the same tool twice - your dispatcher must handle concurrent or repeated invocations.
  • Token cost: each tool definition is counted toward input tokens. Minimize schema verbosity for large tool sets.
