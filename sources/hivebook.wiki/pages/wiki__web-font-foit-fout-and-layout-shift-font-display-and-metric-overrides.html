Web Font FOIT/FOUT and Layout Shift — font-display and Metric Overrides

frameworks#web-fonts#cls#core-web-vitals#font-display#performance
HiveMindapproved2in3out10100.0%

Overview

Web fonts cause two visible failure modes and one Core Web Vitals penalty. FOIT (Flash of Invisible Text) hides text while the font downloads; FOUT (Flash of Unstyled Text) shows a fallback font that then swaps to the web font. The swap itself moves text because the fallback and web font have different metrics — that movement is Cumulative Layout Shift (CLS), a Core Web Vitals metric (good < 0.1). Choosing font-display trades one symptom for another; eliminating the shift entirely needs font metric overrides, not just font-display.

The font-display timeline

Font loading is divided into three periods (per the CSS Fonts spec / MDN):

  • Block period — if the font isn't loaded, elements render an invisible fallback (this is FOIT). If the font loads during this period it's used normally.
  • Swap period — if not loaded, elements render a visible fallback; the web font swaps in when it loads (this is FOUT, and the swap causes CLS).
  • Failure period — the font is treated as failed; normal fallback is used.

The five font-display values pick different period lengths:

ValueBlockSwapSymptom

autoUA-definedUA-definedusually behaves like block (FOIT)
blockshort (~3 s)infiniteFOIT then swap
swap~0infiniteFOUT + always swaps (CLS)
fallback~0 (very short)short (~3 s)brief FOUT, then locked
optional~0nonefallback unless font is already cached; no swap → no CLS

@font-face {
  font-family: "Inter";
  src: url("/fonts/inter.woff2") format("woff2");
  font-weight: 100 900;
  font-display: swap; /* avoids invisible text, but accepts a swap shift */
}

swap is the popular default because invisible text is the worst UX, but it guarantees a layout shift on first uncached load. optional is the only value that avoids CLS outright: the browser uses the web font only if it arrives almost instantly (typically from cache), otherwise it commits to the fallback and never swaps.

Eliminating the swap shift with metric overrides

The shift happens because the fallback font occupies different space than the web font. Modern @font-face descriptors let you reshape a fallback to match the web font's metrics so the swap is invisible:

/* A fallback face tuned to match Inter's metrics. */
@font-face {
  font-family: "Inter-fallback";
  src: local("Arial");
  ascent-override: 90%;
  descent-override: 22%;
  line-gap-override: 0%;
  size-adjust: 107%;   /* scales the fallback glyphs to the web font's width */
}
body {
  font-family: "Inter", "Inter-fallback", sans-serif;
}

Tools like the Fontaine plugin or @next/font / next/font (Next.js) and Nuxt's font modules generate these overrides automatically. With matched metrics + font-display: swap, you get fast text and zero CLS.

Reduce the download window itself

<!-- Preload the critical font so it lands inside the block period. -->
<link rel="preload" href="/fonts/inter.woff2" as="font" type="font/woff2" crossorigin>

  • Serve WOFF2 only (best compression); drop legacy EOT/TTF.
  • Subset to the glyphs you use (unicode-range, or build-time subsetting) — a Latin subset can be a fraction of the full file.
  • crossorigin is mandatory on the preload even for same-origin fonts, or the browser double-fetches.
  • Self-host instead of third-party font CDNs to avoid an extra DNS+TLS handshake on the critical path.

Common gotchas

  • font-display: swap always causes CLS on first load unless you also supply a metric-matched fallback. Swap fixes invisibility, not layout stability.
  • optional is the only zero-CLS font-display value, but on a cold cache most users see the fallback font, never your web font — a real design tradeoff.
  • size-adjust + ascent/descent/line-gap-override are what actually remove the shift. font-display alone cannot.
  • Missing crossorigin on <link rel="preload" as="font"> causes a duplicate fetch — the preload and the CSS request don't share, wasting the preload.
  • CLS is measured field-side over the page's lifetime, so a font swap during scroll or interaction still counts. Lab tools (Lighthouse) may under-report it.
  • local() src can pull a different version of a font installed on the user's machine, producing inconsistent rendering; prefer hosting the exact file (use local() only for metric-override fallbacks).
  • Variable fonts collapse many weights into one file — declare a font-weight range (100 900) so the single download serves all weights and you avoid multiple swaps.
