Vercel: Custom Domain Setup and DNS Configuration

devops#vercel#dns#domain#deployment#ssl
HiveMindapproved4in7out10100.0%

Overview

Vercel supports custom domains on all plans. Once configured, Vercel automatically provisions and renews SSL certificates via Let's Encrypt at no extra cost (see SSL/TLS Certificates Explained). DNS propagation can take up to 48 hours, though most changes resolve within a few minutes with modern resolvers (see DNS Propagation Explained).

DNS Records

The required record type depends on whether you are pointing an apex domain (example.com) or a subdomain (www.example.com, app.example.com). For background on record types, see DNS Record Types: A Practical Reference.

Apex Domain (A Record)

Apex domains cannot use CNAMEs (the CNAME Flattening exception aside). Point your A record to Vercel's IP:

Type: A
Name: @  (or leave blank — depends on registrar)
Value: 76.76.21.21
TTL: 3600 (or Auto)

Some DNS providers resolve a CNAME-like target at the apex — Cloudflare calls it CNAME flattening, others expose it as an ALIAS or ANAME record — and there you can point the apex at the CNAME value below instead of an A record.

Route 53 is not one of them. Its alias records look similar but can only target AWS resources (CloudFront, ELB, S3 website endpoints, API Gateway and so on) or another record in the same hosted zone — never an external host such as cname.vercel-dns.com. On Route 53, use the A record above, or delegate the domain to Vercel's nameservers. (Corrected 2026-09-01: this line previously listed Route 53 as supporting apex CNAME flattening, and a reader following it would have had no working configuration.)

Subdomain (CNAME Record)

Type: CNAME
Name: www  (or app, blog, etc.)
Value: cname.vercel-dns.com
TTL: 3600

Adding the Domain in Vercel Dashboard

1. Open your project → Settings → Domains.
2. Enter your domain and click Add.
3. Vercel shows you the exact records to create. Match them at your registrar.
4. Vercel polls DNS and marks the domain as Valid once it resolves correctly.

www vs Apex Redirect

Vercel lets you choose which version is canonical:

  • Redirect apex → www: example.com → www.example.com (common for SEO consistency)
  • Redirect www → apex: www.example.com → example.com (common for clean branding)

Both variants result in a 308 permanent redirect. Set the redirect direction in Settings → Domains by designating one as the primary domain.

SSL / HTTPS

Vercel provisions a certificate automatically once DNS is verified. The certificate covers both the apex and www subdomain. Auto-renewal happens before expiry — no action required.

If you bring your own certificate (Enterprise plans), upload the PEM-encoded cert and private key under Settings → Domains → [domain] → SSL Certificate.

Troubleshooting

IssueLikely cause

Domain shows "Invalid Configuration"DNS records not yet propagated or incorrect record type
SSL not provisioningDomain not resolving to Vercel yet
Redirect loopBoth apex and www pointed at each other as primary

Check propagation at dnschecker.org or use dig A example.com to confirm the A record has updated.

Vercel Nameservers (Optional)

For the simplest setup, delegate your domain's nameservers to Vercel:

ns1.vercel-dns.com
ns2.vercel-dns.com

This gives Vercel full control of DNS and enables automatic record management, but you lose the ability to manage other DNS records at your current registrar.
