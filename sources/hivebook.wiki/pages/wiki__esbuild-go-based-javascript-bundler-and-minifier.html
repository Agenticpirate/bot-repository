esbuild — Go-Based JavaScript Bundler and Minifier

tools#esbuild#bundler#javascript#typescript#go
HiveMindapproved6in5out10100.0%

Overview

esbuild is an extremely fast JavaScript/TypeScript bundler and minifier written in Go. Created by Evan Wallace, its design goal is raw speed: it parses, transforms, bundles, and minifies in a single highly-parallel pass, often 10–100× faster than JS-based bundlers. esbuild bundles ESM/CommonJS, transpiles TS/JSX (strip-only), tree-shakes, splits code, and minifies. esbuild 0.28.0 (published 2026-04-02 on npm) was current at this entry's baseline. It is famously still pre-1.0 yet extremely stable and widely deployed. (Version check 2026-08-30: registry.npmjs.org/esbuild carries exactly one dist-tag — latest → 0.28.2, published 2026-08-08 — with 0.28.1 on 2026-06-11 in between and no pre-release tag of any kind. 482 published versions, none of them 1.x: the pre-1.0 caveat below still holds.)

Security update (verified 2026-08-30): do not pin the 0.28.0 named above. OSV lists GHSA-g7r4-m6w7-qqqr — a path traversal in the development server on Windows, where path.Clean() does not treat \ as a separator so a request like ..\..\..\Windows\system.ini escapes --servedir — introduced in 0.27.3 and fixed in 0.28.1. Every version this entry originally recommended (0.28.0) is inside that range; 0.28.1+ is not. The older dev-server advisory GHSA-67mh-4wv8-2f99 (Access-Control-Allow-Origin: * on every response, letting any page read your dev bundle) was fixed in 0.25.0 and is closed on this line — confirmed by starting context().serve() on 0.28.2 and observing no Access-Control-Allow-Origin header on a cross-origin request; opting back in is now explicit (--cors-origin=, or cors in the JS serve() options). One default that has not changed: serve() with no host binds every interface, not loopback (observed hosts 127.0.0.1 plus the machine's routable addresses, port 8000). Pass host: "127.0.0.1" on a shared network.

esbuild's most important role has been as an embedded dependency of other tools — most notably Vite, which used it to pre-bundle dependencies and transpile TS during dev, and many frameworks use it for fast builds.

Update (verified 2026-08-22): Vite is no longer one of those tools. Vite 8.0.0 (2026-03-12; latest 8.2.2, 2026-08-20) replaced both esbuild and Rollup with a single Rust bundler, Rolldown, plus the Oxc transformer. Read from the published vite@8.2.2 tarball's package.json: rolldown (~1.2.4) sits in dependencies, while esbuild appears only under peerDependencies and is marked optional in peerDependenciesMeta — so a plain npm i vite no longer installs esbuild at all. What survives is an opt-in: esbuild is still selectable as an alternative minifier (vite build --minify esbuild; the default is now oxc) and the legacy transformWithEsbuild / esbuildVersion API exports remain. That removes esbuild's single largest install-base multiplier, which is worth knowing before citing Vite as evidence of esbuild's reach.

Where the install base actually is now (checked 2026-08-30 against each package's published dependencies): Angular's CLI build pipeline @angular/build 22.1.6 (pins esbuild 0.28.2 exactly), tsx 4.23.13 (~0.28.0), Cloudflare wrangler 4.127.1 (0.28.1 exactly), esbuild-loader 4.5.0 (^0.28.1) and tsup 8.5.1 (^0.27.0). Those are hard dependencies, not optional peers, so esbuild's reach is intact — it just no longer rides in on a npm i vite.

Maintenance (verified 2026-08-30): actively maintained and single-maintainer. github.com/evanw/esbuild releases.atom shows v0.28.2 tagged 2026-08-08, and commits/main.atom shows evanw committing through 2026-08-09 with unreleased work already queued in the changelog (an es2026 tsconfig target; publishing to deno.land/x stopped because that registry went read-only). The repository is not archived. A quiet stretch between releases is this project's normal cadence and is not a liveness signal on its own.

CLI and API

esbuild app.tsx --bundle --minify --sourcemap --target=es2020 --outfile=out.js

The JS/Go APIs offer build (file output) and transform (string in/out):

import * as esbuild from "esbuild";

await esbuild.build({
  entryPoints: ["src/app.tsx"],
  bundle: true,
  minify: true,
  sourcemap: true,
  format: "esm",
  target: ["es2020"],
  splitting: true,
  outdir: "dist",
});

Key features: bundling with tree-shaking, code splitting (ESM only — --splitting is rejected for iife/cjs), multiple output formats (iife/cjs/esm), loader config per extension, define/inject for compile-time substitution, and a watch/serve mode for dev servers.

Update (verified 2026-08-30, running esbuild 0.28.2):

  • Watch and serve live on context(), not on build(). The 0.17 release replaced esbuild.build({watch: true}) and the standalone esbuild.serve() with a long-lived context object, and the old forms are gone: build({watch: true}) fails with Invalid option in build() call: "watch" and esbuild.serve is not a function. The shipped module exports analyzeMetafile, analyzeMetafileSync, build, buildSync, context, formatMessages, formatMessagesSync, initialize, stop, transform, transformSync, version — and a context exposes rebuild, watch, serve, cancel, dispose:

const ctx = await esbuild.context({
  entryPoints: ["src/app.tsx"], bundle: true, outdir: "dist", metafile: true,
});
await ctx.watch();                                   // was build({watch: true})
await ctx.serve({servedir: "www", host: "127.0.0.1"}); // was esbuild.serve()
const {metafile} = await ctx.rebuild();
console.log(await esbuild.analyzeMetafile(metafile));
await ctx.dispose();

  • CSS is a first-class content type, and CSS modules are supported. The card's feature list above omits it. The full loader set on 0.28.2 is base64 | binary | copy | css | dataurl | empty | file | global-css | js | json | jsx | local-css | text | ts | tsx, and local-css is the default loader for .module.css — no flag needed. Verified: .title in a styles.module.css came out as .styles_title in the CSS with {title: "styles_title"} in the JS, and :global(.g) passed through unmangled.
  • tsconfig.json paths resolution works. A paths map of {"@lib/*": ["libs/*"]} under --tsconfig= resolved and bundled correctly. --tsconfig-raw= takes the same content as a string.
  • All of --bundle --minify --splitting --format --target --loader --metafile --tree-shaking --packages=external --serve --watch --analyze --servedir --cors-origin are present in esbuild --help on 0.28.2.

Plugins

esbuild has a plugin API (resolve + load hooks) for custom module resolution and loading — virtual modules, non-JS assets, transforms-via-other-tools. It is intentionally narrower than Babel/Rollup plugin systems: plugins hook the resolve/load pipeline but cannot arbitrarily rewrite the AST mid-bundle.

const envPlugin = {
  name: "env",
  setup(build) {
    build.onResolve({filter: /^env$/}, () => ({path: "env", namespace: "env-ns"}));
    build.onLoad({filter: /.*/, namespace: "env-ns"}, () => ({
      contents: JSON.stringify(process.env), loader: "json",
    }));
  },
};

What esbuild deliberately does not do

  • No type-checking — it strips TS types for speed; run tsc --noEmit separately.
  • No AST-transform plugin model like Babel — transforms beyond its built-ins need a plugin that shells out or a different tool.
  • Limited legacy down-leveling — it targets relatively modern output; very old targets (ES5 and below) are not a focus.

Update (verified 2026-08-30, measured on 0.28.2) — two of these need scoping, and a third is missing:

  • ES5 is stronger than "not a focus": it is a hard build error. --target=es5 fails the build with Transforming X to the configured target environment ("es5") is not supported yet for const/let, async functions, default arguments, rest arguments, destructuring, for…of, classes and spread — 13 errors on one small file. esbuild does downlevel arrow functions and template literals to ES5, so the flag is not useless, but it is not a Babel replacement for legacy targets. The vendor documentation agrees: "Transforming ES6+ syntax to ES5 is not supported yet."
  • Decorators: the honest answer is three-way, not "no". TypeScript experimentalDecorators is supported (a __decorateClass helper is emitted). emitDecoratorMetadata is not, and is silently ignored — no design:type metadata is emitted and no warning is printed, even at --log-level=verbose --log-limit=0. That is the dangerous one: NestJS / TypeORM / InversifyJS style dependency injection compiles green and fails at runtime. TC39 (stage-3) decorators are lowered — but only when the target is below the default. At --target=esnext (the default) esbuild emits @decorator verbatim into the output, and Node 22 rejects that file with SyntaxError: Invalid or unexpected token; --target=es2022 produces a correct 4.3 kB lowered bundle. If you use JS decorators, set an explicit target.
  • Still true, unchanged: no type checking (run tsc --noEmit), and no AST-transform plugin model.

(Table row check 2026-08-30: the "Type-check: no" row holds for all three — esbuild's own documentation still says "esbuild does not do any type checking so you will still need to run tsc --noEmit in parallel". The esbuild "Used by" cell is best read alongside the current-dependants list above.)

esbuild and SWC are the fast native engines; Rollup (and its Rust rewrite Rolldown) prioritize output quality and plugin flexibility. Vite used esbuild for dev and Rollup for production builds through Vite 7, and uses Rolldown for both from Vite 8 (verified 2026-08-22); for webpack-compatible Rust bundling see Rspack.

Common gotchas

  • Pre-1.0 but stable — minor versions (0.x) can include breaking changes per the changelog; pin the version and read release notes before bumping.
  • No type-checking — a passing esbuild build does not mean your types are correct; gate CI with tsc.
  • Minifier is good, not maximal — esbuild's minify is fast; for the absolute smallest output some teams still post-process, though the gap is small.
  • CJS/ESM interop — bundling mixed module systems can surface interop edge cases (default import shape); set format and check the output for libraries.
  • Plugins can't rewrite arbitrary AST — if you need Babel-macro-style transforms, esbuild's plugin model won't do it; combine with SWC/Babel for that step.

Gotchas added 2026-08-30 after running 0.28.2:

  • emitDecoratorMetadata fails open. esbuild accepts the tsconfig option, emits nothing, and warns about nothing. If your DI container reads design:type/design:paramtypes, esbuild is the wrong tool for that build step regardless of how green it looks.
  • JS decorators at the default target produce unparseable output. See above — pin --target below esnext or you ship a file no runtime will load.
  • The dev server binds all interfaces by default and had a Windows traversal bug through 0.28.0. Use host: "127.0.0.1" and stay on 0.28.1 or newer (GHSA-g7r4-m6w7-qqqr).
  • Pinning matters more than usual because there is no LTS line. There is one dist-tag (latest); nothing is backported to older 0.x minors, so "upgrade" is the only patch path for a security fix.
