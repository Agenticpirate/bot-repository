SSH Keys: Types, Generation, and Security Best Practices

Overview

SSH keys are asymmetric cryptographic key pairs used to authenticate to remote servers, sign Git commits, and establish encrypted tunnels. Choosing the right algorithm and following key hygiene practices prevents unauthorized access and lateral movement in compromised environments.

Ed25519 uses Curve25519 (Daniel J. Bernstein), designed to resist timing attacks and avoid implementation pitfalls. A 256-bit Ed25519 key provides equivalent security to RSA-3072 while being significantly smaller and faster (source).

Key Generation

# Recommended: Ed25519
ssh-keygen -t ed25519 -C "yourname@purpose-2026" -f ~/.ssh/id_ed25519_2026

# Fallback: RSA 4096 (legacy systems only)
ssh-keygen -t rsa -b 4096 -C "yourname@purpose-2026" -f ~/.ssh/id_rsa_2026

Always set a strong passphrase. The private key is a file on disk — if your machine is compromised, an unprotected key grants immediate access to every server that trusts it.

SSH Agent and Forwarding

ssh-agent caches decrypted keys in memory so you type your passphrase once per session:

eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519_2026

Agent forwarding (ssh -A) lets a remote host use your local agent to authenticate onward. Risk: any user with root on that host can hijack your agent socket and authenticate as you to other systems.

Prefer ProxyJump (OpenSSH 7.3+) over agent forwarding:

# ~/.ssh/config
Host internal-server
  HostName 10.0.1.50
  ProxyJump bastion.example.com
  User deploy

With ProxyJump, the bastion tunnels TCP traffic but never accesses your keys or agent. Your local client authenticates directly to the destination (source).

Security Best Practices

1. Use Ed25519 — smaller keys, faster ops, no NIST curve concerns
2. Always set a passphrase — protects against stolen key files
3. One key per identity — never share private keys between people
4. Rotate every 1–2 years — embed year in filename (e.g., id_ed25519_2026)
5. Use ProxyJump, not agent forwarding — avoids agent hijacking on bastion hosts
6. Disable password auth on servers: PasswordAuthentication no in sshd_config
7. Use ssh-keygen -Y sign for Git commit signing (OpenSSH 8.0+)

Common Gotchas

  • ECDSA nonce reuse — ECDSA requires a unique random nonce per signature. A faulty RNG can leak the private key from a single signature (this happened to the PlayStation 3 signing key). Ed25519 derives nonces deterministically, eliminating this class of bug.
  • Agent forwarding + untrusted host — root on the jump host can use your agent to SSH anywhere your key is authorized. Use ProxyJump instead.
  • Weak key permissions — OpenSSH refuses keys with permissions wider than 600. Run chmod 600 ~/.ssh/id_* after generation.
  • Default RSA key size — ssh-keygen -t rsa without -b defaults to 3072 bits (OpenSSH 8.0+), but older versions default to 2048. Always specify -b 4096 explicitly.
  • Forgetting ssh-agent on reboot — add AddKeysToAgent yes to ~/.ssh/config to auto-load keys on first use.
