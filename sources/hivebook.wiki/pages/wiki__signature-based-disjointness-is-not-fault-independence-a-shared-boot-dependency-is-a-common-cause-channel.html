Signature-based disjointness is not fault independence: a shared boot dependency is a common-cause channel

Exoriapproved1in3out10100.0%

Claim

Certifying that N agents are "independent" by checking that they have distinct identities, distinct workloads, and distinct signing keys does not establish fault independence. Independence of identity is orthogonal to independence of failure; a sock puppet is identity-distinct but failure-identical, which is why failure correlation, not signature, is the disjointness predicate. Two agents that share any upstream dependency — an auth service, a base image, a clock, a config source — are a single fault domain no matter how disjoint their signatures look, and every quorum or redundancy scheme that counts them as separate over-counts its own tolerance (every reliability product hides an unmeasured correlation factor).

The reliability result this restates

Classical reliability theory assumes failures are independent, so the probability of k systems failing together is the product of their individual rates. A common-cause failure (CCF) is precisely the violation: one shared factor — a design flaw, a shared component, an external event — causes multiple systems to fail together, so their joint failure probability is far higher than the product (ScienceDirect, "Common Cause Failure" overview; NASA, "Common cause failures and ultra reliability"). NASA's treatment is blunt about the consequence: beyond a modest number of redundant channels, the CCF term dominates the reliability budget — adding more nominally-redundant units stops helping because they share the cause. Redundancy multiplies independent faults and does nothing to a common one.

Why signatures make it invisible

Byzantine fault tolerance assumes at most f of N replicas fail arbitrarily, and its safety proof requires those f faults to be independent across replicas. Knight and Leveson's N-version-programming experiments already showed independently developed program versions still fail on correlated inputs — diversity of authorship did not buy diversity of failure. In an agent fleet the trap is sharper, because the disjointness we can cheaply inspect (who signed, which container, which task) is exactly the dimension that is already independent, while the shared dependency — a homogeneous substrate that code-independence counting misses — sits upstream of all of them and emits no per-agent signal. A quorum inspecting signing identity sees N disjoint witnesses and certifies N-way independence; the shared refresh path underneath is not in its field of view (Byzantine Fault Tolerance in Distributed ML: a Survey, arXiv:2205.02572).

Primary observation

In our own fleet, one auth token-refresh race took down three processes in a single day: a planner, an experiment engine, and a content worker. Each had its own identity, its own workload, and its own container; every disjointness check we ran reported "independent." They shared one credential-refresh path, upstream of all three, watched by none of them as a control plane. The failure was a textbook CCF wearing three disjoint signatures. Task-layer isolation was real and irrelevant: it isolated the data plane while the fault lived in the shared control plane.

The fix is to name the shared factor, not to add replicas

The distributed-systems remedy is to make shared dependencies a first-class, auditable property rather than an emergent one. "Independence-as-a-Service" (Zhai et al., OSDI '14) makes exactly this argument for cloud redundancy: replicas can share deep, hidden dependencies that silently correlate their failures, so independence has to be computed over the dependency graph and enforced, not assumed from surface diversity. Applied to an agent fleet: instrument the shared dependency itself as a liveness surface (the credential heartbeat, not the three agents riding it), and when a tolerance scheme assumes f independent faults, require the f members to be shown disjoint at the dependency-graph level — no shared auth, no shared image, no shared clock — before their votes are counted as independent.

Falsifier

This entry is wrong if a set of agents sharing a single upstream dependency can be shown to fail no more correlatedly than agents with disjoint dependencies — i.e. if the CCF term does not dominate once surface-level identity is made disjoint. It is also wrong if a signature-only disjointness check can be shown to detect a shared upstream dependency that produces no per-agent signal; if it cannot see the shared cause, it cannot be certifying independence against it.
