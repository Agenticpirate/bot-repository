Hugging Face Inference Providers — 19-Partner Serverless Router via router.huggingface.co/v1

Overview

Hugging Face Inference Providers is a unified serverless-inference router that sits in front of a fleet of partner backends (19 at the May 2026 baseline; 18 as of 2026-08-22 — SambaNova and Hyperbolic removed, Baseten added) and exposes a single OpenAI-compatible /v1/chat/completions endpoint at https://router.huggingface.co/v1 — one HF token, transparent pass-through pricing (no markup), automatic failover, and :fastest / :cheapest / :preferred policy suffixes for server-side provider selection. It replaces what used to be called the Inference API (serverless): the old single-backend path is now just one provider (hf-inference) in the larger router. Supports chat / vision LM / embeddings / text-to-image / text-to-video / speech-to-text depending on per-provider capability matrix.

Key tradeoff vs alternatives like OpenRouter, LiteLLM, and Cloudflare AI Gateway: HF Inference Providers is catalog-first, tied to model pages on huggingface.co — every open-weights model page shows the providers currently serving it, with per-provider latency / throughput / pricing / context-length probes published live at GET /v1/models. There is no markup on provider rates (HF "passes through" costs), and PRO users get $2.00/month in shared credits, Team & Enterprise organizations get $2.00/seat/month.

Endpoints

EndpointPurpose

POST /v1/chat/completionsOpenAI-compatible chat (all 19 providers that support chat)
GET /v1/modelsAll OpenAI-compatible models with per-provider metadata + live pricing/latency probes
GET /v1/models/{model_id}Single model + provider list
https://huggingface.co/api/models?inference_provider={p}Hub-side filter by provider; combine with pipeline_tag
huggingface.co/api/models/{id}?expand[]=inferenceReturns "warm" if any provider is currently serving
huggingface.co/api/models/{id}?expand[]=inferenceProviderMappingFull per-provider routing map (provider, providerId, task, status)

Note the dual-host split: chat-completion traffic uses router.huggingface.co; catalog/metadata uses huggingface.co/api/models. Both accept the same Authorization: Bearer hf_... token.

Authentication

Generate a fine-grained token at huggingface.co/settings/tokens/new with the "Make calls to Inference Providers" permission. The classic "Read" token still works for backward compatibility but won't be valid for orgs that enforce fine-grained policy. Authorization header: Authorization: Bearer hf_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx. Env-var convention in HF docs and SDKs: HF_TOKEN.

Provider Selection — Three Mechanisms

1. Server-side policy suffix (OpenAI-compatible endpoint only)

Append a suffix to the model id:

SuffixBehavior

(none) / :fastest (default)Highest tokens/sec throughput across live providers
:cheapestLowest USD/output-token rate
:preferredFollows your per-account preference order set at hf.co/settings/inference-providers

curl https://router.huggingface.co/v1/chat/completions \
  -H "Authorization: Bearer $HF_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "deepseek-ai/DeepSeek-V3-0324:cheapest",
    "messages": [{"role": "user", "content": "Hi"}]
  }'

2. Explicit provider via suffix

# Force Baseten (this example forced SambaNova at the May 2026 baseline;
# SambaNova is no longer a partner, and DeepSeek-R1 is served only by Novita as of 2026-08-22)
"model": "openai/gpt-oss-120b:baseten"
# Force DeepInfra
"model": "deepseek-ai/DeepSeek-V4-Pro:deepinfra"

3. Client-side provider= param (Python/JS InferenceClient only)

from huggingface_hub import InferenceClient
client = InferenceClient(token=os.environ["HF_TOKEN"])
result = client.chat_completion(
    model="openai/gpt-oss-120b",
    provider="groq",           # explicit (was "sambanova" at the May 2026
                               # baseline; SambaNova is no longer a partner)
    # provider="auto",          # default → fastest live provider
    messages=[{"role": "user", "content": "Hello"}],
)

The InferenceClient is the only path that supports non-chat tasks (text-to-image, embeddings, STT) — the /v1 OpenAI-compatible endpoint was chat-only at the May 2026 baseline. For T2I / embeddings you must use the SDKs.

Update (verified 2026-08-22): "chat-only" no longer holds. The router now also serves the Responses API (beta) on the same base URL — client.responses.create(...) against base_url="https://router.huggingface.co/v1", documented at huggingface.co/docs/inference-providers/guides/responses-api, with server-side MCP tools, reasoning-effort controls, structured outputs and semantic streaming events (response.created, output_text.delta, response.completed). It takes the same <repo>:<provider> and :fastest / :cheapest / :preferred model-id suffixes. Embeddings, text-to-image, text-to-video and speech-to-text are still SDK-only.

Org-billing header

Team / Enterprise organizations centralize billing across users by either passing bill_to="my-org-name" in the InferenceClient constructor, or adding the X-HF-Bill-To: my-org-name HTTP header on raw requests. Without it, traffic bills the individual user's HF account even if the user is in an org. Update (verified 2026-08-22): Enterprise orgs with Resource Groups can pass the resource group's ID instead of the org name — X-HF-Bill-To: <resource-group-id> — to attribute inference spend to that group; the calling user's token must belong to it. Team/Enterprise admins can also set a spending limit and disable specific Inference Providers from org settings.

# Python — bill_to constructor arg
client = InferenceClient(bill_to="my-org-name")

# OpenAI Python client — header via extra_headers
client.chat.completions.create(
    model="deepseek-ai/DeepSeek-V3-0324",
    messages=[...],
    extra_headers={"X-HF-Bill-To": "my-org-name"},
)


// JavaScript — billTo client option
const client = new InferenceClient(process.env.HF_TOKEN, { billTo: "my-org-name" });

HF Inference (first-party) pricing

The hf-inference provider (formerly "Inference API (serverless)") bills on compute-time × hardware-rate, not per-token. Example: a FLUX.1-dev request that takes 10 s on a $0.00012/s GPU = $0.0012. As of July 2025, HF-Inference is CPU-focused for embeddings / NER / classification / smaller historical LLMs — the heavy LLM traffic is meant to route to the partner providers via the auto policy.

OpenAI-Compatible Drop-in Replacement

The headline use case: change the base URL on existing OpenAI client code and gain access to the open-weights chat catalogue with no other diff. (HF's pricing page advertises "200+ models" across all tasks; GET /v1/models listed 131 chat models on 2026-08-22.)

from openai import OpenAI

client = OpenAI(
    base_url="https://router.huggingface.co/v1",
    api_key=os.environ["HF_TOKEN"],
)

completion = client.chat.completions.create(
    model="openai/gpt-oss-120b:fastest",
    messages=[{"role": "user", "content": "Hello"}],
)

This works in both Python and JS OpenAI SDKs. The /v1 endpoint accepts the standard OpenAI request body (messages, tools, response_format, stream, etc.); response shape matches openai.ChatCompletion verbatim. For evals via Promptfoo or the Vercel AI SDK, point the openai provider config at https://router.huggingface.co/v1 and any open-weights model becomes available.

Listing Models Programmatically

# All chat-completion models with provider metadata + live pricing probes
curl -s https://router.huggingface.co/v1/models \
  -H "Authorization: Bearer $HF_TOKEN" | jq '.data[0]'

# All models served by Fireworks AI
curl -s "https://huggingface.co/api/models?inference_provider=fireworks-ai" | jq '.[].id'

# Text-to-image models served by Fal AI
curl -s "https://huggingface.co/api/models?inference_provider=fal-ai&pipeline_tag=text-to-image" | jq '.[].id'

# Text-to-video models served by any provider
curl -s "https://huggingface.co/api/models?inference_provider=all&pipeline_tag=text-to-video" | jq '.[].id'

The /v1/models providers[] array per model gives you exactly the data you need to programmatically pick the cheapest provider for a given context length: filter by context_length >= N, sort by pricing.output, take the first status: "live" row.

Common Gotchas

1. Token permission mismatch. Classic Read tokens won't have the "Make calls to Inference Providers" scope. Fine-grained token is required for any org that enforces the policy. Error surface: 401 Unauthorized from the router despite the token "working" on other HF APIs.

2. provider="auto" chooses the fastest live provider, not the cheapest. This matters: a $4/1M-output-token provider on Fireworks may serve your default auto traffic instead of a $1.69/1M provider on Novita simply because it scored higher on the last latency probe. Use :cheapest policy suffix or explicit provider to cap costs.

3. The OpenAI-compatible /v1 endpoint is chat-only. Text-to-image, text-to-video, embeddings, speech-to-text all require the Python or JS InferenceClient. OpenAI-SDK code paths like client.embeddings.create() against the HF router return 404 / unsupported errors.

4. Custom Provider Key forfeits monthly credits. If you set a custom OpenAI/Fireworks/Replicate API key in HF settings, those routes are billed by the provider — your $2 PRO credits do nothing for that traffic. Use Custom Key only when you specifically want provider-direct billing.

5. Org credits don't apply without X-HF-Bill-To. A user in a Team org who forgets the bill_to arg / header pays from personal credits. There is no implicit org-defaulting. Wire bill_to once in the shared InferenceClient factory and forget about it.

6. inference: "warm" is the only positive signal — undefined means no provider. Don't assume inferenceProviderMapping will return — call ?expand[]=inference first as a cheap availability gate before constructing the routing path.

7. Provider catalog drift — in both directions. Featherless / Nscale / Z.ai were not in early-2026 docs; Baseten arrived 2026-08-06; SambaNova and Hyperbolic were removed between May and August 2026, which silently breaks any hardcoded :sambanova / :hyperbolic model-id suffix. New partners ship to the router within a release cycle. Treat the provider list as runtime data discovered via /v1/models, not a compile-time enum. Same for per-provider capabilities — DeepInfra launched chat-only and rolled in vision LM later.

8. is_model_author: true is informational, not a routing signal. Just because the model author serves the model doesn't mean their endpoint is the cheapest or fastest. Z.ai serving GLM models vs Fireworks serving the same GLM models is exactly the kind of choice where provider-author isn't necessarily best.

9. Pricing fields can be absent. Some /v1/models provider rows omit the pricing block (e.g. Featherless rows often have status: "live" only). Don't crash on missing keys; default to "unknown — query later" rather than treating absent pricing as $0.

10. bill_to is per-request, not per-token. Switching orgs mid-session requires a new InferenceClient instance (or per-call header). Token does not encode an org binding.
