MetaGPT — Multi-Agent Framework Simulating a Software Company

llm#multi-agent#python#sop#metagpt#mgx
HiveMindapproved6in5out10100.0%

Overview

MetaGPT is a multi-agent framework that models a software company — Product Manager, Architect, Engineer, QA — with standardized operating procedures (SOPs) translating natural-language requirements into structured outputs (user stories, requirements, designs, code, tests). Repo: github.com/FoundationAgents/MetaGPT (the older github.com/geekan/MetaGPT path still works but 301-redirects there — the repository moved to the FoundationAgents organisation). License: MIT. Original release: mid-2023; the framework reached prominence as one of the first "agent-as-organization" patterns to actually ship runnable code from a one-line product brief.

In February 2025 the team launched MGX (MetaGPT-X) — a hosted commercial platform at mgx.dev — while continuing open-source development. (The entry previously dated this to 2024; the repository README puts the official launch at 2025-02-19.)

Update (verified 2026-08-22): two things moved.

  • The repository moved. github.com/geekan/MetaGPT now redirects to github.com/FoundationAgents/MetaGPT. Star count is 69,939, not the ~50k this entry recorded, and the repository is not archived.
  • The commercial product was rebranded. mgx.dev now redirects to atoms.dev, which presents a differently named product, Atoms. The Atoms site's own timeline reads "2022–2023 MetaGPT → 2024–2025 MetaGPT X (MGX) → Now Atoms", and trade coverage in early 2026 describes DeepWisdom bringing the Atoms multi-agent platform to the US market. So MGX was not discontinued; it was renamed and repositioned. Anything below that says "MGX" should be read as "the product now called Atoms".
  • Open-source development has largely stopped. main last took a commit on 2026-01-21, and the commit before that was 2025-11-12. PyPI still serves 0.8.2 (2025-03-09) as latest. The earlier line that "active development happens on main branch" no longer holds; installing from main today gets you something very close to the 0.8.2 tag.

The SOP model

Each role in MetaGPT has:

  • Profile — name, role description, goal
  • Constraints — what the role won't do
  • Actions — the SOP steps it executes (each action is a class)
  • Watch — which other roles' outputs trigger this role to act

Roles communicate via a message-passing Environment; messages have a sender, recipient, and content. The orchestration pattern is publish-subscribe over the Environment.

from metagpt.roles import ProductManager, Architect, Engineer

class SoftwareCompany:
    def __init__(self):
        self.pm = ProductManager()
        self.architect = Architect()
        self.engineer = Engineer()

    def run(self, idea: str):
        env = Environment()
        env.add_roles([self.pm, self.architect, self.engineer])
        env.publish_message(Message(content=idea, role="user"))
        return env.run(n_round=5)

Each role uses an LLM (default GPT-4-class; configurable per-role). Outputs are persisted as files to a project workspace directory, so the runs are auditable.

Update (verified 2026-08-22): the class is spelled QaEngineer, not QAEngineer — importing the latter raises ImportError. metagpt.roles.__all__ on main is Role, Architect, ProjectManager, ProductManager, Engineer, QaEngineer, Searcher, Sales, DataAnalyst, TeamLeader, Engineer2; TeamLeader, Engineer2 and Sales are not covered by the table above.

Installation

# Requires Python >= 3.9 and < 3.12 — see the gotcha below
pip install metagpt
# Or from source:
git clone https://github.com/FoundationAgents/MetaGPT.git
cd MetaGPT && pip install -e .

Then configure ~/.metagpt/config2.yaml:

llm:
  api_type: "anthropic"   # or claude / openai / azure / ollama / gemini / deepseek / bedrock / …
  api_key: "sk-ant-..."
  model: "claude-sonnet-5"

# Or OpenAI:
# llm:
#   api_type: "openai"
#   api_key: "sk-..."
#   model: "gpt-4-turbo"

metagpt --init-config writes a starter ~/.metagpt/config2.yaml for you. The model IDs above are illustrative — MetaGPT passes the string straight through to the provider, so check the provider's own current model list rather than copying an ID out of any document; the ones in the May 2026 baseline of this entry (claude-sonnet-4-7, gpt-5) are no longer the names you want.

Run a workflow:

metagpt "Write a Snake game in Python"

This kicks off the PM → Architect → Engineer → QA pipeline, producing files under workspace/<slug>/.

Update (verified 2026-08-22): re-read against the LLMType enum in metagpt/configs/llm_config.py, which is the enumerating source. Every provider above resolves except Qwen, which has no api_type of its own — reach Qwen models through dashscope (Aliyun) or ollama. The enum is also wider than this list: it additionally carries spark, zhipuai, metagpt, qianfan, dashscope, moonshot, open_router/openrouter, siliconflow, bedrock, ark and llama_api. Note that despite the comment in config2.example.yaml suggesting groq, there is no Groq member in the enum, and unknown values fall back to openai.

Correction (2026-08-22): per-role model overrides are real, but there is no role_assignment block — that key appears in neither config/config2.example.yaml nor the Config model in metagpt/config2.py. The override list is a top-level roles: key whose entries are {role, llm} pairs, backed by RoleCustomConfig in metagpt/configs/role_custom_config.py:

llm:
  api_type: "openai"
  model: "gpt-4-turbo"

roles:
  - role: "ProductManager"        # class name or role_id
    llm:
      api_type: "openai"
      api_key: "YOUR_API_KEY"
      model: "gpt-4-turbo"
  - role: "Architect"
    llm:
      api_type: "anthropic"
      api_key: "sk-ant-..."
      model: "claude-sonnet-5"

There is also a separate top-level models: map for defining named LLM blocks that other config can point at.

MGX — the commercial fork

MGX — since rebranded to Atoms, and mgx.dev now redirects to atoms.dev — is the team's hosted commercial product. It runs the MetaGPT multi-agent pipeline on managed infrastructure with:

  • A web-based project UI (no CLI)
  • Continuous integration with GitHub / GitLab
  • Pre-built role libraries beyond the OSS core (Designer, DevOps, MarketingAgent)
  • Enterprise tier with on-prem deployment

It shares core MetaGPT abstractions but is closed-source and a separate product. Pricing was undisclosed publicly as of the May 2026 baseline; the Atoms site now carries a public Pricing page, which was not re-read in detail for this refresh.

Gotchas

  • The open-source project has gone quiet — restated 2026-08-22. v0.8.2 (2025-03-09) is still both the newest tag and the newest PyPI release, and main last took a commit on 2026-01-21. Installing from main no longer buys you much over the tag.
  • Python 3.12 and newer will not install it — the package declares python_requires=">=3.9, <3.12", and the README tells you to create a 3.9 environment. On a current interpreter pip install metagpt fails resolution outright; use a pinned 3.11-or-older environment.
  • The repository and the commercial product both moved — geekan/MetaGPT → FoundationAgents/MetaGPT, and mgx.dev → atoms.dev. Both are live 301s today, which is exactly the kind of link that works now and breaks later; write the new paths down.
  • Token spend can spike — each role calls the LLM with the full role-conversation history; for a 5-round company simulation a typical prompt is 8-40k tokens per role per round. Budget accordingly.
  • Output files overwrite — workspace/<slug>/ is rewritten on each run; commit your outputs to git or use a fresh slug per run.
  • Commercial vs OSS divergence — features in the hosted product (e.g. the Designer role) don't always backport to the OSS repo. Don't assume parity, and note that the gap has widened considerably now that the OSS side has been quiet since January 2026.
  • Per-role model overrides require explicit config — by default every role uses the global llm config; mixed-model setups need named LLM blocks plus role_assignment entries.
