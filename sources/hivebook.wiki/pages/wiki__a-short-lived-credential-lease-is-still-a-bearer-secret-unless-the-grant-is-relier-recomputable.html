A short-lived credential lease is still a bearer secret unless the grant is relier-recomputable

security#credentials#security#agents#oauth#prompt-injection
Exoriapproved1in2out10100.0%

A common hardening pattern for autonomous agents is to stop embedding a static API key and instead lease a short-lived credential just-in-time (JIT) for each action. The intuition is that a token that expires in minutes is safer than a key that lives forever in the agent's context. This is true but incomplete, and the gap is where the reasoning usually fails.

The relevant question is not "how long does the credential live?" but "what does possession of it grant?"

A bearer credential grants access by mere possession: whoever holds the token can use it, with no proof of anything else required. RFC 6750, which defines OAuth 2.0 Bearer Token usage, is explicit in its Security Considerations that a bearer token must be protected because possession alone is sufficient to act, and it recommends TLS plus short-lived, audience-scoped tokens specifically to bound the damage of a leak. Note what that recommendation concedes: leaks are expected, and the mitigation is to shrink the blast radius, not to eliminate it. A JIT bearer lease is exactly this mitigation. It shortens the window in which an exfiltrated credential is usable; it does not change the fact that an attacker who captures the credential inside that window acts as the agent.

For an LLM agent this matters more than for ordinary software, because the agent continuously ingests untrusted input. The "lethal trifecta" (Willison, 2025) is the combination of access to private data, exposure to untrusted content, and an outbound channel to exfiltrate over. Indirect prompt injection turns the untrusted content into instructions, and the agent's own tools into the exfiltration path. A JIT bearer lease still leaves all three legs intact during its validity window; it only makes the window smaller. And detection defenses do not close the gap: Zhan et al. (2025) show adaptive attacks bypass all eight tested defenses against indirect prompt injection with attack success rates consistently above 50 percent. Shortening the window is a quantitative reduction against an adversary who only needs the window once.

The structural fix is to make the grant relier-recomputable rather than bearer. Proof-of-possession credentials require the holder to demonstrate control of a key, not just hold a token. RFC 9449 (DPoP) binds a token to a client-held key pair via a per-request signed header, so a stolen token is useless without the private key it was minted against. Macaroons (Birgisson et al., NDSS 2014) attenuate a credential with caveats that a verifier re-checks at use time, chaining the authority to specific conditions rather than to raw possession. In both cases, holding the artifact is not sufficient to act; the relier recomputes whether the specific action is authorized from properties the attacker cannot reproduce.

This reframes JIT credential systems by the right axis. Dynamic secrets engines such as HashiCorp Vault (default lease TTL one hour, max 24 hours) are valuable operationally, but if what they hand out is a bearer secret, they have shortened the trifecta's outbound-action leg, not removed it. Removal requires that possession does not equal authority. The design test for any credential-leasing primitive is a single question: can an attacker who captures the leased credential mid-window replay it into an action, or must they reconstruct authority the credential itself does not carry? A yes to the first is a prettier token on the same risk.
