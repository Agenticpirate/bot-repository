Docling — AI Document Parser for RAG and Agentic AI

Overview

Docling is an open-source Python library for converting documents (PDF, DOCX, PPTX, XLSX, HTML, images, audio, more) into a unified, layout-aware data model that downstream gen-AI pipelines consume directly. It is hosted by the LF AI & Data Foundation (donated by IBM Research / Deep Search Team), licensed MIT, and supports local execution for sensitive/air-gapped workloads. Latest stable is v2.94.0 (2026-05-18, PyPI docling==2.94.0). It is one of the standard ingestion stages for retrieval-augmented generation and ships first-class adapters for LlamaIndex, LangChain, Haystack, Crew AI, Bee, and txtai.

Versus heavier proprietary parsers (Unstructured.io commercial tier, LlamaParse), Docling differs on three axes: (1) fully local execution — no API key required, models download once from Hugging Face and run on CPU/CUDA/MPS; (2) lossless DoclingDocument IR — every page produces a typed tree with layout/reading-order metadata that round-trips through Markdown, JSON, DocTags, HTML, and WebVTT without losing structure; (3) enrichment-on-demand — code, formula, picture-classification, and picture-description models are opt-in flags rather than always-on costs.

Quickstart

pip install docling  # requires Python >=3.10, <4.0


from docling.document_converter import DocumentConverter

source = "https://arxiv.org/pdf/2408.09869"  # the Docling Technical Report
converter = DocumentConverter()
result = converter.convert(source)
doc = result.document

print(doc.export_to_markdown())         # Markdown for LLM/RAG
print(doc.export_to_dict())              # Lossless JSON dict
doc.save_as_html("out.html")             # HTML preview
doc.save_as_doctags("out.doctags.xml")   # DocTags layout markup

DocumentConverter() accepts a format_options dict mapping InputFormat to a format-specific FormatOption (with pipeline_options, backend, pipeline_cls). Defaults work out of the box for PDF/DOCX/PPTX/XLSX/HTML/images.

Supported Input/Output

Input — PDF, DOCX, PPTX, XLSX, MD, AsciiDoc, LaTeX, HTML/XHTML, CSV, PNG/JPEG/TIFF/BMP/WEBP, WAV/MP3/M4A/AAC/OGG/FLAC (requires asr extra), MP4/AVI/MOV (requires asr extra + ffmpeg), WebVTT, USPTO XML, JATS XML, XBRL XML, Docling JSON.

Output — HTML (with image embedding or referencing), Markdown, JSON (lossless DoclingDocument serialization), plain text, DocTags (Docling's markup format for content + layout), WebVTT.

Audio/video paths use ASR models and require the asr install extra; video processing additionally requires ffmpeg on PATH.

Architecture

                +------------------------+
   input file  -|  Format-Specific       |  picks backend per format
   or URL       |  Backend (parser)      |  (PDF, DOCX, image, XML, …)
                +-----------+------------+
                            |
                            v
                +------------------------+
                |  Pipeline (standard or |  orchestrates: layout,
                |  VLM pipeline)         |  OCR, table-structure,
                +-----------+------------+  reading-order, enrichments
                            |
                            v
                +------------------------+
                |  DoclingDocument IR    |  typed tree: pages, items,
                +-----------+------------+  layout, captions, tables,
                            |               formulas, pictures
                            v
              +----------------------------+
              | Serializers / Chunkers /   |  Markdown, JSON, HTML,
              | Exporters                  |  DocTags, WebVTT, chunks
              +----------------------------+

Two pipeline shapes ship:

  • StandardPdfPipeline — classical: layout model (default RT-DETR variant; Heron available since v2.85) → OCR (if enabled) → table-structure (TableFormer) → reading-order → optional enrichments. Best CPU performance, deterministic.
  • VlmPipeline — runs Smol-Docling (or another VLM) end-to-end and emits DocTags directly. Higher quality on complex layouts; needs more compute (GPU recommended).

PdfPipelineOptions (the knobs you actually tune)

from docling.document_converter import DocumentConverter, PdfFormatOption
from docling.datamodel.pipeline_options import PdfPipelineOptions
from docling.datamodel.base_models import InputFormat

opts = PdfPipelineOptions()
opts.do_ocr = True                       # enable OCR for scanned PDFs (default True)
opts.do_table_structure = True           # TableFormer table cell extraction (default True)
opts.do_code_enrichment = True           # CodeFormula model: language detect + parse
opts.do_formula_enrichment = True        # CodeFormula model: LaTeX from equations
opts.do_picture_classification = True    # DocumentFigureClassifier-v2.5 (charts/diagrams/...)
opts.do_picture_description = True       # VLM captions on figures
opts.generate_picture_images = True      # keep cropped images attached
opts.images_scale = 2                    # upscale before VLM/classifier

converter = DocumentConverter(
    format_options={InputFormat.PDF: PdfFormatOption(pipeline_options=opts)}
)

OCR backend choice (via opts.ocr_options): EasyOCR (default), Tesseract (TesseractOcrOptions or TesseractCliOcrOptions), RapidOCR, OcrMac (macOS Vision framework). Disable entirely with opts.do_ocr = False when input is born-digital PDF — this alone can cut runtime by 5–10×.

Picture description supports granite_picture_description (IBM Granite Vision 3.1-2b, on-device), smolvlm_picture_description (256M, fastest), PictureDescriptionVlmOptions(repo_id=...) for any HF VLM, and PictureDescriptionApiOptions(url=..., headers=...) for remote endpoints. Default prompt is "Describe the image in three sentences. Be concise and accurate.".

Chunking for RAG

from docling.chunking import HybridChunker

chunks = HybridChunker(tokenizer="BAAI/bge-small-en-v1.5", max_tokens=512).chunk(doc)
for c in chunks:
    print(c.text, c.meta.headings, c.meta.doc_items)

HybridChunker is layout-aware: it respects section boundaries, keeps tables/figures intact when possible, and emits per-chunk provenance (page numbers, headings, parent items) — exactly what a RAG retriever needs to cite back.

Common Gotchas

  • Cadence is multi-per-week — docling==2.94.0 and docling==2.93.0 shipped 11 days apart but back-to-back fixes; always pin exact versions and re-test on every bump. There is no LTS line; >=2.x,<3 is the closest contract guarantee.
  • do_ocr defaults to True even on born-digital PDFs, which dominates wall-time. Set opts.do_ocr = False when you control the input source and know it is text-bearing. Easy speedup, no quality loss.
  • First convert downloads models from Hugging Face. v2.94.0 introduced a threaded two-stage download for the layout model, but the first call to DocumentConverter() on a fresh machine still pulls 500 MB-ish of weights to ~/.cache/huggingface. Pre-warm in your Docker RUN step or air-gapped bundle.
  • VLM pipeline needs a GPU for production throughput. SmolVLM-256M runs OK on CPU; Granite Vision 3.1-2b is borderline; anything Granite-Vision-4.1-class assumes CUDA/MPS.
  • asr extra and ffmpeg are not pulled by default — pip install docling does NOT enable WAV/MP3/MP4 parsing; use pip install "docling[asr]" and install ffmpeg separately for video.
  • do_picture_description with the default API options pings the configured endpoint per-image. If you set PictureDescriptionApiOptions(url="https://api.openai.com/v1/chat/completions", ...) to use a hosted VLM, a 50-figure PDF means 50 outbound requests — budget for it.
  • Output format choice matters for RAG fidelity. export_to_markdown() loses some layout context; HybridChunker over DoclingDocument preserves headings/tables/figures with provenance; always use the IR for downstream chunking, never the post-markdown string.
  • DocTags is not Markdown — it's Docling's own XML-ish layout/content interleave (<doctag>, <page_header>, <text>, <picture>, etc.). Round-trip through DocTags when you need full IR fidelity in a text file; treat Markdown as a lossy export only.
  • License is MIT for the codebase, but several optional models (Granite Vision, SmolVLM, EasyOCR weights) have their own licenses — check the model card before redistributing or running in regulated environments.
