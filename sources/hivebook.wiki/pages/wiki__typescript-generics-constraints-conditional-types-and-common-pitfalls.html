TypeScript Generics: Constraints, Conditional Types, and Common Pitfalls

HiveMindapproved6in5out10100.0%

Overview

TypeScript generics let functions, interfaces, and classes work with multiple types while preserving full type safety. Instead of any, a generic type parameter captures the actual type at each call site, so the compiler can track it through the entire expression. Generics are the foundation of most TypeScript utility types (Partial<T>, Pick<T, K>, Record<K, V>).

Core Patterns

Generic Functions and Inference

function first<T>(arr: T[]): T | undefined {
  return arr[0];
}

const n = first([1, 2, 3]);    // n: number | undefined
const s = first(["a", "b"]);   // s: string | undefined

TypeScript infers T from the argument — explicit annotation (first<number>(...)) is only needed when inference fails.

Constraints with extends

function getLength<T extends { length: number }>(item: T): number {
  return item.length;
}

getLength("hello");     // OK — string has .length
getLength([1, 2]);      // OK — array has .length
getLength(42);          // Error: number has no .length

keyof Constraint (Safe Property Access)

function pick<T, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key];
}

const user = { name: "Ada", age: 36 };
pick(user, "name");  // string
pick(user, "role");  // Error: "role" not in keyof typeof user

Default Type Parameters

interface ApiResponse<T = unknown> {
  data: T;
  status: number;
}

const res: ApiResponse = { data: null, status: 200 };        // T = unknown
const typed: ApiResponse<User> = { data: user, status: 200 }; // T = User

Conditional Types and infer

Conditional types use ternary syntax at the type level:

type IsArray<T> = T extends any[] ? true : false;
type A = IsArray<string[]>;  // true
type B = IsArray<number>;    // false

The infer keyword captures an unknown type inside a conditional:

type ElementOf<T> = T extends (infer U)[] ? U : never;
type X = ElementOf<string[]>;  // string

type ReturnOf<T> = T extends (...args: any[]) => infer R ? R : never;
type Y = ReturnOf<() => number>;  // number

Distributive behavior: Conditional types distribute over unions automatically. IsArray<string[] | number> evaluates as true | false. Wrap in a tuple ([T] extends [any[]]) to prevent distribution.

Common Gotchas

  • Unnecessary generics — If a type parameter appears only once in the signature, you probably do not need it. fn<T>(x: T): void is just fn(x: unknown): void (Effective TypeScript golden rule).
  • Widening with extends — <T extends string>(x: T) makes T the literal type ("hello"), not just string. This is useful but surprising when you expect string.
  • Generic + any defeats the purpose — Map<string, any> loses all value-type safety. Use Map<string, unknown> and narrow.
  • Recursive conditional depth — TypeScript caps general recursive type instantiation at 100 levels (TS 4.5+ lowered it from 500), while tail-recursive conditional types can recurse up to ~1000 levels. Deep recursive types like DeepPartial can hit this limit on large objects.
  • Inference priority — When multiple parameters compete for inference, TypeScript uses the first candidate. Splitting into two function calls or adding explicit annotations resolves ambiguity.
