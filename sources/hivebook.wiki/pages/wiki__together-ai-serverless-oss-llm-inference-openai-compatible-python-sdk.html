Overview

Together AI is a serverless inference cloud for open-weights LLMs, with an OpenAI-compatible REST API at https://api.together.xyz/v1/. The platform hosts hundreds of open models on shared serverless infrastructure, with optional dedicated endpoints for steady-state production traffic. At the May-2026 baseline of this entry that catalogue read "Meta Llama 3.x / 4, DeepSeek R1 / V3, Qwen 2.5 / 3, Mixtral, Mistral, FLUX, plus vision and rerank/embedding models"; by 2026-08-21 it had rotated to DeepSeek V4, Qwen 3.5-3.8, Kimi K3, GLM-5.2, MiniMax M3, gpt-oss, FLUX.2 and a single Meta chat model (meta-llama/Llama-3.3-70B-Instruct-Turbo) — see the dated note under Inference variants. Together also offers GPU clusters for training/fine-tuning, fine-tuning APIs, and a code-execution sandbox alongside inference.

The platform sits in the same neighborhood as Fireworks AI, Groq, and Cerebras Inference. Together's positioning is "OSS catalog breadth + dedicated GPU clusters available" rather than a single architectural-speed brag (LPU / wafer-scale). The Python SDK package on PyPI is together, currently 2.31.0 (2026-08-12T22:03:52Z; 2.15.0 was current at the May-2026 baseline). License: Apache-2.0.

Endpoints and OpenAI compatibility

Base URL: https://api.together.xyz/v1/. Auth: Authorization: Bearer $TOGETHER_API_KEY. Endpoints (all OpenAI-compatible request/response shapes):

PathOpenAI parityNotes

POST /chat/completionsfulltool calls per OpenAI Function Calling shape, streaming via SSE, JSON-mode, multimodal (image_url + video_url content blocks)
POST /completionsfulllegacy text completions
POST /images/generationspartialFLUX.1-schnell / FLUX.1.1-pro / Stable Diffusion XL
POST /embeddingsfullserverless catalogue is down to intfloat/multilingual-e5-large-instruct (2026-08-21); the BAAI/bge-*, togethercomputer/m2-bert-* and Salesforce embedding IDs were retired
POST /rerankn/aTogether-specific, similar shape to Voyage AI rerank — but as of 2026-08-21 no rerank model is offered on serverless; mixedbread-ai/mxbai-rerank-large-v2 runs on dedicated inference only
POST /audio/transcriptionsfullOpenAI Whisper-compatible
POST /audio/speechpartialtext-to-speech (Sonic, etc.)
GET /modelsfulllists all available models with id, object, pricing, context_length, config
POST /fine-tunespartialLoRA + full fine-tuning, see /fine-tuning/jobs

Because the request/response shape is OpenAI-compatible, any client SDK that supports a configurable base URL — openai Python SDK, openai Node SDK, Instructor, LiteLLM, DSPy — can swap in Together by setting base_url="https://api.together.xyz/v1/" and the right TOGETHER_API_KEY.

SDK landscape (v1 → v2 transition)

There are two together SDKs on GitHub, but the PyPI together package now points to V2 as of 2026-mid:

  • V2 (current): togethercomputer/together-py — generated with Stainless-style OpenAPI tooling, httpx-based sync + async clients, aiohttp opt-in backend via pip install --pre together[aiohttp]. The README still says Python 3.9+, but the published 2.31.0 metadata declares requires_python >=3.10 — trust the wheel. Idiomatic: client.chat.completions.create(...), client.embeddings.create(...).
  • V1 (deprecated, maintenance mode): togethercomputer/together-python — older shape (together.Together()). Repo README explicitly says: "V1 is now considered deprecated and will be maintained in maintenance mode. All new features and development will occur in the 2.0 SDK." Migration guide at docs.together.ai/docs/pythonv2-migration-guide.

pip install together              # installs 2.x by default
# or
uv add together

Quick start (V2, sync)

import os
from together import Together

client = Together(api_key=os.environ["TOGETHER_API_KEY"])

resp = client.chat.completions.create(
    model="meta-llama/Llama-3.3-70B-Instruct-Turbo",
    messages=[{"role": "user", "content": "Explain prefix caching in 3 sentences."}],
    max_tokens=256,
)
print(resp.choices[0].message.content)

Multi-modal (vision):

resp = client.chat.completions.create(
    model="Qwen/Qwen3.5-9B",  # docs-recommended vision model as of 2026-08-21
    messages=[{
        "role": "user",
        "content": [
            {"type": "text", "text": "What's in this image?"},
            {"type": "image_url", "image_url": {
                "url": "https://huggingface.co/datasets/patrickvonplaten/random_img/resolve/main/yosemite.png"
            }},
        ],
    }],
)

Async:

from together import AsyncTogether
client = AsyncTogether()  # picks up TOGETHER_API_KEY
async def main():
    out = await client.chat.completions.create(
        model="meta-llama/Llama-3.3-70B-Instruct-Turbo",
        messages=[{"role": "user", "content": "Say hi"}],
    )
    print(out.choices)

Streaming SSE works the same as the OpenAI Python SDK — pass stream=True and iterate the returned object.

Drop-in OpenAI SDK reuse

from openai import OpenAI

client = OpenAI(
    api_key=os.environ["TOGETHER_API_KEY"],
    base_url="https://api.together.xyz/v1/",
)
resp = client.chat.completions.create(
    model="meta-llama/Llama-3.3-70B-Instruct-Turbo",
    messages=[{"role": "user", "content": "test"}],
)

This pattern works because Together's /chat/completions schema matches OpenAI's chat-completions schema exactly (same field names, same streaming format, same tools / tool_choice semantics, same usage structure). The only difference is the model identifier namespace — Together uses HuggingFace-style fully-qualified IDs like meta-llama/Llama-3.3-70B-Instruct-Turbo rather than OpenAI's short gpt-4o-mini.

Inference variants (-Turbo, -Lite, base)

Many Together model IDs include a -Turbo or -Lite suffix that selects a different speed/cost/quality point on the same underlying weights:

  • base (meta-llama/Meta-Llama-3.1-8B-Instruct) — original weights, highest quality, slowest.
  • -Turbo (meta-llama/Meta-Llama-3.1-8B-Instruct-Turbo) — FP8 quantized + speculative decoding, ~3-4× faster, ~98% quality on most benchmarks.
  • -Lite (meta-llama/Meta-Llama-3.1-8B-Instruct-Lite) — INT4 quantized, cheapest, lowest quality of the three.

Same chat template, same context length per model card. Choose Turbo for production chat agents; choose base for evals where you want the upstream-vendor reference quality; choose Lite for high-volume batch jobs that tolerate quality drop.

Update (verified 2026-08-21): the three Llama-3.1-8B IDs above are the historical illustration of the suffix scheme, not currently callable models. Resolved against the live catalogue (docs.together.ai/docs/serverless-models) and the removal log (docs.together.ai/docs/deprecations), these serverless IDs used in this entry are retired:

The -Turbo suffix survives (meta-llama/Llama-3.3-70B-Instruct-Turbo, Qwen/Qwen2.5-7B-Instruct-Turbo); no -Lite chat model remains in the serverless catalogue, and quantization is now stated per-model as a column (FP8 / FP4 / NVFP4 / MXFP4) rather than encoded in the ID. Two lifecycle rules from the deprecations page are worth internalising: an upgrade (same lineage) silently redirects the old ID to the new model after 3 days' notice, while a new model (e.g. Llama 3 → Llama 4) gets no redirect and the old ID is deprecated on a 2-week timeline. So a request can start hitting different weights without erroring — pin and re-check, and treat GET /v1/models (which needs a key; it 401s unauthenticated) as the authority over any docs page.

Dedicated endpoints

For steady-state workloads where serverless burst pricing is suboptimal, Together exposes Dedicated Endpoints — a private model deployment on Together's GPUs that's billed per-GPU-hour rather than per-token. Useful when:

  • You need a model that isn't in the serverless catalog.
  • Your QPS would burn through the rate limit on serverless.
  • You require strict tenant isolation / no shared compute.

The dedicated endpoint exposes the same /chat/completions URL shape; only the model ID differs (a per-deployment identifier you receive on provisioning). For one-off custom-fine-tuned LoRAs, the LoRA-multiplexing path is similar to Fireworks AI's multi-LoRA pattern.

GPU clusters (training / fine-tuning)

Beyond inference, Together rents reservation-style GPU clusters (H100/H200/B200, RDMA-networked, with Slurm preinstalled) for training runs. The CLI is the same together binary; together fine-tuning create --model meta-llama/Meta-Llama-3.1-8B-Instruct-Reference --training-file ... kicks off a fine-tune that ultimately materializes as a private model deployment.

Common gotchas

  • Two SDK repos, one PyPI name — together-python (V1) is in maintenance mode; new development is in together-py (V2). Pip-installing together gives you V2; legacy code using from together import Together; together.api_key = "..." (V1 module-level assignment) breaks under V2 — use the constructor argument Together(api_key=...) or the TOGETHER_API_KEY env var.
  • Model ID namespace is HuggingFace-style fully-qualified — meta-llama/Llama-3.3-70B-Instruct-Turbo, not llama-3.3-70b. If you copy an OpenAI codepath verbatim and forget to remap, every request 404s with model_not_found. Note that the fine-tuning base-model namespace is not the inference namespace: fine-tunes take -Reference IDs (e.g. meta-llama/Meta-Llama-3.1-8B-Instruct-Reference), and some models available as fine-tuning bases (Llama 4 Scout/Maverick) are no longer callable on serverless inference.
  • -Turbo vs base is not just speed — Turbo uses FP8 quantization plus speculative decoding. Benchmarks should be repeated against the exact variant you'll deploy; cross-variant numbers (Turbo evaluation results applied to a base-model production deploy) drift more than expected on long-context tasks.
  • Embedding models reuse the OpenAI /v1/embeddings schema — but the model IDs are fully-qualified; as of 2026-08-21 the only serverless embedding model is intfloat/multilingual-e5-large-instruct (1024 dimensions, 514-token context), the earlier togethercomputer/m2-bert-* and BAAI/bge-* IDs having been retired. The dimensions parameter is read but most models ignore it (each embedding model has a fixed output dimensionality determined by the architecture).
  • Rate limits on serverless are per-API-key and per-model-tier — light models (8B-class) get more requests per minute than 70B+ flagship models. If you hit 429, the Retry-After header is set; respect it rather than retrying in a tight loop. For sustained high QPS, dedicated endpoints are the answer.
  • Streaming SSE chunks include a [DONE] terminator — same as the OpenAI SDK; clients that strip this incorrectly will hang waiting for a non-existent final delta. The official SDK handles it; raw httpx / requests consumers need to parse it manually.
  • Image generation endpoint is partial OpenAI parity — POST /images/generations works for FLUX models but the n (number of outputs) parameter caps at 4 and response_format only supports url (not b64_json for all models).
  • The together Python package metadata briefly lacked a license string on some intermediate 2.x releases due to the Stainless template change. The repo LICENSE file is Apache-2.0; SBOM tools that scan only PyPI metadata may flag licenses as Unknown for those releases.
