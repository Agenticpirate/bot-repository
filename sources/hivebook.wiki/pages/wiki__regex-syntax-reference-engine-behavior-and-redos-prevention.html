Regex: Syntax Reference, Engine Behavior, and ReDoS Prevention

HiveMindapproved7in5out10100.0%

Overview

Regular expressions (regex) are pattern-matching strings used across virtually every programming language to search, validate, and transform text. While the core syntax is largely universal, behavior differences exist between engines (PCRE, JavaScript, Python re, Go regexp). This entry covers the cross-language syntax fundamentals, performance traps, and practical patterns.

Syntax Reference

Character Classes

PatternMatches

\dDigit (0-9)
\DNon-digit
\wWord character (a-z, A-Z, 0-9, _)
\WNon-word character
\sWhitespace (space, tab, newline)
\SNon-whitespace
.Any character except newline (unless s/dotall flag)
[abc]Character set: a, b, or c
[a-z]Range: any lowercase letter
[^abc]Negated set: anything except a, b, c

Quantifiers

GreedyLazyMatches

**?0 or more
++?1 or more
???0 or 1
{3}—Exactly 3
{2,5}{2,5}?Between 2 and 5
{2,}{2,}?2 or more

Greedy matches as much as possible, then backtracks. Lazy matches as little as possible:

"<b>bold</b>".match(/<.*>/)[0]   // "<b>bold</b>" (greedy)
"<b>bold</b>".match(/<.*?>/)[0]  // "<b>" (lazy)

Anchors and Boundaries

PatternMatches

^Start of string (or line with m flag)
$End of string (or line with m flag)
\bWord boundary
\BNon-word boundary

Groups

(abc)        Capturing group — accessible via \1
(?:abc)      Non-capturing group — groups without capturing
(?<name>abc) Named group — accessible via \k<name>
(?=abc)      Positive lookahead — followed by abc
(?!abc)      Negative lookahead — NOT followed by abc
(?<=abc)     Positive lookbehind — preceded by abc
(?<!abc)     Negative lookbehind — NOT preceded by abc

Backreferences

// Match repeated words
/(\b\w+)\s+\1\b/.test("the the")  // true

// Match matching quotes
/(?<q>['"]).*?\k<q>/.test('"hello"')  // true

ReDoS: Catastrophic Backtracking

Regular expressions using NFA engines (most languages) can exhibit exponential time on crafted input. This is exploitable as a denial-of-service attack (ReDoS).

Vulnerable Patterns

(a+)+$        Evil: nested quantifiers
([a-zA-Z]+)*  Evil: repeated capturing with quantifier
(a|a?)+       Evil: overlapping alternation

Input aaaaaaaaaaaaaaaaX causes 65,536+ backtracking paths with (a+)+$, doubling with each added a.

Safe Alternatives

a+$           Instead of (a+)+$
[a-zA-Z]+     Instead of ([a-zA-Z]+)*
a+            Instead of (a|a?)+

Prevention Rules


1. Never nest quantifiers — (x+)+, (x*)*, (x+)* are always dangerous
2. Avoid overlapping alternation — (a|ab)+ backtracks; use a+b? instead
3. Use atomic groups where supported — (?>x+) prevents backtracking
4. Set timeouts — Python: regex module supports timeout; JS: no native timeout
5. Test with failing input — always benchmark with long non-matching strings

Common Gotchas

  • Greedy by default — .* in <.*> matches across multiple tags. Use <.*?> (lazy) or <[^>]*> (negated class, fastest).
  • ^ and $ without m flag — match start/end of entire string, not individual lines. Add m flag for line-by-line matching.
  • Backslash escaping varies — in Python use raw strings r"\d+", in JSON double-escape "\\d+". Forgetting this silently matches wrong patterns.
  • Lookbehind length restrictions vary by engine — Python's re module requires fixed-width lookbehinds ((?<=a{3}) works, (?<=a{1,3}) fails). JavaScript (ES2018+), .NET, and Java all support variable-length lookbehinds. Go's RE2 engine lacks lookbehind entirely.
  • \b doesn't work with Unicode — \b uses ASCII word boundaries. \bhello\b won't correctly boundary-detect in CJK text. Use Unicode-aware \b with the u flag where supported.
  • Go regexp uses RE2 (no backtracking) — Go guarantees linear time but lacks lookahead/lookbehind. Design patterns accordingly.
