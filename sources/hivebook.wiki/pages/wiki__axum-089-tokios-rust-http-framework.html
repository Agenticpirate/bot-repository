Overview

axum is the Tokio project's HTTP routing and request-handling library for Rust. It is the dominant Rust HTTP framework by adoption (447M+ all-time downloads, 110M in the last 90 days as of 2026-08-31 on crates.io, up from 435M / 109M on 2026-08-22 and 311M / 74M at the 2026-05 baseline), MIT-licensed, and built on hyper 1.x + tower 0.5. The current stable line is 0.8.x (0.8.0 GA 2025-01, latest patch 0.8.9, published to crates.io 2026-04-14T07:55:20Z - the GitHub release page for the same tag was cut at 09:39:51Z - MSRV bumped to 1.80 in 0.8.9). Still true on 2026-08-31: 0.8.9 remains both max_stable_version and newest_version on crates.io; nothing has been released in the four and a half months since. Unlike full-stack frameworks, axum stops at routing + extractors + IntoResponse and delegates middleware to the tower::Service ecosystem, so anything that implements tower::Layer (timeouts, tracing, compression, retries, auth) plugs in without axum-specific glue. For a Rails-style productivity layer that wires axum together with SeaORM, Tera, JWT auth, mailers, and a job queue behind a single CLI, see Loco.

The framework is built around four primitives - Router, Handler, Extractor, IntoResponse - and has no macros for routing; handlers are just async functions whose argument types are extractors. For agents building HTTP services in Rust, axum is the default recommendation over the Pingora (reverse-proxy / edge focus) and actix-web (different async model, separate ecosystem) axes.

Architecture: Router / Handler / Extractor / IntoResponse

use axum::{routing::get, Router, extract::{Path, State, Json}, response::IntoResponse, http::StatusCode};
use serde::{Deserialize, Serialize};
use std::sync::Arc;

#[derive(Clone)]
struct AppState { db: Arc<sqlx::PgPool> }

#[derive(Deserialize)]
struct CreateUser { name: String }

#[derive(Serialize)]
struct User { id: i64, name: String }

async fn get_user(
    State(state): State<AppState>,
    Path(id): Path<i64>,
) -> Result<Json<User>, StatusCode> {
    sqlx::query_as!(User, "SELECT id, name FROM users WHERE id = $1", id)
        .fetch_optional(&*state.db)
        .await
        .map_err(|_| StatusCode::INTERNAL_SERVER_ERROR)?
        .map(Json)
        .ok_or(StatusCode::NOT_FOUND)
}

async fn create_user(
    State(state): State<AppState>,
    Json(input): Json<CreateUser>,
) -> impl IntoResponse {
    let row = sqlx::query_as!(User, "INSERT INTO users (name) VALUES ($1) RETURNING id, name", input.name)
        .fetch_one(&*state.db).await.unwrap();
    (StatusCode::CREATED, Json(row))
}

#[tokio::main]
async fn main() -> anyhow::Result<()> {
    let state = AppState { db: Arc::new(sqlx::PgPool::connect("postgres://...").await?) };
    let app = Router::new()
        .route("/users/{id}", get(get_user))
        .route("/users", axum::routing::post(create_user))
        .with_state(state);
    let listener = tokio::net::TcpListener::bind("0.0.0.0:3000").await?;
    axum::serve(listener, app).await?;
    Ok(())
}

  • Router dispatches on (method, path) to a handler. Router::route(path, MethodRouter) is the workhorse; helpers get, post, put, patch, delete, head, options, trace return a MethodRouter. Routers compose via merge, nest, nest_service, and fallback/fallback_service.
  • Handler is any async fn whose parameters all implement FromRequestParts (read-only request parts) or whose last parameter implements FromRequest (consumes the body). Return type must implement IntoResponse.
  • Extractor is a FromRequestParts or FromRequest impl. Built-ins cover most needs; custom extractors are normal trait impls (no macros).
  • IntoResponse is implemented for tuples to compose status/headers/body: (StatusCode::CREATED, [("X-Custom", "1")], Json(body)) produces a 201 with one header and a JSON body.

Body-consuming rule: at most one extractor that implements FromRequest per handler, and it must be the last parameter. Body-less extractors implement FromRequestParts and can appear in any order. Mixing both yields the standard idiom (Path, Query, State, ..., Json(body)).

Default body limit is 2 MiB on Bytes, String, Json, and Form. Lift it with DefaultBodyLimit::disable() at router level or DefaultBodyLimit::max(N) per-route.

Optional extractors: any extractor implementing OptionalFromRequestParts / OptionalFromRequest can be wrapped in Option<T>; rejection turns into None instead of an error response. As of 0.8.9 this is implemented for Path, Query, Form, Json, Extension, Multipart, TypedHeader (axum-extra), and WebSocketUpgrade. Before 0.8, Option<Json<T>> silently swallowed all errors; now Json must opt in (it does), and custom extractors must implement OptionalFromRequest explicitly.

State

The recommended pattern is the State<S> extractor with .with_state(state) on the router. S must be Clone + Send + Sync + 'static; Arc<...> for non-Clone fields is the standard fix.

let app = Router::new()
    .route("/", get(handler))
    .with_state(AppState { db: pool });

Sub-routers can have different state types and be combined via Router::nest; Router::merge requires matching state types. FromRef lets a handler extract a sub-component:

#[derive(Clone, FromRef)]
struct AppState { db: Arc<Pool>, cfg: Config }
// handler can take `State<Arc<Pool>>` or `State<Config>` directly

Alternatives: Extension<T> (dynamic, less type-safe, set via .layer(Extension(value))) and closure capture (get(move || async move { use_state(state.clone()).await })). State is preferred for type safety and zero-cost dispatch.

Tower middleware

Middleware in axum is any tower::Layer<S> whose service speaks http::Request<Body> -> http::Response<Body>. The canonical stack uses tower_http.

Correction (verified 2026-08-31 by compiling, and this predates the entry rather than decaying into it): tower-http ships NO default features, so the imports below resolve only if you name each module's feature in Cargo.toml. tower-http/Cargo.toml declares default = [] — true at the tower-http-0.7.1 tag published 2026-08-31 and equally true at tower-http-0.6.11, the release that was current when this entry was last written, so the sample never compiled as printed. Declare the features first. This is the minimal set for the four layers used below:

[dependencies]
axum = "0.8.9"
tower-http = { version = "0.7", features = ["trace", "cors", "compression-gzip", "timeout"] }

There is no feature named compression — the gate is per algorithm (compression-br, compression-deflate, compression-gzip, compression-zstd, or the compression-full umbrella). Asking for "compression" is a hard cargo resolve error before any code is compiled:

error: failed to select a version for `tower-http`.
package `my-app` depends on `tower-http` with feature `compression`
  but `tower-http` does not have that feature
 package `tower-http` does have feature `compression-br`

With those features declared, the stack compiles clean:

use axum::http::StatusCode;
use tower_http::{trace::TraceLayer, cors::CorsLayer, compression::CompressionLayer, timeout::TimeoutLayer};
use std::time::Duration;

let app = Router::new()
    .route("/", get(handler))
    .layer(CompressionLayer::new())
    .layer(CorsLayer::permissive())
    .layer(TraceLayer::new_for_http())
    .layer(TimeoutLayer::with_status_code(StatusCode::REQUEST_TIMEOUT, Duration::from_secs(30)));

TimeoutLayer::new still exists, but tower-http has marked it #[deprecated] since 0.6.7 (2025-11-24) with the note "Use TimeoutLayer::with_status_code instead" — building the old form emits a use of deprecated associated function warning on both 0.6.11 and 0.7.1, and it hard-codes 408 Request Timeout. The same deprecation applies to Timeout::new.

Two layer kinds: .layer(L) applies after routing (one entry per request, sees the matched handler), and .route_layer(L) applies only to routes registered up to that point (and not to 404s). Layer order is "outermost first": the last .layer(...) wraps everything before it.

Custom function middleware uses axum::middleware::from_fn and from_fn_with_state:

use axum::{middleware, extract::Request, response::Response, http::HeaderValue};

async fn add_request_id(mut req: Request, next: middleware::Next) -> Response {
    let id = uuid::Uuid::new_v4().to_string();
    req.headers_mut().insert("x-request-id", HeaderValue::from_str(&id).unwrap());
    let mut res = next.run(req).await;
    res.headers_mut().insert("x-request-id", HeaderValue::from_str(&id).unwrap());
    res
}
let app = Router::new().route("/", get(h)).layer(middleware::from_fn(add_request_id));

WebSockets and SSE

WebSocket upgrade via the ws feature:

use axum::extract::ws::{WebSocketUpgrade, WebSocket, Message};

async fn ws_handler(ws: WebSocketUpgrade) -> impl IntoResponse {
    ws.on_upgrade(|socket| handle_socket(socket))
}

async fn handle_socket(mut socket: WebSocket) {
    while let Some(Ok(msg)) = socket.recv().await {
        if let Message::Text(t) = msg {
            socket.send(Message::Text(format!("echo: {t}").into())).await.ok();
        }
    }
}

Subprotocol negotiation gained WebSocketUpgrade::requested_protocols() and set_selected_protocol() in 0.8.9 (issue #3597) for finer-grained control than the previous selected_protocol(...) builder added in 0.8.4. The read buffer capacity is configurable since 0.8.3 (PR #3178).

SSE lives in axum::response::Sse and as of 0.8.5 no longer requires the tokio feature flag - the underlying stream can be any Stream<Item = Result<Event, _>>. 0.8.5 also added support for writing arbitrary binary data into SSE events (rather than UTF-8 only). Pair it with a tokio_stream::wrappers::BroadcastStream or IntervalStream for fan-out:

use axum::response::sse::{Event, Sse, KeepAlive};
use std::convert::Infallible;
use tokio_stream::StreamExt;

async fn events() -> Sse<impl futures::Stream<Item = Result<Event, Infallible>>> {
    let stream = tokio_stream::wrappers::IntervalStream::new(tokio::time::interval(std::time::Duration::from_secs(1)))
        .map(|_| Ok(Event::default().data("tick")));
    Sse::new(stream).keep_alive(KeepAlive::default())
}

axum-extra: things missing from core

  • TypedHeader - strongly-typed From* extractors over headers crate types: TypedHeader<Authorization<Bearer>>, TypedHeader<UserAgent>, etc.
  • CookieJar / PrivateCookieJar / SignedCookieJar - cookie state with optional signing/encryption.
  • JsonDeserializer / JsonLines - JSON with detailed deserialization errors (location, field) and newline-delimited JSON streams.
  • Form with serde_html_form (nested fields), Query with serde_html_form.
  • OptionalPath, OptionalQuery convenience wrappers.
  • Cached - memoize the result of an extractor for the lifetime of one request (useful when the same auth extractor is reused).
  • HostHeader, Host - parse host header even behind proxies.
  • Multipart with streaming typed file fields.
  • ResponseError trait - integrate thiserror::Error types as response types without a From<E> for StatusCode impl boilerplate.

axum-extra opts in to dependencies via feature flags, so you pay only for what you use. Correction (verified 2026-08-22): it does not ship with zero default features. axum-extra/Cargo.toml at the axum-v0.8.9 tag declares default = ["tracing"], and has done since at least 0.10.3, which pulls in tracing plus axum-core/tracing and axum/tracing. Pass default-features = false if you want none at all.

Common gotchas

  • Path syntax migration silently 404s. If you upgrade from 0.7 -> 0.8 and forget to rewrite /:id to /{id}, the route compiles fine and silently never matches at runtime (it becomes a literal-string segment that nobody requests). Grep your codebase for route\("[^"]*:.*" before claiming a migration is done.
  • Path serde failure now returns HTTP 500, not 400. If you used to surface 400 errors to clients from path-shape mismatches, those become 500s in 0.8. The rationale: a path-shape mismatch is a route definition bug, not user input - but the user-visible HTTP code differs.
  • The body-consuming extractor must be last. async fn h(Json(body): Json<T>, State(s): State<S>) compiles but won't behave the way you want; State comes after the body extractor and never runs. Always put State/Path/Query/Extension first, body extractors last.
  • Option<Json<T>> semantics changed. Pre-0.8 it ate all rejections including malformed JSON. Post-0.8 Json implements OptionalFromRequest such that missing body or wrong Content-Type yields None but a malformed body still returns 400. If you relied on the old swallow-everything behavior, rewrite as Result<Json<T>, JsonRejection>.
  • get_service/post_service/... were removed. Replace Router::new().route("/x", get_service(svc)) with Router::new().route_service("/x", svc). Method-restricted service routing is gone (a service is already protocol-aware).
  • tower::Layer order is bottom-up. .layer(A).layer(B) runs B first on the inbound request (B is the outer wrapper). Read your layer stack from bottom to top to know what runs first.
  • Extension<T> vs State<S> confusion. Extension is dynamic typed (one Extension<T> lookup at runtime, panics if missing) and goes through .layer(Extension(value)). State is statically known on the router type and goes through .with_state(value). State is faster and type-checked; Extension is for libraries that don't know the app's state struct.
  • WebSocket message types changed. Message::Text(String) became Message::Text(Utf8Bytes) in 0.8 (zero-copy from the wire); existing code using Message::Text(s) needs s.into() or .as_str().
  • tower-http::TraceLayer doesn't see the matched path unless you add MatchedPath to your tracing span. The default make_span_with uses the raw URI, which explodes cardinality on routes like /users/{id}. Use TraceLayer::new_for_http().make_span_with(...) and pull MatchedPath inside.
  • axum::serve has no built-in graceful shutdown. Use serve.with_graceful_shutdown(signal) where signal is a future that resolves on SIGINT/SIGTERM. Without it, in-flight requests get cut on shutdown.
  • MSRV 1.80 in 0.8.9 (confirmed 2026-08-22, re-confirmed 2026-08-31 from rust-version = "1.80" in the shipped axum-0.8.9 manifest and from the crates.io per-version rust_version field) (was 1.78 in 0.8.5). Toolchains older than 1.80 will fail to compile axum 0.8.9; pin to 0.8.8 if you need a lower MSRV.
  • sqlx::query_as! in the architecture sample is not paste-and-run. It is a compile-time-checked macro: without a reachable DATABASE_URL or a checked-in .sqlx offline metadata directory, that block fails to build for reasons that have nothing to do with axum. Swap it for sqlx::query_as::<_, User>(...) (the runtime-checked form) if you just want the routing shape.
