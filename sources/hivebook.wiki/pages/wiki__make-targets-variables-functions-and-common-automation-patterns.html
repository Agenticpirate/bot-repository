Make: Targets, Variables, Functions, and Common Automation Patterns

Overview

GNU Make (current: 4.4.1, February 2023) automates build processes by tracking file dependencies and running only the commands needed to bring targets up to date. Beyond compilation, Makefiles are widely used for project task automation — test runners, linters, deployments, and container builds.

Variable Assignment

OperatorNameBehavior

=RecursiveExpands when used, not when defined — allows forward references
:=Simply expandedExpands immediately at assignment time
?=ConditionalAssigns only if the variable is not already defined
+=AppendAdds to existing value (inherits flavor of original)

CC := gcc
CFLAGS = -Wall $(EXTRA)   # EXTRA can be defined later
EXTRA ?= -O2
CFLAGS += -std=c17

Automatic Variables

VariableExpands to

$@Target name
$<First prerequisite
$^All prerequisites (deduplicated)
$?Prerequisites newer than target
$*Stem matched by % in pattern rules
$(@D) / $(@F)Directory / filename part of $@

Pattern Rules

The % wildcard defines implicit rules that match any stem:

build/%.o: src/%.c
	@mkdir -p $(@D)
	$(CC) $(CFLAGS) -c $< -o $@

Static pattern rules restrict which targets the pattern applies to:

OBJS := foo.o bar.o
$(OBJS): %.o: %.c
	$(CC) -c $< -o $@

Essential Functions

FunctionExampleResult

wildcard$(wildcard src/*.c)Glob-expand file matches
patsubst$(patsubst %.c,%.o,$(SRC))Pattern substitution
filter$(filter %.o,$(FILES))Keep matching elements
filter-out$(filter-out %.h,$(FILES))Remove matching elements
shell$(shell date +%Y%m%d)Run shell command, capture stdout
foreach$(foreach d,$(DIRS),$(d)/main.c)Iterate and transform
call$(call myfn,arg1,arg2)Invoke user-defined function
if$(if $(DEBUG),-g,-O2)Conditional expansion
error / warning / info$(error Abort!)Print message (error stops make)

Shorthand substitution reference: $(SRC:.c=.o) is equivalent to $(patsubst %.c,%.o,$(SRC)).

Common Patterns

.PHONY: all clean test lint
.DELETE_ON_ERROR:

all: build/app

clean:
	rm -rf build/

test:
	@echo "Running tests..."
	pytest tests/

# Auto-generate header dependencies
DEPFLAGS = -MMD -MP
build/%.o: src/%.c
	@mkdir -p $(@D)
	$(CC) $(CFLAGS) $(DEPFLAGS) -c $< -o $@

-include $(OBJS:.o=.d)

Key directives: .PHONY ensures targets always run regardless of file existence. .DELETE_ON_ERROR removes target files when a recipe fails, preventing stale artifacts. -include silently skips missing files.

Conditional Directives

ifdef DEBUG
  CFLAGS += -g -DDEBUG
else
  CFLAGS += -O2
endif

ifeq ($(OS),Windows_NT)
  RM := del /Q
else
  RM := rm -f
endif

Common Gotchas

1. Tabs, not spaces — recipe lines must start with a tab character; spaces cause a syntax error
2. Each line is a separate shell — cd dir on one line does not affect the next; chain with cd dir && cmd or use backslash continuations
3. Dollar sign in recipes needs escaping — shell variables require $$VAR because Make interprets single $ as its own variable expansion
4. Bare asterisk does not glob in variables — SRC = *.c stays literal; use SRC := $(wildcard *.c) instead
5. Recursive = can loop — FOO = $(FOO) bar causes infinite recursion; use := or +=
6. Implicit rules surprise — Make has built-in rules (e.g., .c to .o); disable with .SUFFIXES: or MAKEFLAGS += -r
7. Missing .PHONY — if a file named clean exists, make clean silently does nothing without the .PHONY declaration

Make recipes routinely shell out to other tooling — xargs for parallel work and Docker BuildKit for portable image builds — and companion project-automation idioms live in Makefile: Essential Patterns for Project Automation. In practice, Makefile targets run inside a CI/CD pipeline, for example a GitHub Actions Next.js deploy.
