# 公共管理C刊学术写作

## Overview

本 skill 面向中文公共管理、公共行政与治理研究论文写作。它不是审稿式自查清单，也不是一般润色器，而是把公共管理论文中常见的“问题意识、制度过程、治理主体、机制解释、方法说明、结果阐释和贡献收束”转化为可执行的写作规则。

它可用于 C 刊论文、博士论文普通章节、课题论文、案例研究、政策分析、文献综述、研究述评和混合方法研究。本 skill 已内置普通文献综述与研究述评的通用写作规则。若任务明确属于某一专门主题、专门方法或专门文类，应同时调用对应的专门 skill；若用户明确点名 `public-management-literature-review-zh`，或要求系统检索 Zotero、整节文献综述重写、深度研究述评，再叠加该专门 skill；若任务是投稿前评估，应改用或配合 `social-science-paper-self-review-zh`。

## Source Basis

本 skill 的规则来自两类材料：

1. 博士论文与 C 刊论文写作规则中可迁移的部分，包括判断式起笔、议论式推进、阶段性评述、反模板表达和结尾综合。
2. 从 Zotero 中十篇公共管理/数字治理相关论文抽取的写法共性，包括理论框架型、案例机制型、效能评价型、情境适配型和组态解释型论文。

## Mandatory C-Journal Pre-Writing Protocol

凡生成或改写 C刊/CSSCI论文正文、完整小节、二级标题内容或连续自然段，必须先完成以下判断。这里的“结构优先”发生在写作之前，不是写完以后再调整开头或润色句子。

1. 确定全文位置。判断当前内容位于问题提出、文献综述、理论框架、政策或制度过程、研究设计、结果解释、讨论、结论中的哪一部分，并说明它对全文核心问题承担什么任务。
2. 建立论证单元。若任务包含一个小节或两个以上连续自然段，先确定核心问题、材料顺序、判断形成位置、转向节点和收束方向，再决定分几段。不得逐段单独起草后再拼接。用户只要求一个自然段时，将该段视为最小论证单元。
3. 分配段落功能。明确每段分别承担总起、承接展开、文献转向、概念限定、机制解释、方法说明、结果解释、讨论提升或贡献收束中的哪一种功能。每段都必须推进新的判断、证据或解释，不能只换一种说法重复前文。
4. 设计段际接力。写明每一段接住上一段的哪个实质对象、材料结果、解释边界或未决问题，又把读者推向下一段的哪个判断。不得依靠“前文已经”“本节将”“在此基础上”等元话语维持衔接。
5. 根据功能选择起笔。总起段可以使用较强判断，展开段可从前文留下的对象或材料进入，政策段可从制度节点进入，案例段可从经验场景进入，方法段可从方法边界或测量风险进入，结果段可从表格所回答的问题进入。不得把“判断先行”理解为每段都使用同一种抽象判断句。
6. 安排材料与评述。政策、案例、访谈、数据和文献必须形成问题链、过程链、因果链或机制链。写作前预设至少一个作者评述落点，说明材料对概念边界、理论机制、方法处理、结果解释或政策判断意味着什么。
7. 执行 C刊压缩。篇幅不足时优先删除重复背景、流程播报、同义复述和空泛拔高，保留问题形成、证据支撑和因果机制。压缩不能把论证改成结论清单，也不能删去使判断成立的关键过程。
8. 生成后复查。先检查整组段落能否连续读出问题、材料、转向和判断，再检查各段功能、语义接力、起笔方式、作者评述和反模板表达。发现连续同构开头时，先调整段落功能或推进关系，再修改句子。

## Non-Negotiable Argumentative Gate

议论式推进不是风格建议，而是公共管理正式正文的合格条件。凡生成、改写或顺稿博士论文、C刊正文、课题论文、政策分析、研究设计、结果解释或案例机制段落，必须默认执行“判断—材料—阶段性评述—继续推进或收束”的底层结构。

如果正文连续铺陈事实、政策、文献、数据、案例或方法步骤，却没有及时说明这些材料对研究问题、概念边界、测量设计、机制解释或政策判断意味着什么，默认该段不合格，必须先补入作者评述或重组材料顺序。不得把作者判断全部推迟到段尾，也不得用“由此可见”“具有重要意义”“提供了基础”这类空泛句替代阶段性评述。

## Stage Review Quality Gate

阶段性评述不是在材料后面补一句“这说明……”“由此可见……”。正式正文中的评述必须落到至少一类具体学术功能上：概念边界、测量风险、方法功能、机制解释、研究问题、政策含义或后续处理口径。

输出前必须检查每一句评述是否回答了“这段材料改变了什么判断”。若评述只写“具有重要意义”“提供支撑”“奠定基础”“值得关注”“说明效果较好”而没有指出具体边界、风险、功能、机制或处理方式，默认不合格，必须重写。合格评述应能说明材料如何影响指标归属、题项修订、样本解释、方法选择、变量处理、机制判断或政策解释。

## Pre-Sentence Interception Gate

正式正文的第一句、段落转折句和关键判断句在输出前必须先过句式拦截。若草稿句命中以下模板壳，禁止直接输出，必须先改写为具体对象、过程、风险或方法边界：

1. `不是A，而是B`、`并非A，而是B`、`不在于A，而在于B`、`重点不在于A，而在于B`。
2. `能否A，取决于能否B`、`是否A，决定是否B`、`A能否进入B，取决于C能否……`。
3. `X形成以后，还需要Y`、`在完成X之后，本文进一步Y`、`前文已经X，本节将Y`。
4. `一方面……另一方面……`、`既……又……还……`、`不仅……而且……更……`作为段落骨架。
5. `但这并不意味着……`、`这并不代表……`、`不能直接说明……`作为机械转折壳。
6. 普通正文中默认不用分号。除非同一句确有必要保留两个完整并列分句、比较项或递进关系，否则不用分号。一般说明、承接、转折和结果解释优先改为句号；若草稿句出现“；”，必须先判断其必要性，不能说明必要性时改写为两个句子或改用逗号。

拦截后的改写原则是：把镜像条件、否定对偶和流程说明改为“本段方法/材料/现象要解决什么问题，在哪个环节会产生什么偏差或后果”。只有句子通过该拦截，才能继续生成后续正文。

## Opening Mode Bank

开头不是套用万能句，而是根据章节功能选择进入问题的方式。正式写作前必须先选择一种起笔模式；若无法判断当前段落属于哪一类，不得直接写正文。

1. 方法边界式。用于信度检验、效度检验、德尔菲法、熵值法、回归、QCA、访谈设计等。首句说明该方法在本文中解决哪类问题、不能替代什么判断，避免写成方法教材。
2. 测量风险式。用于指标体系、问卷题项、预调查、样本说明和变量操作化。首句指出若该环节处理不好，后续测量会出现何种偏差，如理解歧义、题项归属不稳、样本口径混乱或数据不可比。
3. 过程变化式。用于政策演进、制度变迁、地方承接和阶段划分。首句写变化发生在哪个治理环节，说明问题如何从一个阶段转向另一个阶段。
4. 经验场景式。用于案例、访谈、区域背景、基层实践和民族地区/乡村场景。首句从具体主体、事务、空间、语言、组织或服务场景进入，不从抽象背景进入。
5. 结果解释式。用于统计表、专家评分、模型结果、组态路径和评价结果。首句先说明该结果回答什么问题，再报告关键数值或路径。
6. 文献转向式。用于文献综述和研究述评。首句写已有解释的边界或研究焦点的移动，不用作者姓名和年份排队起笔。

选择开头后，还要立即补足支撑材料。方法边界式后接方法对象和处理口径；测量风险式后接题项、样本或作答场景；过程变化式后接政策节点或制度环节；经验场景式后接具体实践；结果解释式后接关键数值；文献转向式后接研究对象、方法或发现。

## Argument Unit Map Gate

C刊论文、CSSCI论文、课题论文和博士论文普通章节在写作一个完整小节、一个二级标题内容或一组连续自然段之前,必须先形成“论证单元地图”,不得直接逐段生成正文。论证单元地图至少包括四项: 本单元要处理的核心问题; 准备分几段推进; 每段分别承担问题提出、材料展开、机制解释、结果解释、理论转向或贡献收束中的哪一种功能; 段落之间依靠什么关系推进,如问题链、政策过程、经验场景、方法边界、统计结果或机制链条。

这里的“结构优先”不是写完之后再做结构质检,而是写作前的功能定位。生成 C刊正文、博士论文普通章节或连续段落之前,必须先判断该段或该节在全文中的作用: 它是在引出问题、承接文献、交代政策过程、界定概念、进入案例、说明方法、解释结果,还是收束贡献。只有先确认功能,才能决定开头方式、材料密度和评述位置; 不得把“判断先行”误解为每个自然段都用同一种显性判断句起笔。

论证单元地图可以在内部完成,不必每次展示给用户; 但若用户询问写作逻辑,必须能够说明为什么这样分段、为什么这样起笔、为什么这样收束。正式写作时必须让正文服从论证单元地图,不得边写边临时堆材料。

判断式写作的核心不在于每段第一句都像判断句,而在于整组段落能够形成判断推进。相邻段落应承担不同功能: 总起段提出问题或现实格局; 展开段承接上一段材料、概念或场景; 转向段把材料推向方法、机制、指标或贡献; 收束段提炼作者判断并说明与全文问题的关系。若相邻三段都采用“X源于Y”“X需要Y”“关键在于Y”等同类显性判断起笔,即使逻辑正确,也默认判定为模板化,必须改成“总起判断—承接展开—评价转向”的组合。

C刊的篇幅约束不改变上述顺序，只改变论证密度。相邻段落可以合并，但合并后仍应看出问题如何提出、材料如何进入、作者判断在哪里形成。不得以篇幅有限为由省略证据与解释之间的关键环节，也不得让每段都重新介绍背景和研究重要性。

常用推进结构:

1. 问题提出类: 现实格局进入—矛盾展开—研究问题推出。
2. 政策分析类: 政策节点进入—基层运行展开—机制或边界判断。
3. 研究设计类: 方法边界进入—样本/变量/题项展开—操作口径收束。
4. 结果解释类: 表格问题进入—数值结果展开—研究含义解释。
5. 讨论贡献类: 发现边界进入—理论或政策含义展开—贡献收束。

输出前必须检查本单元各段开头是否承担不同功能,是否存在连续同骨架起笔,是否能够从段际关系中读出问题推进。若不能,先调整段落入口,再修改句子。

## Humanities And Social Science Process Texture Gate

这组规则适用于 C 刊论文、CSSCI论文、课题论文、案例研究、政策分析和博士论文普通章节的正文写作，覆盖公共管理、管理学、社会学、经济学、教育学和相关人文社科研究。它们是出句前的过程约束，不是写完后的修辞检查。若任务明确属于某个专门主题、专门方法或专门文类，再叠加对应专门 skill。

1. 不把章节衔接写成流程播报。必要承接可以保留，但不得连续使用“前文已经”“本节将”“经过……梳理”“后续……”作为段落入口。优先从研究对象、制度矛盾、经验现象、方法风险、材料结果或理论争议进入正文。
2. 控制“能否/是否”镜像句密度。指标、机制、模型和政策段不能把复杂过程压成判断开关。优先写制度规则如何进入执行过程，组织如何分配任务和吸收反馈，市场主体如何响应激励，群体如何形成认知与行动，资源如何在层级、网络或市场中流动。
3. 维度、变量和指标要从研究过程里长出来。不要把正文写成“定义—指标—边界”的说明书。公共管理可以从政策执行、公共服务、责任分工和反馈吸收进入，管理学可以从组织决策、激励约束、流程协同和绩效反馈进入，社会学可以从社会关系、群体分化、身份认同和制度嵌入进入，经济学可以从成本收益、资源配置、市场约束和效率公平进入，再推出概念、维度或变量。
4. 领域语言必须随学科和对象切换。公共管理段落要落到政策工具、执行链条、服务对象、组织承接、资源配置、责任分工、反馈吸收和制度接口。管理学段落要落到组织结构、管理流程、激励机制、能力积累和绩效改进。社会学段落要落到社会结构、互动关系、群体差异、规范秩序和行动逻辑。经济学段落要落到激励相容、约束条件、交易成本、资源错配、效率损失和分配效应。涉及特定地区、行业、组织或群体时，不得只贴标签，必须写这些条件如何改变行为选择、制度执行、资源流动、服务获得或结果差异。
5. 避免关键词和抽象动词复读。“公众感知”“用户体验”“员工感知”“农户意愿”“企业响应”等核心词，需根据语境替换为受访者判断、服务接触、组织成员经验、用户使用评价、家庭决策、市场主体反应、群体行动或政策对象反馈。“构成、转化、纳入、形成、呈现、提供、回答”等抽象动词不可高密度连用，需搭配执行、传导、协调、配置、激励、约束、响应、反馈、协商、监督、扩散、调整、吸收等具体过程动词。
6. 统计结果、测度结果、模型结果、路径结果、表格和案例后必须给研究含义。不能只报数值、路径或案例现象，要说明结果改变了对研究问题、理论边界、机制解释、方法功能或实践判断的哪一项理解。
7. 政策建议、管理建议和实践启示必须从发现中长出来。每条建议至少交代它针对哪项发现或机制问题，行动主体是谁，使用什么政策工具、管理工具或组织安排，落在哪个执行环节，适用于什么条件，可能产生什么风险或反馈。没有前文证据支撑，不得突然提出宏观口号。

## Mandatory Execution Gate

只要用户要求正式写作、改写、顺稿、润色、博士论文正文、C刊正文或文献综述，必须先在内部完成以下判断，再输出正文。不得等待用户提醒。

1. 文类判断。确认当前任务属于博士论文、C刊论文、文献综述、研究设计、政策分析、指标体系、问卷设计、实证结果、案例机制、结论收束中的哪一种。
2. skill 路由。若任务明确属于某个专门主题、专门方法或专门文类，优先叠加对应 skill。普通文献综述或述评默认使用本 skill 内置规则，不额外调用专门文献综述 skill；只有用户明确点名 `public-management-literature-review-zh`，或任务需要系统检索 Zotero、整节文献综述重写、深度研究述评时，才叠加该 skill。若涉及标点克制，同时执行 `chinese-academic-punctuation-discipline-zh`；若涉及图表，同时执行相应图表类 skill。
3. 论证单元地图。若任务涉及一个小节、二级标题内容或连续多段正文,先明确核心问题、段落数量、段落功能和推进关系,再进入单段写作。
4. 段落功能。判断当前段落是冒段、正文分说段、过渡段、结果解释段、机制段还是收束段; 同时判断它在全文中承担起势、承接、转向、证明、比较、深化还是收束作用。
5. 段际接力。明确本段接住上一段的哪个对象、材料结果、解释边界或未决问题，并说明它将论证推向哪个后续判断。没有实质接力关系时，先调整结构，不用连接词强行拼接。
6. 起笔选择。按段落功能选择判断式、问题压缩式、方法边界式、情境过程式、转向式、概念限定式、经验引入式或结果解释式。不得默认使用同一种开头。
7. 密度选择。博士论文默认保留必要细节和支撑，章、节、小节冒段按 500—800 字准备；C刊论文默认压缩但不牺牲问题链。
8. 材料落点。确认本段至少有一个具体落点：政策节点、文献发现、数据结果、案例过程、访谈材料、题项设计、统计检验或机制环节。
9. 阶段性评述。检查材料之后是否有作者判断，说明材料对概念、测量、方法、机制或政策解释意味着什么。
10. 反模板检查。输出前删除“完成以后还需要”“前文已经……本节将”“能否取决于能否”“不是A而是B”“首先其次最后”等脚手架。
11. 输出说明。除非用户明确要求只给正文，正式正文后必须给 3—6 行写作逻辑与风格说明，具体说明本次选择的起笔方式、材料推进方式和去模板处理。若本次只提供章节方案、段落诊断、写作建议或判断某段是否合格，也必须给出简短判断依据，说明依据了哪类章节功能、写作边界或反模板规则。

## Pre-Writing Function Judgment

写作或改写任何正式论文段落前，先完成以下判断。不得在未判定段落功能时直接生成正文。

| 段落功能 | 起笔优先方式 | 必须补足的支撑 | 常见失败 |
| --- | --- | --- | --- |
| 章/节/小节冒段 | 研究风险式、方法边界式、问题提出式 | 本节处理什么问题、为何影响全文论证、前文推进到何处、本节如何处理 | 写成目录说明或流程说明 |
| 普通正文段 | 判断式、过程式、经验引入式 | 事实、政策、文献、数据或案例至少一种 | 段首判断后中间罗列材料 |
| 文献综述段 | 研究推进式、转向式 | 文献对象、材料、发现或机制 | 作者姓名串联 |
| 文献述评段 | 问题压缩式、边界判断式 | 已有研究价值与未打通环节 | 空泛写“仍有不足” |
| 理论基础段 | 概念限定式、解释分工式 | 理论能解释哪部分、不能解释哪部分 | 教材式定义 |
| 政策演进段 | 政策过程式、工具变化式 | 政策回应了什么问题、改变了什么工具或责任 | 文件按时间排队 |
| 研究设计段 | 方法边界式、操作必要式 | 分析单位、样本/材料、方法功能 | 统计教材化 |
| 结果解释段 | 结果问题式 | 该表/模型回答什么、关键数值、含义 | 复述表格 |
| 案例机制段 | 经验引入式、过程解释式 | 主体、环节、规则、资源、反馈、结果 | 只展示材料 |
| 收束段 | 综合判断式 | 本部分推进所得判断及与后文关系 | “综上所述”式复述 |

## Opening Sentence Decision Rules

段首句的选择依据是段落任务，不是形式好看。若段首句可以替换到任何章节都成立，说明起笔过泛，必须重写。

1. 判断式开头。用于核心观点、普通正文段、结果解释前的总领。第一句直接给出本段判断，随后用材料展开。避免写成“随着……”“在……背景下”。
   - 合格方向：`预调查要处理的核心问题，是指标语言进入真实作答场景后可能发生的测量偏差。`
   - 不合格方向：`指标体系形成以后，还需要通过预调查进行检验。`
2. 问题压缩式开头。用于解释原因、机制或研究困惑。问题必须具体，且下一句立即进入解释，不得悬空设问。
   - 合格方向：`数字平台已经上线，治理效能差异仍然存在。差异主要发生在组织承接与服务对象持续使用环节。`
3. 方法边界式开头。用于研究设计、预调查、专家咨询、信效度检验、组态分析、综合评价、回归模型、案例比较等段落。先说明方法能解决什么，不能解决什么。
   - 合格方向：`德尔菲咨询在本文中用于审查指标内容，受访者作答与正式测度仍由后续调查承担。`
4. 情境/过程式开头。用于政策演进、制度变化、实践过程。先写变化发生在什么环节，再写问题如何显现。
   - 合格方向：`基础设施和平台入口逐步完善以后，政策工具开始从供给建设转向服务承接。`
5. 转向式开头。用于文献综述中研究重心变化。先说明前一类解释为何不足，再转入下一类研究。
   - 合格方向：`单纯从平台建设解释数字治理成效，难以说明同一工具在不同组织和服务对象中的使用差异。后续研究因而开始关注组织承接和用户参与。`
6. 概念限定式开头。用于理论基础、概念界定、指标维度。先划清概念边界，再说明为何这样使用。
   - 合格方向：`本文所说的治理效能，指服务对象能够感知到的服务获得、组织回应和场景适配结果，而不是平台建设水平本身。`
7. 经验引入式开头。用于案例、样本、区域背景和访谈材料。直接说明该经验材料为什么具有解释价值。
   - 合格方向：`基层服务对象的空间分布和使用能力差异，使公共服务可及性不能只用机构覆盖率来判断。`
8. 结果解释式开头。用于统计表、模型、组态路径、专家评分结果。先说明结果要回答的问题，再报告数值。
   - 合格方向：`Kendall’s W 检验用于判断专家评分是否具有整体协调性。`

段首句之后必须有实际支撑。判断式开头后接事实或机制，问题式开头后接原因链，情境式开头后接具体变化，转向式开头后接前一视角边界，概念式开头后接适用范围，经验式开头后接材料与研究问题的关系。

### Opening Choice By Dissertation Section

博士论文不同章节的开头不能共用同一套句式。写作前必须先按章节任务选择起笔方式，再进入正文。

| 章节或小节类型 | 首句优先写法 | 首句要回答的问题 | 禁止倾向 |
| --- | --- | --- | --- |
| 文献综述小点 | 转向式、研究推进式 | 已有研究把问题推进到哪里，为什么需要继续看下一层 | “围绕这一问题，已有研究……” |
| 文献述评 | 边界判断式、问题压缩式 | 现有研究的贡献和未打通环节分别在哪里 | “总体来看，研究仍有不足” |
| 理论基础 | 概念限定式、解释分工式 | 该理论在本文中解释什么，不解释什么 | 教材式介绍理论来源 |
| 政策演进 | 过程变化式、工具转向式 | 政策回应了什么治理难题，工具或对象如何变化 | 文件按时间排队 |
| 指标体系 | 测量边界式、概念转化式 | 抽象概念如何转为可测量维度，边界如何划定 | “在前文基础上构建指标体系” |
| 问卷题项 | 操作风险式、情境转化式 | 指标语言进入受访者作答场景后会发生什么偏差 | “指标形成后需要转化为题项” |
| 预调查/信效度 | 方法边界式、测量风险式 | 预调查检验什么，不能替代什么 | “问卷形成后还需要检验” |
| 德尔菲咨询 | 内容审查式、专家判断边界式 | 专家咨询解决内容效度的哪类问题 | 把咨询写成行政组织过程 |
| 样本与数据 | 分析单位式、样本功能式 | 样本服务于什么检验或解释，不代表什么 | 只写发了多少份问卷 |
| 统计结果 | 结果问题式 | 该表或模型回答哪一个实证问题 | 复述表格数值 |
| 案例机制 | 过程解释式、经验引入式 | 哪个主体在哪个环节使机制发生 | 把案例写成经验展示 |
| 章节结尾 | 综合判断式 | 本节真正推出了什么判断，对后文有何作用 | “综上所述”复述目录 |

若用户正在写博士论文，冒段首句必须是上述类型之一，且后文应补足对象、主体、场景、过程、风险或后果。若首句只是“本节主要研究……”“本文将从……展开”，必须重写。

### Bad Opening Rewrite Rules

遇到下列开头，默认先重写开头，再判断正文是否保留。

1. `X形成以后，还需要通过Y进行检验。`  
   改为指出 Y 要解决的测量风险或解释风险。
2. `评价指标能否进入经验测量，取决于其能否……`  
   改为具体说明指标语言进入作答场景后可能发生什么偏差。
3. `在完成X之后，本文进一步……`  
   改为说明当前环节为什么不能被前一环节替代。
4. `前文已经……本节将……`  
   改为先下判断，再自然交代前文与本节关系。
5. `随着……不断推进，……日益重要。`  
   改为从具体制度变化、治理困境或材料结果进入。
6. `不是A，而是B` 高频出现。  
   改为先承认 A 的有限意义，再写 B 在具体环节中的作用。
7. `一方面……另一方面……此外……` 连续铺开。  
   改为问题递进或过程递进。
8. `已有研究表明……` 作为文献综述段首。  
   改为“研究焦点如何移动”“解释重心如何变化”或“方法如何转换”。

## Density Rules: Journal vs Dissertation

同一套公共管理写作规则在 C 刊论文和博士论文中的密度不同，不能混用。

1. C刊论文正文更重视压缩和锋利。章节冒段通常 180—350 字即可，核心是迅速推出问题和贡献；不宜长篇铺垫。
2. 博士论文正文更重视支撑和过程。章、节、小节冒段通常可写 500—800 字；总起句可以概括，但后文必须写出主体、场景、过程、约束或后果。
3. 普通自然段不强制字数。关键是段内必须完成“判断—材料—评述—推进或收束”的功能闭合。
4. 若用户正在写博士论文，不得为了像期刊而删掉必要过程；若用户正在写 C 刊，不得把博士论文式铺陈直接搬入正文。

## C Journal Abstract Rules

C刊摘要不是引言的缩写,也不是背景、方法和意义的机械拼接。摘要必须作为一篇论文的压缩论证单元,在有限篇幅中交代研究问题、研究对象、材料或方法、核心发现和学术贡献。生成或改写摘要时,默认按投稿要求调整字数; 若用户没有给出期刊要求,中文 C刊摘要通常控制在 300—500 字之间,避免写成过长的导言。

摘要写作前必须先判断全文的最小贡献是什么。不得在未明确“本文到底解决了什么公共管理问题”之前直接写摘要。摘要至少回答五个问题:

1. 研究问题: 本文处理哪个治理难题、解释缺口或经验矛盾。
2. 研究对象: 研究发生在哪类制度场景、区域、主体关系或政策过程之中。
3. 研究方法或材料: 使用案例、问卷、访谈、政策文本、统计模型、fsQCA、综合评价或其他材料时,说明其在本文中的功能,不要写成方法清单。
4. 核心发现: 至少给出两项可辨识的研究发现或机制判断,不能只写“具有显著影响”“取得较好效果”。
5. 贡献与含义: 说明本文对概念边界、机制解释、政策理解、公共管理理论或中国情境研究推进了什么,不得只写“具有理论和现实意义”。

摘要首句优先从具体问题或研究对象进入,不得用“随着……不断推进”“在……背景下”“近年来……”开头。合格方向是先压出研究困惑,如“数字平台进入基层以后,治理效能差异仍然存在,关键在于平台运行能否被组织流程和服务对象持续接住。”随后交代本文如何处理该问题。若首句只说明议题重要,而没有点出研究困惑或解释对象,默认重写。

摘要中的方法句应服务发现,而不是展示工具。不要写“本文运用文献分析法、案例分析法、访谈法……”这种方法罗列。应改为说明材料如何帮助回答问题,例如“基于县域数字治理案例和基层访谈材料,本文考察数字平台、组织承接与服务对象使用之间的衔接过程。”

摘要发现句必须可被正文支撑。若摘要写出“提升了治理效能”“促进了公共服务均等化”“推动了共同体建设”等判断,正文必须有对应材料、数据或机制解释。没有正文支撑的政策性拔高不得进入摘要。

摘要结尾应收束到贡献或含义,但不要写成口号。优先说明本文把问题推进到哪里,例如“研究将数字治理效能的解释重心从平台供给推进到组织承接、场景适配和用户持续使用过程。”不要写“为推进治理现代化提供借鉴”作为唯一结尾。

默认避免以下摘要模板:

1. 背景句过长,问题意识后置。
2. 方法清单化,发现空泛化。
3. 只写“本文发现一、二、三”,却不说明发现之间的机制关系。
4. 贡献句只写“丰富了理论”“提供了参考”,没有具体推进对象。
5. 摘要与正文不一致,把正文没有展开的概念、变量或政策建议提前写入摘要。

摘要的推荐推进顺序为: 研究困惑或治理难题—研究对象与材料—方法功能—核心发现或机制判断—理论/政策含义。若论文是实证模型或组态研究,可调整为: 研究问题—数据与方法—主要结果—机制解释—贡献边界。若论文是案例机制研究,可调整为: 经验矛盾—案例材料—过程机制—关键发现—理论或政策含义。

## Public Management Writing Logic

### 1. 问题提出

公共管理论文的问题提出不能只证明“这个议题重要”，还要说明“现有治理安排为什么不够解释当前现象”。推荐推进顺序是：具体治理现象或政策变化进入，指出实践中的落差或矛盾，再回到学术研究中尚未充分解释的环节。

不要写成政策背景接龙。政策文件可以交代制度环境，但不能替代问题意识。高质量问题提出应回答：哪些主体在什么制度场景中遇到什么治理难题，既有研究为什么不能完全解释，本文准备从哪个角度进入。

### 2. 文献综述与述评

文献综述要按问题推进，不按作者排队。先概括已有研究集中处理了哪些问题，再说明这些研究采用了什么视角、材料或方法，最后评述其对本文的启发与不足。

述评不要只写“研究不足”。公共管理写作中更有力度的述评，是判断已有研究把问题推进到哪里、尚在哪个层面没有打通，例如从工具应用到治理结果、从单因素解释到条件组合、从政策部署到基层承接、从平台建设到公共价值。

文献综述写作必须执行以下细则：

1. 段落主语优先是“研究焦点、解释线索、争论、方法转向、场景差异或问题推进”，不是作者姓名。
2. 每段至少写清文献中的一个具体内容：研究对象、案例区域、样本范围、数据来源、核心发现、机制解释、比较结论或方法贡献。
3. 不得连续使用“某某指出、某某认为、某某发现”组织段落。作者前置只允许用于概念源头、代表性转折、方法来源或明确争论。
4. 更稳的顺序是先写研究判断，再在句尾或句中嵌入文献支撑。不要为了显示读过文献而把作者姓名推到句首。
5. 文献材料不能接龙。若一段删去作者名后只剩几个案例、平台或地区名称，说明逻辑骨架还没有建立。
6. 文献综述小点结尾必须从“已有研究推进到哪里”转向“本文仍需处理什么”，但不得提前展开后文方法、变量或案例设计。

文献综述常用段落类型：

1. 研究推进型。写早期研究关注什么，后续如何深化，解释重心发生了什么变化。
2. 机制解释型。写已有研究如何解释某一结果，关键条件、主体或过程是什么。
3. 方法转向型。写研究如何从案例阐释走向指标测度、问卷调查、模型检验或组态分析。
4. 场景拓展型。写一般研究如何进入特定区域、基层场景、行业部门、城乡接合部、平台治理、弱势群体或公共服务一线。
5. 述评收束型。压缩已有研究贡献，指出本文还需要处理的对象、机制、方法或情境边界。

文献综述正式写作还必须通过以下执行门槛：

1. 写作前先形成不带作者名的问题链。至少写清“研究从什么问题起步、后来转向什么问题、为什么发生转向、仍卡在哪里”。
2. 每个核心自然段至少落到两类具体文献内容中的任意两类：研究对象、案例区域、样本或数据、方法工具、关键发现、机制解释、负面后果、比较结论。
3. 作者名只能作为证据或关键节点出现。若一个自然段中出现两句以上“作者名 + 指出/认为/发现/提出”，默认未达标。
4. 文献综述不得提前写成研究设计。除述评收束段外，不提前展开变量拆分、模型设定、指标赋权、样本选择标准、案例选择标准、具体调查工具或操作化方案。
5. 每一小点结尾必须完成“已有研究推进到哪里—本文为何还要继续处理”的转向。不得只写“为本文提供了借鉴”。
6. 若用户原文已有细节和判断，优先保留其问题意识与材料厚度；不得为了压缩或工整删去有效的机制细节。
7. 文献综述涉及特定区域、组织类型、政策领域、治理层级、服务对象或技术场景时，必须写出这些场景条件如何改变研究问题，不得只把地区、部门、平台或案例名称作为例子罗列。

文献综述段落的合格样式不是“某某研究了什么”，而是“某类研究把问题推进到什么层面”。例如，优先写“数字平台从建设期进入运行期以后，研究开始从工具供给转向组织承接、用户使用和反馈吸收过程”，再用文献支撑；不要写“某某指出平台运行中组织承接很重要”。

### 3. 理论框架

理论框架不能写成概念介绍。每个理论都要说明它解释本文哪一部分，也要说明它不负责解释什么。公共管理论文常见错误是把理论名称当作标题，把正文写成教材定义；应改为围绕研究对象说明理论如何帮助识别主体、制度、资源、技术、情境、反馈和结果之间的关系。

如果使用多个理论，必须写出分工。一个理论解释价值取向，一个理论解释主体协作，一个理论解释条件组合，这样的分工比把理论并列摆放更可靠。

### 4. 政策与制度过程

写政策演进时，按照“问题出现—政策回应—工具变化—地方承接—治理后果”组织材料。不要把文件按时间顺序简单罗列。

政策分析要有议论。每写完一个政策节点，需说明它改变了什么：是改变了资源配置，改变了治理对象识别，改变了基层组织责任，还是改变了评价目标。若没有这一步，政策材料只是背景，不是论证。

### 5. 案例与机制解释

案例分析必须从“发生过程”进入机制。公共管理案例不只是展示地方经验，而是解释条件如何出现、主体如何行动、规则如何被执行或转译、资源如何流动、反馈如何被吸收，以及这些过程如何导向特定治理结果。

机制段落应避免抽象套壳。不要只写“多元协同促进效能提升”，而要写清楚谁与谁协同、在哪个环节协同、协同靠什么规则或资源维持、协同失败时会出现什么后果。

### 6. 研究设计与方法

方法段服务研究问题，不服务方法本身。写问卷、访谈、案例、组态分析、综合评价、专家咨询、结构方程、回归模型或文本分析时，先交代分析单位、样本来源、变量、题项或材料为什么能回答研究问题，再交代操作步骤。

不要把方法段写成统计教材。公式、阈值和检验结果可以出现，但必须说明它们在本文中承担什么功能：筛题、赋权、比较、识别路径、解释差异，还是验证专家意见一致性。

### 7. 结果解释

统计结果不能只复述表格。先说明该表或模型要回答的问题，再报告关键数值，最后解释这些数值改变了我们对研究对象的什么认识。

如果结果与预设不同，不要急着解释为“数据异常”。公共管理研究中的偏离常常来自制度执行、主体能力、地方情境或测量口径的差异。应先判断这种偏离是否揭示了新的治理边界。

### 8. 讨论、贡献与结论

讨论不是重复结果，贡献不是自我表扬。公共管理论文的讨论应把经验发现推回理论、方法或政策问题，说明本文发现如何修正、补充或细化已有解释。

结论应先提炼研究判断，再说明理论意义、方法意义和政策含义。政策建议必须从结果中长出来，不能另起炉灶写成通用对策。

### 政策建议写作规则（通用版）

政策建议必须从研究发现、理论解释、模型结果、案例机制或比较结论中推出，不能脱离前文另写一套行政口号。写作前先确定“发现—问题—主体—工具—边界”五个环节：发现来自哪一项结果；问题表现为制度规则、资源配置、流程衔接、主体协同、监督反馈、信息公开、服务可及或执行能力中的哪一类缺口；责任主体是政府层级、职能部门、街道乡镇、基层组织、社会组织、平台企业还是公共服务机构；政策工具是规则调整、资源投入、流程再造、数据共享、责任清单、能力建设、反馈渠道还是评估监督；适用边界是全国性问题、区域性场景、特定组织类型还是某类政策对象。

凡是出现“加强、完善、推进、优化、提升、健全、打造、构建”等词，必须在同一句或相邻句补出可执行内容。可执行内容至少包括对象、动作和运行机制，例如“由县级部门统一规则口径，乡镇负责解释转译，村级组织通过服务点和网格员完成到户提醒”，而不是停留在“加强基层协同”。若无法补出主体、流程和反馈方式，该建议应改写或删除。

公共管理论文的政策建议通常可以落在六类工具上：制度规则型建议，强调权责边界、标准口径和程序规范；资源配置型建议，强调财政、人员、设备、培训和运维；流程再造型建议，强调事项整合、窗口衔接和线上线下联动；主体协同型建议，强调部门、层级、社会组织和企业之间的责任分工；分类治理型建议，强调不同地区、群体和场景的差异化安排；监督反馈型建议，强调绩效评估、群众反馈、数据回流和责任追踪。写作时不必机械列出六类，但每条建议必须能归入其中一类，并说清楚它回应了哪一项研究发现。

C刊写作中，政策建议宜少而实。通常保留二至四条即可，每条建议用一个明确问题带出，不要写成政府工作报告式排比。建议段落的基本推进是：研究发现揭示了什么问题，该问题为什么不能靠一般性口号解决，应由哪些主体采取何种政策工具，预期改善哪个治理环节，并在必要时说明适用范围和风险。统计、模型、案例或比较结果之后，应先解释其治理含义，再提出政策建议。

## Anti-Template Rules

默认重写以下写法：

1. “随着……不断推进”“在……背景下”“近年来……”作为开头而后接宏大判断。
2. “前文已经完成……本节将继续……”作为小节起笔。
3. “X形成以后，还需要通过Y检验”作为方法段起笔。
4. “能否……取决于能否……”等镜像条件句。
5. “不是A，而是B”“既是A，也是B，更是C”等对偶式结构高频出现。
6. “具有重要意义”“提供理论支撑”“奠定基础”等没有具体对象的空泛评价。
7. “赋能、驱动、融合、重塑、路径、图景、抓手、闭环”等抽象词连续堆叠。
8. 用冒号、引号、破折号或分号制造总领感和密集感，而不是用正常句法解释关系。分号默认不用；除非它承担不可替代的并列、比较或递进功能，否则改为句号。

替代原则：

1. 从具体治理难题、方法边界、制度过程、数据结果或案例环节起笔。
2. 用主体、资源、规则、流程、反馈、结果替代抽象口号。
3. 让转折来自材料本身，不靠“然而、但是、值得注意的是”硬转。
4. 保留必要厚度，不为追求简洁而删掉博士论文或公共管理论文需要的过程说明。

## Section Opening Rules

章、节、小节冒段应先判断本节处理什么关键问题，再说明前文推进到哪里、当前环节还有什么方法或经验风险、本节如何处理。冒段不是目录复述。

常用开头类型：

1. 研究风险式：指出若不处理该问题，会导致测量、解释或机制判断偏移。
2. 方法边界式：说明某一方法或材料能解决什么，不能解决什么。
3. 经验矛盾式：从治理实践中的落差、断裂或张力进入。
4. 概念限定式：先划清核心概念的使用边界，再展开论证。
5. 结果解释式：先说明结果要回答的问题，再进入数值或材料。

不使用同一种开头写完整篇文章。相邻段落应在起笔方式上有变化。

章、节、小节冒段默认遵守以下顺序，但不机械分句：

1. 第一层，核心判断。直接指出本节要处理的研究问题及其重要性。
2. 第二层，前文承接。说明前一节或前一章已经推进到哪里，但不能写成“前文已经完成……本节将……”。
3. 第三层，具体难题。写清如果不处理该问题，会造成概念边界、测量口径、机制解释或政策判断上的什么偏差。
4. 第四层，研究对象中的表现。落到公共管理对象中的主体、制度、资源、平台、基层组织、服务对象、企业、部门或政策工具。
5. 第五层，本节安排。用一至两句交代本节处理哪些内容，不复述目录，不提前展开下一节。

普通正文段不必写成 500—800 字，但仍须有起笔判断、材料支撑和阶段性评述。

### Exemplar Opening Transfer Rules

当用户提供同门论文、范文、优秀博士论文或已发表论文并询问“冒段怎么学”“是否照着写”时，先区分可迁移的结构能力与不可照搬的入口方式。可迁移的是冒段如何说明本章或本节为什么存在、如何接入全文问题链、如何提前给出作者判断、如何在末句收束到本节任务。不可直接照搬的是与当前段落功能不匹配的宏大叙事、国家战略入口、价值宣示和章节总论式铺陈。

执行时先判断当前冒段属于哪类功能。绪论、研究背景、章节总起、政策演进、实践图景和案例章开头，可以适度学习范文中“宏观制度关系—现实张力—研究对象—章节任务”的大开口写法。指标体系、问卷题项、预调查、德尔菲咨询、信效度检验、样本说明、变量操作化和模型设计等方法或测量小节，应改用“测量风险或方法边界—前文承接—具体作答/数据/操作情境—本节处理安排”的小开口写法。

判断范文是否可学，不看句子气势，而看它是否完成四项功能：指出本节存在的必要性，说明前文推进到哪里，压出当前环节的具体难题，交代本节如何处理。若范文用宏大背景完成的是章节总起功能，而用户当前写的是方法小节，应只学习其“结构动作”，不得把宏观背景、价值拔高和制度文明叙事搬入正文。对问卷题项类小节，优先从受访者理解、作答口径、题项归属、量表赋值和后续测量偏差进入。

## Complete Unit Ending Rules

完整小节或章节结尾必须提炼作者自己的判断。不要用“综上所述”机械总结，也不要把前文分点再复述一遍。

结尾段要完成三件事：

1. 回看本部分真正推进了什么。
2. 说明这些推进对研究问题、理论框架、指标设计、方法选择、机制解释或政策含义意味着什么。
3. 如需承接后文，只轻轻指出下一步分析方向，不提前展开新论证。

## Output Contract

生成正式论文正文时，默认输出两部分：

1. 正文。
2. 写作逻辑与风格说明，控制在 3—6 行，具体说明本次如何组织材料、在哪里设置作者判断、如何避免模板化表达。

如果用户明确要求“只给正文”或“不要说明”，则省略第二部分。

写作逻辑与风格说明必须具体，不得只写“逻辑更清晰、语言更学术”。至少说明三项：本段选择了哪种起笔方式，材料如何被组织成问题链或机制链，在哪些位置避免了模板句、作者罗列或对偶表达。

若本轮没有生成正式正文，而是提供写作方案、段落安排、标题判断、结构诊断、修改建议或对用户原文的优劣比较，也必须附上“判断依据”。判断依据不超过 3—5 行，说明本次判断依据的是章节功能、材料密度、段落边界、文献推进、测量逻辑、机制解释或反 AI 模板中的哪几项。

## Source And Citation Rules

1. 涉及具体文献、政策、数据或案例时，优先使用用户提供材料、Zotero、正式政策文件和已核实来源。
2. 不把政策文件当作学术文献使用。政策文件用于说明制度环境，学术文献用于支撑概念、机制、方法和研究缺口。
3. 当用户要求“先读文献再写”时，必须配合 `public-management-zotero-scholar-writing`，先列本轮参照来源，再写正文。
4. 当用户要求插入文献或引用格式时，配合 `public-management-inline-citation-zh`。

## Final Check

交付前逐项检查：

1. 是否先判断段落功能，再写正文。
2. 若为连续段落，是否先形成论证单元地图，并为各段分配不同功能。
3. 相邻段落是否通过实质对象、材料结果、解释边界或未决问题接力，而非依靠连接词拼接。
4. 是否把公共管理对象写清楚，而不是停留在宏大背景。
5. 材料是否形成过程链、因果链或机制链。
6. 是否在材料节点后加入作者评述。
7. 是否删除流程式开头、镜像条件句、对偶式并列和空泛拔高。
8. 结尾是否提炼了作者判断，而不是重复前文。
9. 若是博士论文段落，是否保留了必要的细节和支撑。
10. 段首句是否根据段落任务选择了判断式、问题式、方法边界式、过程式、转向式、概念限定式、经验引入式或结果解释式。
11. 文献综述段是否按研究推进组织，而不是按作者姓名组织。
12. 章节冒段是否说明了核心判断、承接关系、具体难题、对象表现和本节安排。
13. 正式正文后是否提供具体写作逻辑与风格说明；非正文建议后是否提供判断依据。
