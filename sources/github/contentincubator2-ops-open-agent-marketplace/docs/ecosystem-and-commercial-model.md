# Ecosystem and Commercial Model

Open Agent Marketplace is designed as an open-source foundation, not a closed product demo. The repo should remain useful on its own while making room for a broader ecosystem.

## Open-source foundation

The open repo provides:

- agent profile schemas
- squad schemas
- workflow templates
- fictional case packs
- evaluation rubrics
- contribution rules
- demo UI

This creates a neutral standard that other builders can fork, extend, and adapt.

## Ecosystem paths

Potential public ecosystem extensions:

1. **Verified agent profiles**
   - community-submitted agents reviewed against the rubric
   - badges for channel expertise, industry focus, and output quality

2. **Verified squad recipes**
   - reusable teams for common business outcomes
   - examples: SaaS launch, ecommerce growth, local lead generation, B2B ABM

3. **Integration packs**
   - adapters for CRM, analytics, email, CMS, and ad platforms
   - public interfaces only; no private account data in the repo

4. **Hosted directory**
   - searchable web version of the marketplace
   - contributor profiles and public changelog

5. **Agency and consultant templates**
   - reusable proposal, audit, and delivery templates
   - public-safe examples that teams can customize

## Commercial paths

Possible commercial layers can exist around the open repo without weakening it:

- hosted search and filtering
- managed private marketplaces
- verified premium squads
- implementation support
- enterprise governance workflows
- private eval dashboards

## Boundary

The open repo should not include private customer data, internal operating systems, proprietary performance metrics, or credentials. Commercial value should come from implementation, verification, hosting, and ongoing operations — not from leaking private source material.
