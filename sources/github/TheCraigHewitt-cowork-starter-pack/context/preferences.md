# Preferences

Co-work reads this file to know *how* to work with you. Not who you are (`about-me.md`) and not how you sound (`voice.md`) — how you want the work done, when to ask versus decide, what "done" looks like.

This is the file that stops Co-work from asking you 14 clarifying questions before starting anything, and also stops it from confidently shipping the wrong thing.

---

## Example (a filled version — delete this when you fill in your own)

### When to ask me, when to decide on your own

- **Just decide:** formatting choices (tables vs. bullets vs. prose), file naming, folder organization, whether to use a connector, low-stakes writing tone calls.
- **Show me a plan first:** anything with more than three steps, anything that touches files outside the current project folder, anything that sends an external communication (email, Slack DM, calendar invite).
- **Always ask first:** deleting files, overwriting existing files, renaming more than five files at once, connecting a new app, committing money, sending to more than three people.

### How I want work delivered

- **Files, not chat.** If you're producing anything longer than three paragraphs, save it as a file in `/output/`. Don't paste it in the chat window.
- **Name files like this:** `{YYYY-MM-DD}-{short-description}.{ext}` — so `2026-04-18-weekly-report.md`, not `weekly_report_final_v2.md`.
- **Date everything.** Every report, brief, or summary starts with the date at the top.
- **Headers and short paragraphs.** Not walls of text. Not over-nested bullet lists either.
- **Tables for parallel data.** Three or more comparable items = table. Fewer = prose.

### How to handle uncertainty

- If you're uncertain about a fact, say so. Don't fabricate.
- If a source conflicts with another source, flag it — don't pick silently.
- If you can't complete a task because of missing info, tell me exactly what you need. Don't stall.

### What "done" looks like

- The deliverable is in the right folder, named correctly, dated.
- Any flagged issues or missing info are listed at the top.
- If the task had multiple steps, a one-line summary of what you did.
- If you made any decisions I should know about, they're listed.

### Defaults

- **Time zone:** America/New_York
- **Currency:** USD
- **Date format:** 2026-04-18 (ISO)
- **Document format:** Markdown unless otherwise specified
- **Spreadsheet format:** CSV unless a specific Excel format is requested

## Customization notes

- **Executive assistants.** Be very specific about tone defaults and sign-offs. Include your principal's calendar preferences, meeting-length defaults, and their hard no's (if they never take calls before 10am, write it down).
- **Marketers.** Include brand guidelines here — required disclaimers, banned claims, required CTAs, which social accounts you post from. If there's a legal review step for certain content, say it.
- **Operations / COO types.** Include decision thresholds (what can Co-work approve vs. escalate). If a report format is standard at your company, describe it exactly.
- **Founders / CEOs.** Be specific about what NOT to do autonomously. You have more blast radius than anyone else in the org — your safety rails should be tighter, not looser.
- **Analysts / researchers.** Specify source-citation requirements (inline vs. footnote), confidence-level tagging ("high confidence," "inferred," "uncertain"), and whether you want the methodology shown or just the result.

## Why this file matters more than the other two

`about-me.md` tells Co-work who to be. `voice.md` tells Co-work how to sound. This file tells Co-work how to *work*. Most bad Co-work outputs come from missing or vague preferences — not missing context. Write this one carefully.
